## Description

Found in review of #0107. VM run `20261019-231415-61437` aborted AudioCoreTests with `required condition is false: NULL != engine`, raised by `AnalyzerTap.remove()` called from the tap's `deinit`. AVAudioEngine raises this when `removeTap(onBus:)` is called on a node that is no longer attached to an engine. It happened once, in the run after #0106 added stream mode (which stops and restarts the player node), and not in the rerun. The same path exists in the app, where it would crash SkinAmp rather than fail a test.

## Expected behavior

- `AnalyzerTap.remove()` (and its `deinit`) is safe when the node has already been detached or its engine released: it removes the tap only if the node still has an engine, and never raises.
- A test releases the tap after detaching its node (and after the engine is gone) without crashing.
- If a stream-mode path detaches or replaces the node while a tap is installed, the tap is removed first.

## Plan

### Cause (from `build/vm-tests/20261019-231415-61437/playerkit-tests.log`)

The stack trace shows `removeTapOnBus:` → `AnalyzerTap.remove()` → `AnalyzerTap.deinit` → `_Block_release` → `AVAudioNodeTap::TapMessage::RealtimeMessenger_Perform` running on a libdispatch worker. The tap block in `install` captures `[self]` strongly. When a test's `Player`, and with it the `AudioGraph`/`AVAudioEngine`, is released while the tap is still installed, the block is the last owner of the `AnalyzerTap`. AVFAudio disposes the block later on its RealtimeMessenger queue. That runs `deinit` off the main thread. `isInstalled` is still `true` and the `weak node` (the mixer) still resolves during teardown, but its engine is gone, so `removeTap(onBus:)` raises `NULL != engine`. Timing decides whether the weak node is already nil, so the crash is intermittent. Stream mode isn't the cause: nothing in AudioCore detaches or replaces a node (`git grep detach` finds none), and the tap is on `mainMixerNode`, which never changes. #0106 only added more short-lived Players to the parallel test run.

### Change (only `Packages/PlayerKit/Sources/AudioCore/Analyzer/AnalyzerTap.swift`)

1. **The tap block stops retaining the `AnalyzerTap`.** Move the producer state into a small private `final class TapSink: @unchecked Sendable` that holds `ring` (the same `VisSampleRing` instance; `AnalyzerTap.ring` keeps returning it) and owns the `scratch` buffer (it allocates `scratch` in `init` and deallocates it in its own `deinit`). Move the body of `handle(_:)` to `TapSink.handle(_:)` unchanged, with no allocations and no locks. `install` captures only the sink: `let sink = self.sink; node.installTap(...) { buffer, _ in sink.handle(buffer) }`. `AnalyzerTap.deinit` then runs on its owner's thread, never from AVFAudio's block disposal. `scratch` stays valid as long as any block can still run, because the block owns the sink. `AnalyzerTap.deinit` deallocates only `window`, `spectrumOut` and `scopeOut`.
2. **`remove()` never calls into a node that has no engine.**
   ```swift
   public nonisolated func remove() {
       guard isInstalled else { return }
       if let node, node.engine != nil { node.removeTap(onBus: bus) }
       node = nil
       isInstalled = false
   }
   ```
   (If the engine is gone, the tap went with it.)

Don't change `AudioGraph`, `Player.swift` or `Player+Stream.swift` (#0112 is being worked there). File playback, gapless scheduling and the install/remove call sites stay as they are.

### Tests (add to `Packages/PlayerKit/Tests/AudioCoreTests/AnalyzerTapTests.swift`)

Each test uses a bare `AVAudioEngine` in `.offline` manual rendering (44.1 kHz stereo, 512 frames, as in `tapDeliversFramesThroughOfflineRender`), started, with no device and no audio.

- `theTapBlockDoesNotKeepTheAnalyzerAlive`: install a tap on `engine.mainMixerNode` and keep only a `weak var weakTap`. Drop the strong reference. `#expect(weakTap == nil)` immediately, on the main actor. This fails before the change because the block retains the tap.
- `removingTheTapAfterItsNodeWasDetachedDoesNotRaise`: attach an `AVAudioMixerNode`, connect it to the main mixer, and install the tap on it. `engine.detach(node)` while holding the node strongly, then call `tap.remove()`, then release the tap. Expect `!tap.isInstalled` and no crash.
- `releasingTheTapAfterItsEngineIsGoneDoesNotRaise`: install on `engine.mainMixerNode`, hold the mixer node strongly, stop and release the engine (in a scoped block), then call `tap.remove()` and release the tap. Expect `!isInstalled` and no crash.

The existing `tapDeliversFramesThroughOfflineRender`, `frameElapsedAdvancesThroughBurstDeliveries`, `streamPlaysThroughTheEQAndTheAnalyzerTap` and `analyzerTapSeesProgressiveAudio` must still pass. They cover the sink-based tap delivering frames.

## Root cause

The tap block in `AnalyzerTap.install` captured `self` strongly. When a Player (and its engine) was released with the tap still installed, the block was the last owner of the tap; AVFAudio disposed it on its RealtimeMessenger queue, running `deinit` -> `remove()` -> `removeTap(onBus:)` on a node whose engine was gone, which raises `NULL != engine`.

## Fix

As planned: producer state (ring + scratch, and `handle`) moved into a private `TapSink`; the tap block captures only the sink, so `AnalyzerTap.deinit` runs on its owner's thread. `remove()` calls `removeTap` only if the node still has an engine, then clears `node`. `ring` is now a computed property returning the sink's ring (same instance). No deviation.
