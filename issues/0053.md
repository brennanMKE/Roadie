# 0053 — EQ and balance changes are delayed by AirPlay 2 buffering

| | |
|---|---|
| **Status** | open |
| **Module** | AudioCore |
| **Platform** | macOS |
| **First seen** | 2026-10-13 |

## Description

With enhanced buffering, audio is rendered up to minutes before it is heard on an AirPlay 2 speaker, so EQ, preamp and balance baked in before enqueue would not be heard until the buffer drains.

## Acceptance criteria

- A DSP parameter change flushes from just ahead of the playhead (`flush(fromSourceTime: now + margin)`) and re-renders from there, so the change is heard promptly on AirPlay 2 and locally through the same code path.
- Slider drags are debounced (about 150 ms) so dragging doesn't flush continuously.
- A flush that fails (too close to the playhead) is handled, not ignored.
