# 0064 — Music Assistant players cannot be controlled from SkinAmp

| | |
|---|---|
| **Status** | open |
| **Module** | App / MusicAssistantKit |
| **Platform** | macOS |
| **First seen** | 2026-10-13 |

## Description

Controller mode (doc section 5.2, mode 1): SkinAmp browses the MA library and plays it on MA players such as HomePods. MA streams from the server; no audio passes through the Mac.

## Acceptance criteria

- An output picker lists MA players (including HomePods and groups).
- Play an album, track or playlist on the chosen player (`player_queues/play_media`), and drive play, pause, next, previous, seek and volume from the skinned transport buttons.
- Now playing, elapsed time and artwork come from MA events and drive the skinned window, Now Playing and media keys.
- Changes made from MA's web UI (play/pause, track change) show in SkinAmp within about 1 s.
- Doc acceptance: on the home LAN the app discovers MA, authenticates, browses the Plex-backed library, plays an album on a HomePod and reflects external changes.

## Plan

Written on top of `ef3c6b5` (#0063: settings, `MusicAssistantBackend.init(server:token:)`, the active-server box). #0063 is still under review, so if its review changes `MusicAssistantBackend`'s connection code or `PlayerModel.init`'s Music Assistant wiring, rebase onto that before starting. Protocol facts are from `docs/ma-protocol-notes.md` (MA 2.10.6, schema 65). Pushed events are **unrecorded** (#0076), so this plan never relies on an event shape alone (section 4).

### 0. Scope

In scope: the output picker, `play` / `transport` / `nowPlaying(on:)` on `MusicAssistantBackend`, routing in `PlayerModel` by output, and the Now Playing / media-key bridge for remote outputs. Out of scope: the once-a-second tick of the time digits between snapshots (#0069; add no timer here), recording event shapes (#0076), playing on This Mac through Sendspin (#0066), shuffle/repeat button *state* for remote outputs (the commands are sent, but `NowPlaying` has no shuffle/repeat fields; follow-up if wanted), persisting the selected output across launches (it would force launch-time network and Keychain access, which `PlayerModel` forbids; follow-up).

### 1. Existing bug this has to fix: commands and now-playing go to the active *library source*, not to the output

`PlayerModel` sends every `TransportCommand` to `self.backend` (the active library source) and subscribes to `sources.nowPlaying(on:)`, which also follows the active source. With Music Assistant as the default source, local files on This Mac get `MusicAssistantBackend.transport(_, on: this-mac)`, which throws `unknownOutput`, and the main window's now-playing stream is MA's empty stream. Once remote outputs exist the same mix-up sends HomePod commands to the folder backend. The fix is to route by **output**:

- **New `PlaybackRouter`** (`Packages/PlayerKit/Sources/LibraryBrowser/PlaybackRouter.swift`, `@MainActor`, depends only on `MusicBackendKit`): `init(local: any MusicBackend, remote: any MusicBackend)`; `backend(for output: OutputDevice.ID) -> any MusicBackend` returns `local` for `OutputDevice.thisMacID` and `remote` for any other id. In the app, `local` is `folderBackend` (its This Mac `transport` / `nowPlaying` go straight to the shared `LocalPlayerOutput` and need no connection, and Plex shares the same `LocalPlayerOutput`), `remote` is `musicAssistant`.
- `PlayerModel`: the command loop calls `router.backend(for: output).transport(command, on: output)`; `observeNowPlaying()` iterates `router.backend(for: output).nowPlaying(on: output)` instead of `sources.nowPlaying(on:)`. Leave `LibrarySourceController.nowPlaying(on:)` and its tests in place (unused by the app afterwards; removing it is optional cleanup, not required).
- `playFromLibrary` keeps using the active source's backend (the ids belong to it). Mismatches get a clear message instead of `unknownOutput`: MA source with This Mac selected throws `MusicBackendError.backend("Choose a speaker in the Library's Output menu to play from Music Assistant.")` from `MusicAssistantBackend.play` (playing MA on This Mac is #0066); folder/Plex source with a remote output selected is refused in `PlayerModel.playFromLibrary` before calling the backend, with a notice "Switch the output to This Mac to play local files.". Neither case should call `fallback.report` (it is not a source failure).

### 2. Output picker

- **`OutputDevice.isGroup`** (`Packages/PlayerKit/Sources/MusicBackendKit/Playback.swift`): new `public var isGroup: Bool`, init parameter defaulted to `false`, so every existing call site compiles unchanged. `OutputDevice.init(ma:)` (`MAMapping.swift`) sets it for `type == "group"` or a non-empty `group_members` (groups are unrecorded on the reference server; `stereo_pair` is a single speaker and stays `false`).
- **`OutputPickerModel`** (`Packages/PlayerKit/Sources/LibraryBrowser/OutputPickerModel.swift`, `@MainActor @Observable`): `devices: [OutputDevice]` (always This Mac first, then the remote backend's players sorted by name, then groups), `refresh() async` (calls `remote.outputs()` only when `remote` is connected, otherwise lists only This Mac plus a `hint` string "Open the Library to connect to Music Assistant."; errors become the hint, never an alert), and `onSelectionLost` support: `reconcile(selected:) -> OutputDevice.ID` returns `thisMacID` when the selected id is no longer listed. It never calls `connect()`.
- `MusicAssistantBackend` needs a public `isConnected` (exists) to be reachable through the picker: give the picker an `isConnected: @Sendable () async -> Bool` closure rather than a downcast, so it stays source-neutral and testable with `StubMusicBackend`.
- **UI** (`App/Browser/LibraryWindowView.swift` toolbar, new small view `App/Browser/OutputPickerView.swift`): a `Menu` with a speaker symbol and the selected output's name. Sections "This Mac", "Speakers", "Groups"; unavailable players are listed disabled (greyed); a checkmark on the selection. It calls `refresh()` when the Library connects (after the browser's first successful load) and each time the menu opens. Picking an entry sets `PlayerModel.selectedOutput`. No change to the skinned windows.
- `PlayerModel`: own the `OutputPickerModel`; in `activeMusicAssistantServerChanged()` set `selectedOutput = OutputDevice.thisMacID` if a remote output was selected (its players belong to the old server) and post a notice; after each `refresh()` apply `reconcile`.

### 3. `MusicAssistantBackend`: play and transport

Replace the stubs in `Packages/PlayerKit/Sources/MusicAssistantKit/MusicAssistantBackend.swift`; capabilities become `[.search, .playlists, .artwork, .remoteOutputs]`.

- **Player cache instead of `players/all` per command.** Today `requireOutput` calls `outputs()` (a full `players/all`) on every command, which a volume drag would turn into dozens of full listings. Keep `players: [String: MAPlayer]`, filled by `outputs()` and updated by player events/refetches (section 4); `requireOutput` reads it and on a miss sends `players/get` (`result: null` → `unknownOutput`). Clear it in `connect()`/`disconnect()` with `counts`.
- **`play(_:on:mode:)`:** `this-mac` → the message in section 1. Otherwise `MARequest.playMedia(queueID: playerID, media: items.map(\.rawValue), option:, startItem:)`. `queue_id == player_id` for every recorded player; groups are unrecorded, so send the player id and let MA redirect (do not call `get_active_queue` here). Modes: `.replace(startIndex: 0)` → `option: .replace`, no `start_item`; `.replace(startIndex: k)` with `k > 0` and `k < items.count` → `start_item: items[k].rawValue` (the browser only uses `k > 0` with a list of track ids, `PlayRequest.play(_:in:album:)`); `.append` → `option: .add`. Item ids are already `library://` URIs. Empty `items` → no request.
- **`transport(_:on:)`:** `.play/.pause/.stop/.next/.previous` → `playerCommand` with the same name; `.togglePlayPause` → `.playPause`; `.seek(t)` → `seek(position: Int(t.rounded()))`, clamped at 0; `.setVolume(v)` → `volumeSet(level: Int((v * 100).rounded()))` clamped 0...100, and `.unsupported(.remoteOutputs)` without sending when the cached player has `supported_features` that lack `volume_set` or a `null` `volume_level`; `.setShuffle(b)` → `shuffle(enabled: b)`; `.setRepeat(b)` → `repeat(mode: b ? .all : .off)`; `.setBalance` → `MusicBackendError.unsupported(.remoteOutputs)`, nothing sent. Errors go through `guarded`/`map` like library calls. In `PlayerModel.showBackendFailure`, skip the notice for `.unsupported` coming from a balance drag on a remote output (the marquee already shows the balance text; a notice per drag tick is noise).
- No optimistic local state: the snapshot after the command (event or poll, section 4) is what moves the UI.

### 4. `nowPlaying(on:)`: events first, refetch and polling as the safety net (#0076)

Because no event frame has ever been recorded, treat every event as a **hint**: decode it when it matches the documented shape, and when it does not, fall back to asking the server. The UI is correct even if every event shape is wrong; events only make it faster.

- **New file `Packages/PlayerKit/Sources/MusicAssistantKit/MANowPlaying.swift`**, pure and fully unit-tested:
  - `MANowPlayingMapper.snapshot(output:player:queue:skew:now:) -> NowPlaying`. State from `player.playback_state` (`playing`→`.playing`, `paused`→`.paused`, `idle`/unknown→`.stopped`), falling back to `queue.state`. Title/artist/album/duration/item from `player.current_media` (`title`, `artist`, `album`, `duration`; `item = MediaID(.track, uri)` only when `MAURI.parse(uri)` is a track), falling back to `queue.current_item` (`name`, `duration`, and `media_item`'s `name` / `artists[0].name` / `album.name` read leniently from the raw `MAJSON`). Elapsed from the queue's `elapsed_time` + `elapsed_time_last_updated`, else `current_media`'s, else the player's; `updatedAt = Date(timeIntervalSince1970: lastUpdated - skew)` where `skew = serverTime - localTime`, and `now` when the timestamp is missing or lands more than a minute in the future or a day in the past. Volume `volume_level / 100` (nil when null). Artwork: the `proxy_id` path segment of `current_media.image_url` (`/imageproxy/<proxy_id>?...`; the host is ignored, it is the server's own base URL) as `ArtworkRef`, else `queue.current_item.image.proxy_id`.
  - `MAEventMatch.classify(_ event: MAServerEvent, playerID:, queueID:) -> Action` with `Action` = `.player(MAPlayer)`, `.queue(MAPlayerQueue)`, `.elapsed(Double)`, `.refetch`, `.ignore`. Matching: `object_id` equal to the player or queue id, **or**, when `object_id` is absent, `data.player_id` / `data.queue_id` equal to it. `player_updated` → decode `data` as `MAPlayer`, `queue_updated` → `MAPlayerQueue`, `queue_time_updated` → `data` as a bare number **or** an object with `elapsed_time`; any matching event that fails to decode, and `player_added`/`player_removed`/`queue_added`/`queue_items_updated`, → `.refetch`; non-matching or unknown names → `.ignore`. Matching events whose ids cannot be determined at all (no `object_id`, no id in `data`) for `player_*`/`queue_*` names → `.refetch` (cheap, and covers an envelope that differs from the API page).
  - `MANowPlayingPolicy { eagerPoll: .seconds(1), relaxedPoll: .seconds(10), refetchDebounce: .milliseconds(150) }`.
- **In the backend**, one watcher per subscriber (`watchers: [UUID: Watcher]`, like `LibrarySourceController`'s subscribers): the returned stream uses `.bufferingNewest(1)`; it yields `.idle(on:)` at once when not connected (and sends nothing), otherwise fetches `players/get` + `player_queues/get_active_queue` (null queue → `player_queues/get` with `queue_id = player_id`) and `time` once for `skew`, yields the snapshot, then runs three things together until cancelled: (a) `client.events()` through `classify`, applying `.player`/`.queue`/`.elapsed` to its cached player/queue and yielding the new snapshot, and turning `.refetch` into a debounced refetch; (b) a poll loop on the injected `clock`: every `eagerPoll` until the first event has been applied for this output, then every `relaxedPoll` (an applied event resets the relaxed timer), so external changes show within about 1 s even if every pushed event is unusable, and the poll drops to one cheap `players/get` + queue every 10 s once events are known to work; (c) `client.states()`: on `.connected` after `.reconnecting`, refetch immediately. Yield only when the snapshot differs from the last one (`NowPlaying` is `Hashable`; compare ignoring `updatedAt` when state and elapsed agree within 0.5 s, so polls that only restate the same position do not re-render).
- `connect()` replacing the client and `disconnect()` restart or end every watcher against the new client (`disconnect()` yields `.idle` before ending the inner task; the outer stream stays open so `PlayerModel` keeps its subscription). `onTermination` removes the watcher and cancels its tasks; after cancellation nothing more is sent (tested).
- Log per watcher at `.debug`: event names (public), counts of applied events, refetches and polls (public), ids private. The host checklist uses this to tell whether events or polling carried the update; that is the evidence #0076 needs.
- Remove the "#0064" seam comments and the "unrecorded … #0064" note on `MAPlayer.groupMembers` once handled; keep the `MAServerEvent` "UNVERIFIED until #0076" comment.

### 5. Now Playing (Control Center) and media keys for remote outputs

`NowPlayingBridge` (`Packages/PlayerKit/Sources/AudioCore/NowPlaying/NowPlayingBridge.swift`) is bound to `Player`. Add, without changing This Mac behaviour:

- `public func setCommandTarget(_ target: (any NowPlayingCommandTarget)?)`: `PlayerModel` installs a small `@MainActor` adapter (in `App/PlayerModel.swift` or a new `App/NowPlayingRouting.swift`) that forwards to `player` when This Mac is selected and to `send(_:)` otherwise (`seek(to:)` → `.seek`).
- `public func showExternal(_ snapshot: NowPlayingSnapshot?, artwork: Data?)` and `public func clearExternal()`: while an external snapshot is set, `publish()` uses it (and its artwork) instead of the player's and ignores player events; clearing returns to the player's state and republishes. AudioCore does not import `MusicBackendKit`, so `PlayerModel` converts `NowPlaying` → `NowPlayingSnapshot` (`.stopped` → `showExternal(nil, …)`, `.loading` → paused, title fallback "Unknown title", artist `ArtistName.unknown`).
- `PlayerModel.observeNowPlaying()`: for a remote output, call `showExternal` on each snapshot; fetch artwork bytes through `musicAssistant.artwork(ref, maxPixels: 512)` when the snapshot's `artwork` ref changes (cancel the previous fetch; no credentials, the image proxy needs none); switching back to This Mac calls `clearExternal()`.

### 9. Host checklist (for the user, on their Mac with the real server)

1. Settings › Music Assistant has a tested server; open the Library (it connects). The toolbar Output menu lists This Mac, the HomePods and other players by name, any MA groups under "Groups", and unavailable players greyed out.
2. Choose a HomePod. Play an album (double-click) and a playlist; then double-click the third track of an album: playback starts there. Within a few seconds the main window marquee shows the track, the time digits and the play indicator.
3. From the skinned window: pause, play, next, previous, drag the position bar to seek, drag volume. The HomePod follows each; the volume slider settles on the HomePod's level.
4. Media keys (play/pause, next, previous) and Control Center's Now Playing show the title, artist and artwork and control the HomePod.
5. From MA's web UI: pause, resume, skip a track, change volume. SkinAmp shows each within about 1 s.
6. In Console.app, filter subsystem `com.brennanmke.SkinAmp`, category `MusicAssistantBackend`, enable debug messages: note whether updates arrived as applied events or only as polls. Ideally, run #0076's recorder (`/usr/bin/python3 -I scripts/record-ma-fixtures.py --events-seconds 60`) during step 5 so the real event shapes get recorded; if events show only as refetches/polls, attach the recording to #0076 so the decoding can be tightened.
7. Switch the output back to This Mac with Music Assistant still the library source, open a local file: play, pause, next and the time digits work (the routing bug in section 1). Playing an MA album with This Mac selected shows the "Choose a speaker" notice.
8. In Settings, change the active Music Assistant server: the output resets to This Mac with a notice.
9. Quit with a HomePod playing: playback continues on the HomePod (MA owns it); relaunch shows This Mac selected and nothing connects until the Library opens.
