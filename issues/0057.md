# 0057 — Plex sign-in logs the PIN id and leaves server lookups running after Forget or close

| | |
|---|---|
| **Status** | open |
| **Module** | PlexKit |
| **Platform** | macOS |
| **First seen** | 2026-10-13 |

## Description

Found in the #0014 review; none of these leaks the token.

- **PIN id in logs.** `PlexClient.fetch` logs the request path as public, so each sign-in poll logs `GET /api/v2/pins/<id>`, at debug level normally and at error level when a poll fails. #0014's plan says the PIN is never logged. Polling also needs the code, which is not logged, and a PIN lives about 30 minutes, so the exposure is small, but the log should not carry it. The POST that creates the PIN is also logged with the method "GET".
- **Server tasks not cancelled.** When sign-in auto-selects the only server, `serversTask` is cleared before the probe runs, so Forget can't cancel that probe. Closing Settings doesn't cancel `serversTask` either. Both are harmless today but break the rule that closing Settings stops Plex work.
- **Log wording.** The resolver's "tier N" log line logs the rank index, not the tier.

## Expected behavior

Logs show `/api/v2/pins/<redacted>` (or no id) with the real HTTP method; Forget and closing Settings cancel every in-flight server lookup; log lines say what they log.

## Notes

See `## Resolution notes` in [#0014](0014.md). Tests: assert the logged path for a pin poll is redacted (or that `fetch` takes a log-safe path), and that Forget and `disappeared()` cancel an in-flight resolver probe.

## Plan

### Scope and decisions

Three small fixes in PlexKit, each with a test that can fail on the current code, and no UI change. Status stays `open`; this plan writes no code.

- **The log line is a pure function of the request, and a redaction rule, not a caller-supplied path.** `PlexClient` gains `public static func logDescription(of request: URLRequest) -> String`, which returns `"<METHOD> <path>"` with the query dropped and everything after `/api/v2/pins/` replaced by `<redacted>`. `fetch` computes it once and uses it on every log statement. A caller-supplied log-safe path (a `logPath:` parameter on `fetch` or `request`) was considered and rejected: every call site would have to remember it, and the one path PlexKit sends that carries a secret is the PIN poll. A rule in one place is what a test can pin, and a future secret-bearing path is one more line in the same function (the doc comment says so). Tests observe the line through the function with the real request the account client builds; nothing reads the unified log.
- **The server-lookup task owns its own bookkeeping, and one `cancelServers()` is called from Forget and `disappeared()`.** Today `applyServers` clears `serversTask` in the middle of the auto-select chain, so the probe that follows runs outside any cancellable handle. After the change `applyServers` and `resolveAndUse` do not touch `serversTask` or `isLoadingServers`; each task body clears them at its end, and only if it was not cancelled. Invariant to keep (write it as a comment next to `serversTask`): *every assignment of `serversTask` cancels the previous task first, so a task that is not cancelled is the current one and may clear the field; a cancelled task never touches model state, and whoever cancelled it owns the state.* That is already how `connectionTask` and `signInTask` work.
- **`invalidate()` must not cancel server lookups.** `resolveAndUse` sets `address`, whose setter calls `invalidate()`; cancelling `serversTask` there would cancel the running task from inside itself and leave `isLoadingServers` stuck. Address and token edits during a lookup stay out of scope, as #0014 decided ("address edits clear `servers` only when the user picks a server").
- **Cancellation is proven with a positive signal, no settle sleeps** (#0058). The stub records a request whose load `URLSession` stopped before the stub had answered it; a test holds the probe with `Route.delay: 60`, acts, and waits for the held loads to show up as cancelled. Under the current code the auto-select probe is never cancelled, the wait times out at 5 s, and the test fails: it fails on the bug, not on timing.
- **The resolver logs the tier, not the index.** `PlexResourceConnection` gets the tier the ranking already computes privately, as a small public enum; the log line names it and the 1-based rank.

### 1. `PlexClient` (`Packages/PlayerKit/Sources/PlexKit/PlexClient.swift`)

```swift
/// What `fetch` logs for a request: the method and the path, never the query, and never a
/// plex.tv PIN id (everything after `/api/v2/pins/` is `<redacted>`). Add a rule here, not a
/// call-site parameter, if another path ever carries a secret.
public static func logDescription(of request: URLRequest) -> String {
    let method = request.httpMethod ?? "GET"
    let path = request.url?.path ?? ""
    if let range = path.range(of: "/api/v2/pins/"), range.upperBound < path.endIndex {
        return "\(method) \(path[..<range.upperBound])<redacted>"
    }
    return "\(method) \(path)"
}
```

`fetch`: `let line = Self.logDescription(of: request)`, then `log.debug("\(line, privacy: .public)")` and the four error lines become `"\(line, privacy: .public) failed: …"` with the same suffixes as today (`transport \(code)`, `401`, `404`, `\(status)`, `not JSON`). The local `path` constant goes away, so no log statement can interpolate the raw path again. `request(…)`'s doc comment: "The path is logged by `fetch`; the query is not." → "`fetch` logs `logDescription(of:)`: the method and the path with a PIN id redacted; never the query." `range(of:)` rather than `hasPrefix` so a base URL with a path prefix (`https://host/proxy`) still redacts.

### 2. `PlexSettingsModel` (`Packages/PlayerKit/Sources/PlexKit/PlexSettingsModel.swift`)

- New `private func cancelServers()`: `serversTask?.cancel(); serversTask = nil; isLoadingServers = false`. `forgetToken()` calls it in place of its three `serversTask`/`isLoadingServers` lines (and still clears `servers`, `serversMessage`, `signInStatus`). `disappeared()` adds `cancelServers()` after `cancelSignIn()`.
- New `private func serversTaskFinished()`: `serversTask = nil; isLoadingServers = false`. Called as the last statement of both task bodies (`useServer` and `startLoadingServers`), behind `guard !Task.isCancelled`.
- `startLoadingServers(useOnlyServer:)`: the body stays one task; after `applyServers(result)`, when `useOnlyServer` and exactly one server, `await resolveAndUse(only)` (no more `isLoadingServers = true` there, it never went false); then `guard !Task.isCancelled else { return }` and `serversTaskFinished()`.
- `applyServers`: delete `serversTask = nil` and `isLoadingServers = false`. `resolveAndUse`: delete the same two lines; keep `guard !Task.isCancelled else { return }` after the probe. Everything else (the address set, the `testConnection()`, the "kept" message, the log lines) is unchanged.
- `waitForServers()` is unchanged and still covers the whole chain, since the chain is one task.

Behaviour after the change: Forget during the auto-select probe cancels the task; `reachableConnection` sees its probes fail with `.cancelled`, returns nil, `resolveAndUse` returns on `Task.isCancelled`, the address stays empty and no connection test starts without a token. Closing Settings during Choose Server or Use does the same.

### 3. `PlexServerResolver` and `PlexResource` (`PlexServerResolver.swift`, `Models/PlexResource.swift`)

```swift
extension PlexResourceConnection {
    /// The ranking tier `PlexResource.rankedConnections` uses, best first.
    public enum Tier: Int, Comparable, Sendable {
        case localHTTPS, remoteHTTPS, relay, http
        public static func < (a: Tier, b: Tier) -> Bool { a.rawValue < b.rawValue }
        /// "local https", "remote https", "relay", "http": for logs; never an address.
        public var name: String { … }
    }
    public var tier: Tier { !isHTTPS ? .http : relay ? .relay : local ? .localHTTPS : .remoteHTTPS }
}
```

`rankedConnections` sorts on `a.element.tier < b.element.tier` instead of the private `tier()` function; the order does not change (the existing test pins it). `reachableConnection`: before `guard let best`, `if Task.isCancelled { log.info("server: cancelled"); return nil }` (a cancelled probe is not "none reachable"); then `log.info("server: resolved \(connection.tier.name, privacy: .public), rank \(best + 1) of \(ranked.count)")`. Tier names are fixed strings, not addresses, so nothing new reaches the log. This also makes manual check 4 in #0014 ("remote or relay won") readable in Console without logging the host.

### 10. Risks

- **`stopLoading` on cancel.** The cancelled-load record relies on `URLSession` calling `stopLoading` on a custom protocol whose load is held when the task is cancelled; that is the documented purpose of `stopLoading`, and the stub's existing `stopped` gate was built on it. Test 4 proves it on its own before the model test depends on it. If it ever fails, the fallback is a timing proof like #0058's: `cancelServers()` leaves the cancelled task in `serversTask` (clearing `isLoadingServers` only), the task's finish clears the field only when not cancelled, and the test asserts `waitForServers()` returns in under 5 s against the 60 s gate.
- **`stopLoading` after normal completion.** It is also called when a load finishes, so a raw count would overstate cancels; the `delivered` flag inside the same lock is the distinction, and test 4's second half checks it.
- **Redaction rule scope.** Only `/api/v2/pins/<id>` is redacted; `/library/metadata/<ratingKey>` and friends stay readable on purpose (they are what a debug log is for). A new secret-bearing path needs a rule, and the doc comment on `logDescription(of:)` says so; the review grep on `privacy: .public` catches a stray raw path.
- **`Tier` is new public API.** Small, `String`-backed, and the ranking order is pinned by the existing test; the log is the only consumer besides the sort.
- **`isLoadingServers` during auto-select** stays `true` across the whole chain instead of flipping false and back within one main-actor turn; no observer can tell the difference, and `canChooseServer` is correctly off throughout.
- **A stalled guest** can delay the held probes reaching `startLoading`, which only lengthens the bounded 5 s waits on positive conditions; nothing in the test depends on a request *not* arriving within a window.
