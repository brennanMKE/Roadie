## Description

Found in the #0093 implementation and review (commit d890d3d). `CountingRenderer` in the SkinLibrary test support calls a blocking `Latch.wait()` inside the thumbnail cache's `Task.detached` render jobs, so each blocked render holds a cooperative-pool thread until its test opens the latch. Five `SkinThumbnailCacheTests` together can hold up to 6 blocked threads (`rendersAreBoundedAndOffMain` 2; `newestRequestRendersFirst`, `cancelledBeforeStartIsDropped`, `cancelledAfterStartStillCaches`, `secondCallerKeepsAQueuedJobAlive` 1 each), which is exactly the guest's pool width. If they all block before any test body resumes, the test process hangs at 0% CPU with no time limit; on a machine with fewer cores the risk is higher. During #0093 a similar pile-up (with the old `StubIngester` gate) did hang a fast-tier run.

Expected: no test blocks a cooperative-pool thread while waiting for another test step (use async gates, continuations or a dedicated thread for the renderer stub), or the suite is `.serialized` with a `.timeLimit` so a hang fails fast instead of stalling the VM run. Coverage of ordering, cancellation and bounded concurrency stays the same.

## Plan

**Why the stub can't just move to another thread.** `SkinThumbnailCache`'s injected `render` is a synchronous `@Sendable (URL) throws(SkinError) -> CGImage`, called from `produce` inside the job's `Task.detached`. Whatever a synchronous stub does, the pool thread that called it stays blocked until it returns. Handing the wait to a dedicated `Thread` doesn't help, because the caller still has to block until that thread finishes. The real fix is to let the render closure suspend instead of block. `.serialized` alone only caps the blocked threads at 2 and still blocks the pool, so it is not the fix.

### 1. Make the injectable render async (production, small)

`Packages/SkinKit/Sources/SkinLibrary/Thumbnails/SkinThumbnailCache.swift`:

- `private let render: @Sendable (URL) async throws(SkinError) -> CGImage`, and the same type on the `init` parameter. Keep the default `= SkinThumbnailCache.renderIdle`; a sync function converts implicitly to the async function type, so `App/PlayerModel.swift` (default renderer) and the QuickLook code are unaffected. Check with `grep -rn "SkinThumbnailCache(" App Packages QuickLook`; today only the app and the tests construct it.
- `produce(...)` becomes `private nonisolated static func produce(...) async -> Outcome` and calls `try await render(url)`. In `startJob`, use `let outcome = await Self.produce(...)`. Leave everything else as it is: `gate.acquire` before produce, `gate.release()` after, and `jobStarted`/`jobFinished` around them. The render slot is held across the suspension, so bounded concurrency means the same thing as before. Nothing in production awaits inside the default renderer, so its behaviour doesn't change. Started jobs are never cancelled (`callerCancelled` only cancels when `!started`), so the render's await never sees cancellation.
- Update the `render` doc line ("injectable for tests; may suspend").

### 2. Replace the blocking `Latch` with an async gate (tests)

`Packages/SkinKit/Tests/SkinLibraryTests/ThumbnailTestSupport.swift`:

- Replace `Latch` (the `NSCondition` wait) with `AsyncLatch: @unchecked Sendable`: an `NSLock`, `isOpen`, and `[CheckedContinuation<Void, Never>]`. `func wait() async` returns at once if it's open; otherwise it appends the continuation under the lock (`withCheckedContinuation`). `func open()` sets `isOpen`, takes the waiters under the lock, and resumes them outside it. No cancellation handler is needed, since started renders are never cancelled. Resume outside the lock, and never call a continuation twice.
- `CountingRenderer`: `init(latch: AsyncLatch? = nil, …)`. `closure` becomes `@Sendable (URL) async throws(SkinError) -> CGImage { url in await self.render(url) }`. `render` becomes `async`: the existing `lock.withLock { … }` bookkeeping (start, `_current`/`_max`, `Thread.isMainThread`, which stays inside the sync closure because some `Thread` APIs are unavailable from async contexts), then `await latch?.wait()`, then the decrement/finish bookkeeping. `maxSimultaneous` still measures renders between start and finish, so the bound check is unchanged.
- Remove `Latch` once nothing references it (`grep -rn "Latch" Packages`; today only these two files).

### 3. Tests: same assertions, plus a backstop

`Packages/SkinKit/Tests/SkinLibraryTests/SkinThumbnailCacheTests.swift`:

- `@Suite(.timeLimit(.minutes(1))) struct SkinThumbnailCacheTests`. One minute is the smallest unit `.timeLimit` takes, and the suite runs in about a second. This is only a backstop: a time limit can't fire if the pool is fully blocked, which step 2 prevents. Don't add `.serialized`; once nothing blocks, parallel runs are fine and still exercise the cache.
- In the five latched tests, swap `Latch()` for `AsyncLatch()` and add `defer { latch.open() }` right after creating it. Then a failing `#expect`/`#require`, or the time limit, can't leave parked renders behind. `open()` is idempotent. Keep each explicit `latch.open()` where it is, since the ordering depends on it.
  - `rendersAreBoundedAndOffMain`: unchanged. `started.count == 2 && queued == 10`, `running == 2`, then open; `maxSimultaneous == 2`, 12 started, `!sawMainThread`.
  - `newestRequestRendersFirst`: unchanged; the holder parks on the async latch while a, b and c queue. Expect `["holder.wsz", "c.wsz", "b.wsz", "a.wsz"]`.
  - `cancelledBeforeStartIsDropped`, `cancelledAfterStartStillCaches`, `secondCallerKeepsAQueuedJobAlive`: unchanged except the latch type. Cancellation goes through `RenderQueue.acquire`/`callerCancelled` exactly as before.
- `failedSkinIsNegativeCachedInMemoryAndOnDisk` and `clearForgetsMemoryAndNegatives` pass sync `counting` closures typed `@Sendable (URL) throws(SkinError) -> CGImage`. Either keep them (they convert implicitly at the `render:` argument) or change the annotation to `async throws(SkinError)`. Both compile; prefer leaving them alone.
- `waitUntil` already polls with `Task.sleep`, so it stays.
- Optional, while editing `TestSupport.swift`, the #0093 review nit: move the `/// An ingester that costs nothing…` doc comment from `LockedBox` back to `StubIngester`.

### 4. Let `--stress` loop SkinKit tests (scripts)

`scripts/stress-realtime-gapless.sh` hardcodes `--package-path Packages/PlayerKit`, so `--stress-filter 'SkinThumbnailCacheTests'` would match nothing, and every iteration would be counted as "did not run". Small change:

- `scripts/stress-realtime-gapless.sh`: take a 4th argument, `PACKAGE` (default `PlayerKit`, also from `$STRESS_PACKAGE`), and use `--package-path "Packages/$PACKAGE"`. Print `stress: package $PACKAGE` next to the filter line. Keep `AUDIOCORE_REALTIME=1` only for the default filter.
- `scripts/run-tests-vm.sh`: add `--stress-package NAME` (`SkinKit` or `PlayerKit`, default `PlayerKit`; reject anything else; error without `--stress`; include it in the `--build-only` refusal list). Pass it as the 4th argument. Name the step `${STRESS_PACKAGE:l}-stress` (`skinkit-stress` / `playerkit-stress`). The step already runs after both test steps against the `--build-tests` binaries, so placement doesn't change. When there's no filter, keep passing an empty 3rd argument so the 4th lands in position: `"${(q)STRESS_FILTER:-}"` or an explicit `''`. Watch the zsh quoting. Update the usage header.
- `docs/testing-in-vm.md`: one quick-start line (`--stress 50 --stress-filter 'SkinThumbnailCacheTests' --stress-package SkinKit --load`) and a mention in "How a run works" step 7.

## Root cause

`SkinThumbnailCache`'s injectable `render` was synchronous, so the test stub `CountingRenderer` could only wait for its `Latch` by blocking (`NSCondition.wait`) inside the job's `Task.detached`. Each parked render held a cooperative-pool thread; the five latched tests together could park up to 6, the guest's pool width, and nothing could then resume to open the latches.

## Fix

As planned. `render` is now `@Sendable (URL) async throws(SkinError) -> CGImage` and `produce` is `async` (`try await render(url)`; `startJob` awaits it). The default `renderIdle` is sync and converts implicitly, so `App/PlayerModel.swift` and app behaviour are unchanged; the render slot is still held across the call. In the tests, `Latch` is replaced by `AsyncLatch` (lock + continuations, resumed outside the lock, idempotent `open`), `CountingRenderer.render` is async and awaits it, every latched test adds `defer { latch.open() }`, and the suite has `.timeLimit(.minutes(1))` (no `.serialized`). The optional `TestSupport.swift` doc-comment nit was not done.

Scripts: `stress-realtime-gapless.sh` takes a 4th argument / `$STRESS_PACKAGE` (default `PlayerKit`) and prints `stress: package …`; `run-tests-vm.sh` adds `--stress-package SkinKit|PlayerKit` (rejects other values, needs `--stress`, refused with `--build-only`) and names the step `skinkit-stress`/`playerkit-stress`. Small deviation: the plan's `${(q)STRESS_FILTER:-''}` produces a literal `\'\'` (a filter of two quote characters) when the filter is empty, so the script builds `stress_filter_arg` (`''` or `${(q)STRESS_FILTER}`) first.
