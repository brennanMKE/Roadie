## Root cause

## Fix

`scripts/record-ma-fixtures.py`: the §1.5 reads added to `ALLOWED` and the default run; opt-in `--record-playlist-writes` with its own `ALLOWED_WRITES`, a throwaway `SkinAmp fixture <run-id>` playlist, favorite add/remove only when the track was not a favorite, `finally` deletion, and `events-playlists.json`; the default run keeps the writes files; `--check` also checks fixture shape; `--help`. `MAFixture` gains the 21 new cases plus `baseline`, `recorded`, `isRecorded` and `recommendationItems(row:)`; tests iterate recorded files only. Notes §14 in `docs/ma-protocol-notes.md`.

Second pass (review notes 1–5 and the §14 update):
- `git rm` of the committed `.pyc`; `.gitignore` gains `__pycache__/` and `*.pyc`.
- The writes steps and cleanup move into `run_playlist_writes` / `cleanup_playlist_writes`, which a fake Session can drive.
- `answered(rc)` treats an error frame or an empty reply as a failure, so a failed or timed-out delete prints `CLEANUP FAILED (...): delete the playlist named '<name>'`.
- Cleanup catches `BaseException` per step, prints the message, finishes the remaining steps, then re-raises an interrupt.
- `fav_added` is set before the add is sent (cleared only on an error frame) and `fav_removed` only on a successful remove; cleanup removes the favorite first and on failure prints `CLEANUP FAILED (...): un-favorite the track '<track name>'`.
- `create_sent` is set before the create; with no playlist id learned, cleanup prints `CLEANUP FAILED: the playlist named '<name>' may exist; delete it in the Music Assistant UI`.
- §14 describes the cleanup order, both failure messages and the test.

## Review notes

2026-10-21, bounced. The read captures, the allowlist split (`ALLOWED_WRITES` reachable only with `--record-playlist-writes`), the writes touching only the created `playlist_id`, the secret gate (new files land in `FIXTURE_REL`, covered by `owned_files` and the writes run's own `gate`), and the default run keeping `WRITE_FIXTURES` are all fine. Verification at HEAD: VERIFY PASS (exit 0) 20261021-011116-38779, 8 steps passed, 1458 tests in 14 test runs; TIER fast; AUDIO silent; EXPECT all 1 expected test(s) passed. Change these before the user runs it against their server:

1. **Remove the committed bytecode.** `eab1fd4` added `scripts/__pycache__/record-ma-fixtures.cpython-315.pyc`. `git rm` it and add `__pycache__/` (and `*.pyc`) to `.gitignore`.
2. **Treat a server error or a timeout on the delete as a cleanup failure.** `Session.call` never raises on an error frame or an empty reply, so `playlist-delete` failing on the server only prints `note: ... error frame`. After the delete, if `is_error(rc)` or `rc["frames"]` is empty, print `CLEANUP FAILED ... delete the playlist named '<name>'`.
3. **Catch Ctrl-C in cleanup.** The `finally` runs on Ctrl-C, but its `except Exception` around the delete misses a second `KeyboardInterrupt` (or any `BaseException`) during the delete, so `CLEANUP FAILED` is never printed. Use `except BaseException` there (and for the favorite restore below), print the message, then let the interrupt continue.
4. **Restore the favorite in `finally`.** If `favorite-add` succeeded and `favorite-remove` then fails, times out, returns an error frame or is interrupted, the track stays a favorite and nothing is reported. Record `favorite_added = True` after a successful add; in `finally` (before the playlist delete), if it was added and not yet removed, send `music/favorites/remove_item` and, on failure (exception, error frame, no frames), print `CLEANUP FAILED ... un-favorite the track '<track name>'`.
5. **Report a playlist whose id was never learned.** If `create_playlist` times out, returns an unexpected shape, or is interrupted after it was sent, `playlist_id` stays `None` and the `finally` silently does nothing, though the server may have created it. Set a `create_sent` flag before the call; in `finally`, if it was sent and `playlist_id is None`, print `CLEANUP FAILED: the playlist named '<name>' may exist; delete it in the Music Assistant UI`.

Update the §14 notes in `docs/ma-protocol-notes.md` to mention the favorite case of `CLEANUP FAILED`.
