# 0124 — Library subtitle shows the server address and why it was chosen

| | |
|---|---|
| **Status** | open |
| **Module** | App / LibraryBrowser / MusicAssistantKit |

| **First seen** | 2026-10-20 |

## Description

Reported by the user on 0.1.0-c87a381. After #0119, the Library window's subtitle reads "Music Assistant · <server IP address> — first reachable". The address and the selection reason ("first reachable", from `MusicAssistantServerRanking.reason`) are diagnostic details the user doesn't need in the window header. (The user's screenshot isn't attached because it shows the server's address.)

## Expected behavior

- The Library subtitle names only the source: "Music Assistant". When the chosen server has a real (non-generic) name and more than one server is configured, it may add that name ("Music Assistant · Home"); it never shows a host, IP address or the selection reason.
- The address and the reason stay available where diagnostics belong: Settings › Music Assistant (the server list and its status line), unchanged.
- The local-folder source's subtitle is unaffected.

## Plan

**Where the text comes from.** `App/Browser/LibraryWindowView.swift` `subtitle` = `FallbackText.subtitle(fallback.status)` ("Music Assistant", or "X (Y unavailable)") + " · " + `player.musicAssistantSelection.statusText`. `MusicAssistantSelectionController.statusText` is "Finding a server…" or `reasonText`, which is `MusicAssistantServerRanking.reason(for:)`: `"\(displayName) — first reachable"` / "— on network X" / "— via Tailscale", or the none-reachable texts. `displayName` falls back to the host for a generic name (#0119), so the subtitle shows an address. Settings uses the same text in two places: `App/Settings/MusicAssistantSettingsView.swift:50` (`reasonText`, `ma.reason`) and `App/Settings/LibrarySettingsView.swift:26` (`statusText`, `library.maReason`).

**Change.** Leave `reason(for:)`, `reasonText`, `statusText` and both Settings sites as they are. Give the Library its own label:

1. `MusicAssistantServerRanking.libraryLabel(for server: MusicAssistantServerConfiguration?, serverCount: Int) -> String?`: the trimmed `server.name` when `server` is non-nil, `serverCount > 1` and `!MusicAssistantServerConfiguration.isGenericName(server.name)`; else nil. Never the host, never `displayName`.
2. `MusicAssistantSelectionController`: `public private(set) var libraryName: String?` (UI only, never logged). Set it in `apply` from `winner?.server` and `resolvedServers?.count ?? 0` (nil when there is no winner), and in `relabel(from:)` from `updated` and `servers.count`, so a rename shows up.
3. `LibraryWindowView.subtitle`: `base`, plus `" · " + name` only when Music Assistant is the selected source and `libraryName` is non-nil. Drop the `statusText` use and update the doc comment. The folder source keeps `base`.

**Files.** `Packages/PlayerKit/Sources/MusicAssistantKit/MusicAssistantServerRanking.swift`, `MusicAssistantSelectionController.swift`, `App/Browser/LibraryWindowView.swift`; tests below.

**Tests** (Swift Testing, fast tier; made-up names and hosts only, such as "Home", "a.local"):
- `ServerRankingTests.swift`: `libraryLabelShowsOnlyARealNameWithSeveralServers`: "Home" with 2 servers gives "Home"; "Home" with 1 gives nil; a generic name ("Music Assistant", "Music Assistant (abc123)", nil/blank) with base URL `http://a.local:8095` and 2 servers gives nil; nil server gives nil. `reasonTexts` and `reasonTextNamesTheHostWhenTheNameIsGeneric` stay unchanged and passing.
- `SelectionControllerTests.swift`: `libraryNameFollowsTheWinner`: with two servers named "A" and "B" and "A" reachable, `libraryName == "A"` while `reasonText` still reads "A — first reachable"; with a single server, `libraryName == nil`; after a rename through `serversEdited()`, `libraryName` follows. Existing `reasonText`/`statusText` tests stay unchanged.

**Tier:** fast. Nothing under `SkinLibrary/` or AudioCore real-time code.
