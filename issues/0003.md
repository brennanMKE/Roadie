# 0003 — Tracks do not play back to back without a gap

| | |
|---|---|
| **Status** | open |
| **Module** | AudioCore |
| **Platform** | macOS |
| **First seen** | 2026-10-12 |

## Description

Schedule the next queued file on the player node before the current one ends so consecutive tracks play gaplessly.

## Acceptance criteria

- Current-track state advances when the scheduled buffer completes.
- Skipping or reordering the queue cancels the pre-scheduled file correctly.

## Plan

Written before #0002 landed. Everything below is designed against the architecture #0002 describes (`Packages/PlayerKit`, `AudioCore` library, `AVAudioPlayerNode` → `AVAudioUnitEQ` → main mixer). Where this plan names a #0002 type, treat the name as a placeholder and adapt to what actually exists — the *shape* is what matters.

### Design

Two new pieces in `Packages/PlayerKit/Sources/AudioCore/`:

1. **`GaplessScheduler`** (pure Swift, `struct`, no AVFoundation import, fully unit-testable). Owns the *decisions*: what is scheduled, which completion callbacks are still valid, where each item starts on the node's sample timeline, and what to do when an item finishes.
2. **Engine adapter code in the existing player class** that turns scheduler decisions into `AVAudioPlayerNode` calls and feeds callbacks back in.

```swift
/// One scheduled file on the player node.
struct ScheduledItem: Equatable, Sendable {
    let token: ScheduleToken
    let trackID: Track.ID
    let startFrame: AVAudioFramePosition   // node timeline, in *connection* sample rate frames
    let frameLength: AVAudioFramePosition  // in connection sample rate frames (after SRC if any)
    let fileSampleRate: Double
    let seekOffsetFrames: AVAudioFramePosition // 0 for a whole-file schedule; the segment start for a seek
}

struct ScheduleToken: Hashable, Sendable {
    let generation: UInt64   // bumped on every discontinuity
    let sequence: UInt64     // monotonically increasing per schedule call
}

struct GaplessScheduler: Sendable {
    private(set) var generation: UInt64 = 0
    private(set) var items: [ScheduledItem] = []   // items[0] is the one audibly playing
    var currentTrackID: Track.ID? { items.first?.trackID }

    /// Call before every player.stop() (seek, skip, stop, reorder, play-new). Returns nothing; stale callbacks compare against `generation`.
    mutating func invalidate()

    /// Records a schedule and returns the token to capture in the completion closure.
    mutating func append(trackID:, frameLength:, fileSampleRate:, seekOffsetFrames:) -> ScheduledItem

    enum CompletionOutcome: Equatable { case stale, advanced(to: Track.ID), reachedEnd }
    /// Called (on the main actor) from the .dataPlayedBack completion handler.
    mutating func complete(_ token: ScheduleToken) -> CompletionOutcome

    /// Position of the audible item, in seconds of the *file*, for a node sample time in connection frames.
    func position(atNodeSampleTime:, connectionSampleRate:) -> TimeInterval
}
```

Use `AVAudioFramePosition` as a plain `Int64` typealias in the pure type (or just `Int64`) so the file needs no AVFoundation import.

### How the next file is scheduled

In the engine adapter, one private method does every schedule — whole file or segment — so bookkeeping can't drift:

```swift
@MainActor
private func schedule(_ file: AVAudioFile, track: Track, fromFrame start: AVAudioFramePosition = 0) {
    let frames = file.length - start
    let item = scheduler.append(trackID: track.id,
                                frameLength: convertedLength(frames, from: file.processingFormat.sampleRate),
                                fileSampleRate: file.processingFormat.sampleRate,
                                seekOffsetFrames: start)
    let token = item.token                        // Sendable value; never capture `file` or `self` strongly
    player.scheduleSegment(file, startingFrame: start, frameCount: AVAudioFrameCount(frames), at: nil,
                           completionCallbackType: .dataPlayedBack) { [weak self] _ in
        Task { @MainActor [weak self] in self?.handleCompletion(token) }
    }
}
```

- `at: nil` means "immediately after whatever is already scheduled", which is exactly the gapless case: the node plays queued files back to back with no silence as long as it is never stopped between them.
- Use `scheduleSegment` for everything (a whole file is `start = 0, frameCount = file.length`); `scheduleFile` is the same call with less control.
- `completionCallbackType: .dataPlayedBack` fires when the *last frame has been rendered to the output*, i.e. when the listener has heard the end. `.dataConsumed` fires much earlier (when the node has finished *reading* the file into its internal buffers) and must not drive the track-change — the UI would flip to the next title seconds before the song ends. (`.dataRendered` is the pre-mixer variant; also too early for the marquee, but close.)
- **When to pre-schedule the next track:** right after the current track starts (in `play(track:)` and after every seek), call `scheduleNextIfNeeded()`:
  1. `queue.peekNext()` → nil ⇒ nothing to do (queue end handling below).
  2. Resolve the track's source to a local `AVAudioFile`. In M1 only `.file(URL)` resolves; a Plex track that is not cached yet is "unavailable" — skip pre-scheduling and let the completion path start it with a gap (TrackCache prefetch in M2 makes this rare). Put this behind a small `TrackFileResolver` protocol (`func localFile(for: Track) async throws -> AVAudioFile`) so M2 can plug in the cache.
  3. Check the format policy (below). If the next file can't play on the current connection, don't pre-schedule; mark `pendingReconnect`.
  4. Otherwise `schedule(nextFile, track: next)`. Guard with `scheduler.items.count < 2` — never more than one item ahead; a deeper look-ahead makes every reorder cost a restart.
  Opening `AVAudioFile` is disk I/O; do it in a `Task.detached` and hop back, re-checking the generation afterwards (the user may have skipped while the file was opening).

### Advancing current-track state and the time offset

The node's sample timeline (`player.playerTime(forNodeTime: player.lastRenderTime!)?.sampleTime`) runs continuously from the last `player.play()` after a `stop()`, in the *connection* sample rate. Each `ScheduledItem.startFrame` is the previous item's `startFrame + frameLength` (0 for the first item after a stop). So:

- **Position (UI tick, ~10–30 Hz):** `position = seekOffset/fileRate + (nodeSampleTime − items[0].startFrame) / connectionRate`. Clamp at the item's length. This stays correct at the boundary *before* the callback arrives, because it's computed from frame counts, not from callback timing.
- **On `.dataPlayedBack` for `items[0]`:** `scheduler.complete(token)` drops `items[0]`; the next item becomes head and its `startFrame` becomes the time origin. The adapter then: `queue.next()` (mutating advance) and assert the queue's new current `id == outcome.advanced(to:)`. If they disagree (queue changed between pre-schedule and completion in a way reconcile missed), treat as a discontinuity: `restart(from: queue.current, at: 0)`. Then `currentTrack = …`, post the change for the UI/Now Playing, and call `scheduleNextIfNeeded()` again to keep one item ahead.
- `lastRenderTime` is `nil` while the node is paused or stopped — cache the last computed position and show that.

### Generation / token scheme (stale callbacks)

`AVAudioPlayerNode.stop()` **calls the completion handlers of every scheduled item it discards**. Every seek, skip, explicit stop, format reconnect and queue-reorder restart therefore produces one or two callbacks that must be ignored, and because they arrive asynchronously they can land *after* the new schedule was made. Hence the two-part token:

- `invalidate()` bumps `generation` and clears `items`. Call it **immediately before** every `player.stop()`, on the main actor.
- `complete(token)`: if `token.generation != generation` → `.stale`. If it matches but `token != items.first?.token` (shouldn't happen; defensive) → also `.stale`, log it. Otherwise pop the head and return `.advanced(to:)` or `.reachedEnd` (nothing left in `items`).
- The check runs *after* hopping to the main actor, against the generation at that moment, so a callback that was already in flight when `invalidate()` ran is correctly discarded.

Discontinuities that must `invalidate()` → `player.stop()` → reschedule:

| Event | After stop |
|---|---|
| `play(track:)` on a new track / double-click in playlist | schedule the track from 0, `play()`, `scheduleNextIfNeeded()` |
| `next()` / `previous()` | `queue.next()` / `previous()`, then as above |
| `seek(to:)` | schedule current from the target frame (`seekOffsetFrames`), `play()` if it was playing (if paused, schedule but don't `play()`), `scheduleNextIfNeeded()` |
| `stop()` | nothing scheduled; `playbackState = .stopped`, position 0 |
| queue mutation (reorder, remove, insert, shuffle/repeat toggle) | see reconcile below |
| format reconnect | reconnect nodes, schedule next from 0, `play()` |

`pause()` does **not** invalidate — `player.pause()` keeps scheduled items, and `play()` resumes them gaplessly.

**Queue mutation — `reconcile()`**: the node cannot drop only the *second* scheduled item, so on every queue change compare `queue.peekNext()?.id` with `scheduler.items.dropFirst().first?.trackID`:
- equal (or both nil) → nothing to do (reorders beyond the next slot, repeat-mode changes that don't alter the next track).
- different → the pre-scheduled file is wrong. Capture the current position, `invalidate()`, `player.stop()`, re-schedule the *current* track from that frame, `play()` if it was playing, then `scheduleNextIfNeeded()`. This is a few-millisecond restart of the current track during a user edit — acceptable; the common case (editing further down the list) costs nothing.
- if the *current* track itself was removed → behave like `next()` (or `stop()` if the queue is empty).

Expose this as a pure function too (`SchedulingDecision.reconcile(queueNext:, scheduledNext:) -> .keep | .restartCurrent | …`) so it's testable.

### Queue end, repeat-one, repeat-all, shuffle

All of these fall out of `queue.peekNext()` — the scheduler never inspects repeat/shuffle itself:

- **Repeat off, last track:** `peekNext()` is nil → nothing pre-scheduled. On `.reachedEnd`: `playbackState = .stopped`, position 0, `currentTrack` stays on the last track (Winamp behaviour: the playlist highlight stays, the player stops). `player.stop()` + `invalidate()` so the timeline resets.
- **Repeat all:** `peekNext()` wraps to the first track → scheduled like any other.
- **Repeat one:** `peekNext()` returns the current track → schedule the *same file again*. Open a fresh `AVAudioFile` for each schedule rather than reusing the instance (an `AVAudioFile` carries a read position; `scheduleSegment` resets it, but a fresh handle is cheap and removes any doubt). Repeat-one ends only when the user acts.
- **Shuffle:** works if `peekNext()` is deterministic (precomputed order). Toggling shuffle on/off is a queue mutation → `reconcile()`.
- `previous()` with Winamp semantics (restart the current track if more than a few seconds in) is #0002's call; whatever it does, it goes through the discontinuity path.

### Format mismatches between consecutive files

The player node's output format is fixed at `engine.connect(player, to: eq, format:)` time. Rules (confirm empirically in the first test run — this is the most API-sensitive part of the issue):

- **Same sample rate and channel count** → gapless, nothing to do.
- **Different sample rate, same channel count** → `AVAudioPlayerNode` performs sample-rate conversion for *files* (not for buffers) when the file's `processingFormat.sampleRate` differs from the connection format. Schedule normally. Bookkeeping consequence: `frameLength` on the node timeline is `file.length × connectionRate / fileRate` (round to nearest); that's why `ScheduledItem` stores both. Position is still computed in file seconds.
- **Different channel count** (mono → stereo, 5.1) → not safely handled by the node; expect an exception or wrong channel mapping. Policy: **do not pre-schedule**; set `pendingReconnect = next`. On the current track's `.reachedEnd`, `invalidate()`, `player.stop()`, `engine.disconnectNodeOutput(player)`, reconnect `player → eq` (and `eq → mixer`) with the new file's `processingFormat`, schedule it from 0, `play()`. This introduces a small gap — unavoidable without converting audio ourselves — and happens only across channel-count changes, which are rare inside an album.
- Put the rule in a pure `FormatPolicy.compare(current: AudioFormatDescriptor, next:) -> .gapless | .gaplessWithSRC | .reconnectRequired` where `AudioFormatDescriptor` is `(sampleRate: Double, channelCount: UInt32)` so it's testable without AVFoundation.
- Optional follow-up (not this issue): true gapless across all formats by connecting the player at one canonical format (e.g. the output device's format, stereo float) and reading every file through `AVAudioConverter` into `AVAudioPCMBuffer`s scheduled with `scheduleBuffer`. Note it in `## Gotchas` if the channel-count gap is noticeable in practice.
- `engine.mainMixerNode` → output handles the final conversion to the device format, so a non-device-rate connection format is fine.
- `AVAudioEngineConfigurationChange` (device change, sample-rate change in Audio MIDI Setup) stops the engine and drops scheduled items. Minimal handling: observe the notification, treat it as a discontinuity (capture position, `invalidate()`, reconnect, reschedule current from that position, resume if it was playing). If #0002 already handles it, reuse that path.

### Threading

- Completion handlers run on an AVAudioEngine-internal queue, never on main. The closure is `@Sendable`; capture only the `ScheduleToken` (a `Sendable` value) and `[weak self]`, then `Task { @MainActor in ... }`. Do not touch the scheduler, the queue, or any `@Observable` state inside the closure itself.
- All `AVAudioPlayerNode` / `AVAudioEngine` calls happen on the main actor (serialises `invalidate()` with `stop()` and with the hopped callbacks). Swift 6 language mode is on (`project.yml`, `swift-tools-version: 6.0`): `AVAudioFile` is not `Sendable`, so a detached open must return it via an `nonisolated(unsafe)` box or by opening on main and accepting the small blocking read (files on local disk open in well under a frame; the detached open is an optimisation, not a requirement — pick the simpler one that compiles cleanly).
- The position tick reads `lastRenderTime` on main; it is cheap and thread-safe to call.

### Tests (no audio hardware required)

Use Swift Testing (`import Testing`, `@Test`, `#expect`) to match `Packages/SkinKit/Tests`. All of these exercise the pure types:

1. `completionAdvancesToNextItem` — append A (1000 frames) then B; `complete(A.token)` → `.advanced(to: B)`; `items.first?.startFrame == 1000`.
2. `positionAccountsForStartFrameAndSeekOffset` — after the advance, `position(atNodeSampleTime: 1500, …)` is 500 frames into B; with `seekOffsetFrames` set, the offset is added in file seconds.
3. `staleTokenIsIgnoredAfterInvalidate` — append A, `invalidate()`, append A′; `complete(A.token)` → `.stale` and `items` unchanged.
4. `stopFiresCallbacksForEveryDiscardedItem` (modelled) — append A, B; `invalidate()`; both tokens → `.stale`.
5. `lastItemCompletionReportsEnd` — single item → `.reachedEnd`, `items.isEmpty`.
6. `sampleRateConversionScalesFrameLength` — 48 kHz file on a 44.1 kHz connection: `frameLength == round(length × 44100/48000)`.
7. `formatPolicy` — same → `.gapless`; rate differs → `.gaplessWithSRC`; channels differ → `.reconnectRequired`.
8. `reconcileKeepsScheduleWhenNextUnchanged` / `reconcileRestartsWhenNextChanged` / `reconcileWithNothingScheduled`.
9. Queue-level (against #0002's `PlayQueue`): `peekNext()` matches a subsequent `next()` for repeat off at end (nil), repeat all (wraps), repeat one (same id), and shuffle (deterministic).

Optional, only if time permits and it proves stable: an offline-rendering integration test with `engine.enableManualRenderingMode(.offline, format:, maximumFrameCount:)`, two tiny generated WAVs written with `AVAudioFile(forWriting:)` into a temp directory, scheduled back to back, rendering with `engine.renderOffline` and asserting the rendered frame total equals the sum of both files and that both `.dataPlayedBack` callbacks fire in order. This runs without a device, but callback timing in manual rendering mode is not something to make the gate depend on — keep it `.enabled(if:)` an env var or drop it if flaky.

### Risks

- **`AVAudioPlayerNode` format handling is the thing most likely to differ from this plan.** Verify the sample-rate-conversion and channel-count behaviour with real files on the first run and adjust `FormatPolicy`; if SRC for files turns out not to be supported on macOS 14, move sample-rate mismatches into the `.reconnectRequired` bucket (gap, but correct).
- `stop()` invoking discarded completion handlers is documented but easy to forget — the generation check is the safety net; test 3 and 4 guard it. Without it, a skip produces a double advance.
- `.dataPlayedBack` fires a render quantum late; the frame-count position math keeps the display honest, but Now Playing / marquee updates lag by up to ~20 ms. Acceptable.
- The Plex path (uncached next track) degrades to a gapped start by design in M1; the plan's `TrackFileResolver` seam is what M2's prefetch plugs into — don't let it become Plex-aware here.
- Swift 6 strict concurrency with non-`Sendable` AVFoundation types can cost time; keep everything on the main actor and capture only tokens in closures.
- Output-device changes (`AVAudioEngineConfigurationChange`) silently kill the schedule; the minimal observer above is enough for M1 but should be noted in `## Gotchas` if it isn't fully handled.
