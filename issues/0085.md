## Description

The user asked to separate the fast tests from the slow tests and move the slow ones to the end of a milestone, so the per-issue VM run (`scripts/run-tests-vm.sh`) stays short and slow or timing-sensitive tests stop blocking every issue.

Measured on run `20261018-230644-6308` (the #0084 implementation), test execution was about 37 s, and these few tests account for most of it:

| Test | Time | Why it is slow |
|---|---|---|
| `SkinIndexScaleTests.hundredThousandStubFilesIndexAndReindexIncrementally` | 23.4 s | writes 100,000 real files and indexes them into SQLite; guards the brief's 100k-skin criterion; asserts counts only |
| `MixedFormatTests.mixedFormatsAdvanceWithoutGapRealtime` | 3.0 s | real-time audio (muted), opt-in through `AUDIOCORE_REALTIME=1`, which the script always sets; has been flaky (#0055) |
| `ProgressiveRealtimeTests.progressiveTrackAdvancesToTheNextFileRealtime` | 1.9 s | real-time audio, same gate |
| `OutputDeviceRealtimeTests` | — | real-time audio, same gate |

Everything else (about 1,000 tests across 14 test runs) takes about 14 s combined; most targets finish in under 0.3 s. `ftsSearchOnHundredThousandRowsIsFast` is another 100k-row scale check to classify.

Expected:

- A **fast tier** (the default, run per issue by the implementer and the reviewer) that excludes the slow tests.
- A **full tier** (an explicit flag, for example `--full`) that adds the slow tests: the scale tests, the real-time audio tests, and anything else the plan classifies as slow. The real-time tests keep their existing `AUDIOCORE_REALTIME` gate; the scale tests get an equivalent opt-in (env var or a Swift Testing tag the script enables), so `swift test` on its own stays fast too.
- The script's summary says which tier ran.
- `issues/Issues.md` and `docs/testing-in-vm.md` describe the tiers: phases 2 and 3 run the fast tier, plus the full tier only when an issue touches the code a slow test guards (for example `SkinLibrary` indexing or AudioCore playback). At the end of each milestone (when its last child is resolved), the orchestrator runs the full tier once; any failure becomes a new cleanup issue under that milestone, not a reopen of a resolved child.

Out of scope here: moving `--launch` / Quick Look to the milestone tier, build caching, a build-only fast-fail stage, and the flaky-test fixes (#0083) — each can follow separately.

### Classification (from run `20261018-230644-6308`)

| `MixedFormatRealtimeTests.mixedFormatsAdvanceWithoutGapRealtime` | 3.0 s | **full** | Real-time audio, flaky under load (#0055) |

| `NowPlayingTests.autoAdvanceUpdatesInfoCenterAndAttachesArtwork` | 2.3 s | **full** | Real-time audio. It uses the same `RealtimeAudio.isAvailable` gate; the description's table missed it. |
| The other `SkinLibraryTests` (indexer, store, thumbnail cache), 14–18 s each | ~14 s | fast | They index 50–200 stub files, with injected delays of at most about 1 s. Almost all of the 14 s is waiting behind the two scale tests on disk and SQLite. |

| PlayerKit tests at ~1–1.9 s (MusicAssistantKit timeouts, Plex resolver debounce, sign-in cancel) | ≤ 1.9 s | fast | They wait on short timers by design, and each target's run finishes in 2 s or less. |

The real-time gate already gives you the full/fast split for AudioCore: `RealtimeAudio.isAvailable` (`MixedFormatTests.swift`) is false unless `AUDIOCORE_REALTIME=1`. Today the fast tier is lost only because `run-tests-vm.sh` always sets that variable.

### Mechanism: env vars, not tags

Use an env-var gate like the existing one. Plain `swift test` stays fast with no flags (both variables unset). The script only adds a prefix. Tag filtering in SwiftPM's CLI goes through `--filter`/`--skip` regexes on test names, and a name regex would be brittle to keep in sync. A gated test still prints `➜ Test <name>() skipped.`, so a log shows by name whether it ran.

- New variable **`SKINAMP_SLOW_TESTS=1`** turns on the scale tests. In `SkinIndexScaleTests.swift`, add:

  ```swift
  /// Opt-in: the 100k scale checks run only in the VM's full tier (`scripts/run-tests-vm.sh --full`, #0085).
  enum SlowTests { static let isEnabled = ProcessInfo.processInfo.environment["SKINAMP_SLOW_TESTS"] == "1" }
  ```

  Put `.enabled(if: SlowTests.isEnabled)` on **each** of the two `@Test`s, next to the existing `.timeLimit(.minutes(5))`, rather than on the suite. That way the log prints both test names as skipped. Update the suite's doc comment to say the tests are opt-in.
- The real-time tests are unchanged and keep `AUDIOCORE_REALTIME=1`. Only update the comment in `MixedFormatTests.swift` (`RealtimeAudio`) and in `ProgressiveRealtimeTests.swift` from "only the VM run sets" to "only the VM's full tier sets (`--full`)".
- `scripts/stress-realtime-gapless.sh` sets `AUDIOCORE_REALTIME=1` itself, so `--stress` keeps working in either tier. Do not change it.

### Expected savings

Test execution was about 37 s per run. The fast tier should drop `SkinLibraryTests` from 23.4 s to a few seconds, because the indexer tests stop queuing behind the 100k disk and SQLite work. AudioCore drops from 5.2 s to roughly 2–3 s, without the real-time tests and their engine start-ups. That is about 25 s less test time per run, so about 50 s per issue (phases 2 and 3), plus no exposure to the #0055 real-time flake on ordinary issues. Compile time is unchanged, since the slow tests still build. VM boot and the builds still dominate a run of several minutes. The full tier costs what a run costs today, and runs once per milestone plus on issues that touch the guarded code.

## Resolution notes

> 🟢 Resolved 2026-10-19 — `scripts/run-tests-vm.sh` now runs a fast tier by default and a full tier with `--full`; the reviewer's VM runs show the 8 slow tests skipped in fast and passing in full, with only the known #0083/#0088 flakes failing.

## Root cause

`scripts/run-tests-vm.sh` always ran every test: it set `AUDIOCORE_REALTIME=1` on the PlayerKit step unconditionally, and the two 100k `SkinIndexScaleTests` had no gate at all, so every per-issue run paid for the scale and real-time tests (and the #0055 real-time flake).

## Fix

As planned. `SkinIndexScaleTests.swift` gains a `SlowTests` gate (`SKINAMP_SLOW_TESTS=1`) applied with `.enabled(if:)` to each of the two tests. `run-tests-vm.sh` takes `--full`, which sets `TIER=full` and prefixes the SkinKit step with `SKINAMP_SLOW_TESTS=1` and the PlayerKit step with `AUDIOCORE_REALTIME=1`; the default is the fast tier with neither. It logs `Tier:` at the start, writes `tier.txt` to the results, and prints a `==> TIER` line after the PASS/FAIL lines. Comments in `MixedFormatTests.swift` and `ProgressiveRealtimeTests.swift` now say only the full tier sets the gate. `issues/Issues.md` and `docs/testing-in-vm.md` got the text changes from the plan.

Small deviations: the `MixedFormatTests.swift` comment did not contain the phrase "only the VM run sets", so the full-tier note was added to its first sentence instead. The `-h` range is `2,37p` (the header now ends at line 37; the old `2,38` already overshot into `set -euo pipefail`).
