# 0121 — SkinAmp doesn't follow or control Music Assistant playback it didn't start

| | |
|---|---|
| **Status** | open |
| **Module** | App / MusicAssistantKit / LibraryBrowser |
| **Platform** | macOS |
| **First seen** | 2026-10-20 |

## Description

Reported by the user on 0.1.0-2671617 (MacBook, Music Assistant source, a HomePod and This Mac as outputs).

1. Music was playing to a HomePod through Music Assistant. The user quit SkinAmp; the HomePod kept playing (expected: Music Assistant plays it server-side).
2. After installing and launching the new build, SkinAmp showed nothing of that playback and its transport couldn't stop it. Stop/Pause did nothing to the HomePod.
3. The user selected the same HomePod in Output and started playback to get control back.
4. Now music plays on both the Mac and the HomePod, badly out of sync, and Stop doesn't stop it at all.

Nothing coordinates playback between SkinAmp's local/This Mac player and Music Assistant's players: SkinAmp's UI and transport don't reflect what Music Assistant is actually doing.

## Expected behavior

- **At launch and on every (re)connect**, SkinAmp reads Music Assistant's players and queues and matches its UI: if a player is playing (or paused), the Output shows it, the main window shows its track, position and play state, and the transport controls it.
- **Stop, Pause, Play, Next, Previous and seek always act on what is actually playing**, wherever that is: the selected Music Assistant player (or group), or This Mac. Stop really stops: the speaker goes quiet.
- **Only one place plays a given queue.** Starting playback on This Mac stops or moves a Music Assistant player that was playing the same thing, and the reverse; SkinAmp never leaves the local player and a HomePod playing independently. Playing in sync across several outputs is #0118's grouping, not two independent players.
- The main window's state follows Music Assistant's events (another app or the MA web app pausing, skipping or changing output shows up in SkinAmp).
- **On Quit, SkinAmp tells Music Assistant to stop** the player(s) its transport currently targets: the selected speaker or group (a #0118 group's leader) and This Mac's own Music Assistant player when Music Assistant feeds it over Sendspin. The stop is sent before the app exits, but a dead connection never holds quitting up for more than about 1.5 s. A Settings › Music Assistant toggle, "Stop playback when SkinAmp quits", turns this off; it is on by default.
- Tests with the existing fakes cover: launch while a player is playing, stop while a remote player plays, starting on This Mac while a HomePod plays the queue, an external pause event, and quit (stop sent, timeout still terminates, toggle off sends nothing).

## Plan

### Root causes

1. **Nothing reads Music Assistant's state at launch, and Music Assistant isn't even connected at launch.** `selectedOutput` is not persisted and starts as `OutputDevice.thisMacID` (`App/PlayerModel.swift`), and `thisMacFeed` starts `.local`. The MA API connects only when the Library window appears (`LibraryBrowserModel`; `SendspinController` says "never at launch", `OutputPickerModel.notConnectedHint` says "Open the Library to connect"). The now-playing watcher for an output is idle while not connected (`MusicAssistantBackend.startWatcher`). Even once connected, the only MA state SkinAmp reads is the *selected* output's (`observeNowPlaying` → `nowPlaying(on: selectedOutput)`). Nothing looks at `players/all` / `player_queues/all` to see that another player is playing, so the HomePod's playback stays invisible.
2. **Transport goes only to `selectedOutput`, which at launch is This Mac on the local feed.** `send(_:)` yields `(command, selectedOutput)`. `router.backend(for: thisMacID)` with feed `.local` is the folder backend, so Stop and Pause go to AudioCore, which is idle. The HomePod is never addressed. Separately, `MusicAssistantBackend.transport` always sends `players/cmd/*` to the selected player's own id, even when that player is a synced member (`syncedTo`/`activeGroup` set) whose audio comes from another queue.
3. **Nothing enforces "one place plays".** Four code paths leave two places playing:
   - `onStreamStarted` sets the feed to `.musicAssistant` (Music Assistant starts SkinAmp's own player, from its web UI, a resume or a phone) without touching `selectedOutput`. If a speaker is selected, the Mac plays while the windows and transport follow the speaker.
   - `playFromLibrary` on a speaker never stops This Mac, whether it plays the local queue (AudioCore) or Music Assistant's queue over Sendspin.
   - Choosing an output only assigns `selectedOutput` (#0117). With 0117 planned, a local queue still `.keepLocal`s on This Mac while the speaker becomes the target.
   - Starting on This Mac never stops the speaker that was the target before.

   Steps 3–4 of the report are one of these. The HomePod played its own queue, and the Mac played either Music Assistant's queue for SkinAmp's player over Sendspin (the same album, so "out of sync") or the local queue. Stop then reached only one of them, the selected HomePod, so the Mac kept going. The code can't tell which of the two fed the Mac. The model below closes every path.
4. **Quit sends nothing to Music Assistant.** `applicationWillTerminate` flushes the queue and says the Sendspin goodbye (`SendspinController.shutdown`). A speaker keeps playing by design. Music Assistant's queue for This Mac's player is never stopped either, so it can resume on that player when SkinAmp reconnects.

### Ownership model: one target, adopted from Music Assistant, exclusive

- **`selectedOutput` stays the single target** (as in 0117 §6). Transport, now-playing, transfer and quit-stop all use it. For a #0118 group it is the leader, so stopping the leader stops the group.
- **SkinAmp adopts what Music Assistant is playing** in two cases. It does so by assigning `selectedOutput` (never `selectOutput`, so nothing is transferred).
  - On every `connected` (launch, reconnect, server change): if the target isn't playing, adopt the most recently updated **playing** leader, else a **paused** one.
  - On activity events: adopt only a leader that **changed into playing** while the target isn't playing (stopped or paused). A player already playing in another room never takes over a choice the user just made.

  SkinAmp's own Music Assistant player maps to This Mac. Adoption posts the notice "Output: <name>".
- **Exclusive start.** Whenever SkinAmp starts playback on the target, it stops SkinAmp's other place. Every SkinAmp-initiated start does this: library play, a local play, a Sendspin stream SkinAmp didn't ask for, and an adoption. The other place is This Mac if it makes sound and the target is a speaker, or the previous target if it still plays and isn't a member or leader of the new one. Unrelated players (another person's room) are never stopped.
- **Quit** stops the target (when it is a Music Assistant output) and This Mac's Music Assistant player (when the feed is `.musicAssistant`), with a 1.5 s cap.

The decisions are pure functions in `LibraryBrowser`, so tests need neither the app nor a network. The app only wires them in.

### Approach

1. **Activity model (MusicBackendKit).**
   ```swift
   /// One Music Assistant player's playback as SkinAmp sees it (#0121). SkinAmp's own player is `OutputDevice.thisMacID`.
   public struct OutputActivity: Hashable, Sendable {
       public var output: OutputDevice.ID
       public var name: String
       public var state: NowPlaying.State
       /// The group or sync leader this player plays as a member of; nil when it plays its own queue.
       public var leader: OutputDevice.ID?
       /// Server time of the last state or position change; for "most recent" when several play.
       public var updatedAt: Double?
   }
   ```

2. **Activity stream (MusicAssistantKit).** `public func playbackActivity() -> AsyncStream<[OutputActivity]>`, registered like `connectionStates()`, with its continuations held on the backend.
   - On every install of a client (`connect()`, after `restartWatchers()`) and on each `.connected` after `.reconnecting`, it runs one snapshot: `players/all` plus `player_queues/all` (`MARequest.playersAll()` / `.queuesAll()`, both already defined and both listed in `docs/ma-protocol/commands.json`).
   - It then follows `client.events()`. A `player_updated`, `queue_updated`, `player_added` or `player_removed` event (the names `MAEventMatch` already handles) schedules one debounced snapshot (`policy.refetchDebounce`). `queue_time_updated` is ignored.
   - It yields `[]` while disconnected (`disconnect()`, `stopWatchers()` paths).
   - Players from `players/all` also refresh the `players` cache.
   - The mapper `MAPlaybackActivity.map(players:queues:localClientID:)` is pure, in `MAPlaybackActivity.swift`:
     - It skips `enabled == false` and `hideInUI == true` players, except SkinAmp's own player (`hosts(sendspinClientID:)`), which maps to `OutputDevice.thisMacID`.
     - `leader = activeGroup ?? syncedTo`, when it differs from the player id.
     - `state = MANowPlayingMapper.state(player:queue:)`, using the queue whose `queueID == leader ?? playerID`.
     - `updatedAt = queue?.elapsedTimeLastUpdated ?? player.elapsedTimeLastUpdated`.

   Don't add a protocol requirement. The app holds the concrete `MusicAssistantBackend` (`musicAssistant`).

3. **Leader redirect in `transport`.** In `MusicAssistantBackend.transport`, for `.play/.pause/.togglePlayPause/.stop/.next/.previous/.seek/.setShuffle/.setRepeat`, send to `player.activeGroup ?? player.syncedTo ?? player.playerID` (the cached player; the selected output's watcher keeps it fresh through `cachePlayer`). Keep volume on the player itself. This needs no new command, and a stop on a member then stops the group's playback. If 0117's `playerID(for:)` has landed, build this on top of it.

4. **Decisions (LibraryBrowser, `PlaybackOwnership.swift`).**
   ```swift
   public enum PlaybackOwnership {
       public enum Trigger: Sendable { case connected, activityChanged(previous: [OutputActivity]) }
       /// The output to adopt, or nil to keep `selected`. `selectedState` is what the target plays now (AudioCore's
       /// state for This Mac on the local feed, else its `nowPlaying.state`).
       public static func adoption(selected: OutputDevice.ID, selectedState: NowPlaying.State,
                                   activity: [OutputActivity], trigger: Trigger) -> OutputDevice.ID? {
           if selectedState == .playing || selectedState == .loading { return nil }
           let leaders = activity.filter { $0.leader == nil && $0.output != selected }
           let newest: ([OutputActivity]) -> OutputDevice.ID? = { $0.max { ($0.updatedAt ?? 0) < ($1.updatedAt ?? 0) }?.output }
           switch trigger {
           case .connected:
               if let id = newest(leaders.filter { $0.state == .playing }) { return id }
               guard selectedState == .stopped else { return nil }
               return newest(leaders.filter { $0.state == .paused })
           case .activityChanged(let previous):
               let wasPlaying = Set(previous.filter { $0.state == .playing }.map(\.output))
               return newest(leaders.filter { $0.state == .playing && !wasPlaying.contains($0.output) })
           }
       }

       public enum Stop: Hashable, Sendable { case thisMacLocal, musicAssistant(OutputDevice.ID) }
       /// What to stop when SkinAmp starts playback on `target`. `thisMacSounding`: AudioCore plays, or a Sendspin stream runs.
       public static func stops(startingOn target: OutputDevice.ID, previous: OutputDevice.ID?, thisMacFeed: ThisMacFeed,
                                thisMacSounding: Bool, activity: [OutputActivity]) -> [Stop] {
           var result: [Stop] = []
           if target != OutputDevice.thisMacID, thisMacSounding {
               result.append(thisMacFeed == .musicAssistant ? .musicAssistant(OutputDevice.thisMacID) : .thisMacLocal)
           }
           if let previous, previous != target, previous != OutputDevice.thisMacID,
              let old = activity.first(where: { $0.output == previous }), old.state == .playing || old.state == .paused,
              old.leader != target, activity.first(where: { $0.output == target })?.leader != previous {
               result.append(.musicAssistant(previous))
           }
           return result
       }
   }
   ```

5. **Quit decision (LibraryBrowser, same file).**
   ```swift
   public enum QuitStop {
       public static let defaultsKey = "musicAssistant.stopOnQuit"
       public static let timeout: Duration = .milliseconds(1500)
       /// The Music Assistant outputs to stop on quit; empty when turned off or not connected.
       public static func targets(enabled: Bool, isConnected: Bool, selected: OutputDevice.ID,
                                  thisMacFeed: ThisMacFeed) -> [OutputDevice.ID] {
           guard enabled, isConnected else { return [] }
           var ids: [OutputDevice.ID] = []
           if selected != OutputDevice.thisMacID { ids.append(selected) }
           if thisMacFeed == .musicAssistant { ids.append(OutputDevice.thisMacID) }
           return ids
       }
       public enum Outcome: Equatable, Sendable { case sent, timedOut }
       /// Sends `.stop` to each target at once; returns when all are answered or `timeout` passes, whichever is first.
       @MainActor public static func run(_ targets: [OutputDevice.ID], on backend: any MusicBackend,
                                         timeout: Duration = timeout, clock: any Clock<Duration> = ContinuousClock()) async -> Outcome {
           guard !targets.isEmpty else { return .sent }
           return await withTaskGroup(of: Outcome?.self) { group in
               group.addTask { await withTaskGroup(of: Void.self) { inner in
                   for id in targets { inner.addTask { try? await backend.transport(.stop, on: id) } } }
                   return .sent }
               group.addTask { (try? await clock.sleep(for: timeout)) == nil ? nil : .timedOut }
               let first = await group.next() ?? .timedOut
               group.cancelAll()
               return first ?? .timedOut
           }
       }
   }
   ```
   Local AudioCore playback isn't Music Assistant's business. It ends with the process, as today.

6. **App wiring (`PlayerModel`).**
   - **Connect at launch.** After `selection.start()`, if `MusicAssistantServerStore.hasVerifiedServer(defaults: .standard)`, run `Task { _ = await selection.resolveNow(); try? await ma.connect() }`. `musicAssistantServerChanged` already disconnects and reconnects on a server change. Update the "never at launch" comments in `SendspinController` and `OutputPickerModel.notConnectedHint`'s callers: the Sendspin session now also starts at launch, since it follows `.connected`. This reads the token from the Keychain at launch. That is the cost of the expected behavior, and it happens only when a verified server exists. After connecting, call `refreshOutputs()` so the menu and the adopted id are listed.
   - **Activity task.** `@ObservationIgnored private var activityTask` and `private(set) var activity: [OutputActivity] = []`, started in `init` like `watchMusicAssistantConnection`. For each snapshot, call `PlaybackOwnership.adoption(...)` with `trigger: .connected` for the first snapshot after each `.connected` (track this with a flag set in the connection watcher), else `.activityChanged(previous: activity)`. Then `activity = snapshot`. On a non-nil result, call `adopt(id)`.
     - `selectedState`: `playsLocalQueue ? player.state mapped : nowPlaying.state`.
     - `adopt` sets `previousTarget = selectedOutput` and `selectedOutput = id`, then posts `StatusNotice(text: "Output: \(name)")` (truncate like `truncated(_:to:)`). If the adopted id is a speaker while This Mac sounds, it also runs `stopOthers(startingOn: id)`.
   - **`previousTarget`.** `@ObservationIgnored private var previousTarget: OutputDevice.ID?`, set in `selectedOutput`'s `didSet` (`previousTarget = oldValue` when they differ).
   - **`stopOthers(startingOn:)`.** It computes `PlaybackOwnership.stops(...)`, with `thisMacSounding: player.state == .playing || sendspinController.sendspin.isStreaming`, and runs each stop:
     - `.thisMacLocal` → `try? await router.local.transport(.stop, on: thisMacID)`.
     - `.musicAssistant(id)` → `try? await musicAssistant.transport(.stop, on: id)`.

     Call it from:
     - `playFromLibrary`, before `backend.play`, in the same `Task`.
     - `importLocalFiles` and `playlist.onPlayLocal`, with target This Mac.
     - `onStreamStarted`. When `selectedOutput != thisMacID` there, the stream wasn't SkinAmp's own request (no `.musicAssistantPlayRequested` since the last stream start; keep a flag set in `playFromLibrary` and cleared on stream start). Then `adopt(thisMacID)` first, which makes the speaker `previousTarget`, and stop it through `stops`.
   - 0117's `selectOutput` needs no change. A transfer already stops the source, and `.keepLocal` leaves This Mac playing until the next start on the speaker, which then stops it here.
   - **`stopPlaybackForQuit() -> Task<Void, Never>?`.** It reads `UserDefaults.standard.object(forKey: QuitStop.defaultsKey) as? Bool ?? true`. It returns nil when `QuitStop.targets(enabled:isConnected:selected:thisMacFeed:)` is empty (`isConnected` comes from the activity flag or `await ma.isConnected` checked inside the task). Otherwise it returns a task running `QuitStop.run(targets, on: musicAssistant)` and logs `.timedOut`.

7. **Quit (`AppDelegate`).**
   ```swift
   @ObservationIgnored private var quitStopPending = false
   func applicationShouldTerminate(_ sender: NSApplication) -> NSApplication.TerminateReply {
       guard !quitStopPending, let stopping = model.stopPlaybackForQuit() else { return .terminateNow }
       quitStopPending = true
       Task { @MainActor in
           await stopping.value                      // capped at QuitStop.timeout inside
           sender.reply(toApplicationShouldTerminate: true)
       }
       return .terminateLater
   }
   ```
   `applicationWillTerminate` stays as it is. It runs after the reply, so the stop goes out while the Sendspin session is still up, and the goodbye follows. A second ⌘Q while one is pending terminates at once.

8. **Settings.** In `MusicAssistantSettingsView`, add `@AppStorage(QuitStop.defaultsKey) private var stopOnQuit = true` and `Toggle("Stop playback when SkinAmp quits", isOn: $stopOnQuit)` under "Play Music Assistant on this Mac", with the footnote "Speakers keep playing after quit when this is off."

### How this fits 0117 and 0118, and the order

- 0117 owns the user's output change: `selectOutput`, `OutputMove`, `transfer`, and the `playerID(for:)` / `queueID(for:)` refactor. 0121 owns everything else that changes the target or starts playback: adoption at connect and from events, exclusive starts, the leader redirect, launch connect and quit. Both keep `selectedOutput` as the one routing id. Adoption assigns it directly, like 0117's fallback paths, and never transfers.
- **Order: 0117 first, then 0121, then 0118.** 0117 is smaller and self-contained, and 0121 builds on its `selectOutput` (the `.keepLocal` case) and `playerID(for:)`. 0121 doesn't absorb any part of 0117. 0118 then adds members under the leader. Adoption already treats a member (`leader != nil`) as part of its leader, and quit-stop and the leader redirect already stop a group through the leader, so 0118 needs no change to this plan.
