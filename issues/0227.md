## Description

A skin can draw the playlist editor's five bottom buttons as anything: 100cc Class draws them as kart racers with no text ([0226/100cc-playlist-editor.png](0226/100cc-playlist-editor.png)), and the user couldn't tell which one held Load (see [#0226](0226.md) for the user's words). Hovering a button shows nothing.

## Expected

Hovering each button shows a tooltip naming it and its menu, e.g. "LIST: Load, Save, New List", "REM: Remove Selected, Crop, Remove All". Real Winamp has none there; this is an addition that costs nothing on a well-labelled skin. The tooltips stay within the button's skin rect and follow the window when docked or shaded.

## Plan

### Text: one source

Each tooltip is the button's name and the labels of its entries, nearest the button first (the order the pop-up stacks them, bottom up), from the labels VoiceOver already reads for the skinned entries (`AXID.PL.Menu.entries`), so the tooltip and VoiceOver can't disagree:

| Button | Tooltip |
|---|---|
| ADD | `ADD: Add File, Add Folder, Add URL` |
| REM | `REM: Remove Selected, Crop, Remove All` |
| SEL | `SEL: Select All, Select None, Invert Selection` |
| MISC | `MISC: Misc Options, File Info, Sort List` |
| LIST | `LIST: Load List, Save List, New List` |

`PLAYLIST_REMOVE_MISC` is left out: it does nothing (`PlaylistMenusView.run` has no case for it), so the tooltip doesn't advertise it.

- `App/PlayerModel+Probe.swift`, `extension PlaylistLayout.Menu` (beside `accessibilityID` / `accessibilityLabel`): `var buttonName: String` ("ADD", "REM", "SEL", "MISC", "LIST") and `var tooltip: String`, built from `PlaylistLayout(…).menuEntries(self)` reversed, minus `PLAYLIST_REMOVE_MISC`, mapped through `AXID.PL.Menu.entries`. The sprite order lives in SkinKit's `PlaylistLayout.spriteNames`; make it reachable without a layout instance (`public static func entrySprites(_ menu: Menu) -> [String]`, used by `menuEntries`) so the tooltip doesn't need geometry.
- If #0226 has landed first, its `PlaylistMenu` model is the single source of titles: then build the tooltip from `PlaylistMenu.command(forSprite:)` and the skinned labels the same way, and keep `AXID.PL.Menu.entries` the labels. Either order works; this issue doesn't depend on #0226.

### Showing it

- `PlaylistMenusView`, the closed-button `Color.clear` view (`.skinControl(menu.accessibilityID, …)`): add `.help(menu.tooltip)`. This is the same view that takes the click, inside the window's `scaleEffect`, so the tooltip's area is the button's skin rect at any scale, as hit testing already is. It follows the window when docked (it's in the window), moves with LIST when the window is resized (the rect is `layout.menuButton`), is absent while the menu is open (the view is replaced by the entries) and in shade mode (`PlaylistShadeView` has no buttons). `.help` also sets the button's accessibility help, so VoiceOver reads it as the hint.
- Nothing covers it: `PlaylistListInputView` covers only `layout.trackArea`, above the bottom bar.
- **Fallback** if, by hand, the SwiftUI tooltip is misplaced at double size or doesn't show in the borderless `SkinWindow`: an AppKit `PlaylistTooltipView` (non-hit-testing: `hitTest` returns nil) installed by `PlaylistWindowOverlays.install(in:)`, laid out in `layout(_:scale:height:shaded:)` with the same `frame(_:)` conversion, `removeAllToolTips()` then `addToolTip(frame(layout.menuButton(menu)), owner: tooltip as NSString, userData: nil)` per button, hidden when shaded. Say which was used in `## Fix`.
- Tooltips show only while Roadie is active (AppKit default); no change.
- Real Winamp has none here; on a labelled skin the tooltip just repeats the button. No setting to turn them off.

Proven by `PlaylistTooltipTests.testEachButtonNamesItsMenu`, `.testTooltipsCoverEveryEntryButRemoveMisc`, SkinKit `PlaylistLayoutTests.entrySpritesMatchMenuEntries` and UI `PlaylistUITests.testMenuButtonsHaveTooltips` (class `PlaylistUITests`, 20 passed). ## Root cause

The five bottom buttons are bare `Color.clear` hit areas over the skin's art, with no tooltip. A skin that draws them without text, like 100cc Class, gives no clue what each one is.

## Fix

- `.help(menu.tooltip)` is on the closed-button view in `PlaylistMenusView`, which is the SwiftUI path from the plan. The AppKit fallback wasn't needed: a help tag shows beside the button in the guest.
- `PlaylistLayout.Menu.buttonName` and `.tooltip` are in `App/PlayerModel+Probe.swift`. The tooltip lists the entries bottom up, using the `AXID.PL.Menu.entries` labels (the ones VoiceOver reads), and leaves out `PLAYLIST_REMOVE_MISC`.
- SkinKit `PlaylistLayout.entrySprites(_:)` is now public and static (it was the private `spriteNames`), and `menuEntries` uses it.
- #0226's `PlaylistMenu` titles are not the source. They are the menu bar's titles ("Load Playlist…") and they don't cover SORT LIST or MISC OPTIONS, while the tooltip should match what VoiceOver reads on the skinned entries. The plan's strings are kept unchanged.
