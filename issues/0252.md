# 0252 — The Library status view's Retry and Open Settings… buttons lose their accessibility identifiers

| | |
|---|---|
| **Status** | open |
| **Module** | App |
| **Platform** | macOS |
| **First seen** | 2026-10-29 |

## Description

Found while fixing #0205 (run 20261029-213920-81208). `App/Browser/LibraryStatusView.swift` puts `.accessibilityIdentifier("library.status")` on the whole `ContentUnavailableView`, and that outer identifier overrides the buttons' own `library.retry` and `library.openSettings`. The accessibility tree shows `Button, identifier: 'library.status', label: 'Retry'` (once per column). The buttons work and VoiceOver still reads their labels; only the identifiers are dead, so UI tests (and `AXID`) can't address them. #0205's test finds them by label instead.

## Plan

Add `.accessibilityElement(children: .contain)` before the outer identifier (or move `library.status` onto the text), so the buttons keep `library.retry` and `library.openSettings`. Then switch #0205's `testUnreachableSourceShowsRetry` back to the identifiers, proven to fail first.
