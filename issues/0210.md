## Description

The three App-layer pieces behind 0.0.4's bugs are `PlaylistModel.playRow` (#0187), `PlaylistListInputView`'s pasteboard reading (#0188) and `JumpToFilePanel`'s play/queue actions (#0187, #0190). They can be driven by UI tests now (#0203–#0206), but a unit test is fast and pins the exact seam. This issue adds `RoadieTests` for `PlaylistModel`, splits a `JumpToFileController` out of the panel and tests it, and moves the pasteboard reading into a `LibraryDropDecoder` and tests it against real `NSPasteboard`s. Design: [docs/design/test-automation.md](../docs/design/test-automation.md) §2.1.

## Root cause

The App-layer seams behind 0.0.4's bugs (#0187 `playRow`, #0188 pasteboard reading, #0190 Jump to File's empty text) had no unit tests, and two of them were buried in AppKit views that a unit test can't drive.

## Fix

Followed the plan. `JumpToFileController` holds the query, results, selection, the off-main index and filter, and the Play/Queue actions; `JumpToFilePanel` keeps the field, table and delegates and forwards to it. Deviation: `query` filters asynchronously (as the panel did), so tests set it and `await settle()`. `LibraryDropDecoder` takes the decoding bodies unchanged from `PlaylistListInputView` (plus `hasFileURLs`/`fileURLs(from:)`). `PlayerKitTestFixtures` became a library product so `RoadieTests` (only) can build the fixture music folder for `PlayerModelDropTests`. Every test model uses an isolated configuration (temp data directory, defaults suite, no or scripted Music Assistant, no discovery). XCTest names carry the `test` prefix, so the expect list uses `testRowsNumberNameMarkerDuration` and so on. Extra tests beyond the plan: remote remove/crop/drag, sort refusal on remote, no-results Play, selection kept across a query change, undecodable data, web URLs.

## Plan

### 1. `PlaylistModelTests` (`Tests/RoadieTests/PlaylistModelTests.swift`)

Build `PlaylistModel(player: Player())` with the closures set like `PlayerModel.init` does (`isLocal`, `isPlayingLocalQueue`, recorders for `onPlayLocal`, `onPlayRemote`, `onRemoteRefused`, `onEditRemote`, `onRemoteNotice`). Local queue: `player.enqueue(tracks)` with `Track`s pointing at nonexistent files (nothing is decoded until play; `play(at:)` sets `currentIndex` first: check `PlayerTests` for how they assert it without audio, e.g. `queue.currentIndex`).

- `rowsNumberNameMarkerDuration`: 5 tracks, up-next [3, 1] → rows' `number`, `name`, `marker` (`[1]` on 3, `[2]` on 1), `duration`, `isCurrent`.
- `playRowLocalSelectsTheRow` (**#0187 local**): `playRow(3)` → `onPlayLocal` fired once, `player.queue.currentIndex == 3`.
- `playRowRemoteSendsTheRowNumber` (**#0187 remote**): `remote = RemoteQueueSnapshot(items: 5 items all with index 0, …)`; `playRow(3)` → `onPlayRemote(3)`; `playRow(9)` → nothing.
- `playFirstSelectedUsesTheLowestSelectedRow`, `playRowIgnoredWhenNotLocal` (`isLocal` false and `remote == nil`).
- `toggleQueueAddsAndRemovesMarkers`, `clearUpNext`, `selectionIsQueued`.
- `removeSelectedCropAndRemoveAll` on local; the same on remote send `QueueEdit.remove`/`clear` through `onEditRemote` (`async`; await the recorder).
- `sortReverseRandomizeOnLocal`; on remote they call `onRemoteRefused` and change nothing.
- `dragSelectedMovesRowsLocally`; on remote → `QueueEdit.move`.
- `scrollAndVisibleRange`: 40 rows, `scroll(by: 4)`, `setScrollValue`, `handleValue`, `allTracksAreVisible`.
- `shadeTextAndRunningTime`.
- `htmlEntriesMatchRows`.

### 2. `JumpToFileController` (`App/JumpToFile/JumpToFileController.swift`, new)

Extract from `JumpToFilePanel`: `init(model: PlayerModel)`, `var query: String { didSet { filter() } }`, `private(set) var results: [Result]` (row index + display name), `selectedResult`, `func playSelected()` → `model.playlist.playRow(index)` and `onClose`, `func toggleQueueSelected()` → `playlist.toggleQueue([index])`, `var queueButtonTitle` (Queue/Dequeue), `var emptyStateText: String?` (nil when there are results; the "playlist is empty, use the Library" text vs "no match"). The panel keeps the `NSSearchField`, table and delegates and forwards to the controller. Tests `JumpToFileControllerTests`: `filterMatchesWordsAcrossArtistTitleAndFileName` (through `JumpToFileMatcher`), `playSelectedPlaysTheRowNotTheResultIndex` (query that leaves rows 2 and 4; select the second result → `playRow(4)`), `queueButtonTitleFollowsTheMarker`, `emptyPlaylistTextMentionsTheLibrary` (#0190), `noMatchTextDiffersFromEmpty`, `arrowSelectionWrapsOrClamps` (whichever the panel does).

### 3. `LibraryDropDecoder` (`App/Playlist/LibraryDropDecoder.swift`, new)

Move `operation(for:)`, `hasMediaID(_:)`, `mediaIDs(from:)` and the file-URL reading out of `PlaylistListInputView` into `enum LibraryDropDecoder` with the same bodies; the view calls them. Tests `DropDecoderTests` with `NSPasteboard(name: NSPasteboard.Name("roadie.tests.\(UUID())"))` released in `tearDown`:

- `readsEveryPasteboardItem` (**#0188**): three `NSPasteboardItem`s each carrying one `MediaIDTransfer` → ids concatenated in order.
- `readsLazilyProvidedData`: an item with `setDataProvider` for the media-id type → decoded (the provider is called).
- `fallsBackToThePasteboardData`: no items with the type but `pasteboard.setData(forType:)` → decoded.
- `typePresentButNoDataIsNil`: an item that declares the type and provides `nil` → `nil` (the notice path).
- `operationPrefersCopyThenGenericThenMove`, `operationIsEmptyForAnUnrelatedMask`.
- `fileURLsAreReadInOrderAndNonAudioIsKept` (the caller filters; assert what the decoder returns today).
- `hasMediaIDLooksAtItemsToo`.

### 4. `appendDroppedLibraryItems` and the SwiftUI fallback

`PlayerModelDropTests` (needs #0194's test-mode model with the folder backend on a fixture library): `appendDroppedLibraryItemsAppendsAtTheEnd` (local queue of 3, drop an album → `PlayRequest` with `.insert(at: 3)` reaches the backend: assert through the queue's rows after the async expansion), `dropOnAMusicAssistantQueueAppends` (scripted server: `play_media option=add` in `receivedCommands`).
