## Description

`AnalyzerTap`'s tap block (`Packages/PlayerKit/Sources/AudioCore/Analyzer/AnalyzerTap.swift`, `TapSink.handle`) averages left and right into one `VisSampleRing`, which is all the main window's 75-column spectrum and 76-point scope need. MilkDrop presets read the stereo waveform (left and right separately: `wave-xy`, `wave-stereo`, the X-Y scopes), and MilkDropMetalKit's `MilkRenderer.feed(samples:channels:sampleRate:)` takes interleaved stereo. There is no stereo copy of the signal anywhere in Roadie, and no reader that hands a renderer the audio a frame at a time (the tap delivers about 100 ms per call, so feeding it straight through makes the picture step; MilkDropMetalKit `docs/api-1.0.md` F5).

Design: [docs/design/visualization.md](../docs/design/visualization.md) §4.1–§4.3. Groundwork for the visualization window (#0235); no UI.

Review run 20261029-020230-1715 failed only in unrelated FolderBackendKit/backend timing tests (`reconnectRefetchesAndKeepsTheStream`, #0149; `playNextExpandsAnAlbumIntoUpNext`, queue advanced during the test), with all 12 expected tests passing; the re-run was clean.

## Root cause

The tap block averaged left and right into the one mono ring the main-window visualizer needs; no stereo copy and no display-rate stereo reader existed.

## Fix

As planned. `TapSink` gains a 32,768-float interleaved stereo ring, a preallocated scratch and a CAtomics enable flag (off by default); `handle` interleaves channels 0/1 (or duplicates a mono source) with `vDSP_ztoc` after the unchanged mono write. `AnalyzerTap` exposes `stereo`, `setStereoEnabled`, `isStereoEnabled`, `stereoSampleRate` and internal `deliver(_:)`. New `StereoFeedReader` paces reads with its own frame-indexed `VisReadCursor`, resets on a sample-rate change, returns one 1,024-frame window after a reset and caps a stall at `maxFrames` (4,096). Test-side deviations: the reader tests use a ramp (L = frame index, R = −L) instead of a sine to check continuity; `readerReturnsNothingWhilePaused` asserts nil after the first 0.5 s of the pause, since the cursor first plays out the buffered tail.

## Plan

### Stereo ring in the tap

`AnalyzerTap.swift`:

- `TapSink` gains `let stereo: VisSampleRing` (capacity 32,768 floats = 16,384 frames, interleaved L R), a preallocated `stereoScratch` of `stereo.capacity` floats, and an enable flag in a preallocated `UnsafeMutablePointer<Int64>` read with `ca_load_acquire` / written with `ca_store_release` (CAtomics, as `VisSampleRing` does).
- `handle(_:)`, after the mono write and only when the flag is set:
  - `n = min(frameLength, stereo.capacity / 2)` frames (newest, same `skip` as the mono path);
  - two or more channels: `vDSP_ztoc(&DSPSplitComplex(realp: left, imagp: right), 1, stereoScratch as DSPComplex, 2, n)` (interleaves; no allocation). Build the `DSPSplitComplex` from the existing channel pointers (they're `UnsafeMutablePointer<Float>` from `floatChannelData`);
  - one channel: the same with `imagp: left` (duplicated);
  - `stereo.write(stereoScratch, count: 2 * n)`.
  - `maxChunk` is `capacity / 4`, a power of two, so every published slice holds whole frames.
- `AnalyzerTap` public API:
  - `public var stereo: VisSampleRing { sink.stereo }`
  - `public nonisolated func setStereoEnabled(_ on: Bool)` (the flag; default off, so the tap does exactly today's work until the vis window renders)
  - `public var isStereoEnabled: Bool`
  - `public private(set) var stereoSampleRate: Double` = the `sampleRate` of the last `prepare` (set in `prepare(sampleRate:)` beside `sampleRate`; the same value, kept separate so the reader can notice a change without touching the mono analyzer).
  - `internal func deliver(_ buffer: AVAudioPCMBuffer)` that calls `sink.handle(buffer)`, so tests drive the real tap body without an engine.
- Nothing else changes: the mono ring, `frame(elapsed:)`, `resetCursor()` and `VisualizerModel` behave as today.

### Paced reader

New `Packages/PlayerKit/Sources/AudioCore/Analyzer/StereoFeedReader.swift`:

```swift
/// Consumer side of the stereo ring, at display rate (main actor in the app). Each `read` returns the frames that
/// played since the previous one (interleaved L R), paced by elapsed time a delivery behind the write head, so a
/// renderer fed once per tick sees smooth audio although the tap delivers ~100 ms bursts.
public final class StereoFeedReader {
    public static let maxFrames = 4_096
    public init(tap: AnalyzerTap)
    /// nil until a window's worth has flowed, or when nothing new played (paused, stopped, stalled).
    public func read(elapsed dt: Double) -> (samples: UnsafeBufferPointer<Float>, frames: Int, sampleRate: Double)?
    public func reset()
}
```

- A `VisReadCursor(window: 1_024, readable: (stereo.capacity - stereo.maxChunk) / 2)` over **frame** indices (`stereo.writeCount / 2`); its own cursor, never the mono one.
- `read`: if `tap.stereoSampleRate` differs from the rate of the last read, `reset()` first. `end = cursor.next(writeCount: frames, elapsed: dt, sampleRate: rate)`; return nil if nil or `end <= lastEnd`. `count = min(end - (lastEnd ?? end - 1_024), maxFrames)` (the first read after a reset returns one 1,024-frame window); `stereo.copy(count: 2 * count, endingAt: 2 * end, into: buffer)`; a torn copy (false) returns nil and keeps `lastEnd`. The buffer (`2 * maxFrames` floats) is allocated in `init` and reused; the returned pointer is valid until the next `read`.
- A jump larger than `maxFrames` (the main thread stalled) returns just the newest `maxFrames`: re-lag, never replay.

## Tests

Fast, swift-testing, in `Packages/PlayerKit/Tests/AudioCoreTests/AnalyzerTapTests.swift` (extend) using `tap.prepare(sampleRate:)` and `tap.deliver(_:)` with `AVAudioPCMBuffer`s built in the test (non-interleaved Float32, like the engine's):

- `stereoIsOffByDefaultAndWritesNothing`: deliver a stereo buffer without enabling; `tap.stereo.writeCount == 0`, the mono ring advanced as before.
- `stereoInterleavesLeftAndRight`: left = 0.25, right = −0.5 (constant), 512 frames; enabled; `stereo.copyLatest(count: 1024)` alternates 0.25, −0.5.
- `monoSourceIsDuplicatedIntoBothChannels`: a one-channel buffer of a ramp; each L equals the next R.
- `extraChannelsAreIgnored`: a four-channel buffer; only channels 0 and 1 appear.
- `monoRingIsUnchangedWithStereoOn`: the mono ring's contents with stereo on equal those with it off for the same buffers (the existing averaging).
- `stereoWritesWholeFramesAcrossChunkBoundaries`: buffers of odd sizes (4,801, 4,799 frames) many times past the ring capacity; every copied window still starts on an L sample (check with distinct L/R constants).

New `Packages/PlayerKit/Tests/AudioCoreTests/StereoFeedReaderTests.swift`:

- `readerReturnsNothingBeforeAWindowHasPlayed`
- `readerPacesBurstDeliveries`: 4,800-frame bursts every 6 ticks at 48 kHz, `read(elapsed: 1/60)` every tick; after warm-up every read returns 799–801 frames and consecutive reads are contiguous (a phase-continuous sine checks continuity across reads), as `frameElapsedAdvancesThroughBurstDeliveries` does for mono.
- `readerReturnsNothingWhilePaused`: no deliveries for 1 s of ticks → nil every time; deliveries resume → frames again, no burst of old audio (≤ one window).
- `readerResetsWhenTheSampleRateChanges`: `prepare(44_100)`, read; `prepare(48_000)`, deliver, read → the returned `sampleRate` is 48,000 and the count is one window, not a 44.1 kHz cursor's jump.
- `readerCapsAStallAtMaxFrames`: no reads for 2 s of deliveries, then one read with `elapsed: 2` → ≤ `maxFrames` frames, the newest.
- `readerHasItsOwnCursor`: interleave `tap.frame(elapsed:)` (mono) and `reader.read(elapsed:)` calls and `tap.resetCursor()`; the reader's frames stay contiguous.

No `--expect-fail` (an addition).
