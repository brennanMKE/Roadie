# 0214 — `MusicBackendKit` and `SendspinKit` are under their coverage goals

| | |
|---|---|
| **Status** | open |
| **Module** | MusicBackendKit / SendspinKit / MusicAssistantKit |
| **Platform** | macOS |
| **First seen** | 2026-10-24 |

## Description

`MusicBackendKit` measured 78.7 % (428 of 544 lines) in #0212's baseline, under its 85 % goal, and `SendspinKit` measured exactly 85.0 % (584 of 687). Their floors were lowered to 78 and 84 so the milestone run passes. The missed lines are almost all small and pure: the default `MusicBackend` extensions that throw `unsupported`, error descriptions, `RecommendationItem`'s computed properties, `RadioURLInput.parse`, and `SendspinTransport` (0 % of 53 lines). This issue tests them and puts both floors back to 85.

## Plan

Missed lines per file in the baseline (`llvm-cov report`, lines/missed): `FavoriteListing.swift` 15/15, `MusicBackend+Playlists.swift` 24/24, `MusicBackend.swift` 35/23 (`MusicBackendError.errorDescription`, `BackendCapabilities`), `Recommendations.swift` 75/33, `RemoteQueue.swift` 36/12 (`QueueEditError.errorDescription`, default `queue`/`edit`/`saveQueueAsPlaylist`), `Radio.swift` 24/6, `MediaIDTransfer.swift` 7/3; `SendspinKit/SendspinTransport.swift` 53/53.

1. `Packages/PlayerKit/Tests/MusicBackendKitTests/DefaultBackendTests.swift`: a minimal `MusicBackend` conformer in the test file that implements only the required members. Assert that every default favorites, playlist-editing, radio and queue method throws `MusicBackendError.unsupported(<capability>)` with the right capability, and that the default `queue(on:)` stream finishes empty.
2. `MusicBackendKitTests/RecommendationsTests.swift`: build one `RecommendationItem` per case and check `id`, `mediaID`, `name`, `subtitle`, `kind`, `artwork` and `isMapping`, plus `RecommendationRow.id`.
3. `MusicBackendKitTests/ErrorTextTests.swift`: `errorDescription` of every `MusicBackendError` and `QueueEditError` case is non-empty and names the thing that failed. Also `RemoteQueueSnapshot.empty(on:)`.
4. `RadioURLInput.parse`: the missing branches (blank text, a name taken from the URL, an explicit name). Add them to the existing tests or to a new `RadioTests.swift`. The `MediaIDTransfer` gaps go in `MediaIDTransferTests`.
5. `Packages/PlayerKit/Tests/SendspinKitTests/SendspinTransportTests.swift`: run `URLSessionSendspinTransport` against an in-process loopback WebSocket server (`NWListener` with `NWProtocolWebSocket` on 127.0.0.1; no network leaves the guest). Check that text goes out, text and binary frames come back as the right `SendspinFrame`, a close code is mapped, and cancelling `receive()` closes the task. Also test `map(error)` directly if it is reachable.
6. Raise `MusicBackendKit` and `SendspinKit` to 85 in `scripts/coverage-floors.tsv` and drop their "baseline" comments. Update the Floor column in design §2.4.

## Tests

`defaultFavoritesThrowUnsupported`, `defaultPlaylistEditingThrowsUnsupported`, `defaultQueueIsEmpty`, `recommendationItemProperties`, `errorDescriptionsNameTheFailure`, `radioURLInputParses`, `transportSendsAndReceivesFrames`, `transportMapsCloseCode`, `cancelledReceiveCloses`. Expect list: all of them. The coverage check is a `--coverage` run with MusicBackendKit and SendspinKit at 85 or more. That run is the milestone's job; quote its `coverage:` lines if the runner does one.

**Fast:** `scripts/verify.sh --expect <the tests above>`. The new tests must not need the network (a loopback listener is fine), a real Keychain or a speaker. They use the stubs and injectable seams the plan names.

No other issue owns it, and it needs the same loopback WebSocket server as step 5, so it is added here:

7. `Packages/PlayerKit/Tests/MusicAssistantKitTests/WebSocketTransportTests.swift`: run `URLSessionWebSocketTransport` against step 5's loopback server (share it through a small test-support file, or `PlayerKitTestFixtures`). Check that `connect` opens `/ws` on the base URL (`socketURL(for:)`), text goes out, text and binary messages both come back as `.text`, a server close comes back as `.closed(code:)`, cancelling `receive()` closes the task, `ping` succeeds, `close(code:)` reaches the server, `receive()` before `connect()` throws, and a refused connection is mapped by `map(_:)`.

Tests added: `maTransportSendsAndReceivesFrames`, `maTransportReportsServerClose`, `maTransportPingsAndCloses`, `maTransportMapsRefusedConnection`. `MusicAssistantKit` (90.6 %) is already over its 85 % floor, so no floor changes for it.
