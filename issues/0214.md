## Gotchas

- `URLSessionWebSocketTransport.close(code:)` ignores `code` and always sends 1000 (`normalClosure`). Left unchanged. It doesn't matter today: the Music Assistant client only closes with 1000, and the server treats every close the same. If a caller ever needs a different close code, it will silently get 1000. `URLSessionSendspinTransport.close(code:)` does pass its code through.
- `NWListener.cancel()` is asynchronous. `LoopbackWebSocketServer.stop()` waits for `.cancelled` and drops any client that arrives after it. The refused-connection tests don't stop a server; they use `RefusingPort`: bind port 0, read the port, then close the socket, so nothing is bound and the connection gets a RST. Their sessions use a 5 s request timeout with `waitsForConnectivity = false`. A socket that was bound but not listening didn't work: on macOS the connection just hung until the 60 s time limit (run `20261029-235826-32189`).
