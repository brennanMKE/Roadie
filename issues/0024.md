### `VisBars` (AudioCore) — port of `BarPaintHandler.paintAnalyzer`

Webamp's constants for the main window (`Vis.tsx` lines 103–117): `bandwidth: "wide"`, `coloring: "normal"`, `peaks: true`, `saFalloff: "moderate"` → `falloff = 12` (`VisPainter.ts` lines 179–198, "12 is the default of a fresh new Winamp installation"), `saPeakFalloff: "slow"` → `peakFalloff = 1.1` (lines 200–219), `maxHeight = 15`, 75 columns (lines 294–300). The arithmetic is integer-sensitive (`Int16Array` truncation), so port it in fixed 60 Hz steps rather than with `dt` multipliers:

```swift
public struct VisBars: Sendable {
    public static let columnCount = 75
    public var falloff: Float = 12            // px/16 per step (VisPainter.ts line 388)
    public var peakFalloff: Float = 1.1       // per-step growth of the peak drop (line 407)
    public var maxHeight = 15
    public var pushDown = 0                   // 2 at 1x, 0 at 2x
    public private(set) var heights: [Int]    // 75; round(saFalloff) - pushDown, min 0 (line 428)
    public private(set) var peaks: [Int]      // 75; barPeak + 1 - pushDown; <= 0 means hidden (lines 418–420, 429)
    public init()
    /// One 60 Hz step. `spectrum` is VisFrame.spectrum (0…1); silence (all zeros) makes everything fall.
    public mutating func step(_ spectrum: [Float])
}
```

Per column `x` (lines 360–432), with `sample[x] = min(spectrum[x] * 16, 15)` (so 1 px = 3.75 dB of the −60 dB range; `sample[75] = 0` as in Webamp's 76-entry array):

1. Wide bandwidth: `chunk = x & ~3`; `saData[x] = Int((sample[chunk] + sample[chunk+1] + sample[chunk+2] + sample[chunk+3]) / 4)` (lines 365–373; the `Int16Array` store truncates), clamped to `maxHeight` (379–381). Columns with `x == chunk + 3` are the 1-px gaps between the 19 three-pixel bars; their state is still updated but the renderer skips them (423).
2. Bar falloff (388–397): `saFalloff[x] -= falloff / 16` (0.75 px per step); `if saFalloff[x] <= Float(saData[x]) { saFalloff[x] = Float(saData[x]) }`.
3. Peaks (399–413), all `Int` in 1/256 px: `if saPeaks[x] <= Int((saFalloff[x] * 256).rounded()) { saPeaks[x] = Int(saFalloff[x] * 256); saData2[x] = 3 }`; `barPeak[x] = saPeaks[x] / 256`; `saPeaks[x] -= Int(saData2[x].rounded())`; `saData2[x] *= peakFalloff`; `saPeaks[x] = max(saPeaks[x], 0)`. Clamp `saPeaks` to `maxHeight * 256` (384–386).
4. `if barPeak[x] < 1 { barPeak[x] = -3 }` (418–420), then `heights[x] = max(0, Int(saFalloff[x].rounded()) - pushDown)` and `peaks[x] = barPeak[x] + 1 - pushDown`.

Resulting feel (what the tests pin down): a full bar falls 0.75 px per step (15 → 0 in 20 steps, 0.33 s); the peak marker holds for about 24 steps (the drop starts at 3/256 px and grows 10 % per step) and is gone within about 52 steps (0.9 s). Frame-rate independence comes from the caller: `VisualizerModel` accumulates `dt` and runs `Int(accumulator * 60)` whole steps per display-link tick (capped at 4), so a 120 Hz display or a dropped frame changes nothing.

### Lagging read cursor (`VisReadCursor` + `AnalyzerTap.frame(elapsed:)`)

Problem (#0005 Gotchas): the mixer tap delivers 4800-frame buffers at 48 kHz, so `latestFrame()` returns a new window only 10× per second; at 60 Hz the bars jump every sixth tick and fall in between. Fix (#0005 plan risk 2): read the ring at a consumer position that advances with wall-clock time and stays one delivery behind the write counter, so every tick analyzes a fresh, contiguous 1024-sample window about 800 samples after the previous one.

Ring: add the general copy and make `copyLatest` a wrapper.

```swift
/// Consumer only. Copies `count` samples ending at absolute index `end` (exclusive), oldest first.
/// False if `end > writeCount`, `end < count`, `count > capacity - maxChunk`, or the region may have been
/// overwritten during the copy (same seqlock check as before: `writeCount - begin <= capacity - maxChunk`).
@discardableResult
public func copy(count: Int, endingAt end: Int, into out: UnsafeMutablePointer<Float>) -> Bool
public func copyLatest(count: Int, into out: UnsafeMutablePointer<Float>) -> Bool   // copy(count:endingAt: writeCount)
```

Cursor (pure, no audio, unit-tested with simulated deliveries):

```swift
public struct VisReadCursor: Sendable {
    public init(window: Int, readable: Int)   // window = fftSize; readable = ring.capacity - ring.maxChunk
    public var slackSeconds: Double = 0.02    // extra lag so clock drift does not run the cursor dry
    public private(set) var position: Int?    // absolute index the last window ended at
    public private(set) var largestDelivery: Int   // largest writeCount jump seen; starts at window
    /// End index of the next window, or nil while fewer than `window` samples exist.
    public mutating func next(writeCount: Int, elapsed dt: Double, sampleRate: Double) -> Int?
    public mutating func reset()
}
```

`next`:

1. Track deliveries: if `writeCount > lastWriteCount` then `largestDelivery = max(largestDelivery, writeCount - lastWriteCount)` and `stalledSeconds = 0`, else `stalledSeconds += dt`. Remember `lastWriteCount`.
2. `guard writeCount >= window else { return nil }`.
3. `lag = min(largestDelivery + Int(slackSeconds * sampleRate), readable - window)`; `steady = writeCount - lag` (the newest index that can be read every tick without running out before the next delivery).
4. Advance: `p = (position ?? steady) + Int((dt * sampleRate).rounded())`.
5. Ran past the audio (`p > writeCount`, e.g. the display clock is slightly fast, or the UI resumed after a pause): `p = steady` (re-lag; a 100 ms visual skip, not a freeze on the newest edge, which would repeat frames until the next delivery).
6. Fell too far behind (`p < writeCount - readable + window`, e.g. the main thread stalled so the ring wrapped): `p = steady`.
7. Audio stalled (`stalledSeconds * sampleRate > 2 * largestDelivery`, engine stopped or no render): `p = writeCount` and keep returning it, so the same window repeats, `sampleCount` stops changing and the UI decays with silence instead of replaying the last 100 ms in a loop.
8. `p = max(p, window)`; store and return.

`AnalyzerTap`:

```swift
public init(fftSize: Int = 1024, ringCapacity: Int = 32_768)   // was 16_384; readable 24 576 = 512 ms @ 48 kHz leaves room for larger callbacks
/// Consumer side at display rate. Advances the read cursor by `dt` and analyzes the window ending there.
/// `VisFrame.sampleCount` is that end index. nil until `fftSize` samples have flowed.
public func frame(elapsed dt: Double) -> VisFrame?
public func resetCursor()                                        // call when the UI pauses/resumes
public func latestFrame() -> VisFrame?                           // unchanged: newest window (tests, diagnostics)
```

`frame(elapsed:)`: `guard let analyzer`; `end = cursor.next(writeCount: ring.writeCount, elapsed: dt, sampleRate: sampleRate)`; if `end == cachedEnd` return the cached frame; `ring.copy(count: fftSize, endingAt: end, into: window)` (on a torn read return the cached frame); analyze into the preallocated outputs; build and cache the `VisFrame`. `install(on:sampleRate:)` resets the cursor. To let the cursor path be tested without an engine, split the analyzer construction into an internal `prepare(sampleRate:)` that `install` calls and tests can call directly before writing into `tap.ring`.

### Staying under 1 ms per frame, and measuring it

Per tick: one 1024-point vDSP FFT (~10 µs, measured in #0005), a 75-column integer loop, a 1216-pixel buffer fill, and one ~5 KB `CGImage`. Expected total well under 100 µs. Two measurements:

1. `VisRendererTests.renderFrameStaysUnderOneMillisecond` (headless, in `swift test`): build a renderer, run 1 000 iterations of `clear` + `drawBars` + `drawOscilloscope` + `makeImage` with a `ContinuousClock`, assert the mean is under 1 ms (loose enough not to flake in the VM) and print the mean so the number lands in `## Verification`. A matching `VisBarsTests.stepStaysCheap` is optional.
2. The `OSSignposter` interval around the tick; `--launch` cannot read it, so the host-side Instruments check is for the user. Document how in `## Fix`.

### Risks and decisions to flag in `## Fix`

1. **Integer-exact port vs. `dt`.** Webamp's falloff math truncates through `Int16Array`s; porting it as fixed 60 Hz steps keeps the look and makes tests exact. The accumulator cap (4 steps/tick) means a long stall does not fast-forward the bars.
2. **Cursor lag is ~100 ms behind the audio** (one tap delivery plus 20 ms). Winamp's vis also lags a little; if it looks late, the only knob that helps is a smaller tap delivery, which macOS does not honor (`installTap` 1024 is a request). Note the observed delivery size in `## Gotchas`.
3. **Stalled audio detection** (`2 * largestDelivery`) is a heuristic; `.loading` between tracks with the engine still rendering silence is the case to watch (the ring keeps advancing with zeros, so no stall is detected and bars simply fall).
4. **Scale and `pushDown`.** Faithful to Webamp (2 px at 1×, 0 at 2×). If the user finds the 1× bars oddly short, that is Winamp's behavior; keep it.
5. **Observation churn.** `image` changes 60×/s; only `VisualizerView` may read it. If the whole `MainWindowView` re-renders (check with the SwiftUI instrument or a `print` in `body` during development in the VM), move the image into a tiny `@Observable` holder.
6. **`CADisplayLink` on macOS 14** comes from `NSScreen`/`NSView`/`NSWindow`; `NSScreen.main` can be nil in odd setups: fall back to a 60 Hz `Timer` and log once. The deployment target is 14.0 so no availability checks are needed.
7. **Default colors overlap with #0020.** Keep the defaults in `VisPalette`; do not edit the parser here.
8. **Ring capacity bump to 32 768** changes `readable` to 24 576 and nothing else; the ring tests use explicit capacities so they are unaffected. The `VisFrame` doc comment about `row = 7 - round(v*7)` is stale; replace it with a pointer to the renderer's Webamp mapping.
9. **No App test target exists.** All logic lives in SkinKit/AudioCore so it is covered by `swift test`; the App layer is glue only.
10. **Scope stride** (8 here, 7 in Webamp) and the `sample = spectrum * 16` input scaling are tuning constants; mention any change made after looking at the result.
