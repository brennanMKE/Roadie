## Description

`docs/testing-in-vm.md` has had a "UI tests (not built yet)" section since the VM was set up. This issue builds it: the `RoadieUITests` target and the `Roadie UI Tests` scheme, a test helper that launches Roadie in test mode with fixtures and a skin, screenshots and the state probe on failure, one smoke test, and the `run-tests-vm.sh --ui` / `verify.sh` wiring that runs it in the guest and reports failures in a few lines. It is the gate for every UI test issue (#0202–#0209). Design: [docs/design/test-automation.md](../docs/design/test-automation.md) §3, §6.

### 2. The harness (`Tests/RoadieUITests/Support/`)

- `RoadieApp.swift`: wraps `XCUIApplication`. `launch(skin: TestSkin = .base291, library: Library = .folder, scenario: MAScenario? = nil, firstRun: Bool = false, windows: Windows = [.main, .playlist], extra: [String] = [])` builds `launchArguments`: `-RoadieUITest 1`, `-RoadieDataDir <ROADIE_TEST_DATA>/<test name>`, `-RoadieNoDiscovery 1`, `-RoadieMuseum fixtures`, `-RoadieExternalOpens record`, `-firstRunVersion 1` (or 0), `-lastSkinPath <ROADIE_TEST_SKINS>/<skin>.wsz`, `-skinsFolderPath <ROADIE_TEST_SKINS>`, `-LibraryFolderPath <ROADIE_TEST_MUSIC>` (folder), `-LibrarySource <id>`, `-RoadieMAScenario <scenario>` (Music Assistant), `-eqWindowOpen`, `-playlistWindowOpen`, `-playlistWindowSize 0 3`, `-SUEnableAutomaticChecks 0`, and `-RoadieWindowLayout column` (a new launch argument #0194 can add cheaply: the docking coordinator lays the three windows out in a column at the top-left, ignoring the saved layout). Before launching: `Process` runs `defaults delete co.sstools.roadie` and removes the data dir. Reads the three `ROADIE_TEST_*` paths from `ProcessInfo.processInfo.environment`; when `ROADIE_TEST_SKINS` is unset (a developer's Xcode), it writes a skin with `make-test-skin.swift`'s logic into a temp dir and uses that.
- Typed accessors: `app.main.play` → `app.buttons[AXID.Main.play]`, `app.main.marquee.value as? String`, `app.playlist.row(3)`, `app.probe` (decodes `state.probe`'s value into a `ProbeState` struct), `app.menuItem("Jump to File…")`.
- `waitForValue(_ element:, _ predicate:, timeout: 5)`, `waitForPlaying()`, `expectCurrentRow(_ n:)`.
- `tearDown`: attach `XCUIScreen.main.screenshot()` and `app.probe` JSON as `XCTAttachment`s with `lifetime = .keepAlways` when `testRun?.hasSucceeded == false`, `.deleteOnSuccess` otherwise; terminate the app.
- `TestSkin` enum from `scripts/test-skins.tsv` names (hard-coded; `SkinSmokeUITests` in #0208 reads the TSV at run time).

### 3. Smoke test (`Tests/RoadieUITests/SmokeUITests.swift`)

- `launchesWithTheBaseSkinAndShowsTheMainWindow`: launch; `app.main.play.waitForExistence(timeout: 10)`; `app.windows.count >= 2` (main, playlist); `app.probe.state == "stopped"`; `app.main.marquee.value` contains "Roadie" (the placeholder text; check `placeholderText`).
- `skinnedWindowsExposeEveryIdentifier` (moved from #0199, whose in-process walk can't see the SwiftUI tree): launch with `windows: [.main, .equalizer, .playlist]`; for each id in `AXID.Main.alwaysPresent`, `AXID.EQ.alwaysPresent` and `AXID.PL.alwaysPresent + [AXID.PL.titleShade, AXID.PL.titleClose, AXID.PL.resize]`, `app.descendants(matching: .any).matching(identifier: id).count == 1` (wait for `main.play` first; the message names the id). With the three-track folder library queued and track 2 current (open the Library, double-click the album, click `main.next`, then `main.stop`, and wait for `app.probe.currentIndex == 1` and `state == "stopped"`): `app.playlist.row(0…2)` exist, `.label == "\(i + 1). <artist> - <title>"`, `.value as? String == "marker= duration=<m:ss> current=\(i == 1)"`, and `pl.row.3` doesn't exist. Also: `main.volume`'s value is the launch volume as a rounded percentage (`"\(Int((volume * 100).rounded()))"`, as `MainWindowView` writes it; launch with a known volume rather than trusting the default) and `state.probe` exists (in UI-test mode).
- `playsTheFixtureLibrary`: launch with the folder library; `app.typeKey("l", .command)` opens the Library; double-click the first album row; `waitForPlaying()`; `app.main.time` value changes between two reads 1.5 s apart; `app.playlist.row(0)` has `current=true`.

- Options: `--ui`, `--ui-filter Class[,Class]` (each becomes `-only-testing:RoadieUITests/Class`), `--ui-skins base|all` (default `base`; exported as `ROADIE_TEST_SKIN_SET`), `--test-skins DIR` (#0198). `--ui` requires the test skins cache (`fetch-test-skins.sh --check`), copies it into the export (#0198), runs `scripts/make-test-library.sh $EXPORT/src/TestMusic` (#0195) on the host, and sets `tart set "$CLONE" --display 2560x1300px` before `tart run`.
- Build stage: after `app-build`, `run_step ui-build "xcodebuild -project Roadie.xcodeproj -scheme 'Roadie UI Tests' -configuration Debug -derivedDataPath build/DerivedData build-for-testing" build`.
- Test stage, after `app-launch`'s slot: `run_step ui-tests "ROADIE_TEST_SKINS=$GUEST_SRC/TestSkins ROADIE_TEST_MUSIC=$GUEST_SRC/TestMusic ROADIE_TEST_DATA=/Users/admin/roadie-test-data ROADIE_TEST_SKIN_SET=$UI_SKINS xcodebuild -project Roadie.xcodeproj -scheme 'Roadie UI Tests' -configuration Debug -derivedDataPath build/DerivedData -resultBundlePath $GUEST_RESULTS/ui/UITests.xcresult -retry-tests-on-failure -test-iterations 2 $only_testing test-without-building"`. Wrap it in the guest with `timeout 1200` (the step fails as `timeout` rather than hanging on a blocked prompt).
- Results: the xcresult comes back with the rest. On the host, after the pull: `xcrun xcresulttool get test-results summary --path $RESULTS_DIR/ui/UITests.xcresult > ui/summary.json` and `xcrun xcresulttool export attachments --path … --output-path $RESULTS_DIR/ui/attachments` (check the Xcode 27 subcommand names; fall back to `get --format json` if they differ). Add `Executed .* tests` and `Test Suite 'RoadieUITests' (passed|failed)` to the summary grep, and a `UI` summary line: `==> UI  N tests passed (Classes) on <skin set>` or `==> UI  M of N tests failed`.
- `--build-only` rejects `--ui` like the other test options.

## Root cause

Nothing could run a UI test. There was no XCUITest target or scheme, no harness to launch Roadie in test mode with fixtures, and no `run-tests-vm.sh` wiring to build and run the tests in the guest and bring results back. Once tests did run, two things in the app and the harness got in the way:

- **Display values were unreadable.** SwiftUI on macOS sets `AXValue` from `.accessibilityValue` only for static text. #0199's `skinDisplay`/`AXMarker` elements (an `.ignore` element over images or `Color.clear`) and `SkinSlider` (a custom `.accessibilityAdjustableAction` element) came out as role `AXUnknown`, with the value in `AXValueDescription`, which XCUITest's `value` can't read.
- **`check-fixtures.sh` failed in the guest.** Its `find` fallback (the guest has no git) scanned the run-time `TestMusic/` that `--ui` lays out in the export.

## Fix

- **Target and scheme** as planned (`project.yml`).
- **Harness:** `Tests/RoadieUITests/Support/RoadieUIApp.swift`.
  - `RoadieUIApp` builds the launch arguments.
  - A guest-only guard: `ROADIE_UI_GUEST=1` and the `admin` user, so `defaults delete` can't wipe a developer's preferences.
  - Typed accessors, and the probe decoded into `ProbeState`.
  - `value(of:)` reads both strings and numbers; `describe(_:)` puts the element's `debugDescription` in failure messages.
  - `playToneAlbum()` checks each step.
  - `stopPlayback()` stops with Playback › Stop (⌃⌘V) and returns the probe's `currentIndex`.
  - `RoadieUITestCase` skips outside the VM and attaches the screenshot and probe in a main-actor teardown block.
- **Smoke tests** as planned, except:
  - **`skinnedWindowsExposeEveryIdentifier`** doesn't force track 2 current with next/stop. The 2.5 s fixture tracks auto-advance, and `Player.next()` always starts playback, so that raced. It stops and checks `current=` against the row the probe reports.
  - **`playsTheFixtureLibrary`** likewise checks the probe's current row, not row 0. The time check waits up to 3 s for `main.time` to change.
  - The marquee check ignores case.
- **VM wiring** (`run-tests-vm.sh --ui`, `--ui-filter`, `--ui-skins`):
  - Lays out the test skins and the music folder in the export.
  - Sets the clone's display to 2560x1300.
  - Runs `ui-build` and `ui-tests`, the latter under the new `scripts/with-timeout.sh 1200`. macOS has no `timeout`, so it uses `timeout` if present and perl's `alarm` otherwise.
  - Exports `ui/summary.json` and `ui/attachments/<test>/`, and prints a `UI` summary line.
- **Report** (`verify.sh`):
  - Prints the `UI` line on a pass.
  - On a failure: a `screenshots:` line per failed test, the xcresult path, a timeout line on exit 124, and `warning:` lines from files named in the errors.
  - `--expect` names work with or without the `test` prefix.
- **App accessibility:**
  - `skinDisplay` adds `.isStaticText`.
  - `SkinSlider` uses `.accessibilityRepresentation { Slider(0...100, step 2) }`. It's an `AXSlider` whose `AXValue` is the position in percent; increment and decrement move it 2 % and commit; the old string becomes the value description.
  - Nothing changes visually or for hit-testing.
- **`check-fixtures.sh`:** in `find` mode it prunes the top-level `TestMusic/` and `TestSkins/`. On the host, `git ls-files` still flags them if committed.

### After the review bounce

- **Coordinate clicks check for covering windows** (finding 1). `click`/`doubleClick` take `file:line:`. When the element isn't hittable, `uncoveredCentre` finds the window holding the element's identifier in `app.windows` (front to back). It checks that no window in front of that one contains the element's centre. If one does, `bringForward` clicks the first uncovered point along the target window's top strip: the title bar, away from the options and close buttons at its ends. Then it checks again. If the centre is still covered, it fails at the caller with the id, the point, the covering window's title, identifier and frame, and `describe(element)`. An overlap inside the element's own window still clicks (`pl.row.N` under `PlaylistListInputView`). `playToneAlbum` passes its `file:line:` through.
- **The plan's launch arguments** (finding 2), all test mode only (read in the Debug `-RoadieUITest 1` branch of `RoadieConfiguration.fromProcess`), so none is a deviation any more:
  - `-RoadieWindowLayout column`: `WindowDockingCoordinator.restoreOrDefaultLayout` ignores the saved layout and stacks main, equalizer and playlist from the primary screen's top-left (closed windows get their spot too, which covers no other, so `show(below:)` keeps it). While the layout is on, a `didBecomeKey` observer moves any other key window (Library, Skins, Jump to File, Welcome) that overlaps the column to its right.
  - `-RoadieVolume N`: `PlayerModel` sets the player's volume (0…100 %) before reading it. `launch(volume:)` defaults to 50. `skinnedWindowsExposeEveryIdentifier` launches at 60 and expects `main.volume` to read "60", so the check proves the argument works instead of trusting the default.
  - `-playlistWindowSize`: no app change was needed. Arguments reach the test suite through `NSArgumentDomain`. The plan's `0 3` is passed as an XML plist array, because the old-style `(0, 3)` reads back as strings and `PlaylistModel` reads `[Int]` (checked with a throwaway reader on the host).
- **`run-tests-vm.sh` summary grep** (finding 3): `Test Suite .RoadieUITests. (passed|failed)`, and the added `Executed .* tests` is gone.
- **Retried passes are visible** (finding 4). On a pass, `verify.sh` reads `ui-tests.log`, and a test with both a failed and a passed `Test Case` line goes on the `UI` line as `(N passed on retry: names)`. Two new `test_verify_report.py` cases cover it.
- **Slider values round** (run 20261024-230734-27669). `main.volume` read "60.00000238418579", because `AXValue` is Float precision. `value(of:)` now rounds every number to the nearest integer. Every slider steps in whole percent, and the slider reads (volume now; position and balance later) all go through `value(of:)`.
- **Minor:** `testPlaysTheFixtureLibrary`'s comment now says the `main.time` check is a smoke check (any change passes, including the reset when the album ends). `menuItem(_:)` was unused, so it's removed.
- `docs/testing-in-vm.md` lists the two new arguments, the harness's covered-window check and the retry note.

## Gotchas

- **The covered-window check in `click`/`doubleClick` hasn't run yet.** It assumes `app.windows` lists windows front to back (AX order). The first UI test that clicks a non-hittable element under another window should confirm that on a failing-then-fixed run, or replace the order with a check that doesn't need it.
- **The coordinate-click fallback clicks whatever is on top.** `RoadieUIApp.click`/`doubleClick` fall back to a coordinate click when an element isn't hittable. Here `main.stop` sat under the Library window, so the click went to the Library. The harness now checks for a covering window and brings the target forward first (after the review bounce), but later UI tests should still prefer menu commands and keyboard shortcuts (Playback › Stop is ⌃⌘V) over clicking skinned controls behind another window.
- **SwiftUI on macOS puts `.accessibilityValue` in `AXValue` only for static text** (and native controls). Any other custom element exposes it as `AXValueDescription`, which XCUITest can't read. `eqSlider` (EQ bands, preamp) still has this. When #0203 fixes it the same way, the readable value becomes Webamp's 0...100 position, not dB.
- **The fixture tracks are 2.5 s and auto-advance, and `Player.next()` always starts playback.** Don't assert a specific current row after transport clicks; read it from the probe.

## Notes

- **Run 20261024-222256-1703** (first UI run that executed tests in the guest). No permission prompt; Roadie launched and drew the base skin, and the probe worked. Wall times, from the step logs' finish times (run.out has no per-step timer): `ui-build` about 5 s (an incremental `build-for-testing` right after `app-build`), `ui-tests` about 49 s (xcodebuild: 6 executions, 3 tests × 2 iterations, in 43.1 s).
- **Empty `value`s.** `main.marquee`, `main.time` and `main.volume` read as `""` while the rows and `state.probe` read correctly. Checked on the host with a small SwiftUI app and an `AXUIElement` dump (a plain accessibility client, not XCUITest): SwiftUI on macOS puts `.accessibilityValue` in `AXValue` only for static text. An `.accessibilityElement(children: .ignore)` element over non-text content gets role `AXUnknown` with the value in `AXValueDescription`, and so does a custom `.accessibilityAdjustableAction` element. XCUITest can't read `AXValueDescription`. The rows (`.combine` over `Text`s) and the probe (an `NSView` with `.staticText`) are static text, so they worked. Fixes: `skinDisplay` (and so `AXMarker`) adds `.isStaticText`; `SkinSlider` uses `.accessibilityRepresentation { Slider(0...100, step 2) }`, an `AXSlider` whose `AXValue` is the position in percent and whose value description is the old string.
