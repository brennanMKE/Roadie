## Description

MilkDrop's L opened a preset browser over the picture: the presets folder as a list, arrows to move, Enter to load. With #0236 Roadie's visualization can only step through presets one at a time; with a folder of hundreds of `.milk` files (after #0241 and #0243) that's no way to find one.

## Root cause

This was a missing feature: #0236 left Presets… disabled, and #0237 had only an `isListOpen` stand-in flag.

## Fix

- `PresetListModel` (`App/Visualization/VisualizationPresetListModel.swift`) holds the list's state. It reads the presets once when the list opens and marks each one as current or failed. It filters names with `localizedStandardContains` and keeps a selection index that ↑ ↓ move, clamped at the ends.
- `VisualizationModel+PresetList.swift` adds `openList`, `closeList` and `loadListSelection`. `isListOpen` is a computed get/set over `presetList`. While the list is open, auto-advance is suspended with a new `.list` suspension. `perform(_:)` ignores every command except Esc and ⌥Return. Return loads the selected preset with the 1.7 s key blend and closes the list. A failed preset can't be loaded, and the list stays open. The song overlay (#0238) can read `isListOpen` to hold itself up.
- `VisualizationPresetListView` is the SwiftUI panel: at most 480 wide and 70 % of the height, dark material, `vis.browser`. The search field (`vis.browser.search`) keeps focus. It uses `onKeyPress` for ↑ ↓, Return (⌥Return toggles full screen) and Esc, with `onSubmit` as a fallback for Return. A double-click on a row loads it.
- `VisualizationHostView.setPresetList` adds and removes the panel's `NSHostingView` and gives the keys back to the host view when the list closes. The window controller drives it by observing `presetList`.
- **Row accessibility:** each row uses `.skinDisplay` (#0200), which makes it one element with the static-text trait. On macOS, SwiftUI puts `accessibilityValue` into `AXValue` only for static text. A bare `.ignore` element gets role `AXUnknown`, and its value goes to `AXValueDescription`, which XCUITest can't read. That is why runs 1 and 2 read the value as "". Dropping `.isSelected` in run 2 didn't help; the trait wasn't the cause.
- **VoiceOver:** the row under the cursor is announced with `.accessibilityHint("Selected")` rather than the `.isSelected` trait. This keeps the row plain static text, with its value "current", "failed" or empty.
- The host view's `keyDown` isn't changed. The `perform` guard does the same job.

## Gotchas

- A SwiftUI accessibility value is readable from XCUITest only on a static-text element. Use `.skinDisplay`.

## Plan

- `VisualizationModel.isListOpen` (introduced as a stand-in flag by #0237; real now), toggled by L (`presetList`) and the right-click menu's Presets… (enabled now). While open: overlay hold `.browser`, auto-advance suspended; Esc closes it first (#0237's order).
- `VisualizationPresetListView` (SwiftUI, in the overlay hosting view, centred panel max 480×70 % of the height, dark material; `vis.browser`):
  - a search field (`vis.browser.search`), focused on open; typing filters by `localizedStandardContains` on the name;
  - a `List` of `navigator`'s presets in catalogue order (`vis.browser.row.N`, N in the filtered list; label = name; value `current` for the shown preset, `failed` for a failed one), with a trailing source tag "Classic" / "MilkDrop" / "Yours" (secondary); failed rows dimmed with "Couldn't load"; the current row selected and scrolled to on open;
  - ↑ ↓ move the selection (the list handles them while it has focus; the search field forwards ↑ ↓ and Return to the list via `onKeyPress`), Return or double-click loads the selected (`navigator.select(id:)`, 1.7 s blend) and closes, Esc closes.
- Keys while the list is open go to it, not `VisKeyMap` (the host view's `keyDown` returns early when `isListOpen`), except Esc and ⌥Return.
- The list reads the presets once on open (the catalogue changes only when Settings' folder changes, #0241).
