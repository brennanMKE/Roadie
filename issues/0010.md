# 0010 — Server address input is not normalized or tested

| | |
|---|---|
| **Status** | open |
| **Module** | PlexKit |
| **Platform** | macOS |

## Description

Implement `PlexAddress.normalize(_:)` and a three-step connection test whose failures map to the user-facing messages in `docs/plex-music-library.md`.

## Acceptance criteria

- `joe`, `joe:32400`, `http://joe:32400`, `192.168.1.10` normalize as documented; `https://` is kept.
- Identity → sections-with-token → music-section-exists, each with its own message.
- The `machineIdentifier` is saved; a change clears the selected library.
- Unit tests cover normalization and every failure path.

## Plan

### Scope and decisions

This issue adds three small, pure pieces to the `PlexKit` target that #0009 landed in `Packages/PlayerKit`: address normalization, the three-step connection test with its user-facing messages, and the "remember the server, clear the library when it changes" rule. No UI, no Keychain, no `UserDefaults` writes (#0011), no Info.plist keys (#0012), no downloads (#0013), no plex.tv (#0014). Everything is testable against `StubURLProtocol` and the fixtures from #0009, and nothing here touches the VM script or `project.yml`.

- **`PlexAddress.normalize(_:)` returns a `URL` and throws `PlexError.invalidBaseURL`**, the case #0009 reserved. The rules are exactly the doc's four examples plus the obvious edge cases (whitespace, trailing slash, a custom port, `https://`), listed in section 1 so the tests and the implementation agree on them. It never guesses: anything that is not an `http`/`https` URL with a host after the two additions is `invalidBaseURL`. Credentials in the URL and a query string are dropped or rejected, so a pasted `…?X-Plex-Token=…` can never become part of the saved address.
- **`PlexConnectionTest` is a `Sendable` struct that builds two `PlexClient`s** (one without a token for `/identity`, one with it for `/library/sections`) and maps the outcome to a typed `PlexConnectionFailure`. The three doc messages (plus "The server address is not valid." for a string that will not normalize) live in one place, `PlexConnectionFailure.message`, so #0011 shows `failure.message` and #0012 edits exactly one string when it adds the Local Network hint. `PlexConnectionTest` takes the token as non-optional: the identity step is the only one that works without a token, and a UI that wants a token-less probe calls `PlexClient.identity()` directly.
- **The `machineIdentifier` rule is a value type, `PlexServerSelection`**, with one mutating `apply(_:)` method. It is `Codable` and holds no token (it is the "Server address", "Music library" and "Server identity" rows of the Settings table in `docs/plex-music-library.md`). #0011 persists it in `UserDefaults`; this issue only defines the type and proves the rule in tests. It also auto-selects the music library when there is exactly one, because #0011 hides the picker in that case and the app still needs a selection.
- **The stub gains per-session route tables.** `PlexClientTests` is `.serialized` because `StubURLProtocol`'s table is static, but `.serialized` does not stop a *second* suite from running at the same time. #0009's plan reserved the fix ("key routes by an `X-Stub-Session` header"); this issue needs it, so it lands here. The existing static API keeps working for `PlexClientTests`, unchanged.
- **Verification is the VM script**, as for #0009: `swift test --package-path Packages/PlayerKit` already runs `PlexKitTests`, so no step is added. The guest never sees `PLEX_URL`/`PLEX_TOKEN`; the one new opt-in integration test skips itself there like the two existing ones.

### 1. `PlexAddress` (`Sources/PlexKit/PlexAddress.swift`)

```swift
public enum PlexAddress {
    public static let defaultPort = 32400

    /// Turns what the user typed into the base URL of a Plex server, or throws
    /// `PlexError.invalidBaseURL`. Never guesses beyond adding `http://` and `:32400`.
    public static func normalize(_ text: String) throws -> URL
}

extension PlexClient {
    /// `PlexClient(baseURL: try PlexAddress.normalize(address), …)`.
    public init(address: String, token: PlexToken?, clientIdentifier: String,
                product: String = "SkinAmp", version: String = "0.1.0",
                timeout: TimeInterval = 15, session: URLSession = .shared) throws
}
```

Rules, in order (each has a test in section 5):

1. Trim whitespace and newlines. Empty → `invalidBaseURL`.
2. If the text contains no `://`, prepend `http://`. This is the only safe way to tell `joe:32400` (host and port) from `ftp://joe` (a scheme): never hand the bare text to `URLComponents`, which would read `joe` as the scheme.
3. Parse with `URLComponents(string:)`. `nil` → `invalidBaseURL` (this is what `joe:notaport` and a space inside the host produce).
4. Scheme, lowercased, must be `http` or `https`; anything else → `invalidBaseURL`. The output scheme is lowercase.
5. Host must be non-empty; `http://` alone → `invalidBaseURL`. The host is lowercased (DNS and Bonjour names are case-insensitive).
6. `user` or `password` present → `invalidBaseURL`. Credentials belong in the `X-Plex-Token` header, never in a URL that will be saved and logged.
7. Port `nil` → `32400`. A present port must be in `1...65535`, else `invalidBaseURL` (`URLComponents` accepts `99999`).
8. Path: drop trailing slashes; an empty or `/` path becomes `""`. A non-empty path is kept (a reverse proxy at `http://host/plex` is plausible; `PlexClient.request` already joins against a base with a path).
9. Query and fragment are discarded. Not an error: a URL copied from a browser's address bar often has `?X-Plex-Token=` or `#!/` on it, and the right thing is to keep the server and lose the rest.
10. `components.url` is the result. `nil` here → `invalidBaseURL`.

Resulting table (`→` is `absoluteString`):

| Input | Output |
|---|---|
| `joe` | `http://joe:32400` |
| `joe:32400` | `http://joe:32400` |
| `http://joe:32400` | `http://joe:32400` |
| `192.168.1.10` | `http://192.168.1.10:32400` |
| `https://joe:32400` | `https://joe:32400` |
| `https://1-2-3-4.abcdef.plex.direct:32400` | unchanged |
| `joe:3000`, `http://joe:8080` | `http://joe:3000`, `http://joe:8080` |
| `  joe  `, `joe\n`, `joe/`, `http://joe:32400/` | `http://joe:32400` |
| `HTTP://Joe:32400` | `http://joe:32400` |
| `brennan-mac-mini-m1.local`, `joe.tailnet.ts.net` | `http://….local:32400`, `http://joe.tailnet.ts.net:32400` (ATS for the long name is #0012's problem, not normalization's) |
| `http://joe:32400/plex/` | `http://joe:32400/plex` |
| `joe?x=1#f`, `http://joe:32400/?X-Plex-Token=abc` | `http://joe:32400` |
| `` , `   `, `ftp://joe`, `http://`, `joe:notaport`, `joe:0`, `joe:99999`, `http://user:pw@joe`, `ht tp://joe`, `joe:32400:1` | throws `invalidBaseURL` |

`normalize` is idempotent: `normalize(normalize(x).absoluteString) == normalize(x)` for every valid row.

### 2. `PlexConnectionTest` (`Sources/PlexKit/PlexConnectionTest.swift`)

```swift
public struct PlexConnectionTest: Sendable {
    public var clientIdentifier: String           // PlexClientIdentifier.stored() in the app; a constant in tests
    public var product: String
    public var version: String
    public var timeout: TimeInterval
    public var session: URLSession

    public init(clientIdentifier: String, product: String = "SkinAmp", version: String = "0.1.0",
                timeout: TimeInterval = 15, session: URLSession = .shared)

    /// Normalizes `address`, then runs the three checks.
    public func run(address: String, token: PlexToken) async throws(PlexConnectionFailure) -> PlexConnection
    /// The three checks against an already-normalized base URL.
    public func run(baseURL: URL, token: PlexToken) async throws(PlexConnectionFailure) -> PlexConnection
}

/// What a successful test learned. Holds no token.
public struct PlexConnection: Hashable, Sendable {
    public var baseURL: URL
    public var identity: PlexIdentity             // machineIdentifier + version
    public var musicSections: [PlexLibrarySection]   // non-empty by construction
}

public enum PlexConnectionFailure: Error, Hashable, Sendable, LocalizedError {
    case invalidAddress                           // normalize threw
    case unreachable(PlexError)                   // step 1 failed for any reason
    case unauthorized                             // step 2: 401 (or 403)
    case noMusicLibrary                           // step 3: no section with type == "artist"

    /// The user-facing text, verbatim from docs/plex-music-library.md.
    public var message: String {
        switch self {
        case .invalidAddress: "The server address is not valid."      // == PlexError.invalidBaseURL.errorDescription
        case .unreachable:    "Can't reach the server. Check the address, and whether you're on the home network or Tailscale."
        case .unauthorized:   "Signed in, but this account can't access this server."
        case .noMusicLibrary: "This server has no music library."
        }
    }
    public var errorDescription: String? { message }
    /// The client error behind `.unreachable`, for logs and a disclosure in Settings; nil otherwise.
    public var underlying: PlexError? { … }
}
```

`run(baseURL:token:)`:

1. **Identity.** `PlexClient(baseURL:, token: nil, …).identity()`. *Any* `PlexError` → `.unreachable(error)`: `.transport` is the doc's "no response", and a 404, an HTML page (`.notJSON`) or a decoding failure mean there is a server at that address but it is not Plex, which to the user is the same message. The call is made without a token on purpose (the doc: `/identity` needs none, and the first step must tell "wrong address" from "wrong token"). Stop here on failure; the sections request is never sent.
2. **Sections with the token.** `PlexClient(baseURL:, token: token, …).librarySections()`. `.unauthorized` → `.unauthorized`; `.httpStatus(403)` → `.unauthorized` too (a valid token for an account without access to this server). Any other `PlexError` → `.unreachable(error)` (the server stopped answering between the two requests).
3. **A music section exists.** `sections.filter(\.isMusic)`; empty → `.noMusicLibrary`. Otherwise return `PlexConnection(baseURL:, identity:, musicSections:)`.

`run(address:token:)` is `try PlexAddress.normalize(address)` mapped to `.invalidAddress`, then step 1–3. No request is sent for an invalid address.

Logging: one `os.Logger` `info` line per run with the outcome case name and the host (`privacy: .public`), nothing else. The token is never a parameter of anything that logs; `PlexConnectionFailure` carries only a `PlexError`, which #0009 already proved cannot contain the token.

Typed throws (`throws(PlexConnectionFailure)`) are Swift 6.0 and keep the UI's `catch` exhaustive. If the guest toolchain objects to typed throws on an `async` function, fall back to plain `throws` and say so in `## Fix`; the tests use `do`/`catch let failure as PlexConnectionFailure` either way, which works for both.

### 3. `PlexServerSelection` (`Sources/PlexKit/PlexServerSelection.swift`)

```swift
/// The Plex settings that are not secrets: the address as typed, the server's identity,
/// and the chosen music library. #0011 stores this in UserDefaults. Deliberately holds no token.
public struct PlexServerSelection: Hashable, Sendable, Codable {
    public var address: String                    // raw text; normalized on every use
    public var machineIdentifier: String?         // from the last successful connection test
    public var librarySectionKey: String?         // PlexLibrarySection.key, or nil = none chosen yet

    public init(address: String = "", machineIdentifier: String? = nil, librarySectionKey: String? = nil)

    public enum Change: Hashable, Sendable { case none, serverChanged, libraryMissing, autoSelected }

    /// Records a successful connection. If the machineIdentifier differs from the saved one,
    /// the address now points at another server and the selected library is cleared.
    /// A selected library that the server no longer lists is cleared too. When the server has
    /// exactly one music library and nothing is selected, it is selected.
    @discardableResult
    public mutating func apply(_ connection: PlexConnection) -> Change

    /// The selected section among `sections`, if it is still there.
    public func selectedSection(in sections: [PlexLibrarySection]) -> PlexLibrarySection?
}
```

`apply` order: (a) if `machineIdentifier != nil && machineIdentifier != connection.identity.machineIdentifier` → `librarySectionKey = nil`, change `.serverChanged`; (b) set `machineIdentifier`; (c) if `librarySectionKey` is set and not among `connection.musicSections.map(\.key)` → clear, `.libraryMissing` (unless (a) already fired); (d) if `librarySectionKey == nil && connection.musicSections.count == 1` → select it, `.autoSelected` only when neither (a) nor (c) fired — otherwise the first change wins, so the UI can say "The server changed; pick a library" even though one was auto-picked. `address` is not touched by `apply`; the UI owns it.

### 4. Stub: per-session route tables (`Sources/PlexKitStub/StubURLProtocol.swift`)

### 8. Risks

- **`URLComponents` edge cases.** Behaviour to confirm in the guest rather than assume: whether `URLComponents(string: "http://joe:99999")` parses (the plan checks the range itself either way); whether an uppercase scheme is returned as typed (lowercase it explicitly); whether `http://[fd00::1]` yields `host == "fd00::1"` or `"[fd00::1]"` (Foundation changed this). IPv6 is not in the acceptance criteria: if a bracketed literal does not round-trip cleanly, leave it out of the tests and note it in `## Gotchas` rather than special-case it.
- **Typed throws on an `async` function.** Supported since Swift 6.0, but `#expect(throws:)` with a typed-throws closure and `Task` boundaries have had rough edges. Write the tests with `do { … ; Issue.record("expected failure") } catch let failure as PlexConnectionFailure { #expect(failure == …) }` (the pattern `malformedJSONIsDecodingError` already uses), which works whether or not the throw stays typed. Fall back to untyped `throws` if the toolchain refuses; say so in `## Fix`.
- **`httpAdditionalHeaders` and `URLProtocol`.** The handle relies on the session's additional headers being visible to `startLoading` (`request.value(forHTTPHeaderField:)`). They are merged into the request before the protocol sees it on current Foundation, and test 31 proves it. If they are not, the fallback is structural, not a different stub: make both stub-using suites nested `@Suite`s of one `@Suite(.serialized) enum PlexStubSuites` (`.serialized` on a parent applies to its children), drop the handle, and note the change in `## Fix`. Do not ship a stub whose cross-suite race is left to luck.
- **Message text will change in #0012.** The unreachable message is in one place and one test (`messagesMatchTheDoc`) asserts it verbatim; #0012 edits the string, the doc table and that one expectation together. Keep it that way: no other test should contain the message text.
- **403 as unauthorized.** Plex answers 401 for a missing or bad token; a 403 for a valid token without access to this server is plausible but not verified against joe. Mapping both to the "Signed in, but…" message is right for the user either way; the opt-in test 32 only proves the 401 path.
- **Identity answered, but by something else.** A random web server on the typed port returns HTML; mapping `.notJSON`/`.notFound` to "Can't reach the server" is the chosen behaviour. The underlying `PlexError` stays in `.unreachable` so #0011 can show it in a disclosure and a log line can say *why*.
- **`apply` precedence.** Two changes can be true at once (server changed *and* a single library auto-selected). The rule "first change wins" is specified in section 3 and tested (26); the UI only needs `Change` for a status line, so the exact enum is cheap to revise in #0011 if it wants more.
- **`PlexServerSelection.address` is raw text.** Storing what the user typed, and normalizing on use, means a later edit of the normalization rules changes behaviour for saved addresses. Acceptable; the alternative (storing the normalized URL) hides what the user typed. #0011 may decide to store both; nothing here prevents it.
