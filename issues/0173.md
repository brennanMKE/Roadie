## Description

Umbrella for milestone **M15: Music selection**. Roadie has no good way to pick music from the skinned windows. Winamp users rarely opened a file dialog: they loaded everything into one playlist and used Jump to File (`J`), queued tracks to play next (`[n]` markers), and dragged from the Media Library into the playlist. This milestone brings those three things to Roadie. It ships no code itself and stays open until every child is resolved, closed or won't-fix.

Spec: [docs/music-selection-features.md](../docs/music-selection-features.md) (the user, 2026-10-23). The plan follows its phase order:

- **A: Jump to File.**
- **B: play-next queue** with `[n]` markers and Library Play Next.
- **C: Library ↔ playlist editor.**

The children's plans were checked against the code. Where the spec is wrong about the code, the plans say so and use what the code really does (see "Spec corrections" below).

## Spec corrections (checked against the code, 2026-10-23)

- **Next free issue number:** 0173. The spec says "after 0169", but 0170–0172 exist.
- **⌘J is free** in both the skinned pop-up menu (`MainMenu.swift`) and the menu bar (`RoadieApp`, `PlaybackCommands`, `SkinsCommands`). But every shortcut in the pop-up must also be in the menu bar: see the `MainMenuShortcut` doc and `MainMenuTests.shortcutsMatchMenuBar`. So Jump to File needs a menu-bar item too, in Playback.
- **Roadie already has a Library command:** "Library", ⌘L, at the top of the Playback menu and in the Window menu (#0115). Only the skinned pop-up menu lacks it, so the new "Media Library" item reuses ⌘L. Bare `L` is already Open File.
- **The playlist has no right-click menu.** `PlaylistContextMenus` only holds the SORT and MISC pop-ups. Right-click is wired only for the main window (`SkinWindowController`, `onRightMouseDown` for `.main`). Control-click on a row is a ⌘-click (toggle selection) in `PlaylistListInputView.mouseDown`. #0179 adds a menu on `rightMouseDown`.
- **The rows the panel searches:** `QueueRowsSource` is chosen in `PlayerModel.observeQueue()` and isn't stored. `PlaylistModel` shows `.none` as an empty remote snapshot, so the two look the same. `PlaylistModel.tracks` already turns local and remote rows into `[Track]`, so Jump to File searches that and reads the source from a new stored property.
- **Remote queues are capped:** `RemoteQueueSnapshot.items` stops at 2,000 for Music Assistant (#0132). Jump to File on a speaker searches only the rows that were fetched.
- **The remote reorder path** moves one item per call (`player_queues/move_item` with `pos_shift`). Music Assistant refuses to move items at or before its buffered index (`QueueEditError.buffered`). So queueing several rows on a remote queue takes several moves in a row.
- **`QueueStore.loadQueue()` accepts only `version == currentVersion`.** Bumping the version would make the new build reject every existing `queue.json`, and older builds would reject new files. #0178 adds an optional `upNext` key and keeps version 1.
- **Name clash:** `Player.enqueue(_ tracks:)` already exists. The spec's `enqueueNext`/`toggleQueued`/`dequeue` become `prependUpNext`/`toggleUpNext`/`removeFromUpNext`, plus `appendUpNext` and `clearUpNext` (#0177).
- **Row text:** `PlaylistText.displayName` takes `artist:title:fileName:`. The App's `PlaylistModel.displayName(_ track:)` turns a `Track` into a row. The matcher lives in a package and takes plain strings.
- **Library search focus:** `LibraryWindowView` uses `.searchable(placement: .toolbar)`. `searchFocused` needs macOS 15, and the deployment target is 14.0. #0185 uses AppKit's `NSSearchToolbarItem.beginSearchInteraction()` instead.
- **Opening the Library from AppKit:** it is a SwiftUI `Window` scene opened with `openWindow(id: "library")`. `PlayerModel`, which runs the pop-up menu's commands, has no `OpenWindowAction`. #0185 captures one from `PlayerView`, which already uses `openWindow`.
- **Drops on the track list:** the rows are covered by an AppKit view, `PlaylistListInputView`. It is a sibling of the SwiftUI hosting view, not its child, and it already owns the mapping from rows to y positions. So drop-at-row is an AppKit dragging destination on that view (#0183, #0184). The SwiftUI `.dropDestination(for: URL.self)` on `PlaylistView` stays for the rest of the window.
- **Confirmed as the spec says:**
  - `Track.id` is a UUID per queue entry.
  - `MAQueueOption.next` exists.
  - `MediaIDTransfer` exists. Album and track rows in the Library are `.draggable` (#0136).
  - `Player.reconcileSchedule()` and `scheduleNextIfNeeded()` (about lines 481–503) read `queue.indexAfterCurrentEnds()`.
  - `QueueSnapshot` holds items, the current index, repeat and shuffle.
  - `PlayMode` has only `.replace(startIndex:)` and `.append`.

## Open decisions (defaults in the plans; say if you want otherwise)

1. **Queue file version** (#0178): add an optional `upNext` key and keep version 1. The spec said to bump the version, but that throws away every existing saved queue unless the loader also changes. With the optional key, downgrading keeps the queue and drops only the markers.
2. **`[n]` placement** (#0179): its own cell just before the time column, so a long title truncates before the marker does. This holds until #0174 says where Winamp puts it.
3. **Media Library item** (#0185): it opens the Library or brings it forward, with a check mark while it's open. It doesn't close the Library, the same as the existing ⌘L. ⌘L from the menu bar and from the pop-up also puts the cursor in the search field. No bare key until #0174.
4. **Dragging Library rows onto a Music Assistant queue** (#0184): they're added at the end. Moving them to the drop row afterwards would need the new items' queue ids from the next refetch. That's fragile, so it's left out.
5. **Shuffle and the queue** (#0177): a queued entry that plays stays in the current shuffle pass, so it can come up again later in that pass.
6. **Play Next order** (#0181): each Play Next goes to the front of up-next. Local does this to match Music Assistant's `next` option, which inserts right after the current track. Queue (`Q`, the Queue button) adds to the end of up-next.
