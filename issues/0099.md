# 0099 — A skin missing a bitmap draws blank holes instead of falling back to a base skin

| | |
|---|---|
| **Status** | open |
| **Module** | SkinKit / App |
| **Platform** | macOS |
| **First seen** | 2026-10-19 |

## Description

Winamp loads each bitmap of a skin from its base skin when the skin doesn't ship it (e.g. a skin with no `eqmain.bmp` or `pledit.bmp`). SkinAmp has two TODOs for this: `SkinParser.parse` (`// TODO: base-skin fallback.`) and `SpriteImage` in `App/MainWindowView.swift` (`TODO: fall back to a generated base skin instead of an empty frame.`), which draws `Color.clear` for any sprite whose sheet is missing.

Expected:

- A **generated** base skin: sheets drawn in code at the classic sizes (simple bevelled grey controls, readable digits/text glyphs where practical), so no Nullsoft or Webamp artwork is copied into the repo.
- A missing sheet is filled from the generated base and listed in `Skin.fallbacks` (e.g. "eqmain.bmp missing; generated base"); `SpriteImage` no longer needs its empty-frame branch for sheets the base provides.
- Tests: a skin archive built in the test without some sheets parses with those sheets present, the right sizes, and the fallback recorded; existing skins are unchanged.
