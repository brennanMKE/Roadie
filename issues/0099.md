## Description

Winamp loads each bitmap of a skin from its base skin when the skin doesn't ship it (e.g. a skin with no `eqmain.bmp` or `pledit.bmp`). SkinAmp has two TODOs for this: `SkinParser.parse` (`// TODO: base-skin fallback.`) and `SpriteImage` in `App/MainWindowView.swift` (`TODO: fall back to a generated base skin instead of an empty frame.`), which draws `Color.clear` for any sprite whose sheet is missing.

Expected:

- A **generated** base skin: sheets drawn in code at the classic sizes (simple bevelled grey controls, readable digits/text glyphs where practical), so no Nullsoft or Webamp artwork is copied into the repo.
- A missing sheet is filled from the generated base and listed in `Skin.fallbacks` (e.g. "eqmain.bmp missing; generated base"); `SpriteImage` no longer needs its empty-frame branch for sheets the base provides.
- Tests: a skin archive built in the test without some sheets parses with those sheets present, the right sizes, and the fallback recorded; existing skins are unchanged.

## Root cause

`SkinParser` never filled absent sheets (a TODO), so any sprite on a missing sheet resolved to nil and `SpriteImage` drew `Color.clear`.

## Fix

Followed the plan. New `GeneratedBaseSkin` draws every sheet except BALANCE, NUMS_EX, EQ_EX and GEN in code: bevelled grey boxes, 7-segment NUMBERS digits, and Menlo 7pt glyphs for TEXT. The images are cached. `SkinParser` fills sheets that are missing or undecodable after the `noBitmaps` guard. It skips NUMBERS when NUMS_EX is present, adds `<sheet>.bmp missing|undecodable; generated base` to fallbacks and records the sheet in `Skin.generatedSheets`. Warnings are unchanged. `CorpusRun.mainWindowComplete` ignores generated sheets. The thumbnail cache version is now 2. The App `SpriteImage` TODO is replaced with a comment.

Deviation: `SkinThumbnailCacheTests.failedSkinIsNegativeCachedInMemoryAndOnDisk` hardcoded `cache/r1/` for a cache using the default version. It now uses `SkinThumbnailCache.thumbnailVersion`.

## Plan

Scope: a code-drawn grey base, filled in by `SkinParser` for sheets the skin doesn't ship. No artwork is copied from Winamp, Webamp or any skin. Keep the look modest: bevelled grey boxes, 7-segment digits, and system-font text glyphs. Warnings stay as they are today (a skin missing `cbuttons.bmp` is still `partial`, and `Missing cbuttons.bmp` is still listed). The base only adds a fallback line and fills the hole, so the library status, ingester and corpus tests keep their meaning.

### Files to change

1. **New: `Packages/SkinKit/Sources/SkinKit/Sprites/GeneratedBaseSkin.swift`** (`enum GeneratedBaseSkin`, internal)
   - `static let sheetNames: Set<String>`: every key of `SkinSprites.sheets` except `BALANCE`, `NUMS_EX`, `EQ_EX` and `GEN`. Those four keep their existing Webamp fallbacks or stay unused. `NUMBERS` is included, but the parser only uses it when both number sheets are missing (see 2).
   - `static func size(of sheet: String) -> (width: Int, height: Int)`: the sprite extents, `max(x + width)` × `max(y + height)` over `SkinSprites.sheets[sheet]`, the same rule as `TestSkin.make`. Every sprite rect then fits, including the 28 frames of `VOLUME` and the `EQ_SLIDER_BACKGROUND` band frames.
   - `static func sheet(_ name: String) -> CGImage?`: returns a cached image, nil for names not in `sheetNames`. Cache: `nonisolated(unsafe) private static let cache: [String: CGImage] = Dictionary(uniqueKeysWithValues: sheetNames.compactMap { n in draw(n).map { (n, $0) } })`. CGImage is immutable, and that is why `Skin` is `@unchecked Sendable`.
   - `private static func draw(_ sheet: String) -> CGImage?`:
     - Context: an RGBA8 `CGContext` with device RGB and premultipliedLast, like `TestSkin.make`. Antialiasing off. Flip it to a top-left origin with `translateBy(0, h)` then `scaleBy(1, -1)`, so sprite rects are used as they are.
     - Fill the whole sheet opaque dark grey `(40, 40, 48)`.
     - **Generic pass** (every sheet except `NUMBERS` and `TEXT`): draw sprites largest area first (the same sort as `TestSkin.make`), each as a bevelled box.
       - Raised bevel: face `(150, 150, 160)`, a 1 px top/left edge `(220, 220, 230)`, a 1 px bottom/right edge `(70, 70, 80)`.
       - Sunken bevel (light and dark edges swapped, face `(120, 120, 130)`) when the name contains `ACTIVE`, `SELECTED`, `DEPRESSED` or `PRESSED`.
       - Names containing `BACKGROUND`, plus `MAIN_WINDOW_BACKGROUND` and `EQ_WINDOW_BACKGROUND`: face `(60, 60, 70)` and a raised edge, so displays read as dark panels.
       - Skip bevels on sprites with width or height < 3: plain face fill.
     - **`NUMBERS`**: background black. For `DIGIT_0`…`DIGIT_9` at their sprite rects, draw lit 7-segment bars in green `(0, 230, 0)` (a static segment table, `[Int: [Segment]]`). Segments inside each 9×13 cell:
       - a = (1, 0, 7×1)
       - b = (7, 1, 1×5)
       - c = (7, 7, 1×5)
       - d = (1, 12, 7×1)
       - e = (1, 7, 1×5)
       - f = (1, 1, 1×5)
       - g = (1, 6, 7×1)

       Don't draw the `MINUS_SIGN` / `NO_MINUS_SIGN` sprites separately. They are 5×1 at y 6 inside digits 2 and 1, so the minus is digit 2's g segment and the blank is digit 1's empty middle, the same trick the real sheet uses.
     - **`TEXT`**: background black. For each `CHARACTER_<code>` sprite, draw `String(UnicodeScalar(code)).uppercased()` in `(0, 230, 0)`. Use CoreText (`import CoreText`; `CTFontCreateWithName("Menlo" as CFString, 7, nil)`, `CTLineCreateWithAttributedString`, `CTLineDraw`) at the sprite's origin. Clip to the 5×6 rect with `context.saveGState()` and `clip(to:)`. Text needs a y-up CTM: inside the save, translate to the cell's bottom-left and `scaleBy(1, -1)`. Skip invalid scalars. `CHARACTER_32` (space) stays blank.
2. **`Packages/SkinKit/Sources/SkinKit/SkinParser.swift`**: replace `// TODO: base-skin fallback.`. Right after `guard !sheets.isEmpty else { throw .noBitmaps }` (generated sheets must never satisfy that guard), add:
   - `var generated: Set<String> = []`.
   - Track undecodable sheets in a new `var undecodable: Set<String>` inside the decode loop. Keep the `Undecodable …` warning.
   - For each `sheet in GeneratedBaseSkin.sheetNames.sorted()` where `sheets[sheet] == nil`:
     - If `sheet == "NUMBERS"` and `sheets["NUMS_EX"] != nil`, `continue`. NUMS_EX already covers the digits.
     - Otherwise, if `let image = GeneratedBaseSkin.sheet(sheet)`, set `sheets[sheet] = image`, insert it into `generated`, and append the fallback `"\(sheet.lowercased()).bmp \(undecodable.contains(sheet) ? "undecodable" : "missing"); generated base"`.
   - Leave every existing `missing`-based warning and fallback line unchanged. They still read the `missing` set, so `Missing cbuttons.bmp` and `Missing numbers.bmp and nums_ex.bmp` stay. `balance.bmp missing; balance slider uses volume.bmp` now also appears when volume was generated, which is correct.
   - Pass `generatedSheets: generated` to `Skin(...)`.
3. **`Packages/SkinKit/Sources/SkinKit/Skin.swift`**: add `public let generatedSheets: Set<String>` (doc: sheets drawn by `GeneratedBaseSkin` because the skin lacked them or they didn't decode) with an init parameter `generatedSheets: Set<String> = []` (last, after `cursors`). Tweak the `fallbacks` doc to mention the generated base.
4. **`Packages/SkinKit/Sources/SkinKit/Tooling/CorpusRun.swift`** (line ~440): `mainWindowComplete` must still mean "the skin itself draws the main window". Use `requiredSprites.allSatisfy { skin.resolve($0).map { !skin.generatedSheets.contains($0.sheet) } ?? false }`. That keeps `mainWindowCompleteFollowsRequiredSprites` passing (`no_cbuttons` → false).
5. **`Packages/SkinKit/Sources/SkinLibrary/Thumbnails/SkinThumbnailCache.swift`**: change `thumbnailVersion` from 1 to 2. Thumbnails of partial skins change pixels.
6. **`App/MainWindowView.swift`** (`SpriteImage`): keep the `Color.clear` branch. It is still reached for EQ_EX/GEN sprites with no fallback. Replace the TODO comment with: `// Only sheets the generated base doesn't provide (EQ_EX, GEN) reach this; see GeneratedBaseSkin.` No other app change.

No `SkinIngester.parserVersion` bump: status and warnings don't change.
