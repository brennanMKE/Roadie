# 0026 — Skin rendering cannot be compared against Webamp

| | |
|---|---|
| **Status** | open |
| **Module** | SkinKit |
| **Platform** | macOS |

## Description

Add `skintool --png <out>` to render the main window offscreen to a PNG for side-by-side comparison with Webamp.

## Acceptance criteria

- Renders headless without AppKit windows.
- Comparison of the 10 sample skins is documented, including any differences.

## Plan

### Scope and decisions

This issue adds one CoreGraphics compositor for the main window to SkinKit, makes the app draw through it, exposes it as `skintool --png`, and documents a pixel comparison of the 10 sample skins against Webamp's own screenshots. It does not add any element the main window lacks today (marquee #0021, time/kbps/kHz/monoster #0022, sliders and toggles #0023, visualizer #0024) or the borderless window (#0025); it provides the place those issues draw into.

- **Order within M4.** After #0020 (fallbacks, so all 10 sample skins parse `ok` and sprite lookup handles `NUMS_EX`/balance/viscolor), and *before or alongside* #0021–#0024: the renderer core, the shared layout table and `--png` should land first so each sibling adds a layer to the renderer instead of a SwiftUI view that would then have to be ported. #0025 is independent; the `NSHostingView` it adds hosts the image view described in section 4. The comparison doc (section 6) is written last, once #0021–#0024 are in; a first pass with the elements that exist today is fine and the doc is updated as layers land.
- **One compositor, no AppKit.** `MainWindowRenderer` lives in SkinKit and draws into a `CGContext` using only CoreGraphics and ImageIO (PNG encode via `CGImageDestination`). `skintool` and the app call the same `render(skin:state:scale:)`. The app's `MainWindowView` stops composing sprites with `ZStack` offsets and instead shows the rendered `CGImage` with transparent hit targets laid out from the same `MainWindowLayout` table the renderer uses. That is the "can't drift" guarantee: one layout table, one drawing routine, and the view only displays the image and maps clicks to actions. Neither SkinKit nor skintool imports AppKit (`grep -rl AppKit Packages/SkinKit` stays empty); `swift test` running headless in the guest is the proof that rendering needs no window.
- **State is a value, not the player.** `MainWindowState` is a `Sendable` struct describing everything the window shows: playback state, focus (selected title bar), elapsed and duration, marquee text and scroll offset, kbps, kHz, channels, volume, balance, position, shuffle, repeat, EQ/playlist toggle state, visualizer mode and pre-computed bar/sample data, and the pressed button, if any. The app builds one from `PlayerModel` per frame; `skintool` uses a preset. The renderer is a pure function of `(Skin, MainWindowState, scale)` and so is unit-testable by pixel.
- **The preset mirrors Webamp's screenshot state**, so our PNG and the Museum screenshot show the same thing: `MainWindowState.webampScreenshot` = playing, main window focused, elapsed 3 s of a 5 s track, marquee `1. DJ Mike Llama - Llama Whipping Intro (0:05)` at offset 0 (Webamp disables the marquee in screenshot mode), 128 kbps, 44 kHz, stereo, volume `round(200/255*100) = 78`, balance 0, position 0.6, shuffle and repeat off, EQ and playlist toggles on (both windows are open in the screenshot layout), visualizer in spectrum mode with no data, work indicator off. Sources: `packages/webamp-demo/js/screenshotInitialState.ts`, `packages/webamp/js/reducers/media.ts` (volume/balance defaults), `packages/webamp/js/reducers/windows.ts` (`focused: WINDOWS.MAIN`), `packages/webamp/js/selectors.ts` (`getMediaText`; confirm the exact marquee string there). A second preset, `.idle` (stopped, `Winamp 2.91`-style default text decided by #0021), is what the app shows with nothing loaded.
- **Positions come from `css/main-window.css`**, collected once in `MainWindowLayout` (title bar 0,0 275×14; minimize/shade/close at x 244/254/264 y 3; play indicator 26,28; time 39,26; vis 24,43; marquee 111,24 154×6; kbps 111,43; kHz 156,43; mono/stereo 212,41; volume 107,57 68×13; balance 177,57 38×13; EQ/PL toggles 219,58; position 16,72 248×10; transport 16/39/62/85/108,88; eject 136,89; shuffle 164,89 47×15; repeat 210,89 28×15). `MainWindowView` currently hard-codes six of these; they move into the table. Siblings add their rows there.
- **Static/dynamic split for the app's frame rate.** The whole window is 275×116 = 31,900 pixels, so a full redraw per visualizer frame is cheap, but the renderer still separates `static` layers (background, title bar, clutter bar, sliders' backgrounds, toggles, transport) from `dynamic` ones (play indicator, time, marquee, vis, position thumb) so the app can cache the static image per skin and redraw only the dynamic layers at 30–60 Hz if #0024's 1 ms budget needs it. `skintool` always renders both.
- **Sample skins and references stay out of git and out of the default VM export.** `/Skins/` and `*.wsz` are gitignored and `run-tests-vm.sh` exports `git ls-files -co --exclude-standard`, so neither the skins nor the Museum screenshots reach the guest unless the script is told to carry them. Section 7 adds `--skins <dir>` for that. Nothing from a third-party skin (neither `.wsz` nor a screenshot of it) is committed; the comparison doc records numbers and notes, and the images stay under `build/vm-tests/<run-id>/`.
- **Webamp checkout.** There is no `References/webamp` in the repo (the directory is gitignored and absent). A full monorepo checkout is at `/private/tmp/claude-501/-Users-brennan-Developer-brennanMKE-SkinAmp/5851b7d4-5135-49c1-ac3b-f5d40617c8c8/scratchpad/webamp-src/webamp` (commit `79117c66`, 2026-10-12, `packages/webamp` 2.3.1, no `node_modules`), with a flat copy of the main-window files at `…/scratchpad/webamp-ref/`. Paths below are relative to the monorepo. Recommend cloning it to `References/webamp` on the host so every M4 issue cites one stable location; being gitignored, it is never exported to the VM.
- **Verification is the VM script only.** `scripts/run-tests-vm.sh` (SkinKit tests pick up the renderer tests; `app-build` proves the app compiles against it), and `scripts/run-tests-vm.sh --skins Skins` for the comparison run. Nothing is built or run on the host.

### 1. SkinKit: renderer, layout, state (`Packages/SkinKit/Sources/SkinKit/Rendering/`)

```swift
/// Everything the main window shows. The app fills one from PlayerModel; skintool uses a preset.
public struct MainWindowState: Sendable, Equatable {
    public enum Playback: Sendable { case stopped, playing, paused }
    public enum Visualizer: Sendable, Equatable { case off, spectrum([UInt8]), oscilloscope([Int8]) }
    public var playback: Playback = .stopped
    public var focused = true
    public var elapsed: TimeInterval? = nil, duration: TimeInterval? = nil
    public var showsRemaining = false
    public var marqueeText = "", marqueeOffset = 0          // #0021 draws it
    public var kbps: String? = nil, khz: String? = nil        // #0022
    public var channels: Int? = nil                           // 1 mono, 2 stereo, nil neither lit
    public var volume = 78, balance = 0, position = 0.0        // #0023 draws them
    public var shuffle = false, `repeat` = false, eqOpen = false, playlistOpen = false
    public var visualizer: Visualizer = .off                  // #0024
    public var pressed: MainWindowLayout.Control? = nil       // draws the _ACTIVE sprite
    public static let webampScreenshot: MainWindowState       // values in "Scope and decisions"
    public static let idle: MainWindowState
}

/// Main-window geometry in skin pixels, from Webamp's css/main-window.css. One table for the
/// renderer and for the app's hit targets.
public enum MainWindowLayout {
    public static let size = CGSize(width: 275, height: 116)
    public enum Control: Sendable, Hashable { case previous, play, pause, stop, next, eject, minimize, shade, close, time, marquee, volume, balance, position, shuffle, `repeat`, eq, playlist, vis }
    public static func rect(_ control: Control) -> CGRect
    public static let playIndicator = CGPoint(x: 26, y: 28)  // and the other draw origins
}

public enum MainWindowRenderer {
    /// Composites the main window at `scale` (1 = 275x116). Nearest-neighbor, top-left origin.
    /// Missing sprites are skipped (the background stays visible); never traps.
    public static func render(skin: Skin, state: MainWindowState, scale: Int = 1) -> CGImage
    /// The two halves of `render`, so the app can cache the static image per skin.
    public static func renderStatic(skin: Skin, state: MainWindowState, scale: Int) -> CGImage
    public static func renderDynamic(over base: CGImage, skin: Skin, state: MainWindowState, scale: Int) -> CGImage
}
```

- `SpriteDrawer` (internal): wraps the `CGContext` (8-bit RGBA premultiplied, `CGColorSpace(name: .sRGB)`, `interpolationQuality = .none`, CTM flipped once so y grows downward like the CSS) and offers `draw(_ spriteName:, at:)`, `draw(_ image: CGImage, in: CGRect)` and `fill(_ rect:, color:)`. Everything a layer does goes through it.
- Layers: `Rendering/Layers/` with one file per element group: `BackgroundLayer` and `TitleBarLayer` (this issue: `MAIN_WINDOW_BACKGROUND`, `MAIN_TITLE_BAR[_SELECTED]`, minimize/shade/close), `TransportLayer` (this issue: previous/play/pause/stop/next/eject, `_ACTIVE` when `state.pressed` matches), `PlayIndicatorLayer` (this issue), and empty files with a `// #0021` style TODO for `MarqueeLayer`, `TimeLayer`, `MediaInfoLayer`, `SlidersLayer`, `TogglesLayer`, `VisualizerLayer`. Each layer is `static func draw(_ d: SpriteDrawer, skin: Skin, state: MainWindowState)` and is listed once in the renderer in Webamp's DOM order (`components/MainWindow/index.tsx`: title bar, status (clutter bar, play/pause, time), vis, media info (marquee, kbps, kHz, mono/stereo), volume, balance, windows toggles, position, action buttons, eject, shuffle/repeat).
- `PNGWriter.write(_ image: CGImage, to url: URL) throws` using `CGImageDestinationCreateWithURL(url, UTType.png.identifier as CFString, 1, nil)`. `ImageDiff.compare(_ a: CGImage, _ b: CGImage, tolerance: UInt8 = 0) -> ImageDiff.Result` (differing pixel count, total compared, ignored-transparent count, optional diff image with differing pixels in magenta) used by `--compare` and by tests; both live under `Rendering/` so the CLI stays thin.
- `Skin.image(for:)` keeps returning `nil` for a missing sprite; the drawer skips it and the renderer records nothing (warnings already live on `Skin`). #0020's fallbacks sit in `Skin.image(for:)`, so the renderer gets them for free.

### 2. `skintool --png` (`Packages/SkinKit/Sources/skintool/main.swift`)

Usage stays hand-parsed (no argument-parser dependency); parsing moves into `SkinKit/Tooling/SkintoolOptions.swift` so it is testable.

```
skintool <skin.wsz | folder>                       # unchanged report
skintool --png <out> [--state webamp|idle] [--scale N] [--compare <refdir>] <skin.wsz | folder>
```

- One skin: `<out>` is the PNG path. A folder: `<out>` is a directory and each skin writes `<out>/<basename>.png`; the report lines still print.
- `--state` defaults to `webamp` so output lines up with Museum screenshots. `--scale` defaults to 1.
- `--compare <refdir>` reads `<refdir>/<basename>.png` (a Museum screenshot, 275×348), crops the top 275×116, diffs it against our render with `ImageDiff` (tolerance 0 and 2), writes `<out>/<basename>.diff.png`, and prints `diff     <name>: 1234 px exact, 980 px ±2, 300 transparent-in-reference skipped`. A missing reference prints `noref    <name>` and is not an error.
- Exit codes: 64 usage, 66 missing input, 65 if every skin failed to render; otherwise 0 (a `failed` skin in a folder is reported, like today).

### 3. Reference images from Webamp (offline-friendly)

The Winamp Skin Museum's screenshots are Webamp renders produced by `packages/skin-database/shooter.js` (Puppeteer, viewport 275×348, `https://webamp.org/?screenshot=1`, `omitBackground: true`, clipped to main + EQ + playlist stacked at y 0/116/232) with the state above. They are served at `https://r2.webampskins.org/screenshots/{md5}.png` where `md5` is of the `.wsz` bytes (`docs/winamp-skin-museum-access.md`). Procedure, on the host, one time, network allowed there (the VM has none):

1. For each sample skin: `md5 -q "Skins/<name>.wsz"`, then `curl -fsSL -o "Skins/reference/<name>.png" "https://r2.webampskins.org/screenshots/<md5>.png"`. Record the md5 and whether the fetch succeeded in the comparison doc. `Skins/reference/` is under the gitignored `/Skins/`.
2. If a skin is not in the Museum (404: a locally modified or re-zipped file has a different md5): open `https://webamp.org/?screenshot=1` in a browser, load the skin through the file input (drop it on the window), and use the browser's "Capture node screenshot" on `#main-window`. Save it under the same name and note "manual" in the doc. The marquee is frozen in this mode, so the capture is deterministic.
3. Running Webamp itself in the VM is not planned: the checkout has no `node_modules` and the guest has no network. If a deterministic reproducible reference is ever needed inside the VM, it is the same Puppeteer script against a locally built `packages/webamp-demo` on the host, which is out of scope here.

### 4. App: draw through the renderer (`App/MainWindowView.swift`)

- `MainWindowView` becomes: an `Image(decorative: rendered, scale: 1).interpolation(.none)` of `MainWindowRenderer.render(skin:state:)`, overlaid with invisible hit targets positioned from `MainWindowLayout.rect(_:)` (`Button` with a clear label for transport/eject, the sliders and toggles added by #0023, time and marquee clicks by #0021/#0022). The pressed state is tracked (`@GestureState`/`ButtonStyle` → `state.pressed`) so the `_ACTIVE` sprite is drawn by the renderer, not by a second sprite view. `SpriteImage` and `SpriteButtonStyle` go away.
- `PlayerModel` gains `var mainWindowState: MainWindowState` derived from its published playback state (play indicator and transport pressed state now; elapsed/kbps/vis as siblings land). The view caches the static image per `(skin, scale)` and re-renders the dynamic layers on state change.
- #0025's `NSHostingView` hosts this view unchanged.

### 5. Tests (`Packages/SkinKit/Tests/SkinKitTests/RenderingTests.swift`)

A generated skin, not a real one: `TestSkin.make()` builds every sheet with `CGContext`, filling each sprite rectangle with a unique flat color (`index → (r,g,b)`), returning a `Skin` directly and, where a file is needed, a `.wsz` in a temp directory through ZIPFoundation. A pixel at a layout position then identifies which sprite landed there. Helper `pixel(_ image:, x:, y:) -> (r,g,b,a)`.

1. `rendersHeadless`: `render` returns a 275×116 RGBA image under `swift test` (no `NSApplication` exists in the process).
2. `backgroundAndTitleBarAtWebampPositions`: (0,0) is the background color; (100,5) is `MAIN_TITLE_BAR_SELECTED` when `focused`, `MAIN_TITLE_BAR` when not; (244,3), (254,3), (264,3) are minimize/shade/close.
3. `transportButtonsAtWebampPositions`: (16,88), (39,88), (62,88), (85,88), (108,88), (136,89) are previous/play/pause/stop/next/eject; with `pressed = .play`, (39,88) is `MAIN_PLAY_BUTTON_ACTIVE`.
4. `playIndicatorFollowsPlayback`: (26,28) is the playing/paused/stopped indicator per `state.playback`.
5. `missingSheetLeavesBackground`: a skin without `cbuttons.bmp` renders without trapping and (16,88) is the background color.
6. `staticPlusDynamicEqualsFullRender`: `renderDynamic(over: renderStatic(...))` is pixel-identical to `render(...)`.
7. `scaleTwoIsNearestNeighbor`: at scale 2 every pixel (2x+dx, 2y+dy) equals the scale-1 pixel (x,y); no intermediate colors appear.
8. `pngRoundTrips`: `PNGWriter` → ImageIO decode gives the same size and the same pixels at the sampled positions.
9. `imageDiffCountsAndIgnoresTransparentReference`: two generated images differing in k known pixels report k; a reference with t transparent pixels reports t skipped; a 275×348 reference is cropped to its top 275×116.
10. `webampScreenshotPreset`: the preset's values match `screenshotInitialState.ts` (playing, 3/5 s, 128/44/stereo, 78/0/0.6, toggles on, focused).
11. `skintoolOptionsParse`: `--png out --compare ref --scale 2 skin.wsz` parses; `--png` without a path, unknown flags and a missing input are usage errors.
12. `layoutRectsMatchSpriteSizes`: every `Control` with a sprite has `rect(control).size == sprite size`, so hit targets and drawn sprites agree.

Siblings add pixel tests in the same style for their layers (time digits at 39,26; marquee at 111,24; sliders; vis).

### Risks

1. **Color management.** ImageIO may tag decoded BMPs and drawing into an sRGB context can shift values by a few units against Webamp's untagged canvas pixels. Mitigation: report exact and ±2 counts; if the ±2 count is near zero and exact is not, create the context in the sheet's own color space (or `kCGColorSpaceDeviceRGB`) and note the choice in the doc.
2. **Reference age and state.** Museum screenshots were taken when each skin was added, by whatever Webamp was deployed then; the state has been stable but small rendering fixes since can show as a few-pixel differences. The doc attributes rather than chases them; the per-skin note says which element differs.
3. **Region transparency.** References are transparent outside `region.txt`; ours are opaque until #0025. `ImageDiff` skips pixels transparent in the reference and reports the count, so the metric is meaningful before #0025.
4. **Sample skins in the guest.** They are gitignored and never exported by default; the comparison run depends on `--skins`. The doc records the run id so the numbers are reproducible from the same folder.
5. **Marquee determinism.** The reference marquee is at offset 0 because Webamp's screenshot mode disables stepping; `marqueeOffset` in the state gives #0021 the same control, and the preset pins it to 0.
6. **Frame rate in the app.** If `renderDynamic` at 60 Hz shows up in profiling once #0024 lands, the vis layer can be drawn into its own small image and composited; the layer interface does not change. Do not take performance numbers from the VM (paravirtualized GPU; `docs/testing-in-vm.md`).
7. **Retina display.** The image is 1× in skin pixels and shown at 1 point per pixel with `.interpolation(.none)`; `scale: 2` exists for a later double-size mode, not for Retina, which the system upscales crisply because of the interpolation setting. Verify by eye in the `--launch` smoke run's screen if needed, never on the host.
8. **Hit-target drift.** The only remaining way the app and the PNG can disagree is the overlay rects; test 12 ties them to the sprite sizes, and the rects come from the same `MainWindowLayout` table.
