# 0026 — Skin rendering cannot be compared against Webamp

| | |
|---|---|
| **Status** | open |
| **Module** | SkinKit |
| **Platform** | macOS |
| **First seen** | 2026-10-12 |

## Description

Add `skintool --png <out>` to render the main window offscreen to a PNG for side-by-side comparison with Webamp.

## Acceptance criteria

- Renders headless without AppKit windows.
- Comparison of the 10 sample skins is documented, including any differences.

## Plan

Rewritten 2026-10-14. The first plan (2026-10-13) predates #0020–#0025 and proposed one CoreGraphics `MainWindowRenderer` that the app would *display* as a single image with hit targets over it. That is not how M4 landed: the main window is composed in SwiftUI (`MainWindowView`, `TitleBarView`, `MainWindowStatusView`, `MarqueeView`, `SliderViews`, `VisualizerView`) from SkinKit's pure helpers (`Skin.image(for:)`/`image(for:frame:)`, `Skin.textImage`, `MainSliders`, `MarqueeLayout`, `TimeDigits`, `MainWindowStatus`, `MediaInfoText`, `VisRenderer`, `SkinRegion`), hosted in a borderless `SkinWindow`. This plan keeps those views and adds the headless path beside them, with one shared layout table and one shared base image so the two cannot drift. The CLI shape, the Webamp screenshot preset, the host-fetched reference images, `--compare`, the numbers-only comparison doc and the `--skins` VM option carry over from the first plan.

### Scope and decisions

**Goal.** `skintool --png <out> [skin|folder]` writes a 275×116 PNG of the main window with no AppKit window and no `NSApplication`, for comparison with the Winamp Skin Museum's Webamp screenshots, and the app shows the same pixels for the same state. The acceptance criteria are unchanged.

**Approach: (a), a CoreGraphics compositor in SkinKit that the app also uses for its static layers.** Three options were weighed:

- **(a) `MainWindowRenderer` in SkinKit (chosen).** A pure function `(Skin, MainWindowState, scale) -> CGImage` drawing into a `CGContext` with the helpers the views already use. The app takes its *base* image (background, title-bar strip, clutter bar, transport and eject sprites) from the same renderer and keeps the landed SwiftUI views for everything that moves or is clicked. Every position literal in the views moves into one `MainWindowLayout` table that the renderer reads too. Cost: a small edit per view (literals → table lookups, two sprites removed, one button style changed), no behaviour change. Headless by construction: SkinKit imports CoreGraphics, ImageIO and Foundation only (`grep -rl 'import AppKit\|import SwiftUI' Packages/SkinKit` stays empty), so `swift test` in the guest proves it. The same function is what #0034's thumbnail cache and #0043's Quick Look extensions were planned against (both cite `MainWindowRenderer.render(skin:state:scale:)`, `MainWindowState.idle` and `MainWindowLayout.size`; names and paths below keep those).
- **(b) Move the SwiftUI views into a package target and render with `ImageRenderer` from skintool (rejected).** Feasibility: `ImageRenderer` (macOS 13+) is `@MainActor`, rasterises through SwiftUI's own display list rather than a window, and does run in command-line processes in principle. But (1) nothing here has run it headless under `tart exec`, and its default `scale` and colour handling come from the main display, which the headless guest session may not expose; `ImageRenderer.cgImage` returning nil would only be discovered in the VM run. (2) It is not pixel-exact by contract: `.clipped()`, `.opacity`, `.padding` and gesture overlays go through SwiftUI's rasteriser, which may antialias or snap; a reference comparison needs byte-exact sprite blits. (3) The views are entangled with `PlayerModel` (AppKit, Plex, `@Environment`), `VisualizerModel` (`CADisplayLink`), `@Environment(\.skinWindow)` and `controlActiveState`; extracting them into a package means rewriting them around a value-type state, the largest possible change to the landed views. (4) `@MainActor` single-threaded rendering is a poor fit for #0034 (hundreds of thumbnails off the main thread) and unusable in #0043's `QLThumbnailProvider`, which hands the extension a `CGContext` to draw into. (5) It links SwiftUI into `skintool` and into SkinKit's tests.
- **(c) Screenshot the real window in the VM (`--launch` plus `screencapture` or an XCUITest attachment) (rejected as the primary path).** Not headless (fails the first acceptance criterion), depends on the guest's display scale and window placement, and does not serve #0034/#0043. It remains a useful one-off cross-check of the app against `--png` output once `docs/testing-in-vm.md`'s UI tests exist; not part of this issue.

**No-drift guarantee, concretely.** After this issue the app's main window pixels come from exactly two sources: (1) `MainWindowRenderer.renderBase` for the static layers, cached per skin, and (2) the SkinKit helpers the renderer's dynamic layers call themselves (`skin.image(for:)`, `skin.image(for:frame:)`, `skin.textImage`, `MainSliders.*`, `MarqueeLayout.*`, `MainWindowStatus.*`, `VisRenderer`), placed by `MainWindowLayout`. The renderer's pixel tests pin the table; a grep in the verification step shows no numeric `offset(x:`/`frame(width:` literals remain in the App's main-window views. The residual drift surface is the dynamic SwiftUI views' *composition* (order, clipping), which the comparison doc checks by eye once per run through the `--launch` smoke test's window.

**State is a value made of the landed types.** `MainWindowState` wraps `MainWindowStatus` (#0022) and the slider/toggle/marquee/vis inputs the views already take from `PlayerModel`. The app never builds a full `MainWindowState` (its views read the model directly); `skintool`, tests, #0034 and #0043 use the presets.

**The Webamp screenshot state, corrected from the Museum's shooter.** `packages/webamp-demo/js/screenshotInitialState.ts` plus `index.tsx` (`?screenshot=1`): status PLAYING, `timeElapsed: 3` of a 5 s track, track 1 "DJ Mike Llama - Llama Whipping Intro" (128 kbps, 44 kHz, 2 channels), `DISABLE_MARQUEE` (step 0), main window focused (`reducers/windows.ts` `focused: WINDOWS.MAIN`), EQ and playlist windows open (toggles selected), volume `round(200/255*100) = 78`, balance 0, time mode elapsed, **`TOGGLE_REPEAT` and `TOGGLE_SHUFFLE` dispatched, so shuffle and repeat are on** (the first plan had them off), visualizer style 0 (bars). `SET_DUMMY_VIZ_DATA` is still dispatched but nothing in the current `Vis.tsx` reads it (`getDummyVizData` has no consumer), so a *current* Webamp paints the bar background only; *old* Museum screenshots do show bars (risk 2), which is why `--compare` reports the vis rectangle separately. The marquee text is `getMediaText`: `1. DJ Mike Llama - Llama Whipping Intro (0:05)`. Title-bar buttons are not drawn (Webamp's `ClickedDiv`: nothing until first clicked; `skinSelectors.ts` `.selected #title-bar #minimize.clicked`), matching #0025's `TitleBarView`. The clutter bar (`MAIN_CLUTTER_BAR_BACKGROUND`, 8×43 from `titlebar.bmp` at `#clutter-bar` top 22 left 10) is always drawn by Webamp and is missing from the app today; the base layer adds it, so the app gets it for free (its five buttons stay inert; a later issue wires O/A/I/D/V).

**`MainWindowRenderer.swift`**

```swift
public enum MainWindowRenderer {
    /// The static layers the app draws once per skin: MAIN_WINDOW_BACKGROUND, the title-bar strip for
    /// `focused`, MAIN_CLUTTER_BAR_BACKGROUND, the six transport sprites (unpressed). No title-bar buttons
    /// (Webamp draws none until clicked). Nearest-neighbour, top-left origin, device RGB, premultiplied RGBA8.
    public static func renderBase(skin: Skin, focused: Bool, scale: Int = 1) -> CGImage
    /// The dynamic layers in Webamp DOM order over `base`: work and play indicators, time (minus/no-minus
    /// as the app draws it, four digits), visualizer, marquee, kbps, kHz, mono/stereo, volume, balance,
    /// EQ/playlist toggles, position track and thumb, shuffle/repeat.
    public static func renderDynamic(over base: CGImage, skin: Skin, state: MainWindowState, scale: Int = 1) -> CGImage
    /// renderBase + renderDynamic; `clipToRegion` clips to `skin.region.normal` (non-antialiased, like
    /// SkinRegion.maskImage) so pixels outside the shape are transparent, as in Webamp's screenshots.
    public static func render(skin: Skin, state: MainWindowState, scale: Int = 1, clipToRegion: Bool = false) -> CGImage
    /// The primitive the others wrap: draws the window with its top-left at `origin` (device pixels) into a
    /// caller-owned context whose CTM is y-down. For #0043's QLThumbnailReply drawing block and for stacking
    /// EQ/playlist renders later.
    public static func draw(into context: CGContext, at origin: CGPoint, skin: Skin, state: MainWindowState, scale: Int, clipToRegion: Bool)
}
```

- `scale < 1` is clamped to 1. A missing sprite is skipped (background stays); a missing `MAIN` sheet fills the window with `CGColor(gray: 0.1, alpha: 1)` in device grey so a partial skin still yields a picture (#0043 relies on this). Never traps; `Skin.image(for:)` already carries #0020's fallbacks.
- Internal `SpriteDrawer`: wraps the `CGContext` (device RGB, `premultipliedLast`, `interpolationQuality = .none`, antialiasing off, CTM flipped once and scaled by `scale`) with `draw(_ name: String, at: CGPoint)`, `draw(_ image: CGImage, at: CGPoint)`, `draw(_ image: CGImage, in: CGRect)` (for the 3-px work indicator crop and the marquee window), `clip(to: CGRect)`. Device RGB, not sRGB: `TextRenderer`, `VisRenderer`, `SkinRegion.maskImage` and `TestBitmaps.pixel` all use `CGColorSpaceCreateDeviceRGB()`, and #0021's gotcha records that sRGB colours were colour-matched in the VM and shifted values. A PNG written from a device-RGB context carries no colour profile, which is what byte comparison against Webamp's untagged canvas wants.
- Layer drawing uses the helpers verbatim: time via `status.digits`/`skin.digitSpriteName`/`skin.minusFrame`/`minusName`/`noMinusName`; kbps/kHz via `skin.textImage(status.kbps)`; marquee via `skin.textImage(MarqueeLayout.loopText(text))` offset by `-MarqueeLayout.stepOffset(text:step:pixels:)` clipped to `MainWindowLayout.marquee`; volume/balance via `skin.image(for:frame:)` with `MainSliders.volumeFrame`/`balanceFrame` and thumbs at `Slider.thumbX(for:)` (balance fraction via `MainSliders.fraction(forBalance:)`); position via `MainSliders.position`; toggles via `MainSliders.spriteName(_:selected:pressed: false)`; vis via `VisRenderer(colors: skin.visColors)` with `pushDown = scale >= 2 ? 0 : 2` (the rule in `VisualizerModel.setScale`), `drawBars`/`drawOscilloscope`, `makeImage()` drawn at `MainWindowLayout.visualizer.origin`. If a helper lacks a public entry the layer needs, add it to the helper rather than re-implementing in the layer.

**`PNGWriter.swift`** — `PNGWriter.write(_ image: CGImage, to url: URL) throws`, `PNGWriter.data(_ image: CGImage) -> Data?` (`CGImageDestinationCreateWithData`/`WithURL`, `UTType.png.identifier as CFString`, `import UniformTypeIdentifiers`), and `PNGWriter.read(_ url: URL) -> CGImage?` via `CGImageSourceCreateWithURL`. Named as #0043's plan expects.

**`ImageDiff.swift`**

```swift
public enum ImageDiff {
    public struct Result: Equatable, Sendable {
        public var compared: Int, differing: Int, withinTolerance: Int   // tolerance applies per channel
        public var skippedTransparent: Int                                // alpha 0 in either image
        public var differingOutsideIgnored: Int, withinToleranceOutsideIgnored: Int
    }
    /// Both images are drawn into device-RGB RGBA8 buffers of `ours`' size; a taller `reference` (the
    /// Museum's 275x348 stack) is cropped to its top rows. `ignoring` rects (skin pixels x scale) are still
    /// counted in `differing` but excluded from the `OutsideIgnored` pair.
    public static func compare(ours: CGImage, reference: CGImage, tolerance: UInt8 = 2, ignoring: [CGRect] = []) -> Result
    /// `ours` with every differing pixel painted magenta.
    public static func diffImage(ours: CGImage, reference: CGImage) -> CGImage
}
```

Minimal, behaviour-preserving edits; no view is restructured.

### 3. `skintool --png` (`Packages/SkinKit/Sources/skintool/main.swift`, `SkinKit/Tooling/SkintoolOptions.swift`)

Hand-parsed as today; parsing moves into `SkintoolOptions.parse(_ arguments: [String]) -> Result<SkintoolOptions, UsageError>` in SkinKit so it is unit-tested. `-v`/`--verbose` and the report lines are unchanged.

```
skintool [-v] <skin.wsz | folder>
skintool --png <out> [--state webamp|idle] [--scale N] [--compare <refdir>] [--no-region] [-v] <skin.wsz | folder>
```

- One skin: `<out>` is the PNG path. A folder: `<out>` is a directory (created), each skin writes `<out>/<basename>.png`, and the `ok`/`partial`/`failed` report lines still print.
- `--state` defaults to `webamp` (`MainWindowState.webampScreenshot`); `idle` is `.idle`. `--scale` defaults to 1. The region clip is on unless `--no-region`.
- `--compare <refdir>` reads `<refdir>/<basename>.png`, runs `ImageDiff.compare(tolerance: 2, ignoring: [MainWindowLayout.visualizer])`, writes `<out>/<basename>.diff.png`, and prints one line: `diff     <name>: exact 1234/31900 px differ, ±2 980; excluding vis 900 / 700; 3100 skipped transparent`. A missing reference prints `noref    <name>` and is not an error.
- Each render prints `png      <name> -> <path>`. Exit status: unchanged rule (0 only if every skin is `ok`) and additionally 1 if any render or PNG write failed; comparison numbers never affect the exit status (they are documented, not gated). Usage errors 64, missing input 66.

### 4. Reference images from Webamp (host only, one user step)

The Museum serves Webamp's own renders at `https://r2.webampskins.org/screenshots/{md5}.png` (md5 of the `.wsz` bytes; `docs/winamp-skin-museum-access.md`), taken by `packages/skin-database/shooter.js` (Puppeteer, viewport 275×348, `https://webamp.org/?screenshot=1`, body background none, main + EQ + playlist stacked at y 0/116/232).

New host script `scripts/fetch-webamp-references.sh <skins-dir> [out-dir]` (default `build/webamp-reference`, under the gitignored `build/`): for each `*.wsz` in `<skins-dir>` (read only; the user's `untitled folder/` is never written to) it runs `md5 -q`, `curl -fsSL --retry 2 -o "<out-dir>/<basename>.png" "https://r2.webampskins.org/screenshots/<md5>.png"`, and appends `name<TAB>md5<TAB>fetched|missing` to `<out-dir>/manifest.tsv`, printing a summary. It downloads public screenshots only, sends nothing, and is never called by `run-tests-vm.sh`. A `missing` (404: a re-zipped or edited file has a different md5) is recorded in the comparison doc as "no reference"; the manual fallback (open `webamp.org/?screenshot=1`, load the skin through `#webamp-file-input`, capture `#main-window` in the browser's DevTools) is described in the doc as optional and was not required for a number to be reported.

The user runs it once on the host before the comparison run: `scripts/fetch-webamp-references.sh "untitled folder"`.

### Risks

1. **Colour management.** ImageIO may tag decoded BMPs; drawing into a device-RGB context avoids a conversion on our side, but the reference PNGs are what Chrome wrote. The ±2 count separates "a few units everywhere" from real layout differences; if exact is low and ±2 is near zero the doc attributes it to decoding, not drawing.
2. **Reference age.** Museum screenshots date from when each skin was added; older Webamp builds painted the dummy vis bars and may differ in small fixes since. The vis rect is excluded in the second pair of numbers and other differences are attributed per skin, not chased.
3. **md5 mismatch.** A sample skin that was re-zipped has no Museum screenshot; it is reported as `noref` and the doc says so. The manual capture is optional.
4. **Base image staleness.** The base is rendered in `loadSkin`; a skin change always goes through it, and focus is a two-image lookup, so there is no cache key to get wrong. If a future change makes the clutter bar or transport stateful, those sprites move from the base to the dynamic layers and the view draws them again; the table does not change.
5. **Hit areas after the button-style change.** `Color.clear` with `.contentShape(Rectangle())` keeps the transport buttons clickable; the `--launch` smoke run cannot click, so the user checks play/pause by hand on the host afterwards (as with #0023's sliders).
6. **Performance in the app.** Unchanged: the dynamic views are the ones that existed; the base is one image drawn once per frame instead of seven sprites. Do not take numbers from the VM (paravirtualized GPU).
7. **Retina / 2×.** The base is 1× skin pixels under the view's `scaleEffect`, as every sprite is today; `--scale` in skintool is for a future double-size mode and for #0043, not for Retina.
8. **Region edges.** Our clip uses the same non-antialiased polygon fill as #0025's mask; Webamp's SVG clip-path is antialiased in Chrome, so a thin band of edge pixels can differ on shaped skins. Counted and attributed in the doc; not a drawing bug.
