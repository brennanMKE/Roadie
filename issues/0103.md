# 0103 — A playlist whose nested playlists fan out can expand to millions of entries and hang import

| | |
|---|---|
| **Status** | open |
| **Module** | AudioCore |
| **Platform** | macOS |
| **First seen** | 2026-10-19 |

## Description

Found in review of #0100. `LocalTrackLoader.expandPlaylists` now expands nested playlists in place, stopping cycles (ancestor chain only) and nesting deeper than 8 levels. A playlist that is not a cycle but repeats nested playlists is still unbounded in total work: if `p1.m3u` lists `p2.m3u` ten times, `p2.m3u` lists `p3.m3u` ten times, and so on for 8 levels, the loader reads about 10^7 playlist files and appends up to 10^8 URLs before any track loads, so import hangs and memory grows. Diamonds are meant to expand more than once (Winamp does), so the cycle check can't catch this.

Expected:

- A cap on total work during one expansion, for example at most a fixed number of nested playlist reads (say 256) and/or a fixed number of expanded entries (say 100,000). Past the cap, remaining nested playlists or entries are reported as skipped with a clear reason (for example "too many playlist entries") instead of being expanded.
- Ordinary nesting (#0100's tests, including a small diamond) is unaffected.
- Tests: a fan-out playlist tree written to a temp folder stops at the cap, returns quickly, and reports the skip; a small diamond still expands twice.
