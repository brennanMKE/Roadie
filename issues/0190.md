## Description

The playlist editor's LIST › Load follows the queue the editor is showing (#0146):

- **The local queue** opens a playlist **file** (M3U/PLS).
- **A Music Assistant queue** picks one of the server's playlists with `PlaylistPickerSheet`.

So when This Mac is playing its local queue and the Library is browsing Music Assistant, there's no way to get a server playlist like "Party" into the editor from the skinned windows. LIST › Load only shows a file panel, and the menu bar's File › Load Playlist… is file-only too. The menu bar has "Save Queue as Playlist…" but nothing to load a Library playlist.

The ⌘J panel's "The playlist is empty" also leaves a user stuck. That's what the user saw first: an empty Jump to File list.

This issue:

- makes LIST › Load offer a Library playlist whenever the Library's source has playlists;
- adds a matching menu-bar item;
- makes Jump to File's empty state point at the Library.

## Steps to reproduce

1. Set a music folder and play something from File › Open, so the editor shows the local queue.
2. Connect Music Assistant and switch the Library to it. The Playlists section shows "Party".
3. In the skinned playlist editor, click LIST › Load. A file panel opens; there's no way to pick "Party".
4. Empty the playlist and press ⌘J. The panel only says "The playlist is empty".

## Expected behavior

- LIST › Load offers "Library Playlist…" (the picker) and "Playlist File…". Choosing "Party" plays it, and the editor shows it.
- The Playback menu has "Load Playlist from Library…".
- ⌘J on an empty playlist says how to add music.

## Actual behavior

LIST › Load is file-only on the local queue, and nothing tells the user about the Library.

## Resolution notes

## Fix

Implemented the plan as written: `QueueSaveTarget.loadChoices` decides the choices; `loadList()` posts the refusal, goes straight to the file panel or picker, or pops up "Library Playlist… / Playlist File…"; `PlayerModel.pickLibraryPlaylist()` opens the editor if needed and shows the picker; `canLoadLibraryPlaylist` gates the new Playback menu item. One divergence: the Jump to File empty label wraps to two lines up front rather than after checking truncation.

## Root cause

- `PlayerModel.loadList()` (`App/PlayerModel+PlaylistFiles.swift:12–23`) switches on `QueueSaveTarget.load(...)`. That's `QueueSaveTarget.choose` (`Packages/PlayerKit/Sources/LibraryBrowser/QueueSaveTarget.swift:15–31`), which looks only at the **output's** backend and the This Mac feed. On the local feed it's always `.file`, even when the Library's selected source (`PlayerModel.backend`, `sources.backend`, `App/PlayerModel.swift:39`) has playlists.
- `PlaylistPickerSheet` already lists the Library's playlists (`library.playlists`, so the selected source). `PlayerModel.loadPlaylist` already plays the chosen one through `playFromLibrary`, which moves This Mac onto the Music Assistant feed. The picker is just never offered on the local queue.
- `App/PlaybackCommands.swift:53` has only "Save Queue as Playlist…". `App/RoadieApp.swift:46`'s File › Load Playlist… calls `loadPlaylistFile()`.
- `JumpToFilePanel.updateEmptyState` (`App/JumpToFile/JumpToFilePanel.swift:188–194`) shows only "The playlist is empty".

## Plan

### 1. Decide the choices in the package (`QueueSaveTarget.swift`)

Add a pure function next to `load`:

```swift
/// What LIST › Load offers (#0190). A Music Assistant queue: its playlists. The local queue: a playlist file,
/// plus the Library's playlists when the Library's source has them (loading one moves This Mac onto that source).
public enum LoadChoice: Hashable, Sendable { case libraryPlaylist, file }

public static func loadChoices(
    output: OutputDevice.ID, feed: ThisMacFeed, capabilities: BackendCapabilities, libraryHasPlaylists: Bool
) -> [LoadChoice] {
    switch load(output: output, feed: feed, capabilities: capabilities) {
    case .remote: [.libraryPlaylist]
    case .file: libraryHasPlaylists ? [.libraryPlaylist, .file] : [.file]
    case .refused: []
    }
}
```

`libraryHasPlaylists` comes from the App: `backend.capabilities.contains(.playlists)` for the Library's selected source, with `PlayerModel.backend`. Check the capability's exact name in `MusicBackendKit`; `MusicBackendError.unsupported(.playlists)` uses it.

### 2. LIST › Load (`App/PlayerModel+PlaylistFiles.swift`)

Rewrite `loadList()`:

- `[]`: the current refusal notice.
- `[.file]`: `loadPlaylistFile()`.
- `[.libraryPlaylist]`: `pickLibraryPlaylist()`.
- Two choices: `PlaylistContextMenus.popUp([("Library Playlist…", { pickLibraryPlaylist() }), ("Playlist File…", { loadPlaylistFile() })])`. That's the same native pop-up at the pointer that SORT and MISC use.

Add `func pickLibraryPlaylist()`:

- call `library.loadPlaylistsIfNeeded()`;
- open the playlist editor if it's closed (`setPlaylistWindowOpen(true)`), because the picker sheet is attached to `PlaylistView` (`App/Playlist/PlaylistWindowView.swift:60–65`);
- set `isPickingPlaylist = true`.

`loadPlaylist(_:)` stays as it is.

**Gate:** on a speaker with the folder library, `playFromLibrary` already refuses. On This Mac with Music Assistant, `playFromLibrary` switches the feed. Nothing new is needed.

### 3. Menu bar (`App/PlaybackCommands.swift`)

After "Save Queue as Playlist…", add `Button("Load Playlist from Library…") { model.pickLibraryPlaylist() }`, disabled unless the Library's source has playlists. Expose that as `var canLoadLibraryPlaylist: Bool` on `PlayerModel`. Don't give it a keyboard shortcut. `MainMenuTests.shortcutsMatchMenuBar` only checks shortcuts, but don't add one to the skinned pop-up either.

### 4. Jump to File's empty state (`App/JumpToFile/JumpToFilePanel.swift:191`)

Change the text to "The playlist is empty. Add music from the Library (⌘L) or File › Open." Check the label's width: it's one line. If it truncates, set `emptyLabel.maximumNumberOfLines = 2` and `lineBreakMode = .byWordWrapping`, or shorten it to "Empty: add music from the Library (⌘L)".
