## Description

With [#0243](0243.md) and [#0257](0257.md) the window can draw `.milk` presets beside the classics, but a Release build has none to draw: Roadie bundles no presets, and Settings › Visualization's presets folder row is Debug-only (#0241's `showsPresetsFolder`). MilkDropMetalKit 1.0.0 doesn't vend presets (its `MilkMetal` target has no resources and no list API); its `Presets/` folder holds 42 MIT presets written for the package, one per renderer feature, with `spike-tunnel.milk` as the showcase and `gallery.json` giving each a title. This is the piece that puts MilkDrop in front of users for 0.0.5.

Split from #0243 on 2026-10-30 (see its `## Notes`). Design: [docs/design/visualization.md](../docs/design/visualization.md) §5.1, §5.3, §8.3, §11 question 5 (default: the package's own MIT presets).

## Root cause

MilkDropMetalKit 1.0.0 has no presets for Roadie to use (its `MilkMetal` target has no resources and no API that lists them), and Roadie bundled none of its own. Settings › Visualization's presets folder row was hard-coded to Debug (`showsPresetsFolder`). So a Release build had no `.milk` preset to draw, and no way to add one.

## Fix

- `scripts/update-milkdrop-presets.sh [TAG] [REPO]` (host only) reads the package with `git archive` and `rev-parse` only. It copies `Presets/*.milk`, `gallery.json` and `README.md` into `App/Visualization/Presets/`, and writes a `VERSION` file with the tag and commit. I ran it once for `1.0.0` (d9c4fb4): 42 presets.
- `project.yml`: `App` excludes the folder, which ships as one folder reference at `Contents/Resources/Presets`. That is the name XcodeGen gives, not the `MilkDropPresets` the plan expected. The code reads it through `RoadieConfiguration.bundledPresetsFolderName` and `appPresetsFolder`.
- `PresetCatalog.bundled(in:)` scans the folder as `.bundled` and takes each name from `gallery.json` (`file` → `title`). A preset the gallery doesn't title, or a missing or unreadable gallery, keeps its file name.
- `RoadieConfiguration.bundledPresetsFolder` is set in `.standard` and in UI-test mode, and stays nil in unit tests, so the test host's bundle is never picked up by accident. `VisualizationModel` lists `classics + bundledPresets + userPresets` in `prepareRenderer` and `applyCatalogue`.
- Fresh install: with no `visualization.lastPreset`, the window starts on `bundled:spike-tunnel.milk` (`freshInstallPreset`) when the renderer can load it, else on the first classic.
- `showsPresetsFolder` asks the renderer whether it can load a `.milk` preset. Before the first open it uses `canDrawMilkBeforeOpen`, which checks for a Metal device. Debug's `-RoadieVisRenderer classic` still shows the row, as before.
- **Deviation from the plan:** the bundled presets are scanned once, on the main actor, on first use (the first open, or a folder rescan), not off the main actor in `init`. It's 42 directory entries and a small JSON file, and it keeps the fresh-install start simple, with no race against an async load.
- UI tests: `testPresetsFolderAddsItsPresets` now passes `-visualization.lastPreset classic:spectrum`, since a fresh install would otherwise start on Spike Tunnel. `testArrowCrossesFromClassicToMilkDrop` now expects "Bass, Mid, Treble" after → from the last classic: it's the first MilkDrop preset by name, ahead of the folder's Seeded Presets.
- Docs: §5.12 row, `visualization.md` (§5.1 item 2, §5.3, §10, §11 question 5 answered), the handoff's upgrade note, `website/help.html`, CHANGELOG and NOTICE.

## Plan

### Bundle the package's presets

- `scripts/update-milkdrop-presets.sh [TAG] [REPO]` (host only, read-only on the package; defaults `1.0.0` and `../MilkDropMetalKit`): `git -C "$REPO" archive "$TAG" Presets | tar -x` into a temp dir, then replace `App/Visualization/Presets/` with its `*.milk`, `gallery.json` and `README.md`, and write `App/Visualization/Presets/VERSION` with the tag and commit (`git -C "$REPO" rev-parse "$TAG^{commit}"`). Refuses when `TAG` doesn't exist; never checks out, fetches or builds in `REPO`. Run it once for `1.0.0` (→ `d9c4fb4`) and commit the 42 presets (64 KB).
- All 42, as design §11 question 5 defaults (see `## Notes` for the user's choice). Licence: the package's MIT (`Presets/README.md`: "written for this package and released under its MIT licence"); `NOTICE` (MilkDropMetalKit's entry from #0243) gains one line: "Roadie bundles the presets from MilkDropMetalKit 1.0.0's Presets/ folder, under the same MIT licence."
- `project.yml`: the folder ships as one folder reference in the app's resources (`Contents/Resources/MilkDropPresets/`), not as 42 loose files in the group: in the `Roadie` target, exclude `Visualization/Presets` from `sources: [App]` and add `- path: App/Visualization/Presets`, `type: folder`, `buildPhase: resources` (check the result with `xcodegen generate` and the Info.plist/bundle check; name the destination whatever XcodeGen gives, and read it through one constant).

### Catalogue

- `PresetCatalog.bundled(in folder: URL) -> [VisualizationPreset]` (VisualizationKit): `scan(folder:source: .bundled)`, then names from `gallery.json` when it's there (`file` → `title`, e.g. "Spike Tunnel", "Mode 0: Circle"), else the file name. Ids stay `bundled:<file name>`. A missing folder or unreadable JSON gives the scan with file names. Unit tested over a temp folder.
- `VisualizationModel`: `bundledPresets` loaded once (off the main actor in `init`, like `reloadCatalogue`) from `Bundle.main`'s preset folder; `prepareRenderer` and `applyCatalogue` list `classics + bundledPresets + userPresets`. Catalogue order stays §5.1's: classics, then every `.milk` by name. Tests inject the folder (an `init` parameter or a `bundledPresetsFolder` property set before first open), never `Bundle.main` of the test runner by accident.
- Default start preset: when `visualization.lastPreset` is unset (a fresh install), start on `bundled:spike-tunnel.milk` if the renderer can load it, else the first classic (design §5.3 changes; a remembered preset that's gone still falls back to the first classic).

### Release

## Notes

- For the user: the 42 presets are the package's feature demos (one renderer feature each, e.g. "Invert", "Gamma"), not a curated art pack, and a few flash (Invert, Beat Flash). The plan ships all 42 (design §11 question 5's default). Ship a subset instead (say, the Showcase, Custom Waves, Motion, Per-Vertex and MilkDrop 2 Shaders groups), or all of them? **Settled by the user:** ship all 42, and keep MilkDropMetalKit at `from: 1.0.0`.
- Follow-ups from #0257's review (not in scope here):
  1. With no Metal device, `.milk` presets drop out of the list with only a `notice` log.
  2. The crossfade advances only in `draw(at:)`, so a paused render loop leaves a half-faded frame.
- Review (2026-10-30): the UI test sets `lastPreset` explicitly, so the fresh-install start is proven by the unit tests (`testAFreshInstallStartsOnSpikeTunnel`), not end to end. `showsPresetsFolder` calls `MTLCreateSystemDefaultDevice()` on each read before the first open; cheap enough, but could be cached.
