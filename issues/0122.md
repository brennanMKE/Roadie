# 0122 — A lost guest-agent connection during one VM step is reported as a test failure

| | |
|---|---|
| **Status** | open |
| **Module** | Tooling |
| **Platform** | macOS |
| **First seen** | 2026-10-20 |

## Description

Run `20261020-174818-79928` (#0119, third pass) reported `VERIFY FAIL (exit 1)` with `FAIL  app-plist (exit 1)` and nothing else, though every test passed. `run.out` shows the step never ran: `Failed to connect to the VM using its control socket: The operation couldn't be completed. (GRPC.GRPCConnectionPoolError error 1.), is the Tart Guest Agent running?`. The next steps in the same guest passed.

Two gaps:
1. `run-tests-vm.sh` counts a `tart exec` transport error on a single step as that step failing (exit 1), not as infrastructure (exit 3), so `verify.sh`'s INFRA retry doesn't kick in.
2. `verify.sh`'s failure report shows nothing for a step with no log of its own (app-plist writes none), so the reader can't tell an infra blip from a real Info.plist problem.

## Expected behavior

- A `tart exec` control-socket/GRPC error on a step retries that step once; if it still can't connect, the run is `INFRA` (exit 3).
- Every failing step's report includes its last lines of output (from `run.out` when the step has no log file), so the cause is visible without reading logs.
