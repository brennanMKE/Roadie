# 0196 — Music Assistant queue fixtures are synthetic and nothing pins the server's quirks

| | |
|---|---|
| **Status** | open |
| **Module** | MusicAssistantKit / Tooling |
| **Platform** | macOS |
| **First seen** | 2026-10-24 |

## Description

#0187 happened because `player-queue-items.json` was recorded against an empty queue, so `BackendQueueTests.itemJSON` invented rows with `"index": n`, and the real server's `"index": 0` on every row was never seen by a test. Two things are missing: a recording of a loaded queue, and a rule (with a test) that recorded quirks are kept and noticed when they change. This issue extends the read-only recorder with `--record-queue`, adds the quirk registry and its test, and replaces the synthetic rows in `BackendQueueTests` with the recording once it exists. Design: [docs/design/test-automation.md](../docs/design/test-automation.md) §2.3.

The recording step needs the user: `scripts/record-ma-fixtures.py --record-queue` runs on the host against their server with a queue loaded and playing. The code below doesn't block on it; `MAFixture.isRecorded` stays false for the new names until then and the tests skip or use the synthetic fallback.

## Plan

### 1. `--record-queue` (`scripts/record-ma-fixtures.py`)

- New entry point `record_queue(args)` next to `record()`. Read-only: it uses `Session(... allowed=ALLOWED)` and sends `players/all`, `player_queues/all`, `player_queues/get_active_queue`, `player_queues/get` and `player_queues/items` (offset 0 and one more page at `limit` 50) for the queue that has `state == "playing"` or, with `--queue-id`, the named one. It refuses to run (`die`) if no queue has items, saying "load and play a queue first".
- Writes, through `write_fixtures` (scrub, truncate per `TRUNCATE`, gate): `players-all-playing`, `player-queue-get-loaded`, `player-queue-items-loaded` (keep **all** rows up to 50, not the 5 of `TRUNCATE`: set `TRUNCATE["player-queue-items-loaded"] = 50` and record the real count in `original_item_counts`), `player-queue-items-page2` (the second page), and `events-queue` (`--events-seconds`, default 30, while the queue plays: `queue_updated`, `queue_items_updated`, `player_updated` frames).
- `--check` gains the new names in `shape_problems`. `scripts/tests/test_record_writes_cleanup.py`-style test `scripts/tests/test_record_queue.py`: with a `FakeSession`, `record_queue` sends only allow-listed commands, picks the playing queue, writes the expected fixture names, and dies when every queue is empty.

### 2. Quirk registry and test

- `docs/ma-protocol-notes.md`: a `## Quirks` section. First entries: (a) `player_queues/items` rows carry `"index": 0` whatever their position (MA 2.10.6, seen 2026-10-24, #0187); position is the paging offset plus the place in the page; (b) `playlist_tracks` streams chunk frames then an empty `partial: false` (from #0060's notes); (c) `players/get` of an unknown id is `result: null`. Each entry names the fixture that shows it.
- `Packages/PlayerKit/Tests/MusicAssistantKitTests/MAFixtureTests.swift`: `recordedQuirksHold`: for each quirk, assert it against its fixture (skip, with `XCTSkip`/`#expect` guard, the ones whose fixture `isRecorded == false`). For (a): every item in `player-queue-items-loaded` has `index == 0` while `current_index` in `player-queue-get-loaded` is > 0 (or the test states the recorded value). The doc comment says what to do when it fails: a re-record changed the server's behaviour; update the quirk entry and reconsider `MAQueueWatch.item(_:position:)`, don't edit the fixture.
- Add `fixturesAreVerbatimRecordings`: every call fixture has `command`, `args`, `frames`, and no frame carries a key named `synthetic`; and the file list equals `MAFixture.recorded` (no stray files, nothing missing).

### 3. Use the recording (`BackendQueueTests`, `FixtureScript`)

- `MAFixture`: add `playersAllPlaying`, `playerQueueGetLoaded`, `playerQueueItemsPage2`, `eventsQueue`. `playerQueueItemsLoaded` exists.
- `FixtureScript.recorded(token:)`: route `player_queues/items` by `offset` to `player-queue-items-loaded` / `-page2` when recorded, else to the existing empty fixture.
- `BackendQueueTests`: a new `queueRowsFromTheRecordedLoadedQueueAreNumberedByPosition` that runs the rig over the recorded fixture and asserts `items.map(\.index) == Array(0..<count)`, `items[current].isCurrent`, and that titles match the fixture's `media_item.name`s. Skipped while unrecorded. Keep `queueRowsUsePositionWhenTheServerSendsIndexZero` (synthetic, explicit) as the always-on guard; rename `itemJSON`'s default to `serverIndex: 0` so the synthetic rig matches the real server by default.

### 4. Docs

`docs/ma-protocol-notes.md`: the `--record-queue` recipe under the existing recording section; the Quirks section. `scripts/record-ma-fixtures.py` header: the new line.

## Tests

- `scripts/tests/test_record_queue.py`: `test_records_the_playing_queue`, `test_sends_only_reads`, `test_dies_when_no_queue_has_items` (run by the `release-tools` step pattern: add `-p 'test_record_queue.py'` to a new `recorder-tests` step or widen the existing step's pattern to `test_*.py`).

## By hand (the user, on the host)

1. Load a playlist on a speaker in Music Assistant and play it. Run `/usr/bin/python3 -I scripts/record-ma-fixtures.py --record-queue --events-seconds 30`. It prints `secret gate: passed (N files)`. `git status` shows the five new fixtures and nothing else.
2. `/usr/bin/python3 -I scripts/record-ma-fixtures.py --check` passes.
3. `grep -c '"index": 0' Packages/PlayerKit/Sources/MusicAssistantKitStub/Fixtures/player-queue-items-loaded.json` equals the number of rows: the quirk is in the recording. If it isn't (a newer server), `recordedQuirksHold` fails on the next run and the quirk entry is updated.
4. Commit the fixtures as `#0196 Record a loaded Music Assistant queue`.
