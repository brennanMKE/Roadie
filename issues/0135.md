## Resolution notes

> 🟢 Resolved 2026-10-21 — Music Assistant playlists can now be created, renamed and deleted from the Library window, with optimistic list edits that roll back when the server refuses.

Review (Opus, phase 3): read `git diff b6d135c 756193c` against design §1.2, §1.3, §2.2, §2.7, §2.8 and W2. The requests use the documented arg names: `create_playlist` sends `name` only (the server picks builtin), rename fetches the playlist with `music/playlists/get` and sends the whole raw object with the new `name` and `overwrite: true`, and delete uses `music/library/remove_item` with the library id. Built-in playlists are refused before anything is sent, in both the backend and `PlaylistsModel`. A server error whose details mention "scope" or "permission" maps to `MusicBackendError.forbidden`, which disables Rename/Delete for that playlist with the server's text as help. Error 12 still goes through `noteUnsupported`. `PlaylistsModel` inserts and selects a created playlist, renames and deletes at once, and restores the row (and the selection) on failure; write failures are kept out of the Library fallback. `selectedPlaylist` now compares ids, so a rename keeps the loaded tracks. The UI has the toolbar `[+]` (⌘N, `library.playlists.new`), the name sheet, Rename…/Delete… in the row context menu, the delete confirmation with the design's wording, and Delete/⌘⌫ on the selected playlist. Backends without `.playlistEditing` throw `.unsupported` from the protocol defaults and show none of it.

Minor, not blocking: rename is through the name sheet only; the inline row edit and the detail header's click-to-edit (§2.2, §2.3) aren't there. The row menu lacks Play/Shuffle/Add to Queue, "New Playlist…" sits on the row menu instead of on empty space, and there is no File › New Playlist… item (⌘N works through the toolbar button). The backend tests use synthetic `get`/`create` answers until #0133's write capture.

## Root cause

The `MusicBackend` API had no playlist writes: nothing sent `create_playlist`, `update` or `library/remove_item`, and the Playlists list was read-only.

## Fix

- `MusicBackendKit`: `.playlistEditing` capability, `createPlaylist/renamePlaylist/deletePlaylist` (defaults throw `.unsupported`), `MusicBackendError.forbidden`.
- `MusicAssistantKit`: `MARequest+Playlists.swift` builders and `MusicAssistantBackend+Playlists.swift` (fetch-then-update rename, `remove_item` delete, built-in refusal, scope → `.forbidden` in `write(_:)`).
- `LibraryBrowser`: `PlaylistsModel` (name sheet and delete-confirmation state, optimistic create/rename/delete with rollback, per-playlist refusals); `PagedList.insert/replace/remove` for local edits; `LibraryBrowserModel.playlistsModel`.
- App: `PlaylistNameSheet` + `PlaylistEditingModifier` + `PlaylistMessageBar`, the toolbar button, and the row context menu and delete shortcuts in `PlaylistListView`.
- `StubMusicBackend` implements the writes.
