## Description

A Music Assistant server reached over Tailscale by its MagicDNS name can't be added. In Settings › Music Assistant, `http://homeassistant.sawfish-byzantine.ts.net:8095` is rejected with "Use https for this address; plain http works only on the local network." Switching to `https://homeassistant.sawfish-byzantine.ts.net:8095` passes the address check, but Test Connection fails with "Can't reach the Music Assistant server." because Music Assistant doesn't serve TLS on 8095.

The server is reachable: MA 2.10.6, Home Assistant add-on, Tailscale IP `100.96.2.0`. The `100.x` address works today because ATS's `NSAllowsLocalNetworking` covers IP literals. The MagicDNS name doesn't, because #0063 kept ATS at the local-network exemption with no exception domains.

**User decision (2026-10-23):** allow plain http for Tailscale MagicDNS names `*.ts.net`. Tailscale encrypts the traffic with WireGuard, so http on the tailnet isn't sent in the clear.

## Resolution notes

> 🟢 Resolved 2026-10-23 — Settings accepts plain http/ws to Tailscale MagicDNS `*.ts.net` names (bare ones default to http:8095), ATS has a single `ts.net` exception domain allowing insecure HTTP loads, and an unreachable https address on port 8095 explains that Music Assistant serves plain http there.

Review (Opus, medium): the matcher rejects `ts.net`, `evil-ts.net`, `boxts.net`, `ts.net.example.com`, empty labels and the trailing-dot form, and it is case-insensitive. The ATS keys are correct (`NSIncludesSubdomains`, `NSExceptionAllowsInsecureHTTPLoads`, `NSAllowsLocalNetworking` kept, no `NSAllowsArbitraryLoads*`) and cover `ws://` WebSocket tasks, which go through URLSession like http. https keeps default certificate validation, since no code handles a server-trust challenge. `check-info-plist.sh` now pins the exception dictionary exactly, and the built app's plist printed that exact JSON. The port-8095 hint is a fixed string with no host or token. Reviewer run: `20261023-163816-22515` PASS, fast tier, 1583 tests, audio silent, all 11 expected tests passed. Minor gap, not blocking: no test for a trailing-dot `.ts.net.` host, but the code rejects it (falls to `.httpsRequired`).

## Root cause

ATS allowed only `NSAllowsLocalNetworking`, which covers IP literals, `.local` and single-label names but not Tailscale MagicDNS `*.ts.net` names. `MusicAssistantAddressInput.parse` mirrored that rule, so it rejected `http://<name>.ts.net` with `.httpsRequired`. Music Assistant serves only plain http on 8095, so the https form failed with a generic "Can't reach" message.

## Fix

- `MusicAssistantAddressInput.isTailscaleMagicDNS` accepts `<label>(.<label>)*.ts.net`. It rejects `ts.net` itself, look-alikes and the trailing-dot form. `parse` uses `isLocalHost || isTailscaleMagicDNS` for the no-scheme default (http, port 8095) and for the `.httpsRequired` check. `isLocalHost` is unchanged.
- `MusicAssistantAddressSecurity` has a new `.tailnet` case.
- ATS: `NSExceptionDomains` has one entry, `ts.net` (`NSIncludesSubdomains`, `NSExceptionAllowsInsecureHTTPLoads`), in `project.yml` and the regenerated `App/Info.plist`. `check-info-plist.sh` compares that dictionary exactly as JSON.
- New `MusicAssistantConnectionFailure.httpsOnMusicAssistantPort`. It is used only by the `/info` step, when the failure would be `.unreachable` and the base URL is https on port 8095. The `.httpsRequired` and `.blockedByATS` messages now mention Tailscale.
- Updated the Settings caption, the docs and the CHANGELOG.
- Divergence from the plan: skipped the optional tidy-up of `MusicAssistantServerRanking.isTailscale`.

## Steps to reproduce

1. Settings › Music Assistant, add a server.
2. Address: `http://<machine>.<tailnet>.ts.net:8095`.
3. Then try `https://<machine>.<tailnet>.ts.net:8095` and press Test Connection.

## Expected behavior

- `http://<name>.ts.net[:port]` (and `ws://`) is accepted. With no port it gets 8095, like a local address. Test Connection, the library and Sendspin connect over http/ws.
- When an `https` address with an explicit port 8095 can't be reached, the message explains that Music Assistant serves plain http on 8095. It suggests http for a `.ts.net` or local name, or https without the port behind `tailscale serve`.

## Actual behavior

- http: `.httpsRequired` ("Use https for this address; plain http works only on the local network.").
- https on 8095: "Can't reach the Music Assistant server." with no hint.

## Plan

### 1. Address rules (`Packages/PlayerKit/Sources/MusicAssistantKit/MusicAssistantAddressInput.swift`)

- Add `static func isTailscaleMagicDNS(_ host: String) -> Bool`. It trims `[]`, lowercases, and returns `host.hasSuffix(".ts.net")` with at least one non-empty label before `.ts.net`. Don't accept a trailing-dot form (`box.ts.net.`); ATS matching for that isn't verified. It must reject `ts.net` itself, `evil-ts.net`, `boxts.net`, `ts.net.example.com` and `box.ts.net.example.com`.
- **Leave `isLocalHost` unchanged.** `MusicAssistantDiscovery` (lines 60 and 72) uses it to filter discovered hosts, and it should keep meaning "what `NSAllowsLocalNetworking` covers".
- In `parse`, add `let plainHTTPAllowed = local || isTailscaleMagicDNS(host)`. Use it in place of `local` for:
  - the no-scheme default: `http` for a `.ts.net` name too. Music Assistant serves http on 8095, and the add-on doesn't do TLS. Someone behind `tailscale serve` types `https://`. This is a behaviour change for bare `.ts.net` input; see "User decisions".
  - the `.httpsRequired` check.
  - port 8095 then follows from the existing `resolved == "http", port == nil` line.
- `Problem.httpsRequired.message`: "Use https for this address; plain http works only on the local network or Tailscale." (It must still name no address.)
- Rewrite the type's doc comment (lines 3–8). ATS has `NSAllowsLocalNetworking` plus one exception domain, `ts.net` with subdomains, allowing insecure HTTP loads (#0172). So plain http/ws works for local addresses and Tailscale MagicDNS names; every other address needs https/wss. Update the `parse` bullet list the same way.
- `MusicAssistantAddressSecurity`: add a case `tailnet` ("Plain http to a Tailscale MagicDNS name: WireGuard encrypts it, and the ATS `ts.net` exception allows it"). In `classify`, an http host that is local gives `.local`, then `isTailscaleMagicDNS` gives `.tailnet`, else `.requiresTLS`. Nothing outside tests switches on this enum (checked), so the new case breaks nothing. Update the `.requiresTLS` comment.
- Optional tidy-up: `MusicAssistantServerRanking.isTailscale` has its own `.ts.net` suffix check, which accepts a trailing dot. It may call the new helper for the non-dot form; don't change its behaviour.

### 2. ATS (`project.yml`, regenerated `App/Info.plist`)

- Under `NSAppTransportSecurity`, keep `NSAllowsLocalNetworking: true` and add:
  ```yaml
  NSExceptionDomains:
    "ts.net":
      NSIncludesSubdomains: true
      NSExceptionAllowsInsecureHTTPLoads: true
  ```
  Add a comment: `# #0172: Tailscale MagicDNS names over plain http/ws; WireGuard encrypts tailnet traffic.` Add no other keys (no `NSExceptionMinimumTLSVersion`, no forward-secrecy relaxations). https to a `.ts.net` name keeps full certificate validation: no code in App or Packages implements a server-trust challenge (checked), so the "loosen trust evaluation" side of that key is never used.
- Run `xcodegen generate` on the host (allowed) and commit the regenerated `App/Info.plist`, which is tracked.
- **Coverage.** Every Music Assistant path goes through `URLSession`, and ATS applies the same per-domain rule to `ws://` WebSocket tasks as to `http://`. That covers:
  - `URLSessionHTTPTransport` (`/info`, artwork through `MAImageProxy.url(base:…)`, built from the server's base URL).
  - `URLSessionWebSocketTransport` (`/ws`).
  - `URLSessionSendspinTransport` (`/sendspin` via `SendspinConnectionConfiguration`, also built from the base URL).

  Nothing else needs its own treatment. External artwork URLs are https from providers and aren't affected. The QuickLook appexes (`QuickLook/Thumbnail`, `QuickLook/Preview`) do no networking and have no ATS dictionary; leave them alone.

### 3. Plist check (`scripts/check-info-plist.sh`)

- Replace `absent NSAppTransportSecurity.NSExceptionDomains` with an exact check. `plutil -extract` can't address the `ts.net` key, because the dot splits the key path. Extract the whole dictionary as JSON and compare it; plutil sorts keys, and a string `"true"` wouldn't match the JSON `true`, so this also checks the types (tried on the host):
  ```zsh
  ex="$(plutil -extract NSAppTransportSecurity.NSExceptionDomains json -o - "$P" 2>/dev/null || true)"
  print -r -- "NSAppTransportSecurity.NSExceptionDomains = ${ex:-<absent>}"
  [[ "$ex" == '{"ts.net":{"NSExceptionAllowsInsecureHTTPLoads":true,"NSIncludesSubdomains":true}}' ]] || {
    print -u2 -r -- "!! NSExceptionDomains must be exactly ts.net (subdomains, insecure HTTP loads) (#0172)"; exit 1; }
  ```
- Rewrite the comment above it to explain the rule: local-network exemption plus the single `ts.net` exception. Keep the three `NSAllowsArbitraryLoads*` `absent` checks. Add `(#0172)` to the header comment. Both the Debug (`app-plist`) and `--release` (`app-release-plist`) steps call this script, so both stay green.

### 4. Hint for https on port 8095 (`MusicAssistantConnectionTest.swift`)

- Add `MusicAssistantConnectionFailure.httpsOnMusicAssistantPort`. It holds no address. Message: "Can't reach Music Assistant over https on port 8095. Music Assistant serves plain http on 8095: use http:// for a local or .ts.net address, or https without a port if you use tailscale serve."
- In `run`, when the `/info` step fails: if `Self.failure(for:found:)` gives `.unreachable`, and `baseURL.scheme == "https"`, and `baseURL.port == MusicAssistantAddressInput.defaultPort`, return `.httpsOnMusicAssistantPort` instead. Put this in a small `static func failure(for:found:baseURL:)` overload, or a check in `run`, so the existing function stays address-free. Apply it only to the `/info` step, which is where a TLS handshake against MA's plain-http port fails (typically `URLError.secureConnectionFailed`, mapped to `.transport` and then `.unreachable`).
- `.blockedByATS` message: "macOS blocks this connection. Use https; plain http works only on the local network or Tailscale." Update its doc comment to say it shouldn't happen once the address rules and the ATS exception agree.

### User decisions

- **Bare `.ts.net` defaults to http:8095** (was https). This matches Music Assistant's own port, and someone using `tailscale serve` types `https://`. If you'd rather keep https as the bare default, drop that line from the plan and its test assertions.
- **Exposure.** The `ts.net` exception covers every `*.ts.net` name. If such a name resolves outside the tailnet, plain http would leave the machine unencrypted, including the token sent on the WebSocket. Tailscale Funnel names are public, but Funnel serves only https on 443, so plain http to one fails. Accepting that is the decision as given. Checking that the name resolves into `100.64.0.0/10` before connecting is out of scope.
