## Description

Choosing, applying and downloading skins is half of what Roadie is for, and nothing drives it: the Skins window's library grid and Museum tab, Next/Previous/Random, Open Skin…, the no-skin placeholder, Settings › Skins. And no test opens the app with anything but one skin. This issue adds `SkinsUITests` (base skin, stubbed Museum) and `SkinSmokeUITests`, which launches every skin in the manifest (`--ui-skins all`, milestone runs) and checks the three windows and both shade modes render. Rows: [docs/design/test-automation.md](../docs/design/test-automation.md) §5.8.

## Root cause

Nothing drove the Skins window, the Museum tab or the skin menus, and no test launched with any skin but `base-2.91`. Writing `nextPreviousRandom` turned up an app bug. ⌘] / ⌘[ right after launch stepped from the wrong skin. The skin given by `-lastSkinPath` loads before the background index scan adds its row, so `SkinBrowserModel.skinDidLoad(from:)` finds no row and leaves `currentSkinID` nil. `step(_:)` then steps from `-1`, the start of the index, instead of from the loaded skin.

## Fix

- **App bug.** `SkinBrowserModel` keeps the loaded skin's folder-relative path (`loadedPath`). `step(_:)` uses `resolvedCurrentSkinID(_:)`, which looks that row up in the index at step time when `currentSkinID` is still nil. The regression test is `SkinBrowserModelTests.stepsFromASkinLoadedBeforeItsRowWasIndexed`.
- **UI tests.** `Tests/RoadieUITests/SkinsUITests.swift` has the eight tests in the plan. `Tests/RoadieUITests/SkinSmokeUITests.swift` has `smokeEverySkin`, which runs one activity per manifest skin with `--ui-skins all` and `base-2.91` otherwise. Each skin gets a screenshot kept always.
- **Debug test hooks** (UI-test mode only):
  - The state probe gains `skin` and `skinFiles`. The XCUITest runner is sandboxed, so it can't read the skins folder and reads it through the probe instead.
  - Show in Finder goes through `PlayerModel.revealInFinder`, which `-RoadieExternalOpens record` records.
  - `-RoadieMuseumFeatured <name>` and `-RoadieSeedSkins <folder>` / `-RoadieSeedSkinsOmit` are new launch arguments.
  - The harness launches with `-ApplePersistenceIgnoreState YES`.
- **Departures from the plan:**
  - `museumTab` doesn't use the plan's stub downloader writing a copy of `base-2.91.wsz`. The fixture transport instead rewrites the browse page's first row to a real cached skin (`-RoadieMuseumFeatured Pika_Amp`, left out of that test's seeded library copy). The download then gets real, md5-matching bytes, and Apply loads a real skin.
  - `mutatesSkins: true` seeds a per-test skins folder from inside the app (`-RoadieSeedSkins`), because the sandboxed runner can't write outside its container.
  - The smoke test shades each window with the Window menu shortcuts (⌃⌘W/E/P) instead of clicking the skinned title-bar buttons.
  - The playlist's expected size is 275×203 skin pixels: `-playlistWindowSize [0, 3]` adds 3 × 29 to the 116-pixel minimum. The plan said 275×232.

## Gotchas

- **The Museum tab carried over between tests.** `@SceneStorage("skins.source")` survives relaunch through window restoration. After `museumTab`, the next test's Skins window opened on the Museum tab, and `nextPreviousRandom` saw 0 `skins.cell`. The harness's `defaults delete` doesn't clear it, because the runner is sandboxed (#0202). The fix is `-ApplePersistenceIgnoreState YES`, plus `openSkinsWindow` selecting the Library tab explicitly.
- **The main pop-up menu isn't a child of the application.** The menu opened with `NSMenu.popUp(positioning:at:in: hosting)` is in the accessibility tree, but under the main window, so `app.children(matching: .menu)` never finds it. Use `roadie.main.popUpMenu`, which looks for a descendant menu of the window that holds `main.play`.
- **Never take a coordinate from the app element on macOS.** `app.coordinate(withNormalizedOffset:)` raises `point.x != INFINITY` because the application element has no finite frame. Take coordinates from a window element instead.

## Plan

Launch: folder library, `-skinsFolderPath <TestSkins>` so the skin library indexes the seven cached skins (the index runs in the background: wait for `skins.counts` to read 7).

### `Tests/RoadieUITests/SkinsUITests.swift`

- `libraryGrid`: ⌘K → the Skins window; `skins.source` is Library; the grid has 7 `skins.cell`s with the manifest names (labels), thumbnails rendered (the cell exists; no pixel check); the count label reads `7 skins`; `skins.filter` by status keeps 7 (all ok); click the `Windows_Classic` cell → `probe.skin == "Windows_Classic"` and the main window's size is still 275×116 (scale 1); `skins.random` → the skin changes (retry once if it picks the same); `skins.refresh` leaves 7.
- `nextPreviousRandom`: ⌘] → the next skin in index order (`probe.skin`); ⌘[ back; ⇧⌘R random; the pop-up's Skins ▸ Next Skin too; the menu items are disabled when `-skinsFolderPath` is empty (launch variant).
- `openWszViaOpenCommand`: `open -a Roadie <TestSkins>/Pika_Amp.wsz` while running (`Process`) → `probe.skin == "Pika_Amp"` (the `application(_:open:)` path); File › Open Skin… with `-RoadieOpenFiles <skin>` → applied.
- `cellTrashMovesTheSkinOut`: `skins.cell.trash` on a cell → confirmation; confirm → 6 cells and the file is gone from the folder (the test's own copy of the cache: #0200's harness copies `TestSkins` per test when a test says `mutatesSkins: true`; add that option).
- `museumTab`: `skins.source` → Museum; the grid shows the fixture page (`skins-page1.json` names); type `zelda` in `skins.museum.search` → the `search-zelda.json` rows; a cell's button reads Download; click → the stub downloader copies the file into the skins folder (it must exist in `TestSkins/` with that md5: the fixture JSON names Museum skins we don't cache, so #0194's `.fixtures` mode rewrites one row of `skins-page1.json` to a manifest skin's md5 and filename at load time, or the stub downloader writes a copy of `base-2.91.wsz` under the requested name; pick the latter and note it) → the button reads Apply and the Library tab shows 8; Apply → `probe.skin`; right-click › Open in Skin Museum → `probe.lastExternalOpen` is the museum URL; Show in Finder → recorded too (`.record` mode captures `activateFileViewerSelecting`); Move to Trash → back to 7.
- `nsfwToggle`: Settings › Skins › Show NSFW off → the fixture rows flagged `nsfw: true` (`search-odd-rows.json` has some) are hidden in a search; on → shown.
- `noSkinPlaceholder`: launch with no `-lastSkinPath` → the main window shows the placeholder; `player.browseMuseum` opens the Skins window on the Museum tab; the EQ and playlist windows show their Open Skin… buttons.
- `settingsSkinsTab`: Settings › Skins shows the folder path (`skins.folder`), counts (`skins.counts` 7), Scan → counts stay 7, Rescan All → a progress state then 7, Reset Index… → Reset → `0 skins` then a scan brings 7 back; `skins.choose` is a panel (skipped; `-RoadieChooseFolder <path>` stand-in if cheap).

### `Tests/RoadieUITests/SkinSmokeUITests.swift`

Reads `scripts/test-skins.tsv` from `ROADIE_TEST_SKINS/test-skins.tsv`; when `ROADIE_TEST_SKIN_SET != all` it runs only `base-2.91`. For each skin, one test (`XCTContext.runActivity(named: skin)` inside `smokeEverySkin`, so the report names the skin), launching with that skin, `windows: [.main, .eq, .playlist]`, the fixture library loaded and playing:

1. The three windows exist and are docked in a column with the skin's sizes (main 275×116, EQ 275×116, playlist 275×232 at steps 0,3).
2. `main.play`, `eq.on`, `pl.row.0` exist; `pl.row.0…4` labels are the five first tracks (the playlist colours and font don't affect labels).
3. Shade each window (`main.title.shade`, `eq.title.shade`, `pl.title.shade`) and back; `shade.main.time` advances.
4. Open the main pop-up menu and close it.
5. Attach a screenshot of the column **always** (`.keepAlways`): the per-skin screenshots are the human-readable record of what each skin looks like in Roadie, next to `skintool --png`.
6. For `base` (S190947, missing sheets): the EQ and playlist windows still exist (generated sheets); for `Expensive_HI_FI_Sony_2005`: a click on a transparent region point doesn't activate anything (`SkinShapeView.hitTest`; click the top-left corner coordinate and assert nothing changed); for `Windows_Classic`: `pl.row.0` exists (white background, no pixel check); for `Pika_Amp`: rows render with the fallback font (label present).

Budget: about 25 s per skin; 7 skins ≈ 3 min, milestone runs only.
