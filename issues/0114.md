# 0114 — This Mac stays on the Music Assistant feed after the stream fails or ends

| | |
|---|---|
| **Status** | open |
| **Module** | App / LocalPlayback |
| **Platform** | macOS |
| **First seen** | 2026-10-19 |

## Description

Found in review of #0109 (code c8273f6). While Music Assistant feeds This Mac, the playlist window shows the local queue (empty) and double-clicking a row does nothing, although #0109's Fix says a double-click hands This Mac back. Worse, the feed stays on Music Assistant when the MA play fails (for example with the This Mac toggle off), when the Sendspin stream ends, or when Music Assistant disconnects. After that, the transport buttons and media keys keep going to Music Assistant, and only Open, Add, Add Dir, Load List, drag and drop or the folder source bring This Mac back to the local queue.

## Expected behavior

- If the Music Assistant play on This Mac fails, the feed returns to the local queue (or never switches), and the failure is shown.
- When the Sendspin session stops (toggle off, disconnect, server change, sleep) or Music Assistant ends the stream with nothing queued, This Mac returns to the local queue, so transport and media keys act on it again.
- Double-clicking a row in the playlist window while Music Assistant feeds This Mac plays that local track and hands This Mac back to the local queue.
- Tests cover each of these transitions with the existing fakes; nothing touches the network.

## Plan

Three gaps in c8273f6: (1) `playFromLibrary` sets `.musicAssistant` before the MA call and never undoes it on failure; (2) `SendspinPlayer` reports only preemption, so a server-side end (`.streamEnded`, `.disconnected`, `stop()` from the controller on toggle off, server change, sleep, MA disconnect) leaves the feed on `.musicAssistant`; (3) `PlaylistModel.isLocal` is `playsLocalQueue`, so while MA feeds This Mac the list is empty and `playRow` is a no-op. A double-click already hands back on its own once it reaches `player.play(at:)`: AudioCore preempts the stream and `onStreamPreempted` sets `.local` (covered by `localPlaybackPreemptsAndNotifies`).

### 1. Feed transitions as a pure, tested rule (`LibraryBrowser/PlaybackRouter.swift`)

```swift
public enum ThisMacFeedEvent: Sendable, Equatable {
    case musicAssistantPlayRequested            // → .musicAssistant
    case musicAssistantPlayFailed(isStreaming: Bool) // → isStreaming ? .musicAssistant : .local
    case streamStarted                          // → .musicAssistant
    case streamStopped                          // server ended the stream or the session stopped → .local
    case localPlayRequested                     // local files, folder source, playlist double-click → .local
}
extension ThisMacFeed { public func after(_ event: ThisMacFeedEvent) -> ThisMacFeed }
```

`musicAssistantPlayFailed(isStreaming: true)` keeps `.musicAssistant`: MA was already streaming an earlier play and still is, so transport must keep going there.

### 2. `SendspinPlayer`: say when the stream stops for a reason other than local playback

Add `@ObservationIgnored public var onStreamStopped: (() -> Void)?` with the doc "the server ended the stream, or the session dropped or was stopped; never called for a local preemption". Call it:
- in `.streamEnded`, after `endStreamFromServer()`, only if a stream was running;
- in `.disconnected`, always (a play may have been requested with no stream yet);
- in `stop(reason:)`, always, after `status = .off` (the controller's `halt` covers toggle off, server change, sleep and MA `.failed`/`.disconnected`).
`start(_:)` does not call it (it only tears down). The preemption path keeps calling only `onStreamPreempted`. The callback fires on the main actor. The app's handler is idempotent (`setThisMacFeed` guards equal values), so firing it twice is harmless.

Note: if MA sends `stream/end` between tracks, the feed goes `.local` for the gap and `onStreamStarted` sets it back. Accepted. If that turns out to flicker on the host, a grace delay belongs in a follow-up, not here.

### 3. `App/PlayerModel.swift`

- Add `private func applyFeed(_ event: ThisMacFeedEvent) { setThisMacFeed(thisMacFeed.after(event)) }` and route every existing feed change through it: `onStreamStarted` → `.streamStarted`; `onStreamPreempted` → `.localPlayRequested` (keep the MA `.stop`); `importLocalFiles` → `.localPlayRequested`; `playFromLibrary` → `.musicAssistantPlayRequested` / `.localPlayRequested`.
- New hook: `stack.sendspin.onStreamStopped = { [weak self] in self?.applyFeed(.streamStopped) }`.
- `playFromLibrary`'s `catch`: when `output == OutputDevice.thisMacID && sourceID == musicAssistant.sourceID`, call `applyFeed(.musicAssistantPlayFailed(isStreaming: stack.sendspin.isStreaming))` before `showBackendFailure(error)`. The failure notice is already posted there; keep it. The catch runs in a `Task` started from the main actor, so the call is main-actor isolated. Otherwise wrap it in `await MainActor.run`.
- Never switching when Sendspin is off: if `!sendspinController.isEnabled` and the request is MA on This Mac, leave the feed alone and let the call fail. The catch then keeps `.local` (`isStreaming` is false). The rule above already covers this; no extra branch.

### 4. Playlist window (`App/Playlist/PlaylistModel.swift`, `PlayerModel.swift:358`)

- Set `playlist.isLocal = { [weak self] in self?.selectedOutput == OutputDevice.thisMacID }`: the window shows AudioCore's queue whenever This Mac is the output, whatever feeds it. Queue edits are safe while streaming (`Player.clearQueue` keeps a server stream playing; sort, move and remove don't touch transport).
- Add `@ObservationIgnored var isPlayingLocalQueue: @MainActor () -> Bool = { true }`, set to `playsLocalQueue`. Use it for `currentIndex` only, so no local row is highlighted as current while MA plays.
- Add `@ObservationIgnored var onPlayLocal: @MainActor () -> Void = {}`, set by PlayerModel to `applyFeed(.localPlayRequested)`. Call it in `playRow` before `player.play(at:)`. Preemption would also set `.local`. The explicit call keeps the hand-back working when no stream is running (feed stuck on `.musicAssistant`, nothing playing).
- Update the class doc comment, which says the list is empty with a remote output: it is empty only on a speaker.

### Tests (all with existing fakes; no network)

`LibraryBrowserTests/OutputPickerModelTests.swift`, in the existing `PlaybackRouterTests`:
- `feedFollowsMusicAssistantPlayAndStream`: `.local.after(.musicAssistantPlayRequested)` and `.after(.streamStarted)` are `.musicAssistant`.
- `failedMusicAssistantPlayReturnsToLocalUnlessStreaming`: `isStreaming: false` → `.local`; `isStreaming: true` → `.musicAssistant`.
- `streamStopReturnsThisMacToTheLocalBackend`: a router with feed `.musicAssistant`. Apply `.streamStopped` through `after`, and `backend(for: thisMacID, command: .next)` is `local`.
- `localPlayTakesThisMacBack`: `.musicAssistant.after(.localPlayRequested) == .local`.

`SendspinPlaybackTests/SendspinPlayerTests.swift` (Rig gains a `stopped` counter wired to `onStreamStopped`):
- `serverStreamEndNotifiesStopped`: after `startStream()`, a `.streamEnded` event gives `stopped == 1` and `preempted == 0`.
- `disconnectNotifiesStopped`: `.disconnected` gives `stopped >= 1`, with or without a stream.
- `stopNotifiesStoppedWithoutAStream`: `connect()`, no stream, `await bridge.stop()` gives `stopped == 1`.
- `localPlaybackPreemptsWithoutStopped`: extend the existing preemption scenario: `preempted == 1`, `stopped == 0` before the final `stop()`.
