# 0114 — This Mac stays on the Music Assistant feed after the stream fails or ends

| | |
|---|---|
| **Status** | open |
| **Module** | App / LocalPlayback |
| **Platform** | macOS |
| **First seen** | 2026-10-19 |

## Description

Found in review of #0109 (code c8273f6). While Music Assistant feeds This Mac, the playlist window shows the local queue (empty) and double-clicking a row does nothing, although #0109's Fix says a double-click hands This Mac back. Worse, the feed stays on Music Assistant when the MA play fails (for example with the This Mac toggle off), when the Sendspin stream ends, or when Music Assistant disconnects. After that, the transport buttons and media keys keep going to Music Assistant, and only Open, Add, Add Dir, Load List, drag and drop or the folder source bring This Mac back to the local queue.

## Expected behavior

- If the Music Assistant play on This Mac fails, the feed returns to the local queue (or never switches), and the failure is shown.
- When the Sendspin session stops (toggle off, disconnect, server change, sleep) or Music Assistant ends the stream with nothing queued, This Mac returns to the local queue, so transport and media keys act on it again.
- Double-clicking a row in the playlist window while Music Assistant feeds This Mac plays that local track and hands This Mac back to the local queue.
- Tests cover each of these transitions with the existing fakes; nothing touches the network.
