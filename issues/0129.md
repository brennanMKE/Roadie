# 0129 — Restoring a minimized skinned window can leave the docked stack shifted or overlapping

| | |
|---|---|
| **Status** | open |
| **Module** | App / WindowDocking |
| **Platform** | macOS |
| **First seen** | 2026-10-20 |

## Description

Found while fixing #0120 (7f4fc61, EQ and PL are child windows of main). Minimizing any skinned window now detaches every child window until it comes back from the Dock. On macOS 27 with Stage Manager on, when the docked stack hangs off the bottom of the screen, the restored stack can come back shifted: on a 1470x956 display the group moved up 156 pt (still docked); on 1024x768 main moved to the top and EQ came back 8 pt over main. Also, closing main from its title bar now hides the attached EQ and PL too (they return with main from the Dock icon); not yet checked in a VM.

## Expected behavior

- Minimize detaches only what it must (the minimized window, or main's children when main minimizes), and the others stay grouped.
- After a window comes back from the Dock, the docked layout is checked and re-docked so no skinned window overlaps another (the #0120 Fix A rule).
- Closing main and bringing it back restores EQ/PL as they were; confirm it's the intended behaviour.
