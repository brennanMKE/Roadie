## Description

`PlayerModel.backend` (`App/PlayerModel.swift`) is a `let` bound to `PlexPlaybackStack.standard().backend` at init, and everything that talks to a source is built from it once: `LibraryBrowserModel(backend:)`, `ArtworkCache(backend:)`, the transport path and the `backend.nowPlaying(on:)` subscription. #0065 added `PlayerModel.folderBackend` (a working `FolderBackend` with Settings › Library to choose and index a folder), but nothing can hand it to the browser, so a user who sets a folder cannot browse or play it from the Library window.

The source picker (#0063) and the fallback (#0067) both need one mechanism underneath: make the active backend replaceable while the app runs.

## Acceptance criteria

- `PlayerModel` exposes the active `any MusicBackend` as a switchable value with one entry point (e.g. `select(_ backend:)`); switching rebuilds or re-points the browser model, `clear()`s the `ArtworkCache` (refs mean something only to their backend, per its own comment), re-subscribes to `nowPlaying(on:)` and routes transport and play through the new backend.
- Switching does not stop what is playing on This Mac (Plex and folder share one `LocalPlayerOutput`/`Player`) and never discards the other source's settings or tokens.
- The Library window shows which source it is browsing.
- Unit-tested with `MusicBackendStub` backends; no audio device opened.

## Plan

### Scope and decisions

This issue makes the active `MusicBackend` replaceable while the app runs and gives Settings › Library a minimal picker over the two sources that exist today (Plex, Local folder). It decides nothing about defaults beyond "what the app does now" (Plex), adds no Music Assistant code (#0061/#0063/#0064) and no fallback (#0067); section 9 says exactly where those hook in. `MusicBackendKit`, `LocalPlayback`, `PlexBackendKit`, `FolderBackendKit`, `AudioCore`, `PlexKit` and `TrackCache` are untouched.

- **One owner, `LibrarySourceController`, in the `LibraryBrowser` target.** It holds the ordered list of `LibrarySource`s (a backend plus what Settings shows about it), the current choice, and the three things the app builds from the active backend today: the `LibraryBrowserModel`, the `ArtworkCache` and the now-playing subscription. `PlayerModel.backend`, `.library` and `.artwork` become computed properties over the controller, so every view that reads `player.library` / `player.artwork` compiles unchanged and re-renders when the source changes (Observation tracks through the chain). The entry point is `controller.select(_ id:)`; nothing else swaps a backend. It lives in `LibraryBrowser` (not `App/`) so it is unit-tested in the VM, and that target gains a dependency on `MusicLibraryKit` for `ArtworkCache` (no cycle: `MusicLibraryKit` depends on `MusicBackendKit` only).
- **Sources are identified by `MusicBackend.sourceID`** (`"plex"`, `"folder"`, later `"musicAssistant"`). The persisted choice is that string under `UserDefaults` key `LibrarySource`. An unknown or missing stored id resolves to a `defaultSourceID` the composition root passes (`"plex"` here; #0063 passes `"musicAssistant"` and prepends its source). Nothing is written to defaults until the user picks, so a later change of the default reaches users who never chose.
- **Switching rebuilds, it does not mutate.** `LibraryBrowserModel.backend` and `.sections` are `let`, and `ArtworkCache.backend` is `private let`, so the controller calls `disappeared()` on the old browser model (cancels in-flight pages, tracks and search) and constructs a new `LibraryBrowserModel(backend:)` and a new `ArtworkCache(backend:)`. A fresh cache supersedes the acceptance criterion's `clear()`: `clear()` keeps in-flight fetches, which would still insert the old source's images into a cache now bound to the new backend; a new instance cannot. The old backend is **not** `disconnect()`ed: Plex keeps its client and `knownTracks`, the folder keeps its index and watcher, so switching back costs nothing and neither source's settings or tokens are touched (criterion 2, and what #0067 needs to flip back and forth).
- **The now-playing subscription survives the switch.** The controller exposes `nowPlaying(on:) -> AsyncStream<NowPlaying>`, an outer stream that forwards the *active* backend's `nowPlaying(on:)` and, on `select`, cancels the inner subscription and opens one on the new backend, forwarding its first (current) snapshot at once. `PlayerModel.observeNowPlaying()` keeps its loop and its volume-follow rule and only changes the callee from `backend.nowPlaying(on:)` to `sources.nowPlaying(on:)`. Nothing is reset to `.idle` on a source switch (only on an output change, as today).
- **What is playing keeps playing (recommended, chosen).** Plex and the folder share one `LocalPlayerOutput` over one `Player`, and the queue, `CachePinner`, `PlexTrackResolver` and `NowPlayingBridge` all hang off the `Player`, not off a backend. So a switch leaves the queue, the position and the main window alone; the new backend's first snapshot from the shared output is the same live snapshot, so the marquee does not even flicker. The alternative, stopping on switch, would be `output.perform(.stop)` in `select` and buys nothing today; it is noted in section 9 for the MA case (remote outputs) where #0064 decides. `NowPlaying.item` stays the queued track's id from whichever source queued it (the output's `UUID → MediaID` registry is shared, as the #0062 reviewer noted); no code reads `item` across sources yet.
- **Transport and play go through the active backend at call time.** `PlayerModel`'s command loop currently captures `stack.backend` once (`transportBackend`); it reads `sources.backend` per command instead. `playFromLibrary` already reads `backend` at call time. For This Mac both backends route to the same output, so behaviour is unchanged; it matters once a backend owns remote outputs.
- **The Library window shows the source and follows the swap.** `.navigationSubtitle(library.backend.displayName)` under the "Library" title, and `.task(id: ObjectIdentifier(player.library)) { library.appeared() }` so a rebuilt model connects when the window is open (today's `.task` without an id runs once per window and would leave a new model idle). The window is the only thing that connects: picking a source in Settings never calls `connect()` (the no-launch-I/O rule holds for the picker too).
- **Settings › Library gets a `Source` section above the folder section**, a radio-group `Picker` over `controller.sources` (display names, with a "Not set up" caption from `LibrarySource.isConfigured`), bound to `controller.select`. `isConfigured` reads `UserDefaults` only, never the Keychain (a Keychain prompt in the headless guest would hang `app-launch`): Plex is configured when the saved `PlexServerSelection` has a non-empty address; the folder when `FolderBackend.storedFolder()` is non-nil. The token's presence is checked where it is today, in `connect()`.
- **`StubMusicBackend` gains `sourceID`/`displayName` init parameters** (defaults unchanged) so two stubs can stand for two sources. Additive; no existing test changes.
- **Verification is `scripts/run-tests-vm.sh --launch` only.** No `swift test`, `xcodebuild` or app launch on the host. Every new test runs over `StubMusicBackend`s and a private `UserDefaults` suite; nothing touches `Player`, AudioCore, the network, the Keychain or the real defaults, and no token or address exists in any test.

### 3. `LibrarySource.swift`

```swift
/// One selectable library source: the backend plus what Settings shows about it.
public struct LibrarySource: Identifiable, Sendable {
    /// `backend.sourceID`: "plex", "folder", "musicAssistant".
    public var id: String
    public var displayName: String
    public var backend: any MusicBackend
    /// Whether the user has set this source up, from UserDefaults only (never the Keychain or the network).
    /// Settings shows "Not set up" from it; #0067's fallback order reads it.
    public var isConfigured: @Sendable () -> Bool

    public init(backend: any MusicBackend, isConfigured: @escaping @Sendable () -> Bool)   // id/displayName from the backend
}

/// Pure: which source a stored choice resolves to.
public enum LibrarySourceSelection {
    /// `stored` when it names one of `available`; else `fallback` when it does; else the first available id.
    public static func resolve(stored: String?, available: [LibrarySource], fallback: String) -> String
}
```

`available` must be non-empty (`precondition`); ids must be distinct (`precondition` in the controller's init).

### 4. `LibrarySourceController.swift`

```swift
@MainActor @Observable
public final class LibrarySourceController {
    public static let defaultsKey = "LibrarySource"

    /// In fallback order; #0063 prepends Music Assistant.
    public let sources: [LibrarySource]
    public private(set) var selectedID: String
    public var selected: LibrarySource { sources.first { $0.id == selectedID }! }
    public private(set) var backend: any MusicBackend
    public private(set) var library: LibraryBrowserModel
    public private(set) var artwork: ArtworkCache
    /// Increments per switch (tests; #0067).
    public private(set) var generation = 0
    /// Live outer now-playing streams (tests).
    public var nowPlayingSubscriberCount: Int { subscribers.count }

    public init(sources: [LibrarySource], defaultSourceID: String, defaults: UserDefaults = .standard,
                pageSize: Int = 100, searchDelay: Duration = .milliseconds(300), searchLimit: Int = 50,
                artworkLimitBytes: Int = ArtworkCache.defaultLimitBytes, artworkLimitCount: Int = ArtworkCache.defaultLimitCount)

    /// The one entry point. false (and no change) for an unknown id or the current one. Persists the choice,
    /// tears down the old browser model, builds a new browser model and artwork cache, re-points every live
    /// now-playing stream. Never connects or disconnects a backend.
    @discardableResult public func select(_ id: String) -> Bool

    /// Forwards the active backend's `nowPlaying(on:)` and follows `select`. Ends when the subscriber cancels.
    public func nowPlaying(on output: OutputDevice.ID) -> AsyncStream<NowPlaying>
}
```

Rules, each tested in section 7:

- **`init`**: `selectedID = LibrarySourceSelection.resolve(stored: defaults.string(forKey: Self.defaultsKey), available: sources, fallback: defaultSourceID)`; `backend = selected.backend`; `library = LibraryBrowserModel(backend:pageSize:searchDelay:searchLimit:)`; `artwork = ArtworkCache(backend:limitBytes:limitCount:)`. Writes nothing to defaults. Logs `info` "source <id>" (category `LibrarySource`, subsystem `com.brennanmke.SkinAmp`); never a path or address.
- **`select(id)`**: guard `id != selectedID` and `sources` contains `id`, else return false. Then, in this order: `library.disappeared()`; `selectedID = id`; `backend = source.backend`; `library = LibraryBrowserModel(backend: …)` (same page size / delays as init); `artwork = ArtworkCache(backend: …)`; `generation += 1`; `defaults.set(id, forKey: Self.defaultsKey)`; for every live subscriber cancel its inner task and start a new one on the new backend (`resubscribe(_:)`); log `info` "switched to <id>". No `connect()`, no `disconnect()`, no transport.
- **`nowPlaying(on:)`**: `AsyncStream(bufferingPolicy: .bufferingNewest(1))`; a `Subscriber { output, continuation, inner: Task<Void, Never>? }` keyed by UUID in `subscribers` (`@ObservationIgnored`); `resubscribe` sets `inner = Task { [backend] in for await s in await backend.nowPlaying(on: output) { guard !Task.isCancelled else { return }; continuation.yield(s) } }`; the outer `onTermination` hops with `Task { @MainActor in self?.end(id) }`, which cancels the inner task and removes the entry. Cancelling the inner task terminates the backend stream (both `LocalPlayerOutput` and `StubMusicBackend` remove their continuation in `onTermination`), so no backend keeps a dead subscriber. The outer stream does not yield anything of its own: the first element is always the backend's current snapshot.

### 11. Risks and gotchas

- **`.task` without an id would not re-run for a rebuilt model.** `LibraryWindowView` must key the task on the model's identity (`ObjectIdentifier(player.library)`), or the new model never connects while the window is open. `onDisappear { library.disappeared() }` captures the body-time model, which is the current one; fine.
- **Observation through computed properties.** `PlayerModel.library` is `{ sources.library }`; reading it inside a SwiftUI body registers on the controller's stored property, so a switch re-renders the window. `@Bindable var library = player.library` inside `body` stays valid because it is re-evaluated per render.
- **`LibrarySource` is `Sendable` only if its parts are.** `any MusicBackend` is `Sendable` by protocol; the closure is `@Sendable`. Do not store a `UserDefaults` in the struct; capture `nonisolated(unsafe)` where a closure needs one (as `PlexPlaybackStack.standard()` does), or read `.standard` inside.
- **Stream termination runs off the main actor.** The outer `onTermination` must hop (`Task { @MainActor in … }`) before touching `subscribers`; cancelling the inner task from there is enough to end the backend's stream. Use `bufferingNewest(1)` on the outer stream too, so a slow consumer sees the latest snapshot.
- **The inner task must capture the backend by value**, not read `self.backend`, or a switch would race the old loop. `resubscribe` cancels the old inner task before starting the new one; a snapshot from the old backend that was already buffered may still be delivered once, which the test tolerates by waiting for the new backend's title rather than asserting the exact sequence length.
- **Stubs yield `.idle` first; real outputs yield the live snapshot.** That is why the now-playing test emits on the folder stub *before* the switch; with `LocalPlayerOutput` shared by both real backends the continuity is structural (`LocalPlaybackTests.streamYieldsTheIdleSnapshotFirst` already proves "current snapshot first").
- **Keychain.** `isConfigured` for Plex must decode the selection from defaults only. `PlexBackend.settingsProvider` reads the token store and must not be used for it: a Keychain prompt during `app-launch` in the guest hangs the run.
- **The Settings › Library index section still connects the folder backend on appear** regardless of the picker (unchanged #0065 behaviour). It indexes files, opens no audio, and is harmless; leave it.
- **`sections` differ per backend.** Rebuilding the model handles it (Plex and folder both lack playlists today; MA may have them). `LibrarySidebarView` reads `library.sections` from the current model.
- **Picker style.** `.radioGroup` is macOS-only and fine here; `.segmented` also works. Tag type is `String`, matching `selectedID`.
- **Swift 6 strictness.** The controller is `@MainActor`; `subscribers` is `@ObservationIgnored`; `ArtworkCache` and the stubs are actors, so awaits in tests need `@MainActor` helpers (same as #0062/#0065).
