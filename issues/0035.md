## Description

Add a SwiftUI `LazyVGrid` library browser with search by name/readme, status filter, random skin, and apply on click; meanwhile add a Skins menu with next/previous.

## Acceptance criteria

- Search returns in under 200 ms on the full corpus.
- Applying a skin during playback causes no audio glitch.

## Plan

### Scope and decisions

This issue adds the Skins window (a `LazyVGrid` of thumbnails over the #0033 index, with search, a status filter, a random button and apply-on-click), a Skins menu (Skin Library…, Next Skin, Previous Skin, Random Skin), and the view model that drives both. It depends on #0033 (`SkinLibrary`: `SkinIndexStore`, `SkinRecord`, `SkinStatus`, the FTS5 table, `SkinLibraryModel` in `App/`) landing first. #0034's thumbnail cache is consumed through a one-method protocol so the two can land in either order. It writes no indexing, no thumbnail generation of its own beyond a fallback, no Quick Look (#0043), and no EQ/playlist skins.

- **View models live in a new `SkinBrowser` target in `Packages/SkinKit`, not in `App/`.** The `SkinAmp` scheme tests package targets only, so anything in `App/` is untestable in the VM (#0016 made the same call with `LibraryBrowser`). `SkinBrowser` depends on `SkinLibrary` and `SkinKit`; it imports Foundation, Observation and CoreGraphics only. `App/SkinBrowser/` holds the SwiftUI views and nothing else. It lives in the SkinKit package so it never links AudioCore, PlexKit or TrackCache.
- **The model talks to a protocol, `SkinIndexReading`, that `SkinIndexStore` conforms to.** Behaviour tests use an in-memory `StubSkinIndex` actor with recorded calls, error injection and gates (the `StubMusicBackend` pattern), so loading states are deterministic. The 200 ms budget test uses the real store seeded with 100k rows (section 7). `SkinIndexStore` gains four additive methods (section 2); nothing in #0033's API changes.
- **One query shape.** `SkinQuery { text, statuses, limit, offset }` maps to one `SELECT` in the store: `status IN (…)`, optionally joined to `skins_fts MATCH ?` (the quoted-prefix-token expression #0033 builds) ordered by `bm25(skins_fts), name COLLATE NOCASE, id`, otherwise ordered by `name COLLATE NOCASE, id`. Pages are 200 rows with `OFFSET`; the grid never holds the whole corpus. Queries shorter than two characters are treated as empty (an unfiltered listing): a one-letter prefix matches most of 100k rows and makes bm25 rank all of them, which is the one query shape that threatens the budget.
- **Search is debounced in the model (150 ms), Return searches at once, a generation counter drops stale answers.** Same rules as `LibraryBrowserModel`; shorter delay because the store is local.
- **Status filter: All / OK / Partial / Failed, as a `Set<SkinStatus>`.** `All` is `[ok, partial, failed]`. Apply is refused for a `failed` record (the parser rejected it; the cell is drawn dimmed with no pointer action). Random and Next/Previous always use `[ok, partial]` regardless of the filter, so the menu never lands on a skin that cannot load.
- **Next/Previous walk the whole index in `name COLLATE NOCASE, id` order (the browser's default order), loadable skins only, wrapping at both ends, independent of the window's search and filter.** The menu works with the window closed, so it cannot depend on what the window shows. The starting point is the current skin's index row: set optimistically when the browser or menu applies a skin (so holding ⌘] steps through the list even while a parse is in flight), and resolved from the file's folder-relative path when a skin was loaded another way (Open Skin…, drop, `lastSkinPath`). Unknown current → Next applies the first row, Previous the last.
- **Applying a skin is `PlayerModel.loadSkin(from:)`, unchanged in substance, plus a generation counter.** The parse already runs in `Task.detached`; the main-actor tail assigns `skin`, `mainWindowBase`, `skinName`, calls `visualizer.setColors` (builds a `VisRenderer`, a few allocations) and writes a default. Nothing in that path touches `Player`, `AudioGraph` or `AVAudioEngine`; `AnalyzerTap`'s tap block "allocates nothing and takes no locks" and only the display-link tick on the main actor reads the ring, so a skin switch cannot reach the render thread. The audio acceptance criterion is therefore satisfied by construction and checked by (a) a grep that `SkinBrowser` and `App/SkinBrowser/` import no AudioCore/AVFoundation, (b) a test that the apply hook is called on the main actor exactly once per action, and (c) a hand check on the host (section 8), since the VM is silent. The generation counter is needed because two rapid applies today race: the slower parse would overwrite the newer skin.
- **Thumbnails go through `SkinThumbnailProviding`.** `func thumbnail(for record: SkinRecord, at url: URL) async -> CGImage?`; the browser hands over both the content hash (#0033's key) and the file URL, so #0034's cache can key by either. `SkinBrowser` ships a `RendererThumbnailProvider` fallback (parse + `MainWindowRenderer.render(skin:state: .idle, scale: 1, clipToRegion: true)` in a `Task(priority: .utility)`, nothing on disk) so the grid works before #0034 lands; `App/SkinBrowser/SkinThumbnailAdapter.swift` swaps in #0034's disk-backed cache when it exists. The model keeps an in-memory LRU of 400 `CGImage`s (275×116 RGBA8 ≈ 128 KiB each, ≈ 50 MiB) and de-duplicates in-flight requests by hash.
- **The window is a SwiftUI `Window` scene (`id: "skins"`, ⌘K), like the Library window (#0016).** It is unskinned, resizable, and opened on demand only: `AppDelegate`'s launch guard closes any window whose identifier starts with `library` today and gains `skins`, so the `--launch` smoke test never opens it and never opens the database (with no folder set, nothing opens at all, as in #0033).
- **The Skins menu is a `CommandMenu("Skins")` in `SkinAmpApp.commands`.** Skin Library… ⌘K (opens the scene through `openWindow` from a tiny view inside the menu, since `Commands` bodies take views), Next Skin ⌘], Previous Skin ⌘[, Random Skin ⌘⇧R; the three navigation items are disabled while the index has no loadable skin.
- **Verification is `scripts/run-tests-vm.sh --launch` (and `--launch --skins "untitled folder"`) only.** No `swift test`, `swift run`, `xcodebuild` or app launch on the host. Tests are silent (no audio device, no network) and build their own data: stub records for behaviour, 100k generated rows for the budget.

### 2. `SkinLibrary` additions (`SkinQuery.swift`, `SkinIndexStore.swift`)

```swift
public struct SkinQuery: Hashable, Sendable {
    public var text: String = ""                               // trimmed by the caller; < 2 characters means "no text"
    public var statuses: Set<SkinStatus> = Set(SkinStatus.allCases)
    public var limit: Int = 200
    public var offset: Int = 0
    public static let loadable: Set<SkinStatus> = [.ok, .partial]
    public var hasText: Bool { text.count >= 2 }
    public init(text: String = "", statuses: Set<SkinStatus> = Set(SkinStatus.allCases), limit: Int = 200, offset: Int = 0)
}

public enum SkinNeighborDirection: Sendable { case next, previous }

extension SkinIndexStore {   // all actor-isolated, each one statement
    /// Text + status + page in one SELECT. With text: skins JOIN skins_fts ON skins_fts.rowid = skins.id
    /// WHERE skins_fts MATCH ? AND status IN (…) ORDER BY bm25(skins_fts), name COLLATE NOCASE, id LIMIT ? OFFSET ?.
    /// Without: WHERE status IN (…) ORDER BY name COLLATE NOCASE, id LIMIT ? OFFSET ?. Same row shape as `skins(...)`.
    public func skins(matching query: SkinQuery) throws -> [SkinRecord]
    /// COUNT(*) over the same WHERE (no ORDER/LIMIT); the status bar's "N of M".
    public func count(matching query: SkinQuery) throws -> Int
    /// The row after/before `id` in (name COLLATE NOCASE, id) order among `statuses`, wrapping to the first/last;
    /// nil when no row has one of `statuses`. Two statements: the strict neighbour, then the wrap.
    public func neighbor(of id: Int64, direction: SkinNeighborDirection, statuses: Set<SkinStatus>) throws -> SkinRecord?
    /// The skin one of whose files is at this folder-relative path (files.path = ?).
    public func skin(atPath path: String) throws -> SkinRecord?
    /// `ORDER BY random() LIMIT 1` over ids WHERE status IN (…), then fetch.
    public func randomSkin(statuses: Set<SkinStatus>) throws -> SkinRecord?
}
```

The strict-neighbour SQL for `.next`: `WHERE status IN (…) AND (name > ?1 COLLATE NOCASE OR (name = ?1 COLLATE NOCASE AND id > ?2)) ORDER BY name COLLATE NOCASE, id LIMIT 1`, with `?1`/`?2` the current row's name and id (looked up first by id; an id no longer in the index behaves as unknown → first row). `.previous` flips the comparisons and the order. The FTS expression reuses #0033's quoted-prefix-token builder (hoist it to an internal `static func ftsExpression(for:)` if it is a private helper), so punctuation can never make `MATCH` throw. `status IN` is built from the sorted set as `?,?,?` placeholders; an empty set returns `[]`/`0`/`nil` without touching SQLite. Timing of each query is measured by the model, not the store.

### 4. `SkinBrowser`: `SkinBrowserModel`

```swift
public enum SkinBrowserPhase: Hashable, Sendable {
    case needsFolder          // no folder configured (index closure returned nil)
    case idle, loading        // first page in flight
    case loaded               // items may be empty = the empty state
    case failed(String)
}
public enum SkinStatusFilter: String, CaseIterable, Sendable, Identifiable {
    case all, ok, partial, failed
    public var statuses: Set<SkinStatus>   // all → every case
}

@MainActor @Observable
public final class SkinBrowserModel {
    public typealias IndexProvider = @Sendable () async throws -> (any SkinIndexReading)?   // nil = no folder
    public init(index: @escaping IndexProvider,
                folder: @escaping @MainActor () -> URL?,
                thumbnails: any SkinThumbnailProviding,
                applySkin: @escaping @MainActor (URL) -> Void,
                pageSize: Int = 200, prefetchDistance: Int = 40, searchDelay: Duration = .milliseconds(150))

    public private(set) var phase: SkinBrowserPhase = .idle
    public private(set) var items: [SkinRecord] = []          // the loaded pages, ids unique
    public private(set) var matchCount: Int?                  // count(matching:) for the current query
    public private(set) var counts: (files: Int, skins: Int, byStatus: [SkinStatus: Int])?
    public private(set) var isLoadingMore = false
    public private(set) var loadMoreError: String?
    public private(set) var lastQueryDuration: Duration?      // measured around skins(matching:); shown in the status bar
    public var hasMore: Bool
    public var searchText = ""                                // didSet: scheduleSearch()
    public var filter: SkinStatusFilter = .all                // didSet: reload()
    public private(set) var currentSkinID: Int64?
    public var canNavigate: Bool { (counts?.byStatus[.ok] ?? 0) + (counts?.byStatus[.partial] ?? 0) > 0 }
    public var query: SkinQuery                               // the trimmed text (if ≥ 2 chars), filter.statuses, pageSize, offset 0

    public func appeared()          // open the index (needsFolder when nil), counts(), then reload() if phase is .idle/.needsFolder
    public func disappeared()       // cancel in-flight loads, the pending search and thumbnails; keep items
    public func reload()            // first page of `query`; generation++, cancels the previous load
    public func loadMoreIfNeeded(current record: SkinRecord)   // index ≥ items.count - prefetchDistance → loadMore()
    public func retryLoadMore()
    public func searchNow()         // Return: skip the delay
    public func clearSearch()
    public func indexDidChange()    // a pass finished: counts() and reload(), keeping searchText/filter
    public func canApply(_ record: SkinRecord) -> Bool          // status != .failed
    public func apply(_ record: SkinRecord)                     // currentSkinID = record.id; applySkin(folder/primaryPath)
    public func random()            // index.randomSkin(statuses: .loadable) → apply
    public func next()              // index.neighbor(of: currentSkinID ?? …, .next, .loadable) → apply; unknown current → first
    public func previous()          // … → last
    public func skinDidLoad(from url: URL)   // PlayerModel calls after a successful load: resolve the folder-relative path → skin(atPath:) → currentSkinID (nil when outside the folder)
    public func thumbnail(for record: SkinRecord) async -> CGImage?   // through ThumbnailCache with folder/primaryPath
}
```

Rules:

- `appeared()`: `index()` nil → `.needsFolder`, items cleared, nothing else. Else keep the reader, `counts()`, then `reload()` unless `phase == .loaded` (reopening the window keeps the pages). Errors from `counts()`/`skins(matching:)` → `.failed(message)` with `(error as? LocalizedError)?.errorDescription ?? error.localizedDescription`.
- `reload()`: generation++, cancel the previous task, `items = []`, `matchCount = nil`, `.loading`; `Task { let t0 = ContinuousClock.now; let page = try await reader.skins(matching: query); lastQueryDuration = t0.duration(to: .now); … matchCount = try await reader.count(matching: query) }`. A stale generation returns without touching state; `CancellationError` never produces `.failed`. The count is a second statement so the first page shows before the count lands.
- `loadMore()`: no-op unless `.loaded`, `hasMore` and not already loading; requests `offset: items.count`; appends records whose id is not already present; `hasMore = page.count == pageSize`. Failure keeps the items and sets `loadMoreError`.
- `scheduleSearch()`: cancel `searchTask`; the trimmed text with fewer than 2 characters makes `query.text == ""`; if the effective query did not change, do nothing; else `searchTask = Task { try await Task.sleep(for: searchDelay); reload() }`. `searchNow()` is the same without the sleep.
- `filter.didSet` → `reload()` at once (no debounce).
- `next()/previous()`: one at a time is not required; each call reads `currentSkinID` as it is now, so rapid presses chain (test `rapidNextChainsFromTheLatestSelection`). `neighbor` nil (no loadable skin) → nothing. The applied record is also inserted into the thumbnail cache's recent set, nothing else.
- `apply(record)`: `guard canApply(record), let folder = folder()`; `currentSkinID = record.id`; `applySkin(folder.appending(path: record.primaryPath))`. Never async: the hook runs synchronously on the main actor so the test can assert the call count right after.
- `skinDidLoad(from:)`: compute the path relative to `folder()?.standardizedFileURL.resolvingSymlinksInPath()` (same root rule as `FolderScanner`); outside the folder → `currentSkinID = nil`; inside → `Task { currentSkinID = try await reader.skin(atPath:)?.id }` (a stale generation guard is not needed: later calls simply overwrite). If `apply` set the id optimistically for the same path, the lookup confirms it.
- Logging: `Logger(subsystem: "com.brennanmke.SkinAmp", category: "SkinBrowser")`; `debug` for query durations and result counts, `info` for apply/next/random by record id and status. Never the search text, a file name or a path.

`SkinBrowserFormat` (pure): `countLabel(matching: Int?, total: Int?, isFiltered: Bool) -> String` ("1,234 of 98,765 skins", "98,765 skins", "No skins"), `elapsedLabel(_ d: Duration?) -> String?` ("12 ms", nil), `fileURL(folder: URL, path: String) -> URL`, `relativePath(of url: URL, in folder: URL) -> String?`.

### 9. Risks and gotchas

- **Landing order.** #0033 must be in before this starts (the store, `SkinRecord`, `SkinLibraryModel`). If #0033 lands with different names (`skins(status:)` vs `statuses`, a public seeding helper, a different `SkinLibraryModel` shape), adapt section 2 and the three one-line hooks in section 5; the model and the views name only `SkinIndexReading`, `SkinQuery` and `SkinRecord`. #0034 may land before or after: only `SkinThumbnailAdapter.make()` changes.
- **bm25 on broad queries.** FTS5 must score every matching row before `LIMIT`; a two-letter prefix over 100k rows is the worst case and is what the budget test measures. Mitigations already in the design: the two-character minimum, `LIMIT 200`, the name column first in the ranking. If the VM numbers are still over, the next lever is `rank` only when the match count is below a threshold (`count(matching:)` first, then `ORDER BY name` for broad matches), which is a store-only change.
- **`OFFSET` paging on a live index.** A pass finishing between two pages can shift rows; ids are de-duplicated on append and `indexDidChange()` reloads, so the worst case is a missed row until the next reload. Keyset paging (`(name, id) > last`) is the upgrade if it shows.
- **100k rows in the guest.** Seeding 100k rows with FTS triggers takes tens of seconds; the 5-minute limit guards a slow volume. Keep readmes short (40 words) so the test measures the query, not the seed. Never assert on the seed time.
- **Thumbnail memory and churn.** `LazyVGrid` creates cells as they appear; `.task(id:)` cancels on disappear, and the cache de-duplicates by hash, so fast scrolling does not fan out renders. 400 images ≈ 50 MiB; the fallback provider parses each skin (ms) and renders once. #0034's disk cache removes the parse.
- **Stale skin loads.** Without the generation counter, ⌘] ⌘] can show the older skin; with it, the last request wins. The counter lives in `PlayerModel`, where the only `loadSkin` is.
- **`currentSkinID` and duplicates.** A skin with three files has one row; `skin(atPath:)` maps any of its paths to it, so Next continues from the right place whichever copy was opened.
- **`Commands` and observation.** `.disabled(!model.skinBrowser.canNavigate)` inside `CommandMenu` re-evaluates when the observed `counts` change; if a menu item is seen stale, read `canNavigate` through a small `@Observable`-aware view (`SkinsMenuItems`) rather than the `Commands` body.
- **`openWindow` from a menu.** `@Environment(\.openWindow)` inside a view in a `CommandMenu` works on macOS 14; if it does not, the "Skin Library…" item goes, and the Window menu's automatic item with ⌘K remains.
- **Shortcut clashes.** ⌘K, ⌘[, ⌘] and ⌘⇧R are unused by the app today (⌘L Library, ⌘1 Player, ⌘O/⌘⌥O/⌘⇧O open). `.searchable` takes ⌘F when the Skins window is key.
- **`.searchable` outside `NavigationSplitView`.** A `Window` with a toolbar still gets the search field at `.toolbar` placement; if macOS 14 refuses, fall back to a `TextField` in the toolbar bound to `searchText` with `onSubmit` → `searchNow()`.
- **Strict concurrency.** `SkinIndexReading` methods are `async` on an actor; `SkinRecord` and `SkinQuery` are `Sendable`; `CGImage` crosses from the provider's task to the main actor as `MainWindowBase` already does. The apply hook is `@MainActor` so it never hops.
- **Settings link.** `SettingsLink` exists on macOS 14; it opens the Settings scene, whose Skins tab is #0033's. No `NSApp.sendAction(Selector(("showSettingsWindow:")))`.
- **No audio in tests.** `SkinBrowser` cannot reach AudioCore (package boundary and the grep), and the model never blocks the main actor on the store (every store call is `await`ed), so the only audio-relevant claim left for the host check is the one that cannot be tested headlessly: that nothing in the apply path stalls the render thread, which by design it does not touch.

## Root cause

The #0033 index and #0034 thumbnails had no consumer: nothing listed, searched, filtered or applied skins from the library, and the menu had no way to step through it.

## Fix

Followed the plan: new `SkinBrowser` target (`SkinBrowserModel`, `SkinIndexReading`, `SkinThumbnailProviding`, `SkinBrowserFormat`), `SkinQuery` plus five store methods in `SkinLibrary`, SwiftUI views and `SkinsCommands` in `App/SkinBrowser/`, a `Window("Skins", id: "skins")` scene (⌘K), and `PlayerModel` wiring (lazy `skinBrowser`, `skinLoadGeneration`, `skinDidLoad`, `passFinished` hook). Applying calls `loadSkin(from:)` only; no AudioCore/AVFoundation import in either new module.

Adaptations and divergences:
- No `RendererThumbnailProvider` and no model-side LRU/`ThumbnailCache`: #0034's `SkinThumbnailCache` already has the memory LRU, in-flight de-duplication and disk cache, so `SkinThumbnailAdapter` just wraps `thumbnail(hash:url:)` (failed rows return nil without a request). The #0034 note about a re-requested queued hash not moving to the front was not addressed (not cheap; the cell's `.task` only requests once per appearance).
- The plan's `ThumbnailCache` tests were replaced by `thumbnailsAskTheProviderWithTheFolderRelativeURL`.
- Store query tests live in `SkinLibraryTests` (`SkinQueryTests`, `SkinSearchBudgetTests`) where `parsedOutcome`/`TempDir` already exist, not in `SkinBrowserTests`.
- The VM's first run showed the unfiltered listing at offset 50,000 at about 217 ms: with a `status IN` filter SQLite chose the status index and sorted 100k rows. The no-text path now uses `INDEXED BY skins_name` and drops the filter when every status is selected (about 1 ms). Broad FTS matches (more than 2,000 hits, probed with a bounded `LIMIT` count) list by name instead of bm25, and `count(matching:)` with all statuses counts on the FTS table alone.
- `canNavigate` needs counts with the window closed: `indexDidChange()` (fired by `passFinished`) opens the index and refreshes counts even if the window never appeared; it reloads the listing only if one was shown.
- Next/Previous/Random are serialized through a task chain so rapid presses read the latest `currentSkinID`; `skinDidLoad` is ignored if a newer `apply` happened meanwhile.
- The menu's navigation buttons live in a small `SkinsNavigationButtons` view (the plan's fallback) so `canNavigate` is observed. `⌘K` is on both the menu item and the scene; not exercised (no UI test).
- `SkinThumbnailView` (#0034) is still unreferenced; the grid cell does its own `.task` through `skinBrowser.thumbnail(for:)`.
