# 0229 — The playlist editor's right-click menu has no Load Playlist or Clear Playlist

| | |
|---|---|
| **Status** | open |
| **Module** | App |
| **Platform** | macOS |
| **First seen** | 2026-10-27 |

## Description

Right-clicking a row of the playlist editor offers Play, Queue/Dequeue, Clear Queue, Remove and File Info… (`PlaylistContextMenus.rowMenu`). Changing to another playlist needs LIST › Load, and emptying the list needs REM › Remove All or LIST › New List: both behind skinned buttons a skin can leave unlabelled ([#0226](0226.md), user report 2026-10-27).

## Expected

The right-click menu, on a row or on the empty area below the rows, also offers **Load Playlist…** (the same action as LIST › Load: the Library playlist picker on a Music Assistant queue, the file panel on the local queue) and **Clear Playlist** (Remove All). Enabled as the skinned items are.

## Plan

**Blocked by #0226.** The two items come from #0226's `PlaylistMenu` model (`PlaylistMenu.item(.loadPlaylist, state)`, `.clearPlaylist`), built by its `PlaylistMenuBuilder` and run through `PlayerModel.perform(_:)`, so the right-click menu, the menu bar's Playlist menu and the skinned LIST/REM entries share titles, actions and enabled state. Doing it before #0226 would mean a second copy of the enabled rules.

### Menus

- SkinKit `PlaylistMenu.contextEntries(_ state:) -> [PlaylistMenuEntry]`: `[.item(loadPlaylist), .item(clearPlaylist)]`. Titles **Load Playlist…** and **Clear Playlist**, enabled as in #0226 (Load: `QueueSaveTarget.loadChoices` non-empty; Clear: the list has rows), with #0226's ⌥⌘L shown beside Load (display only in a pop-up).
- `PlaylistContextMenus.rowMenu(_:)`: after File Info…, a separator and the builder's `contextEntries` items. Result: Play, Queue/Dequeue, [Clear Queue], —, Remove, File Info…, —, Load Playlist…, Clear Playlist. ("Clear Queue" there is the play-next queue, #0179; "Clear Playlist" empties the list. The two names stay apart on purpose.)
- `PlaylistContextMenus.emptyAreaMenu(_:) -> NSMenu` (new): just `contextEntries`.
- Load Playlist… is LIST › Load (`loadList()`): the Library playlist picker on a Music Assistant queue, the file panel on the local queue, or the Library Playlist… / Playlist File… chooser at the pointer when the local queue has both (it pops on the next main-actor turn, after the context menu has closed). Clear Playlist is `playlist.removeAll()` (a Music Assistant queue gets `clear`, #0145). No confirmation, as in Winamp.

### Empty area

`PlaylistListInputView.rightMouseDown`: today a right-click below the last row returns without a menu. Now: below the last row (including an empty list), `playlist.selectNone()` (what a left-click there does, the list's `onClick={selectZero}`) and `NSMenu.popUpContextMenu(PlaylistContextMenus.emptyAreaMenu(model), with: event, for: self)`. On a row, unchanged (select the row if needed, `rowMenu`). Control-click stays a command-click (`mouseDown`).

The empty area is inside `layout.trackArea` (the AppKit view covers the whole list area), so no other view needs a menu.

### Docs

- `website/help.html`, Playlists: in "Put a playlist in the editor", add "or right-click the list › Load Playlist…"; a short item "**Empty the editor.** Right-click the list › Clear Playlist (or REM › Remove All, LIST › New List, Playlist › Clear Playlist)."
- `docs/design/test-automation.md` §5.5: the "Right-click row menu" row becomes "Right-click menu on a row: Play, Queue/Dequeue, Clear Queue, Remove, File Info…, Load Playlist…, Clear Playlist; below the rows: Load Playlist…, Clear Playlist (#0229)" → UI `PlaylistUITests.testRowMenu`, `.testRowMenuLoadsAndClears`, `.testEmptyAreaRightClickMenu`; Unit `RoadieTests.PlaylistMenusTests`, SkinKit `PlaylistMenuTests.contextEntriesAreLoadAndClear`.

## By hand

2. Right-click below the last row → only Load Playlist… and Clear Playlist; Clear Playlist empties the list; right-click the empty list → Clear Playlist is greyed.
