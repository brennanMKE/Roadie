# 0249 — Jump to File's result rows are invisible to VoiceOver

| | |
|---|---|
| **Status** | open |
| **Module** | App |
| **Platform** | macOS |
| **First seen** | 2026-10-29 |

## Description

Found while writing #0204's UI tests (run 20261029-200200-41710). The Jump to File panel draws its result rows, but the accessibility tree shows `jump.table` (430×272) with no children: the `jump.row.N` row views are not exposed. XCUITest can't see them, and VoiceOver very likely can't either, so a VoiceOver user can type a query but can't hear or pick a result.

#0204 works around it by reading the panel's rows from the Debug-only probe (`JumpToFilePanel.probe`), so its tests don't prove the rows are accessible.

## Expected

Each result row is an accessibility row (or cell) with the track's title as its label, selection reported, and Return/double-click reachable through VoiceOver's default action, like the playlist editor's rows (`pl.row.N`).

## Plan

To be planned. Start from `App/JumpToFile/JumpToFilePanel.swift` and how its table hosts the row views; once fixed, switch #0204's row assertions from the probe to the accessibility tree (keep the probe for selection if needed).
