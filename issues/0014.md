## Description

Implement the plex.tv PIN sign-in flow and read server connections (including `plex.direct` HTTPS URIs) from `/api/v2/resources`.

## Acceptance criteria

- PIN create → open browser → poll until `authToken`; cancellable with a timeout.
- Server picker lists the account's servers; prefers a local `plex.direct` HTTPS connection.
- Flow verified against the real account; `docs/plex-music-library.md` updated (it is currently marked untested).

## Plan

### Scope and decisions

This issue adds the plex.tv side of PlexKit: a `PlexAccountClient` for `plex.tv` (create a PIN, poll it, list the account's servers), a `PlexPinSignIn` loop that opens the browser and waits for the token, a `PlexServerResolver` that turns a server's connection list into one reachable address, the new models (`PlexPin`, `PlexResource`), and the Settings › Plex additions that drive them: a **Sign in with Plex…** button, a **Choose Server…** button and a server list. The paste-token field, Forget, Test Connection and the library picker from #0011 stay exactly as they are; the PIN flow ends in the same `PlexTokenStore` and the same `testConnection()`. No browser window (#0016), no UI tests, no per-server tokens (see risks), no change to `TrackCache` (#0013's `settingsClientProvider` reads the store, so a token from the PIN flow is picked up on the next download).

- **The token from plex.tv goes straight into the store and nowhere else.** `PlexPin` decodes `authToken` directly into a `PlexToken` (custom `init(from:)`); it is `Decodable` only, never `Encodable`, prints as `PlexPin(claimed: true)` and has an empty mirror. On success the model calls `tokenStore.save(token)` and sets the same state a committed paste would (`enteredToken`, `tokenDirty = false`, `hasStoredToken = true`), so the Token field shows dots and Forget/Test behave as before. The token is never logged, never a query item, never in `UserDefaults`, never in an error, and never rendered except as the `SecureField`'s dots. `PlexClient.fetch` already logs only the request *path* (not the query), so the PIN code in the poll query (section 2) is not logged either.
- **The auth URL carries no token, and the tests pin down exactly what it carries.** `https://app.plex.tv/auth#?clientID=<X-Plex-Client-Identifier>&code=<pin code>&context[device][product]=SkinAmp`, built with `URLComponents` (`percentEncodedFragment`). There is no token to carry at that point: the token only exists in the poll response after the user has signed in. The URL is handed to an opener closure (`NSWorkspace.shared.open` in the app, a counter in tests); the model logs "auth URL opened" without the URL, because the code is a one-time secret while the PIN is unclaimed.
- **plex.tv is reused through `PlexClient`, not a second HTTP stack.** `PlexClient.request(path:query:page:)` gains a `method:` parameter (default `"GET"`, so no caller changes) and `PlexAccountClient` wraps a `PlexClient(baseURL: https://plex.tv, token: …)`, so every plex.tv request carries the same `Accept: application/json`, `X-Plex-Client-Identifier`, `X-Plex-Product`, `X-Plex-Version` and `X-Plex-Platform` headers, and the same error mapping and token rules (#0009) apply. The internal `fetch<T>` is reachable from the same module. Both hosts are `https`, so no ATS change: `project.yml`, `App/Info.plist` and `scripts/check-info-plist.sh` are untouched, and the check still asserts there is no `NSExceptionDomains`.
- **Polling: every 2 s, until claimed, cancelled, expired or timed out.** Plex PINs live about 30 minutes (`expiresIn`); the app stops earlier, after `PlexPinSignIn.Options.timeout` (default 10 minutes), because a Settings window should not poll plex.tv for half an hour. A 404 on the poll means the PIN expired or was never created (`.expired`); up to `maxConsecutiveFailures` (5) transport or 5xx errors in a row are retried on the next tick, so a Wi-Fi hiccup does not abort a sign-in. Cancellation is Swift task cancellation (`Task.sleep` and `URLSession` both honour it) and maps to `.cancelled`, which the model turns back into `.idle`, like the connection test. Cancel, Forget, editing the token field and closing Settings all cancel an in-flight sign-in.
- **Server choice is a probe, not a guess.** `/api/v2/resources?includeHttps=1&includeRelay=1` lists every server with its connections. `PlexResource.rankedConnections` orders them: local `https` non-relay first (the `plex.direct` LAN URI the acceptance criteria ask for), then remote `https` non-relay, then relay, then plain `http`; IPv4 before IPv6 within a tier. `PlexServerResolver` probes the ranked list in parallel with `GET /identity` (no token, 5 s timeout) and keeps the best-ranked one whose `machineIdentifier` equals the resource's `clientIdentifier`. If nothing answers (a router blocking `plex.direct` names, or the user on Tailscale where the LAN IP is unreachable) the **current address is kept** and a message says so, rather than overwriting an address that works. A chosen URI goes into `address` as text; `PlexAddress.normalize` passes an `https://…:32400` URI through unchanged (tested in #0010), and the ordinary connection test runs.
- **One token per app, as #0011 decided.** `/resources` also returns a per-server `accessToken`. It is **not decoded** (no `CodingKeys` case, like `Part.file`), the hand-written fixture does not contain it, and a test checks both. The account token works for every server the account owns (joe); a server merely *shared* with the account may need its own token, which is out of scope and listed in the risks. Shared servers are still listed, after the owned ones, so the user sees them; if the account token is refused the existing "Signed in, but this account can't access this server." message appears.
- **Tests are stubbed, silent, token-free.** Every plex.tv response in the tests comes from `StubURLProtocol` with **hand-written** fixtures under `Fixtures/plextv/`: a PIN with `authToken: null`, the same PIN claimed with `"authToken": "tok-FIXTURE-PIN-0014"`, and a resources list with placeholder hashes, private-range IPs, fake public IP and no `accessToken`. Nothing is recorded from the real account (a recorded PIN response *is* a token, and a recorded resources response carries the account's device names, public IP and per-server tokens). The recorder's "token-like field" check is told to skip that folder. The guest never has `PLEX_TOKEN`, never opens a browser (the opener is a closure) and never touches the Keychain (`InMemoryPlexTokenStore`). The real flow can only be run by the user, by hand, on the host (section 10).

### 2. `PlexAccountClient` and the models (`Sources/PlexKit/PlexAccountClient.swift`, `Models/PlexPin.swift`, `Models/PlexResource.swift`)

```swift
/// plex.tv: PIN sign-in and the account's servers. Every request goes through `PlexClient`, so the
/// headers, the error mapping and the token rules are the ones the server client has.
public struct PlexAccountClient: Sendable {
    public static let defaultBaseURL = URL(string: "https://plex.tv")!
    public static let defaultAuthURL = URL(string: "https://app.plex.tv/auth")!

    public var clientIdentifier: String
    public var product: String
    public var version: String
    public var baseURL: URL             // tests: https://stub.plex.tv (the stub matches on path)
    public var authBaseURL: URL
    public var timeout: TimeInterval
    public var session: URLSession

    public init(clientIdentifier: String, product: String = "SkinAmp", version: String = "0.1.0",
                baseURL: URL = defaultBaseURL, authBaseURL: URL = defaultAuthURL,
                timeout: TimeInterval = 15, session: URLSession = .shared)

    /// POST /api/v2/pins?strong=true — no token. A strong PIN has a 24-character code.
    public func createPin() async throws -> PlexPin
    /// GET /api/v2/pins/<id>?code=<code> — no token; `authToken` is set once the user has signed in.
    public func pin(_ pin: PlexPin) async throws -> PlexPin
    /// https://app.plex.tv/auth#?clientID=…&code=…&context[device][product]=… — never a token.
    public func authURL(for pin: PlexPin) -> URL
    /// GET /api/v2/resources?includeHttps=1&includeRelay=1 — token in the header. Servers only, owned first.
    public func resources(token: PlexToken) async throws -> [PlexResource]
}
```

`createPin` and `pin(_:)` use `PlexClient(baseURL:, token: nil, …)`; `resources(token:)` uses one with the token. `authURL(for:)` builds `URLComponents(url: authBaseURL)` and sets `percentEncodedFragment` to `"?" + ["clientID": clientIdentifier, "code": pin.code, "context[device][product]": product]` joined with the strict encoder `PlexClient.request` already uses (brackets become `%5B`/`%5D`, which Plex Web decodes). No `forwardUrl` (the app has no URL scheme), no `X-Plex-Token`, no pin id.

```swift
/// A plex.tv PIN. `Decodable` only: it can carry the token, so it must never be encoded,
/// printed or reflected. Not `Codable`, not `Encodable`.
public struct PlexPin: Hashable, Sendable, Decodable, CustomStringConvertible, CustomDebugStringConvertible, CustomReflectable {
    public var id: Int
    public var code: String
    public var expiresIn: Int?                  // seconds, from plex.tv (about 1800)
    public var expiresAt: String?               // ISO 8601 text, kept as text; the deadline uses `expiresIn` and the local clock
    public var authToken: PlexToken?            // decoded from a String by a custom init(from:); nil until claimed
    public var isClaimed: Bool { authToken != nil }
    public var description: String { "PlexPin(claimed: \(isClaimed))" }
    public var debugDescription: String { description }
    public var customMirror: Mirror { Mirror(self, children: []) }
}
```

```swift
public struct PlexResourceConnection: Codable, Hashable, Sendable {
    public var `protocol`: String               // "https" | "http"
    public var address: String                  // "10-0-0-5.<hash>.plex.direct" or an IP
    public var port: Int
    public var uri: String                      // "https://10-0-0-5.<hash>.plex.direct:32400"
    public var local: Bool
    public var relay: Bool
    public var ipv6: Bool                       // CodingKey "IPv6"
    public var isHTTPS: Bool { `protocol` == "https" }
    public var isPlexDirect: Bool { address.hasSuffix(".plex.direct") }
    public var url: URL? { URL(string: uri) }
}

/// One entry of /api/v2/resources. `Decodable` only; `accessToken` is deliberately not decoded.
public struct PlexResource: Decodable, Hashable, Sendable, Identifiable {
    public var name: String
    public var clientIdentifier: String         // == /identity's machineIdentifier
    public var provides: String                 // "server", "server,client", "client", …
    public var owned: Bool
    public var presence: Bool?
    public var productVersion: String?
    public var platform: String?
    public var httpsRequired: Bool?
    public var connections: [PlexResourceConnection]   // default [] when absent

    public var id: String { clientIdentifier }
    public var isServer: Bool { provides.split(separator: ",").contains("server") }
    /// Local https non-relay, remote https non-relay, relay, http; IPv4 before IPv6; Plex's order within a tier.
    public var rankedConnections: [PlexResourceConnection]
    public var preferredConnection: PlexResourceConnection? { rankedConnections.first }
}
```

`resources(token:)` returns `isServer` entries only, sorted owned-first then by `name` (case-insensitive); everything else about the list is the caller's. The JSON is a top-level array; `fetch<[PlexResource]>` handles it without an envelope. Field names follow Plex's documented response; as in #0009, the implementer treats the hand-written fixture as the shape and keeps every field that Plex does not always send optional (`connections` defaults to `[]`).

### 3. `PlexPinSignIn` (`Sources/PlexKit/PlexPinSignIn.swift`)

```swift
public enum PlexSignInFailure: Error, Hashable, Sendable, LocalizedError {
    case unreachable(PlexError)     // plex.tv did not answer the PIN request, or kept failing while polling
    case couldNotOpenBrowser        // the opener returned false
    case expired                    // the PIN was gone before it was claimed (404 while polling, or past expiresIn)
    case timedOut                   // Options.timeout passed
    case cancelled                  // the task was cancelled; the UI shows nothing for it

    /// The user-facing text; the one place these strings live (the doc table in section 7).
    public var message: String {
        switch self {
        case .unreachable: "Can't reach plex.tv. Check your internet connection and try again."
        case .couldNotOpenBrowser: "Couldn't open your browser. Paste a token instead."
        case .expired: "The sign-in code expired before it was used. Try again."
        case .timedOut: "Sign-in took too long. Try again."
        case .cancelled: "Sign-in was cancelled."
        }
    }
    public var errorDescription: String? { message }
    public var underlying: PlexError? { … .unreachable's error … }
}

public struct PlexPinSignIn: Sendable {
    public struct Options: Hashable, Sendable {
        public var pollInterval: Duration = .seconds(2)
        public var timeout: Duration = .seconds(600)
        public var maxConsecutiveFailures: Int = 5
        public init(…)
    }
    /// Returns false when the URL could not be opened. Called on the main actor.
    public typealias URLOpener = @MainActor @Sendable (URL) -> Bool

    public var account: PlexAccountClient
    public var options: Options
    public init(account: PlexAccountClient, options: Options = Options())

    /// Create a PIN, open the browser, poll until the PIN is claimed. Cancel the task to stop.
    public func run(open: URLOpener) async throws(PlexSignInFailure) -> PlexToken
}
```

`run`:

1. `try Task.checkCancellation()`; `createPin()`. Any `PlexError` → `.unreachable(error)`; `CancellationError` or `.transport(.cancelled)` → `.cancelled` (the same `failure(_:)` helper shape as `PlexConnectionTest`).
2. `deadline = now + min(options.timeout, .seconds(pin.expiresIn ?? 1800))`. `guard await open(account.authURL(for: pin)) else { throw .couldNotOpenBrowser }`.
3. Loop: `try await Task.sleep(for: options.pollInterval)` (→ `.cancelled` on cancellation); if `now >= deadline` → `.timedOut` when the app's timeout was the smaller bound, else `.expired`; `account.pin(pin)`: `.notFound` → `.expired`; any other `PlexError` increments a failure counter and throws `.unreachable(error)` once it reaches `maxConsecutiveFailures`, otherwise continues; a successful answer resets the counter; `authToken != nil` → return it.
4. Logging (`category: "PlexSignIn"`): `info` lines "pin created", "auth URL opened", "poll: waiting" (at `debug`), and the outcome case name. Never the pin id, the code, the URL or the token.

The returned `PlexToken` is the only value that leaves the loop; the `PlexPin` with the token inside is a local.

### 4. `PlexServerResolver` (`Sources/PlexKit/PlexServerResolver.swift`)

```swift
/// Finds the connection of a server that actually answers from here.
public struct PlexServerResolver: Sendable {
    public var clientIdentifier: String
    public var product: String
    public var version: String
    public var timeout: TimeInterval            // per probe, default 5
    public var session: URLSession
    public init(clientIdentifier: String, product: String = "SkinAmp", version: String = "0.1.0",
                timeout: TimeInterval = 5, session: URLSession = .shared)

    /// Probes `resource.rankedConnections` in parallel with GET /identity (no token). Returns the
    /// best-ranked connection whose machineIdentifier equals `resource.clientIdentifier`, or nil.
    public func reachableConnection(of resource: PlexResource) async -> PlexResourceConnection?
}
```

`withTaskGroup` over the ranked connections (index, connection): each child builds `PlexClient(baseURL: connection.url, token: nil, timeout: timeout, session: session)`, calls `identity()`, and yields `(index, ok)`; the parent collects the successes and returns the lowest index. Cancellation of the caller cancels the group. A connection whose `uri` is not a URL is skipped. No logging of addresses beyond the case ("resolved tier N" / "none reachable").

```swift
public enum SignInStatus: Hashable, Sendable { case idle, waitingForBrowser, signedIn, failed(PlexSignInFailure) }
public private(set) var signInStatus: SignInStatus = .idle
public var isSigningIn: Bool { signInStatus == .waitingForBrowser }
public var canSignIn: Bool            // account != nil && !isSigningIn && tokenStoreError == nil
public var signInMessage: String?     // .failed → failure.message; .signedIn → "Signed in with Plex."; else nil
public var signInDetail: String?      // .failed(.unreachable(e)) → e.errorDescription

public private(set) var servers: [PlexResource] = []
public private(set) var isLoadingServers = false
public private(set) var serversMessage: String?   // "no servers", "couldn't reach", "sign in again"
public var canChooseServer: Bool      // account != nil && hasStoredToken && !isLoadingServers && !isSigningIn
public func serverLabel(_ resource: PlexResource) -> String   // "<name> · <preferred host or 'no address'>" plus "(shared)" when !owned

public func signIn()                  // cancelSignIn(); signInStatus = .waitingForBrowser; start the task
public func cancelSignIn()            // cancels; .waitingForBrowser → .idle
public func loadServers()             // resources(token:) → servers; errors → serversMessage
public func useServer(_ resource: PlexResource)   // probe; set address or keep it; testConnection()
public func waitForSignIn() async     // awaits the sign-in task, for tests
public func waitForServers() async    // awaits the resources/probe task, for tests
```

Rules:

- **`signIn()`**: requires `account`; `cancelTest()`; the token the loop will replace is left untouched in the store until success. The task runs `PlexPinSignIn(account:options:).run(open: openURL)`; on return, `guard !Task.isCancelled`. Success → `storeSignedInToken(token)`: `tokenStore.save(token)`; on success `enteredToken = token.rawValue` (the second and last place the model reads `rawValue`, after `load()`), `tokenDirty = false`, `hasStoredToken = true`, `tokenStoreError = nil`, `signInStatus = .signedIn`, `servers = []`; on a store failure keep the token in `enteredToken` with `tokenDirty = true` (so Test works this session and the next commit retries), set `tokenStoreError`, and still `.signedIn`. Then: if the trimmed address is non-empty → `testConnection()`; else → `loadServers()`, and when exactly one server comes back, `useServer` it (so a first-run user signs in once and is connected). Failure `.cancelled` → `.idle`; other failures → `.failed(f)`; nothing in the store or the field changes on failure.
- **`cancelSignIn()`** is called by `cancelTest()`'s siblings: `invalidate()` (address or token edits), `forgetToken()`, `disappeared()`. Address edits also clear `servers` only when the user picks a server (not on every keystroke).
- **`loadServers()`**: the token is the trimmed field value if non-empty, else `tokenStore.load()`; none → return. `.unauthorized` from plex.tv → `serversMessage = "plex.tv no longer accepts this token. Sign in again."`; empty list → "Your Plex account has no servers. Type an address instead."; other errors → `PlexError.errorDescription`.
- **`useServer(_:)`**: `isLoadingServers = true`; `serverResolver.reachableConnection(of:)`; found → `address = connection.uri` (through the normal setter, so it is persisted and the test state is invalidated), `serversMessage = nil`, `testConnection()`; nil → `serversMessage = "Couldn't reach \(name) at any of its addresses. The current address was kept."`, address untouched.
- **Printing/logging**: `customMirror` stays empty; the `PlexSettings` logger gets case names only ("sign-in: signedIn", "servers: 2", "server: resolved"/"unreachable"). No name, host, URL or token.
- **`forgetToken()`** also clears `servers`, `serversMessage` and sets `signInStatus = .idle`.

### 12. Risks

- **The plex.tv shapes are from Plex's documentation and other clients, not from a recording.** Field names (`id`, `code`, `expiresIn`, `authToken`; `clientIdentifier`, `provides`, `owned`, `connections[].uri/local/relay/IPv6`), the `strong=true` parameter, the 24-character code, the `code=` query on the poll, the `201` on create and the `404` on an expired PIN are all as documented, but nothing here can be checked in the guest. The implementer keeps every optional field optional and the user's step 1–3 are the real test. If a field turns out to be named differently, it is a `CodingKeys` change plus the fixture.
- **`plex.tv` versus `clients.plex.tv` for `/resources`.** The doc names `clients.plex.tv`; current clients use `plex.tv/api/v2/resources` and both resolve to the same service. The base URL is one property; step 7 says what to do if the guess is wrong.
- **Polling rate.** 2 s is what Plex's own guidance uses; a `429` would arrive as `.httpStatus(429)` and is treated as a transient failure (retried up to 5 times, i.e. 10 s), after which the user sees "Can't reach plex.tv". If 429 shows up in step 1, lengthen `pollInterval` to 3 s; the option is one value.
- **Bracket encoding in the fragment.** `context%5Bdevice%5D%5Bproduct%5D` is what `URLComponents` produces; Plex Web decodes it. If the auth page shows a blank product name in step 1, switch `authURL(for:)` to a literal `[`/`]` in `percentEncodedFragment` (they are legal in a fragment) and keep test 4, which decodes either form.
- **The PIN code is a one-time secret while unclaimed.** Anyone with the code and the (non-secret) client identifier could claim the PIN with *their* account, giving the app their token, not the user's. The URL is handed to the system browser and not logged; that is the same exposure every Plex client has. The pin *id* with the identifier would let a third party poll the token after it is claimed, which is why the id is never logged either and the `PlexPin` value never leaves the loop.
- **`plex.direct` names and DNS rebinding protection.** `10-0-0-5.<hash>.plex.direct` resolves to a private IP; some routers (and Pi-hole-style resolvers) refuse such answers. The probe then fails for the local connection and the remote or relay one wins, or the address is kept. Step 3 records the outcome; the doc gains a sentence if it bites.
- **Local plex.direct over Tailscale.** The LAN IP in the name is not routable from the tailnet unless the Mac mini advertises a subnet route, so away from home the picker falls through to remote/relay. `joe` over plain `http` stays the simplest address for the tailnet case; the picker never deletes it.
- **Shared servers and `accessToken`.** A server shared with the account may reject the account token and want the per-resource `accessToken` from `/resources`. Supporting that means one token per server in the Keychain and a different store shape; not in this issue. The shared row is still listed so the user understands why "can't access this server" appears; a follow-up issue can add per-server tokens if anyone needs them.
- **Revoked tokens.** plex.tv tokens do not expire, but the user can remove "SkinAmp" from the devices page; the next request gets `401`, the connection test says "Signed in, but this account can't access this server." and `loadServers()` says "Sign in again." No automatic re-sign-in: the user clicks the button.
- **`hasStoredToken` and the dots.** The sign-in path fills `enteredToken` so the field shows dots and Forget/Test work, exactly as a paste does; the token is in memory in the model either way, and `customMirror` keeps it out of `dump`. The `SecureField` never reveals it.
- **`NSWorkspace.open` on the main actor.** The opener is typed `@MainActor @Sendable (URL) -> Bool` and awaited from the loop's task, so the AppKit call runs where it belongs. `open` returning `false` (no default browser) is a real, if rare, failure with its own message.
- **Closing Settings cancels the sign-in.** Deliberate: a window the user cannot see should not keep polling plex.tv. The cost is a second click if they close it by accident; the status line tells them. If this annoys in practice, the task could move to the app's lifetime; the loop and the model API would not change.
- **Keychain prompt during sign-in.** The store write happens on the main actor as in #0011; with ad-hoc signing the dialog may appear once after a rebuild, during step 1. Deny → `tokenStoreError` is shown, the token stays in the field (dirty) and the next Test or Return retries the write. Nothing is lost.
- **`PlexClient.request` signature.** Adding a defaulted first parameter is source-compatible; `TrackCache`'s `client.request(path: partKey)` compiles unchanged. A grep for `request(path:` in the review confirms no call was broken.
- **Stub `host` matching.** Routes without a `host` keep matching any host, so every existing test is unaffected; only the resolver tests set one. The probe's parallel task group makes the resolver tests timing-independent (every route answers or errors at once; no delays).
