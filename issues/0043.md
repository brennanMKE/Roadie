# 0043 — Finder shows no thumbnail or Quick Look preview for .wsz skins

| | |
|---|---|
| **Status** | open |
| **Module** | QuickLook / SkinKit / App |
| **Platform** | macOS |
| **First seen** | 2026-10-12 |

## Description

`.wsz` files show a generic zip icon in Finder, and pressing Space shows nothing useful. Add Quick Look extensions, built as new targets embedded in SkinAmp, that render the skin's main window as the Finder thumbnail and as the Quick Look preview.

## Acceptance criteria

- `project.yml` exports a declared UTType for `.wsz` (for example `com.brennanmke.skinamp.wsz`, conforming to `public.zip-archive`, extension `wsz`) in the app's Info.plist. `App/PlayerView.swift` uses that declared type instead of the dynamic `UTType(filenameExtension:conformingTo:)`.
- A new **thumbnail extension** target (`QLThumbnailProvider`) renders the main window to fit the requested size, and is used for Finder icons and gallery view.
- A new **preview extension** target (`QLPreviewingController`, or the data-based `QLPreviewProvider`) shows the main window at 2×, with the skin name. Optionally it also shows the EQ and playlist windows and the readme text.
- Both extensions are sandboxed (Quick Look requires it), read only the file Quick Look hands them, and are embedded in SkinAmp by `xcodegen generate`.
- Rendering uses a shared offscreen renderer in SkinKit, the same one `skintool --png` (#0026) and library thumbnails (#0034) use, not a copy.
- A broken or modern (`.wal`) skin gives a clear fallback (the generic icon, or a "can't preview" message), never a crash.
- Verified with `qlmanage -r`, then `qlmanage -t -s 512 <skin>.wsz` and `qlmanage -p <skin>.wsz`, against the sample skins in `Skins/`.

## Plan

### Decisions

- **#0026 has not landed and has no plan, so this issue builds the offscreen renderer** (`SkinRenderer` in SkinKit) and adds `skintool --png <outdir>` while it is at it, because that flag is the only way to check the renderer headlessly without Finder. #0026 then shrinks to the Webamp comparison document plus any fidelity fixes, and #0034 calls the same `SkinRenderer.mainWindowImage(for:scale:)` for library thumbnails. Say so in `## Fix` and in a one-line note on #0026 when this lands.
- **Preview is data-based** (`QLPreviewProvider` returning HTML with `cid:` PNG attachments), not view-based. Reasons: no AppKit or main-thread work in the extension, so it is trivially Swift 6 clean; the page builder is a pure function that lives in SkinKit and is covered by `swift test`; HTML gives us the skin name, warnings and readme for free, where a `QLPreviewReply(dataOfContentType: .png …)` could show only the picture; and `QLPreviewingController`-with-`NSViewController` needs a xib/`loadView`, runs on the main thread, and cannot be unit-tested without the VM.
- **Pixel art stays pixel art.** The renderer only draws at integer scales with `interpolationQuality = .none`. The thumbnail picks the largest integer scale that fits the request in device pixels and only falls back to smooth downscaling when even 1× does not fit (Finder's 16–64 pt icons).
- `Info.plist` content is expressed with XcodeGen `info: properties:` (arrays and dictionaries are impossible through `INFOPLIST_KEY_*`). `GENERATE_INFOPLIST_FILE: YES` stays on every target; Xcode merges the generated keys into the file XcodeGen writes. The generated `Info.plist` and `.entitlements` files are committed (deterministic output of `xcodegen generate`; never hand-edit them).
- Untrusted input: `SkinArchive` gains byte caps and an extension allow-list (see step 3). Everything else already never traps.

### Step 2 — Shared offscreen renderer in SkinKit

New folder `Packages/SkinKit/Sources/SkinKit/Render/` (CoreGraphics + ImageIO only; no AppKit, so it links into the sandboxed extensions and `skintool`).

`SkinRenderer.swift`:

```swift
public enum SkinRenderer {
    public static let mainWindowSize = CGSize(width: 275, height: 116)

    /// Composites the idle main window at an integer `scale` (1 → 275×116 px, 2 → 550×232 px)
    /// with nearest-neighbour sampling. Never throws: a missing sprite is skipped and a missing
    /// MAIN sheet leaves the dark fill, so a partial skin still produces a picture.
    public static func mainWindowImage(for skin: Skin, scale: Int = 1) -> CGImage?

    /// PNG encoding through ImageIO (CGImageDestination, UTType.png).
    public static func pngData(_ image: CGImage) -> Data?
}
```

Implementation: `CGContext(data: nil, width: 275*scale, height: 116*scale, bitsPerComponent: 8, bytesPerRow: 0, space: CGColorSpaceCreateDeviceRGB(), bitmapInfo: CGImageAlphaInfo.premultipliedFirst.rawValue | CGBitmapInfo.byteOrder32Little.rawValue)`; `interpolationQuality = .none`; fill with `CGColor(gray: 0.1, alpha: 1)`; `scaleBy(x: scale, y: scale)`; then draw each layout item at `CGRect(x: x, y: 116 - y - h, width: w, height: h)` (Core Graphics origin is bottom-left). `scale < 1` returns nil. Return `context.makeImage()`.

`MainWindowLayout.swift` (internal): the idle composition, in skin pixels, positions from Webamp's `main-window.css` (the same numbers `MainWindowView` already uses for the transport row). An item is a sprite name or, for the two slider backgrounds, a sheet name plus a frame rect:

| Item | Source | x | y |
|---|---|---|---|
| background | `MAIN_WINDOW_BACKGROUND` | 0 | 0 |
| title bar | `MAIN_TITLE_BAR_SELECTED` | 0 | 0 |
| clutter bar | `MAIN_CLUTTER_BAR_BACKGROUND` | 10 | 22 |
| play indicator | `MAIN_STOPPED_INDICATOR` | 26 | 28 |
| mono / stereo | `MAIN_MONO`, `MAIN_STEREO` | 212, 239 | 41 |
| volume background | sheet `VOLUME` rect (0, 405, 68, 13) — frame 27 of 28 (full volume) | 107 | 57 |
| volume thumb | `MAIN_VOLUME_THUMB` | 161 | 58 |
| balance background | sheet `BALANCE` rect (9, 0, 38, 13) — frame 0 (centred) | 177 | 57 |
| balance thumb | `MAIN_BALANCE_THUMB` | 189 | 58 |
| EQ / PL toggles | `MAIN_EQ_BUTTON`, `MAIN_PLAYLIST_BUTTON` | 219, 242 | 58 |
| position bar | `MAIN_POSITION_SLIDER_BACKGROUND` | 16 | 72 |
| transport | `MAIN_PREVIOUS_BUTTON`, `MAIN_PLAY_BUTTON`, `MAIN_PAUSE_BUTTON`, `MAIN_STOP_BUTTON`, `MAIN_NEXT_BUTTON` | 16, 39, 62, 85, 108 | 88 |
| eject | `MAIN_EJECT_BUTTON` | 136 | 89 |
| shuffle / repeat | `MAIN_SHUFFLE_BUTTON`, `MAIN_REPEAT_BUTTON` | 164, 210 | 89 |

Draw in that order. No time digits, marquee or visualizer (they need #0021/#0022/#0024); when those land the renderer gets a `MainWindowState` parameter, not a second code path. Sprites come from `skin.image(for:)`; the two frame rects use `skin.sheets[sheet]?.cropping(to:)`.

`SkinPreviewPage.swift` (public, pure, used by the preview extension):

```swift
public struct SkinPreviewPage: Sendable {
    public let title: String                      // skin file name without extension
    public let html: String                       // complete document, UTF-8
    public let attachments: [String: Data]        // "main" → PNG (plus "eq" if rendered)
    /// Parses and renders; on failure returns a "Can't preview" page with the SkinError text. Never throws.
    public static func make(url: URL) -> SkinPreviewPage
}
```

Page content: `<h1>` title; `<img src="cid:main" width="550" height="232" style="image-rendering: pixelated">` where the attachment is rendered at **scale 4** (1100×464 px) so Retina shows it 1:1 and 1× displays downsample exactly 2:1 even if the web view ignores `image-rendering`; a `<ul>` of `skin.warnings` if any; the readme in `<pre>` (first file matching `readme*.txt`/`*.txt` that is not `viscolor`/`pledit`/`region`, decoded as UTF-8 then `.windowsCP1252`, capped at 20 KB); a `prefers-color-scheme: dark` block. Every interpolated string goes through one `htmlEscaped` helper (`& < > "`). Optional, only if the main path is done: an `equalizerWindowImage(for:scale:)` compositing `EQ_WINDOW_BACKGROUND` + `EQ_TITLE_BAR_SELECTED` at (0, 0), attached as `cid:eq`. Parse with `SkinArchive(url:)` then `SkinParser.parse(archive:)` so the readme is reachable from the same archive read.

`skintool --png <outdir>`: `skintool [--png <outdir>] <skin.wsz | folder>` writes `<outdir>/<skin basename>.png` at scale 1 next to the existing report lines; `--scale N` is #0026's to add if it wants it.

### Step 3 — Harden `SkinArchive` for untrusted input

Add `public struct Limits: Sendable { maxEntryBytes = 8 MB; maxTotalBytes = 64 MB; allowedExtensions = ["bmp","png","txt","cur","ini","xml"] }` and `init(url:limits: = .default)`. Skip entries whose extension is not allowed or whose `uncompressedSize` exceeds `maxEntryBytes`; enforce the caps inside ZIPFoundation's consumer closure too (it is `(Data) throws -> Void`, so throw a private error and `continue` when the running total would exceed the cap — the central directory is as untrusted as the data). Stop reading once the total cap is hit. Existing callers are unaffected (`skin.xml` still triggers `.modernSkin`; cursors stay readable for M7).

### Step 5 — Thumbnail provider

```swift
import QuickLookThumbnailing
import SkinKit

final class ThumbnailProvider: QLThumbnailProvider {
    override func provideThumbnail(for request: QLFileThumbnailRequest,
                                   _ handler: @escaping (QLThumbnailReply?, Error?) -> Void) {
        let skin: Skin
        do { skin = try SkinParser.parse(url: request.fileURL) }
        catch { handler(nil, error); return }                 // generic icon, no crash

        let size = SkinRenderer.mainWindowSize
        let fit = min(request.maximumSize.width / size.width, request.maximumSize.height / size.height)
        let pixelScale = Int((fit * request.scale).rounded(.down))   // whole skin pixels per device pixel
        let renderScale = max(pixelScale, 1)
        guard let image = SkinRenderer.mainWindowImage(for: skin, scale: renderScale) else { handler(nil, nil); return }

        // pixelScale ≥ 1: the context is exactly renderScale skin pixels per device pixel → 1:1 blit.
        // pixelScale == 0 (tiny icons): draw the 1× render smoothly into the fitted size.
        var contextSize = pixelScale >= 1
            ? CGSize(width: size.width * CGFloat(pixelScale) / request.scale, height: size.height * CGFloat(pixelScale) / request.scale)
            : CGSize(width: (size.width * fit).rounded(.down), height: (size.height * fit).rounded(.down))
        contextSize.width = max(contextSize.width, request.minimumSize.width)
        contextSize.height = max(contextSize.height, request.minimumSize.height)
        let imageSize = pixelScale >= 1 ? contextSize : CGSize(width: size.width * fit, height: size.height * fit)
        let origin = CGPoint(x: (contextSize.width - imageSize.width) / 2, y: (contextSize.height - imageSize.height) / 2)

        let reply = QLThumbnailReply(contextSize: contextSize) { context in
            context.interpolationQuality = pixelScale >= 1 ? .none : .high
            context.draw(image, in: CGRect(origin: origin, size: imageSize))
            return true
        }
        reply.extensionBadge = "WSZ"
        handler(reply, nil)
    }
}
```

The context is already scaled by `request.scale`, so sizes above are in points. Aspect fit happens through `fit`; the picture is centred if `minimumSize` forces a taller context.

### Step 6 — Preview provider

```swift
import QuickLookUI
import SkinKit
import UniformTypeIdentifiers

final class PreviewProvider: QLPreviewProvider, QLPreviewingController {
    func providePreview(for request: QLFilePreviewRequest) async throws -> QLPreviewReply {
        let url = request.fileURL
        return QLPreviewReply(dataOfContentType: .html, contentSize: CGSize(width: 620, height: 560)) { reply in
            let page = SkinPreviewPage.make(url: url)          // heavy work belongs in this block (Apple's guidance)
            reply.title = page.title
            reply.stringEncoding = .utf8
            reply.attachments = page.attachments.mapValues { QLPreviewReplyAttachment(data: $0, contentType: .png) }
            return Data(page.html.utf8)
        }
    }
}
```

A modern or unreadable skin yields `SkinPreviewPage`'s "Can't preview <name>: <SkinError description>" page (acceptance's "clear fallback"); the thumbnail side returns the error so Finder keeps the generic document icon.

### Step 7 — Concurrency, limits, isolation

- Both targets compile in Swift 6 strict mode (project-level `SWIFT_VERSION`). Nothing in the extensions is `@MainActor`: `provideThumbnail` is called on a background thread and the preview data block runs after `providePreview` returns. `Skin` is `@unchecked Sendable` over immutable `CGImage`s, `SkinPreviewPage` is `Sendable`, and the closures capture only `url`, `image`, value types. If a `SWIFT_DEFAULT_ACTOR_ISOLATION: MainActor` ever lands at project level, give both extension targets `SWIFT_DEFAULT_ACTOR_ISOLATION: nonisolated`.
- Memory and time: Quick Look kills slow or fat providers (budget is tens of MB and a few seconds). One parse decodes ~15 small BMPs (a few MB) and one 275×116×scale draw; step 3's caps keep a hostile archive inside that budget. Do not cache across requests; the process may be reused but must not grow.
- The extensions touch only `request.fileURL`, no `UserDefaults`, no network, no app group.

### Risks

- **Registration, not code, is where this usually fails.** Extensions are discovered only after LaunchServices sees the app bundle (launch, `/Applications`, or `pluginkit -a`); several copies of SkinAmp.app (DerivedData vs `/Applications`) confuse pluginkit — `pluginkit -r <path>` the stale one. Check `log stream --predicate 'subsystem == "com.apple.quicklook"'` while running `qlmanage` if nothing shows.
- **Ad-hoc signing.** The app is signed with `-`; embedded appexes must be signed consistently (XcodeGen's embed phase signs on copy). If Quick Look lists the extensions but never calls them, switch `CODE_SIGN_IDENTITY` on all three targets to `Apple Development` (an identity is present on this Mac) and note it in `## Gotchas`; distribution needs Developer ID + notarization (#mac-release, out of scope).
- **UTI binding.** No other app on this Mac claims `.wsz` today (`lsregister -dump` is empty for it), but on a user's Mac another app's export could win; then `mdls` shows a foreign UTI and our `QLSupportedContentTypes` never matches. Document the `mdls` check.
- **Info.plist merge.** If Xcode's merge of `INFOPLIST_FILE` with `GENERATE_INFOPLIST_FILE` drops a key, the fallback is to move the remaining `INFOPLIST_KEY_*` values into `info: properties:` (`CFBundleDisplayName`, `LSApplicationCategoryType`) — never the other way round.
- **Package in an extension.** `APPLICATION_EXTENSION_API_ONLY` makes Xcode build SkinKit/ZIPFoundation with extension-safe API; both are UI-free so this should be silent. If Xcode complains about the `ZIPFoundation_ZIPFoundation.bundle` resource bundle in the appex, that is only a warning.
- **Scope creep.** Marquee text, digits, EQ/playlist renders and the Webamp comparison belong to #0021/#0022/#0026; the renderer draws the idle composition above and nothing more.

## Notes

- Depends on the offscreen renderer from #0026. The UTType declaration doesn't, and could land earlier on its own.

- Extensions register once the app is in `/Applications` or has been launched. Ad-hoc signing works locally; distribution needs Developer ID signing and notarization.
