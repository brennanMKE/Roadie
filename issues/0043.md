## Description

`.wsz` files show a generic zip icon in Finder, and pressing Space shows nothing useful. Add Quick Look extensions, built as new targets embedded in SkinAmp, that render the skin's main window as the Finder thumbnail and as the Quick Look preview.

## Acceptance criteria

- `project.yml` exports a declared UTType for `.wsz` (for example `com.brennanmke.skinamp.wsz`, conforming to `public.zip-archive`, extension `wsz`) in the app's Info.plist. `App/PlayerView.swift` uses that declared type instead of the dynamic `UTType(filenameExtension:conformingTo:)`.
- A new **thumbnail extension** target (`QLThumbnailProvider`) renders the main window to fit the requested size, and is used for Finder icons and gallery view.
- A new **preview extension** target (`QLPreviewingController`, or the data-based `QLPreviewProvider`) shows the main window at 2×, with the skin name. Optionally it also shows the EQ and playlist windows and the readme text.
- Both extensions are sandboxed (Quick Look requires it), read only the file Quick Look hands them, and are embedded in SkinAmp by `xcodegen generate`.
- Rendering uses a shared offscreen renderer in SkinKit, the same one `skintool --png` (#0026) and library thumbnails (#0034) use, not a copy.
- A broken or modern (`.wal`) skin gives a clear fallback (the generic icon, or a "can't preview" message), never a crash.
- Verified with `qlmanage -r`, then `qlmanage -t -s 512 <skin>.wsz` and `qlmanage -p <skin>.wsz`, against the sample skins in `Skins/`.

### Decisions

- **Scope.** Four pieces: (1) the document-type claim plus `onOpenURL`, so a `.wsz` opened from Finder loads in SkinAmp; (2) a Quick Look thumbnail extension (`QLThumbnailProvider`); (3) a Quick Look preview extension (data-based `QLPreviewProvider`, HTML with `cid:` PNG attachments); (4) the VM-side checks that prove all three. Both extensions are XcodeGen `app-extension` targets embedded in `SkinAmp.app/Contents/PlugIns`.
- **Rendering comes from #0026, not from here.** The extensions call `MainWindowRenderer.render(skin:state:scale:)` with `MainWindowState.idle` (`Packages/SkinKit/Sources/SkinKit/Rendering/`, per #0026 section 1). Nothing in `QuickLook/` draws a sprite itself. Preferred order: land #0026 first (it is M4; this is M7). If this issue is worked before #0026, the fallback in step 2 lands the smallest slice of #0026's design under #0026's names and paths, so #0026 extends it instead of replacing it. No second renderer, no "composite main.bmp + titlebar" helper living in the extension.
- **Preview is data-based**, not view-based. `QLPreviewProvider` + `QLPreviewReply(dataOfContentType: .html …)` needs no AppKit, no xib and no main-thread work, so it is trivially Swift 6 clean; the page builder (`SkinPreviewPage`) is a pure function in SkinKit and runs under `swift test` in the guest. HTML gives the skin name, warnings and readme for free; a `.png` reply could show only the picture.
- **Pixel art stays pixel art.** The renderer draws at integer scales with nearest-neighbour sampling. The thumbnail picks the largest integer skin-pixels-per-device-pixel that fits the request and only falls back to a smooth downscale when even 1× does not fit (Finder's 16–64 pt icons). The fit arithmetic is a pure SkinKit function so it is unit-tested.
- **Untrusted input.** Finder renders every `.wsz` in a folder without being asked, so the extensions are the first place SkinKit meets hostile archives. `SkinArchive` gains size caps and an extension allow-list (step 3). Everything else in SkinKit already never traps.
- **Info.plist content goes through XcodeGen `info: properties:`** (arrays and dictionaries cannot be expressed with `INFOPLIST_KEY_*`), exactly as #0047 did for the UTType. `GENERATE_INFOPLIST_FILE: YES` stays on; Xcode merges the generated keys into the file XcodeGen writes. The generated `Info.plist` and `.entitlements` files are committed, like `App/Info.plist` (deterministic output; never hand-edited).
- **Verification is `scripts/run-tests-vm.sh [--launch]` only.** The script gains one step, `app-quicklook`, which registers the built app in the guest, runs `qlmanage -t` against a test `.wsz` generated inside the guest, and checks the resulting PNG by pixel. Nothing is built, tested, launched or `qlmanage`d on the host. `*.wsz` is gitignored, so there is no committed fixture; the guest generates one.

### Step 3 — SkinKit additions owned by this issue

New folder `Packages/SkinKit/Sources/SkinKit/QuickLook/` (CoreGraphics, ImageIO and Foundation only; no AppKit, so it links into the sandboxed extensions):

`ThumbnailFit.swift` — the pure size arithmetic the thumbnail provider applies:

```swift
public enum ThumbnailFit {
    public struct Result: Equatable, Sendable {
        public var renderScale: Int      // integer scale to ask the renderer for (≥ 1)
        public var contextSize: CGSize   // points; what QLThumbnailReply is created with
        public var imageRect: CGRect     // points; where to draw the render, centred in the context
        public var smooth: Bool          // true only on the downscale path (pixelScale == 0)
    }
    /// `maximumSize`/`minimumSize` are points, `scale` is the request's device scale factor.
    public static func fit(maximumSize: CGSize, minimumSize: CGSize, scale: CGFloat,
                           window: CGSize = MainWindowLayout.size) -> Result
}
```

`fit = min(maximumSize.width / window.width, maximumSize.height / window.height)` (points per skin pixel); `pixelScale = Int((fit * scale).rounded(.down))` (whole device pixels per skin pixel). If `pixelScale >= 1`: `renderScale = pixelScale`, image size = `window * pixelScale / scale` points, `smooth = false`. Else: `renderScale = 1`, image size = `(window * fit).rounded(.down)`, `smooth = true`. `contextSize` is the image size raised per axis to `minimumSize`; `imageRect` is centred in it.

`SkinPreviewPage.swift` — the preview document, pure and `Sendable`:

```swift
public struct SkinPreviewPage: Sendable {
    public let title: String                 // file name without extension
    public let html: String                  // complete document, UTF-8
    public let attachments: [String: Data]   // "main" → PNG; absent on the failure page
    /// Parses and renders; on failure returns a "Can't preview" page with the SkinError text. Never throws.
    public static func make(url: URL, limits: SkinArchive.Limits = .default) -> SkinPreviewPage
}
```

Parse with `SkinArchive(url:limits:)` then `SkinParser.parse(archive:)` so the readme is reachable from the same archive read. Page: `<h1>` title; `<img src="cid:main" width="550" height="232" style="image-rendering: pixelated">` where the attachment is `render(skin:state: .idle, scale: 4)` (1100×464 px) encoded with `CGImageDestination` as PNG, so Retina shows it 1:1 and a 1× display downsamples exactly 2:1 even if the web view ignores `image-rendering`; a `<ul>` of `skin.warnings` if any; the readme in `<pre>` (first `*.txt` whose base name is not `viscolor`, `pledit` or `region`, preferring one starting with `readme`, decoded as UTF-8 then `.windowsCP1252`, capped at 20 KB with a trailing `…`); a `prefers-color-scheme: dark` block. Every interpolated string goes through one `htmlEscaped` helper (`& < > "`). The failure page is `<h1>Can't preview <name></h1><p><SkinError description></p>`. PNG encoding is a private `pngData(_ image: CGImage) -> Data?` here unless #0026's `PNGWriter` exists, in which case use it.

`Archive/SkinArchive.swift` — hardening:

```swift
public struct Limits: Sendable {
    public var maxEntryBytes: Int = 8 << 20
    public var maxTotalBytes: Int = 64 << 20
    public var allowedExtensions: Set<String> = ["bmp", "png", "txt", "cur", "ini", "xml"]
    public static let `default` = Limits()
}
public init(url: URL, limits: Limits = .default) throws(SkinError)
```

Skip entries whose extension is not allowed or whose `uncompressedSize` exceeds `maxEntryBytes`; also enforce both caps inside the ZIPFoundation consumer closure (the central directory is as untrusted as the data): throw a private error from the closure and `continue`. Stop iterating once `maxTotalBytes` is reached. Existing callers are unaffected (`skin.xml` still triggers `.modernSkin`; `.cur` stays readable for #0037).

### Step 5 — Thumbnail provider (`QuickLook/Thumbnail/ThumbnailProvider.swift`)

```swift
import QuickLookThumbnailing
import SkinKit

final class ThumbnailProvider: QLThumbnailProvider {
    override func provideThumbnail(for request: QLFileThumbnailRequest,
                                   _ handler: @escaping (QLThumbnailReply?, Error?) -> Void) {
        let skin: Skin
        do { skin = try SkinParser.parse(url: request.fileURL) }   // add limits: once SkinParser.parse(url:limits:) exists
        catch { handler(nil, error); return }                      // generic document icon, no crash

        let fit = ThumbnailFit.fit(maximumSize: request.maximumSize, minimumSize: request.minimumSize, scale: request.scale)
        let image = MainWindowRenderer.render(skin: skin, state: .idle, scale: fit.renderScale)
        let reply = QLThumbnailReply(contextSize: fit.contextSize) { context in
            context.interpolationQuality = fit.smooth ? .high : .none
            context.draw(image, in: fit.imageRect)
            return true
        }
        reply.extensionBadge = "WSZ"
        handler(reply, nil)
    }
}
```

The context Quick Look hands the block is already scaled by `request.scale`, so `contextSize`/`imageRect` are in points. On the integer path the render is exactly `renderScale` skin pixels per device pixel, so the draw is a 1:1 blit.

### Step 6 — Preview provider (`QuickLook/Preview/PreviewProvider.swift`)

```swift
import QuickLookUI
import SkinKit
import UniformTypeIdentifiers

final class PreviewProvider: QLPreviewProvider, QLPreviewingController {
    func providePreview(for request: QLFilePreviewRequest) async throws -> QLPreviewReply {
        let url = request.fileURL
        return QLPreviewReply(dataOfContentType: .html, contentSize: CGSize(width: 620, height: 560)) { reply in
            let page = SkinPreviewPage.make(url: url)   // heavy work belongs in this block (Apple's guidance)
            reply.title = page.title
            reply.stringEncoding = .utf8
            reply.attachments = page.attachments.mapValues { QLPreviewReplyAttachment(data: $0, contentType: .png) }
            return Data(page.html.utf8)
        }
    }
}
```

A modern or unreadable skin yields the "Can't preview <name>: <SkinError>" page (the acceptance criteria's clear fallback); the thumbnail side returns the error so Finder keeps the generic icon.

Concurrency: nothing in either extension is `@MainActor`. `provideThumbnail` runs on a background thread; the preview data block runs after `providePreview` returns. The closures capture only `url`, a `CGImage` and value types. `Skin` is `@unchecked Sendable` over immutable `CGImage`s and `SkinPreviewPage` is `Sendable`. If `SWIFT_DEFAULT_ACTOR_ISOLATION: MainActor` is ever set at project level, give both extension targets `SWIFT_DEFAULT_ACTOR_ISOLATION: nonisolated`. The extensions touch only `request.fileURL`: no `UserDefaults`, no network, no app group, no caching across requests (the process may be reused but must not grow).

### Step 7 — Signing for local builds

- All three targets stay `CODE_SIGN_STYLE: Automatic` with `CODE_SIGN_IDENTITY: "-"` (ad-hoc) and no `DEVELOPMENT_TEAM`, matching the app today. The embed phase XcodeGen generates for `target:` dependencies of an application signs each appex on copy, and the app's own signature then seals `Contents/PlugIns`. Ad-hoc signatures carry entitlements, and `com.apple.security.app-sandbox` and `files.user-selected.read-only` are unrestricted entitlements (no provisioning profile), so the sandbox Quick Look requires is in force on a local build. `ENABLE_HARDENED_RUNTIME: YES` on the appexes costs nothing now and is required later for notarization.
- Do not add a team, a real identity or a profile to `project.yml` to make Quick Look "work"; that is a distribution concern (Developer ID + notarization, the `mac-release` skill) and is out of scope. If the guest lists the extensions in `pluginkit` but never runs them, the first suspects are registration and the Info.plist (step 8's checks), not the signature; a signature problem shows as `codesign --verify --deep --strict` failing or as a `taskgated`/`amfid` line in `log show`.
- An unsandboxed host app with sandboxed extensions is fine; each process is evaluated on its own entitlements.
- `APPLICATION_EXTENSION_API_ONLY` makes Xcode build SkinKit and ZIPFoundation with extension-safe API; both are UI-free so this should be silent. A warning about ZIPFoundation's resource bundle in the appex is only a warning.

### Test cases (`swift test --package-path Packages/SkinKit`, run by the `skinkit-tests` step)

`Tests/SkinKitTests/ThumbnailFitTests.swift`:

### Risks

- **Registration, not code, is where this usually fails.** Extensions are discovered only after LaunchServices sees the bundle; the check script does `lsregister -f` and `pluginkit -a` explicitly rather than relying on `open`. If `pluginkit -m` lists nothing, look at `$outdir/quicklook.log` for `PlugInKit` rejections (wrong `NSExtensionPointIdentifier`, bundle id not prefixed by the host's, principal class not found).
- **`qlmanage` in a headless guest.** It needs the per-user Quick Look agents, which exist in the auto-logged-in session; `--launch` proves that session is reachable. If `qlmanage -t` returns an icon for every file including a `.png`, the agent is unreachable from `tart exec` and the step must be reworked to run through `launchctl asuser` with the console user's uid; note it in `## Gotchas`.
- **Quick Look caches.** A stale icon from before registration survives `qlmanage -r`; the script runs `qlmanage -r cache` too and renders into a fresh `$outdir` each run (fresh clone anyway).
- **Pixel check assumptions.** It assumes `contextSize == imageRect.size` (true when `minimumSize` is zero, which `qlmanage` requests). If Quick Look pads the context, sample relative to the magenta bounding box instead; the script should print the sampled RGBA either way so a failure is diagnosable from the log.
- **`.wal` and foreign UTIs.** Only the `wsz` tag maps to our UTI, so `.wal` never reaches us. On a user's Mac another app may export a conflicting type for `wsz`; then `mdls` shows a foreign identifier and `QLSupportedContentTypes` never matches. The `mdls` check in the script documents the symptom; the fix (also listing `public.zip-archive`) is deliberately not taken because it would make SkinAmp claim every zip.
- **Info.plist merge.** If Xcode's merge of `INFOPLIST_FILE` with the `INFOPLIST_KEY_*` values drops a key, move the remaining keys into `info: properties:`, never the other way round (#0047 already proved the merge for the app target).
- **Time and memory budget.** Quick Look kills slow or fat providers. One parse (around 15 small bitmaps), one 275×116×n draw and one PNG encode fit comfortably; step 3's caps keep a hostile archive inside the budget. No caching across requests.
- **#0026 drift.** If both issues are in flight at once, the fallback slice and #0026's work touch the same files; whoever lands second rebases on the other's `Rendering/`. The public signature `render(skin:state:scale:)` and `MainWindowState.idle` are the contract; the extensions use nothing else.
- **Scope creep.** Marquee, digits, sliders, EQ/playlist renders and the Webamp comparison belong to #0021–#0026; the optional EQ-window attachment in the acceptance criteria is skipped unless everything else is done and reviewed.

## Gotchas

- `qlmanage -t` hangs (even with a 60 s watchdog it never returns) for extension-provided types in the headless guest ("No sandbox token for thumbnail request", "missing or invalid generator" in the log) while it works for system types, so the gate is `QLThumbnailGenerator`, which runs the same extension. `qlmanage -t` stays as an informational line.
- A zsh unmatched glob (`rm *.wsz.png`) aborts a non-interactive script, and a hung guest command hangs `tart exec` forever; the check script wraps risky commands in a `perl alarm` watchdog (`tmo`).
- `pluginkit -m -p <point>` listed nothing for the thumbnail point; `-i <bundle id>` works.
