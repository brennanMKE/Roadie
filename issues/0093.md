# 0093 — SkinLibrary unit tests take about 10 s without the scale tests

| | |
|---|---|
| **Status** | open |

## Description

Found while implementing #0085 (commit 86a433f). With the two 100k scale tests moved to the full tier, `SkinLibraryTests` still took 10.3 s in the fast-tier run `20261019-000504-24208` (18.3 s with them). Every other test target in both packages finishes in under 2 s, and most in under 0.3 s.

The user expects unit tests that mock their dependencies to run well under 10 s in total. The SkinLibrary tests use real temp directories, real SQLite stores, thumbnail rendering and indexer passes; some may also wait on real time.

Expected: find what the 84 tests spend their time on (per-test times in `skinkit-tests.log`, noting that Swift Testing runs tests in parallel, so a test's reported time includes waiting), then cut the target to a couple of seconds without losing coverage: in-memory SQLite where the file format isn't under test, smaller fixtures, injected clocks instead of sleeps, fewer files per test. Anything that genuinely needs scale or real time moves to the full tier (#0085).
