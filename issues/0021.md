## Description

Port Webamp's `FONT_LOOKUP` for `text.bmp` and draw the scrolling song title in the main window.

## Acceptance criteria

- Unknown characters fall back like Webamp.
- Marquee scrolls at Winamp speed and can be dragged.

## Plan

### Scope and decisions

Four pieces: the `TEXT` sheet (text.bmp) joins the generated sprite table; SkinKit gains the character lookup (Webamp's `FONT_LOOKUP` + `characterClassName`), a headless text renderer and the pure marquee arithmetic; AudioCore gains the marquee text rules; the App gains a `MarqueeView` and wires it to the player. Status stays `open`; this plan writes no code.

- **The font table stays generated, not hand-written.** Webamp builds the `TEXT` sheet from `FONT_LOOKUP` at module load (`skinSprites.ts` 14–84 is the table, 86–87 `imageConstFromChar` = `CHARACTER_<charCode>`, 89–90 `CHAR_X = 5`/`CHAR_Y = 6`, 92–103 `x = column * 5, y = row * 6, 5x6`, 585 `TEXT: characterSprites`). `scripts/port-webamp-sprites.py` only parses the literal map, which is why `SkinSprites.swift` has no `TEXT` sheet and `SkinParser` never loads text.bmp today. - **Unknown characters fall back exactly like Webamp's `characterClassName`** (`Character.tsx` 9–10): `deburr(char).toLowerCase().charCodeAt(0)` on each UTF-16 unit of the string (`CharacterString.tsx` 10 splits with `split("")`), and a code with no `CHARACTER_<code>` sprite gets a 5x6 cell with no background (`css/webamp.css` 92–99), i.e. the main window background shows through. - **What the marquee says** (`selectors.ts` `getMarqueeText` 633–676, `getMediaText` 428–436, `getMinimalMediaText` 422–426; `trackUtils.ts` `trackName` 5–22; `utils.ts` `getTimeStr` 66–87): a user message or slider focus text wins, else `"<n>. <Artist - Title> (<m:ss>)"` for the current track (1-based queue index; `Artist - Title` when both are set, else the title; `m:ss` with unpadded minutes, `62:05` past the hour), else `"Winamp 2.91"`. - **Rendering is one `CGImage` per text, made headlessly in SkinKit.** `Skin.textImage(_:)` draws each cell from the `TEXT` sheet into a `cells.count * 5` by 6 bitmap; the view offsets that strip inside a clipped 154x6 frame. ### 2. Font lookup and renderer (`Packages/SkinKit/Sources/SkinKit/Text/TextFont.swift`, `Text/TextRenderer.swift`, new)

```swift
/// The `text.bmp` font: 5x6 cells addressed by Webamp's FONT_LOOKUP (sprites `CHARACTER_<code>` in the
/// TEXT sheet). Lookup follows Webamp's `characterClassName`: deburr, lowercase, first UTF-16 unit.
public enum TextFont {
    public static let sheet = "TEXT"
    public static let cellWidth = 5
    public static let cellHeight = 6

    /// lodash `deburr` for one UTF-16 unit: Latin-1 Supplement and Latin Extended-A letters become basic
    /// Latin (`Æ` → "Ae", `ß` → "ss"), combining marks become "", everything else is unchanged.
    static func deburr(_ unit: UInt16) -> String

    /// "CHARACTER_<code>" for the cell that draws `unit`, or nil when text.bmp has none: that cell is
    /// left blank, like Webamp. `Å` resolves to the `a` cell because deburr runs before the lookup.
    public static func spriteName(for unit: UInt16) -> String?

    /// One entry per UTF-16 unit of the NFC form of `text`, nil for a blank cell.
    public static func cells(for text: String) -> [String?]
}

extension Skin {
    /// `text` in the text.bmp font, one 5x6 cell per UTF-16 unit, left to right, cells without a glyph
    /// transparent. nil when the skin has no TEXT sheet or `text` is empty.
    public func textImage(_ text: String) -> CGImage?
}
```

`spriteName`: `let s = deburr(unit).lowercased(); guard let code = s.utf16.first else { return nil }` (a lone combining mark deburrs to `""`, Webamp's `character-NaN`); `let name = "CHARACTER_\(code)"; return SkinSprites.byName[name] != nil ? name : nil`. `deburr`: a `[UInt16: String]` table ported from `deburredLetters` plus the three combining ranges → `""`; units outside `reLatin` return `String(utf16CodeUnits:)` of themselves (a surrogate half stays a surrogate half and misses the lookup, like Webamp). `cells`: `Array(text.precomposedStringWithCanonicalMapping.utf16).map(spriteName)`.

`textImage`: `guard let sheet = sheets[TextFont.sheet]`, `let cells = TextFont.cells(for: text)`, `guard !cells.isEmpty`; `CGContext(data: nil, width: cells.count * 5, height: 6, bitsPerComponent: 8, bytesPerRow: 0, space: CGColorSpaceCreateDeviceRGB(), bitmapInfo: CGImageAlphaInfo.premultipliedLast.rawValue)`, `interpolationQuality = .none`; for each `(i, name)` with a name, `sheet.cropping(to: SkinSprites.byName[name]!.sprite.rect)` drawn in `CGRect(x: i * 5, y: 0, width: 5, height: 6)` (a 6-high context needs no y flip); `makeImage()`. A text.bmp smaller than 155x18 makes `cropping` return nil or a clipped glyph for the missing cells; skip those, never trap.

### 3. Marquee arithmetic (`Packages/SkinKit/Sources/SkinKit/Text/MarqueeLayout.swift`, new)

```swift
/// Webamp's Marquee.tsx: the 154x6 strip at (111, 24) scrolls one 5 px character per step.
public enum MarqueeLayout {
    public static let width = 154
    public static let charWidth = 5          // CHAR_WIDTH
    public static let maxLength = 31         // MARQUEE_MAX_LENGTH
    public static let separator = "  ***  "  // SEPARATOR
    public static let stepInterval: Duration = .milliseconds(220)
    public static let resumeDelay: Duration = .seconds(1)

    public static func isLong(_ text: String) -> Bool            // utf16.count >= maxLength
    public static func loopText(_ text: String) -> String        // long: text + separator + text; short: padded to 31 with spaces
    public static func stepOffset(text: String, step: Int, pixels: Int) -> Int
    // short → 0; long → mod(step * 5 + pixels, (utf16.count + 7) * 5), always-positive modulus
}
```

### 5. App (`App/MarqueeView.swift` new; `App/MainWindowView.swift`, `App/PlayerModel.swift`)

- `PlayerModel`: `var marqueeOverride: String?` with a doc comment naming #0023, and `var marqueeText: String { marqueeOverride ?? MarqueeText.display(queue: player.queue, state: player.state) }`. Both `player.queue` and `player.state` are `@Observable`, so the view re-renders on track and state changes.
- `MainWindowView`: add `MarqueeView(skin: skin, text: model.marqueeText)` to the `ZStack` and drop "marquee text" from the TODO comment. Nothing else moves.
- `MarqueeView` (`struct MarqueeView: View { let skin: Skin; let text: String }`), state `step = 0`, `dragPixels = 0`, `dragging = false`, `stepping = true`:
  - Body: `Image(decorative: image, scale: 1).interpolation(.none)` where `image = skin.textImage(MarqueeLayout.loopText(text))`, offset by `-stepOffset(text:step:pixels:)` in x, inside `.frame(width: 154, height: 6, alignment: .topLeading).clipped()`, then `.padding(.vertical, 3).contentShape(Rectangle())` (the 154x12 hit target) and `.offset(x: 111, y: 21)`. When `textImage` is nil (no text.bmp) the frame stays empty. Computing the strip in `body` is cheap (≤ 69 crops and 5x6 draws, well under a millisecond); memoize on `text` only if a profile says so.
  - Stepping: `.task(id: stepping) { guard stepping else { return }; while !Task.isCancelled { try? await Task.sleep(for: MarqueeLayout.stepInterval); step += 1 } }`. The task dies with the view, so nothing ticks without a skinned window. Step always, even for short text, like Webamp's global counter.
  - Drag: `DragGesture(minimumDistance: 0, coordinateSpace: .local)`; `onChanged`: `dragging = true; dragPixels = -Int(value.translation.width.rounded())` (replaces, never accumulates: Webamp's `setDragOffset(-diff)`); `onEnded`: `dragging = false`. Resume: `.task(id: dragging) { if dragging { stepping = false } else { try? await Task.sleep(for: MarqueeLayout.resumeDelay); if !Task.isCancelled { stepping = true } } }`. The residual `dragPixels` stays after release, as in Webamp.
  - Translation is in the view's local space. `PlayerView` scales the whole window with `scaleEffect(model.scale)`; SwiftUI reports gesture translations in the unscaled local space, so no division by `scale` should be needed. See Risks; the fix if wrong is one division.

### 10. Risks

- **Drag units under `scaleEffect`.** If a drag at 2x moves the text twice as far as the pointer, `DragGesture` is reporting scaled points: divide `translation.width` by `model.scale` (pass the scale into `MarqueeView`). Pixel steps must stay integers either way.
- **Sprite-table drift.** Regenerating from `master` could change other sheets if Webamp edited `skinSprites.ts` since the original port. The diff check in step 1 catches it; keep the `TEXT` hunk only.
- **`Skin`'s memberwise init is internal**, so the synthetic-sheet tests rely on `@testable import SkinKit` (already how `SkinKitTests` imports it). If `Skin` grows a public init in #0020, use that instead.
- **Text.bmp with transparency or odd size.** Glyphs are drawn opaque (text.bmp has no alpha); a sheet smaller than 155x18 leaves the out-of-range cells blank. Neither traps.
- **Timer while hidden.** The 220 ms task lives as long as `MarqueeView` is in the hierarchy, including a minimized window; it is one integer increment, so leave it unless Energy Impact shows otherwise.
- **Webamp's `()` for unknown duration** is intentionally not reproduced; `displaysIdleBufferingAndTrack` pins the omission so a later reviewer does not "fix" it the other way without a test change.

## Root cause

text.bmp was never loaded: `scripts/port-webamp-sprites.py` only parsed the literal sprite map, and Webamp builds the `TEXT` sheet from `FONT_LOOKUP` at module load, so `SkinSprites` had no `TEXT` sheet and `SkinParser` skipped text.bmp. There was also no text renderer, marquee arithmetic or marquee view, and the main window drew no title.

## Fix

Followed the plan, adapted to the landed #0020/#0062/#0018 code.

- The generator now parses `FONT_LOOKUP` (bare, quoted and `[UTF8_ELLIPSIS]` keys) and emits the `TEXT` sheet (69 `CHARACTER_<code>` sprites, 5x6 at `column*5, row*6`); regenerating from the current Webamp `master` changed nothing else (diff is one inserted block). `SkinParser` picks up text.bmp through `SkinSprites.sheets.keys`, unchanged.
- SkinKit `Text/TextFont.swift` (lodash 4.17.21 `deburr` table of 190 entries plus the combining-mark ranges, `spriteName(for:)`, NFC `cells(for:)`), `Text/TextRenderer.swift` (`Skin.textImage`) and `Text/MarqueeLayout.swift` (31-unit threshold, `  ***  `, 220 ms step, 1 s resume, positive-modulus `stepOffset`). lodash added to `NOTICE`.
- App: `MarqueeView` (154x6 clipped strip at (111, 24), 154x12 hit target, `DragGesture` replacing `dragPixels`, stepping task and 1 s resume task) in `MainWindowView`; `PlayerModel.marqueeOverride` (hook for #0023) and `marqueeText`.
- Adaptations: `PlayerModel` now follows a `NowPlaying` stream (#0062), which has no `Track`/`PlayQueue`/source. So `MarqueeText` lives in `MusicBackendKit` (not AudioCore, which cannot see `NowPlaying`) and takes `NowPlaying` plus an optional queue number: `display(_:number:)`. "Buffering…" is shown when `state == .loading` and `item != nil` (a backend track; local files carry no `item`), per #0018's note that `.loading` already covers buffering. The number comes from `player.queue.currentIndex + 1` only while the selected output is This Mac, else the prefix is omitted. Tests went to `MusicBackendKitTests/MarqueeTextTests.swift`. `Skin` already had a public init (#0020), though the tests use it via `@testable`.
- Drag translation is used as is (no division by `scale`); not verifiable headlessly, see Gotchas.
