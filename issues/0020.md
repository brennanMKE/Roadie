## Root cause

SkinKit recorded every missing optional sheet (`nums_ex.bmp`, `numbers.bmp`, `balance.bmp`, `eq_ex.bmp`, `gen.bmp`) as a warning and returned fewer than 24 viscolors for short or absent `viscolor.txt`, so consumers would see gaps where Webamp substitutes. The viscolor parser also took the first three numbers anywhere on a line instead of Webamp's start-anchored match.

## Fix

Followed the plan. Fallbacks are applied at lookup: `Skin.resolve(_:)`/`image(for:)` pick NUMS_EX over NUMBERS (either alone is enough), crop balance sprites from the volume sheet, and use `EQ_MAXIMIZE_BUTTON_ACTIVE_FALLBACK` from eqmain; `Skin.usesNumsEx` is exposed for #0022. `VisColorParser` starts from the 24 Webamp defaults and overwrites the i-th line matching the anchored regex. Substitutions go to the new `Skin.fallbacks`; only genuinely missing things (required sheets, no number sheet at all, undecodable sheets) stay warnings. `skintool` gained `-v` and exits 1 unless every skin is ok. `run-tests-vm.sh --skins DIR` (merged with `--stress`/`--load`) copies samples into the throwaway export, runs `sampleSkinsAreOk` and a `skintool -v` step. Deviations: the skintool step runs with `-v` so the log lists fallbacks; "defaults for 23" is worded without a range when only one entry is defaulted.

### The rules, as Webamp has them

**1. Sprite fallbacks** (`Skin.tsx` 30–35, applied at 58–69). Webamp builds one CSS rule per sprite name from `skinImages[imageName] || skinImages[FALLBACKS[imageName]]`:

| Requested | Falls back to | Sheet |
|---|---|---|
| `MAIN_BALANCE_BACKGROUND` (38×420 at x 9 of `balance.bmp`) | `MAIN_VOLUME_BACKGROUND` (68×420 at x 0 of `volume.bmp`) | BALANCE → VOLUME |
| `MAIN_BALANCE_THUMB` (14×11) | `MAIN_VOLUME_THUMB` (14×11) | BALANCE → VOLUME |
| `MAIN_BALANCE_THUMB_ACTIVE` (14×11) | `MAIN_VOLUME_THUMB_SELECTED` (14×11) | BALANCE → VOLUME |
| `EQ_MAXIMIZE_BUTTON_ACTIVE` (9×9) | `EQ_MAXIMIZE_BUTTON_ACTIVE_FALLBACK` (9×9 at 254,152 of `eqmain.bmp`) | EQ_EX → EQMAIN |

The fallback image is used as the *background* of an element that keeps its own size: `#balance` is 38 px wide with `background-position: 0 0` (`css/main-window.css` 256–262), so the balance slider shows the leftmost 38 px of the 68 px volume background, row for row. Port this as: crop the fallback sprite's rect to the requested sprite's size from the fallback's top-left. The thumbs and the EQ button are the same size, so only the balance background is actually clipped. A skin that has `balance.bmp` is unaffected: the fallback applies only when the whole `BALANCE` sheet is missing (`skinParserUtils.ts` 120–129: a missing sheet contributes no sprite keys at all, with no error; 62–77: an undecodable image is also silently dropped).

**2. `NUMS_EX` ↔ `NUMBERS`** (`skinSelectors.ts` 35–58). The two sheets target the *same* CSS selectors: `DIGIT_n` and `DIGIT_n_EX` both map to `.digit-n`; `NO_MINUS_SIGN`/`NO_MINUS_SIGN_EX` to `#time #minus-sign`; `MINUS_SIGN`/`MINUS_SIGN_EX` to `#time.countdown #minus-sign`. `Skin.tsx` 58–69 emits the rules in `imageSelectors` key order, so when both sheets exist the `_EX` rules come later and win the cascade (same specificity). The effective rule, both directions:

- `nums_ex.bmp` present → all digits and both minus signs come from `nums_ex.bmp`, whether or not `numbers.bmp` exists.
- `nums_ex.bmp` absent → they come from `numbers.bmp`.
- Both absent → nothing is drawn (Webamp), which is the one case that stays a warning here.

Two things ride along. `numExIsUsed` is `Boolean(skinImages.DIGIT_0_EX)` (`Skin.tsx` 28), i.e. "the `NUMS_EX` sheet decoded", and when it is true the minus sign is a 9×13 cell at `top: 0; left: -1` (`Skin.tsx` 112–118) instead of the 5×1 bar at `top: 6; left: -1` (`main-window.css` 116–123) — the sprites already have those sizes (`SkinSprites.swift` 36–37 vs 50–51). The minus sign is only shown in remaining-time mode (`Time.tsx` 19–20). #0022 needs `usesNumsEx` to place it; this issue only exposes it. `#time` sits at (39, 26), digits are 9×13 at x 9/21/39/51 inside it (`main-window.css` 99–106, 125–150), for #0022's reference.

**3. Default viscolors** (`utils.ts` 89–101, `skinParser.js` 54–62, `constants.ts` 48, `baseSkin.json` `"colors"`). `genVizColors` returns `DEFAULT_SKIN.colors` when there is no `viscolor.txt`. `parseViscolors` starts from a *copy of the 24 defaults* and overwrites index *i* with the *i*-th line that matches `^\s*(\d+)\s*,?\s*(\d+)\s*,?\s*(\d+)` — non-matching lines (comments, blanks, prose) are filtered out *before* indexing, so they do not consume a slot; commas are optional; anything after the third number is ignored. Webamp does not cap the array (Matrix_Code yields 30 entries, of which only 0–23 are ever read). SkinKit keeps exactly 24: lines past the 24th are ignored. Webamp does not clamp values either; SkinKit keeps `UInt8(clamping:)`. The 24 defaults, in order (index: r,g,b):

```
 0: 0,0,0        1: 24,33,41     2: 239,49,16    3: 206,41,16    4: 214,90,0     5: 214,102,0
 6: 214,115,0    7: 198,123,8    8: 222,165,24   9: 214,181,33  10: 189,222,41  11: 148,222,33
12: 41,206,16   13: 50,190,16   14: 57,181,16   15: 49,156,8    16: 41,148,0    17: 24,132,8
18: 255,255,255 19: 214,214,222 20: 181,189,189 21: 160,170,175 22: 148,156,165 23: 150,150,150
```

(0 background, 1 grid dots, 2–17 spectrum top→bottom, 18–22 oscilloscope, 23 peak dots.) The current `VisColorParser` differs from Webamp in one way that matters: it takes the first three numbers *anywhere* on the line, so `color 1 = 24,33,41` would parse as (1,24,33); Webamp's regex is anchored at the start of the line and skips it. Port the anchored regex.

### Files to change

**`Packages/SkinKit/Sources/SkinKit/Sprites/SpriteFallbacks.swift`** (new)

```swift
extension SkinSprites {
    /// Webamp's FALLBACKS table (js/components/Skin.tsx). Requested sprite name -> substitute.
    public static let fallbacks: [String: String] = [
        "MAIN_BALANCE_BACKGROUND": "MAIN_VOLUME_BACKGROUND",
        "MAIN_BALANCE_THUMB": "MAIN_VOLUME_THUMB",
        "MAIN_BALANCE_THUMB_ACTIVE": "MAIN_VOLUME_THUMB_SELECTED",
        "EQ_MAXIMIZE_BUTTON_ACTIVE": "EQ_MAXIMIZE_BUTTON_ACTIVE_FALLBACK",
    ]

    /// Sheets whose absence is covered by a fallback or unused in v1; missing ones are noted, not warned.
    static let optionalSheets: Set<String> = ["BALANCE", "NUMBERS", "NUMS_EX", "EQ_EX", "GEN"]

    /// For a NUMBERS or NUMS_EX sprite, the (plain, ex) pair of names; nil for every other sprite.
    /// "DIGIT_3" and "DIGIT_3_EX" both give ("DIGIT_3", "DIGIT_3_EX").
    static func numberPair(for name: String) -> (plain: String, ex: String)?
}
```

`numberPair` derives from the tables, not from string surgery on arbitrary names: build a static dictionary from `sheets["NUMBERS"]` (plain → plain + "_EX") and `sheets["NUMS_EX"]` (ex → ex without the suffix) and look up in it.

**`Packages/SkinKit/Sources/SkinKit/Skin.swift`**

```swift
public struct Skin: @unchecked Sendable {
    public let sheets: [String: CGImage]
    /// Always 24 entries: viscolor.txt lines over Webamp's base-skin defaults.
    public let visColors: [RGBColor]
    /// Things that will render wrong (missing or undecodable required sheets, no number sheet at all).
    public let warnings: [String]
    /// Substitutions that keep the skin whole (balance from volume, digits from one number sheet, default viscolors…).
    public let fallbacks: [String]

    /// True when nums_ex.bmp decoded; Webamp's `numExIsUsed`. Digits and the minus sign then come from
    /// NUMS_EX, and the minus sign is a 9x13 cell at (-1, 0) in #time instead of a 5x1 bar at (-1, 6).
    public var usesNumsEx: Bool { sheets["NUMS_EX"] != nil }

    /// Where a sprite is actually drawn from after the Webamp fallback rules; nil if nothing can draw it.
    /// `rect` is the crop rect in `sheet`; for a fallback it is the substitute's origin with the requested size.
    public func resolve(_ spriteName: String) -> (sheet: String, rect: CGRect)?

    /// Crops the resolved sprite. Equivalent to `resolve` + `sheets[sheet]?.cropping(to: rect)`.
    public func image(for spriteName: String) -> CGImage?
}
```

`resolve`, in this order:

1. `numberPair(for:)` matches → if `sheets["NUMS_EX"] != nil` return the `ex` sprite from `NUMS_EX`; else if `sheets["NUMBERS"] != nil` return the `plain` sprite from `NUMBERS`; else nil. (Rule 2; the EX sheet wins whenever present.)
2. Otherwise look the name up in `SkinSprites.byName`; if its sheet decoded, return it as is.
3. Otherwise, if `fallbacks[name]` names a sprite whose sheet decoded, return that sheet with `CGRect(origin: substitute.rect.origin, size: CGSize(width: min(requested.width, substitute.width), height: min(requested.height, substitute.height)))`. (Rule 1.)
4. Otherwise nil.

`image(for:)` keeps using `CGImage.cropping(to:)`, which intersects the rect with the bitmap, so a 419-row `volume.bmp` (The_Hustler's is 68×419; the sprite says 420) still yields a 38×419 balance background rather than nil. Give `fallbacks` a default of `[]` in the memberwise init so nothing else needs to change.

### Risks and notes

- **An undecodable bitmap in a sample keeps a skin at `partial`.** ImageIO rejects some BMP variants (`BitmapLoader` has a TODO for a fallback decoder). If a sample fails that way, file it as a separate BitmapLoader issue rather than hiding the warning; the acceptance criterion is about fallbacks, and the report line names the file.
- **Sprite rects taller than the bitmap.** Real `volume.bmp`/`balance.bmp` files are 419 rows while Webamp's sprites say 420. `cropping(to:)` intersects, so this is fine today and the `fallbackCropClampsToSheetBounds` test pins it; `resolve` must not pre-check the rect against the bitmap size.
- **Minus-sign size changes under NUMS_EX.** `image(for: "MINUS_SIGN")` is 5×1 or 9×13 depending on `usesNumsEx`. #0022 must place it from `usesNumsEx` (`top 0/left -1` vs `top 6/left -1` inside `#time`) rather than from the sprite table; say so in #0022's plan or notes.
- **`SpriteImage` placeholders in `App/MainWindowView.swift`** size the empty frame from `SkinSprites.byName`; after this issue the right size comes from `skin.resolve(name)?.rect.size`. Not changed here (nothing in the current main window hits a fallback); #0023 should use `resolve` when it adds the sliders.
- **Webamp divergences kept on purpose:** values clamp to 0–255; colour lines past 24 are dropped; undecodable sheets warn. All three are noted in code comments.
- **Order among M4 siblings.** This issue has no dependency on #0021–#0026 and should land first: #0022 (digits, `usesNumsEx`), #0023 (balance slider), #0024 (24 `visColors`) and #0026 (`skintool` exit status, `--skins` in the VM script) build on its API. #0026 extends the same `main.swift`; rebase it on this change.
