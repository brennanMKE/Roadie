- **Winamp's cursor names, from Webamp.** `js/skinParser.js` 10–34 lists the 24 names Winamp uses (`CLOSE`, `EQCLOSE`, `EQNORMAL`, `EQSLID`, `EQTITLE`, `MAINMENU`, `MMENU`, `MIN`, `NORMAL`, `PCLOSE`, `PNORMAL`, `POSBAR`, `PSIZE`, `PTBAR`, `PVSCROLL`, `PWINBUT`, `PWSNORM`, `PWSSIZE`, `SONGNAME`, `TITLEBAR`, `VOLBAL`, `WINBUT`, `WSNORMAL`, `WSPOSBAR`); the comment at 35–50 quotes the Skinners Atlas: `volbar`, `wsclose`, `wswinbut` and `wsmin` are never used, and animated cursors ship under the `.cur` extension. `js/skinParserUtils.ts` 138–151 (`getCursorFromFilename`) loads `<NAME>.CUR` case-insensitively from any folder (`getFilenameRegex`, 13–18), tags data starting with `RIFF` as `ani` and everything else as `cur`. SkinKit parses all 24 now (the EQ and playlist ones wait for M5's windows, but parsing is one table lookup) and ignores any other `.cur`.
- **Where each cursor shows, from Webamp.** `js/skinSelectors.ts` 356–403 (`cursorSelectors`) maps names to CSS selectors; `js/components/Skin.tsx` 85–110 emits `cursor: url(…), auto` for `.cur` and `convertAniBinaryToCSS` for `.ani`. The main-window geometry is `css/main-window.css`: title bar 275×14 at (0,0) (14–20); the four 9×9 buttons at y 3, x 6 (option), 244 (minimize), 254 (shade), 264 (close) (22–48); marquee 154×6 at (111,24) with `padding: 3px 0` "to ensure the target is correct for the cursor" (169–178), i.e. a 154×12 target at (111,24); position 248×10 at (16,72) (298–304); volume 68×13 at (107,57) (228–235); balance 38×13 at (177,57) (256–263); shade-mode position 17×7 at (226,4) (479–485). The fallback is the CSS cascade: an element with no rule inherits its parent's cursor, so a missing `TITLEBAR` shows `NORMAL`, and `#main-window.shade #title-bar` is listed under both `NORMAL` and `WSNORMAL` with `WSNORMAL` emitted later, so shade mode shows `WSNORMAL`, else `NORMAL`. The region map in section 2 encodes exactly that cascade as an ordered candidate list per point.
- **Formats.** A `.cur` is the ICO container with type 2: a 6-byte `ICONDIR` (reserved 0, type, count), 16-byte `ICONDIRENTRY`s (width, height — 0 means 256 — colour count, reserved, hotspot x, hotspot y — in an ICO these two are planes and bit count — bytes in resource, image offset), and per entry either a PNG or a `BITMAPINFOHEADER` whose `biHeight` is twice the image height, followed by the palette (≤ 8 bpp), the bottom-up XOR bitmap and the bottom-up 1-bpp AND mask, each row padded to 4 bytes. ImageIO is not used for the DIB path: whether `CGImageSource` accepts type-2 ICO data is undocumented, and the hotspot sits where ImageIO expects planes/bit count. Writing the decoder (about 150 lines) makes the behaviour deterministic and fully unit-testable; PNG entries (Vista and later) go through the existing `BitmapLoader` since that is ImageIO's job. An `.ani` is a RIFF `ACON` file (`packages/ani-cursor/src/parser.ts` 38–127): an `anih` chunk (36 bytes: `cbSize`, `nFrames`, `nSteps`, `iWidth`, `iHeight`, `iBitCount`, `nPlanes`, `iDispRate` in jiffies of 1/60 s, `bfAttributes` — bit 0 set means the frames are ICO/CUR files, bit 1 that a `seq ` chunk exists), optional `rate` and `seq ` chunks of `nSteps` DWORDs, and a `LIST` of form `fram` whose `icon` subchunks are complete `.cur` files; `parser.ts` 113–118 tolerates the `fram` list nested inside the `LIST INFO` chunk ("Take ONE" cursors). Chunk bodies are padded to even length. `index.ts` 57–75 turns `rate`/`seq` into keyframes (`rate ?? iDispRate` per step, `seq[i] ?? i`) and 39–44 notes that Winamp restarts the animation whenever the mouse enters an element.
- **AppKit tracking area, not SwiftUI `.pointerStyle` and not cursor rects.** `.pointerStyle(.image(_:hotSpot:))` is macOS 15 and the deployment target is 14.0 (`project.yml`); it also has no animated form. `NSView.addCursorRect` only tracks the key window, while Winamp shows its cursors over an inactive window (#0025's drag view accepts first mouse for the same reason). So #0025's `SkinShapeView` owns one `NSTrackingArea` over its bounds (`.mouseMoved`, `.mouseEnteredAndExited`, `.cursorUpdate`, `.activeInActiveApp`, `.inVisibleRect`) and a small controller resolves the cursor from the pointer position through the SkinKit region map and calls `NSCursor.set()` when it changes. One area with a point lookup, rather than one tracking area per region, keeps overlap and nesting rules out of AppKit's hands and makes the lookup unit-testable. Animated cursors are stepped by a `Timer` on the main run loop in `.common` modes, restarted from step 0 on every region change (Winamp's behaviour per ani-cursor) and stopped on exit.
- **Pixel size.** Cursors are drawn at 1 point per cursor pixel regardless of `PlayerModel.scale`; Winamp never scaled them and Webamp's double-size mode leaves `cursor: url()` alone. On Retina the `NSImage` carries a second, 2× nearest-neighbour representation so the pixels stay crisp instead of being bilinear-blurred.
- **Fallback.** Missing cursor → the cascade in section 2 → system arrow. An unreadable file is treated as missing and recorded in `SkinCursors.unreadable`, not in `Skin.warnings`: a bad cursor is cosmetic, Webamp drops it silently (`Skin.tsx` 96–103 catches and logs), and #0020's `sampleSkinsAreOk` asserts `warnings.isEmpty` for every sample skin. The decoder never throws or traps; every byte read is bounds-checked and every dimension is capped, because `corpusNeverCrashes` and #0038's corpus run will feed it a thousand skins' worth of hand-made files.
- **Inverted pixels.** Windows composes `(screen AND mask) XOR image`: AND 1 / XOR black is transparent, AND 1 / XOR non-black inverts the screen (used for the white outline of classic arrows). `NSCursor` cannot invert, so those pixels are drawn opaque in their XOR colour; browsers do about the same, and the outline reads correctly on dark skins. Documented deviation, tested in section 5.

### 1. SkinKit: decoding (`Packages/SkinKit/Sources/SkinKit/Cursors/`, new folder)

`SkinCursor.swift` (public types):

```swift
/// One decoded skin cursor: a single frame for a `.cur`, several for a RIFF `.ani` saved under the `.cur` name.
public struct SkinCursor: @unchecked Sendable {            // CGImage is immutable, like Skin.sheets
    public struct Frame: @unchecked Sendable {
        public let image: CGImage                           // RGBA, premultiplied, native pixels
        public let hotSpot: CGPoint                         // pixels, top-left origin (NSCursor's convention too)
        /// Nearest-neighbour upscale for Retina representations; nil if the context cannot be made.
        public func upscaled(_ factor: Int) -> CGImage?
    }
    public struct Step: Sendable, Equatable {
        public let frame: Int                               // index into `frames`
        public let duration: TimeInterval                   // seconds (jiffies / 60); 0 for a static cursor
    }
    public let frames: [Frame]                              // never empty
    public let steps: [Step]                                // never empty; `[Step(frame: 0, duration: 0)]` for a `.cur`
    public var isAnimated: Bool { steps.count > 1 }
    public var cycleDuration: TimeInterval                  // sum of step durations
}

/// Every cursor a skin ships under a name Winamp uses.
public struct SkinCursors: @unchecked Sendable {
    /// Webamp's CURSORS (js/skinParser.js 10–34), in that order. 24 entries; no VOLBAR/WSCLOSE/WSWINBUT/WSMIN.
    public static let names: [String]
    public let byName: [String: SkinCursor]                 // uppercase name → cursor
    public let unreadable: [String]                         // "titlebar.cur", sorted; present but undecodable
    public static let empty: SkinCursors
    public var isEmpty: Bool { byName.isEmpty }
    public subscript(name: String) -> SkinCursor? { byName[name.uppercased()] }
    static func load(from archive: SkinArchive) -> SkinCursors   // archive.file(name.lowercased(), extensions: ["cur"]) per name
}
```

`CursorParser.swift` (public entry point):

`ByteReader.swift` (internal): a bounds-checked little-endian reader over `[UInt8]` (copy the `Data` once; `Data` slices have non-zero `startIndex`, which is the classic trap). `u8()`, `u16()`, `u32()`, `i32()`, `bytes(count)`, `seek(to)`, all returning `nil` past the end; a `bit(at:)` helper for the 1-bpp mask (MSB first).

`CursorBitmap.swift` (internal): `static func decode(_ bytes: [UInt8]) -> SkinCursor.Frame?`.
- `ICONDIR`: reserved must be 0, type 1 (ICO) or 2 (CUR), count 1...64. Entries: hotspot from the entry for type 2, `(0,0)` for type 1; `imageOffset` must lie inside the data; a `bytesInRes` that overruns is clamped to what is there (seen in the wild; Windows is lenient).
- Entry choice: Winamp loads at the 32×32 system size, so pick the entry minimising `|w − 32| + |h − 32|`, ties broken by the higher DIB bit count; every sample cursor has one entry anyway.
- PNG signature at the offset → `BitmapLoader.image(from:)`, hotspot from the entry.
- Otherwise `BITMAPINFOHEADER`: `biSize` ≥ 40 (skip to `biSize` for V4/V5 headers), width 1...256, `biHeight` = 2 × height (accept `biHeight == height` as "no AND mask": all opaque), `biBitCount` ∈ {1, 2, 4, 8, 16, 24, 32}, `biCompression` 0 (`BI_RGB`) or 3 (`BI_BITFIELDS`, accepted for 32 bpp with the default masks only). Palette of `biClrUsed` (or `1 << bpp`) BGRx quads for ≤ 8 bpp; an index past a short palette is black. XOR stride `((width × bpp + 31) / 32) × 4`, AND stride `((width + 31) / 32) × 4`, both bottom-up; a truncated XOR block is a failure, a short AND block is padded with 0 (opaque). 16 bpp is 5-5-5.
- Composite into an RGBA8 premultiplied buffer, top-down: AND 1 and XOR black → `(0,0,0,0)`; AND 1 and XOR non-black → the XOR colour, opaque; AND 0 → opaque, except for 32 bpp where, if any pixel's alpha byte is non-zero, the alpha channel is used (premultiplied; old files leave it all zero and rely on the mask). Hotspot clamped into the image. `CGImage` via `CGDataProvider(data:)`, `premultipliedLast`, device RGB.

`AniParser.swift` (internal): `static func parse(_ bytes: [UInt8]) -> SkinCursor?`.
- `RIFF` + size + `ACON`; otherwise nil. Walk chunks (`id`, `u32` size, body, pad to even); recurse into every `LIST` (skip its 4-byte form). Collect `anih` (needs 36 bytes; take `nFrames`, `nSteps`, `iDispRate`, `bfAttributes`), `rate`, `seq `, and the `icon` subchunks of every `fram` list wherever it sits (`parser.ts` 113–118). Ignore dimensions and bit depth in `anih` (the Sony files say 0×0 4-bit). `bfAttributes` bit 0 clear (raw DIB frames) → nil, like ani-cursor, which only reads `icon` chunks.
- Frames: `CursorBitmap.decode` on each `icon` body, capped at 256; frames that fail are dropped with every step that references them; no frames → nil.
- Steps: count `nSteps` (capped at 1024, at least 1); `frame = seq[i] ?? i` (`index.ts` 69), dropped if out of range; `duration = (rate[i] ?? iDispRate) / 60`, with 0 jiffies clamped to 1 (The_Hustler's single-frame files have `iDispRate` 0; a 4-frame file always ships a `rate` chunk in the samples, but a 0-rate step must not spin a timer at infinity). No steps left → nil.

`Skin.swift`: `public let cursors: SkinCursors` (after `visColors`; `init` gains the parameter with a default of `.empty` so the test-only initialisers in #0020–#0024 keep compiling). `SkinParser.swift`: `let cursors = SkinCursors.load(from: archive)` before the `return`, pass it in, and strip "cursors" from the TODO comment. ### 3. App: showing the cursors (after #0025)

```swift
/// Shows the skin's cursor for the main-window region under the pointer; animates RIFF cursors.
@MainActor
final class SkinCursorController {
    var pointsPerPixel: CGFloat = 1                   // Winamp/Webamp never scale cursors

}
```

### 5. Tests (`Packages/SkinKit/Tests/SkinKitTests/SkinCursorTests.swift`, Swift Testing, headless, no AppKit, silent)

Fixtures are built in the test file by a tiny `ByteWriter` (`u8`, `u16`, `u32`, `bytes`): `makeCur(width:height:bitCount:palette:pixels:andMask:hotSpot:type:extraEntries:)` writes the directory, header (`biHeight = 2h`), palette, bottom-up padded XOR rows and AND rows; `makeAni(frames: [[UInt8]], rate: [UInt32]?, seq: [UInt32]?, dispRate:, flags:, nestFramInInfo: Bool)` writes RIFF/`ACON` with even padding; `makePNG(2×2)` through `CGImageDestination`. Pixels are read back by drawing the `CGImage` into an RGBA8 context (#0021 plans the same helper; share it if it exists, else add `TestPixels.rgba(of:at:)` here).

1. `curHeaderIsParsedWithHotSpot`: 4×4 4-bit, palette `[black, red, white, blue]`, hotspot (1,2) → one frame 4×4, `hotSpot == (1,2)`, `steps == [Step(frame: 0, duration: 0)]`, `!isAnimated`, `cycleDuration == 0`; pixel (0,0) is opaque red.
2. `andMaskMakesPixelsTransparentOrInverted`: 8×1 1-bit: AND 1 over black → alpha 0; AND 1 over white → opaque white; AND 0 over black → opaque black. `biHeight == height` (no mask) → everything opaque.
3. `paletteIndexAndRowOrderAreHonoured`: 5×3 8-bit (stride 8 with padding), `biClrUsed = 3`, each row a different colour → the image's top row is the last stored row; a palette index ≥ 3 is black; pixel (4,0) is the expected colour.
4. `trueColourAndAlphaDecode`: 24-bit `B,G,R` bytes come back as RGB; 32-bit with every alpha byte 0 → opaque; 32-bit with one pixel at alpha 128 → that pixel reads back premultiplied (≈ half) while AND 1 still clears it; 16-bit 5-5-5 pure red → `(255, 0, 0)` within ±8.
5. `pngEntryDecodesThroughImageIO`: entry whose payload is a 2×2 PNG, hotspot (1,1) → 2×2 frame, hotspot (1,1).
6. `bestEntryIsClosestToThirtyTwo`: entries 16×16 1-bit, 32×32 4-bit, 48×48 8-bit in that order → the 32×32 one; two 32×32 entries (4-bit, 8-bit) → the 8-bit; ICO type 1 → hotspot `(0,0)`.
7. `malformedCursorsReturnNil`: empty, 5 bytes, type 3, count 0, count 65, offset past the end, `biSize` 12, bit count 3, compression 1, width 0, width 300, `biHeight` 3h, truncated XOR block, hotspot (40,40) clamped to (3,3) on a 4×4 (that one is non-nil) — plus 500 seeded single-byte mutations of fixture 1 (a fixed LCG, no `SystemRandomNumberGenerator`) that must return without trapping.
8. `aniFramesRatesAndSequenceAreRead`: 3 frames (distinct colours), `rate [6, 12, 60]`, `seq [2, 0, 1]` → `frames.count == 3`, `steps == [(2, 0.1), (0, 0.2), (1, 1.0)]`, `cycleDuration == 1.3`, `isAnimated`; frame 2's pixel (0,0) is the third fixture's colour.
9. `aniDefaultsToDisplayRateAndIdentitySequence`: no `rate`/`seq`, `iDispRate 10`, 2 frames → `[(0, 1/6), (1, 1/6)]`; `iDispRate 0` → each step 1/60; `nSteps 5`, 2 frames, no `seq` → steps 3 and 4 dropped, 2 remain; a `seq` entry of 7 → that step dropped.
10. `aniToleratesNestedFramOddChunksAndWrongHeader`: `fram` nested inside `LIST INFO` after an `INAM` of odd length (pad byte) → frames found; `anih` claiming 0×0 4-bit over 32×32 24-bit frames → 32×32 images (the Sony layout); `wsmin`-style 15 frames / 16 steps with `seq` ending in 0 → 16 steps, last one frame 0.
11. `aniRejectsRawFramesAndBrokenFiles`: flags bit 0 clear → nil; form `WAVE` → nil; no `anih` → nil; no `fram` → nil; one `icon` that is garbage among three → 2 frames and only their steps; all `icon`s garbage → nil; a chunk size past the end → nil, no trap.
12. `cursorsLoadByWebampNameOnly`: `SkinArchive(files: ["Skin/CLOSE.CUR": cur, "normal.cur": ani, "volbar.cur": cur, "mainmenul.cur": cur, "matrix.cur": cur])` → `byName.keys == ["CLOSE", "NORMAL"]`, `cursors["close"]` non-nil (case-insensitive subscript), `unreadable.isEmpty`; `SkinCursors.names.count == 24`, contains `"WSPOSBAR"`, not `"VOLBAR"`.

### 7. Risks

- **SwiftUI resetting the cursor.** `NSHostingView` has its own tracking areas and could set the arrow on hover changes over its subviews (check (6)). If it does, the `cursorUpdate(with:)` override is the first lever (AppKit sends it to the deepest view, so add the same override to a thin `NSHostingView` subclass that forwards to the controller); `NSCursor.hide/unhide` games are not an option. Note the outcome in `## Gotchas`.
- **Inversion approximation.** The AND 1 / XOR non-black rule paints inverted pixels opaque. Cursors designed to invert over bright backgrounds will show a white blob there; acceptable, documented in test 2.
- **Cursor image size.** macOS shows large cursor images, but very large ones (> 64 pt) are unusual; the entry choice prefers 32×32 and the decoder caps at 256, so a huge cursor is legal but odd, not a crash.
- **Timer behaviour during drags.** The title-bar drag runs in the normal event loop, so a `.common`-mode timer keeps stepping; if the animation visibly stalls while dragging, that is cosmetic and matches Winamp's single-threaded redraw closely enough.
- **Hotspot coordinate system.** `NSCursor(image:hotSpot:)` takes the hotspot in the image's flipped (top-left) coordinates, the same as the `.cur` entry; if check (1) shows the tip offset vertically, flip `y` in the controller only, never in SkinKit.
- **Decoder trust.** All counts and dimensions are capped (entries 64, width/height 256, frames 256, steps 1024) before any allocation; every read goes through `ByteReader`; the fuzz test and `corpusNeverCrashes` are the safety net for #0038.
- **Sibling merges.** `Skin.swift`/`SkinParser.swift` are also edited by #0020 and #0025 (one line each here); `SkinShapeView.swift`/`SkinWindowController.swift` are #0025's files, edited after it lands. Rebase, re-run the VM script, do not re-plan.
