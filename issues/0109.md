## Description

With #0105 to #0108 in place, SkinAmp has a Sendspin player that can play Music Assistant's stream through AudioCore, and the Music Assistant backend can target it as This Mac. The app still treats "This Mac" as "the local queue": `PlaybackRouter` sends every This Mac command to the folder backend, `PlayerModel` reads the main window's track, time and playlist number from `player.queue`, nothing starts or stops the Sendspin session, and Settings has no way to turn it on. This issue wires it up so that, with Music Assistant as the source and This Mac as the output, picking an album plays it through the Mac with the EQ, balance and visualizer working, and the transport buttons, media keys and Control Center control it.

## Fix

Commit c8273f6. Followed the plan.

Divergences from the plan:
- **Router tests:** a `PlaybackRouterTests` struct already existed in `OutputPickerModelTests.swift`, so the four new tests went into it rather than into a new `PlaybackRouterTests.swift`. A second struct with that name would not have compiled.
- **Feed changes:** every feed change goes through `PlayerModel.setThisMacFeed(_:)`, which calls `observeNowPlaying()` again. I used that instead of `withObservationTracking`.
- **Local entry points:** `.local` is set in `importLocalFiles` after the gate check and the load. Open, Add, Add Dir, Load List and drag and drop all go through it. The playlist window's double-click plays through AudioCore, which preempts the stream, and that sets `.local` too.
- **Stopping the session:** on `.failed`, `.disconnected`, a server change or sleep, the session stops with `.restart`. Turning the setting off sends `.userRequest`, and quitting sends `.shutdown`, bounded to 0.5 s by running the main run loop.

## Plan

### Concept: what feeds This Mac

This Mac (`OutputDevice.thisMacID`) is one output fed by one of two things:

- `.local`: AudioCore's own queue (local files, the folder source): today's behaviour.
- `.musicAssistant`: Music Assistant's queue for SkinAmp's own MA player, arriving over Sendspin.

`LibraryBrowser/PlaybackRouter.swift` gains:

```swift
public enum ThisMacFeed: Sendable, Equatable { case local, musicAssistant }
@MainActor @Observable public final class ThisMacFeedState { public var feed: ThisMacFeed = .local; public init() {} }
```

`PlaybackRouter.init(local:remote:feed:)` takes the state (default a fresh `.local` one, so existing callers and tests compile). `backend(for:)`: a speaker → remote; This Mac → `feed == .musicAssistant ? remote : local`. New `backend(for output:, command: TransportCommand)`: `.setVolume` and `.setBalance` on This Mac always go to `local` (they act on the local `Player`, which reports volume to Music Assistant through Sendspin, #0108; #0107 makes the MA backend refuse them for This Mac).

The feed changes only in these places:

1. `PlayerModel.playFromLibrary`: Music Assistant source + This Mac → `.musicAssistant` before `backend.play`; folder source → `.local`.
2. `SendspinPlayer.onStreamStarted` (Music Assistant started playing on this Mac, from SkinAmp or from MA's own UI, Home Assistant or a phone) → `.musicAssistant`.
3. `SendspinPlayer.onStreamPreempted` (the user opened, dropped or double-clicked a local file, or the folder source played, while a stream was on) → `.local`, and `Task { try? await musicAssistant.transport(.stop, on: OutputDevice.thisMacID) }` so Music Assistant stops sending.
4. Local file entry points (`open(_:replace:)`, `openFolder`, playlist loads, drag and drop) set `.local` before they touch the queue (the preemption then follows from AudioCore).

### MusicAssistantKit (small)

`MusicAssistantBackend` keeps the token it connected with (`private var connectedToken`, cleared with `connectedBaseURL`) and exposes `public func sendspinEndpoint() -> MusicAssistantSendspinEndpoint?` (`baseURL`, `token`; nil when not connected). No second Keychain read, and Sendspin always targets the server the API is connected to (#0075's selection). Test in `MusicAssistantKitTests/MusicAssistantThisMacTests.swift`: `sendspinEndpointFollowsTheConnection` (nil before `connect`, the base URL and token after, nil after `disconnect`).

### SendspinPlayback: when to connect (pure, tested)

`Sources/SendspinPlayback/SendspinAutoConnect.swift`: `enum SendspinAutoConnect { static func decide(enabled: Bool, endpointURL: URL?, runningURL: URL?) -> Action }` with `enum Action: Equatable { case start, restart, stop, none }`: start when enabled, an endpoint exists and nothing runs; restart when the endpoint's base URL differs from the running one; stop when disabled or the endpoint went away while running; otherwise none. (Plain `URL?` so SendspinPlayback stays free of MusicAssistantKit.) Tests in `SendspinPlaybackTests/SendspinAutoConnectTests.swift`: `startsWhenEnabledAndConnected`, `restartsWhenTheServerChanges`, `stopsWhenDisabledOrDisconnected`, `doesNothingWhenUnchanged`.

### App

1. **`App/SendspinController.swift` (new, `@MainActor`)** — owns the policy:
   - Setting `UserDefaults` key `sendspin.enabled` (default **true**; the user asked for local playback), exposed as `var isEnabled`.
   - Follows `musicAssistant.connectionStates()` (the same stream `watchMusicAssistantConnection` reads): on `.connected`, read `sendspinEndpoint()`, apply `SendspinAutoConnect.decide`, and on start build `SendspinConnectionConfiguration(baseURL:, token: endpoint.token.rawValue, clientID: identity.clientID, name: identity.name, deviceInfo: SendspinDeviceInfo(productName: "SkinAmp", manufacturer: "SkinAmp", softwareVersion: CFBundleShortVersionString), format: stack.sendspin.advertisedFormat())`, call `stack.sendspin.start(_)` and `await musicAssistant.setLocalSendspinClientID(identity.clientID)` (#0107). On `.failed`/`.disconnected` or a server change (`musicAssistantServerChanged`), stop with `.restart` and clear the client id. So Sendspin connects when Music Assistant does (the Library or #0067's probe), never earlier: launch still reads no Keychain and opens no socket by itself.
   - `SendspinIdentity.load(defaults: .standard, hostName: Host.current().localizedName ?? "Mac")`; the MA player is named `SkinAmp (<computer name>)`.
   - Sleep and quit: `NSWorkspace.willSleepNotification` → `stop(reason: .restart)`; `didWakeNotification` → re-decide; `AppDelegate.applicationWillTerminate` → `stop(reason: .shutdown)` (bounded: do not block quit more than 0.5 s).
2. **`App/PlayerModel.swift`**:
   - `init`: keep `stack` (`LocalPlaybackStack.standard()`, which now has `sendspin`); `let feedState = ThisMacFeedState()`; `router = PlaybackRouter(local: folderBackend, remote: ma, feed: feedState)`; `sendspinController = SendspinController(sendspin: stack.sendspin, musicAssistant: ma, feed: feedState)`; hook `onStreamStarted`/`onStreamPreempted` as above.
   - `var thisMacFeed: ThisMacFeed { feedState.feed }` and **`var playsLocalQueue: Bool { selectedOutput == OutputDevice.thisMacID && thisMacFeed == .local }`**. Use it instead of `selectedOutput == OutputDevice.thisMacID` wherever the check means "the local queue drives this": `isShuffled`, `isRepeating`, `marqueeText`'s number, `currentTrackInfo`, `mainWindowStatus(at:)` (`isLocal`), `playlist.isLocal` closure (the playlist window still edits the local queue, but its "now playing" highlight follows the local queue only), `remoteClockAnchor` (pass `followsLocalPlayer: playsLocalQueue`, below), `observeNowPlaying` (`isRemote = !playsLocalQueue` for Control Center's external display). Leave `selectedOutput == thisMacID` where it means "the Mac's own audio": `LocalPlaybackGate` calls, `activeMusicAssistantServerChanged`, the balance error filter.
   - `observeNowPlaying()` also re-runs when the feed changes (observe `feedState.feed` with `withObservationTracking`, or call it from the three feed setters).
   - Command loop: `self.router.backend(for: output, command: command).transport(command, on: output)`.
   - `mainWindowStatus` in the `.musicAssistant` feed: time and duration from `nowPlaying` (as for a speaker), sample rate and channels from `player.currentFormat` (the stream's format, set by #0106), bitrate nil.
3. **`MusicBackendKit/Playback.swift`**: `remoteClockAnchor(selected:)` becomes a wrapper over new `remoteClockAnchor(followsLocalPlayer: Bool)` so the 1 s clock ticks for This Mac when Music Assistant feeds it. Test in `MusicBackendKitTests`: `remoteClockTicksForThisMacFedByMusicAssistant` and keep the existing anchor tests passing.
4. **`App/NowPlayingRouting.swift`**: `remote` is the model when `!model.playsLocalQueue` (so media keys on This Mac + Music Assistant go to MA, which then streams the result).
5. **Output picker**: no change; This Mac is always first, and #0107 hides SkinAmp's own MA player from the speaker list.
6. **Settings › Music Assistant (`App/Settings/MusicAssistantSettingsView.swift`)**: a section "This Mac" with `Toggle("Play Music Assistant on this Mac", isOn:)` bound to `SendspinController.isEnabled`, a status line from `stack.sendspin.status` ("Connected: shows in Music Assistant as SkinAmp (<name>)", "Connecting…", "Off", or the failure text) and a footnote: "Music Assistant streams to SkinAmp over Sendspin. Group This Mac with other speakers in Music Assistant." Keep it a plain `Form` section like the existing ones.
7. **`project.yml`**: link `SendspinKit` and `SendspinPlayback` into the app target (next to `LocalPlayback`), then `xcodegen generate` happens in the VM run as usual. `App/Info.plist`: nothing new (the local-network usage text already covers Music Assistant; the proxy uses the API host and port, no Bonjour).
