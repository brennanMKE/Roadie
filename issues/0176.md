# 0176 — There is no Jump to File panel or J hotkey

| | |
|---|---|
| **Status** | open |
| **Module** | App / SkinKit |
| **Platform** | macOS |
| **First seen** | 2026-10-23 |

## Description

Phase A of M15. Winamp's best-remembered feature is Jump to File: press `J` in any Winamp window, type a few letters, press Return, and that track plays. Roadie has nothing like it. Picking a track from a big queue means scrolling the playlist editor.

This issue adds:

- A native "Jump to File" panel over the playlist editor's rows.
- A bare `J` hotkey in the skinned windows.
- A "Jump to File…" item with ⌘J in the skinned pop-up menu (Playback) and in the menu bar's Playback menu.

Play jumps straight to the row, and the playlist editor scrolls to it and selects it. The Queue button and ⇧Return come in #0180. Until then the button is hidden.

Spec: [docs/music-selection-features.md](../docs/music-selection-features.md) §3 Phase A. Decision: `J` while the panel is open brings it forward rather than toggling it. That's friendlier on macOS; #0174 row 7 checks what Winamp did.

## Plan

### 1. Hotkey (`Packages/SkinKit/Sources/SkinKit/Layout/WinampHotkeys.swift`)

- Add `case jumpToFile` to `WinampHotkey`.
- In `hotkey(...)`'s letter switch, add `case "j": return .jumpToFile`. The existing rules apply: no modifiers, no repeat, Caps Lock ignored.
- Update the doc comments ("Z X C V B, arrows, S R L J"), and the matching comment on `SkinWindow.onHotkey` in `App/Window/SkinWindow.swift`.
- `SkinWindow.keyDown` needs no change. A `J` pressed while the playlist's `PlaylistListInputView` is first responder falls through its `default: super.keyDown` to the window, as the other letters do.

### 2. Menu command (`Packages/SkinKit/Sources/SkinKit/Menus/MainMenu.swift`)

- Add `case jumpToFile` to `MainMenuCommand`.
- In `playbackEntries`, after Next: `.separator`, then `.item(MainMenuItem(.jumpToFile, "Jump to File…", shortcut: MainMenuShortcut("j")))`. ⌘J is free in the pop-up and in the menu bar (checked: `RoadieApp`, `PlaybackCommands`, `SkinsCommands`, `MainMenu`). Winamp used Ctrl+J for Jump to *Time*; Roadie has no Jump to Time.

### 3. Menu bar (`App/PlaybackCommands.swift`)

In `PlaybackMenuItems`, after the Next button: `Divider()`, then `Button("Jump to File\u{2026}") { model.showJumpToFile() }.keyboardShortcut("j")` (⌘J). The pop-up's shortcut must match the menu bar's (`MainMenuShortcut` doc).

### 4. Model hooks (App)

- `App/PlayerModel.swift`, `perform(_ hotkey: WinampHotkey)`: add `case .jumpToFile: showJumpToFile()`.
- `App/PlayerModel+MainMenu.swift`, `perform(_ command: MainMenuCommand)`: add `case .jumpToFile: showJumpToFile()`.
- `PlayerModel`: `func showJumpToFile() { JumpToFilePanel.shared.show(model: self) }`.
- **Stored row source.** In `observeQueue()`, store the result of `QueueRowsSelection.choose(...)` in a new `private(set) var queueRowsSource: QueueRowsSource = .local` before switching on it. `PlaylistModel` shows `.none` as an empty remote snapshot, so the panel can't tell the two apart without this.
- `App/Playlist/PlaylistModel.swift`, add:
  ```swift
  /// Selects row `index` alone and scrolls it into view (Jump to File, #0176).
  func reveal(_ index: Int) {
      let tracks = tracks
      guard tracks.indices.contains(index) else { return }
      selection.click(index, in: tracks)
      scrollPosition = PlaylistScroll.position(revealing: index, position: scrollPosition, count: tracks.count,
                                               visibleRows: layout.visibleRows)
  }
  ```

### 5. The panel (`App/JumpToFile/JumpToFilePanel.swift`, new)

Copy the `FileInfoPanel` pattern: `@MainActor final class JumpToFilePanel` with `static let shared` and one lazily made `NSPanel`.

Use **AppKit**: an `NSSearchField` and a view-based `NSTableView` with a data source. A SwiftUI `List` diffs every row on each keystroke, and the panel must stay fast at 50,000 rows. `NSTableView` asks only for the visible rows, and it makes the key routing below simple. Then run `xcodegen generate` on the host (allowed) so the new folder is in the project; the VM run generates it again anyway.

**Window**

- `NSPanel(contentRect: 420×360, styleMask: [.titled, .closable, .resizable, .utilityWindow], backing: .buffered, defer: true)`, title "Jump to File".
- `isReleasedWhenClosed = false`, `hidesOnDeactivate = false`, `becomesKeyOnlyIfNeeded = false`, `minSize` 320×200.
- `setFrameAutosaveName("JumpToFilePanel")` so it remembers its frame. Call `center()` only on the first show, when there's no saved frame.
- `level = .floating`, so it stays above skinned windows that are Always On Top.
- Losing key status doesn't close it.

**Layout** (an `NSStackView`, vertical, 8 pt spacing, 12 pt insets)

1. The `NSSearchField`, with placeholder "Type to filter the playlist". Its `delegate` is the panel controller.
2. An `NSScrollView` holding the `NSTableView`:
   - `allowsMultipleSelection = true`, `usesAlternatingRowBackgroundColors = true`, `style = .inset` (or `.plain`).
   - `doubleAction = #selector(playSelected)`.
   - Three columns: `number` (right-aligned, about 48 pt, "\(index + 1)"), `name` (flexible, `PlaylistModel.displayName(track)`), `time` (right-aligned, about 52 pt, `PlaylistText.time(track.duration > 0 ? track.duration : nil)`).
   - Monospaced digits for the number and time cells.
   - The rows show the matched results, numbered by their row in the full queue.
3. An `NSTextField(labelWithString:)` for the empty state, hidden unless it applies:
   - `.none` source: "This speaker's queue can't be listed".
   - Empty queue: "The playlist is empty".
   - No matches: "No matches".
4. A button row: **Play** (`playSelected`), **Queue** (`queueSelected`, `isHidden = true` until #0180), a spacer, **Close** (`performClose`).

**Data**

- Source rows: `model.playlist.tracks`. It's already the local `player.queue.tracks`, or the remote snapshot's items as `Track`s with stable ids.
- Build `JumpToFileIndex` (#0175) from it with `JumpToFileEntry(artist: track.artist, title: track.title, album: track.album ?? "", fileName: fileName)`. `fileName` is `url.lastPathComponent` when `case .file(let url) = track.source` and `url.isFileURL`, else "". Remote rows carry `URL(string: mediaID)`, which isn't a file URL.
- Build the index off the main actor: `Task.detached(priority: .userInitiated)`. `Track` and `JumpToFileIndex` are `Sendable`; build the entries on main, then hand them off.
- **Filtering:** each `controlTextDidChange` cancels the previous filter task. Then `Task.detached { index.matches(query, isCancelled: { Task.isCancelled }) }`. Back on the main actor, if the result is non-nil and the query is still current: store `results: [Int]`, `reloadData()`, and select the first row (or keep the selection by `Track.id` if that row is still in the results).
- **Live updates:** while the panel is visible, watch `model.playlist.tracks` with `withObservationTracking` (re-arm in `onChange`, hop to `@MainActor` as `QueueAutosaver.observe()` does). On a change, rebuild the index and filter again with the current text. Also watch `model.queueRowsSource` for the empty-state text. Stop watching when the panel closes (`NSWindow.willCloseNotification`).

**Keys** (`NSSearchFieldDelegate.control(_:textView:doCommandBy:)`; return true when handled)

- `moveUp(_:)` / `moveDown(_:)`: move the table selection by one row and `scrollRowToVisible`. Focus stays in the field.
- `scrollPageUp(_:)` / `scrollPageDown(_:)` / `pageUp(_:)` / `pageDown(_:)`: move by the number of visible rows.
- `insertNewline(_:)`:
  - If `NSApp.currentEvent?.modifierFlags.contains(.shift)`, it's ⇧Return. Return true and do nothing until #0180 wires Queue.
  - Otherwise `playSelected()`.
- `cancelOperation(_:)` (Esc): close the panel. The search field's own Esc clears the text first, so handle `cancelOperation` here before it does, and close.

**Play** (`playSelected`)

- The row is the first selected result, else the first result, else nothing (beep).
- `let index = results[row]`, then `model.playlist.playRow(index)`, then `model.playlist.reveal(index)`. `playRow` already takes the local path (`onPlayLocal` + `player.play(at:)`) or the remote one (`onPlayRemote`). Don't add another play path.
- Then close the panel. "Close after Play" is hard-coded on; note it in `## Fix`.
- Play uses only the first of several selected rows.

**Show** (`show(model:)`)

- Make the panel on first use. `makeKeyAndOrderFront(nil)`, then `makeFirstResponder(searchField)`, then `searchField.selectText(nil)`, so the previous text is kept and fully selected (Winamp did this).
- Filter again with the kept text, since the queue may have changed while the panel was hidden.
- Showing an already-open panel just brings it forward and focuses the field.

### By hand (the App target has no unit tests; list these in the resolution notes)

1. `J` from the main window, the equalizer and the playlist editor (also with a row selected) opens the panel with the cursor in the field.
2. A bare `J` in the Library window doesn't open the panel (it types into the search field when that has focus). ⌘J from the menu bar opens it from any window.
3. With a 10,000-row local queue, typing `daft tech` finds "Daft Punk - Technologic" with no visible lag. ↑/↓ and Page Up/Down move the list while typing.
4. Return plays it and closes the panel. The playlist editor shows the row selected and scrolled into view. A double-click plays too.
5. Reopening shows the last text, all selected. Esc closes. Clicking another window leaves the panel open.
6. With a Music Assistant speaker selected, the panel lists the remote queue and Play plays that row on the speaker. With This Mac fed by Music Assistant it lists that queue.
7. A speaker of a backend with no queue listing shows "This speaker's queue can't be listed".
8. Adding or removing tracks while the panel is open updates the list.
9. With Always On Top on, the panel stays above the skinned windows.
