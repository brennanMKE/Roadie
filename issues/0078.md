## Description

The options button at the left of the main window's title bar (`MAIN_OPTIONS_BUTTON`, `App/TitleBarView.swift:19`) has an empty action. In Winamp it opens the main menu (play file, play location, windows, skins, options such as time elapsed/remaining, always on top, double size, EQ and playlist toggles, playback, exit). Right-clicking the main window opens the same menu in Winamp.

Expected: clicking the options button, or right-clicking the main window, opens an `NSMenu` with the Winamp entries SkinAmp supports, wired to existing `PlayerModel` actions (open, add, open skin, the window and shade toggles, time elapsed/remaining, transport). Entries for features not built yet (for example double size before #0079) are left out rather than shown disabled.

## Plan

**Approach.** Keep the menu's contents as plain data in SkinKit, where tests can reach them, and build the `NSMenu` from that data in one place on the app side. The options button and a right-click both use that one builder. #0079, #0080, #0081 and #0082 then add entries by adding a command case, a state field and an entry, without touching the AppKit code.

1. **Menu model (SkinKit, no AppKit).** New file `Packages/SkinKit/Sources/SkinKit/Menus/MainMenu.swift`:
   - `public enum MainMenuCommand: Hashable, Sendable`: `about, openFiles, addFiles, toggleEQWindow, togglePlaylistWindow, openSkin, nextSkin, previousSkin, randomSkin, timeElapsed, timeRemaining, toggleMainShade, toggleEQShade, togglePlaylistShade, toggleRepeat, toggleShuffle, previous, play, pause, stop, next, quit`.
   - `public struct MainMenuState: Equatable, Sendable`: `timeMode` (the existing SkinKit `TimeMode`), `isEQWindowOpen`, `isPlaylistWindowOpen`, `isMainShaded`, `isEQShaded`, `isPlaylistShaded`, `isRepeating`, `isShuffled`, `canNavigateSkins`. Give it a memberwise init with defaults so siblings can add fields without breaking callers.
   - `public struct MainMenuShortcut: Equatable, Sendable { key: String; modifiers: Modifiers }` (an `OptionSet` with command, option, shift, control). In a popped-up menu these are display only. They show the shortcut the menu bar already binds, so the two must match.
   - `public struct MainMenuItem`: `command`, `title`, `state: CheckState` (`.off/.on`; time mode uses `.on` on the current choice, which works as a radio pair), `isEnabled`, `shortcut: MainMenuShortcut?`.
   - `public indirect enum MainMenuEntry: Equatable`: `.item(MainMenuItem)`, `.separator`, `.submenu(title: String, [MainMenuEntry])`.
   - `public enum MainMenu`: `static func entries(_ state: MainMenuState) -> [MainMenuEntry]`. Each submenu comes from its own static (`skinsEntries`, `optionsEntries`, `playbackEntries`), so #0080 can show `playbackEntries` in the menu bar's Playback menu and #0079's V button can get its own `visualizationEntries`.
   - Layout (Winamp 2.x and Webamp `MainContextMenu`, trimmed to what SkinAmp supports): **About SkinAmp** · sep · **Play File…** (⌘O) · **Add to Playlist…** (⌥⌘O) · sep · **Equalizer** ✓ (⌘2) · **Playlist Editor** ✓ (⌘3) · sep · **Skins ▸** (Open Skin… ⇧⌘O, sep, Next Skin ⌘], Previous Skin ⌘[, Random Skin ⇧⌘R, the last three disabled when `!canNavigateSkins`, matching `SkinsCommands`) · **Options ▸** (Time Elapsed / Time Remaining radio, sep, Windowshade ⌃⌘W ✓, EQ Windowshade ⌃⌘E ✓, Playlist Windowshade ⌃⌘P ✓, sep, Repeat ✓, Shuffle ✓) · **Playback ▸** (Previous, Play, Pause, Stop, Next; no shortcuts until #0080) · sep · **Exit** (⌘Q).
   - Leave out (per the Description): Play Location (no streams), Main Window toggle, Always on Top and Double Size (#0079), Visualization (#0079), Preferences / Skin Library / Library (these open SwiftUI scenes; that needs `openWindow` plumbing from AppKit, which is out of scope here), and Seek/Volume (#0080).

2. **Dispatch (app).** New file `App/PlayerModel+MainMenu.swift`, following the pattern of `PlayerModel+Equalizer.swift`:
   - `var mainMenuState: MainMenuState`, built from `timeMode`, `isEQWindowOpen`, `isPlaylistWindowOpen`, `isMainWindowShaded`, `isEQWindowShaded`, `isPlaylistWindowShaded`, `isRepeating`, `isShuffled` and `skinBrowser.canNavigate`.
   - `func perform(_ command: MainMenuCommand)`: one exhaustive `switch` onto existing calls: `openFiles(replace:)`, `openSkin()`, `skinBrowser.next/previous/random()`, the `toggle*` calls, `previous/play/pause/stop/next`, `NSApp.orderFrontStandardAboutPanel(nil)` and `NSApp.terminate(nil)`. For time mode, add a small `setTimeMode(_:)` next to `toggleTimeMode()` in `App/PlayerModel.swift` (persisting the same key), so choosing the current mode leaves it unchanged.

3. **NSMenu builder (app).** New file `App/Window/MainMenuBuilder.swift`, `@MainActor enum MainMenuBuilder`:
   - `static func menu(_ entries: [MainMenuEntry], perform: @escaping (MainMenuCommand) -> Void) -> NSMenu` maps entries to `NSMenuItem`s (`state`, `isEnabled`, `keyEquivalent` plus `keyEquivalentModifierMask`, and submenus via `NSMenu` / `setSubmenu`), with `autoenablesItems = false` so `isEnabled` is respected.
   - Use a private `ClosureMenuItem: NSMenuItem` whose target is itself. That way nothing outside the menu has to hold the targets.
   - Write no other `NSMenu` code anywhere for the main menu.

4. **Showing the menu (app).** In `App/Window/SkinWindowController.swift`:
   - `func popUpMainMenu(atSkinPoint p: CGPoint)` builds `MainMenuBuilder.menu(MainMenu.entries(model.mainMenuState), perform: model.perform)` and calls `menu.popUp(positioning: nil, at:in: hosting)`. The point is `p` × `model.scale`; `NSHostingView` is flipped, so skin y maps directly.
   - `func popUpMainMenu(for event: NSEvent)` uses `NSMenu.popUpContextMenu(_:with:for: hosting)`.
   - Install right-click only for `kind == .main`, so the EQ and playlist windows behave as before: in `App/Window/SkinWindow.swift`, add `var onRightMouseDown: ((NSEvent) -> Bool)?`. In `sendEvent`, when the event is `.rightMouseDown`, or `.leftMouseDown` with `.control` held (the Mac's secondary click), and the hook returns true, swallow the event. Otherwise call `super` as today. The main controller sets the hook to pop the menu and return true.

5. **Options button.** In `App/TitleBarView.swift`, give `button("MAIN_OPTIONS_BUTTON", .options)` the action `window?.popUpMainMenu(atSkinPoint: CGPoint(x: rect.minX, y: rect.maxY))`, which opens the menu under the button, as Winamp does. `TitleBarView` is shared with `MainShadeView` and draws the options button on the key window in both modes, so this one change covers normal and shade mode. Right-click works in both modes through the window hook.

6. **No `project.yml` change is needed.** The new SkinKit file is picked up by the existing `SkinKit` target and the new test by `SkinKitTests`. Run XcodeGen as usual for the new app files; `sources: [App]` globs them.

**Tests.** Add `Packages/SkinKit/Tests/SkinKitTests/MainMenuTests.swift` (Swift Testing, like the other SkinKitTests):
- `topLevelOrder`: the titles and separators in order, and the three submenus present.
- `timeModeRadioChecksCurrentMode`: elapsed gives Time Elapsed `.on` and Time Remaining `.off`, and the reverse.
- `windowTogglesReflectState`: the Equalizer and Playlist Editor checks follow `isEQWindowOpen` / `isPlaylistWindowOpen`.
- `shadeRepeatShuffleChecksReflectState`.
- `skinNavigationDisabledWithoutIndex`: Next/Previous/Random are disabled when `canNavigateSkins` is false, and Open Skin… stays enabled.
- `everyCommandAppearsOnce`: flatten the tree; no command is duplicated.
- `unsupportedEntriesAreAbsent`: no "Double Size", "Always On Top" or "Play Location" titles.
- `shortcutsMatchMenuBar`: the expected `MainMenuShortcut` for Play File (⌘O), Add (⌥⌘O), Open Skin (⇧⌘O), Equalizer (⌘2), Playlist (⌘3) and the three windowshades (⌃⌘W, ⌃⌘E, ⌃⌘P).

The app target has no unit-test bundle, so `PlayerModel.perform`, `MainMenuBuilder` and the pop-up wiring are checked by the build, the launch and the host checklist below. Keep `perform` a plain exhaustive switch, so the compiler catches a missing case.

## Resolution notes

> 🟢 Resolved 2026-10-18 — The options button and a right-click or Control-click on the main window now open a Winamp-style main menu built from SkinKit's `MainMenu` data and wired to existing `PlayerModel` actions.

## Root cause

`TitleBarView` gave `MAIN_OPTIONS_BUTTON` an empty action, and the main window had no secondary-click handling, so there was no main menu at all.

## Fix

Followed the plan. `MainMenu` (SkinKit) describes the menu as data (`MainMenuCommand`, `MainMenuState`, `MainMenuShortcut`, `MainMenuItem`, `MainMenuEntry`, with `skinsEntries`/`optionsEntries`/`playbackEntries` as separate statics). `PlayerModel.mainMenuState` and `perform(_:)` (one exhaustive switch) connect it to the model; `setTimeMode(_:)` was added beside `toggleTimeMode()`. `MainMenuBuilder` is the only `NSMenu` code, using self-targeting `ClosureMenuItem`s and `autoenablesItems = false`. `SkinWindowController.popUpMainMenu(atSkinPoint:)` opens it under the options button; `SkinWindow.onRightMouseDown` (right-click, or Control-click) is installed only for the main window and opens it at the pointer via `popUpMainMenu(for:)`. No deviations. VM run id: `20261018-205825-49769`.
