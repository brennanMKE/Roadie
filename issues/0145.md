## Root cause

The playlist editor showed a Music Assistant queue read-only (#0144). `QueueEdit` had only `.play`, so the remove, crop, clear, drag and Delete actions on a remote queue only showed the "Not for Music Assistant queues" notice.

## Fix

- **API:** `QueueEdit` gains `.remove(items:)`, `.move(itemID:shift:)` and `.clear`. A new `QueueEditError.buffered` error has the marquee text "Track already buffered".
- **Music Assistant:**
  - Remove sends one `player_queues/delete_item` per item, by `queue_item_id`, highest index first.
  - Move sends `player_queues/move_item` with `pos_shift`. Clear sends `player_queues/clear`.
  - A server error whose details name `IndexError` or buffering becomes `.buffered`, and `map` passes that error through.
- **Plan:** `QueueEditPlan` in `LibraryBrowser/QueueRows.swift` turns a selection into edits:
  - Remove and crop list the rows to delete, highest index first, and never include the current row. Remove reports when it left the playing row out.
  - A drag of more than one row is refused. A single-row drag is clamped to the ends of the queue.
  - `apply` builds the optimistic snapshot.
- **App:**
  - `PlaylistModel` routes REM (remove selected, crop, remove all), LIST › New, the Delete key and single-row drags to the remote queue.
  - It shows each edit at once and sends edits one after another. If the server refuses an edit, the rows go back to how they were and the marquee shows the error.
  - The marquee also says "Can't remove the playing track" and "Drag one track at a time".
  - The MISC Sort menu entries are disabled on a remote queue, with the existing notice.
  - `PlayerModel` wires `onEditRemote` and `onRemoteNotice` (additive).

Deviations from the plan:
- The request builders live in `MusicAssistantBackend+Queue.swift`, not `MARequest.swift`, to keep clear of parallel edits.
- `StubMusicBackend` and `PlaylistWindowView` are unchanged: the protocol default covers the stub, and `run` already goes through `PlaylistModel`.
- The buffered refusal text is shortened to fit the marquee's 31-character limit.
