## Root cause

Settings had no way to configure Music Assistant: no server list, no per-server Keychain token, no Test Connection, and no Music Assistant entry in the source picker. The client and backend from #0061 only took a fixed address in tests. The user's server is also moving to a Tailscale endpoint, so the address rules had to work with App Transport Security as it is.

## Gotchas

- A public IP address over http counts as "local" for ATS (any IP literal), so the app accepts `http://<public-ip>`; the classification follows ATS, not the network.
- `.env` currently holds an `http` address. If it is a public DNS name, the app will refuse it (error text above); switch the server entry to `https://...` or an IP before the host checklist.
- The Python recorder cannot trust a private CA unless `SSL_CERT_FILE` points at it; `tailscale serve` certificates are publicly trusted and need nothing.
- `UserDefaults` is not `Sendable` in this SDK, so `MusicAssistantServerStore` holds it as `nonisolated(unsafe)`.

The `networks` (SSID) field is already in the stored model, with no UI yet, so #0075 needs no migration.
- **Bonjour is dropped.** #0060 found that the user's server does not advertise `_music-assistant._tcp` (`docs/ma-protocol-notes.md` §10). The standalone server's zeroconf type is unconfirmed. Browsing would also trigger the Local Network prompt as soon as Settings opens. Manual entry is the only path, `NSBonjourServices` stays **absent**, and `check-info-plist.sh` keeps `absent NSBonjourServices`. This deviates from the acceptance criterion, deliberately: say so in `## Fix`. If a later issue confirms an advertised type on a real install, it adds discovery and the one key together.
- **ATS: `NSAllowsArbitraryLoads = true` replaces `NSAllowsLocalNetworking`.** See section 7 for the reasoning and the trade-off. Both keys can't be kept: on macOS 10.12+ the presence of `NSAllowsLocalNetworking` makes ATS **ignore** `NSAllowsArbitraryLoads`.
- **Token rules (stricter than #0011).**
  - Keychain only, through the existing `KeychainMusicAssistantTokenStore` (service `com.brennanmke.SkinAmp.musicAssistant`, which #0074 relies on), with one item per server: `account` = the configuration's UUID string.
  - **The token is never read back into the UI.** The field is write-only. Empty means "keep what is stored", and a placeholder says whether one is stored. Existence comes from an attribute-only Keychain query (`kSecReturnAttributes`, no `kSecReturnData`), which never prompts or decrypts.
  - A failed read or existence check never deletes. Only an explicit **Remove Token**, **Remove Server**, or the mismatch flow's **Replace With This Server** deletes.
  - The token is never logged, put in a URL, or shown.
  - **The token leaves the process only after `server_id` verification.** Test Connection first reads `/info` (no token), then connects with `expectedServerID` = that id. The client compares it with the socket's first message before `auth` (#0061). The backend refuses to connect to any configuration without a learned `server_id`.
- **The MA settings get their own tab.** It holds a list plus an editor, which is too tall for the Library form at 480 pt. Tabs: Library (picker, folder, index), **Music Assistant**, Plex, Cache, Skins. #0074 §8 (f) already allows this and removes Plex and Cache later. The Library tab's picker gains nothing new beyond the MA radio item, which comes from `sources`.
- **No I/O at launch.** `PlayerModel.init` reads defaults only. Keychain access happens only when Settings › Music Assistant appears (existence queries) and on connect or Test Connection (one read). The network is used only on Test Connection, the window's connect, or the #0067 probes, which never run at launch. In the guest no server is configured, so nothing can prompt.

Rules, each pinned by a test (section 9):

- **Address edits.** A change to the address keeps the learned `serverID`, because the same server may have moved. The next connect then proves or refutes it, and a mismatch reads "a different server answered". Every list mutation saves, then recomputes `active.set(firstVerified(in:))`. When that returns true, it calls `onActiveServerChanged`.
- **Dirty token.** `tokenDirty` is per selected server. Changing selection commits a dirty non-empty token first. An empty dirty field commits nothing: empty means keep. Only `removeToken()` deletes.
- **`testConnection()`** for the selected server is one `Task`, cancelled by any input change, re-selection, or `disappeared()`. A cancelled task never writes state.
  1. Parse the address, or fail with `.invalidAddress`.
  2. `MusicAssistantConnectionTest.info(at:)` calls `MusicAssistantClient.serverInfo(at:http:timeout: 5 s)`. A transport error maps to `.unreachable` or `.blockedByATS`. A schema below `minimumSchemaVersion` fails with `.schema`.
  3. If a stored `serverID` exists and differs from `info.serverID`, fail with `.serverMismatch(foundName: info.name)`. No token is read and no socket is opened.
  4. The token is the typed one when dirty and non-empty, else `tokenStore(id).load()`. A load error fails with `.keychain` (nothing deleted). nil fails with `.needsToken(foundName:)`.
  5. `MusicAssistantConnectionTest.connect(baseURL, token, expectedServerID: info.serverID)` creates a `MusicAssistantClient`, connects, then `disconnect()`s.
  6. On success: store `address.serverID = info.serverID`, set the name to `info.name` if it is still the default, commit a typed token (save), and set status `.connected(name:version:)`. On `.tokenRejected`, keep the stored token and identity (the user may have typed a wrong one; nothing is deleted).

### 7. App Transport Security, decided

- **Problem.** `URLSession` applies ATS to `ws://` and `http://` (#0061 Gotchas). `NSAllowsLocalNetworking` covers single-label names, `.local` and local IPs only. Over http, the user's server (reached by a public DNS name) and Tailscale (`*.ts.net` MagicDNS or `100.x`) fail with -1022.
- **Options considered.**
  1. *Per-domain `NSExceptionDomains`*: the hosts are user-entered and unknown at build time. Hard-coding the user's domain would also put the `.env` host into the tree, which #0061's review checks against.
  2. *`NSAllowsLocalNetworking` + `NSExceptionDomains { ts.net: NSIncludesSubdomains, NSExceptionAllowsInsecureHTTPLoads }`*: the narrowest key set that covers MagicDNS. It still blocks the user's public-DNS server over http, so it fails the requirement. It may also not cover `100.x` addresses.
  3. *Require https/wss for every non-local host*: MA's port 8095 serves http only, so this needs a reverse proxy with a certificate on every server. Not the user's setup today.
  4. *Bypass ATS with Network.framework* (an `NWConnection` with `NWProtocolWebSocket`, plus a hand-written HTTP/1.1 GET for `/info` and artwork): a large, risky transport rewrite for a policy problem.
  5. *`NSAllowsArbitraryLoads = true`*: works for every address the user can enter.
- **Decision: option 5, alone.** The dict holds only `NSAllowsArbitraryLoads = true`; `NSAllowsLocalNetworking` is removed, since keeping it would silently disable the exemption.
- **The trade-off, to document in `## Fix` and in the doc comment of `MusicAssistantAddressSecurity`.** ATS no longer stops an accidental cleartext load anywhere in the app. The app is unsandboxed, distributed outside the App Store, and its only cleartext peers are the addresses the user typed. Its other URLs are https literals; check with `git grep -n "http://" App Packages` that no non-test http literal exists. The client already refuses redirects (`NoRedirects`).
- **Compensations in-app.**
  - The classification above, with the "Not encrypted" note for `.cleartext`.
  - An `https://` address is used as `wss://` automatically. The transport already maps it.
  - The token is only sent after the identity check.
- **Revisit.** If every server later sits behind TLS or Tailscale, switch to option 2 or 3 and tighten the check script.
- **`scripts/check-info-plist.sh`**, exactly:
  - `plutil -extract NSAppTransportSecurity.NSAllowsArbitraryLoads raw -expect bool`, then `expect … true`.
  - `absent` for `NSAppTransportSecurity.NSAllowsLocalNetworking`, `NSAppTransportSecurity.NSExceptionDomains`, `NSAppTransportSecurity.NSAllowsArbitraryLoadsInWebContent` and `NSAppTransportSecurity.NSAllowsArbitraryLoadsForMedia`.
  - `absent NSBonjourServices`.
  - The description must contain both `Music Assistant` and `Plex` (#0074 later drops Plex).
  - Update the header comment to name #0063. The `.wsz` lines are unchanged.

### 8. Edge rules

- Two configurations may share a base URL (two locations each with `homeassistant.local:8095`). The `server_id` tells them apart, and the Keychain account is the UUID, not the host.
- Removing the active server moves `active` to the next verified one, or nil. nil makes `isConfigured` false, and #0067 falls back.
- A corrupt defaults blob loads as an empty list and is **not** overwritten until the user changes something, which mirrors `QueueStore`.
- The first `appeared()` with N servers issues N attribute queries, which never prompt. No query issues a data read.

### 12. Risks and gotchas

- **`NSAllowsArbitraryLoads` is ignored if `NSAllowsLocalNetworking` (or `…InWebContent`/`…ForMedia`) is present.** The check script asserts their absence. A green VM run does not prove ATS behaviour; checklist step 5 does.
- **#0074's plan says `NSAllowsLocalNetworking` stays.** It is superseded by this decision. #0074 §10 keeps the ATS lines "as #0063 left them", so its implementer must not re-add the key. Note this in `## Fix` so the orchestrator can amend #0074's §2.
- **Bonjour dropped against the criterion.** Recorded in Scope; the user may ask for it back.
- **Ad-hoc signing and the Keychain.** A rebuilt binary may be treated as a different app, so the data read on connect can prompt once per build. Attribute queries don't prompt. Tests never touch the real Keychain (`KeychainMusicAssistantTokenStore` keeps only its opt-in host test).
- **Trust on first use is a user action.** The first `server_id` comes from whatever answers when the user presses Test Connection. The socket re-checks the same id before `auth`, so a DNS change between `/info` and the socket cannot redirect the token.
- **`reload` versus fallback.** If the active MA server changes while the fallback has the folder active, `reload("musicAssistant")` returns false and nothing happens; the next probe uses the new server. Calling `fallback.retryNow()` is #0075's job.
- **Swift 6.** `MusicAssistantActiveServer` is `Sendable` through `OSAllocatedUnfairLock`. The backend's provider closures are `@Sendable` and capture only it and the store type. The settings model is `@MainActor` and its tasks capture `[weak self]`.
- **Plex still exists here.** The picker lists MA, Plex and Local Folder, and `FallbackText` strings name all three until #0074.
