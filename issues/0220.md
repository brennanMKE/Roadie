## Description

Umbrella for milestone **M17: Genres**. The Music Assistant web app has a "Browse by Genre" row (Classical, Experimental, Electronic, Rock, Punk, Podcast, Dance, Pop); Roadie's Library has no genres at all, so music the user finds that way in MA can't be found in Roadie. The user, 2026-10-27: "What I was seeing is genres. … Can we do this?" (screenshot: [0220/ma-browse-by-genre.png](0220/ma-browse-by-genre.png)).

What the user's server has (read-only look, 2026-10-27, server schema as in `docs/ma-protocol/commands.json`):

- `music/genres/count` → 113; `music/genres/library_items {limit: 100, offset: 0}` returned **99** (not 100): find out why before paging on the count.
- Most genres are empty. `music/genres/media_counts {genre_ids}` gives per-type counts; about 30 have any music. Largest: Classical (649 tracks, 3 artists, 2 playlists), Experimental (575 tracks, 5 albums), Electronic (403 tracks, 39 albums, 33 artists), Rock (266 tracks, 83 albums, 64 artists), Punk (230 tracks, 63 albums, 50 artists), Dance (215 tracks), Pop (65 tracks, 33 albums, 32 artists), Christmas Music (49), Soundtrack (25).
- Many are podcast/audiobook categories (Business, True Crime, Self Help, …), and some names appear twice with different ids (Business 61/81, Comedy 13/62, History 67/88, Science 73/94, Sports 75/97, Technology 76/98, Religion & Spirituality 72/92).
- Genre item keys: `available, external_ids, favorite, genre_alias_count, is_playable, item_id, media_type, metadata, name, provider, provider_mappings, sort_name, uri, version`.
- Reads that exist: `music/genres/library_items`, `count`, `get`, `media_counts`, `tracks {item_id, limit}`, `albums {item_id, limit}`, `overview {item_id}`; `music/{artists,albums,tracks}/library_items` also take a `genre` filter.

Scope (proposed to and accepted by the user):

1. A **Genres** section in the Library window listing only genres that have music, ordered by size, with counts; duplicate names merged.
2. Selecting a genre shows its albums, artists and tracks; rows behave like the rest of the Library (play, play next, add to queue, drag to the playlist editor).
3. Play / shuffle a whole genre.
4. Groundwork: record real genre responses with the read-only recorder, teach `ScriptedMusicAssistant` and the stub genres, unit tests and a UI test, the §5 feature inventory row.

Open question for the user: hide podcast/audiobook genres even when they have content (none do today)? (Default in the plans: hide; see Design below.)

Also in this milestone: [#0221](0221.md), a playlist bug found during the same look at the server; and [#0226](0226.md)–[#0229](0229.md), making the playlist editor's commands reachable on any skin (user report 2026-10-27: on 100cc Class the user couldn't find LIST › Load).

## Design

[docs/design/genres.md](../docs/design/genres.md) (2026-10-27): what the server returns, the UI (Genres after Albums in the sidebar; genres with music only, by track count, duplicate names merged; a detail with Albums | Artists | Tracks and Play / Shuffle), the backend API (`BackendCapabilities.genres`, `MediaKind.genre`, `LibraryGenre`, `genres()`, per-genre lists, `play(…, shuffled:)` over `play_media {shuffle}`), paging and the 99-of-113 probe, risks, and the open questions below.

**Folder library:** no genres in M17 (its index reads no genre tags; adding them means an index version bump and a reindex). The API is backend-neutral, so it's a follow-up issue if wanted (design §4.4).

Open questions for the user (design §6; the plans use the defaults):

1. Podcast and audiobook genres: hidden, even with content (Roadie doesn't play podcasts or audiobooks). This answers the question above.
2. A genre's playlists (Classical has 2): not shown; the accepted scope is albums, artists, tracks.
3. Order: by size, no A–Z toggle.
4. Folder library genres: not in M17.
5. Play on a huge genre: whatever Music Assistant's `play_media` does; Roadie's own fallback caps at 2,000 tracks.

Scope note: #0221's root cause includes the recorder. `scripts/record-ma-fixtures.py` rewrites every playlist `owner` to `"user"`, which hid the server's real `"Music Assistant"`. #0221 keeps that one value verbatim from now on.
