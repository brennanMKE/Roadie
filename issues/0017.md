# 0017 — Duplicate artist spellings and missing album art clutter the browser

| | |
|---|---|
| **Status** | open |
| **Module** | PlexKit / App |
| **Platform** | macOS |
| **First seen** | 2026-10-12 |

## Description

Group artists whose names differ only by `&`/`and`, a trailing `;`, or case, and show a placeholder for albums without a `thumb`.

## Acceptance criteria

- Normalization is a pure function with unit tests using the real examples (`AJ & Jordan` / `AJ and Jordan`).
- Album art loads from the `/photo/:/transcode` URL at thumbnail size and is cached in memory.

## Plan

### Scope and decisions

This issue builds on #0062 (`MusicBackendKit`, `PlexBackendKit`), which lands first, and is written against its `## Plan`: `LibraryArtist` / `LibraryAlbum` / `LibraryTrack` with `artwork: ArtworkRef?`, `Page` / `PageRequest`, `MusicBackend.artwork(_:maxPixels:)` returning bytes with the token in the request header, and `PlexBackend` mapping an album's art as `thumb ?? parentThumb`. It adds two things: artist de-duplication as pure, source-neutral code, and a bounded in-memory artwork cache with a placeholder. It writes no browser window (#0016) and no play/enqueue (#0018); it defines the seam those use.

- **Normalization and grouping live in `MusicBackendKit`** (Foundation only, like the rest of that target), not in `PlexBackend` and not in the app. Three reasons: every source flows through the same `LibraryArtist` values, so grouping at the browser layer covers Plex, Music Assistant and the folder backend alike; the key function is reusable *inside* a backend where de-duplication at the source is the right thing (the folder backend, #0065, will key artists by `ArtistName.key` when it builds artists from tags, so it never emits two spellings; Plex cannot, since its ids are the server's); and the functions are pure and unit-tested without a backend. `PlexBackend` keeps returning the server's spellings unchanged: the raw `LibraryArtist` ids are still needed to fetch each member's albums.
- **Grouping is incremental across pages.** Plex sorts artists by sort title, so `AJ & Jordan` and `AJ and Jordan` (or `Foo` / `Foo Bar` / `Foo;`) can land on different pages. `ArtistGrouper` is an accumulator the browser feeds page by page; a group gains members as later pages load. The same function, called once, groups search results.
- **A merged artist's albums come from every member id.** `albums(of: ArtistGroup)` fans out one `albums(of:)` per member, walks every page of each, concatenates in member order and drops duplicate album ids.
- **The artwork cache is an actor in a new target, `MusicLibraryKit`**, that depends on `MusicBackendKit` and decodes with ImageIO. It cannot live in `MusicBackendKit` (which #0062 keeps Foundation-only so `MusicAssistantKit` can depend on it) and cannot live in `App/` (the VM runs package tests only; the app has no test target). Hand-written LRU rather than `NSCache`: `NSCache` evicts at times of its own choosing and cannot coalesce in-flight requests, so tests of bounds and single-fetch would be flaky. The cache stores decoded thumbnails (`CGImage`), keyed by `ArtworkRef`, bounded by bytes and count, and remembers refs that have no art so the placeholder shows without a second request.
- **Thumbnail size is one bucket, `ArtworkCache.thumbnailPixels = 200`.** 200 px covers a 100 pt cell at 2×, matches Plex's own default thumbnail, and keeps the budget honest (200² × 4 B ≈ 160 KiB per image; the 32 MiB default holds about 200 images, far more than any visible list). The browser (#0016) shows rows and grids at or under 100 pt. The cache passes `maxPixels: 200` to the backend *and* decodes with `kCGImageSourceThumbnailMaxPixelSize = 200`, so a backend that returns bigger bytes (embedded art from the folder backend) is downsampled on the way in.
- **The placeholder is a SwiftUI view in `App/`**, shown immediately for every cell, kept when the item has no `artwork` ref, when the cache answers `nil`, and until the image arrives.
- **Nothing here builds a URL or sees a token.** The cache only calls `backend.artwork(ref, maxPixels:)`; `PlexBackend` (#0062) puts the token in `X-Plex-Token` and uses its own uncached ephemeral session. An end-to-end test with `PlexBackend` over `StubURLProtocol` proves the recorded `/photo/:/transcode` URL never carries the secret. Logs carry counts only, never a ref, URL or error body.
- **Verification is `scripts/run-tests-vm.sh --launch` only.** No `swift test`, `xcodebuild` or app launch on the host. No test opens an audio device, nothing reaches joe, no token exists in the guest.

Assumptions where #0062's API could still move (check its landed code first; adjust names, not the design): `ArtworkRef` is `Hashable` with a `rawValue: String`; `MusicBackend.artwork(_:maxPixels:)` throws `MusicBackendError` (`.notFound`, `.unsupported`, `.unreachable`, `.unauthorized`, `.backend`); `Page` has `nextOffset` and `PageRequest(offset:limit:)`; `PlayerModel` holds `let backend: any MusicBackend`. If #0062 added a stub backend to a shared target, use it instead of the `FakeBackend` described in section 6.

### 2. `MusicBackendKit`: artist-name normalization (`Sources/MusicBackendKit/ArtistName.swift`)

```swift
/// Pure functions over artist names. `key` decides which spellings are the same artist; `display` is what the UI shows.
public enum ArtistName {
    /// Shown when a name is empty after cleaning.
    public static let unknown = "Unknown Artist"

    /// The grouping key: case-folded, `and` ⇄ `&`, trailing `;` dropped, whitespace collapsed. Idempotent.
    public static func key(_ name: String) -> String

    /// The name as written, minus trailing `;` and stray whitespace. `unknown` when nothing is left. Idempotent.
    public static func display(_ name: String) -> String
}
```

`display(name)`, in order:

1. Trim whitespace and newlines.
2. Drop every trailing `;` and the whitespace before it, repeatedly (`"AJ & Jordan;"`, `"AJ & Jordan ;"`, `"AJ & Jordan;;"` → `"AJ & Jordan"`).
3. Collapse each run of whitespace to one space (`"10,000   Maniacs"` → `"10,000 Maniacs"`).
4. Empty → `unknown`.

`key(name)`, in order:

1. `display(name)`; if it is `unknown` return `""`.
2. Put a space on both sides of every `&`, then collapse whitespace again (`"AJ&Jordan"` → `"AJ & Jordan"`).
3. Split on spaces; replace each token that case-insensitively equals `and` with `&` (only whole tokens: `Sandy Denny`, `Band of Horses`, `Andy` are untouched).
4. Join with single spaces and fold with `.folding(options: [.caseInsensitive, .widthInsensitive], locale: nil)`.

Not normalized, on purpose: leading `The` (`Beatles` and `The Beatles` stay apart), diacritics (`Björk` ≠ `Bjork`), other conjunctions (`+`, `feat.`), and any punctuation other than a trailing `;`. Each is a possible follow-up; none is in the issue, and every extra rule is a chance to merge two real artists.

Real examples from `docs/plex-music-library.md`, which the tests use verbatim: `AJ & Jordan` and `AJ and Jordan` share the key `aj & jordan`; `AJ & Jordan;` has that key too and displays as `AJ & Jordan`; `aerosmith` and `Aerosmith` share `aerosmith`. From the recorded fixtures, `10,000 Maniacs` keys to `10,000 maniacs` (the comma stays).

### 3. `MusicBackendKit`: grouping (`Sources/MusicBackendKit/ArtistGrouping.swift`)

```swift
/// One artist as the UI shows it: every `LibraryArtist` whose name keys the same.
public struct ArtistGroup: Identifiable, Hashable, Sendable {
    /// `ArtistName.key` of the members; `"unknown"` for the empty key.
    public var id: String
    /// `ArtistName.display` of the first member seen. Fixed for the life of the group so rows do not rename as pages load.
    public var name: String
    public var sortName: String?            // first member's
    /// Members in the order they were seen (backend order); never empty.
    public var members: [LibraryArtist]
    /// The first member's artwork, or the first later member that has one.
    public var artwork: ArtworkRef?
    public var memberIDs: [MediaID] { members.map(\.id) }
    public var isMerged: Bool { members.count > 1 }
}

/// Accumulates artists page by page. Value type; the browser keeps one per listing.
public struct ArtistGrouper: Sendable {
    public init()
    /// Groups in first-seen order. Stable: a group keeps its position when later members join.
    public private(set) var groups: [ArtistGroup]
    /// Adds a page. An artist whose `id` was already seen is ignored (page overlap). Returns the ids of groups created or changed.
    @discardableResult public mutating func add(_ artists: [LibraryArtist]) -> Set<ArtistGroup.ID>
    public mutating func removeAll()
    /// One-shot grouping (search results).
    public static func group(_ artists: [LibraryArtist]) -> [ArtistGroup]
}
```

Rules: `groups` is backed by `[ArtistGroup.ID: Int]` (index) plus `Set<MediaID>` of seen ids. On `add`, for each artist: skip if seen; `key = ArtistName.key(name)`, `id = key.isEmpty ? "unknown" : key`; existing group → append to `members`, fill `artwork` if nil; else append a new group with `name = ArtistName.display(name)`. The total reported by `Page<LibraryArtist>.total` is the server's raw count and no longer matches `groups.count`; the browser shows the loaded count and keeps paging on `Page.hasMore`, not on group count.

Albums of a merged artist (`Sources/MusicBackendKit/MergedArtistAlbums.swift`):

```swift
extension MusicBackend {
    /// Every page of `albums(of:)` for one id, in order; stops at `nextOffset == nil`, an empty page, or `limit` items.
    public func allAlbums(of artist: MediaID, pageSize: Int = 200, limit: Int = 10_000) async throws -> [LibraryAlbum]
    /// All members' albums, concatenated in member order, duplicate album ids dropped. One failing member fails the call.
    public func albums(of group: ArtistGroup, pageSize: Int = 200) async throws -> [LibraryAlbum]
}
```

`albums(of group:)` runs the members in a `withThrowingTaskGroup`, collects `(memberIndex, albums)` and sorts by index before concatenating, so the result does not depend on which request finished first. Albums are left in each backend's own order (Plex: by year, then title); no client-side resort.

Where else `ArtistName.display` applies: the browser's album and track rows show `ArtistName.display(album.artistName)` / `(track.artistName)`, so a track under `AJ & Jordan;` reads `AJ & Jordan`. The skinned window's marquee is out of scope here (it shows `NowPlaying.artist` as the backend sends it).

### 4. `MusicLibraryKit`: the artwork cache (`Sources/MusicLibraryKit/ArtworkCache.swift`, `Artwork.swift`)

```swift
/// A decoded thumbnail. `CGImage` is immutable, so sharing it across actors is sound.
public struct Artwork: @unchecked Sendable {
    public let image: CGImage
    public var pixelWidth: Int { image.width }
    public var pixelHeight: Int { image.height }
    /// Decoded size in bytes (bytesPerRow × height), the cost used for the byte budget.
    public var byteCount: Int
}

public actor ArtworkCache {
    public static let thumbnailPixels = 200
    public static let defaultLimitBytes = 32 * 1024 * 1024
    public static let defaultLimitCount = 400

    public struct Statistics: Hashable, Sendable {
        public var hits, misses, fetches, failures, evictions: Int
        public var count: Int, bytes: Int
    }

    public nonisolated let maxPixels: Int
    public init(backend: any MusicBackend, maxPixels: Int = thumbnailPixels,
                limitBytes: Int = defaultLimitBytes, limitCount: Int = defaultLimitCount)

    /// The thumbnail for `ref`, or nil when there is none (show the placeholder). Never throws: a failure is a nil.
    /// Concurrent calls for the same ref share one fetch; a caller that is cancelled stops waiting, the fetch finishes
    /// and the result is cached for the next caller.
    public func image(for ref: ArtworkRef) async -> Artwork?
    /// Without fetching (tests, prefetch decisions).
    public func cached(_ ref: ArtworkRef) -> Artwork?
    public func clear()
    public var statistics: Statistics { get }
}
```

State: `entries: [ArtworkRef: Entry]` where `Entry { artwork: Artwork; lastUsed: UInt64 }`, a `tick: UInt64` incremented per touch, `bytes: Int`, `inFlight: [ArtworkRef: Task<Artwork?, Never>]`, and `missing: Set<ArtworkRef>` (bounded at `limitCount`; cleared wholesale when it overflows, and by `clear()`).

`image(for:)`:

1. Hit in `entries` → bump `lastUsed`, `hits += 1`, return.
2. In `missing` → `hits += 1`, return nil.
3. In `inFlight` → `await task.value` (a `Task`'s value is not cancelled by a cancelled awaiter).
4. Else `misses += 1`; create `Task { await self.fetch(ref) }` (unstructured, so cell cancellation does not abort it), store in `inFlight`, await it, remove it.

`fetch(ref)`: `fetches += 1`; `try await backend.artwork(ref, maxPixels: maxPixels)`; decode with `CGImageSourceCreateWithData` + `CGImageSourceCreateThumbnailAtIndex(source, 0, [kCGImageSourceCreateThumbnailFromImageAlways: true, kCGImageSourceThumbnailMaxPixelSize: maxPixels, kCGImageSourceCreateThumbnailWithTransform: true, kCGImageSourceShouldCacheImmediately: true])`; on success `insert(ref, artwork)`; on an undecodable body, `.notFound` or `.unsupported` → `missing.insert(ref)`, `failures += 1`, nil; on any other error (`.unreachable`, `.notConnected`, `.unauthorized`, `.backend`, `CancellationError`) → `failures += 1`, nil, *not* remembered, so the next appearance retries. Logging: `Logger(subsystem: "com.brennanmke.SkinAmp", category: "ArtworkCache")`, `debug` with the error's case name and the running counts; never the ref, a URL or the error text.

`insert`: add the entry, `bytes += byteCount`, then while `bytes > limitBytes || entries.count > limitCount` remove the entry with the smallest `lastUsed` (`evictions += 1`). A single image larger than the budget is still inserted and evicted on the next insert; with 200 px thumbnails that cannot happen. `clear()` empties `entries`, `missing` and the counters' `count`/`bytes` (not the history counters) and leaves `inFlight` alone (those tasks insert when done, which is correct).

Decode runs inside the actor; a 200 px JPEG decodes in well under a millisecond, so no hop to a detached task.

### 9. Risks and gotchas

- **`CGImage` and `Sendable`.** Recent SDKs mark `CGImage` `Sendable`; if the compiler in the guest's Xcode does not, the `@unchecked Sendable` wrapper `Artwork` already covers it. Do not store `NSImage` (not `Sendable`, and it would pull AppKit into the package).
- **False merges are irreversible in the UI.** The rules are deliberately narrow (case, `and`/`&`, trailing `;`, whitespace). Resist adding diacritic or article folding here; each should be its own issue with examples from a real library.
- **A straddling duplicate changes an earlier row.** When page 2 adds a member to a group from page 1, that row gains albums and maybe artwork but keeps its name and position; the browser must key rows by `ArtistGroup.id`, not by index.
- **Group names are only as good as the first spelling.** `AJ and Jordan;` seen first names the group `AJ and Jordan`. Acceptable; the alternative (renaming rows as pages load) is worse.
- **Unstructured fetch tasks outlive cancelled rows.** By design, but each holds a `backend` call; a fast scroll through hundreds of rows can queue hundreds of fetches. The browser's visible set is bounded and the Plex transcode is cheap; if it shows, add a small concurrency gate (`maxConcurrentFetches`, default 6) inside the actor, which the tests above tolerate unchanged.
- **`missing` is per session.** A thumb added on the server after a miss shows the placeholder until `clear()` or relaunch. Fine for now; a reconnect (#0063) clears it.
- **`StubURLProtocol` route order and `times`.** The 404 case must register a status-404 route for `/photo/:/transcode` *instead of* the PNG route, not after it (first match wins).
- **Do not reach the audio engine.** The `PlexArtworkTests` fixture builds a `Player` only because `PlexBackend` needs a `LocalPlayerOutput`; it never enqueues anything.
- **The transcode query is #0062's, not this issue's.** If #0062 landed `width`/`height` differently (for example `maxPixels` only on the long side), adjust the assertion in `plexArtworkIsFetchedAtThumbnailSize…`, not the backend.
