## Description

Make Music Assistant (MA) the default library source, configured in Settings, with Plex as the alternative and a local folder as the last fallback. The skinned UI depends only on a source-neutral `MusicBackend` and its domain models, never on MA or Plex types.

## Long Description

Umbrella for milestone **M9: Music Assistant library source**, from [docs/music-assistant-integration.md](../docs/music-assistant-integration.md). It ships no code itself; it stays open until every child issue is resolved, closed or won't-fix.

Source order:

1. **Music Assistant** (default): a server on the home LAN reached over its WebSocket API (`ws://<host>:8095/ws`), token in the Keychain. MA merges sources (including the Plex library) and streams to players such as HomePods.
2. **Plex**: the M2 client (PlexKit, TrackCache), kept as the alternative.
3. **Local folder**: a folder organized into `Artist/Album/Track` subfolders like the Plex library, played through AudioCore.

Order of work: the spike (#0060) first, since much of the MA protocol is marked VERIFY in the doc. The backend protocol (#0062) should land before M3's browser (#0015–#0018) so the browser is written once against `MusicBackend` rather than against Plex. Controller mode (#0064) ships before local playback via Sendspin (#0066), which the doc calls the larger, riskier piece.

MA also plays to HomePods and AirPlay 2 speakers from the server, with multi-room sync. That overlaps M8 (#0049): with MA as the default, M8's in-app AirPlay work matters mainly for the Plex and folder sources. Revisit M8's scope once #0064 works.
