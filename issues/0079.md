# 0079 — Clutter bar buttons do nothing

## Description

The clutter bar (the strip of five small buttons O, A, I, D, V at the left of the main window; `MainWindowLayout.clutterBar`, x 10, y 22, 8×43) is drawn with the skin's background but none of its buttons respond. In Winamp: **O** opens the options menu, **A** toggles always on top, **I** shows file info for the current track, **D** toggles double size, **V** opens the visualization menu. Each button shows its pressed sprite while held, and A and D show a selected state while on.

Expected: the five buttons hit-test, show the pressed/selected sprites from Webamp's sprite table, and act. Always on top floats every skinned window and is persisted. Double size scales the main, EQ and playlist windows by 2 keeping docking and integer-scale nearest-neighbour drawing, and is persisted. File info shows the current track's title, artist, album, duration, format, bitrate and sample rate. O and V open menus (O can reuse #0078's menu; V can offer the existing visualizer modes).

## Plan

### Reference (Webamp)

`packages/webamp/js/components/MainWindow/ClutterBar.tsx` and `css/main-window.css` (fetched 2026-10-18):

- `#clutter-bar` sits at top 22, left 10, 8×43. Each button is `left 0, width 8, height 7` unless noted: **O** top 3 h 8, **A** top 11, **I** top 18, **D** top 25 h 8, **V** top 33. In absolute main-window skin pixels the rects are O (10,25,8,8), A (10,33,8,7), I (10,40,8,7), D (10,47,8,8), V (10,55,8,7).
- Sprites (already in `SkinSprites.swift:208-212`): `MAIN_CLUTTER_BAR_BUTTON_{O,A,I,D,V}_SELECTED`, with sizes that match the rects. Webamp draws the `_SELECTED` sprite on `:active` (pressed) and on `.selected`. There are no unpressed sprites: the unpressed buttons are part of `MAIN_CLUTTER_BAR_BACKGROUND`, which `MainWindowRenderer` already draws into the base image. `_BACKGROUND_DISABLED` is not used here (Webamp doesn't use it either).
- In Webamp, only O (options context menu) and D (double size, `selected` while doubled) are wired up. A, I and V are inert there. This issue follows Winamp for those three, as the Description asks.

### Decision on double size: it fits in this issue

Double size does **not** need a separate issue. The scaling it needs already runs end to end. `PlayerModel.scale` (stored, default 2) drives `PlayerView`, `EqualizerWindowView` and `PlaylistWindowView` (`scaleEffect` with `.interpolation(.none)`). It also drives `SkinWindowController.applyLayout()`, which observes `model.scale` and, on a change, goes through `WindowDockingCoordinator.resize`, so docked neighbours move by the size difference (Webamp's `withWindowGraphIntegrity`). The playlist overlays, the cursor controller, the region mask and the visualizer (`setScale`) all read the same scale. So double size comes down to "persist a flag and set `scale` to 2× the base". There is no new rendering work.

- The app's normal size is already `scale` 2 (one skin pixel = 2 points). Double size is therefore `scale` 4 (Winamp doubles whatever the normal size is). Add `static let baseScale: CGFloat = 2` and derive from it.
- If the host check shows docking going wrong when all three windows rescale at once (each controller resizes in its own observation `Task`), **do not** grow this issue. Note it under Gotchas and file a follow-up for a single group rescale in `WindowDockingCoordinator`.

1. **`Packages/SkinKit/Sources/SkinKit/Rendering/MainWindowLayout.swift`**: add, next to `clutterBar`:

2. **`Packages/PlayerKit/Sources/AudioCore/TrackInfo.swift`** (new): a pure value type for the File Info panel, shared with #0081's playlist File Info.
   ```
   public struct TrackInfo: Equatable, Sendable {
       public var title: String; public var artist: String; public var album: String?
       public var duration: TimeInterval?; public var format: String?   // "MP3", "FLAC"… from the file extension, uppercased
       public var bitrateKbps: Int?; public var sampleRate: Double?; public var channels: Int?
       public init(track: Track, format: PlaybackFormat?)   // PlaybackFormat wins over Track for sampleRate/channels
       public var rows: [(label: String, value: String)]    // see below
   }
   ```
   Rows are in this order: Title, Artist, Album, Duration (`m:ss`, `h:mm:ss` from an hour up), Format, Bitrate (`"320 kbps"`), Sample rate (`"44.1 kHz"`, `"48 kHz"`: one decimal, a trailing `.0` dropped), Channels (`Mono` / `Stereo` / `"N channels"`). A nil or empty value shows as `"—"`. `format` comes from `Track.Source.file(url)` → `url.pathExtension.uppercased()` (nil when empty) and is nil for `.plex`. Also add a memberwise `public init(title:artist:album:duration:format:bitrateKbps:sampleRate:channels:)` for non-local outputs. Rows are an array of tuples, so leave `Equatable` off if the tuple array gets in the way, or make the rows a small `public struct Row: Equatable { label, value }` (preferred).
3. **`App/Visualizer/VisualizerModel.swift`**: add `func setMode(_ mode: Mode)`. Move the body of `cycleMode()` into it (persist, `resetCursor` on spectrum, repaint when paused / clear when off) and make `cycleMode()` call `setMode(next)`. Add `var title: String` on `Mode` ("Spectrum Analyzer", "Oscilloscope", "Off") for the V menu.
4. **`App/PlayerModel.swift`**:
   - Keys: `static let alwaysOnTopKey = "alwaysOnTop"`, `static let doubleSizeKey = "doubleSize"`, `static let baseScale: CGFloat = 2`.
   - `private(set) var isAlwaysOnTop = UserDefaults.standard.bool(forKey: alwaysOnTopKey)` and `func toggleAlwaysOnTop()` (toggle and persist).
   - `private(set) var isDoubleSize = UserDefaults.standard.bool(forKey: doubleSizeKey)`. Change `scale`'s initial value to `PlayerModel.baseScale * (UserDefaults.standard.bool(forKey: PlayerModel.doubleSizeKey) ? 2 : 1)` and keep the `didSet`. `func toggleDoubleSize()` toggles, persists and sets `scale = Self.baseScale * (isDoubleSize ? 2 : 1)`. The existing `visualizer.setLayout(…, scale: scale)` in `init` covers a doubled launch, and `pushDown` stays 0 for any scale of 2 or more.
   - `var currentTrackInfo: TrackInfo?`. On This Mac (`selectedOutput == OutputDevice.thisMacID`) it is `player.queue.current.map { TrackInfo(track: $0, format: player.currentFormat) }`. Otherwise it is built from `nowPlaying.title/artist/album/duration` (nil when `title` is nil), with format, bitrate and rate left nil.
   - `func showFileInfo()`: `guard let info = currentTrackInfo else { NSSound.beep(); return }`, then `FileInfoPanel.shared.show(info)`.

It keeps one lazily built `NSPanel` (`[.titled, .closable, .utilityWindow]`, title "File Info", `isReleasedWhenClosed = false`, `hidesOnDeactivate = false`). Its content is `NSHostingView(rootView: FileInfoView(info:))`: a SwiftUI `Grid` of label/value rows (`.textSelection(.enabled)` on the values, monospaced digits, around 320 pt wide). `show(_:)` swaps in the root view, centres the panel the first time, then calls `makeKeyAndOrderFront`. The panel is non-modal (no `NSAlert.runModal`, which would stall the visualizer's run loop). #0081 reuses `FileInfoPanel.shared.show(TrackInfo(track: selected, format: nil))`.

That style draws `SpriteImage(skin, MainWindowLayout.spriteName(button))` when `configuration.isPressed || selected`, else `Color.clear`. It is framed to the rect size and has `.contentShape(Rectangle())`. Actions:
