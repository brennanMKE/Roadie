# 0090 — Some playlist entries do not survive Save then Load

| | |
|---|---|
| **Status** | open |
| **Module** | AudioCore |
| **Platform** | macOS |
| **First seen** | 2026-10-19 |

## Description

Found in the #0082 review (commit d93f918), not blocking there:

- A relative entry whose name has a colon after a letters-only prefix is read as a URL scheme and skipped as a stream. Finder shows `AC/DC - x.mp3`, which is `AC:DC - x.mp3` on disk, so it is written and then dropped on load.
- A relative file name that starts with `#` is written as-is and read back as an M3U comment.
- UTF-16 playlists (with a BOM) are not detected.

Expected: Save then Load round-trips every local file the queue held, and UTF-16 M3U/PLS files load.
