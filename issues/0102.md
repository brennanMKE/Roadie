# 0102 — Playlist files in UTF-16 without a byte-order mark decode as garbage

| | |
|---|---|
| **Status** | open |
| **Module** | AudioCore |
| **Platform** | macOS |
| **First seen** | 2026-10-19 |

## Description

`PlaylistFile.decode` handles UTF-8 (with or without BOM), UTF-16 with a BOM, and falls back to Windows-1252; its doc comment says "BOM-less UTF-16 and UTF-32 are not detected". Some Windows tools write BOM-less UTF-16LE playlists; today those decode through UTF-8/CP1252 into text full of NULs and every entry is lost.

Expected:

- BOM-less UTF-16 LE and BE are detected by the NUL-byte pattern of mostly-ASCII text (for example, NULs at odd or even offsets in the first few hundred bytes) and decoded; ordinary UTF-8 and CP1252 files are never misdetected.
- The doc comment is updated.
- Tests: BOM-less UTF-16LE and BE M3U and PLS with non-ASCII names; UTF-8 and CP1252 files unchanged; a tiny or odd-length file doesn't crash.
