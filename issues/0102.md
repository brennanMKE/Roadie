# 0102 — Playlist files in UTF-16 without a byte-order mark decode as garbage

| | |
|---|---|
| **Status** | open |
| **Module** | AudioCore |
| **Platform** | macOS |
| **First seen** | 2026-10-19 |

## Description

`PlaylistFile.decode` handles UTF-8 (with or without BOM), UTF-16 with a BOM, and falls back to Windows-1252; its doc comment says "BOM-less UTF-16 and UTF-32 are not detected". Some Windows tools write BOM-less UTF-16LE playlists; today those decode through UTF-8/CP1252 into text full of NULs and every entry is lost.

Expected:

- BOM-less UTF-16 LE and BE are detected by the NUL-byte pattern of mostly-ASCII text (for example, NULs at odd or even offsets in the first few hundred bytes) and decoded; ordinary UTF-8 and CP1252 files are never misdetected.
- The doc comment is updated.
- Tests: BOM-less UTF-16LE and BE M3U and PLS with non-ASCII names; UTF-8 and CP1252 files unchanged; a tiny or odd-length file doesn't crash.

## Plan

Scope: only `PlaylistFile.decode` (plus one private helper next to it) and `PlaylistFileTests`. #0100/#0101 edit other functions in `PlaylistFile.swift` / `LocalTrackLoader.swift`; don't touch those.

### Files

- `Packages/PlayerKit/Sources/AudioCore/PlaylistFile.swift` — `decode(_:pathExtension:)` (currently lines ~43–61) and a new `private static func bomlessUTF16Encoding(_ bytes: Data) -> String.Encoding?` placed right after it.
- `Packages/PlayerKit/Tests/AudioCoreTests/PlaylistFileTests.swift` — four new `@Test`s at the end of `PlaylistFileTests`, after `plsInUTF16IsDetected`.

### Approach

1. **Detector** `bomlessUTF16Encoding(_ bytes: Data) -> String.Encoding?`:
   - Look at `Array(bytes.prefix(512))` (copy to an array so slice indices of a `dropFirst`-ed `Data` don't matter; index by offset 0…n-1). Use `n = sample.count & ~1` (even). If `n < 4`, return nil.
   - `pairs = n / 2`. Count `evenNUL` = NULs at offsets 0, 2, 4…; `oddNUL` = NULs at offsets 1, 3, 5….
   - LE (ASCII high byte is second): return `.utf16LittleEndian` if `oddNUL * 10 >= pairs * 6` (≥ 60 %) and `evenNUL * 10 <= pairs` (≤ 10 %).
   - BE: mirror, `evenNUL` ≥ 60 % and `oddNUL` ≤ 10 % → `.utf16BigEndian`.
   - Otherwise nil. Real UTF-8 and CP1252 text has no NUL bytes, so it can never pass the 60 % bar; UTF-32 fails the ≤ 10 % bar (out of scope, still undetected).
2. **`decode`**: keep the BOM branches as they are. Add a new `else if` after the two UTF-16-BOM branches (so it runs only when no BOM matched):
   ```
   } else if let encoding = bomlessUTF16Encoding(bytes) {
       let even = bytes.count & ~1   // drop a stray trailing byte so decoding can't fail on odd length
       if let text = String(data: Data(bytes.prefix(even)), encoding: encoding) { return text }
   }
   ```
   If that `String(data:encoding:)` returns nil (e.g. unpaired surrogates), fall through to the existing UTF-8 / CP1252 / lossy path unchanged.
3. **Doc comment** on `decode`: replace the last sentence with: "BOM-less UTF-16 LE/BE is detected from the NUL-byte pattern of mostly-ASCII text in the first 512 bytes; BOM-less UTF-32 is not detected." Mention a trailing odd byte is ignored for UTF-16.

Note for tests: `String.data(using: .utf16LittleEndian/.utf16BigEndian)` emits **no** BOM (the existing BOM test prepends it by hand), so it yields BOM-less input directly.

### Tests to add (`PlaylistFileTests`) — the `--expect` list

- `decodesBOMlessUTF16M3U` — text `"#EXTM3U\n#EXTINF:120,Björk - Hunter\nBjörk/01 Hunter.mp3\n"`; `text.data(using: .utf16LittleEndian)!` and `.utf16BigEndian` each parsed with `format: .m3u` (also with `pathExtension: "m3u8"`) equal the UTF-8 parse `[.init(location: "Björk/01 Hunter.mp3", title: "Björk - Hunter", duration: 120)]`.
- `decodesBOMlessUTF16PLS` — text `"[playlist]\nFile1=Café/a.mp3\nTitle1=Café\nNumberOfEntries=1\n"` in BOM-less LE and BE: `PlaylistFile.format(for: URL(filePath: "/tmp/x/list.m3u"), data:)` is `.pls`, and `parse(data, format: .pls)` == `[.init(location: "Café/a.mp3", title: "Café")]`.
- `bomlessUTF16DetectionLeavesUTF8AndWindows1252Alone` — a UTF-8 non-ASCII M3U (`Data("#EXTM3U\nBjörk/a.mp3\n".utf8)`) still parses to `["Björk/a.mp3"]`; the CP1252 bytes from `m3uFallsBackToWindows1252` still give `["Café.mp3"]`; and assert `PlaylistFile.decode` of both returns the same string as before (UTF-8 text / `"Café.mp3\n"`), i.e. contains no `"\u{0}"`.
- `bomlessUTF16ToleratesTinyAndOddLengthData` — `decode` on `Data()`, `Data([0x00])`, `Data([0x61, 0x00])`, `Data([0x00, 0x61, 0x00])` doesn't crash (just call it and `#expect` on something trivial such as no crash / result is a String); and `"a.mp3\nb.mp3\n".data(using: .utf16LittleEndian)! + Data([0x00])` (odd length) parses as `.m3u` to `["a.mp3", "b.mp3"]`.

Run: `VERIFY: scripts/verify.sh --expect decodesBOMlessUTF16M3U,decodesBOMlessUTF16PLS,bomlessUTF16DetectionLeavesUTF8AndWindows1252Alone,bomlessUTF16ToleratesTinyAndOddLengthData`
