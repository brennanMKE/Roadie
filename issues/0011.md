# 0011 — Settings has no Plex section and the token is not stored securely

| | |
|---|---|
| **Status** | open |
| **Module** | App / PlexKit |
| **Platform** | macOS |
| **First seen** | 2026-10-12 |

## Description

Add a SwiftUI `Settings` scene with a Plex section: server address, paste-a-token field (stored in the Keychain), Test Connection, and a music-library picker.

## Acceptance criteria

- Token in Keychain, never `UserDefaults`.
- Library picker appears after a successful connection and hides when there is only one music library.
- Connection errors show the messages from the connection test.

## Plan

### Scope and decisions

This issue puts a Settings window in front of what #0009 and #0010 built: a `Settings` scene with a Plex tab, a token store behind a protocol (Keychain in the app, in-memory in tests), a `@MainActor @Observable` settings model that owns the paste-a-token field, Test Connection and the library picker, and the two follow-ups from #0010's review (a pasted Plex Web URL, and cancellation reported as "unreachable"). No ATS / Local Network keys (#0012), no cache or Settings › Cache tab (#0013), no plex.tv sign-in or server picker (#0014). The PIN flow in #0014 will store its token through the same `PlexTokenStore`, and the Cache tab slots into the same `TabView`.

- **The token store is a protocol in `PlexKit`, `PlexTokenStore`, with two implementations.** `KeychainPlexTokenStore` (`SecItem*`, in `PlexKit`, `import Security`) is what the app uses; `InMemoryPlexTokenStore` (in `PlexKitStub`, next to the `URLProtocol` stub, so later UI tests can launch the app with it) is what every unit test uses. The store reads and writes `PlexToken.rawValue`, which #0009 reserved for exactly this. Nothing else ever reads `rawValue`.
- **The real Keychain store has no test in the guest, only an opt-in one on the host.** `scripts/run-tests-vm.sh` has no per-step timeout, so an access-control dialog in the headless guest would hang a verification run forever rather than fail it; and the same suite run by mistake on the host must not write to the real login keychain. So `KeychainPlexTokenStoreTests` is `.enabled(if:)` an environment variable the VM never sets (`PLEX_KEYCHAIN_TEST=1`), uses a per-run unique `service` so it never touches the app's own item, and deletes its item in a `defer`. It is the same shape as `PlexIntegrationTests`, and a user/reviewer step, not something the implementation subagent runs. The real store is otherwise proven by hand in Settings (section 9) and by Keychain Access.
- **The file-based login keychain, not the data-protection keychain.** The app is ad-hoc signed (`CODE_SIGN_IDENTITY: "-"` in `project.yml`). `kSecUseDataProtectionKeychain` on macOS needs a real application identifier, so it is not set; the item goes into the default (login) keychain as a generic password, with no `kSecAttrAccessible` (that attribute is for the data-protection keychain) and no `kSecAttrSynchronizable` (a server token must not sync through iCloud Keychain). The known cost, in the risks: an ad-hoc signature changes on every rebuild, so the first read after a rebuild shows the "SkinAmp wants to use your confidential information" dialog once. The user clicks Always Allow; `mac-release` signing fixes it for good later.
- **The settings model lives in `PlexKit`, the views in `App/`.** The app has no test target, and adding one would mean a new `xcodebuild test` step in the guest. `AudioCore.Player` is already a `@MainActor @Observable` class in a package, so `PlexSettingsModel` follows that precedent: all behaviour (persistence, token commit, the test-connection state machine, cancellation, picker visibility) is in the model and unit-tested against `InMemoryPlexTokenStore`, a `UserDefaults(suiteName:)` and a `StubURLProtocol.handle()`. The SwiftUI views are thin and are checked by hand only.
- **A pasted Plex Web URL is normalized, not explained.** `PlexAddress.normalize` cuts the path at a `web` component, so `http://joe:32400/web/index.html#!/…` becomes `http://joe:32400` and a reverse-proxied `http://host/plex/web/index.html` becomes `http://host/plex`. This is the smallest rule that makes "copy the address bar from Plex Web" work, it is idempotent, and it keeps #0010's "non-root path is kept" behaviour for anything else. The address field's help text also says a Plex Web link is fine.
- **Cancellation is its own outcome.** `PlexConnectionFailure` gains `.cancelled`: a `CancellationError`, or a `PlexError.transport(.cancelled)` from `URLSession`, maps to it instead of `.unreachable`, and `check()` checks for cancellation between its steps. The model additionally ignores the result of any task it has cancelled, so a stale completion can never overwrite the state of a newer test. Editing the address or the token, Cancel, and closing Settings all cancel the in-flight test and leave the status at idle, never at an error.
- **The token is committed on demand, not per keystroke.** The field edits `tokenText` in memory; `commitToken()` writes it to the store (trimmed; empty deletes the item) and runs on field submit, before every Test Connection, and when Settings closes. The address, by contrast, is saved to `UserDefaults` (inside `PlexServerSelection`, as #0010 intended) on every change, since that is a tiny JSON write.
- **Settings runs the test on open when it can.** When Settings appears with a saved address and token, the model runs the connection test once so the library picker is filled without a click; the result is shown exactly as a manual test would show it. Closing cancels it. The model's `init` and `load()` do no network I/O, and `init` does no Keychain I/O either, so the app's launch never triggers the keychain dialog; only opening Settings does.
- **Verification is the VM script, with `--launch`.** `swift test --package-path Packages/PlayerKit` already runs `PlexKitTests`; the Debug app build proves the SwiftUI compiles; `--launch` proves the app still starts with the new scene. The guest never gets `PLEX_URL`, `PLEX_TOKEN` or `PLEX_KEYCHAIN_TEST`. The token is never written to disk outside the Keychain, logged, or committed; section 10 has the checks.

### 1. `PlexTokenStore` (`Sources/PlexKit/PlexTokenStore.swift`)

```swift
/// Where the Plex token lives. The only code that reads `PlexToken.rawValue`.
public protocol PlexTokenStore: Sendable {
    func load() throws -> PlexToken?          // nil when there is none
    func save(_ token: PlexToken) throws      // add or replace
    func delete() throws                      // no error when there is none
}

public enum PlexTokenStoreError: Error, Hashable, Sendable, LocalizedError {
    case keychain(OSStatus)
    /// "The Keychain refused the request (<SecCopyErrorMessageString>, status <n>)." Never the token.
    public var errorDescription: String? { … }
}

/// A generic-password item in the login keychain.
public struct KeychainPlexTokenStore: PlexTokenStore {
    public static let defaultService = "com.brennanmke.SkinAmp.plex"
    public var service: String
    public var account: String                // "plex.tv": one token per app, not per server
    public init(service: String = Self.defaultService, account: String = "plex.tv")
}
```

`KeychainPlexTokenStore`: a private `baseQuery` of `kSecClass: kSecClassGenericPassword`, `kSecAttrService`, `kSecAttrAccount`. `load()` adds `kSecReturnData: true`, `kSecMatchLimit: kSecMatchLimitOne`, calls `SecItemCopyMatching`; `errSecItemNotFound` → `nil`; any other non-zero status → `.keychain(status)`; the data is UTF-8 → `PlexToken`. `save(_:)` tries `SecItemUpdate(baseQuery, [kSecValueData: data])` first and on `errSecItemNotFound` calls `SecItemAdd(baseQuery + [kSecValueData: data, kSecAttrLabel: "SkinAmp Plex token"])`. `delete()` calls `SecItemDelete(baseQuery)` and treats `errSecItemNotFound` as success. The calls are synchronous and fast; the model calls them on the main actor (an access-control dialog blocks the main thread while it is up, which is how every Mac app behaves). No `kSecUseDataProtectionKeychain`, `kSecAttrAccessible` or `kSecAttrSynchronizable` (see the decisions). The store never logs; the error carries only the `OSStatus`.

`InMemoryPlexTokenStore` (`Sources/PlexKitStub/InMemoryPlexTokenStore.swift`):

```swift
/// A token store for tests and, later, the UI-test launch path. Counts its calls.
public final class InMemoryPlexTokenStore: PlexTokenStore, @unchecked Sendable {   // OSAllocatedUnfairLock inside
    public init(token: PlexToken? = nil)
    public var token: PlexToken? { get }
    public var loads: Int { get }; public var saves: Int { get }; public var deletes: Int { get }
    /// When set, every call throws it (for the "Keychain refused" path in the model).
    public var failure: PlexTokenStoreError?
}
```

### 2. `PlexAddress`: strip the Plex Web path (`Sources/PlexKit/PlexAddress.swift`)

In `normalize`, after the trailing slashes are removed and before the components are reassembled:

```swift
var parts = path.split(separator: "/", omittingEmptySubsequences: true)
if let web = parts.firstIndex(where: { $0.lowercased() == "web" }) { parts.removeSubrange(web...) }
path = parts.isEmpty ? "" : "/" + parts.joined(separator: "/")
```

| Input | Output |
|---|---|
| `http://joe:32400/web/index.html`, `http://joe:32400/web/`, `http://joe:32400/web` | `http://joe:32400` |
| `joe:32400/web/index.html#!/media/x` (no scheme; fragment dropped as before) | `http://joe:32400` |
| `http://joe:32400/plex/web/index.html` | `http://joe:32400/plex` |
| `http://joe:32400/webhooks` | unchanged (the component is not `web`) |

Still idempotent. `nonRootPathIsKept` (`/plex`) is unchanged. `docs/plex-music-library.md` gets one clause in the paragraph #0010 added: "a Plex Web link (`…/web/index.html`) is cut back to the server".

### 3. `PlexConnectionFailure.cancelled` (`Sources/PlexKit/PlexConnectionTest.swift`)

```swift
public enum PlexConnectionFailure: Error, Hashable, Sendable, LocalizedError {
    case invalidAddress
    case unreachable(PlexError)
    case unauthorized
    case noMusicLibrary
    /// The task was cancelled (an edit, Cancel, or Settings closed). The UI shows nothing for it.
    case cancelled
    // message: "The connection test was cancelled."  caseName: "cancelled"
}
```

One private helper replaces `plexError(_:)` and is used by both catch sites in `check()`:

```swift
private static func failure(_ error: any Error) -> PlexConnectionFailure {
    if error is CancellationError { return .cancelled }
    guard let plex = error as? PlexError else { return .unreachable(.transport(.unknown)) }
    if case .transport(.cancelled) = plex { return .cancelled }
    return .unreachable(plex)
}
```

Step 2's `switch` keeps `.unauthorized, .httpStatus(403) → .unauthorized` and sends everything else through `failure(_:)`. Add `try Task.checkCancellation()` (mapped through the same helper) before step 1 and before step 2, so a test cancelled between the two requests does not send the second one. `run(address:token:)` and the log line are unchanged.

### 4. Stub: a `delay` on `Route` (`Sources/PlexKitStub/StubURLProtocol.swift`)

The cancellation tests need a request that is still in flight when it is cancelled. `Route` gains `public var delay: TimeInterval = 0` (also in the memberwise `init`). In `startLoading`, when `route.delay > 0`, the response (or `route.error`) is delivered from `DispatchQueue.global().asyncAfter(deadline: .now() + delay)`; the instance keeps an `OSAllocatedUnfairLock<Bool>` "stopped" flag that `stopLoading()` sets, and the delayed block delivers nothing when it is set. Matching, recording and the undelayed path are untouched. `URLSession` makes the cancelled `data(for:)` throw `URLError(.cancelled)` on its own; the flag only keeps the stub quiet afterwards. Fallback if delivering from another queue misbehaves under the guest's Foundation: `Thread.sleep(forTimeInterval:)` inside `startLoading` (one request per test session, so blocking the protocol's queue is harmless); say so in `## Fix`.

### 5. `PlexSettingsModel` (`Sources/PlexKit/PlexSettingsModel.swift`)

```swift
import Observation

@MainActor @Observable
public final class PlexSettingsModel: CustomStringConvertible, CustomDebugStringConvertible, CustomReflectable {
    public enum Status: Hashable, Sendable {
        case idle
        case testing
        case connected(PlexConnection, PlexServerSelection.Change)
        case failed(PlexConnectionFailure)        // never .cancelled: cancellation goes to .idle
    }
    public static let selectionDefaultsKey = "PlexServerSelection"   // JSON of PlexServerSelection

    public init(tokenStore: any PlexTokenStore, defaults: UserDefaults = .standard, connectionTest: PlexConnectionTest)
    // No I/O here. The app passes KeychainPlexTokenStore(), .standard,
    // PlexConnectionTest(clientIdentifier: PlexClientIdentifier.stored()).

    // Inputs (SwiftUI bindings). Changing either cancels an in-flight test and sets status to .idle.
    public var address: String { get set }             // persisted to defaults on every change
    public var tokenText: String { get set }           // memory only until commitToken()
    public var librarySectionKey: String? { get set }  // persisted on every change

    // Outputs
    public private(set) var status: Status
    public private(set) var musicSections: [PlexLibrarySection]      // from the last successful test this session
    public private(set) var tokenStoreError: String?                 // PlexTokenStoreError text, or nil
    public var isTesting: Bool { status == .testing }
    public var canTest: Bool                     // trimmed address and token non-empty, and not testing
    public var hasStoredToken: Bool              // the store had a token at load(), or a commit saved one
    public var showsLibraryPicker: Bool { musicSections.count > 1 }
    public var selectedSection: PlexLibrarySection?                  // selection.selectedSection(in: musicSections)
    public var statusMessage: String?            // .failed → failure.message; .connected → "Connected to Plex Media Server <version>."
    public var statusDetail: String?             // .failed → failure.underlying?.errorDescription (the disclosure #0010 planned)
    public var changeNote: String?               // .serverChanged → "This address now points to a different server; the music library was reset."
                                                 // .libraryMissing → "The selected library is no longer on this server."

    // Lifecycle
    public func load()                 // defaults → selection; store.load() → tokenText; idempotent. Store errors → tokenStoreError.
    public func appeared()             // load(), then testConnection() if canTest and status == .idle
    public func disappeared()          // commitToken(); cancelTest()
    public func commitToken()          // trimmed tokenText → store.save, or store.delete when empty; errors → tokenStoreError
    public func forgetToken()          // tokenText = ""; commitToken()
    public func testConnection()       // cancelTest(); commitToken(); status = .testing; start the task
    public func cancelTest()           // cancels the task; if status == .testing, status = .idle
    public func waitForTest() async    // awaits the in-flight task, for tests
}
```

Implementation rules:

- **Storage.** A private stored `selection: PlexServerSelection` is the observed state; `address` and `librarySectionKey` are computed over it (get returns the field; set guards against no change, writes the field, calls `persistSelection()`, and for `address` also `invalidate()`). `tokenText` is computed over a private stored `enteredToken`; its setter calls `invalidate()`. This mirrors `Player.volume`'s pattern and avoids a `didSet` that reassigns. `persistSelection()` is `JSONEncoder().encode(selection)` into `defaults` under `selectionDefaultsKey`; `load()` decodes it, falling back to `PlexServerSelection()`.
- **`invalidate()`**: `cancelTest()`, and `status = .idle` unless it already is. `musicSections` is kept so the picker does not vanish while the user retypes; a new successful test replaces it.
- **`testConnection()`**: `cancelTest()`; `commitToken()`; if `tokenStoreError != nil` or the trimmed token is empty, return without testing (the UI disables the button anyway); `status = .testing`; capture `connectionTest`, `address` and the committed `PlexToken` as `let`s; `connectionTask = Task { [weak self] in … }`. The task runs `test.run(address:token:)`, builds a `Result<PlexConnection, PlexConnectionFailure>`, then `guard let self, !Task.isCancelled else { return }` and calls `apply(result)` on the main actor. `connectionTask` is `@ObservationIgnored`.
- **`apply(_:)`**: `.failure(.cancelled)` → `status = .idle` (defensive; the guard above normally catches it). `.failure(f)` → `status = .failed(f)`. `.success(c)` → `let change = selection.apply(c)` (so a changed `machineIdentifier` clears the library and a single library is auto-selected, as #0010 built), `persistSelection()`, `musicSections = c.musicSections`, `status = .connected(c, change)`.
- **`cancelTest()`**: `connectionTask?.cancel()`, `connectionTask = nil`, and `if status == .testing { status = .idle }`.
- **Printing.** `description` and `debugDescription` are `"PlexSettingsModel(<address>)"`; `customMirror` is `Mirror(self, children: [])`. `String(reflecting:)` on an `@Observable` class would otherwise walk its backing storage and print `enteredToken`.
- **Logging.** One `os.Logger` (`category: "PlexSettings"`) `info` line for `commitToken` ("token saved" / "token removed" / "token store failed <status>") and for each `apply` outcome by case name. No token, no `tokenText` length, no selection JSON.

### 11. Risks

- **Keychain dialog after every rebuild.** With ad-hoc signing the app's designated requirement is its code hash, so an item written by build N is "another app's" to build N+1 and `SecItemCopyMatching` shows the access dialog once per rebuild (Always Allow adds that build to the item's ACL). It is the dev-build experience only; Developer ID signing (`mac-release`) ends it. It must never be seen by the guest, which is why the real store has no test there. If the user clicks Deny, `load()` gets `errSecAuthFailed`, the model shows `tokenStoreError` and leaves the field empty; nothing crashes.
- **ATS blocks the happy path until #0012.** The manual check cannot show Connected over `http://joe:32400` yet; section 9 says what to expect instead (-1022 in the detail line). The implementer must not add the ATS keys to make its own check pass.
- **`@Observable` and property observers.** `Player` shows `didSet` works on stored properties but a `didSet` that reassigns recurses; the model uses computed properties over private stored state (the `Player.volume` pattern) so the setters can cancel and persist without that. Keep `connectionTask` `@ObservationIgnored`.
- **Swift Testing on a `@MainActor` class.** The suite is `@MainActor`; `waitForTest()` awaits the stored task's `value` so tests do not poll. `Task.sleep` after `waitForTest()` is only there to prove a cancelled task never delivers; keep delays at 0.5–1 s so the suite stays fast.
- **Delayed stub delivery from another queue.** `URLSession` tolerates `URLProtocol` client callbacks from any queue in practice (OHHTTPStubs does the same), but if the guest's Foundation drops the delayed response, use the `Thread.sleep` fallback in section 4 and note it. A cancelled `data(for:)` throws `URLError(.cancelled)` regardless of what the protocol does, so the cancellation tests do not depend on this.
- **`Status: Hashable`** holds a `PlexConnection` with the sections array; `==` on it is what `status == .testing` uses. Fine, but do not put the model's `Status` through `UserDefaults` or logs.
- **`SecureField` and the token.** It accepts paste on macOS. If the user wants to see what they pasted, that is a later nicety; a Show toggle is not planned. The token is also in `tokenText` in memory, unavoidably; the model's `customMirror` keeps it out of `dump`/`String(reflecting:)`.
- **Auto-test on open** sends two requests whenever Settings opens with saved inputs. That is a LAN server and the result is what the user would click for anyway; if it proves annoying, delete the `testConnection()` call in `appeared()` and test 25.
- **`SecItemUpdate` before `SecItemAdd`** avoids a duplicate-item error on a second save; `errSecDuplicateItem` from `SecItemAdd` would mean a race with another process, which is not expected here, so it surfaces as `tokenStoreError` rather than being retried.
- **The `web` rule is positional, not semantic.** A server mounted at `http://host/web/` (nobody does this) would be cut to `http://host`; the rule is documented in the doc and the test table, and anyone with that setup can type `https://…` to a `plex.direct` URI from #0014 instead.
- **`PlexConnectionFailure` gains a case.** Exhaustive `switch`es over it: only `caseName` and `message` inside PlexKit; the app `switch`es on `Status`, not on the failure. #0012's single-string edit for `.unreachable` is unaffected.
