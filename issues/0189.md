## Description

A playlist in the Library (⌘L › Playlists) can be renamed, deleted, exported and favourited, but it can't be played. The user made a playlist called "Party" and couldn't get it into the skinned playlist editor. Double-clicking it, right-clicking it and dragging it all fail to play it.

An album row already does all three (#0136, #0181). This issue makes a playlist row work the same way:

- double-click plays the playlist, replacing the queue;
- the context menu gains Play, Play Next and Add to Queue;
- the row can be dragged onto the skinned playlist editor.

## Steps to reproduce

1. Connect to Music Assistant and open the Library's Playlists section.
2. Double-click "Party". It only opens the track list.
3. Right-click "Party". The menu has New Playlist…, Rename…, Delete…, Export…, Import… and Favorite, but no Play.
4. Drag "Party" onto the playlist editor. Nothing drags.

## Expected behavior

Double-click plays "Party", replacing the queue. The menu has Play, Play Next and Add to Queue. A drag onto the playlist editor adds its tracks (appended, since this is Music Assistant).

## Actual behavior

None of these works.

## Root cause

`App/Browser/ArtistListView.swift:80–95` (`PlaylistListView`, `.playlist` row):

- the `.contextMenu` holds only `FavoriteMenuItem` and `playlistMenu` (New / Rename / Delete / Export / Import, lines 36–52);
- there's no `.draggable`;
- there's no double-click gesture.

`PagedListView`'s selection only opens the playlist's tracks (`library.select(playlist)`).

The backends:

- **Music Assistant** plays a playlist id as it is. `MusicAssistantBackend.play` sends the ids' URIs to `play_media` (`MusicAssistantBackend.swift:530–552`), and `play_media` expands a playlist URI. `BackendTransportTests` already sends `library://playlist/2` with `.append` and `.insert(at:)` (lines 84, 93). `PlayerModel.loadPlaylist` (`App/PlayerModel+PlaylistFiles.swift:25–28`) already plays one this way for LIST › Load (#0146).
- **Folder library:** it has no playlists. `FolderBackend.playlists` throws `.unsupported(.playlists)` (`FolderBackend.swift:325`), so the Playlists section isn't shown. `play` refuses `.playlist` ids (line 373). Nothing is needed there.

## Plan

This depends on #0188, which adds `libraryDraggable(_:)` and `libraryContainerMenu`/`libraryContainerActions(_:favorite:model:addsToPlaylists:)` in `App/Browser/LibraryPlaybackActions.swift`, and `PlayRequest.play/append/next(container:)`.

### 1. The playlist row (`App/Browser/ArtistListView.swift`, `PlaylistListView`)

On the `.playlist(let playlist)` row:

- Replace the `.contextMenu { … }` with one that holds, in order:
  - Play: `player.playFromLibrary(.play(container: playlist.id))`;
  - Play Next: `.next(container:)`;
  - Add to Queue: `.append(container:)`;
  - `Divider()`, then `FavoriteMenuItem`;
  - then the existing `playlistMenu(playlist)` (behind its own `Divider()`; it's empty when `!model.canEdit`).

  Either extend `libraryContainerMenu` with a trailing `@ViewBuilder extra:` slot, or write the three buttons inline using the same `PlayRequest` helpers. Pick whichever keeps the menu-building code in one place. There's no Add to Playlist ▸: adding a playlist into a playlist isn't supported (`addsDroppedItems` takes only tracks and albums).
- Double-click plays: `.simultaneousGesture(TapGesture(count: 2).onEnded { player.playFromLibrary(.play(container: playlist.id)) })`, the same as `libraryAlbumActions` (`LibraryPlaybackActions.swift:47–50`). The single click still opens the playlist's tracks.
- Drag: `.libraryDraggable([playlist.id])`.
- Keep `.addsDroppedItems(to: playlist, model: player)`, so albums and tracks can still be dropped onto a playlist (#0136).

### 2. Accept playlists in drops (`App/Playlist/PlaylistWindowOverlays.swift`, `PlaylistWindowView`)

The drop targets pass whatever ids arrive to `playFromLibrary`. Check that nothing between them filters by kind:

- #0188's `mediaIDs(from:)`, and the SwiftUI fallback's `transfers.flatMap(\.ids)`. `addsDroppedItems` filters, and that's for the Library playlists, which is correct.

On This Mac with the folder library, a playlist id can't arrive, because the folder library has no Playlists section. If one somehow does, `FolderBackend.play` throws `.unsupported(.playlists)`, and `playFromLibrary` shows that as a notice. That's acceptable.

### 3. Dynamic and read-only playlists

Play works on every playlist, including read-only ones (`!playlist.isEditable`) and dynamic ones (`playlist.isDynamic`), because playing doesn't edit it. Music Assistant expands a dynamic playlist into its current sample. No special case.

- Not re-verified by the reviewer; the implementer's passing run 20261024-170659-47000 stands.
- The row's modifier order (container menu, `simultaneousGesture(TapGesture(count: 2))`, `libraryDraggable`) matches the album row exactly, so if #0188's by-hand check finds the double-click gesture blocks album drags, playlist rows need the same fix (the List-level `primaryAction` route in #0188's decision tree).

- Both editor drop paths (AppKit `performDragOperation` at the drop row, SwiftUI fallback at `playlist.count`) send `.insert(at:)`, which Music Assistant turns into `option: add` (`insertSendsOptionAdd` already pins this for a playlist URI).
- Nit, not blocking: when the backend lacks `.playlistEditing`, the menu ends with a trailing `Divider()` (the `playlistMenu` is empty). The folder library has no Playlists section, so this shouldn't show up in practice.

## Fix

Followed the plan with no change of route:

- **Menu.** `libraryContainerMenu` gains an optional trailing `@ViewBuilder extra:` slot (default `EmptyView`), placed after the favourite. The playlist row uses `libraryContainerMenu(playlist.id, favorite:, model:, addsToPlaylists: false) { Divider(); playlistMenu(playlist) }`, giving Play, Play Next, Add to Queue, Favorite, then New / Rename / Delete / Export / Import. The menu code stays in one place.
- **Double-click.** `.simultaneousGesture(TapGesture(count: 2))` plays `.play(container: playlist.id)`. A single click still opens the tracks.
- **Drag.** `.libraryDraggable([playlist.id])`. `.addsDroppedItems(to:model:)` is kept.
- **Drops.** `PlaylistWindowOverlays.swift`'s `mediaIDs(from:)` and the SwiftUI fallback don't filter by kind, so nothing changed there.
- No special case for read-only or dynamic playlists.
