# 0098 — A skin BMP that ImageIO can't decode is lost; there is no fallback decoder

| | |
|---|---|
| **Status** | open |
| **Module** | SkinKit |
| **Platform** | macOS |
| **First seen** | 2026-10-19 |

## Description

`BitmapLoader.image(from:)` (`Packages/SkinKit/Sources/SkinKit/Parsers/BitmapLoader.swift`) decodes only through ImageIO and carries `TODO: add a fallback BMP decoder for files ImageIO rejects.` Classic Winamp skins were made with many Windows tools, and some write BMP variants ImageIO may not accept (for example RLE8/RLE4 compression, 16-bit BI_BITFIELDS, OS/2 `BITMAPCOREHEADER`, top-down rows). When ImageIO returns nil the whole sheet is missing and the skin renders with holes.

Expected:

- A small pure-Swift BMP decoder used when ImageIO returns nil, covering at least: 1/4/8-bit paletted, 24- and 32-bit, RLE8 and RLE4, 16-bit (5-5-5 and BI_BITFIELDS), bottom-up and top-down, `BITMAPINFOHEADER` and `BITMAPCOREHEADER`.
- Garbage or truncated data still returns nil without crashing; sizes are bounded (no huge allocations from a forged header).
- Unit tests build each variant synthetically in the test (no new binary fixtures needed) and check decoded pixels.
