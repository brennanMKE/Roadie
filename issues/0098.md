# 0098 — A skin BMP that ImageIO can't decode is lost; there is no fallback decoder

| | |
|---|---|
| **Status** | open |
| **Module** | SkinKit |
| **Platform** | macOS |
| **First seen** | 2026-10-19 |

## Description

`BitmapLoader.image(from:)` (`Packages/SkinKit/Sources/SkinKit/Parsers/BitmapLoader.swift`) decodes only through ImageIO and carries `TODO: add a fallback BMP decoder for files ImageIO rejects.` Classic Winamp skins were made with many Windows tools, and some write BMP variants ImageIO may not accept (for example RLE8/RLE4 compression, 16-bit BI_BITFIELDS, OS/2 `BITMAPCOREHEADER`, top-down rows). When ImageIO returns nil the whole sheet is missing and the skin renders with holes.

Expected:

- A small pure-Swift BMP decoder used when ImageIO returns nil, covering at least: 1/4/8-bit paletted, 24- and 32-bit, RLE8 and RLE4, 16-bit (5-5-5 and BI_BITFIELDS), bottom-up and top-down, `BITMAPINFOHEADER` and `BITMAPCOREHEADER`.
- Garbage or truncated data still returns nil without crashing; sizes are bounded (no huge allocations from a forged header).
- Unit tests build each variant synthetically in the test (no new binary fixtures needed) and check decoded pixels.

### Decoder rules (implement exactly)

- **File header**: needs ≥ 14 bytes, `"BM"` magic; `bfOffBits` = u32 at offset 10. DIB header starts at 14; `size` = u32 there.
- **Header kinds**: `size == 12` → `BITMAPCORE`: u16 width, u16 height (unsigned, always bottom-up), u16 planes, u16 bitCount; compression 0; palette entries are **3 bytes** (B,G,R), count `1 << bitCount`. `size` in {40, 52, 56, 108, 124} → `BITMAPINFO`: i32 width, i32 height, u16 planes, u16 bitCount, u32 compression, u32 sizeImage, 2× i32 resolution, u32 clrUsed, u32 clrImportant; palette entries **4 bytes** (B,G,R,x), count `clrUsed` if `1...(1<<bitCount)` else `1 << bitCount`. Any other size → nil. Header must fit in data.
- **Orientation**: height < 0 → top-down with `abs` (convert to `Int` first so `Int32.min` can't trap); RLE with negative height → nil.
- **Bounds (before any allocation)**: `1...maxDimension` for width and height, `width * height <= maxPixels`, else nil.
- **Allowed combos**: compression 0 (BI_RGB) with bitCount 1/4/8/16/24/32; 1 (BI_RLE8) with 8; 2 (BI_RLE4) with 4; 3 (BI_BITFIELDS) with 16/32. Anything else → nil.
- **Masks**: BI_BITFIELDS reads R,G,B u32 masks at offset 14+40 (right after a 40-byte header, or inside a ≥52-byte header — same offset either way); palette/masks area ends at `14 + size + 12` when `size == 40`, else `14 + size`. Default masks: 16-bit `0x7C00/0x03E0/0x001F` (5-5-5), 32-bit `0xFF0000/0xFF00/0xFF`. Channel = `(pixel & mask) >> trailingZeroBitCount`, scaled `v * 255 / ((1 << mask.nonzeroBitCount) - 1)`; zero mask → 0. Alpha is ignored (skins are opaque).
- **Palette** (bitCount ≤ 8) follows the header/masks; truncated palette → nil. Index past the palette → black.
- **Pixel offset**: `bfOffBits` if it's ≥ end of header+palette and < data.count, else the end of header+palette.
- **Uncompressed rows**: stride `((width * bitCount + 31) / 32) * 4`; need `offset + stride * height <= data.count` else nil. Sub-byte pixels are MSB first. Stored row r maps to output y = `height - 1 - r` (bottom-up) or `r` (top-down).
- **RLE8/RLE4** (bottom-up, start x = 0, y = 0 meaning the bottom row): read byte pairs `(n, b)`. `n > 0`: run of n pixels; RLE8 index b, RLE4 alternates `b >> 4`, `b & 0xF`. `n == 0`: `b == 0` end of line (x = 0, y += 1), `b == 1` end of bitmap (stop, success), `b == 2` delta (read dx, dy; x += dx, y += dy), `b >= 3` absolute run of b pixels (RLE8: b bytes; RLE4: `(b + 1) / 2` bytes, high nibble first) then skip one pad byte if the bytes consumed for the run are odd. Pixels outside the image are dropped (no write, no crash); stop with success once y ≥ height. Unwritten pixels are palette index 0. Running out of data before end-of-bitmap (and before y ≥ height) → nil.
- **Output**: RGBA8, `bytesPerRow = width * 4`, alpha 255, `CGImageAlphaInfo.noneSkipLast`, device RGB, via `CGDataProvider(data:)` (same construction as the end of `CursorBitmap.decodeDIB`). Any failure → nil; never `fatalError`/force-unwrap/unchecked subscript.

### Tests (all in `BMPDecoderTests`, names are the `--expect` list)

Each builds a tiny BMP (e.g. 3×2 or 4×2) in code and checks specific pixels via `BMPDecoder.decode`, including that top and bottom rows land where expected:

- `bmpDecodes1BitPaletted`
- `bmpDecodes4BitPaletted`
- `bmpDecodes8BitPaletted`
- `bmpDecodes24BitBottomUp`
- `bmpDecodes24BitTopDown`
- `bmpDecodes32Bit`
- `bmpDecodes16Bit555`
- `bmpDecodes16BitBitfields565` (masks `0xF800/0x07E0/0x001F`)
- `bmpDecodesRLE8` (encoded run, absolute run with odd length + pad, end-of-line, delta, end-of-bitmap; check an unwritten pixel is palette[0])
- `bmpDecodesRLE4` (encoded run alternating two nibbles, absolute run, end-of-bitmap)
- `bmpDecodesCoreHeader` (12-byte OS/2 header, 8-bit, 3-byte palette entries)
- `bmpRLEOverrunIsClipped` (run longer than width and delta past the top: returns an image, no crash)
- `bmpRejectsGarbage` (random bytes, empty data, `"BM"` alone → nil)
- `bmpRejectsTruncatedData` (valid 24-bit file cut mid-pixel-data, cut mid-header, RLE without end marker cut short → nil)
- `bmpRejectsForgedDimensions` (headers claiming 100000×100000, 0 width, `Int32.min` height, 4097 wide → nil, with only a few bytes of data)
- `bitmapLoaderFallsBackWhenPrimaryFails` (`BitmapLoader.image(from: TestBitmaps.bmp(...), primary: { _ in nil })` still decodes with the fill colour; and garbage through `BitmapLoader.image(from:)` → nil)

Verify: `scripts/verify.sh --expect bmpDecodes1BitPaletted,bmpDecodes4BitPaletted,bmpDecodes8BitPaletted,bmpDecodes24BitBottomUp,bmpDecodes24BitTopDown,bmpDecodes32Bit,bmpDecodes16Bit555,bmpDecodes16BitBitfields565,bmpDecodesRLE8,bmpDecodesRLE4,bmpDecodesCoreHeader,bmpRLEOverrunIsClipped,bmpRejectsGarbage,bmpRejectsTruncatedData,bmpRejectsForgedDimensions,bitmapLoaderFallsBackWhenPrimaryFails`
