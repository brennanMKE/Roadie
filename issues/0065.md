# 0065 — A local music folder cannot be used as a library

| | |
|---|---|
| **Status** | open |
| **Module** | App / PlayerKit |
| **Platform** | macOS |
| **First seen** | 2026-10-13 |

## Description

The last-fallback source: point SkinAmp at a folder organized like the Plex library, `Artist/Album/<tracks>`, and browse and play it through AudioCore without any server.

## Acceptance criteria

- Settings › Library: choose the folder (open panel), shown with its path; the choice persists.
- A `FolderBackend` conforming to `MusicBackend` indexes artists from top-level folders and albums from their subfolders, reading track metadata with `LocalTrackLoader` (#0006); embedded or folder artwork (`cover.jpg`, `folder.jpg`) for album art.
- Loose files and odd layouts are handled gracefully (tracks directly under an artist, discs as `Disc 1/` subfolders, unsupported files skipped and reported).
- The index is built off the main actor, cached, and refreshed when the folder changes.
- Unit tests build a small generated folder tree in a temp directory (generated audio, as #0006's tests do).

## Plan

If #0062 lands with different names the implementer follows the landed code; the behaviour below does not change. If `Page.make` is missing, write the three-line equivalent locally.

- **One target, `FolderBackendKit`**, depending on `MusicBackendKit`, `LocalPlayback` and `AudioCore` (for `LocalTrackLoader`, `Track`, `SkippedFile`, `EmbeddedArtworkLoader`, `TrackResolver`). The name ends in `Kit` for the same reason as `PlexBackendKit`: the type is `FolderBackend`. It must not import PlexKit or TrackCache.
- **The folder structure is the truth; tags refine it.** Artists are the top-level folders, albums their subfolders, tracks the audio files below. Embedded tags supply the track title, per-track artist name, track and disc numbers when present; they never move a file to another artist or album. A library "organized like the Plex library" is exactly this, and it keeps the index a pure function of the tree.
- **`MediaID`s are relative paths.** `rawValue` is the path relative to the chosen root, `/`-separated, NFC-normalized (`precomposedStringWithCanonicalMapping`, so an HFS+ copy and an APFS copy of the same library give the same ids): `artist:10,000 Maniacs`, `album:10,000 Maniacs/Our Time in Eden (1992)`, `track:The Beatles/The White Album/Disc 1/01 Back in the U.S.S.R..wav`. Ids survive a rescan, a relaunch and moving the whole root. The two synthetic containers use ids no folder can have: loose tracks directly under an artist form a `Singles` album with `album:<Artist>` (same raw value as the artist, different kind), and audio files directly under the root belong to an `Unknown Artist` with `artist:.` and album `album:.`.
- **Indexing is a pure async function, off the main actor.** `FolderIndexer.build(root:previous:loader:)` is `nonisolated` and runs on the global executor: a synchronous walk, then a 4-wide task group over the files (the same shape as `LocalTrackLoader.load`), then assembly. The actor `FolderBackend` only owns the result. The loader is a closure (default `LocalTrackLoader.loadTrack`) so tests can count calls and prove the cache is reused.
- **The cache is one JSON file per root, used first and refreshed in the background.** `connect()` reads it, serves it at once, and rescans; per-file entries whose size and modification date are unchanged are reused without touching AVFoundation, so a second launch over a 20,000-file library costs a directory walk, not 20,000 asset loads. `Reindex` in Settings ignores the entries.
- **Changes are watched with FSEvents, debounced, with the watcher injectable.** `DispatchSource.makeFileSystemObjectSource` watches one directory and is not recursive; FSEvents is, and delivers on a dispatch queue. The backend takes a `makeWatcher` closure, so backend tests fire a `ManualWatcher` by hand and only `FolderWatcherTests` touches the real one.
- **Playback goes through the shared `LocalPlayerOutput`.** Folder tracks map to `AudioCore.Track` with `.file(url)`; the `Player`'s existing `FileTrackResolver`/`PlexTrackResolver` path (`PlexTrackResolver.localURL` returns the URL unchanged for `.file` sources) plays them, `CachePinner` ignores them, `NowPlayingBridge` already reads their embedded art.
- **Settings is one tab, `Library`, with only the folder section.** #0063 adds its picker at the top of the same tab. The model, `FolderSettingsModel`, lives in `FolderBackendKit` (as `CacheSettingsModel` lives in `TrackCache`) so it is unit-tested; the view is thin. The stored key `FolderBackend.folderDefaultsKey` is what #0063/#0067 read to know the source is configured.
- **No launch-time I/O.** `PlayerModel` builds the backend but does not call `connect()`; the Library tab connects when it appears and a folder is stored, so the status line is live. The browser (#0016) and the picker (#0063) connect when they select the source.
- **Verification is `scripts/run-tests-vm.sh --launch` only.** No `swift test`, `xcodebuild` or app launch on the host. Every test uses generated audio and generated images in a temp directory, nothing is committed, and **no test opens an audio device**: the `Player` in backend tests gets a resolver that points every track at a non-existent file (section 9), so `AVAudioFile` never opens and `ensureGraph()` is never reached. The real WAVs exist only so the indexer can read them.

### 3. `FolderIndex.swift`: the index and its cache

```swift
/// Everything the backend serves, as a value. Codable so it is the cache file too.
public struct FolderIndex: Codable, Hashable, Sendable {
    public static let formatVersion = 1
    public var version: Int
    public var root: String                     // root.standardizedFileURL.path
    public var builtAt: Date
    public var artists: [LibraryArtist]         // sorted by sortName (section 4)
    public var albums: [LibraryAlbum]           // sorted by artist, year, title
    public var tracks: [FolderTrack]            // in album order (disc, number, name)
    public var skipped: [FolderSkippedFile]
    public var summary: FolderIndexSummary
    public static func empty(root: URL) -> FolderIndex
}

/// A LibraryTrack plus what the player and the cache need.
public struct FolderTrack: Codable, Hashable, Sendable {
    public var library: LibraryTrack
    public var relativePath: String             // as the file system spelled it (not NFC-normalized)
    public var fileSize: Int64
    public var modified: Date
    public var sampleRate: Double?; public var channels: Int?; public var bitrate: Int?
    public var album: String?                   // for AudioCore.Track.album
    public func audioTrack(root: URL) -> Track  // Track(title:artist:album:duration:bitrate:sampleRate:channels:source: .file(root/relativePath))
}

public struct FolderSkippedFile: Codable, Hashable, Sendable { public var relativePath: String; public var reason: String }

public struct FolderIndexSummary: Codable, Hashable, Sendable {
    public var artists: Int; public var albums: Int; public var tracks: Int; public var skipped: Int; public var builtAt: Date
    public var text: String   // "12 artists, 30 albums, 412 tracks" (+ ", 3 files skipped")
}

public enum FolderIndexStatus: Hashable, Sendable {
    case notConnected
    case indexing(previous: FolderIndexSummary?)   // previous is the cached summary being served meanwhile
    case ready(FolderIndexSummary)
    case failed(String)
}

/// One JSON file per root under Caches.
public enum FolderIndexCache {
    public static func defaultDirectory(bundleIdentifier: String? = Bundle.main.bundleIdentifier) -> URL
        // ~/Library/Caches/<bundle id or com.brennanmke.SkinAmp>/FolderIndex/
    public static func fileURL(for root: URL, in directory: URL) -> URL
        // directory/index-<first 16 hex of SHA-256 of the standardized root path>.json
    public static func load(for root: URL, in directory: URL) -> FolderIndex?
        // nil when missing, undecodable, version != formatVersion, or root != standardized path (then the file is deleted)
    public static func save(_ index: FolderIndex, in directory: URL) throws   // JSONEncoder (.iso8601 dates), Data.write(.atomic), creates the directory
    public static func remove(for root: URL, in directory: URL)
}
```

`LibraryArtist`, `LibraryAlbum`, `LibraryTrack`, `MediaID` and `ArtworkRef` are `Codable` per #0062; if any is not, add a retroactive `Codable` conformance in this target (they are plain structs).

**Invalidation rules** (each tested in section 9): a cache is ignored when the version or root differs; entries are reused only when `relativePath`, `fileSize` and `modified` all match the file on disk; the file is rewritten after every successful scan and removed when the folder is cleared or changed in Settings; `reindex()` ignores every entry. Nothing in the file is a secret (paths and tags only); it lives in Caches, not Application Support, so a stale or corrupt file costs a rescan, never a failure.

### 4. `FolderIndexer.swift`: scanning rules

```swift
public struct FolderIndexer: Sendable {
    public typealias Loader = @Sendable (URL) async throws -> Track
    public var loader: Loader = LocalTrackLoader.loadTrack(at:)
    public var maxConcurrent = 4
    public init(loader: @escaping Loader = LocalTrackLoader.loadTrack(at:))
    /// Walks `root`, reuses unchanged entries of `previous`, reads the rest. Throws only CancellationError or an unreadable root.
    public func build(root: URL, previous: FolderIndex?) async throws -> FolderIndex
}
```

Three phases, with `try Task.checkCancellation()` between them and per file:

**Phase 1, the walk (synchronous, `FileManager.contentsOfDirectory` with `[.isDirectoryKey, .fileSizeKey, .contentModificationDateKey]`, options `[.skipsHiddenFiles, .skipsPackageDescendants]`, entries sorted with `localizedStandardCompare` like `LocalTrackLoader.walk`).** The root and every entry are `standardizedFileURL.resolvingSymlinksInPath()` before computing the relative path (`/var` vs `/private/var`, #0006's gotcha). Symlinked directories are not followed (resource values report them as non-directories, as #0006's reviewer found).

- **Root entries.** A directory is an artist folder. An audio file (`LocalTrackLoader.isAudio`) is a loose root track under `Unknown Artist` (`artist:.`, album `album:.`, album title `Unknown Album`). Any other file goes through the sidecar rule below.
- **Artist folder entries.** A directory is an album folder. An audio file is a loose track in the artist's `Singles` album (`album:<Artist>`, title `Singles`). Other files: sidecar rule.
- **Album folder, any depth below it.** Audio files are the album's tracks, in Finder order, files before subfolders (so `LocalTrackLoader`'s order holds). A track's **disc number** is the number of the nearest ancestor folder below the album whose name matches `^(disc|disk|cd)\s*0*(\d{1,3})$` (case-insensitive), else the tag's disc number, else nil. Deeper folders that do not match are walked as part of the album (graceful, one album) and logged once at `debug`.
- **Sidecar rule for non-audio files.** Extensions `jpg jpeg png gif webp bmp tif tiff txt nfo cue log m3u m3u8 pls pdf sfv md5 ini url db` (case-insensitive) are ignored silently, as #0006 does for folders. Everything else is recorded in `skipped` with reason `not an audio file`, so a `.wma`, `.ape` or `.xyz` the user expected to play is reported rather than vanishing.
- **Empty artist or album folders** (no audio anywhere below) produce no artist or album.

Each audio file becomes a `FileJob(relativePath, artistFolder, albumFolder?, discNumber?, fileSize, modified)`.

**Phase 2, metadata (4-wide task group, results reassembled by index as in `LocalTrackLoader.load`).** For each job: if `previous` has an entry with the same `relativePath`, `fileSize` and `modified`, reuse it (no I/O). Otherwise `loader(url)`; a thrown error becomes `skipped` with `error.localizedDescription` (`AVAudioFile` cannot open it, so the player could not either) and a `warning` log with `lastPathComponent` only, matching #0006. Then read the track and disc numbers with `FolderTrackNumbers.read(url:)` (own file-private helper in this file): `AVURLAsset.load(.metadata)`, first of `.iTunesMetadataTrackNumber` / `.id3MetadataTrackNumber` (string `"3"` or `"3/12"` → 3; `iTunes` data value: bytes 2–3 big-endian) and `.iTunesMetadataDiscNumber` / `.id3MetadataPartOfASet`; any failure → nil, never thrown. The `AVURLAsset` is local to the function, so nothing non-`Sendable` escapes.

**Phase 3, assembly (pure, unit-tested through `build`).**

- `LibraryTrack`: `id = MediaID(.track, nfc(relativePath))`; `title` = the tag title from `Track.title`, except that when the title equals the file stem (no tag) a leading `^\d{1,3}[\s._-]+` is stripped if what remains is non-empty (`01 Intro.wav` → `Intro`); `trackNumber` = the tag, else that stripped prefix as an integer; `discNumber` = folder, else tag; `artistID` = the artist folder's id; `artistName` = `Track.artist` when non-empty (compilations keep per-track artists) else the artist folder name; `albumID`, `albumName` = the album folder's id and title; `duration`, `bitrate`, `sampleRate`, `channels` from `Track`; `artwork` = the album's ref.
- Order within an album: `(discNumber ?? 0, trackNumber ?? Int.max, relativePath localizedStandardCompare)`.
- `LibraryAlbum`: `id = MediaID(.album, nfc(albumFolderRelativePath))`; `title` and `year` from the folder name: `^(\d{4})\s*[-–]\s*(.+)$` or `^(.+?)\s*\((\d{4})\)$` with the year in 1900…2100 gives `year` and the remainder as `title`, else the folder name as-is and `year` nil; `artistID`, `artistName` = the folder's; `trackCount`; `artwork` per section 5.
- `LibraryArtist`: `id = MediaID(.artist, nfc(folderName))`; `name` = folder name; `sortName` = name with a leading `The ` removed (case-insensitive); `artwork` = the first album's artwork (by album order), nil if none.
- Sorting: artists by `sortName` with `localizedStandardCompare`; albums by artist sort name, then `year ?? Int.max`, then title; `Unknown Artist` sorts last.
- `summary` from the counts; `builtAt = Date()`.

`FolderIndexer` logs one `info` line per build (`counts: a/b/t, skipped n, reused r, read m, seconds`), category `FolderIndexer`, subsystem `com.brennanmke.SkinAmp`; never a full path at `info` or above.

### 5. `FolderArtwork.swift`: album art

- `ArtworkRef.rawValue` for the folder backend is `file:<relativePath>` for an image file or `embedded:<relativePath of a track>`.
- At assembly, each album's ref is the first existing name in the album folder from `cover.jpg, cover.jpeg, cover.png, folder.jpg, folder.jpeg, folder.png, front.jpg, front.png, album.jpg, album.png` (case-insensitive match against the directory listing, so `Cover.JPG` counts); else, if the album's first track is not reused from the cache or had no ref, `EmbeddedArtworkLoader.artworkData(for:)` on the first track decides between `embedded:` and nil (one asset load per album with no image file, cached with the index). Disc folders inherit the album's art; an image inside `Disc 1/` is used only when the album folder has none.
- `FolderArtwork.data(for ref: ArtworkRef, root: URL, maxPixels: Int) async throws -> Data`: `file:` reads the bytes, `embedded:` calls `EmbeddedArtworkLoader.artworkData`; a missing file or no embedded art throws `.backend("The album art is missing.")`. The bytes are returned unchanged when `CGImageSourceCopyPropertiesAtIndex` reports both dimensions ≤ `maxPixels`; otherwise `CGImageSourceCreateThumbnailAtIndex` with `kCGImageSourceThumbnailMaxPixelSize = maxPixels`, `kCGImageSourceCreateThumbnailFromImageAlways`, `kCGImageSourceCreateThumbnailWithTransform`, encoded as JPEG (`CGImageDestination`, quality 0.85). ImageIO and CoreGraphics only, no AppKit; paths outside the root (`..`) are refused with the same error.

### 6. `FolderWatcher.swift`

```swift
public protocol FolderWatching: AnyObject, Sendable {
    var isRunning: Bool { get }
    func stop()
}
/// FSEvents on one root, recursive. Fires `onChange` on a private queue, at most once per `latency`.
public final class FSEventsFolderWatcher: FolderWatching, @unchecked Sendable {
    public init(url: URL, latency: TimeInterval = 2, onChange: @escaping @Sendable () -> Void)
    public static func make(url: URL, onChange: @escaping @Sendable () -> Void) -> any FolderWatching
}
```

`FSEventStreamCreate` on `[url.path]`, `sinceWhen: kFSEventStreamEventIdSinceNow`, flags `kFSEventStreamCreateFlagFileEvents | kFSEventStreamCreateFlagNoDefer | kFSEventStreamCreateFlagIgnoreSelf | kFSEventStreamCreateFlagUseCFTypes`, context `info` = `Unmanaged.passUnretained(self)`, `FSEventStreamSetDispatchQueue` on a private serial queue, `FSEventStreamStart`. The callback ignores the paths and calls `onChange()` once per batch. `stop()` (and `deinit`) does `FSEventStreamStop`, `FSEventStreamInvalidate`, `FSEventStreamRelease` under a lock, idempotent; `isRunning` is the lock-protected flag. The `kFSEventStreamEventFlagRootChanged`/`MustScanSubDirs` flags do not need special handling: any event means "rescan". Kernel-level filtering is coarse, so the watcher also fires for a `.DS_Store` write; the debounce and the per-entry reuse make that a cheap no-op scan.

### 7. `FolderBackend.swift`: the actor

```swift
public actor FolderBackend: MusicBackend {
    public typealias SettingsProvider = @Sendable () -> URL?
    public typealias WatcherFactory = @Sendable (URL, @escaping @Sendable () -> Void) -> any FolderWatching

    public nonisolated let sourceID = "folder"
    public nonisolated let displayName = "Local Folder"
    public nonisolated let capabilities: BackendCapabilities = [.search, .artwork, .localOutput]
    /// Settings key; the path of the chosen folder. #0063 and #0067 read it through `storedFolder`.
    public nonisolated static let folderDefaultsKey = "LibraryFolderPath"
    public static func storedFolder(in defaults: UserDefaults = .standard) -> URL?
    public static func settingsProvider(defaults: UserDefaults = .standard) -> SettingsProvider

    public init(settings: @escaping SettingsProvider, output: LocalPlayerOutput,
                cacheDirectory: URL = FolderIndexCache.defaultDirectory(),
                indexer: FolderIndexer = FolderIndexer(),
                makeWatcher: @escaping WatcherFactory = FSEventsFolderWatcher.make,
                rescanDelay: Duration = .seconds(2))

    public private(set) var isConnected: Bool
    public private(set) var root: URL?
    public private(set) var status: FolderIndexStatus       // .notConnected until connect()
    public func statusUpdates() -> AsyncStream<FolderIndexStatus>   // current value first, then every change; bufferingNewest(1)
    public func reindex() async throws                       // full rescan, ignores cached entries; .notConnected before connect()
    public func waitForIndexing() async                      // awaits the in-flight scan and any requested follow-up (tests, Settings)
    // … the protocol methods
}
```

Behaviour, each rule tested in section 9:

- **`connect()`**: provider → nil ⇒ `.notConfigured("Choose a music folder under Settings › Library.")`, nothing read. The URL must exist and be a readable directory (`isReadableFile(atPath:)`, `isDirectoryKey`), else `.unreachable("The music folder “<lastPathComponent>” can't be read.")`. Already connected to the same standardized root → return (idempotent). A different root → `disconnect()` first. Then: `FolderIndexCache.load` → if present, `index = cached`, `status = .indexing(previous: cached.summary)`, start the rescan as a background `Task` and return; if absent, `status = .indexing(previous: nil)`, await the scan (the first connection over a new folder is a full read and the caller shows loading), store, save, `status = .ready`. Start the watcher last (the factory is called on the actor; its `onChange` hops back with `Task { await self.folderChanged() }`). `isConnected` is true as soon as an index (cached or fresh) is in place.
- **Scan management.** One `scanTask: Task<Void, Never>?` at a time and a `rescanRequested` flag. `folderChanged()` cancels a pending debounce task and starts one that sleeps `rescanDelay` then calls `rescan(full: false)`; if a scan is running, it sets `rescanRequested` and the running scan loops once more when it finishes. Each scan: `status = .indexing(previous: index?.summary)`, `indexer.build(root:previous: full ? nil : index)`, then (if not cancelled and the root is unchanged) `index = new`, `FolderIndexCache.save` (a save error is logged at `error` and ignored: the index still serves), `status = .ready(summary)`; a thrown error other than cancellation → `status = .failed(error.localizedDescription)` with the old index kept. Status changes yield to every live `statusUpdates()` continuation (dictionary keyed by UUID, removed in `onTermination`).
- **`disconnect()`**: `watcher?.stop()`, cancel the scan and debounce tasks, `index = nil`, `root = nil`, `status = .notConnected`, `isConnected = false`.
- **Library calls before `connect()`** throw `.notConnected`. All are answered from the in-memory index, synchronously on the actor, no I/O.
- **`artists(page:)`** → `Page.make(items: slice, request:, total: artists.count)`; the slice is `artists[offset ..< min(offset + limit, count)]` (empty when `offset >= count`).
- **`albums(of: nil, page:)`** → all albums, paged the same way. **`albums(of: id, page:)`**: `id.kind == .artist` else `.notFound(id)`; unknown artist id → `.notFound(id)`; else that artist's albums in index order, paged.
- **`tracks(of: album)`**: `.album` kind and known, else `.notFound`; tracks in index order.
- **`playlists` / `tracks(ofPlaylist:)`** → `.unsupported(.playlists)`.
- **`search(query, limit)`**: trimmed empty → `.empty`; else `range(of: query, options: [.caseInsensitive, .diacriticInsensitive])` on artist names, album titles and track titles, each list truncated to `limit`, in index order.
- **`artwork(ref, maxPixels)`** → `FolderArtwork.data(for:root:maxPixels:)` (runs off the actor via a `nonisolated` helper; it is file I/O).
- **`outputs()`** → `[LocalPlayerOutput.device]`, no connection needed.
- **`play(items, on:, mode:)`**: output must be `thisMacID` else `.unknownOutput`; needs the index (`.notConnected`); expand in order: `.track` → the entry or `.notFound(id)`; `.album` → its tracks; `.artist` → its albums' tracks in album order; `.playlist` → `.unsupported(.playlists)`; then `LocalQueueItem(track: entry.audioTrack(root:), id: entry.library.id)` and `await output.play(items, mode:)` on the main actor. An empty expansion (an album whose files all vanished) throws `.backend("None of these tracks is on disk any more.")` after a `fileExists` check per item; a mixed set skips the missing ones with an `info` log.
- **`transport(cmd, on:)`** → `thisMacID` ⇒ `await output.perform(cmd)`, else `.unknownOutput`; no connection needed. **`nowPlaying(on:)`** → `thisMacID` ⇒ `await output.nowPlaying()`, else an empty, finished stream. Identical to `PlexBackend`; a shared helper in `LocalPlayback` is a follow-up, not this issue.
- **Logging**: `Logger(subsystem: "com.brennanmke.SkinAmp", category: "FolderBackend")`: `info` for connect outcomes (by case, with the folder's `lastPathComponent`), `debug` for listing counts, `warning` on a cache save failure. Never a full path above `debug`.

### 8. `FolderSettingsModel.swift` and the app


### 12. Risks and gotchas

- **#0062's landed API may differ from its plan.** Follow the code, keep the behaviour in sections 3–8, and list every renamed symbol in `## Fix`. If `LocalPlayerOutput` is not shared through `PlexPlaybackStack.output`, build a second `LocalPlayerOutput` over the same `Player`; two outputs over one player are harmless until #0063 picks one.
- **Never let a real WAV reach `Player.begin`.** `MissingFileResolver` is the guard in `FolderBackendTests` and `FolderSettingsModelTests`; a test that builds a `Player()` with the default resolver and plays an indexed track would open the guest's output device (silent there, but it breaks the rule and would be audible on a host). Reviewer: grep the test target for `Player()` and `FileTrackResolver`.
- **FSEvents in a headless guest.** Events on the temp volume do arrive, but latency is coarse (the test waits up to 15 s) and `IgnoreSelf` only filters the calling process. If the watcher test proves flaky in the guest, keep it but reduce it to start/stop assertions, note it in `## Gotchas`, and rely on `folderChangesTriggerADebouncedRescan` (manual watcher) for the backend's behaviour. Do not add `AUDIOCORE_REALTIME`-style opt-in; nothing here touches audio.
- **`/var` vs `/private/var`.** Standardize and resolve symlinks on the root and every entry before computing relative paths, or the ids differ between `makeLibrary`'s spelling and `contentsOfDirectory`'s (#0006's gotcha). The cache file name hashes the standardized path for the same reason.
- **Unicode file names.** Ids are NFC; `relativePath` is what the file system returned. Always open files through `relativePath`, never by reconstructing a path from an id.
- **Track and disc tags are best-effort.** `AVURLAsset` exposes ID3/iTunes items reliably for MP3/M4A, not Vorbis comments in FLAC (#0006's note); the filename prefix and disc folders are the dependable path, which is why the required tests use untagged WAVs and the tagged test is optional.
- **Large libraries.** A first scan of tens of thousands of files takes minutes (one `AVURLAsset` load per file, 4-wide). The cache makes every later launch a walk; the Settings status shows progress only as `Indexing…`. A count-based progress is a follow-up if it is wanted.
- **Scan while the folder keeps changing** (a copy in progress): the debounce plus `rescanRequested` means at most one extra scan, and half-copied files that `AVAudioFile` rejects land in `skipped` until the next event clears them. Acceptable.
- **Removable or network volumes.** `connect()` on an unmounted path reports `.unreachable` and keeps the setting; FSEvents on SMB/NFS volumes does not deliver remote changes, so `Reindex` is the user's recourse. Say so in the Settings caption only if it fits in one line; otherwise `## Gotchas`.
- **Sandbox later.** A plain path works because `ENABLE_APP_SANDBOX` is `NO`. If the app is sandboxed, store a security-scoped bookmark under a new key and resolve it in `settingsProvider`; nothing else in the backend changes.
- **Settings tab order and naming.** The acceptance criterion says `Settings › Library`; the tab is created here with only the folder section so #0063 can add the picker above it without moving anything.
