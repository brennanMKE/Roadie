# 0016 — There is no window for browsing the Plex music library

| | |
|---|---|
| **Status** | open |
| **Module** | App |
| **Platform** | macOS |
| **First seen** | 2026-10-12 |

## Description

Add a SwiftUI browser window: artists → albums → tracks, plus search, loading pages lazily.

## Acceptance criteria

- Uses PlexKit paging; scrolling a long list does not block the UI.
- Search uses the `title=` filter and debounces input.
- Loading, empty and error states are shown.

## Plan

### Scope and decisions

This issue adds the Library window: a three-column SwiftUI browser (sections → artists/albums/playlists → albums → tracks) with a debounced search field and lazily paged lists. It is written against `MusicBackend` and the `Library*` models from #0062, never against PlexKit, so the same window serves Music Assistant (#0064), Plex and the folder source (#0065). It ships no artist de-duplication or artwork (#0017) and no play/enqueue (#0018); section 9 says exactly where those two issues hook in.

- **Depends on #0062 landing first.** Everything below uses the API in #0062's `## Plan`: `MusicBackend` (`connect`, `artists(page:)`, `albums(of:page:)`, `tracks(of:)`, `playlists(page:)`, `tracks(ofPlaylist:)`, `search(_:limit:)`, `capabilities`), `PageRequest(offset:limit:)`, `Page<Item>` with `nextOffset`/`total`/`Page.make`, `MediaID`, `LibraryArtist/Album/Track/Playlist`, `SearchResults`, `BackendCapabilities` and `MusicBackendError` (`LocalizedError`, user-facing `errorDescription`, never a URL or token). If #0062 lands with different names (for example a `cursor` on `Page`), adapt the two places that touch them, `PagedList` and `LibraryBrowserModel`; the views and tests do not name the backend.
- **The view models live in PlayerKit, not in `App/`.** The `SkinAmp` scheme tests only package targets, so anything in `App/` is untestable in the VM. A new Foundation-plus-Observation target `LibraryBrowser` (depends on `MusicBackendKit` only) holds `PagedList`, `LibraryBrowserModel` and `LibraryFormat`; `App/Browser/` holds the SwiftUI views and nothing else. This mirrors `PlexSettingsModel` (PlexKit) and `PlexSettingsView` (App). The module name `LibraryBrowser` does not collide with any type (`LibraryBrowserModel`, `LibraryWindowView`).
- **A shared in-memory stub backend.** `StubMusicBackend` goes in its own library target `MusicBackendStub` (like `PlexKitStub`), so #0017, #0018, #0064 and #0065 test against the same stub. It is an actor with a sample `StubLibrary`, recorded calls, per-method error injection, and per-method gates (continuations) so a test can hold a request in flight, observe the loading state, then release or fail it. No test in this issue uses `StubURLProtocol`, PlexKit or the network.
- **"Uses PlexKit paging" is satisfied through the protocol.** `PagedList` asks for `PageRequest(offset:limit: 100)` pages; `PlexBackend` turns those into `X-Plex-Container-Start/Size` (#0062). A backend without totals (MA) works unchanged because `Page.nextOffset` drives the "load more" decision and `total` is only displayed when present.
- **Nothing blocks the main actor.** Every backend call is `async` on an actor; the models are `@MainActor` and only touch state. `List` on macOS is `NSTableView`-backed and lazy; a row's `onAppear` near the end of the loaded items requests the next page. Stale answers are dropped by a per-list generation counter, and duplicate ids across pages are skipped so `ForEach` never sees two rows with one id.
- **Search is debounced in the model, not the view.** `searchText` sets restart a 300 ms task; the trimmed query goes to `backend.search(_:limit: 50)` once, Return searches at once, and whitespace or an empty field sends nothing and clears the results. Each query cancels the previous one. With `PlexBackend` that is the `title=` filter, three requests per query (#0062), which the debounce keeps cheap.
- **The window connects on appear, never at launch.** `PlayerModel` builds the backend but does not call `connect()` (#0062); `LibraryBrowserModel.appeared()` does. So `scripts/run-tests-vm.sh --launch` never touches the network, the Keychain or `joe`: the Library window is not opened by the smoke test.
- **States are explicit enums, drawn by small shared views.** Connection: idle / connecting / connected / failed(message). Each list: idle / loading / loaded / failed(message), plus `isLoadingMore` and `loadMoreError` for the footer. Empty is `loaded` with no items. `.notConfigured` failures get an "Open Settings…" button (`SettingsLink`); every other failure gets Retry.
- **Verification is `scripts/run-tests-vm.sh --launch` only.** No `swift test`, `xcodebuild` or app launch on the host. Tests are silent (nothing opens an audio device: the stub never touches AudioCore), no token exists anywhere in this issue, no log line carries a query or an address, and commits stage explicit paths.

### 2. `LibraryBrowser`: `PagedList` (`Sources/LibraryBrowser/PagedList.swift`)

One generic, testable object per paged column. It knows nothing about the backend; the model gives it a loader closure.

```swift
public enum ListPhase: Hashable, Sendable {
    case idle            // nothing requested yet
    case loading         // first page in flight, no items
    case loaded          // at least one page answered (items may be empty = the empty state)
    case failed(String)  // first page failed; `items` is empty
}

@MainActor @Observable
public final class PagedList<Item: Identifiable & Hashable & Sendable> where Item.ID: Sendable {
    public typealias Loader = @Sendable (PageRequest) async throws -> Page<Item>

    public private(set) var items: [Item] = []
    public private(set) var phase: ListPhase = .idle
    public private(set) var total: Int?            // from the last page that reported one
    public private(set) var isLoadingMore = false
    public private(set) var loadMoreError: String? // a later page failed; items are kept
    public var hasMore: Bool { nextOffset != nil }
    public let pageSize: Int
    /// `loadMoreIfNeeded(current:)` fires when `item` is within this many rows of the end.
    public let prefetchDistance: Int

    public init(pageSize: Int = 100, prefetchDistance: Int = 10, loader: Loader? = nil)

    /// Swap the loader (e.g. the selected artist changed) and start over; a nil loader resets to `.idle`.
    public func reload(with loader: Loader?)
    public func reload()                            // same loader, first page again
    public func loadMore()                          // no-op unless `.loaded`, `hasMore`, not already loading
    public func loadMoreIfNeeded(current item: Item) // index(of item) >= items.count - prefetchDistance → loadMore()
    public func retryLoadMore()                     // clears `loadMoreError`, then loadMore()
    public func cancel()                            // cancels the in-flight task; phase becomes .loaded if items exist, else .idle
    public func reset()                             // cancel + clear everything; phase .idle
}
```

Rules:

- `reload` bumps a private `generation`, cancels the previous task, clears `items`/`total`/`nextOffset`/`loadMoreError`, sets `.loading`, and starts `Task { … }` that awaits `loader(PageRequest(offset: 0, limit: pageSize))`. A completion whose captured generation is stale returns without touching state. `CancellationError` never produces `.failed`.
- `loadMore` requests `PageRequest(offset: nextOffset, limit: pageSize)`, sets `isLoadingMore`, appends items whose `id` is not already present (a `Set<Item.ID>` is kept alongside), updates `total` when non-nil and `nextOffset = page.nextOffset`. Failure sets `loadMoreError = error.message` and keeps `nextOffset` so retry works.
- `error.message`: `(error as? MusicBackendError)?.errorDescription ?? error.localizedDescription`, a private helper shared with the model (`MusicBackendError` is already user-facing and redacted per #0062).
- A page with zero items and a non-nil `nextOffset` is treated as the last page (defensive against a backend that always sets `nextOffset`).

### 3. `LibraryBrowser`: `LibraryBrowserModel` (`Sources/LibraryBrowser/LibraryBrowserModel.swift`)

```swift
public enum LibrarySection: String, Hashable, Sendable, CaseIterable, Identifiable { case artists, albums, playlists }

@MainActor @Observable
public final class LibraryBrowserModel {
    public enum Connection: Hashable, Sendable {
        case idle, connecting, connected
        case failed(message: String, needsSettings: Bool)   // needsSettings: `.notConfigured`
    }
    public enum LoadState<Value: Hashable & Sendable>: Hashable, Sendable {
        case idle, loading, loaded(Value), failed(String)
    }
    public enum SearchPhase: Hashable, Sendable { case idle, searching, loaded(SearchResults), failed(String) }

    public let backend: any MusicBackend
    public private(set) var connection: Connection = .idle
    /// `.playlists` only when `backend.capabilities.contains(.playlists)`.
    public var sections: [LibrarySection]
    public var section: LibrarySection = .artists             // didSet: loads that section's list once (lazily), clears selection
    public let artists: PagedList<LibraryArtist>             // section .artists
    public let allAlbums: PagedList<LibraryAlbum>            // section .albums
    public let playlists: PagedList<LibraryPlaylist>         // section .playlists
    public let artistAlbums: PagedList<LibraryAlbum>         // albums of `selectedArtist`
    public private(set) var tracks: LoadState<[LibraryTrack]> = .idle   // of `selectedAlbum` or `selectedPlaylist`
    public var selectedArtist: LibraryArtist?     // didSet: artistAlbums.reload(with: albums(of:)); selectedAlbum = nil
    public var selectedAlbum: LibraryAlbum?       // didSet: loadTracks(of: album) or tracks = .idle
    public var selectedPlaylist: LibraryPlaylist? // didSet: loadTracks(ofPlaylist:)
    /// Rows the artists column draws. #0017 replaces the identity mapping with its grouping.
    public var artistRows: [LibraryArtist] { artists.items }

    public var searchText: String = ""            // didSet: scheduleSearch()
    public private(set) var search: SearchPhase = .idle
    public var isSearching: Bool { !trimmedQuery.isEmpty }
    public let searchDelay: Duration
    public let searchLimit: Int

    public init(backend: any MusicBackend, pageSize: Int = 100, searchDelay: Duration = .milliseconds(300), searchLimit: Int = 50)

    public func appeared()        // connect() unless already connected/connecting; then load the current section if its list is .idle
    public func disappeared()     // cancel in-flight loads and the pending search; keep items and selection
    public func retryConnection() // connect() again (also after `.failed`)
    public func refresh()         // reload the current section's list and the selection's children
    public func searchNow()       // Return in the field: skip the delay
    public func clearSearch()     // searchText = "" (results cleared, nothing sent)
    public func select(_ artist: LibraryArtist)   // from a list or a search result; switches section to .artists if needed
    public func select(_ album: LibraryAlbum)     // from any column; also sets selectedArtist when the album carries artistID and the current artist differs (looked up in loaded rows; else nil)
}
```

Behaviour:

- `connect()`: `.connecting`; `try await backend.connect()`; success → `.connected` then `loadSectionIfNeeded()`. `MusicBackendError.notConfigured(msg)` → `.failed(message: msg, needsSettings: true)`; any other error → `.failed(message: error.message, needsSettings: false)`; `CancellationError` → back to `.idle`. One task at a time (`connectTask`), cancelled by a new `connect()` or `disappeared()`.
- `loadSectionIfNeeded()`: the current section's `PagedList` gets `reload(with:)` only when its `phase == .idle`; the loaders are `{ try await backend.artists(page: $0) }`, `{ try await backend.albums(of: nil, page: $0) }`, `{ try await backend.playlists(page: $0) }`. Switching sections keeps the other lists' items (no refetch when switching back); `refresh()` reloads.
- `selectedArtist.didSet`: `artistAlbums.reload(with: id.map { id in { try await backend.albums(of: id, page: $0) } })`; `selectedAlbum = nil`. Selecting the same artist again is a no-op.
- `loadTracks`: a private `tracksGeneration` + task; `.loading` → `.loaded(tracks)` in the backend's order (no client-side sort; disc/track numbers are only displayed) → `.failed(message)`. Changing the selection cancels the previous task.
- `scheduleSearch()`: cancel `searchTask`; `trimmedQuery` empty → `search = .idle`, return (nothing sent). Else `searchTask = Task { try await Task.sleep(for: searchDelay); guard !Task.isCancelled; search = .searching; let r = try await backend.search(query, limit: searchLimit); search = .loaded(r) }`, errors → `.failed(message)`, cancellation → nothing. `searchNow()` is the same without the sleep. A search generation counter drops answers for an older query.
- Selecting a search result does not clear `searchText`; the detail column shows the selection while the content column keeps the results. The user clears the field to go back to the lists.
- `disappeared()` cancels `connectTask`, `searchTask`, the tracks task and `cancel()`s the four lists; a `.connecting` connection goes back to `.idle` so the next `appeared()` retries. `appeared()` on an already connected model does not call `connect()` again.
- Logging: `Logger(subsystem: "com.brennanmke.SkinAmp", category: "LibraryBrowser")`, `info` for connect outcomes by case name and `debug` for page counts and the query's character count. Never the query text, a message body or an address.

`Sources/LibraryBrowser/LibraryFormat.swift`: `public enum LibraryFormat { static func duration(_ seconds: TimeInterval?) -> String }` → `"3:06"`, `"1:02:03"` above an hour, `"–:––"` for nil; `static func trackNumber(_ track: LibraryTrack) -> String` → `"9"`, or `"1-9"` when `discNumber > 1`; `static func countLabel(_ list: PagedList<…>) -> String?` → `"23 of 242"` when `total` is known, else nil. Pure and unit-tested.

`StubMusicBackend.swift`:

```swift
public actor StubMusicBackend: MusicBackend {
    public enum Method: Hashable, Sendable, CaseIterable { case connect, artists, albums, tracks, playlists, playlistTracks, search, artwork, outputs, play, transport }
    public enum Call: Hashable, Sendable {
        case connect, disconnect
        case artists(PageRequest), albums(MediaID?, PageRequest), tracks(MediaID), playlists(PageRequest), playlistTracks(MediaID)
        case search(String, Int), artwork(ArtworkRef, Int), outputs
        case play([MediaID], OutputDevice.ID, PlayMode), transport(TransportCommand, OutputDevice.ID)
    }
    public nonisolated let sourceID = "stub"
    public nonisolated let displayName = "Stub"
    public nonisolated let capabilities: BackendCapabilities

    public init(library: StubLibrary = .sample(), capabilities: BackendCapabilities = [.search, .artwork, .localOutput], reportsTotals: Bool = true)
    public var library: StubLibrary                      // settable between calls
    public private(set) var isConnected = false
    public private(set) var calls: [Call] = []
    public func calls(_ method: Method) -> [Call]
    public func count(_ method: Method) -> Int

    /// Thrown by every later call of `method` until cleared.
    public func setError(_ error: MusicBackendError?, for method: Method)
    /// Later calls of `method` suspend until `release`/`fail`; a cancelled suspended call throws CancellationError.
    public func gate(_ method: Method)
    public func release(_ method: Method)
    public func fail(_ method: Method, with error: any Error)
    public private(set) var suspendedCount: Int          // currently suspended calls
    public private(set) var cancelledCount: Int          // suspended calls that were cancelled

    public var artworkBytes: [ArtworkRef: Data] = [:]    // for #0017
    public func emit(_ snapshot: NowPlaying)             // feeds every live `nowPlaying` stream, for #0018/#0064
}
```

Rules: every library method records its `Call`, then checks `errors[method]`, then the gate (same continuation-table pattern as `StubDownloader` in `TrackCacheTests/TestSupport.swift`, with `withTaskCancellationHandler`), then answers from `library`. Paging: `Page.make(items: slice, request:, total: reportsTotals ? count : nil)`. `albums(of: id)` whose kind is not `.artist` throws `.notFound`. `playlists`/`tracks(ofPlaylist:)` throw `.unsupported(.playlists)` unless `capabilities` contains `.playlists`. `artwork` returns `artworkBytes[ref]` or throws `.notFound`. `outputs()` → `[OutputDevice.thisMac]`. `play`/`transport` record only; `nowPlaying(on:)` is an `AsyncStream` that yields `.idle(on:)` first and then whatever `emit` sends. The gates are what make the loading-state tests deterministic.

### 7. Tests (`Tests/LibraryBrowserTests/`)

### 11. Risks and gotchas

- **#0062 API drift.** Only `PagedList` (`PageRequest`, `Page.nextOffset`, `Page.total`) and `LibraryBrowserModel` (the protocol methods, `capabilities`, `MusicBackendError`) name #0062 types. If `Page` gains a cursor, `PagedList` stores `next: PageRequest?` instead of an offset and nothing else moves. If `MusicBackendError` is not `LocalizedError`, the `message` helper switches on the cases.
- **`ForEach` and duplicate ids.** Plex paging is offset-based over a live library; an insert between pages can repeat an item. `PagedList` dedupes by id, which is also what keeps `List(selection:)` stable.
- **`onAppear` as the paging trigger.** When a first page is shorter than the viewport, every row including the last one appears, so `loadMoreIfNeeded` still fires. `prefetchDistance` 10 covers fast scrolling; `isLoadingMore` guards against the burst of `onAppear`s that a scroll produces.
- **`@Observable` plus `Task` captures.** Every task captures `[weak self]` and its generation; completions check both before writing state. `searchText.didSet` must not do async work directly: it only schedules a task.
- **`.searchable` on macOS** keeps its own field state and calls the binding per keystroke; the model's debounce is the only throttle. `onSubmit(of: .search)` maps Return to `searchNow()`; the `.searching` phase is shown with a spinner, not by disabling the field.
- **Debounce tests and time.** A 20 ms delay with synchronous `searchText` writes is deterministic (the task cannot run between the writes); `waitFor` has a 5 s ceiling. The "Return searches at once" test uses a 5 s delay so a wrongly debounced call would time out visibly rather than pass by luck.
- **Stub gates and cancellation.** A gated call must resume with `CancellationError` on task cancellation, or `disappeared()`/selection-change tests hang; copy the `withTaskCancellationHandler` pattern from `StubDownloader`, including the early-cancel case.
- **Strict concurrency.** `PagedList.Loader` is `@Sendable`; the closures capture `any MusicBackend` (Sendable) and a `MediaID` (Sendable). `PagedList` is `@MainActor`; `StubMusicBackend` is an actor whose `library` setter is awaited in tests.
- **Window scene and the smoke test.** The Library window is not opened at launch (`Window` scenes open on demand), so `--launch` stays offline. Do not add `.defaultLaunchBehavior` or an auto-open; if a first-launch open is wanted later it goes behind a defaults key.
- **No art slot.** Rows deliberately leave no reserved space for art; #0017 adds the leading `ArtworkView` so the layout changes once, not twice.
- **Music Assistant totals and search.** `total == nil` hides the "N of M" caption rather than showing "N of ?"; a backend whose search is one server call (#0062 section 10) changes nothing here.
