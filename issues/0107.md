## Description

`MusicAssistantBackend.play(_:on:mode:)` refuses `OutputDevice.thisMacID` ("Choose a speaker…"), `transport` and `nowPlaying` treat This Mac as not theirs, and `outputs()` would list SkinAmp's own Sendspin player as one more speaker once #0108 connects it. For #0066, This Mac must be selectable as a Music Assistant player: Music Assistant content played on This Mac goes to the MA player that wraps SkinAmp's Sendspin client, transport and now-playing follow that player, and the player never shows up twice in the Output menu.

How the player appears (probed, [docs/sendspin-notes.md](../docs/sendspin-notes.md) section 7): MA registers a non-web Sendspin client as a hidden protocol player and, about 15 s after its first connect, wraps it in a `universal_player` whose `player_id` is `up` + 8 hex characters (not the client id). The client id appears in that player's `output_protocols` (`protocol_domain: "sendspin"`). After a disconnect the universal player stays listed with `available: false` and is reused on the next connect. Playback commands go to the universal player's id (it has no `play_media` feature; MA routes to the Sendspin protocol).

## Resolution notes

> 🟢 Resolved 2026-10-19 — MusicAssistantBackend resolves This Mac to the universal player wrapping SkinAmp's Sendspin client (via `output_protocols`), plays, sends transport and follows now playing there, hides it from `outputs()`, and keeps volume and balance local; remote outputs are unchanged.

Review (Opus, medium): independent fast-tier run `20261019-231709-63009` passed (1246 tests, all 14 expected). A first review run (`20261019-231415-61437`) also passed all 14 expected tests but AudioCoreTests aborted with `required condition is false: NULL != engine` in `AnalyzerTap.remove()` from its deinit; AudioCore is outside this change, and the rerun was clean. Secret gate: `record-ma-fixtures.py --check` passed (49 files). The app does not shorten backend texts: `PlayerModel.showBackendFailure` posts `errorDescription` as the marquee notice, which scrolls when longer than 31 units (as the old "Choose a speaker…" text did); `LibraryFallbackController.report` ignores `.backend`, so these errors do not trigger a source fallback. Today the app routes This Mac transport and now playing to the local backend (`PlaybackRouter`), so the new paths stay unused until #0109.

## Root cause

`MusicAssistantBackend` had no notion of SkinAmp's own Sendspin client: it refused `thisMacID` for play, treated it as foreign for transport and now playing, and `MAPlayer` did not decode `output_protocols`, so the universal player wrapping the client could not be recognised or hidden.

## Fix

Followed the plan. `MAOutputProtocol` + `MAPlayer.outputProtocols` + `hosts(sendspinClientID:)`; backend gains `.localOutput`, `setLocalSendspinClientID(_:)`, `resolveLocalPlayer()` (cache, then `players/all`; not-registered / pending / unavailable messages as public statics `thisMacNotRegisteredText`, `thisMacPendingText`, `thisMacUnavailableText`), filters the local player from `outputs()`, routes play/transport on This Mac to the wrapper's id, throws `.unsupported(.localOutput)` for volume/balance, and runs the now-playing watch on the wrapper (retry every 2 s up to 30 s while pending) rewriting `output` to `thisMacID`. `connect`/`disconnect` clear `localPlayerID` and keep `localClientID`.

Deviations / notes:
- No existing test contained "Choose a speaker"; the refusal test was `BackendTransportTests.playOnThisMacExplainsHowToPickASpeaker`, renamed to `playOnThisMacWithoutSendspinExplains` and now expects `thisMacNotRegisteredText`.
- `BackendOutputsAndProbeTests.capabilitiesIncludeRemoteOutputs` now expects `.localOutput` too.
- Two new `MAFixture` cases (`playersAllSendspin`, `playersAllSendspinUnavailable`); `MAFixtureTests` count goes 40 -> 42 and both join the skipped set (they share `players/all` with the winning route).
- Fixture: `display_name` set to null and the scrubbed placeholder id dropped from `can_group_with`. `record-ma-fixtures.py --check`: "secret gate: passed (49 files)".
- Marquee length of the messages was not checked against the app's truncation (no `showBackendFailure` found); first sentences are kept short.

## Plan

### Model (`Packages/PlayerKit/Sources/MusicAssistantKit/Models/MAPlayers.swift`)

- `public struct MAOutputProtocol: Codable, Hashable, Sendable { outputProtocolID (output_protocol_id), name?, protocolDomain? (protocol_domain), isNative? (is_native), available?, priority? }`.
- `MAPlayer` gains `outputProtocols: [MAOutputProtocol]?` (`output_protocols`; optional, so older fixtures still decode).
- `extension MAPlayer { public func hosts(sendspinClientID id: String) -> Bool }`: `playerID == id` (a standalone Sendspin player) or any `outputProtocols` entry with `outputProtocolID == id` and `protocolDomain == "sendspin"` (the universal wrapper).

### Backend (`Packages/PlayerKit/Sources/MusicAssistantKit/MusicAssistantBackend.swift`)

1. `capabilities` gains `.localOutput` (the comment "#0066 adds `.localOutput`" goes).
2. New state: `private var localClientID: String?` and `public func setLocalSendspinClientID(_ id: String?)` (called by the app when the Sendspin session starts or stops, #0109). Setting a different id clears `localPlayerID`.
3. `private var localPlayerID: String?`, resolved by `private func resolveLocalPlayer() async throws -> MAPlayer`: the cached `players` first, else `players/all` (refreshing the cache), picking the entry where `hosts(sendspinClientID:)` is true; prefer an `available` one if several match. Errors: no client id set → `MusicBackendError.backend(Self.thisMacNotRegisteredText)` = "This Mac isn't connected to Music Assistant. Turn on Play on this Mac in Settings › Music Assistant."; not found → `.backend(Self.thisMacPendingText)` = "Music Assistant is still setting up this Mac as a player. Try again in a few seconds." (the first-connect 15 s wait); found but `available == false` → `.backend("This Mac isn't connected to Music Assistant right now.")`. Messages fit the 31-character marquee notice the way the app already truncates `MusicBackendError.backend` texts (check `StatusNotice`/`showBackendFailure`; keep the first sentence short).
4. `outputs()`: filter out every player where `hosts(sendspinClientID: localClientID)` (and, when `localClientID` is nil, nothing changes). Cache them as today so `resolveLocalPlayer` can use the listing.
5. `play(_:on:mode:)`: for `thisMacID`, `let player = try await resolveLocalPlayer()` and send the same `player_queues/play_media` as for a speaker with `queueID: player.playerID`. The `thisMacID` refusal goes.
6. `transport(_:on:)`: `thisMacID` maps to the resolved player id for `play`, `pause`, `togglePlayPause`, `stop`, `next`, `previous`, `seek`, `setShuffle`, `setRepeat`. `setVolume` and `setBalance` on `thisMacID` throw `MusicBackendError.unsupported(.localOutput)`: the app applies them to the local `Player` (#0109), which reports volume to MA through Sendspin (#0108).
7. `nowPlaying(on:)` / `startWatcher`: for `thisMacID`, when a client id is set, resolve the player id inside the watcher task (retrying every 2 s while `thisMacPending`, at most 30 s, yielding `.idle(on: thisMacID)` meanwhile) and run `MANowPlayingWatch` on that id, then set every snapshot's `output` (a `var`) to `OutputDevice.thisMacID` before yielding. With no client id, keep today's idle stream. `setLocalSendspinClientID` restarts watchers on `thisMacID`.
8. `disconnect()` keeps `localClientID` (it belongs to the app) but clears `localPlayerID` (a new server has other players).
