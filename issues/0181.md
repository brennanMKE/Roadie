# 0181 — The Library has no Play Next

| | |
|---|---|
| **Status** | open |

| **Platform** | macOS |
| **First seen** | 2026-10-23 |

## Description

Phase B of M15. The Library's context menus offer Play (replace the queue) and Add to Queue (append). There's no way to say "play this album after the current song" without replacing the queue. Winamp's JTFE did this with `/ADD \\QUEUE`, which appends the files and queues them.

This issue adds:

- A **Play Next** item between Play and Add to Queue for track rows, album rows and Discover rows.
- A `PlayMode.next` that the folder backend and Music Assistant both understand.

**Order (umbrella decision 6):** Play Next puts its items at the *front* of up-next, in their own order. So a second Play Next plays before the first.

- Local: append the tracks, then `prependUpNext` their new entry ids (#0177).
- Music Assistant: `MAQueueOption.next` (it exists: `MARequest.swift`), which inserts right after the current item.

Both behave the same way. Like `.append`, Play Next starts playback only when the output was idle with an empty queue.
