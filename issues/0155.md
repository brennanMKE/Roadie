## Description

M14 work item W4 from [docs/design/release.md](../docs/design/release.md). Depends on: W3.

## Expected behavior

About, marquee, Sendspin player name, Museum user agent, Settings copy, errors, usage descriptions, Keychain label, `skinAmpMediaID`, `SKINAMP_SLOW_TESTS` → Roadie equivalents; tests updated. Case-insensitive grep finds no `SkinAmp` in `App/`, `Packages/`, `QuickLook/`, `scripts/`, `project.yml` except legacy migration constants; `--full` VM pass.

## Root cause

After W3 renamed the project, targets and scripts, the strings people see and the code identifiers still said SkinAmp:
About, the idle marquee, the Sendspin product, manufacturer and player name, the Museum User-Agent, Settings copy,
errors, the Keychain label, thread names, the playlist temp file, `skinAmpMediaID`, `outputsHideSkinAmpsOwnPlayer`,
`SKINAMP_SLOW_TESTS`, and the probe and recorder scripts.

## Fix

- eddb694: every item above renamed to Roadie (`Roadie (<host>)`, `Roadie/<v> (+https://roadie.sstools.co/)`,
  `Roadie Music Assistant token`, `Roadie.progressive-*`, `Roadie Playlist.html`, `roadieMediaID`,
  `outputsHideRoadiesOwnPlayer`, `ROADIE_SLOW_TESTS`), and the tests that assert them. Tests that replay recorded
  fixtures now read the recorded ids from the fixture instead of a `skinamp-...` literal, so they still exercise the
  same paths: `MusicAssistantThisMacTests` passes the recorded Sendspin id to the backend and checks the wrapper is
  hidden with it and shown without it; `ClientCallTests`/`SecrecyTests` call the recorded unknown player and command;
  `SendspinMessagesTests` encodes a hello with the recorded identity and compares it to the recorded frame.
- 7a4b843: the stale-clone sweep in `run-tests-vm.sh` dropped the transitional `skinamp-test-` prefix, so the capture
  groups moved to date `$match[1]`, time `$match[2]`, pid `$match[3]`. No `skinamp-test-*` clones existed (`tart list`).
- efac7c7 (review): the hello test used to pin the default `SendspinDeviceInfo` product and manufacturer implicitly;
  reading them from the fixture lost that. `identityAndDeviceInfoNameRoadie` now pins `Roadie`/`Roadie`, the
  `Roadie (<host>)` name, the `roadie-` client-id prefix and that the id is kept across loads.

The recorder's probe ids are now `roadie-no-such-player` and `roadie/no_such_command`. The next recording (#0133)
writes those into `error-unknown-*.json`; the tests read the ids from the fixture and `PROBES` matches the new command,
so nothing breaks, and those two fixtures then drop out of the grep exceptions.
