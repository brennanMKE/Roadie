## Description

Play to one or more AirPlay 2 speakers (HomePods, Apple TVs) from inside SkinAmp, the way Music.app does, with enhanced buffering, multi-room sync and working remote controls.

## Long Description

Umbrella for milestone **M8: AirPlay 2 speakers**, from [docs/airplay-macos-handoff.md](../docs/airplay-macos-handoff.md). It ships no code itself; it stays open until every child issue is resolved, closed or won't-fix.

The current `AVAudioEngine` output cannot get enhanced buffering; only `AVQueuePlayer` (option A) or `AVSampleBufferAudioRenderer` + `AVSampleBufferRenderSynchronizer` (option B) can, and per-app routing on macOS is thinly documented. So the spike (#0050) comes first and decides the architecture; #0052–#0054 are written against its outcome. Now Playing and remote commands (handoff step 3) already exist from #0007, including the macOS `playbackState`; the spike checks they work from a HomePod.

Open questions for the user (from the handoff doc), to settle before #0052 is planned:

- Formats beyond what AVFoundation decodes (OGG, Opus, MOD/XM/IT)? If yes, option B is effectively required.
- Is crossfade a requirement?
- Is system-wide output (option C) acceptable as the AirPlay path if per-app routing proves unsupported for a custom renderer?

Music Assistant (M9, #0059) becomes the default library source and plays to HomePods from its server, with multi-room sync. Revisit this milestone's scope once #0064 works; it matters mainly for the Plex and folder sources.

The minimum macOS version is 14 (`project.yml`).
