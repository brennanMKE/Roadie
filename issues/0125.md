# 0125 — Output panel has no per-speaker volume or view of what each player is playing

| | |
|---|---|
| **Status** | open |
| **Module** | App / LibraryBrowser / MusicAssistantKit |
| **Platform** | macOS |
| **First seen** | 2026-10-20 |

## Description

Requested by the user after trying 0.1.0-c87a381 alongside Music Assistant's own web app and iPhone app. Those apps show:

1. **Every player and what it's playing.** The player list shows each speaker (and SkinAmp's own "SkinAmp" player for This Mac), with its current track and state, so the user can see which one SkinAmp is driving.
2. **An output sheet in Now Playing.** Expanding Now Playing shows an outputs button at the bottom; tapping it lists the outputs of the current playback (the group leader and its members), each with its own volume slider, plus the group's volume.

SkinAmp has the Output panel from #0118 (checkboxes, "Only", groups) but no per-speaker volume, no group volume, and no indication of what each player is playing. The main window's volume slider only drives the target (#0121's leader).

## Expected behavior

- **Per-output volume in the Output panel.** Each checked output (This Mac and every member speaker) has a volume slider (and mute), sent with `players/cmd/volume_set` / `volume_mute` to that player. This Mac's slider sets SkinAmp's own volume.
- **Group volume.** When more than one output is selected, a group slider at the top moves them together (`players/cmd/group_volume`, `group_volume_mute`), and the main window's volume slider drives the group volume, not only the leader's.
- **Volumes follow Music Assistant.** A change made in the web or iPhone app moves SkinAmp's sliders (from the player-updated events #0121 already follows); dragging a slider doesn't fight incoming updates.
- **What each player is playing.** Each row in the Output panel shows the player's state and current track (title · artist, or "Idle"), and marks the one SkinAmp controls, so the panel works like Music Assistant's player list. Picking a row that's already playing something adopts it (per #0121) rather than restarting.
- Tests with the existing fakes cover the volume commands, group volume, following an external volume change, and the per-row now-playing text.

## Plan

### What the recorded data actually carries

Checked against `Packages/PlayerKit/Sources/MusicAssistantKitStub/Fixtures/players-all*.json`, `player-get.json`, `player-queues-all.json` and the `Player` schema in `docs/ma-protocol/openapi.json`:

- `volume_level`: integer 0…100, or **null** on universal players whose `volume_control` is `"none"` (then `supported_features` has no `volume_set`/`volume_mute`).
- `volume_muted`: bool or **null** (null on AirPlay speakers that do list `volume_mute`).
- `group_volume`: integer, present on every recorded player. For an ungrouped player it equals `volume_level`; it is `0` where `volume_level` is null. `group_volume_muted` is a nullable bool. No grouped player was recorded, so `group_volume` on a real leader is unverified: treat it as the group's level and fall back to the leader's `volume_level` when it is missing.
- `current_media`: recorded only on the hidden Sendspin web player. The track for a speaker comes from its (leader's) queue `current_item` (`name`, `media_item.artists[0].name`). `MANowPlayingMapper.snapshot` already does this fallback.
- `events.json` is empty, so the shape of `player_updated` is unverified. That doesn't matter here: `playbackActivity()` refetches `players/all` plus `player_queues/all` on any `player_updated`/`queue_updated`, with a 150 ms debounce. Volumes come from that snapshot and never from event payloads.
- Commands (`docs/ma-protocol/commands.json`): `players/cmd/volume_set {player_id, volume_level: int}`, `players/cmd/volume_mute {player_id, muted: bool}`, `players/cmd/group_volume {player_id (group player or sync leader), volume_level: int}`, `players/cmd/group_volume_mute {player_id, muted: bool}`. The last one redirects a synced member to its leader server-side.

### Step 1: model, decoding, commands (MusicBackendKit, MusicAssistantKit, LocalPlayback, LibraryBrowser router)

1. **`OutputActivity`** (`MusicBackendKit/Models.swift`) gains these fields, all optional with nil defaults so existing call sites compile:
   - `volume: Float?` (0…1; nil means no volume control) and `muted: Bool?`.
   - `groupVolume: Float?` and `groupMuted: Bool?`.
   - `title: String?` and `artist: String?`.
2. **`MAPlayer`** (`Models/MAPlayers.swift`): decode `groupVolume: Double?` (`group_volume`) and `groupVolumeMuted: Bool?` (`group_volume_muted`). Use `Double?` like `volumeLevel` so ints decode.
3. **`MAPlaybackActivity.map`** fills the new fields:
   - Volumes come from the player itself, never its leader: `volume_level / 100` clamped, nil when null or when `supported_features` lacks `volume_set`. `muted` is nil when `volume_mute` isn't listed.
   - `groupVolume`/`groupMuted` come from `group_volume`/`group_volume_muted`, nil when `volume_level` is null.
   - `title`/`artist` come from the same queue the state already uses (the leader's queue for a member), through a new `MANowPlayingMapper.titleAndArtist(player:queue:)`. Factor it out of `snapshot` so the two can't drift.
4. **`TransportCommand`** gains `setMute(Bool)`, `setGroupVolume(Float)` and `setGroupMute(Bool)`. The one exhaustive switch outside MA is `LocalPlayerOutput.perform`: there `setMute` and the group cases are no-ops. The local backend never receives them, see 6.
5. **`MARequest`**: add `groupVolume(playerID:level:)` and `groupVolumeMute(playerID:muted:)` with the documented arg names. `volumeMute` already exists.
6. **`MusicAssistantBackend.transport`**:
   - `.setMute`: goes to the player itself, never redirected. Throws `.unsupported(.remoteOutputs)` when `supported_features` lacks `volume_mute`.
   - `.setGroupVolume` and `.setGroupMute`: go to `activeGroup ?? syncedTo ?? playerID`, the same redirect playback commands use. Level clamped like `.setVolume`.
   - On `thisMacID`, only `.setVolume`/`.setBalance` keep throwing `.unsupported(.localOutput)`. `.setMute` and the group commands resolve the wrapper through `resolveLocalPlayer()`, so they throw `thisMacNotRegisteredText` with Sendspin off.
7. **`PlaybackRouter.backend(for:command:)`**: `.setMute`, `.setGroupVolume` and `.setGroupMute` on This Mac always go to `remote`. The local `Player` has no mute: muting This Mac goes through Music Assistant, whose `setMute` reaches `SendspinPlayer` (#0108).

### Step 2: pure decisions (LibraryBrowser, new `OutputVolume.swift`)

All testable without the app (the app has no test target):

- **`OutputVolume.mainTarget(selection:devices:) -> MainVolumeTarget`**: `.player(leader)` when `selection.members.isEmpty` and the leader isn't a group player, else `.group(leader)`. `PlayerModel.setVolume`/`nudgeVolume` turn it into `.setVolume` or `.setGroupVolume` on the leader. This is how the main window's slider drives group volume: a group player (`isGroup`) also counts as a group, since its own `volume_level` is MA's group level.
- **`OutputVolume.mainLevel(target:activity:localVolume:nowPlayingVolume:) -> Float?`**: the value the main slider shows.
  - `.player(thisMac)`: the local `Player.volume`.
  - `.player(speaker)`: `nowPlaying.volume`, as today.
  - `.group(id)`: that player's `groupVolume ?? volume` from the activity.
- **`OutputVolume.rowLevel(for:activity:localVolume:)`**: This Mac's row always shows the local `Player.volume`, because AudioCore is the truth and Sendspin reports it to MA. Every other row shows its activity `volume`/`muted`.
- **`OutputStatusText.line(for:activity:names:) -> String`**: the per-row caption:
  - "Playing · Title — Artist" or "Paused · Title"
  - "Idle" when stopped or when no activity is known
  - "Unavailable" when the device isn't available
  - "With Kitchen" when it plays as a member of another leader, followed by the track when known.

  Title and artist are trimmed. A missing artist drops the " — Artist" part.
- **`VolumeFollower`** (value type, injected `Date`): how incoming updates and drags coexist, extending the existing `SliderFocus` rule ("follow unless held") with a settle window.
  - `hold(value)`: while held, `incoming(_:)` is ignored.
  - `release(sent:at:)`: after release, the slider keeps the last sent value until a snapshot reports it (±1 %) or `settle` (1.5 s) passes, then follows again. Without this the slider snaps back to the stale level from the debounced snapshot that raced the last `volume_set`.
  - One follower per row id, plus one for the group slider. The main window's volume uses one too: replace the bare `sliderFocus != .volume` check in `observeNowPlaying` with the follower, keeping `SliderFocus.volume` for the marquee.
- **Adopt on pick**: `PlaybackOwnership.adoptsOnPick(_ id:selected:activity:) -> Bool` is true when `id != selected` and its activity is `.playing`/`.paused` with `leader == nil`. `OutputSelection.selectingOnly(_:adopt:)` then emits a new `Step.adopt(id)` instead of `.move(to:)` (an ungroup `.setMembers` still comes first). Adopting never moves or stops anything: it doesn't stop the previous target. #0121's exclusive stop runs only when SkinAmp starts playback, so picking a speaker that already plays is the same as Music Assistant's player list switching its view. Checkbox toggles are unchanged: adding a busy speaker as a member makes it join the leader, which is what grouping means.

### Step 3: app wiring and the popover

- **`PlayerModel`**:
  - Keep `activity` `@ObservationIgnored` for the ownership logic. Add an observed `outputLevels: [OutputDevice.ID: OutputLevel]`, holding the shown volume, muted and isHeld for each row plus a `group` entry. `activityChanged` updates it through the followers. This is what makes a change made in the web or iPhone app move SkinAmp's sliders.
  - Add `setOutputVolume(_:for:)`, `setOutputMute(_:for:)`, `setGroupVolume(_:)`, `setGroupMute(_:)`, `beginOutputVolumeDrag(_:)` and `endOutputVolumeDrag(_:)`. All of them go through the existing serial `commandStream`: add a `send(_:to:)` overload so popover drags reach the speakers in order.
  - `setVolume`/`nudgeVolume` pick `.setVolume` or `.setGroupVolume` from `OutputVolume.mainTarget`. `activityChanged` also refreshes the main `volume` from `mainLevel` while the target is `.group`.
  - `applyOutputSelection` handles `.adopt(id)` by calling `adopt(id)` (`PlayerModel+Ownership.swift`). `selectOnlyOutput` passes `adopt: PlaybackOwnership.adoptsOnPick(...)`.
- **`OutputPickerView`**: widen to about 360 pt and wrap the list in a `ScrollView` capped near 480 pt.
  - **Group volume header**: shown when `mainTarget` is `.group`. It holds a mute button (`speaker.slash`/`speaker.wave.2`), a `Slider` and a percentage. Ids `library.output.group.volume` and `library.output.group.mute`.
  - **Each device row**: line 1 is the checkbox and name, a "SkinAmp" badge on the leader (it replaces the "leader" caption and keeps the help text), then "Only". Line 2 is the `OutputStatusText` caption in `.caption`/secondary. Line 3 appears only for checked outputs: mute button, `Slider(onEditingChanged:)` wired to begin/end drag, and a percentage. Ids `library.output.<id>.volume` and `.mute`.
  - When `volume` is nil the slider is disabled, with help "This speaker has no volume control". This Mac shows no mute button unless the activity has a This Mac entry (wrapper registered).
  - **Group rows**: get the caption line too. The selected group's volume is the header.
  - No marquee text for popover drags; the main window keeps its own.
