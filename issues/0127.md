## Description

Reported by the user while checking #0120: every DMG installs as SkinAmp 0.1.0 (1), so neither About SkinAmp nor Finder's Get Info shows which build is installed, and the only clue is the DMG's filename. The user asked for a build number set in the build script, the way another of their projects does it:

```
BUILD_NUMBER="$(date -u +%Y%m%d)"
xcodebuild archive ... CURRENT_PROJECT_VERSION="$BUILD_NUMBER"
```

There, `CFBundleVersion` comes from `$(CURRENT_PROJECT_VERSION)`, so the command-line override reaches the bundle, and the committed default (`1`) is used only by non-release builds. In SkinAmp, `project.yml` sets `CURRENT_PROJECT_VERSION: "1"` with `GENERATE_INFOPLIST_FILE: YES`, and the Release app is built by the `app-release` step of `scripts/run-tests-vm.sh --dmg` inside the guest, then packaged by `scripts/make-dmg.sh`.

## Expected behavior

- A release build (the `--dmg` path) gets a unique, increasing `CFBundleVersion` set by the script: a UTC date plus time, e.g. `20261020.2115`, because several builds land on one day. The value is computed once on the host and passed into the guest's `xcodebuild` as `CURRENT_PROJECT_VERSION=…` (the app and the thumbnail extension must share it).
- About SkinAmp shows it: "Version 0.1.0 (20261020.2115)". If cheap, also show the commit hash (e.g. in the About panel's credits or a custom Info.plist key).
- `make-dmg.sh` names the DMG with the build number as well as the commit, and prints the version it found inside the app.
- Debug and test builds keep the committed default `1`.

## Plan

- `scripts/run-tests-vm.sh --dmg`: compute `BUILD_NUMBER=$(date -u +%Y%m%d.%H%M)` on the host and pass `CURRENT_PROJECT_VERSION=$BUILD_NUMBER` to the guest's Release `xcodebuild` (a command-line setting applies to every target, so the app and both Quick Look extensions match); write it to `release/build.txt`.
- `scripts/verify.sh`: the RELEASE line names the build number.
- `scripts/make-dmg.sh`: read `CFBundleVersion` from the app, name the DMG `SkinAmp-<version>-<build>-<commit>.dmg`, print the version.
- About panel: the standard panel already shows `Version <short> (<CFBundleVersion>)`; no code change. Commit hash in the bundle skipped (needs a custom plist; not cheap) — it stays in the DMG name.
- Debug/test builds untouched (project.yml keeps `1`).

## Root cause

`project.yml` hard-codes `CURRENT_PROJECT_VERSION: "1"` for every target, and nothing in the release path overrode it, so every Release build carried `CFBundleVersion` 1.

## Fix

`scripts/run-tests-vm.sh --dmg` computes `date -u +%Y%m%d.%H%M` once on the host and passes `CURRENT_PROJECT_VERSION=<n>` to the guest's Release `xcodebuild`. That setting applies to every target, so the app and both Quick Look extensions get the same number. The script also writes the number to `release/build.txt`. `scripts/verify.sh` reports it on the RELEASE line. `scripts/make-dmg.sh` reads `CFBundleVersion` from the app, names the DMG `SkinAmp-<version>-<build>-<commit>.dmg`, and prints `Version X (build), commit C`. About SkinAmp's standard panel shows `Version 0.1.0 (<build>)` without any code change. I didn't embed the commit in the bundle because that needs a custom plist, so the commit appears only in the DMG name. Debug and test builds keep `1`.
