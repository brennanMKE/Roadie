# 0256 — Random Skin can pick the skin that is already showing

| | |
|---|---|
| **Status** | open |
| **Module** | SkinKit / App |
| **Platform** | macOS |
| **First seen** | 2026-10-30 |

## Description

Found while writing #0217's tests. Main menu › Skins › Random Skin (and the Skins window's Random) can land on the skin that's already showing, so the command sometimes appears to do nothing. `SkinIndexStore.randomSkin` (`Packages/SkinKit/Sources/SkinLibrary/SkinIndexStore.swift:461`, and the `statuses:` overload at :603) is a plain `ORDER BY random() LIMIT 1`, and neither it nor `SkinBrowserModel.random()` excludes the current skin. #0217's plan expected Random never to return the current skin when two or more loadable skins exist.

## Plan

Pass the current skin's id to `randomSkin` and exclude it (`AND id != ?`) when at least one other candidate exists; fall back to the current one only when it's the only loadable skin. Make the choice testable deterministically (an injectable random source, or assert over the SQL's candidate set rather than a random draw). Regression test in SkinLibraryTests: with two loadable skins and one current, Random always returns the other; proven to fail first.
