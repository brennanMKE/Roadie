# 0075 — Only one Music Assistant server can be configured

| | |
|---|---|

## Description

The user runs a different Music Assistant server at each location (home, another site), and sometimes reaches one remotely over Tailscale. SkinAmp should hold several Music Assistant configurations and connect to whichever one is reachable, switching automatically when the Mac moves between networks.

## Acceptance criteria

- Settings › Music Assistant lists multiple servers. Each has a name, an address (LAN host, `.local`, IP, or a Tailscale MagicDNS name or 100.x address), its own token in the Keychain (one item per server), and the server id learned on first successful connection.
- Each server can optionally be tied to one or more Wi-Fi network names (SSIDs). "Use current network" fills it in from the network the Mac is on.
- Choosing the active server:
  1. Servers tied to the current SSID are tried first.
  2. Then every other server, in the user's list order. This covers Tailscale, where the SSID tells nothing.
  3. A server counts as reachable only if its `/info` answers in time **and** its `server_id` matches the one stored for that configuration. A different server answering at the same address never receives the token (the MA API docs recommend this check).
- The choice is re-evaluated when the network changes (`NWPathMonitor`, Wi-Fi changes, Tailscale coming up or going down) and when the active server drops. The switch goes through #0070's source controller without interrupting what is playing on This Mac.
- Settings and the Library window say which server is in use and why ("Home — on network X", "Studio — via Tailscale", "none reachable").
- If none is reachable, #0067's fallback goes to the local folder as today.
- Tokens, addresses and SSIDs never appear in logs; addresses and SSIDs live in UserDefaults, tokens only in the Keychain.

## Notes

Reading the Wi-Fi SSID on macOS 14 and later (`CWWiFiClient.shared().interface()?.ssid()`) returns nil unless the app has Location Services permission. That means adding `NSLocationUsageDescription` and requesting `CLLocationManager` authorization. The plan must decide how to handle a denied permission. Recommended: the SSID is only a hint, so with no permission or no Wi-Fi (Ethernet, Tailscale) the reachability probe alone picks the server, and Settings explains that the SSID shortcut needs Location access.

Builds on #0061 (client) and #0063 (settings). It may simply be folded into #0063 if that issue isn't implemented yet; the planner decides.
