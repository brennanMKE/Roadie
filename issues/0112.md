## Description

Found in review of #0106 (code 6614606). When the timed PCM stream runs dry (a network stall), the player node's sample time keeps advancing with nothing scheduled. `streamErrorMicros` is computed as `anchor + sample/rate`, so it can't see the offset the stall created and never crosses `snapMicros`; playback resumes late by the length of the stall and stays out of sync with the server and with grouped speakers. The Sendspin spec requires a re-anchor after an underrun. Separately, a `.gap` schedules its whole silence as one buffer however long the gap is.

## Expected behavior

- When the played sample passes `scheduledNodeFrames` (an underrun), the stream re-anchors on the next chunk so it plays at that chunk's presentation time.
- A gap longer than `snapMicros` re-anchors instead of scheduling one long silence buffer; shorter gaps keep today's silence fill.
- Offline-render tests cover an underrun followed by a late chunk (it lands at its presentation time) and a long gap (no oversized silence buffer, re-anchored), without changing file playback.

## Plan

All changes are in `Packages/PlayerKit/Sources/AudioCore/Player+Stream.swift` plus tests. `StreamSync.swift`, `GaplessScheduler`, file and progressive playback stay as they are.

### 1. Underrun → re-anchor

- `StreamSession` gains `var underruns = 0`, a diagnostic. It is cumulative, so `resetPosition()` doesn't clear it.
- In `appendStream`, after `now` is computed and **before** `session.timeline.place(…)`, check whether the node has played everything scheduled:

  ```swift
  if session.timeline.anchorMicros != nil, session.scheduledNodeFrames > 0,
     let played = streamPlayerSample(graph), played.sample >= session.scheduledNodeFrames {
      session.underruns += 1
      log.notice("stream underrun at node frame \(played.sample): re-anchoring")
      session.timeline.reset()
  }
  ```

  After the reset, `place` returns `.start` and goes through the existing `startStream` path (stop, `play(at:)` at the chunk's time, past prefix dropped), or `.late` if the chunk is already entirely past. In that case the next chunk that isn't late starts the node. Before `play(at:)` time the player sample is negative and `streamPlayerSample` returns nil, so the start-up wait never counts as an underrun.
- Use the sample comparison, not `pendingBuffers <= 0`. Buffer completions reach the main actor through a `Task`, so they lag behind the render and aren't deterministic offline. `streamBufferFinished` keeps its log line.

### 2. Long gap: no silence buffer

- In the `.gap(_, silenceMicros)` case, if `silenceMicros <= session.timeline.policy.snapMicros`, keep today's code: silence buffer, then the chunk.
- If the gap is longer, schedule no silence. Decode the chunk and schedule it at its own node sample:

  ```swift
  let startFrame = session.scheduledNodeFrames + Int64((Double(silenceMicros) * nodeRate / 1e6).rounded())
  ```

  using `scheduleBuffer(buffer, at: AVAudioTime(sampleTime: startFrame, atRate: nodeRate), …)`, and set `scheduledNodeFrames = startFrame + buffer.frameLength`. Let `scheduleStreamBuffer` take an optional `at: AVAudioTime?` (default nil) and a `startFrame` override. Log at `.notice`.
  - This re-anchors the chunk on the node's own timeline. Later contiguous chunks still chain with `at: nil` after it, and `anchor + sample/rate` stays exact, because the gap counts as played node frames, as the silence buffer did.
  - Don't restart the node (`timeline.reset()` + `startStream`). A restart would throw away the audio queued before the gap, the reason #0106 avoided restarts. If the node has already run dry, step 1 has re-anchored before `place`, so this path only sees a node that still has audio queued.
- If the explicit-time schedule misbehaves in offline rendering, fall back to a restart, which drops the pre-gap tail. Record the deviation in `## Fix`.

### Tests (`Packages/PlayerKit/Tests/AudioCoreTests/StreamPlayerRenderTests.swift`, using `StreamRig`)

- `underrunReanchorsTheNextChunkAtItsPresentationTime`
  - Setup: `beginStream`, append 5 chunks from 0 (100 ms, 441 Hz, amplitude 0.5), render 20 blocks. The node runs dry at about 4 410 frames; now is about 232 ms.
  - Append 15 chunks stamped from 100 000 µs onward. These continue the server's timeline, and the first ~6 are past.
  - Expect `rig.player.stream?.underruns == 1`.
  - Render until 400 ms + 4 blocks. The last non-zero sample must be within 512 frames of `0.4 × rate` (17 640). Today the 120 ms of skipped stream becomes a gap of silence and the audio ends about 5 300 frames late.
  - The resumed onset, the first sample above 1e-3 after frame 10 240, must be within 512 of the append-time `nowMicros` frame.
- `longGapIsReanchoredWithoutASilenceBuffer`
  - Setup: `beginStream`, append 5 chunks from 0, then 5 chunks from 2 000 000 µs (a 1.9 s gap, well over `snapMicros`).
  - Right after appending, before any render: `rig.player.stream?.pendingBuffers == 10`, so no silence buffer was scheduled. Also `scheduledNodeFrames ≈ 2.1 s × rate` (±2).
  - Render `(2.1 s × rate) / 512 + 4` blocks.
  - The first burst is all played: non-zero samples reach within 512 of frame 4 410.
  - Between about 5 000 and 87 000 the output stays below 1e-4.
  - The second burst's onset is within 512 of 88 200, and `underruns == 0`.

## Resolution notes

> 🟢 Resolved 2026-10-19 — An underrun now re-anchors the next chunk at its presentation time, and gaps longer than `snapMicros` schedule the chunk at an explicit node time instead of one long silence buffer; review re-run 20261019-232210-65352 passed the full tier (1248 tests).

## Root cause

`streamErrorMicros` maps the node's sample to stream time as `anchor + sample/rate`. During an underrun the node's sample keeps advancing with nothing scheduled, so the stall never shows up as error and the stream resumes late by the stall's length. A `.gap` also scheduled its whole silence as a single buffer, however long.

## Fix

- `appendStream` checks, before `place`, whether the played sample has reached `scheduledNodeFrames`. If so it counts `StreamSession.underruns`, logs, and resets the timeline, so the chunk starts through `startStream` at its presentation time.
- A gap longer than `snapMicros` schedules no silence. The chunk is scheduled at `scheduledNodeFrames + gap × nodeRate` with an explicit `AVAudioTime`, and `scheduleStreamBuffer` now takes `at:` and `startFrame:`. Shorter gaps keep the silence fill. The explicit-time schedule worked in offline rendering, so the restart fallback wasn't needed. Implemented as planned.
