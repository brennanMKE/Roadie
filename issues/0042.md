## Description

When the queue moves from one track to another with a different sample rate (44.1 kHz → 48 kHz) or channel count (stereo → mono), the app crashes with an uncaught `com.apple.coreaudio.avfaudio` exception, `error -10868`, thrown from `AVAudioEngine.connect` in `AudioGraph.connect(format:)`, called from `Player.begin`. Found by the #0003 review on a real-time engine; it reproduces on the pre-#0003 code too, so it dates from #0002.

## Steps to reproduce

1. Queue a 44.1 kHz stereo file followed by a 48 kHz file (or a mono file).
2. Play and let the first track end, or press Next.

## Expected behavior

The second track plays. A short gap at a format change is acceptable for now; gapless playback across formats can be a later issue.

## Actual behavior

The process crashes with `error -10868` from `AVAudioEngine.connect`.

## Plan

### Root cause (confirmed with a raw engine, scratchpad `exp42`)

`-10868` is `kAudioUnitErr_FormatNotSupported`. `AudioGraph.connect(format:)` changes the two links one at a time, so for a moment the EQ's input is at the new format and its output at the old one (or vice versa). While the engine is running the `AVAudioUnitEQ` is an *initialized* audio unit, and an initialized AU effect rejects an input/output sample-rate or channel-count mismatch; `AVAudioEngine.connect` turns that into an Objective-C exception, which nothing catches. Reproduced on a running engine for 44.1 kHz → 48 kHz and stereo → mono: the first `connect(playerNode, to: eq, format:)` throws `-10868` (reverse order throws the same, then the second call fails with `required condition is false: !srcNodeMixerConns.empty() && !isSrcNodeConnectedToIONode`). Disconnecting both links first or `engine.reset()` does not help. The same two `connect` calls succeed when the engine has never been started or is stopped, and they succeed on a running engine when the EQ is not in the chain (`playerNode → mainMixerNode`; the mixer accepts any input format). So the trigger is: reconnecting an initialized EQ at a different rate or channel count, which `Player.begin` does on the gapped (`.reachedEnd → trackEnded → startCurrentTrack`) path at every format change.

### Fix: one fixed processing format, the player node converts

Connect `playerNode → eq → mainMixerNode` once, at **the output's sample rate, stereo** (`AVAudioFormat(standardFormatWithSampleRate: rate, channels: 2)`), and never reconnect while the engine runs. `AVAudioPlayerNode` resamples and up/down-mixes files it schedules; confirmed on the default output and in offline manual rendering: 22.05/44.1/48/96 kHz, mono, stereo and 5.1 files scheduled back to back into a 48 kHz stereo connection all play (no throw), with zero silent 128-frame blocks between them, `.dataPlayedBack` completions fire for each, and mono reaches both channels. The node's timeline (`playerTime(forNodeTime:)`) runs at the connection rate: a 0.5 s file of any rate occupies 24,000 node frames at 48 kHz, and each completion arrived one render quantum (~1024 frames) after the expected boundary. Driven through the real `Player` with 44.1 stereo → 48 stereo → 44.1 mono → 96 stereo, the index went 0 → 1 → 2 → 3 → `.stopped` with zero silent blocks and 97,280 audible frames against 96,000 expected, so format changes become **gapless** too (the #0003 "deviation accepted" goes away), and the EQ runs at a single rate, which suits #0004's absolute-Hz bands. The reviewer's #0003 harness (skip, previous, seek, pause, queue edits, repeat one) behaves the same on the modified copy as on the current code.

The rate is read from `engine.outputNode.outputFormat(forBus: 0).sampleRate` *inside `start()`*, while the engine is stopped: on hardware that is the device rate (48 kHz here) and in manual-rendering mode it is the render format, so the existing offline test and the new ones run headless with no double conversion. Fall back to 44,100 if it reports 0 (no device). An output change (`AVAudioEngineConfigurationChange`) arrives after the engine stopped itself, and `handleConfigurationChange` already calls `graph.start()`, so reconnecting there at the new rate is safe (verified: the same reconnect that throws while running succeeds while stopped, and restarts fine).

Rejected alternative: stop/reset the engine around the reconnect. Works, but keeps the gap at every format change, keeps the engine stop/start on the audible path, and leaves the EQ's rate changing underneath #0004.

### Code changes

`Packages/PlayerKit/Sources/AudioCore/AudioGraph.swift`

- Remove `connectedFormat` and `connect(format:)`. Add `private(set) var processingFormat: AVAudioFormat?` (nil until the first `start()`), `var processingSampleRate: Double? { processingFormat?.sampleRate }`, and a private `connectIfNeeded()`: read the output rate (fallback 44,100), return if `processingFormat` already has that rate, else `engine.connect(playerNode, to: eq, format:)` and `engine.connect(eq, to: engine.mainMixerNode, format:)` and store it. Call it from `start()` after the `guard !engine.isRunning` and before `engine.prepare()`. Document that it is only safe while stopped (the -10868 rule above). Constructing a graph still touches no engine state beyond attach, so `AudioGraphTests` stay headless.

`Packages/PlayerKit/Sources/AudioCore/GaplessScheduler.swift`

- `ScheduledItem.frameLength` and `startFrame` are node-timeline frames (document it). Replace `seekOffsetFrames: Int64` with `seekOffset: TimeInterval` (file seconds); `append(trackID:frameLength:seekOffset:)`; `position(atNodeSampleTime:nodeSampleRate:)` returns `head.seekOffset + Double(played) / nodeSampleRate` with `played` clamped to `0...frameLength` as now.
- Add `func nodeFrames(fileFrames: Int64, fileSampleRate: Double, nodeSampleRate: Double) -> Int64` (`(fileFrames × node/file).rounded()`, identity when rates match or either is 0).
- Delete `FormatPolicy` and `AudioFormatDescriptor`; nothing else needs them.

`Packages/PlayerKit/Sources/AudioCore/Player.swift`

- `begin`: drop `graph.connect(format: file.processingFormat)`; `try graph.start()` now does the connect.
- `schedule(_:trackID:from:)`: `guard remaining > 0, let nodeRate = graph.processingSampleRate`; `frameLength: nodeFrames(fileFrames: remaining, fileSampleRate: file.processingFormat.sampleRate, nodeSampleRate: nodeRate)`, `seekOffset: Double(frame) / fileRate`. `scheduleSegment` keeps taking file frames.
- `scheduleNextIfNeeded`: remove the `connectedFormat` / `FormatPolicy` guard (keep `_graph != nil`); every next file is pre-scheduled.
- `updateCurrentTime`: `scheduler.position(atNodeSampleTime: playerTime.sampleTime, nodeSampleRate: playerTime.sampleRate)` (the node rate, not the file rate); `file` is only needed for the nil check.
- `seek`, `reconcileSchedule(.restartCurrent)` and `handleConfigurationChange` keep computing the start frame in file frames from `file.processingFormat.sampleRate`; unchanged.
- Small hardening while there: the `AVAudioEngineConfigurationChange` loop should ignore notifications whose `object` is not `graph.engine` (tests run several engines in one process).

No `App/` or `project.yml` change.

### Risks

- The processing rate is fixed at first `start()`; a later device-rate change is handled on the configuration-change path only. If macOS ever posts that notification without stopping the engine, `connectIfNeeded` must not reconnect; the `guard !engine.isRunning` in `start()` already prevents it (then the mixer converts, as today).
- `nodeFrames` rounding drifts under one frame per item; position is clamped per item and promotion is completion-driven, so it cannot accumulate.
- Real-time tests share the machine's output device and are timing-based: keep files ≤ 0.5 s, tolerances as above, and the suite serialized. If they prove flaky on the dev Mac, keep them but gate on an opt-in env var and say so in `## Gotchas`.
- A format change in the *pre-scheduled* file is now silent and gapless; the only remaining gapped path is an uncached (Plex) next track, unchanged.

## Root cause

`AudioGraph.connect(format:)` changed player -> EQ and EQ -> mixer one link at a time on a running engine. An initialized `AVAudioUnitEQ` rejects mismatched input/output sample rate or channel count, so the first `connect` at a new format threw `kAudioUnitErr_FormatNotSupported` (-10868) as an uncaught Objective-C exception. `Player.begin` did this at every format change.

## Fix

Followed the plan. `AudioGraph` has a fixed `processingFormat` (output rate, stereo) connected once by `connectIfNeeded()` from `start()` while the engine is stopped; `AVAudioPlayerNode` converts each file. `GaplessScheduler` now uses node-rate frames (`nodeFrames` scaling) and `seekOffset` in file seconds; `FormatPolicy`/`AudioFormatDescriptor` removed so every next file is pre-scheduled and format changes are gapless. `Player.updateCurrentTime` uses the node's rate; configuration-change notifications for other engines are ignored. No deviation from the plan.

## Gotchas

- The mixer's `outputFormat` reports 44.1 kHz before the engine starts even when the device is 48 kHz; the real-time test reads `graph.processingSampleRate` after `.playing`.
- A mixer tap closure created in a `@MainActor` test inherits main-actor isolation and traps (`dispatch_assert_queue`) on the audio queue; install it from a `nonisolated` helper.
- The tap lags the render thread by ~100 ms, so the real-time test waits 200 ms after `.stopped` before removing it.

## Notes
