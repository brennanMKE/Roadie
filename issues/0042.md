# 0042 — Advancing to a track with a different sample rate or channel count crashes the app

| | |
|---|---|
| **Status** | open |
| **Module** | AudioCore |
| **Platform** | macOS |
| **First seen** | 2026-10-12 |

## Description

When the queue moves from one track to another with a different sample rate (44.1 kHz → 48 kHz) or channel count (stereo → mono), the app crashes with an uncaught `com.apple.coreaudio.avfaudio` exception, `error -10868`, thrown from `AVAudioEngine.connect` in `AudioGraph.connect(format:)`, called from `Player.begin`. Found by the #0003 review on a real-time engine; it reproduces on the pre-#0003 code too, so it dates from #0002.

## Steps to reproduce

1. Queue a 44.1 kHz stereo file followed by a 48 kHz file (or a mono file).
2. Play and let the first track end, or press Next.

## Expected behavior

The second track plays. A short gap at a format change is acceptable for now; gapless playback across formats can be a later issue.

## Actual behavior

The process crashes with `error -10868` from `AVAudioEngine.connect`.

## Notes

The #0003 reviewer's suggestions: stop or reset the engine around the reconnect, or keep the EQ → mixer link at one fixed format so only the player → EQ link changes (or let the player node / mixer do the conversion). Needs a real-time test with mixed 44.1/48 kHz and mono/stereo queues; offline-mode completion handlers don't fire, so an offline render alone won't cover the advance.

The reviewer's reproduction harness is outside the repo, in the session scratchpad: `PlayerKit/Tests/AudioCoreTests/ReviewGaplessRealtime.swift` and `PK0002/`.
