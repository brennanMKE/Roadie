## Description

Add a `TrackCache` library that downloads Plex parts to `~/Library/Caches/<bundle id>/Tracks/`, indexes them, and evicts least-recently-used files above a size limit.

## Acceptance criteria

- Cache key = server `machineIdentifier` + part id + part `updatedAt`; extension from the part.
- Download to a temp file, check size against `Part.size`, then move into place; concurrent requests for the same key share one download.
- Index records size and last access; every play touches it; rebuilt from disk if missing or corrupt; partial temp files removed on launch.
- LRU eviction after each insert down to the limit (default 2 GB); the playing and prefetched tracks are pinned.
- Prefetch the next queued track when a track starts; cancel on skip.
- Settings › Cache shows usage, the limit, and Clear cache.
- Unit tests: eviction order, pinning, size accounting, index rebuild, with temp dirs and a stub downloader.

## Plan

### Scope and decisions

This issue adds the `TrackCache` target to `Packages/PlayerKit`: a bounded on-disk cache of Plex parts with LRU eviction, the `TrackResolver` that turns a Plex `Track` into a local file for `AudioCore`, the pinning link to the `Player`, and a Settings › Cache tab. It also adds the one mapping both sides need, `Track(plexTrack:machineIdentifier:)`. No browser window (#0016), no play/enqueue UI (#0018: the end-to-end "browse, play, hear the next track start with no gap" check waits for it), no plex.tv (#0014), and no playing while the download continues (#0039, M7; section 11 says what is left open for it). The "Buffering…" marquee text is M4/#0018; the `.loading` state it hangs off already exists (#0041).

- **`~/Library/Caches/<bundle id>/Tracks/`, as the description says, not Application Support.** The files are re-downloadable copies, bounded by a limit the user sets; that is the definition of a cache. Application Support is backed up by Time Machine and never purged, so 2 GB of music would land in every backup and could not be reclaimed by the system. Caches is excluded from backups and may be purged under disk pressure, which `docs/plan.md` already accepts. The consequences are handled rather than assumed: every hit stats the file, `prepare()` reconciles the index against the directory, and a file that disappears is simply downloaded again. The index (`index.json`) lives in the same directory so a purge takes both and the rebuild is the normal path. The app is unsandboxed, so the path is `FileManager.default.urls(for: .cachesDirectory, in: .userDomainMask)[0]/com.brennanmke.SkinAmp/Tracks`; `Bundle.main.bundleIdentifier` is read at runtime with that string as the fallback, and tests always pass a temp directory.
- **The cache is a generic file cache; Plex stays outside it.** `TrackCache` (an `actor`) knows keys, file names, sizes, dates, pins and a `CacheDownloader` protocol. It never sees a `URLRequest`, a `PlexClient` or a token. `PlexPartDownloader` is the one `CacheDownloader` that talks HTTP: it builds the request with `PlexClient.request(path: partKey)`, so the token goes in the `X-Plex-Token` header through the one place that sets Plex headers, and streams the body into the temp file the cache hands it. This split is what makes the token rule provable: the only type that holds a token is `PlexClient`, which is built per download and discarded.
- **AudioCore does not import PlexKit, before or after.** `TrackCache` depends on both `AudioCore` (for `Track`, `TrackResolver`, `Player`, `PlayQueue`) and `PlexKit` (for `PlexClient`, `PlexPart`, the token store). `PlexTrackResolver: TrackResolver` lives in `TrackCache` and is what the app passes to `Player(resolver:)`. The one `AudioCore` edit is additive: `Track.Source.plex` gains `size: Int64? = nil` so the resolver can check the download against `Part.size` (a byte count is not Plex knowledge; the default keeps every existing `.plex(partKey:cacheKey:)` call compiling).
- **Prefetch is the `Player`'s existing look-ahead; the cache just makes it a download.** `Player.scheduleNextIfNeeded()` already calls `resolver.localURL(for:)` on the track after the current one as soon as a track begins, and `discardSchedule()` cancels that `preloadTask` on every skip, seek and queue restart. With the cache as the resolver, that call *is* the prefetch and that cancel *is* the cancel. Nothing in `Player` changes for this. The one race it creates is handled in the cache: skipping *to* the track being prefetched cancels the preload a moment before `startCurrentTrack` asks for the same key, so a download whose last waiter leaves is cancelled only when its key is **not pinned**; pinned downloads run to completion with zero waiters. The pins are set on `trackChanged`, which `Player` emits from `queue.select`/`queue.next` *before* `startCurrentTrack` runs, so the new current track is pinned by the time its preload is cancelled.
- **Pinning = "keep on disk and keep downloading".** One set, `setPinned(_:)`, holds the current track's key and the key of the track `PlayQueue.indexAfterCurrentEnds()` names (so repeat and shuffle agree with the look-ahead). `CachePinner` computes it from `player.queue` on every `PlayerEvent` and is otherwise a pure function, `CachePinner.pinnedKeys(in:)`, that is unit-tested without an engine. Eviction also never touches the key being inserted or any key with a download in flight, so a prefetched file survives its own insert even if the pins are stale.
- **Cancellation is per waiter; the download belongs to the actor.** `file(forKey:)` registers a continuation per caller (the `GateResolver` pattern from `AudioCoreTests/TestSupport.swift`). Cancelling a caller resumes only that continuation with `CancellationError`; when the last waiter leaves and the key is not pinned, the download `Task` is cancelled and its entry removed at once, so a request that arrives a moment later starts a fresh download instead of inheriting a cancelled one. The orphaned task deletes its temp file on the way out.
- **Writes are temp-then-rename on the same volume.** Downloads go to `Tracks/tmp/<key>-<uuid>.part`; after the size check the file is moved to `Tracks/<key>.<ext>` with `FileManager.moveItem`, a rename on APFS. `index.json` is written with `.atomic`. `prepare()` wipes `tmp/` on launch, so a crash mid-download leaves nothing behind.
- **The limit is in `UserDefaults` (`TrackCacheLimitBytes`), default 2 GB = 2,000,000,000 bytes**, chosen from a picker (500 MB, 1 GB, 2 GB, 5 GB, 10 GB, 20 GB; `ByteCountFormatter` shows decimal units on macOS, so "2 GB" reads as 2 GB). Lowering it evicts immediately; that is `docs/plan.md`'s manual check 4.
- **Models in the package, views in the app**, as #0011 did: `CacheSettingsModel` (`@MainActor @Observable`, in `TrackCache`) is unit-tested; `CacheSettingsView` is thin and checked by hand.
- **Verification is the VM script.** `swift test --package-path Packages/PlayerKit` picks up the new `TrackCacheTests` target (a fourth "Test run with …" line). Every download in the tests comes from `StubURLProtocol` (random bytes) or an in-process `StubDownloader`; nothing reaches joe, no token exists in the guest, and nothing opens an audio device. The one test that needs a real server is opt-in, like `PlexIntegrationTests`, and is left for the user on the host.

### 3. `TrackCache` (`Sources/TrackCache/TrackCache.swift`)

```swift
/// Writes one part into a file the cache created. Must honour task cancellation (throw
/// `CancellationError` or `URLError(.cancelled)`); the cache deletes the file either way.
public protocol CacheDownloader: Sendable {
    func download(partKey: String, to fileURL: URL) async throws -> Int64   // bytes written
}

public actor TrackCache {
    public struct Entry: Codable, Hashable, Sendable {
        public var key: String
        public var fileName: String          // "<key>.<ext>"
        public var size: Int64
        public var lastAccess: Date
    }
    public struct Stats: Hashable, Sendable {
        public var totalBytes: Int64
        public var fileCount: Int
        public var limitBytes: Int64
        public var inFlight: Int
    }

    public static let defaultLimitBytes: Int64 = 2_000_000_000
    public static let indexFileName = "index.json"
    public static let tempDirectoryName = "tmp"
    /// ~/Library/Caches/<bundle id>/Tracks
    public static func defaultDirectory(bundleIdentifier: String? = Bundle.main.bundleIdentifier) -> URL

    public init(directory: URL, limitBytes: Int64 = defaultLimitBytes,
                downloader: any CacheDownloader, now: @escaping @Sendable () -> Date = Date.init)

    /// Creates the directories, wipes tmp/, loads or rebuilds the index, reconciles it with the
    /// files on disk, evicts to the limit. Idempotent; every other method calls it first.
    public func prepare() throws

    /// The cached file for `key`, downloading it through `partKey` when it is not on disk.
    /// A hit touches `lastAccess`. Concurrent calls for one key share one download.
    public func file(forKey key: String, partKey: String, expectedSize: Int64?) async throws -> URL

    public func setPinned(_ keys: Set<String>)
    public private(set) var pinned: Set<String>
    public private(set) var limitBytes: Int64
    public func setLimit(_ bytes: Int64)            // persists nothing; evicts at once
    public func stats() -> Stats
    public func entries() -> [Entry]                // oldest first (tests, the Cache tab later)
    public func clear() throws                      // every file and the index; downloads in flight finish normally
}

public enum TrackCacheError: Error, Hashable, Sendable, LocalizedError {
    case notPlexTrack
    case noServer                                   // no saved address or no token
    case serverMismatch                             // the key's machineIdentifier is not the saved server's
    case download(PlexError)                        // 401, 404, other status, transport
    case sizeMismatch(expected: Int64?, actual: Int64)
    case io(String)                                 // a FileManager / FileHandle failure, its localizedDescription
    // errorDescription: short English per case; none interpolates a URL, a request or a header.
    // The Player shows `localizedDescription` as `errorMessage`, so these are user-facing.
}
```

Rules (each has a test in section 9):

- **File name:** `key + "." + ext`, where `ext` is `(partKey as NSString).pathExtension.lowercased()` filtered to `[a-z0-9]{1,5}`, else `"audio"`. Keys contain only `[A-Za-z0-9-]` by construction (section 5), so there is no path escape.
- **Hit:** entry present and `fileExists` with the entry's size → `lastAccess = now()`, write the index, return the URL. Entry present but file missing or a different size → remove the entry (and the file, if present; it is corrupt), fall through to a miss.
- **Miss:** if `inflight[key]` exists, join it; otherwise create the temp file (`FileManager.createFile` in `tmp/`), start `Task { downloader.download(partKey:to:) }` and store it with an empty waiter list. The caller then suspends on a `CheckedContinuation` inside `withTaskCancellationHandler`. The download task, on success: stat the temp file; if `expectedSize != nil` and differs, or the file is empty, delete it and fail with `.sizeMismatch`; else `moveItem` to the final name (removing a stale file there first), insert the entry with `lastAccess = now()`, run eviction protecting that key, write the index, resume every waiter with the URL. On failure: delete the temp file, resume every waiter with the error (a `PlexError` arrives wrapped as `.download`, cancellation as `CancellationError`). In both cases `inflight[key] = nil` unless the entry was already replaced by an orphan rule below.
- **Waiter cancellation:** the handler calls `leave(key, waiterID)` on the actor: resume that continuation with `CancellationError`; if no waiters remain and `key ∉ pinned`, cancel the task and remove `inflight[key]` immediately (the task's own failure path then finds no entry and only cleans its temp file). A pinned download keeps running with no waiters and inserts normally.
- **Eviction** (`evictIfNeeded(protecting:)`): while `totalBytes > limitBytes`, remove the entry with the oldest `lastAccess` that is not in `pinned ∪ protecting ∪ inflight.keys`; delete its file; stop when nothing is removable (log once at `info`). Runs after every insert, after `setLimit`, and at the end of `prepare()`. A file larger than the whole limit is still stored (it is protected during its own insert) and goes at the next insert.
- **Index:** `{"version": 1, "entries": [Entry…]}`, `lastAccess` as seconds since 1970, `JSONEncoder` with sorted keys, written atomically after every mutation (insert, touch, evict, clear). `prepare()` loads it; a missing or undecodable file starts from empty. Then reconcile with `contentsOfDirectory` (skipping `tmp/` and `index.json`): entries whose file is missing are dropped; entries whose size differs from disk are dropped and the file deleted; files not in the index are added with `lastAccess` = modification date. Write the result.
- **`clear()`:** delete every entry's file and the index, empty `entries`; files held open by `AVAudioFile` keep playing (APFS keeps the unlinked inode), so the Player needs no notice. In-flight downloads are not cancelled; they insert when they finish.
- **Logging:** `Logger(subsystem: "com.brennanmke.SkinAmp", category: "TrackCache")`: `debug` per hit/miss/insert/evict with the key and byte counts (`privacy: .public`; a key is server id + part id + stamp, not a secret), `error` per failure with the case name. Never a URL, request, header, or file contents.

### 4. `PlexPartDownloader` (`Sources/TrackCache/PlexPartDownloader.swift`)

```swift
public struct PlexPartDownloader: CacheDownloader {
    /// Built per download so Settings changes apply without restarting; nil means "no server set up".
    public typealias ClientProvider = @Sendable () throws -> PlexClient?

    public init(clientProvider: @escaping ClientProvider, session: URLSession = Self.makeSession())
    /// Ephemeral, `urlCache = nil`, `requestCachePolicy = .reloadIgnoringLocalCacheData`,
    /// `timeoutIntervalForRequest = 30`, `timeoutIntervalForResource = 600`. No URL cache: Foundation's
    /// Cache.db must never hold a response body or the request that fetched it.
    public static func makeSession() -> URLSession

    /// The app's provider: `PlexServerSelection` from `defaults` (`PlexSettingsModel.selectionDefaultsKey`),
    /// `PlexAddress.normalize(address)`, the token from `tokenStore.load()`, `PlexClientIdentifier.stored()`.
    /// Returns nil when the address is empty or there is no token. Reads the Keychain on each call.
    public static func settingsClientProvider(
        defaults: UserDefaults = .standard, tokenStore: any PlexTokenStore = KeychainPlexTokenStore()) -> ClientProvider

    public func download(partKey: String, to fileURL: URL) async throws -> Int64
}
```

`download`: `guard let client = try clientProvider() else { throw TrackCacheError.noServer }`; `var request = client.request(path: partKey)`; `request.setValue("*/*", forHTTPHeaderField: "Accept")` (the token header stays; a part is a file, not JSON); `let (bytes, response) = try await session.bytes(for: request)`; map a non-`HTTPURLResponse` to `.download(.transport(.badServerResponse))`, 401 → `.download(.unauthorized)`, 404 → `.download(.notFound)`, any other non-2xx → `.download(.httpStatus(n))`, a thrown `URLError` → `.download(.transport(code))` (`.cancelled` is rethrown as `CancellationError` so the cache treats it as a cancel); then open `FileHandle(forWritingTo: fileURL)` and copy `bytes` through a 256 KB `[UInt8]` buffer, flushing on each full buffer and at the end, counting bytes; `try fileHandle.close()`; return the count. The `for try await` loop throws when the task is cancelled, which is the cancellation path. Nothing here logs; the cache does.

The `URLSession` from `makeSession()` is created once per downloader (a `let`); tests pass `StubURLProtocol.handle().session`.

### 9. Unit tests (`Tests/TrackCacheTests/`, Swift Testing)

Shared helpers in `TestSupport.swift`: `makeTempDir()` (removed in `defer`), `ManualClock` (a lock-guarded `Date` whose `now` closure the cache takes, with `advance(seconds:)`), `StubDownloader: CacheDownloader` (a `[partKey: Data]` table, a call counter per key, an optional per-key `Gate` that suspends `download` on a continuation until `release`/`fail`, and an `onCancel` counter through `withTaskCancellationHandler`; it writes the bytes with `Data.write(to:)`), `randomBytes(n)`, `filesOnDisk(dir) -> [String: Int64]` (names to sizes, excluding `tmp/` and `index.json`), and `directoryContains(dir, text)` which reads every file under `dir` as bytes and searches for the UTF-8 of `text`. The token constant is `tok-UNIT-TEST-SECRET-0013`.

`TrackCacheTests` (one temp dir, cache and stub per test; parallel-safe):

1. `missDownloadsOnceAndStoresTheFile` — URL is `<dir>/<key>.m4a`; size matches; one downloader call with the part key; `entries()` has the key; `index.json` exists.
2. `hitSkipsTheDownloaderAndTouchesLastAccess` — second call: still one download; `lastAccess` moved to the advanced clock; the index on disk shows the new date.
3. `concurrentRequestsForOneKeyShareOneDownload` — gated; two tasks; both see the downloader called once; release; both get the same URL.
4. `differentKeysDownloadConcurrently` — gated; two keys; both downloads are in flight before either is released; `stats().inFlight == 2`.
5. `sizeMismatchStoresNothing` — `expectedSize` ≠ body length → `.sizeMismatch(expected:actual:)`; no file, no entry, `tmp/` empty.
6. `emptyBodyIsRejected` — zero bytes with `expectedSize: nil` → `.sizeMismatch(expected: nil, actual: 0)`.
7. `downloadFailureReachesEveryWaiterAndLeavesNoTemp` — gate fails with `.download(.httpStatus(500))`; both waiters get it; `tmp/` empty; the next request downloads again (nothing stuck in flight).
8. `cancellingTheLastWaiterCancelsTheDownload` — gated; `task.cancel()`; the stub's `onCancel` fired; `tmp/` empty; `stats().inFlight == 0`; a new request starts a new download (count 2).
9. `cancellingOneOfTwoWaitersKeepsTheDownload` — cancel one; `onCancel` not fired; release; the other receives the file.
10. `pinnedDownloadOutlivesItsWaiters` — `setPinned([key])`; cancel the only waiter; `onCancel` not fired; release; the file is on disk and the next request is a hit.
11. `skipToPrefetchedTrackJoinsTheRunningDownload` — the race from the decisions, in miniature: pin `{A, B}`, request B (gated), cancel that waiter, request B again → one download, the second request completes on release.
12. `lruEvictsTheOldestFirst` — limit 300; A, B, C of 100 bytes with the clock advancing; touch A; insert D → B is gone (not A); `filesOnDisk` has A, C, D; `stats().totalBytes == 300`.
13. `pinnedFilesAreNeverEvicted` — pin A (the oldest); insert past the limit → B goes instead; pin everything and insert → nothing is evicted, `totalBytes > limitBytes`, no error.
14. `theInsertedFileSurvivesItsOwnInsert` — one 500-byte file into a 300-byte cache → stored; the next 100-byte insert evicts it.
15. `loweringTheLimitEvictsAtOnce` — three files, `setLimit(150)` → one remains (the newest).
16. `sizeAccountingMatchesDisk` — after a mix of inserts, touches and evictions, `stats().totalBytes` equals the sum of `filesOnDisk` and `fileCount` its count.
17. `indexIsRebuiltWhenMissing` — fill a cache, delete `index.json`, open a new cache on the directory → same keys and sizes; `lastAccess` within 2 s of each file's modification date.
18. `corruptIndexIsReplaced` — write `not json` to `index.json` → `prepare()` succeeds; entries come from disk; the file is valid JSON afterwards.
19. `staleEntriesAndWrongSizedFilesAreDropped` — remove one file by hand (entry dropped) and truncate another (entry dropped, file deleted); the next requests download both again.
20. `partialTempFilesAreRemovedOnPrepare` — write `tmp/x-y.part` → `prepare()` → `tmp/` empty, stored files untouched.
21. `clearRemovesEverything` — files and `index.json` gone, `stats()` zero, the next request downloads again; `clear()` on an empty cache does not throw.
22. `lastAccessSurvivesRestart` — touch A after B; new cache on the directory; insert past the limit → B is evicted (the persisted date wins over file order).
23. `fileNamesUseTheKeyAndTheSanitizedExtension` — `file.m4a` → `.m4a`, `file.MP3` → `.mp3`, `file.weird-ext!` → `.audio`, no extension → `.audio`.

### 12. Risks

- **`URLSession.bytes(for:)` through `StubURLProtocol`.** It creates a data task with a delegate internally, and a `URLProtocol` that calls `didLoad` feeds it, so the stub path should work unchanged; test 26 proves it in the guest. If the guest's Foundation delivers nothing through the stream, fall back inside `PlexPartDownloader` to `session.download(for:)` and `moveItem` the returned temp file into `fileURL` *before* any further `await` (the file is gone once the method returns), and say so in `## Fix`. Do not fall back to `data(for:)`: a 50-minute podcast must not be buffered in memory.
- **Byte-at-a-time iteration of `AsyncBytes`.** It reads from an internal buffer and is fast enough for a 20 MB file (well under a second), but a `URLSessionDataDelegate` that writes each `didReceive data` chunk is the alternative if a VM run shows a 65 KB stub body taking more than a few milliseconds per test. Either way the protocol `CacheDownloader` is unaffected.
- **The pinned/skip race is handled by ordering, not timing.** It depends on `Player` emitting `trackChanged` from the `queue` `didSet` *before* `startCurrentTrack` cancels the preload, which is how `play(at:)`, `next()` and `previous()` are written today. Test 11 proves the cache side; test 39 proves the pins move. If `Player` is ever changed to select and start in another order, the only cost is a restarted download, never a wrong file.
- **Pins are updated on events, not on every queue edit.** Enqueueing behind the current track changes "next" without an event; the new next is prefetched by `reconcileSchedule` and its file is protected during its own insert, so the only exposure is a later insert evicting it before it plays, which would then just download again. Acceptable; a `queueChanged` event in `AudioCore` is the fix if it ever shows.
- **Keychain prompt on the first download of a dev build.** `settingsClientProvider` reads the Keychain per download, from a background task. With ad-hoc signing the "SkinAmp wants to use your confidential information" dialog appears once per rebuild (as #0011 documents), now possibly during playback rather than in Settings. Click Always Allow; it is the dev-build experience only. A denied read makes the provider return nil → `.noServer` → the player shows "Plex is not set up…". Nothing crashes, nothing is deleted.
- **`Accept: */*` on part requests.** `PlexClient.request` sets `Accept: application/json`; Plex serves a part regardless, but overriding to `*/*` is the honest header and costs nothing. Test 26 asserts it so a later refactor of `request` does not drop it.
- **A purged Caches directory during playback.** `AVAudioFile` holds the open inode, so the current and pre-scheduled files keep playing; later hits stat the file and re-download. The same holds for Clear Cache, which is why it needs no coordination with the Player.
- **One index write per touch.** A few hundred bytes per play, atomic. If the Cache tab's 2 s refresh plus touches ever show up in Instruments, coalesce writes with a short debounce inside the actor; the API does not change.
- **Decimal "2 GB".** `2_000_000_000` bytes matches what `ByteCountFormatter` prints; if the user expects GiB the picker labels still say what they mean. Do not mix units between `storedLimit` and the picker.
- **A single file over the limit** is kept until the next insert, so a 50-minute podcast plays even on a tiny limit, and `totalBytes > limitBytes` is a legal transient state the Cache tab may show.
- **Disk full** surfaces as `.io(...)` from the `FileHandle` write, the temp file is removed, and the player shows the message; nothing half-written is ever moved into place.
- **`Track.Source` gained an associated value.** `Hashable` now includes `size`, so `.plex(a, b)` and `.plex(a, b, size: 1)` differ; `Track` identity is its `id`, nothing compares sources across the two forms, and the default argument keeps old call sites compiling.
- **Actor reentrancy.** Every `await` inside `TrackCache` (there are few: the download task's completion, `leave`) re-reads state afterwards; `inflight` is the only cross-await structure and each path checks whether its entry is still the one it created (orphans compare the task identity before touching it).
- **Swift Testing and the gates.** Gated tests await continuations, never `Task.sleep` polling, except 34 (0.2 s before cancelling a delayed stub route) and 39 (`waitUntil` for the pinner's `Task`). Keep every delay under a second.
