## Description

In #0212's run `20261029-191545-21712`, #0208's UI tests and #0211's unit tests left `SkinBrowserWindowView` at 96 %, `SkinCellView` at 97.4 %, `MuseumCellView` at 95.4 % and `SkinLibraryModel` at 82.2 % (185 of 225 lines). `testFolderSetAndClear` and `testApplyDefaultFolderKeepsASetFolder` (`Tests/RoadieTests/PlaylistMenusTests.swift:126-158`) already check `setFolder` and "No folder chosen", and #0209 (in flight) adds `applyDefaultFolderCreatesAndStoresTheDefault`. Four gaps remain:

- `SkinLibraryModel.countsText` with a folder but no index ("Not indexed yet") and after a scan (`N skins in M files`), and `statusText` after a scan, are never checked (#0211's follow-up).
- Main-menu skin navigation (`.nextSkin`, `.previousSkin`, `.randomSkin`) has crash-only checks (`PlayerModelDispatchTests.swift:126`): no test model has an indexed skins list (#0211's follow-up).
- `SkinBrowserStatusView` is at 17.4 % (8 of 46): the "No skins folder" and "Could not read the skin index" states never show.
- `MuseumStatusView` is at 60.2 % (109 of 181): the offline, failed and empty content and the folder prompt never show. `SkinGridView` and `MuseumGridView` (74.5 % each) miss the same kind of branch: the load-more error footer with Retry.

## Plan

1. `Tests/RoadieTests/SkinLibraryModelTests.swift` (new, or added to the `SkinLibraryModelTests` class in `PlaylistMenusTests.swift`), on a temp folder seeded from `TestSkins/` (or the SkinKit fixture skins when the cache is absent): `countsText` is "Not indexed yet" with a folder set and no scan, then `N skins in M files` and `statusText` `N ok, P partial, F failed` (counts from the seeded folder) after `scan()`. Also `addDownloaded` of a file outside the folder (ignored) and inside it (indexed).
2. Main-menu skin navigation: with that indexed folder as the model's skins list, `.nextSkin`, `.previousSkin` and `.randomSkin` through `PlayerModel.perform(_:)` (`PlayerModel+MainMenu.swift`) change `skinBrowser`'s current skin. Next and previous wrap. Random never returns the current skin when there are two or more. These replace the `crashChecksOnly` rows in `PlayerModelDispatchTests`.
3. The status views' choice of content: move it into a small `static` function or enum next to each view (`SkinBrowserStatusView`'s phase → needs folder / failed with message / progress; `MuseumStatusView.content`'s loading / offline / failed / empty / results and when `folderPrompt` shows; the grid footers' error / loading / nothing) with no behaviour change, and test them with `SkinMuseumStub` and a `SkinBrowserModel` on a missing or unreadable index.

## Tests

`countsTextBeforeAndAfterScan`, `addDownloadedIndexesOnlyInsideFolder`, `mainMenuNextPreviousRandomSkin`, `skinsStatusContent`, `museumStatusContent`, `gridFooterContent`. Expect list: all of them.

## Which tier

**Fast:** `scripts/verify.sh --expect <the tests above>`. The new tests must not need the network, a real Keychain or a speaker. They use the stubs and injectable seams the plan names.

## UI tests

None here. The Skins window and Museum clicks are [#0208](0208.md)'s (resolved); the status states above are the ones it doesn't reach.

## By hand

None; this issue adds tests and, where the plan says so, small seams. `git diff --stat App/SkinLibraryModel.swift App/SkinBrowser/` shows only those.
