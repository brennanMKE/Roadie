## Description

Found in review of #0105. In `Packages/PlayerKit/Sources/SendspinKit/SendspinSession.swift`, `after` and `afterSleeper` append every per-exchange timeout task and every burst-tick task to `connectionTasks`, and that array is only emptied on disconnect. A connection that stays up grows it by about 9 tasks every 10 s, roughly 3,000 an hour, so memory grows for as long as SkinAmp stays connected as a Music Assistant player.

## Resolution notes

> 🟢 Resolved 2026-10-19 — The receive loop and one timer per purpose (handshake, state deadline, time reply, burst) replace the unbounded task array, so a long connection holds at most 5 tasks and disconnect cancels all of them.

Review: the diff matches the plan. Each slot cancels the task it replaces, the time-reply timer is cancelled when its exchange finishes, and the `runConnection` defer cancels and clears everything. The handshake, burst and reconnect logic is unchanged apart from the slot arguments. Independent run `20261019-233040-69180`: PASS, 8 steps, 1253 tests in 12 test runs, fast tier, silent, all 7 expected tests passed.

## Root cause

`after` and `afterSleeper` appended every timeout and burst-tick task to `connectionTasks`, which was only cleared in the `runConnection` defer. On a long-lived connection the array grew without bound (about 9 tasks per 10 s burst).

## Fix

Followed the plan. `connectionTasks` is replaced by `receiveTask` plus `timers: [TimerSlot: Task]` with slots `handshake`, `stateDeadline`, `timeReply`, `burst`. Storing a timer cancels the slot's previous task. `exchangeDone` cancels the pending time-reply timer. The defer cancels and clears all of them. `trackedTaskCount` (at most 5) is exposed for tests. Minor divergence: `disconnectCancelsEveryTrackedTask` uses `waitFor` for the zero count after `stop`, so it doesn't rely on `stop` awaiting the connection's teardown.

## Expected behavior

- Finished or cancelled timer tasks are removed (or a single timer per purpose is reused), so the number of tracked tasks stays bounded on a connection of any length.
- Disconnect still cancels every outstanding task.
- A test drives many burst intervals through the injected sleeper and asserts the tracked task count stays bounded.

## Plan

**Change** (`Packages/PlayerKit/Sources/SendspinKit/SendspinSession.swift` only, plus test support):

1. Replace `connectionTasks: [Task<Void, Never>]` with one task per purpose:
   - `private var receiveTask: Task<Void, Never>?` for the receive loop in `runConnection`.
   - `private enum TimerSlot: Hashable { case handshake, stateDeadline, timeReply, burst }` and `private var timers: [TimerSlot: Task<Void, Never>] = [:]`.
2. `after` and `afterSleeper` take a slot: `after(_ slot: TimerSlot, _ duration:, _ value:)`. Each one cancels `timers[slot]` before storing the new task, so a slot holds at most one task. Call sites: auth and hello deadlines use `.handshake` (the hello deadline replacing the auth one is fine, since `.deadline(.auth)` is ignored once `phase != .auth`); `unavailableStateAfter` uses `.stateDeadline`; `sendTime` uses `.timeReply`; `exchangeDone` uses `.burst`.
3. In `exchangeDone`, cancel the pending time-reply timer once the exchange finishes (`timers[.timeReply]?.cancel(); timers[.timeReply] = nil` next to `pendingT1 = nil`), so a fast reply doesn't leave a 2 s `Task.sleep` running.
4. The `runConnection` `defer` cancels `receiveTask` and every value in `timers`, then clears both (disconnect still cancels everything).
5. Add `var trackedTaskCount: Int { timers.count + (receiveTask == nil ? 0 : 1) }` (internal, read by tests through `@testable import`). The bound is 5.

**Test support** (`Packages/PlayerKit/Tests/SendspinKitTests/TestSupport.swift`): give `TestSleeper` an `init(releasedBursts: Int = 0)`. The first `releasedBursts` sleeps of 10 s or longer return at once (still recorded); later ones block as they do now, so the burst loop stops instead of spinning. Existing callers keep the default and behave the same.

**Tests to add** (in `SendspinSessionTests`):
- `longConnectionKeepsTrackedTasksBounded`: `startSynchronized(sleeper: TestSleeper(releasedBursts: 50))`, wait until `sleeper.sleeps.filter { $0 >= .seconds(10) }.count > 50` (all released bursts ran and the next one is blocked), then `#expect(await session.trackedTaskCount <= 5)`. Also check the transport sent many more `client/time` messages than one burst does, so the loop really ran. Then `stop`.
- `disconnectCancelsEveryTrackedTask`: synchronize, `#expect(await session.trackedTaskCount > 0)`, `await session.stop(reason: .shutdown)`, then `#expect(await session.trackedTaskCount == 0)`.

`--expect longConnectionKeepsTrackedTasksBounded,disconnectCancelsEveryTrackedTask`
