## Description

`scripts/run-tests-vm.sh` prints its summary (`==> PASS/FAIL/SKIP` per step, `TIER`, `BUILD`/`ERRORS`, `INFRA`, `AUDIO`, the selected `Test run with …` lines) only to stdout. Agents often keep just the tail of a long run's output, lose the summary, and then run the whole VM again just to quote it: #0090's and #0092's implementers each did a second full run on 2026-10-19 for that reason alone (about 2.5–3 minutes each).

Also, from the #0086 review: the `--spike` line in the script's header lists `spike-tests, spike-build, spike-smoke` but not the newer `spike-pkg-build`.

Expected:

- Every run writes its summary, exactly as printed, to `build/vm-tests/<run-id>/summary.txt` (and still prints it), including runs that end in `INFRA` or a build failure, and the exit code.
- The last line printed names the summary file, so an agent that only kept the tail can read it instead of re-running.
- `issues/Issues.md` phase 2/3 "Quote the evidence" and `docs/testing-in-vm.md` say to quote from `summary.txt` and never to re-run only to recapture output.
- The `--spike` header line lists `spike-pkg-build`.

## Plan

Only `scripts/run-tests-vm.sh`, `issues/Issues.md` and `docs/testing-in-vm.md` change. Tier: **fast** (tooling only; no slow test guards it).

### Which paths print a summary today

- **Usage errors / `--help`** (exit 2 / 0, lines 67–106): before `RUN_ID` exists. No summary, no file. Leave as is.
- **`fail`** (exit 1, `!! …` on stderr): preflight (Tart/xcodegen/disk/memory) and `gx_prep` failures. No summary. Leave as is; say so in the docs.
- **`infra_fail`** (exit 3): boot timeout (line 244) and a guest lost in `gx_prep` (line 253). It prints one `==> INFRA …` line, and this happens **before** `RESULTS_DIR` is created (that only happens at line 379). Its message points at `$EXPORT/tart-run.log`, which the `EXIT` trap deletes.
- **The normal end** (lines 392–442): the PASS/FAIL/SKIP loop, `BUILD`/`ERRORS` (with indented compiler lines), `INFRA` for a guest lost mid-run (`overall=3`), `BUILD-ONLY`/`TIER`, the indented `grep -h` lines (`Test run with …`, `Build complete!`, …), `AUDIO`, `Logs:`, then `exit $overall`. This covers passes, build failures (with or without `--build-only`) and mid-run INFRA.
- **The `cleanup` trap** then prints `==> Cleaning up (exit $rc)`. It runs on every exit, so it is the real last line today and carries the real exit code.

### Script changes

1. **One switch for teeing.** Add `SUMMARY_FILE=""` next to the other globals. Change `log` to also append to it when set:
   ```zsh
   log() { print -r -- "==> $*"; if [[ -n "$SUMMARY_FILE" ]]; then print -r -- "==> $*" >>"$SUMMARY_FILE"; fi; }
   ```
   Use `if`, not `[[ … ]] && print …`: as the last command, a false `[[ ]]` makes `log` return 1, and `set -e` would abort the script on every `log` call before the summary.
   Add a helper that turns it on: `summary_start() { mkdir -p "$RESULTS_DIR"; SUMMARY_FILE="$RESULTS_DIR/summary.txt"; : >"$SUMMARY_FILE"; }`.
2. **Normal end.** Call `summary_start` right after the `print ""` at line 392 (the blank line stays out of the file, so the file starts at the first `PASS/FAIL/SKIP` line). Every `log` from there on is teed automatically. Make the three indented blocks tee as well by appending `| tee -a "$SUMMARY_FILE"` to each pipeline: the compiler errors (`… | head -30 | sed 's/^/    /'`), the no-`file:line:col` tail (`… | tail -15 | sed 's/^/    /'`), and the `grep -hE … | sed 's/^/    /'` line (keep its `|| true` at the very end, after the `tee`, so a no-match grep under `pipefail` still doesn't abort).
3. **INFRA before the summary.** In `infra_fail`, call `summary_start` first, copy `$EXPORT/tart-run.log` into `$RESULTS_DIR/` (`cp … 2>/dev/null || true`) and make the boot-timeout message point at `$RESULTS_DIR/tart-run.log` instead of the export (which the trap deletes). Then `log "INFRA  $*"` and `exit 3` as now. Also add `log "Logs: $RESULTS_DIR"` before the exit so this path ends like the normal one.
4. **Exit code and the final line, in `cleanup`.** The existing `log "Cleaning up (exit $rc)"` is now teed when a summary was started, which records the true exit code on every summary path (including an unexpected abort after the summary started). Keep it first in `cleanup`. At the **end** of `cleanup` (after `rm -rf "$EXPORT"`), add
   ```zsh
   if [[ -n "$SUMMARY_FILE" ]]; then log "Summary: $SUMMARY_FILE"; fi
   ```
   so the very last printed line names the file, and the file ends with the same line. Nothing else in `cleanup` prints (lease/stop/delete are silenced), so the file is byte-for-byte the tail of stdout. Use the absolute path, like the `Logs:` line.
5. **Header comment.** Line 28: `steps spike-pkg-build, spike-build, spike-tests, spike-smoke` (run order). Under "Exit codes" (after line 49) add:
   ```
   # The summary (from the first PASS/FAIL/SKIP line, or the INFRA line if the guest never came up, to the
   # final "Cleaning up (exit N)") is also written to build/vm-tests/<run-id>/summary.txt; the last line printed names it.
   # Usage errors (exit 2) and preflight failures (exit 1, "!!" on stderr) print no summary and write no file.
   ```
   `--help` prints this header, so it shows up there too.

## Root cause

The summary existed only on stdout, so an agent that kept the tail of a long run lost it. `infra_fail` also ran before the results directory existed and pointed at `tart-run.log` in the export, which the `EXIT` trap deletes.

## Fix

Per the plan: `SUMMARY_FILE` + `summary_start`; `log` tees into it when set; the normal end starts it after the blank line and the three indented blocks `tee -a` into it; `infra_fail` starts it, copies `tart-run.log` into the results dir (boot-timeout message points there), and logs `Logs:`; `cleanup` keeps `Cleaning up (exit $rc)` first (now teed) and ends with `Summary: <path>`. Header lists `spike-pkg-build` and documents summary.txt. Docs wording as planned.

Deviation: the `grep -hE … "$RESULTS_DIR"/*.log` line printed a zsh `no matches found` error to stderr when the guest was lost before the results pull (no logs), so the output tail no longer matched the file. It now builds `step_logs=(…/*.log(N))` and greps only if non-empty. Found by the extra INFRA run.
