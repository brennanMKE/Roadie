## Root cause

There was no backend API or menu item for saving a queue as a playlist, and nothing chose between a file and a Music Assistant playlist for the queue on screen.

## Fix

- `MusicBackend.saveQueueAsPlaylist(on:named:)`. The default (in `RemoteQueue.swift`) throws `.unsupported(.queueEditing)`.
- Music Assistant (in `MusicAssistantBackend+Queue.swift`, with `MARequest.queueSaveAsPlaylist`): trims the name and refuses an empty one. Resolves the active queue, which for a synced speaker is the leader's queue. Sends `player_queues/save_as_playlist`. A `QueueEmpty` error (Music Assistant error code 8, details "Cannot save an empty queue as a playlist.") becomes `emptyQueueText`. A details text naming an empty queue is kept as a fallback. An `InvalidDataError` (code 3: nothing in the queue can go in a playlist, such as only radio stations) becomes `nothingToSaveText`, "Nothing in this queue can go in a playlist."
- `LibraryBrowser/QueueSaveTarget.choose(output:feed:capabilities:)` follows `QueueRowsSelection` (decision 4):
  - local queue → file
  - speaker, or This Mac on the Music Assistant feed → Music Assistant
  - a speaker whose backend can't edit queues → refused
- App: Playback › Save Queue as Playlist… calls `PlayerModel.saveQueue()`. The file target uses the existing file panel. The Music Assistant target asks for a name in `SaveQueueSheet`, a stand-in for W2's `PlaylistNameSheet`. On success the notice reads "Saved queue as "X"" and the Library's Playlists list reloads, or is reset when it isn't shown.
- Departures from the plan:
  - The Music Assistant tests are in `BackendSaveQueueTests`, not `BackendPlaylistTests`, to avoid a file conflict with #0135/#0136.
  - `StubMusicBackend` is unchanged and uses the protocol default.

The empty-queue mapping can't fire against a real server, and its test uses a made-up error frame:

- In the server's `controllers/player_queues/controller.py`, `PlayerQueuesController.save_as_playlist(queue_id, name)` raises `QueueEmpty("Cannot save an empty queue as a playlist.")` when the queue has no items. It raises `InvalidDataError("No valid items in queue to save as playlist.")` when no item has a playlist media type.
- In `controllers/webserver/websocket_client.py`, `WebsocketClientHandler._run_handler` sends `error_code = err.error_code` and `details = str(err) or err.__class__.__name__`. The class name only appears when the message is empty.
- In `music_assistant_models/errors.py`, `QueueEmpty.error_code` is **8** and `InvalidDataError.error_code` is **3**.
- So the real frame is `error_code: 8, details: "Cannot save an empty queue as a playlist."`. `MusicAssistantBackend+Queue.swift` matches `details.lowercased().contains("queueempty")`, which never matches that frame. The error falls through to `map(_:)` → `.server` → "The Music Assistant server reported an error.", which is the unclear notice the plan asked to replace.
- `BackendSaveQueueTests.saveQueueOnAnEmptyQueueIsAClearError` passes only because its stub route sends `code: 999, details: "QueueEmpty: Queue is empty"`.

The next pass must fix these:

1. Match the empty queue on `MusicAssistantError.server(code: 8, _)`. A details check for "empty queue" can stay as a fallback.
2. Map `code: 3` (`InvalidDataError`, e.g. a queue of radio stations) to its own clear text, such as "Nothing in this queue can go in a playlist."
3. Change the test's stub error to the real frame (`code: 8`, `details: "Cannot save an empty queue as a playlist."`). Add a test for the code-3 case and include it in `--expect`.

Everything else checked out, so the next pass should touch only the items above:

- The arguments match the server: `queue_id` and `name` are both required strings, per `docs/ma-protocol/commands.json` and the controller signature.
- The server doesn't redirect `queue_id`, so the client's leader redirect is needed. `queueID(for:)` (`player_queues/get_active_queue`) does it, the same way the #0144/#0145 edits do.
- The name is trimmed and an empty one is refused before anything is sent.
- `QueueSaveTarget` follows `QueueRowsSelection`, and the App uses the same `router.backend(for:)` lookup as `observeQueue()`.
- The local queue keeps `savePlaylistFile()`.
- The menu item is disabled only for `.refused`.
- On success, the Playlists list is refreshed when it is shown and reset when it isn't.
- The `SaveQueueSheet` stand-in is fine until #0135.
- The tests use the stub transport only, with no network.
