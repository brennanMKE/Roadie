## Description

Generate a main-window thumbnail per skin with the offscreen renderer and cache it to disk.

## Acceptance criteria

- Thumbnails are generated lazily and keyed by content hash.

## Plan

Written 2026-10-14 against #0026's `MainWindowRenderer` (in progress, `Packages/SkinKit/Sources/SkinKit/Rendering/`) and #0033's `SkinLibrary` plan (not implemented). Status stays `open`; this plan writes no code.

### Scope and decisions

This issue adds one actor, `SkinThumbnailCache`, that turns a `.wsz` into a 275×116 PNG of its main window on demand and keeps it in memory and on disk, plus the smallest app hook (`PlayerModel.skinThumbnails` and a `SkinThumbnailView` cell) so #0035's grid drops it in. No grid, no search, no Skins menu (#0035), no index (#0033), no Quick Look (#0043).

- **The render is #0026's, verbatim.** One thumbnail = `MainWindowRenderer.render(skin: skin, state: .idle, scale: 1, clipToRegion: true)` after `SkinParser.parse(url:)`. `render` is a static function with no `@MainActor`, `Skin` is `Sendable`, so it runs on any worker. `clipToRegion: true` leaves the corners of shaped skins transparent, which is what a grid wants. `.idle` (stopped, "SkinAmp" in the marquee, focused title bar) is the same preset #0043 uses, so Finder and the library show the same picture. Scale 1 only: the renderer is nearest-neighbour and SwiftUI draws the image with `.interpolation(.none)`, so a 1× PNG scaled 2× on a Retina cell is pixel-identical to a 2× render (#0026's `scaleTwoIsNearestNeighbour`), at a quarter of the bytes. A half-size cell (138×58 pt) on Retina is exactly 1:1 with the file.
- **The cache key is the SHA-256 content hash from #0033, not the md5 #0026 §8 mentions.** Decision: `hash` = lowercase hex SHA-256 of the whole `.wsz`, 64 characters, exactly `SkinIngester.hash` in #0033 §6. Reasons: (1) the grid gets its rows from the index, which already stores that hash, so a lookup needs no second read of the file; (2) #0033 de-duplicates by it, so two copies of one skin share one thumbnail; (3) md5 is the Museum's key for reference screenshots, a host-side comparison concern that `scripts/fetch-webamp-references.sh` already handles with `md5 -q`; nothing at runtime needs it. #0026 §8's sentence "keyed by the `.wsz` md5" is superseded by this plan; #0026's text is not edited here. The hash function lives in one place, `SkinContentHash.hex(of: URL)` in `SkinLibrary` (CryptoKit, `Data(contentsOf:options: .mappedIfSafe)`), and whichever of #0033/#0034 lands second calls the other's function rather than hashing twice.
- **Where it lives: the `SkinLibrary` target, not `SkinKit`.** #0033 keeps `SkinKit` free of folders and persistence; a cache under `~/Library/Caches` is persistence. `SkinLibrary` depends on `SkinKit` only, so the extensions in #0043 never link it. Preferred order: #0033 first. If this issue is worked first, it creates the target, the test target, the `project.yml` product dependency and the scheme `test:` entry exactly as #0033 §1 declares them (`linkedLibrary("sqlite3")` included, so #0033's `Package.swift` diff is then zero), with only `Thumbnails/` and `SkinContentHash.swift` inside; #0033 fills the rest in.
- **Disk: `~/Library/Caches/<bundle id>/SkinThumbnails/r<version>/<hash>-275x116.png`.** Caches, not Application Support: a thumbnail is a few milliseconds to rebuild, so the system may purge it (the index in #0033 is minutes of work and lives in Application Support; the two are deliberately different). Same root as `TrackCache.defaultDirectory` and `FolderIndex` (`FileManager.urls(for: .cachesDirectory)` + `Bundle.main.bundleIdentifier ?? "com.brennanmke.SkinAmp"`). The path encodes all three key parts: content hash, renderer version (the directory) and size (the file name), so a 2× or EQ-stacked variant later cannot collide, and a stale file is self-describing. Written with `PNGWriter.data` + `Data.write(options: .atomic)`; read with `CGImageSourceCreateWithURL` and `kCGImageSourceShouldCacheImmediately: true` so decoding happens on the worker, not on the main thread at draw time (`PNGWriter.read` has no options parameter and is #0026's file; the cache calls ImageIO itself for the read).
- **Lazy, newest-first, bounded.** Nothing is rendered until a cell asks. Requests queue inside the actor and are served last-in-first-out, because during a fast scroll the most recent requests are the cells on screen; at most `maxConcurrentRenders = max(1, activeProcessorCount - 1)` run at once (the same bound as #0033's indexer), each in `Task.detached(priority: .userInitiated)` so the actor itself never does pixel work and visible thumbnails outrank the `.utility` index pass. Parsing dominates (unzip plus BMP decode of up to 16 sheets, tens of milliseconds); the composite is under a millisecond (#0026 §8).
- **Cancellation when scrolled away, without wasting finished work.** The cell uses `.task(id:)` exactly like `AlbumArtView`, so SwiftUI cancels the request when the cell leaves the screen. A request that is still queued and whose last interested caller is cancelled is dropped (never parsed). A render that has already started runs to completion and is cached (the cell comes back a moment later, as `ArtworkCache` reasons for artwork). The cancelled caller returns nil immediately.
- **Memory in front of disk.** An LRU by count and bytes, as `ArtworkCache` does: 275×116 RGBA is 127,600 bytes; the default 256 entries is about 33 MB (`memoryLimitBytes` 48 MiB, whichever trips first). Concurrent callers for one hash share one job. Disk is bounded too (`diskLimitBytes`, default 1 GiB, roughly 40k thumbnails at 25 KB): a sweep at open, in a detached `.utility` task, deletes oldest-written files (`contentModificationDate`) until under 75 % of the limit. The sweep is the only directory listing; lookups are a single `stat`.
- **Invalidation = renderer version.** `SkinThumbnailCache.thumbnailVersion = 1`, bumped whenever a commit changes the pixels of `render(state: .idle)`: `MainWindowRenderer`, `MainWindowLayout`, `MainWindowState.idle`, `SkinParser` fallbacks, `VisRenderer` colours. On open, every `r*` sibling of `r<current>` is removed (one directory delete, no per-file scan). It lives in `SkinLibrary` rather than next to the renderer so it does not touch #0026's files while #0026 is in progress; the reviewer of any renderer change checks it.
- **Failure: placeholder plus a negative cache.** `SkinParser.parse` throwing (`.modernSkin`, `.unreadableArchive`, `.noBitmaps`) returns nil, is remembered in memory (bounded set) and on disk as an empty marker `<hash>-275x116.failed` next to the PNG, so a 50 MB broken archive is never re-read after relaunch; markers live and die with the version directory. A partial skin is not a failure: the renderer draws the dark fill for a missing `main.bmp` and skips missing sprites, so partial skins get real thumbnails. A missing file (moved since indexing) returns nil with no marker, since the file may come back. A write failure (disk full, Caches purged mid-session) is logged, the directories are recreated once and the write retried, and the image is returned regardless because memory has it (the `TrackCache` rule). The placeholder itself is the cell's, not the cache's.
- **Verification is `scripts/run-tests-vm.sh [--launch] [--skins DIR]` only.** Nothing is built, tested or launched on the host. The guest has no `.wsz` files, so every test writes its own tiny archives; the opt-in `SKIN_SAMPLES_DIR` test (already exported by `--skins`) renders the real corpus and prints timings.

### 2. API (`SkinThumbnailCache.swift`)

```swift
/// One main-window thumbnail. `CGImage` is immutable; wrapped like `Skin` is.
public struct SkinThumbnail: @unchecked Sendable {
    public let image: CGImage            // 275x116, premultiplied RGBA8 (decoded from PNG on a disk hit)
    public var byteCount: Int { image.bytesPerRow * image.height }
}

public actor SkinThumbnailCache {
    /// Bump when `MainWindowRenderer.render(state: .idle)` pixels change (renderer, layout, idle preset, parser fallbacks, vis colours).
    public static let thumbnailVersion = 1
    public static let size = MainWindowLayout.size                      // 275x116, scale 1
    /// ~/Library/Caches/<bundle id>/SkinThumbnails
    public static func defaultDirectory(bundleIdentifier: String? = Bundle.main.bundleIdentifier) -> URL

    public struct Statistics: Hashable, Sendable {
        public var memoryHits = 0, diskHits = 0, renders = 0, failures = 0, dropped = 0   // dropped: cancelled before start
        public var evictions = 0, count = 0, bytes = 0, queued = 0, running = 0
    }

    /// `render` is injectable for tests; the default parses and renders `.idle` (section 3).
    public init(directory: URL,
                version: Int = thumbnailVersion,
                maxConcurrentRenders: Int = max(1, ProcessInfo.processInfo.activeProcessorCount - 1),
                memoryLimitCount: Int = 256, memoryLimitBytes: Int = 48 << 20,
                diskLimitBytes: Int64 = 1 << 30,
                render: @escaping @Sendable (URL) throws(SkinError) -> CGImage = SkinThumbnailCache.renderIdle)

    /// The thumbnail for the skin at `url` whose content hash is `hash` (from `SkinRecord.hash`). nil means: show the
    /// placeholder (failed, missing, or this caller was cancelled). Never throws.
    public func thumbnail(hash: String, url: URL) async -> SkinThumbnail?
    /// Hashes the file first (`SkinContentHash`); for callers without an index row (drag-and-drop, the current skin).
    public func thumbnail(for url: URL) async -> SkinThumbnail?
    public func cached(hash: String) -> SkinThumbnail?                  // memory only, no I/O, no touch
    public nonisolated func fileURL(hash: String) -> URL                 // <dir>/r<version>/<hash>-275x116.png
    public func clear()                                                 // memory and negative set
    public func removeAll() throws                                      // disk too (Settings › Reset, later)
    public func sweep() async                                           // trim disk to diskLimitBytes; also run at open
    public var statistics: Statistics { get }

    public static func renderIdle(_ url: URL) throws(SkinError) -> CGImage
}
```

`renderIdle`: `let skin = try SkinParser.parse(url: url); return MainWindowRenderer.render(skin: skin, state: .idle, scale: 1, clipToRegion: true)`. The `Skin` (all decoded sheets) is dropped as soon as the function returns, so at most `maxConcurrentRenders` skins are decoded at once.

### 3. `thumbnail(hash:url:)`, step by step

1. Memory: `touch(hash)` → `memoryHits += 1`, return. Negative set contains `hash` → return nil.
2. In flight for `hash`: join it (`waiters += 1`) and await its task; on the way out (`withTaskCancellationHandler`) `waiters -= 1`, and if the job has not started and `waiters == 0`, remove it from the pending list (`dropped += 1`) and cancel its task. The caller returns nil when cancelled.
3. Otherwise create the job: `Task.detached(priority: .userInitiated)` whose body (a) `await gate.acquire()` (the gate hands slots to the newest pending job first), (b) `store.readPNG(hash)` → on a hit decode immediately, `diskHits += 1`; `store.hasFailedMarker(hash)` → remember negative, nil; (c) else `render(url)`: success → `PNGWriter.data` → `store.write(hash, data)` (atomic; on `ENOENT` recreate the directories once and retry; log and continue on a second failure), `renders += 1`; `SkinError` → `store.writeFailedMarker(hash)`, `failures += 1`, negative; a file that does not exist (`FileManager.fileExists` false before parsing) → nil, no marker; (d) `gate.release()`, insert into memory (LRU evict by count/bytes), `inFlight[hash] = nil`, return. Every mutation of actor state happens through `await self.something` from the detached task; state is re-checked after each `await` (actor reentrancy).
4. Return the job's value.

`RenderQueue` (internal): `pending: [JobID]` (LIFO), `running: Int`, `limit`, and `acquire()` as a `CheckedContinuation` parked until `running < limit` and this job is the newest pending, `release()` resumes the newest waiter. About 40 lines; tested through the cache (section 6).

`ThumbnailStore` (internal, `Sendable` struct over a directory URL): `prepare()` creates `r<version>/`, deletes other `r*` entries, and writes nothing else; `url(for hash)`, `markerURL(for hash)`, `readPNG`, `write`, `writeFailedMarker`, `hasFailedMarker`, `removeAll`, `sweep(limitBytes:)` (enumerate `r<version>/` with `.fileSizeKey` and `.contentModificationDateKey`, delete oldest until ≤ 75 % of the limit, skip markers' zero bytes but count them as files). Hash strings are validated (`^[0-9a-f]{64}$`) before being used in a path, so a caller can never traverse out of the directory.

Logging: `os.Logger(subsystem: "com.brennanmke.SkinAmp", category: "SkinThumbnails")`, `debug` per render with the hash prefix (8 chars, `.public`), `info` for the version prune and sweep totals, `error` for write failures; never a file name at `.public`.

### Risks and gotchas

1. **#0026 is in flight.** The names this plan calls (`MainWindowRenderer.render(skin:state:scale:clipToRegion:)`, `MainWindowState.idle`, `MainWindowLayout.size`, `PNGWriter.data`) are in the working tree today; if #0026's review renames anything, follow the landed code and note it in `## Fix`. Do not edit any file under `Rendering/` from this issue.
2. **#0033 ordering.** If #0033 lands first, `SkinThumbnailCache` goes into its existing target and `SkinContentHash` replaces the body of `SkinIngester.hash`; if #0034 lands first, #0033's implementer must reuse `SkinContentHash` (the hashes must be byte-identical or every thumbnail misses). Either way one hash function.
3. **Parse cost, not render cost, is the budget.** `SkinParser.parse` decodes every sheet (ImageIO BMP) and unzips the archive; tens of milliseconds per skin on the guest's paravirtualized CPU, less on the host. With `cores - 1` workers and LIFO order, a fast scroll shows the cells that stop on screen first. Do not take timing numbers from the VM as product numbers; the `thumb` lines are informational.
4. **Actor reentrancy.** Every `await` inside the actor lets another request in; check `entries`/`inFlight`/`negative` again after each one, and never hold a job's continuation across an `await` of the job itself. The detached task is the only place pixels are made; the actor only bookkeeps.
5. **`.task(id:)` cancellation is cooperative.** The job's detached task is cancelled only when it has not started; a started `SkinParser.parse` cannot be interrupted and is allowed to finish. The caller's `withTaskCancellationHandler` must hop back into the actor (`Task { await self.release(...) }`) because the handler is synchronous.
6. **Disk growth.** 100k skins at ~25 KB is 2.5 GB if every one is viewed; the 1 GiB limit and the sweep bound it, and the system may purge Caches at any time, which the recreate-once path handles. Markers are empty files; 100k of them is harmless.
7. **The idle marquee text is baked into every thumbnail.** Changing `MainWindowState.idle.marqueeText` (or `MarqueeText.idle`, which #0026's test ties to it) is a `thumbnailVersion` bump.
8. **Colour.** The PNG is written from a device-RGB context with no profile (#0026's decision) and read back untagged; SwiftUI displays it as sRGB, the same as every sprite the app draws today. Tests compare against the colour they wrote, through `rgba(_:x:y:)` on a device-RGB context, so no colour management enters the comparison.
9. **Two caches competing for cores.** An index pass (`.utility`, `cores - 1` workers) and a scroll (`.userInitiated`, `cores - 1` workers) can run together; QoS orders them and the main thread is never one of the workers. If the Settings progress bar stalls while scrolling, lower `maxConcurrentRenders` to `cores / 2`; do not make the thumbnails `.utility`.
10. **Test flakiness.** Ordering and cancellation tests must synchronize on the renderer's gate stream, never on `Task.sleep`; the only sleep is inside the renderer in the bound test, and it asserts a maximum, not a timing.

## Resolution notes

> 🟢 Resolved 2026-10-14 — `SkinThumbnailCache` renders idle main-window thumbnails lazily, keyed by content hash, newest-first and bounded off the main thread, with a memory LRU, versioned PNGs on disk and failure markers; verified in VM run 20261014-043606-57470.

Review (Opus):

- Reviewer fix d0be1c3: a caller arriving between a job's cancellation and its `jobDropped` hop joined the dying job and got nil, so the cell stayed on the placeholder. `thumbnail(hash:url:)` now starts a fresh job when the in-flight task is cancelled.
- Not changed, noted for #0035: re-requesting a hash whose job is still queued joins it with its old (lower) sequence number, so it is not promoted to the front of the LIFO queue.
- `Asian Dragon.wsz` is not slow. ## Root cause

Nothing could turn a skin into a picture on demand: the renderer (#0026) and the index (#0033) existed, but there was no cache between them, so a browser would have had to parse and render every skin on each appearance.

## Fix

Followed the plan: `SkinThumbnailCache` (actor), `ThumbnailStore` (disk layout, atomic write, failed markers, version prune, sweep) and `RenderQueue` (newest-first counting gate) in `Packages/SkinKit/Sources/SkinLibrary/Thumbnails/`; `PlayerModel.skinThumbnails`; `App/Browser/SkinThumbnailView.swift`. The render is `SkinParser.parse` + `MainWindowRenderer.render(state: .idle, scale: 1, clipToRegion: true)`; key is `SkinContentHash` SHA-256 (already landed with #0033, so `SkinContentHash.swift` and the `Package.swift`/`project.yml` edits were not needed).

Adaptations and divergences:
- `SkinLibrary` and its test target already existed (#0033), so only new files plus the `PlayerModel` line changed; `project.yml` and `Package.swift` untouched.
- #0035's `SkinThumbnailProviding` seam is not created here (it is #0035's file); its adapter wraps `thumbnail(hash:url:)`, which takes both the hash and the URL as that plan expects.
- A cancelled caller waits for its job instead of returning nil instantly: a job nobody wants that has not started is dropped (so that wait is short), but a started render finishes first. Simpler than a second continuation per caller; the result is still cached.
- `RenderQueue` orders waiters by the request sequence number assigned inside the actor, not by when the detached task reaches the gate, so newest-first is deterministic. Cancellation is race-free (checked under the gate lock).
- Added `sweepOnOpen` init parameter (default true; the sweep runs once in a utility task on first use) so tests can disable it; internal `waiterCount(hash:)` for tests to synchronize without sleeping on timing.
- `SkinThumbnailView` uses a hash-less placeholder with no request, as planned; unreferenced until #0035.
- Tests: 20 in `SkinThumbnailCacheTests` (incl. opt-in `sampleSkinsProduceThumbnails`) + `SkinContentHashTests.hexMatchesCryptoKitAndIsStable`. Test hold-ups use a `Latch` (NSCondition) inside the injected renderer; waiting uses a 1 ms polling loop on actor-visible state, never a timing assertion.
