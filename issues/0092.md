# 0092 — Renaming a Music Assistant server re-checks every server on each keystroke

| | |
|---|---|
| **Status** | open |
| **Module** | MusicAssistantKit / App |
| **Platform** | macOS |
| **First seen** | 2026-10-19 |

## Description

Found in the #0075 review (commit 80d3e78), not blocking there: the server name field saves on every keystroke, and after the first server choice each save triggers a re-check of every configured server at once, with no debounce. A rename never changes which server it is. Also, until the first server choice the Library window subtitle ends with "· Not checked yet".

Expected: a rename does not trigger a server re-check (or shares the existing 2 s network-change debounce), and the subtitle reads sensibly before the first choice.

## Plan

### Where it happens today

- `MusicAssistantSettingsModel.name`'s setter calls `persist()` on every keystroke (`TextField("Name", text: $model.name)` in `App/Settings/MusicAssistantSettingsView.swift`, line ~58). `persist()` saves, runs `refreshActive()` (already keeps the active box's copy current on a rename) and calls `onServersChanged`.
- `PlayerModel` (line ~364) wires `onServersChanged` to `selection.serversChanged()`, which sets `isValid = false` and, after the first resolution, calls `schedule(after: nil)`: an immediate `resolveNow()`, one `/info` probe per verified server. Each keystroke cancels the previous pending task, but the cancel does not stop the selector round already started, and the next keystroke starts a new one.
- The wake observer (line ~388) also calls `serversChanged()`; that one must keep re-probing.
- `reasonText` starts as `MusicAssistantServerRanking.notCheckedText` ("Not checked yet"). `LibraryWindowView.subtitle` appends it whenever MA is the selected source, and `LibrarySettingsView` shows it under the picker when MA is preferred.

### Decision

A rename does **not** re-check (no debounce either): the name is not part of ranking or probing. `candidates(_:ssid:)` and the selector read only `id`, `address` (`baseURL`, `serverID`), `networks` and list order. But the name *is* in the reason text ("A — first reachable") and in `current`, so a rename must relabel those without a probe. The controller decides this, not the settings model. It compares the stored list with the list its last resolution used, ignoring names. That covers per-keystroke renames and keeps every other edit (address commit, networks, move, remove, Test Connection learning a `server_id`) on today's immediate re-check.

### Files

- `Packages/PlayerKit/Sources/MusicAssistantKit/MusicAssistantSelectionController.swift`
  - New `@ObservationIgnored private var resolvedServers: [MusicAssistantServerConfiguration]?`, set in `resolveNow()` to the `store.load()` result it ranks (before the `await`).
  - New `public func serversEdited()`, the settings hook's target:
    1. Load the store.
    2. If `hasResolvedOnce` and the loaded list equals `resolvedServers` with every `name` blanked (a private `ignoringNames(_:)` helper that maps `name = ""`; `MusicAssistantServerConfiguration` is `Hashable`, so `==` compares order, ids, addresses and networks), only relabel: set `resolvedServers` to the loaded list, call `relabel(from:)`, and leave `isValid` and `pendingTask` untouched. A pending debounced network re-check still runs.
    3. Otherwise call `serversChanged()`, which behaves as today.
  - `private func relabel(from servers:)`: if `current` exists and the same-id server in `servers` has `sameIdentity(as:)`, rebuild `current` as `Candidate(server: updated, basis: current.basis)`, set `reasonText = MusicAssistantServerRanking.reason(for:)`, and call `active.set(updated)`. That call is idempotent with the settings model's `refreshActive()`. No `onChange`, no log line with the name.
  - In `apply(_:hasCandidates:)`, after choosing the winner, call `relabel(from: store.load())`, so a rename typed while a probe was in flight does not leave the old name in `reasonText`.
  - `serversChanged()` keeps its body and stays the wake path. Update its doc comment ("the Mac woke or a list change that matters").
  - Subtitle: a new observed `public private(set) var hasDecision = false`, set `true` in `apply`, plus `public var statusText: String?`:
    - `nil` before the first decision when nothing is resolving.
    - `MusicAssistantServerRanking.checkingText` ("Finding a server…", new constant) while `isResolving && !hasDecision`.
    - `reasonText` otherwise.

    `reasonText` and its "Not checked yet" start value stay for Settings › Music Assistant, where it sits beside **Check Now** and reads correctly.
- `Packages/PlayerKit/Sources/MusicAssistantKit/MusicAssistantServerRanking.swift`: add `checkingText`.
- `App/PlayerModel.swift`: `musicAssistantSettings.onServersChanged = { [weak selection] in selection?.serversEdited() }`. The wake observer is unchanged.
- `App/Browser/LibraryWindowView.swift`: `subtitle` appends `" · " + text` only when `musicAssistantSelection.statusText` is non-nil. Before the first choice the subtitle is just `FallbackText.subtitle(...)` (e.g. "Music Assistant"), then "Finding a server…" while the Library's connect resolves, then the reason.
- `App/Settings/LibrarySettingsView.swift`: show `selection.statusText` (hide the `Text` when nil) instead of `reasonText`, for the same reason.
- `MusicAssistantSettingsModel.swift`: no behaviour change. Update the `onServersChanged` doc comment ("the selection re-checks unless only names changed"). The `name` setter's comment stays.
- `docs/music-assistant-integration.md` §7: one sentence saying a rename relabels without a re-check, and that the Library subtitle omits the reason until the first check.
