## Description

M14 work item W7 from [docs/design/release.md](../docs/design/release.md). Depends on: W4, W6.

## Expected behavior

Sparkle 2 pinned with `exactVersion`, app target only; `UpdaterModel`; Check for Updates… in the app menu and the skinned main menu; Settings › Updates. Release has the feed URL, Debug doesn't start the updater (VM launch silent); `check-sparkle.sh`; `MainMenuTests` case.

## Resolution notes

> 🟢 Resolved 2026-10-23 — Sparkle 2.10.0 is embedded in the app only, with Check for Updates… in both menus and Settings › Updates; Debug builds never start the updater.

## Root cause

Roadie had no update mechanism: no Sparkle dependency, no feed URL or public key in the Info.plist, and no menu or
settings for updates, so an installed copy could never learn about a new release.

## Fix

- `project.yml`: Sparkle pinned `exactVersion: 2.10.0`, linked by the Roadie target only. `SUFeedURL` and
  `SUPublicEDKey` map to the per-configuration `ROADIE_FEED_URL` / `ROADIE_PUBLIC_ED_KEY` (Release: the
  `https://roadie.sstools.co/appcast.xml` feed and, until W15 (#0166), an empty key; Debug: both empty). No
  `SUEnableAutomaticChecks`, `SUEnableSystemProfiling` or installer/downloader service keys.
- `App/Updates/Updater.swift`: `@MainActor @Observable` wrapper around `SPUStandardUpdaterController(startingUpdater:
  isConfigured, …)`, where `isConfigured` needs both keys non-empty. It mirrors `canCheckForUpdates`,
  `automaticallyChecksForUpdates`, `automaticallyDownloadsUpdates` and `lastUpdateCheckDate` through KVO (a nonisolated
  hop back to the main actor) and refreshes after its own setters. `UpdateCommands` adds Check for Updates… after About.
- Skinned main menu: `MainMenuCommand.checkForUpdates` right after About Roadie, enabled from
  `MainMenuState.canCheckForUpdates`; the app injects the closures through `PlayerModel.updateActions`, so SkinKit and
  the model stay free of Sparkle.
- Settings › Updates: both toggles (download disabled while checks are off; the section disabled when the updater
  isn't configured), Check Now, Last checked, and "Updates are off in development builds." in Debug.
- `App/Credits.rtf` with the tagline, the §2.8 disclaimer, acknowledgements and the site link.
- `check-info-plist.sh --release` (VM step `app-release-plist`), the Debug assertion that `SUFeedURL` is empty,
  `scripts/check-sparkle.sh` (VM step `app-sparkle`), `release/sparkle-bin/{sign_update,generate_keys}` from the
  guest, NOTICE and `docs/sparkle.md`.
