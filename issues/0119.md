## Description

Seen in the user's screenshot for #0116 on 0.1.0-2671617. The Library window's subtitle reads "Music Assistant · Music Assistant (<server id>…)": when the server has no friendly name, the fallback label includes the raw `server_id`, which is truncated and meaningless to the user. The id shouldn't be shown in the UI.

## Expected behavior

- The subtitle names the server by its configured or advertised name, else its host (e.g. "homeassistant.local"), never the server id.
- The source name isn't repeated ("Music Assistant · Music Assistant").
- The album header counts tracks in the singular when there is one ("1 track", not "1 tracks"), here and wherever else the Library pluralizes counts.

## Plan

**Root cause.**
- The subtitle is `FallbackText.subtitle(status)` ("Music Assistant", the source's display name) + " · " + `MusicAssistantSelectionController.statusText`, which is `MusicAssistantServerRanking.reason(for:)`: `"\(candidate.server.name) — first reachable"` (or "— on network X", "— via Tailscale") (`App/Browser/LibraryWindowView.swift` `subtitle`).
- `server.name` is whatever the server advertised in `/info` `name`. `MusicAssistantSettingsModel.apply(_:for:typedToken:)` copies `info.name` over `defaultName` after a successful test, and `addDiscoveredServer(_:)` copies `found.name` (also `info.name`, from `MusicAssistantDiscovery`). A server with no friendly name advertises Music Assistant's generic label with its id in parentheses, so that string is stored and shown verbatim. That is where the id and the doubled "Music Assistant" come from. Nothing anywhere treats the generic label (bare "Music Assistant", or "Music Assistant (<token>)") as "no name". The recorder (`scripts/record-ma-fixtures.py`) rewrites real names to "Music Assistant", so the fixtures can't show this.
- "1 tracks": `App/Browser/TrackListView.swift` builds `Text("\(tracks.count) tracks, …")` with no singular case. It is the only pluralized count in the Library UI. Playlist rows show a bare number, and `StatusNotice` already handles "file"/"files" and only says "N tracks" when N > 1.

**Approach.**
1. `Packages/PlayerKit/Sources/MusicAssistantKit/MusicAssistantServerConfiguration.swift`:
   - Add `public static func isGenericName(_ name: String?) -> Bool`. It is true for nil, empty or whitespace, `defaultName`, or `defaultName` followed by ` (<one token with no spaces>)` (case-insensitive, after trimming), so it needs no server id.
   - Add `public var displayName: String`: the trimmed `name` unless it is generic, else `address.baseURL.host()`, else `defaultName`. It is for the UI only and is never logged (document that, as `reason(for:)` does). The stored `name` stays as it is, so rows already saved with the generic label display correctly with no migration.
2. In the same module, add `displayName` on `MusicAssistantDiscoveredServer` (in `MusicAssistantDiscovery.swift`), built the same way from `name` and `url.host()`.
3. `MusicAssistantSettingsModel`:
   - In `apply`, adopt `info.name` only when `!isGenericName(info.name)`, and replace the current name when it `isGenericName` (not only when it equals `defaultName`). An old generic name then gets upgraded once the server gets a real one.
   - In `addDiscoveredServer`, use `found.name` only if it isn't generic, else `defaultName`.
4. `MusicAssistantServerRanking.reason(for: Candidate)`: use `candidate.server.displayName` in all three strings. The subtitle then reads, for example, "Music Assistant · homeassistant.local — first reachable": the server id is gone and the source name isn't repeated. `LibrarySettingsView` uses the same `statusText`, so it follows automatically.
5. App UI that shows a server label:
   - `App/Settings/MusicAssistantSettingsView.swift:224` (`Text(server.name)` in the list row) becomes `server.displayName`.
   - `App/Settings/MusicAssistantDiscoveryViews.swift:84` (`offer.name ?? "Music Assistant"`) becomes `offer.displayName`.
   - Leave the editable `TextField("Name", text: $model.name)` alone. Optionally give it `prompt:` showing the host.
6. `Packages/PlayerKit/Sources/LibraryBrowser/LibraryFormat.swift`:
   - Add `public static func count(_ n: Int, _ singular: String, plural: String? = nil) -> String` ("1 track", "2 tracks", "0 tracks").
   - Add `public static func trackSummary(count: Int, duration: TimeInterval) -> String` ("1 track, 3:41").
   - `TrackListView` uses `trackSummary`.
7. Out of scope, but cheap to fix with `LibraryFormat.count` if the implementer touches it: `App/PlayerModel+PlaylistFiles.swift:59` ("skipped 1 server tracks"). Note it in `## Fix` either way.
8. Never log names or hosts. The new code adds no log lines.

**Tests** (fast tier, Swift Testing):
- `Packages/PlayerKit/Tests/MusicAssistantKitTests/ServerStoreTests.swift`:
  - `genericNamesAreRecognized`: bare, padded, `"music assistant (a1b2c3)"` and nil count as generic; "Home", "Music Assistant Kitchen" and "Music Assistant (Living Room)" (spaces inside) don't.
  - `displayNameFallsBackToTheHostForAGenericName`: "Home" stays "Home"; a generic name with base URL `http://a.local:8095` gives "a.local".
- `ServerRankingTests.swift`: `reasonTextNamesTheHostWhenTheNameIsGeneric`, which checks `"a.local — first reachable"` and that the result has no "(" and no repeated "Music Assistant". Keep `reasonTexts` passing.
- `SettingsModelTests.swift`:
  - `testDoesNotAdoptAGenericAdvertisedName`: `rig.renameServerInfo(to: "Music Assistant (abc123)")`, run the test, and the stored name stays `defaultName`.
  - `testReplacesAStoredGenericNameWithARealOne`: start from a stored "Music Assistant (abc123)", rename the info to "Living Room", run the test, and the name becomes "Living Room".
  - `addDiscoveredServerDropsAGenericAdvertisedName`.
- `DiscoveryTests.swift`: `discoveredServerDisplayNameFallsBackToTheHost`.
- `Packages/PlayerKit/Tests/LibraryBrowserTests/LibraryFormatTests.swift`: `countUsesTheSingularForOne` (0/1/2), and `trackSummaryUsesTheSingularForOne` ("1 track, 3:41", "2 tracks, 7:22").

Use made-up ids and hosts only (for example "abc123", "a.local"). Never use the real server id or host.

**Tier:** fast. The change touches nothing under `SkinLibrary/` or AudioCore real-time code. Run `scripts/verify.sh` with `--expect` listing the tests above.

## Root cause

Music Assistant advertises a generic `/info` name ("Music Assistant (<server id>)") when the server has no friendly name. The settings model stored it as the server name, and `MusicAssistantServerRanking.reason(for:)` showed it verbatim in the Library subtitle, which put the id in the UI and repeated "Music Assistant". Separately, `TrackListView` always wrote "N tracks". The review found two more paths: the Test Connection status passed the raw `info.name` ("Connected to Music Assistant (<id>) …"), and a stored legacy generic name was kept, and shown in the Name field, when the server still advertised a generic name. The second review found that `MusicAssistantConnectionTest.run` also built its `needsToken` and `serverMismatch` failures from the raw `info.name`, so "Found Music Assistant (<id>). Enter a token." showed on the usual first-run path.

## Fix

- `MusicAssistantServerConfiguration.isGenericName(_:)` recognizes nil, blank, "Music Assistant" and "Music Assistant (<token without spaces>)". `displayName(_:host:)` and `displayName` return the name unless it is generic, else the host, else `defaultName`. `MusicAssistantDiscoveredServer.displayName` works the same way.
- `MusicAssistantSettingsModel`: `apply` adopts `info.name` only when it isn't generic, and replaces a stored name when that name is generic. `addDiscoveredServer` drops a generic advertised name.
- Ranking reasons, the Settings list row and the discovery offer row use `displayName`.
- `LibraryFormat.count` and `trackSummary` were added, and `TrackListView` uses `trackSummary`.
- Second pass (3be2206, after review): `apply` reports `.connected(name: servers[index].displayName, …)` instead of the advertised `info.name`, and resets a stored generic name other than exactly `defaultName` to `defaultName` when the advertised name is generic too. `testUsesTheStoredTokenWhenTheFieldIsEmpty` now expects the stored name ("Home") in the status rather than the advertised generic "Music Assistant".
- Third pass (b029fe5, after the second review): `MusicAssistantConnectionTest.friendlyName(_:)` returns the trimmed advertised name, or nil when `isGenericName` says it is generic. All three sites use it: `.serverMismatch(foundName:)`, `.needsToken(foundName:)`, and `failure(for:found:)` after the WebSocket connect. The messages then read "Found a Music Assistant server. Enter a token." and "A different server answered. Its token was not sent." The sweep also found and fixed two more sites: `MusicAssistantBackend.requireConfiguration` ("Test the connection to \(configuration.name) …" is now `displayName`), and the Settings "Verified: \(model.selected?.name)" fallback in `MusicAssistantSettingsView.identityText` (now `displayName`). `testWithoutTokenStopsAfterInfo` and `mismatchNeverReadsOrSendsTheToken` now expect `foundName: nil`, because the fixture's "Music Assistant" is generic.
- Sweep of every user-visible string that interpolates or shows a server name or id (`Packages/PlayerKit/Sources`, `App/`):
  - `MusicAssistantConnectionTest.swift`: the `serverMismatch`, `needsToken` and `failure(for:found:)` sites. Fixed in this pass.
  - `MusicAssistantConnectionFailure.message`: renders only `foundName`, which is now never generic. No other case holds a name or id.
  - `MusicAssistantSettingsModel.statusMessage` (`.connected(name:)`): set from `displayName` (second pass).
  - `MusicAssistantSettingsModel.name` (the Name field) and `apply`/`addDiscoveredServer`: generic names are never stored or kept (passes 1 and 2).
  - `MusicAssistantServerRanking.reason(for:)`: all three strings use `displayName` (pass 1). They also feed `statusText`, the Library subtitle and `LibrarySettingsView`.
  - `MusicAssistantBackend.swift:131` "Test the connection to …": fixed in this pass.
  - `App/Settings/MusicAssistantSettingsView.swift`: `Text(server.displayName)` in the row (pass 1); `identityText` "Verified: \(name)" comes from the `.connected` status (`displayName`), and its fallback was fixed in this pass. The networks section shows Wi-Fi names, not server names.
  - `App/Settings/MusicAssistantDiscoveryViews.swift`: `Text(offer.displayName)` (pass 1) and the host caption. The host is intended.
  - `MusicAssistantDiscovery.swift`: the name goes only into `MusicAssistantDiscoveredServer`, whose UI uses `displayName`. The `idle:` log line has counts only.
  - `App/Browser/LibraryStatusView.swift` "Connecting to \(library.backend.displayName)…", `LibraryBrowser/FallbackText.swift` (`activeName`/`preferredName`) and `LibrarySettingsView`: all use the backend's fixed display name ("Music Assistant", "Local Folder"), not a server name.
  - `App/SendspinController.swift:90` "shows in Music Assistant as \(identity.name)": SkinAmp's own client name, not the server's.
  - Server ids (`serverID`, `address.serverID`, `info.serverID`) appear only in comparisons and in `MusicAssistantError.serverMismatch`, whose `errorDescription` names no id. No user-visible string interpolates one.
- Not done: optional plan step 7 (`App/PlayerModel+PlaylistFiles.swift`, "skipped N server tracks") is left as is.
