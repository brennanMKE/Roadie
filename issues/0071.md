# 0071 — The play queue is lost when the app quits

| | |
|---|---|
| **Status** | open |
| **Module** | App / AudioCore |
| **Platform** | macOS |
| **First seen** | 2026-10-14 |

## Description

Window positions, open/closed state, shade, the playlist size and the EQ settings survive a relaunch, but the queue does not: after ⌘Q and relaunch the playlist window is empty. Winamp reloads its last playlist (`winamp.m3u`) at startup, stopped at the same track. #0030 planned this (docs/plan.md M5 item 3) and left it out by decision, since it touches PlayerKit and `PlayerModel`'s init.

## Expected behavior

On relaunch the queue, the current index, repeat and shuffle come back, stopped at the saved track; nothing auto-plays. A queue can be thousands of tracks, so it belongs in a file in Application Support rather than `UserDefaults`. A missing, corrupt or newer-version file restores nothing. Restored Plex tracks whose part is gone fail with the usual playback error, nothing worse.

#0030's `## Plan` section 3 has a worked design (`Track: Codable`, `QueueSnapshot`/`QueueStore`, `Player.restoreQueue`, a coalesced save on queue changes) and its tests (`QueueSnapshotTests`); the backend/source work since then (#0062, #0065, #0070) has to be checked against it, e.g. whether a restored track's `MediaID` still resolves through the active source.
