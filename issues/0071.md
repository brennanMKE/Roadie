## Description

Window positions, open/closed state, shade, the playlist size and the EQ settings survive a relaunch, but the queue does not: after ⌘Q and relaunch the playlist window is empty. Winamp reloads its last playlist (`winamp.m3u`) at startup, stopped at the same track. #0030 planned this (docs/plan.md M5 item 3) and left it out by decision, since it touches PlayerKit and `PlayerModel`'s init.

## Expected behavior

On relaunch the queue, the current index, repeat and shuffle come back, stopped at the saved track; nothing auto-plays. A queue can be thousands of tracks, so it belongs in a file in Application Support rather than `UserDefaults`. A missing, corrupt or newer-version file restores nothing. Restored Plex tracks whose part is gone fail with the usual playback error, nothing worse.

#0030's `## Plan` section 3 has a worked design (`Track: Codable`, `QueueSnapshot`/`QueueStore`, `Player.restoreQueue`, a coalesced save on queue changes) and its tests (`QueueSnapshotTests`); the backend/source work since then (#0062, #0065, #0070) has to be checked against it, e.g. whether a restored track's `MediaID` still resolves through the active source.

## Plan

### Scope and decisions

Persist the "This Mac" queue (the one `Player` behind `LocalPlayerOutput`, shared by the Plex and folder backends since #0065) to a JSON file in Application Support, restore it in `PlayerModel.init` stopped at the saved track, and save it coalesced on every queue change and on quit. Status stays `open`; this plan writes no code.

#0030 §3 was checked against the landed code (#0062 `LocalQueueItem`/`MediaID`, #0065 shared output, #0068 skip-on-failure, #0070 runtime source switch). Its shape holds, with these adjustments:

- **The snapshot lives in `LocalPlayback`, not `AudioCore`.** A queue entry is a `LocalQueueItem` (`Track` + optional `MediaID`), and `LocalPlayerOutput.ids` is what gives `NowPlaying.item` its value; both are `LocalPlayback` types. `AudioCore` gains only `Player.restoreQueue`. `LocalPlayback` already depends on `AudioCore` and `MusicBackendKit`; `Package.swift` and `project.yml` are not touched (`LocalPlaybackTests` is already in the scheme).
- **No `Track: Codable`.** The file format is written by hand through private mirror structs with a fixed key set (what #0065 did for `FolderIndex`), so `AudioCore` carries no file format, a synthesized enum layout (`{"file":{"_0":…}}`) is not frozen into user files, and a test can pin the key allowlist (the no-secrets guarantee). `RepeatMode` is stored as a string (`"off"`/`"all"`/`"one"`) by the mirror; `PlayQueue.swift` and `Track.swift` are untouched.
- **Restored tracks do not go through a backend.** `Player` plays `Track`s by `Track.Source`, never by `MediaID`: a `.file` URL opens directly, a `.plex(partKey, cacheKey, size)` goes through `PlexTrackResolver` → `TrackCache`. So the active library source (#0070), `PlexBackend.knownTracks` and `FolderBackend`'s index are irrelevant to playback of a restored queue, and nothing connects at launch. The `MediaID` is stored only so `NowPlaying.item` comes back (`MarqueeText` uses it for "buffering"); ids of both sources already share one registry (#0062 review note), so persisting them changes nothing.
- **What is persisted:** items (track metadata + source + `MediaID`), `currentIndex`, `repeatMode`, `isShuffled`. **Not persisted:** the position (restore is stopped at 0:00, as Winamp reads `winamp.m3u`), the shuffle order and pass (private `PlayQueue` bookkeeping; a restored shuffled queue starts a fresh pass headed by the current track, exactly what clicking a row does), volume/balance, `selectedOutput`, the playlist selection.
- **Restore is synchronous in `PlayerModel.init`,** so the playlist window's first frame shows the queue and a file the user drops in the first 100 ms cannot race it. Decoding a 10,000-track file (~3 MB) is tens of milliseconds; see Risks for the fallback.
- **No audio device, no network, no Keychain at launch.** `Player.restoreQueue` never touches `_graph`; the resolvers run only when the user presses Play. Side effects of the restore's `.trackChanged` event, each checked: `CachePinner` → `cache.setPinned` (sets a key set on the actor; no I/O, no network; `prepare()` is not required for it); `NowPlayingBridge.publish` → `currentSnapshot()` is nil while stopped → Control Center shows nothing; `LocalPlayerOutput` subscriptions → the marquee shows "N. Artist - Title" stopped; `PlayerModel`'s observer only handles `.failed`.
- **Missing files are kept, not pruned.** No `stat` or `AVAudioFile` at launch (metadata comes from the snapshot; a volume may mount later; Winamp keeps them). Pressing Play on one hits `AVAudioFile(forReading:)`'s error in `startCurrentTrack`, which #0068 turns into a per-track skip and a "Could not play <title>" notice.
- **File, not `UserDefaults`:** `~/Library/Application Support/com.brennanmke.SkinAmp/queue.json` (`Bundle.main.bundleIdentifier`, falling back to `SkinAmp`), written atomically, with a `version` field. Missing, undecodable or `version != 1` → restores nothing, logs one `info` line, leaves the file alone (the next save overwrites it).

### 1. `LocalPlayback`: `QueueSnapshot.swift`

```swift
/// The "This Mac" queue as saved to disk. Value type, `Sendable`, equatable; the file format is the private
/// mirror below, not `Track`'s layout.
public struct QueueSnapshot: Equatable, Sendable {
    public static let currentVersion = 1
    public var items: [LocalQueueItem]
    public var currentIndex: Int?
    public var repeatMode: RepeatMode
    public var isShuffled: Bool
    public init(items: [LocalQueueItem], currentIndex: Int?, repeatMode: RepeatMode, isShuffled: Bool)
}

/// One JSON file, written atomically. nil from `load()` when the file is missing, corrupt or from a newer version.
public struct QueueStore: Sendable {
    public let fileURL: URL
    public init(fileURL: URL)
    /// `~/Library/Application Support/<bundle id>/queue.json`.
    public static func defaultURL(bundleIdentifier: String? = Bundle.main.bundleIdentifier) -> URL
    public func load() -> QueueSnapshot?
    /// Creates the directory, encodes with sorted keys, `Data.write(options: .atomic)`.
    public func save(_ snapshot: QueueSnapshot) throws
}
```

Format (`version` 1, keys sorted on write):

```json
{"version":1,"currentIndex":1,"repeat":"all","shuffle":false,
 "items":[
  {"id":"<UUID>","title":"…","artist":"…","album":"…","duration":241.3,"bitrate":320,"sampleRate":44100,"channels":2,
   "source":{"kind":"file","path":"/Volumes/Music/a.mp3"},"mediaID":{"kind":"track","rawValue":"Artist/Album/01.mp3"}},
  {"id":"<UUID>","title":"…","artist":"…","duration":180,
   "source":{"kind":"plex","partKey":"/library/parts/5010/1791856627/file.m4a","cacheKey":"abcdef0123-5010-1791856627","size":7147054},
   "mediaID":{"kind":"track","rawValue":"3001"}}]}
```

Private `Stored`/`StoredItem`/`StoredSource` mirrors do the encoding (`StoredSource` is an enum keyed by `kind`; unknown kinds fail the decode, so the whole file loads as nil rather than a partial queue). Optional fields (`album`, `bitrate`, `sampleRate`, `channels`, `mediaID`, `size`) are omitted when nil. `Track.id` is stored and restored so the same file queued twice stays two entries. Nothing in the file can be a secret: `partKey` is a server-relative path and `cacheKey` is `<machine id letters/digits>-<part id>-<stamp>` (`PlexCacheKey`); no address, token or header exists on `Track` at all, and test 2 pins the key set so a later field is a deliberate change.

`LocalPlayerOutput.swift` gains:

```swift
/// The queue as it is now (tracks, their library ids, index, repeat, shuffle).
public func queueSnapshot() -> QueueSnapshot
/// Fills an empty, stopped player from `snapshot` without starting anything; false (no change) otherwise.
@discardableResult public func restore(_ snapshot: QueueSnapshot) -> Bool
```

`restore` calls `player.restoreQueue(...)` and, when it returns true, `register(snapshot.items)`; `queueSnapshot` maps `player.queue.tracks` to `LocalQueueItem(track:, id: ids[track.id])`.

### 2. `AudioCore`: `Player.restoreQueue`

```swift
/// Launch-time restore: only while stopped with an empty queue, and only with tracks. Appends, sets repeat,
/// selects `currentIndex` when in range, then turns shuffle on (so the current track heads the pass).
/// Never opens the engine or starts a load; emits `.trackChanged` like any queue change.
@discardableResult
public func restoreQueue(_ tracks: [Track], currentIndex: Int?, repeatMode: RepeatMode, isShuffled: Bool) -> Bool
```

Body: `guard state == .stopped, queue.tracks.isEmpty, !tracks.isEmpty else { return false }`; `queue.append(tracks)`; `queue.repeatMode = repeatMode`; `if let i = currentIndex, tracks.indices.contains(i) { queue.select(i) }`; `if isShuffled { queue.setShuffle(true) }`; `return true`. No `reconcileSchedule()` (a no-op while stopped anyway), no `startCurrentTrack`. After it, `play()` takes the `.stopped` branch with `queue.current != nil` and starts the saved track, so Play resumes where the user left off.

### 3. `LocalPlayback`: `QueueAutosaver.swift`

```swift
@MainActor
public final class QueueAutosaver {
    public init(output: LocalPlayerOutput, store: QueueStore, delay: Duration = .seconds(1))
    /// Observes the player's queue; each change (re)starts the delay, then one save.
    public func start()
    /// Cancels a pending save and writes now (quit).
    public func flush()
    /// Saves started so far (tests).
    public private(set) var saveCount: Int
}
```

`start()` registers `withObservationTracking { _ = output.player.queue } onChange: { Task { @MainActor in self.queueChanged(); self.start() } }` (the re-registering pattern of `AppDelegate.observeEQWindow`), guarded by a flag so it runs once. `queueChanged()` cancels the pending task and schedules `Task { try? await Task.sleep(for: delay); guard !Task.isCancelled; save() }`. `save()` takes `output.queueSnapshot()` on the main actor and writes it off-main, chained like `CachePinner.apply` (`await previous?.value` first) so an older snapshot can never land after a newer one; a write error is logged at `error` level with the error's description only. `flush()` cancels the pending task and writes synchronously on the main actor (a few milliseconds even for a large queue; `applicationWillTerminate` must not race a background task). Every mutation of `Player.queue` (append, remove, move, select, next, failure skip, `clearQueue`) fires the observer; the delay coalesces bursts, and an emptied queue is saved as `items: []` so a relaunch is empty too.

### 4. App

`App/PlayerModel.swift`: two stored properties, `private let queueStore: QueueStore` and `private let queueAutosaver: QueueAutosaver`, both built in `init` right after the EQ restore (and before `observeNowPlaying()`): `queueStore = QueueStore(fileURL: QueueStore.defaultURL())`; `if let saved = queueStore.load() { stack.output.restore(saved) }`; `queueAutosaver = QueueAutosaver(output: stack.output, store: queueStore)`; `queueAutosaver.start()` (after the restore, so the restore itself is not re-saved). One method `func flushQueue() { queueAutosaver.flush() }`. Nothing else in the model changes: `importLocalFiles`, `playFromLibrary`, the transport stream and `PlaylistModel` all mutate `player.queue` already and are picked up by the observer. `App/AppDelegate.swift`: `applicationWillTerminate` adds `model.flushQueue()` beside `docking.layoutDidChange()`.

### 5. Re-hydration per source, after a relaunch

- **Local files** (drop, Open, Add): `.file(URL)` stored as the absolute path. Present → plays. Missing → `AVAudioFile` throws in the load task → `trackFailed` → skip + "Could not play <title>" (#0068); the row stays in the list.
- **Local folder** (#0065): `FolderBackend.play` already hands the output plain `.file` tracks (`FolderTrack.audioTrack(root:)`) with `MediaID(.track, …)`, so they persist and restore exactly like dropped files; the index, the watcher and the folder setting are not consulted. Folder moved or un-set → missing file → per-track skip.
- **Plex**: `.plex(partKey:cacheKey:size:)` plus `MediaID(.track, ratingKey)`. Play → `PlexTrackResolver`: saved server differs from the key's machine id → `TrackCacheError.serverMismatch` (whole-source → stop + notice "This track belongs to a different Plex server…"); Plex no longer configured → `.noServer` (whole-source stop); otherwise `TrackCache.file` → cache hit plays offline, else a download through `settingsClientProvider` (Keychain read at play time, as today); part gone → `.download(.notFound)` → per-track skip. Nothing is pinned beyond current/next (`CachePinner` pins, never downloads).
- **Source switched** (#0070/#0067): the Library source and the player queue are independent; a Plex queue stays playable with the folder selected and vice versa. **Remote outputs** (future Music Assistant): the file is This Mac's queue only; `selectedOutput` is not persisted and the queue of a remote player is not ours to save.

### 9. Risks

- **Launch time with a huge queue.** Decoding and appending 10,000 tracks synchronously in `init` should be under 100 ms; if the implementer measures more in the VM log, move `load()` to a `Task(priority: .userInitiated)` and `restore` on the main actor afterwards; the stopped-and-empty guard already makes that safe, at the cost of a briefly empty playlist window.
- **A write per track change.** `currentIndex` changes on every advance and on every #0068 skip; the 1 s coalescing and the chained off-main writes keep this to one small write per track, and a 3 MB file for 10,000 tracks is still a few milliseconds. `flush()` on quit is synchronous on purpose.
- **Observation fires only for `player.queue`.** `withObservationTracking` on `@Observable` `Player.queue` re-registers after each change; a missed re-registration would silently stop saving. Test 10 covers consecutive changes, and `flush()` on quit saves regardless.
- **Stale Plex entries stop the player, they do not skip.** `serverMismatch` and `noServer` are whole-source by #0068's classification, so a queue from an old server stops on the first such track with the usual notice. That is the "usual playback error" the description asks for; clearing the list is the recourse (host check 7).
- **Older build after a newer one.** An older build cannot read a newer `version` (restores nothing) and overwrites it at its first save; accepted, no migration story until a version 2 exists.
- **Duplicate or malformed ids.** `Track.id` comes from the file; a duplicated UUID would make the two entries one key in `LocalPlayerOutput.ids` (last wins) and in `PlaylistSelection`. Decode defensively: if an item's `id` is missing or duplicated, give it a fresh `UUID()` rather than failing the whole file.
- **#0033 rebase** touches `App/PlayerModel.swift` in parallel; the edits are in different parts of `init` and should merge cleanly. Rebase, re-run the VM script, keep the plan.
- **Sandboxing.** The app is unsandboxed, so stored absolute paths reopen directly; if the sandbox is ever enabled, `.file` sources need security-scoped bookmarks (the same note as #0065 and #0033).

## Root cause

The play queue was only ever held in memory (`Player.queue`); nothing wrote it out or read it back, so a relaunch started with an empty playlist. #0030 left persistence out by decision.

## Fix

Followed the plan. `QueueSnapshot`/`QueueStore` (new, `LocalPlayback`) write the queue by hand through private mirror structs to `~/Library/Application Support/<bundle id>/queue.json` (version 1, sorted keys, atomic). `Player.restoreQueue` fills an empty stopped player without touching the engine. `LocalPlayerOutput` gained `queueSnapshot()` and `restore(_:)`. `QueueAutosaver` observes `player.queue` (re-registering `withObservationTracking`), coalesces with a 1 s delay, writes off-main in a chain, and `flush()` writes synchronously on quit. `PlayerModel.init` restores then starts the autosaver; `AppDelegate.applicationWillTerminate` calls `model.flushQueue()`.

Adaptations: the restore/autosaver block sits right after `commandStream = continuation` in `init` (before the `[weak self]` event observer), because Swift rejects `self` capture before `queueAutosaver` is assigned; #0033-#0035 changes (`skinLibrary`, `skinBrowser`, `loadSkin` generation) did not conflict. Added one test beyond the plan (`duplicateOrMissingIdsGetFreshOnes`, covering the plan's Risks note).
