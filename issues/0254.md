# 0254 — The scripted Music Assistant server can't drive several of #0206's flows

| | |
|---|---|

## Description

Found while writing #0206's `MusicAssistantUITests` against the scripted server (#0197, `App/TestSupport/ScriptedMusicAssistant+Roadie.swift`). These flows are left out of #0206 or only half covered because the server can't support them:

1. **Elapsed time runs past the track.** The server sets `elapsed_time_last_updated` to the recording's epoch plus uptime, so the app projects elapsed time beyond the track's end (`main.time` sat at Circles' full 03:06 in run 20261029-223259-454). `testNowPlayingFollowsTheServer` dropped its elapsed-time check.
2. **No Sendspin in scripted mode.** This Mac never becomes a Music Assistant player, so "This Mac plays Music Assistant media" can't pass: double-clicking album 27 on This Mac sends only `album_tracks` and the feed stays local. `testThisMacPlaysMusicAssistant` is marked `XCTExpectFailure` until this lands.
3. **No recommendation or radio fixtures,** so Discover and Radio aren't tested.
4. **No received-commands log,** so "quit sends stop" (`quitSendsStop`) can't be asserted after the app exits.
5. **`maRequests` keeps only the last 20 summaries** while the app polls `get`/`get_active_queue` about twice a second, so early requests such as `auth` scroll out; tests compare counts before and after instead.

Also left out: `dropOntoPlaylistAdds` (an album row and a playlist row are never on screen together in the Library window) — a test-design problem, not the server's.

## Plan

To be planned. Fix the epoch (use the time the snapshot is served), add a scripted Sendspin stand-in or a Debug hook that makes This Mac a scripted player, record or synthesize recommendation and radio fixtures with the read-only recorder, have the server append received commands to a file in the data directory, and raise or make configurable the probe's request window. Then remove #0206's `XCTExpectFailure` and add the left-out tests.
