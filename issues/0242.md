## Description

A MilkDrop visualization is fast motion and, for some presets, flashing. After #0238–#0241 Roadie's window changes presets every 16 s whatever the system's accessibility settings say, cuts between presets on H, hides its overlay (and with it the only text VoiceOver could read) after 3 s, announces nothing, and gives no warning about flashing. Winamp never handled any of this; a Mac app should.

Design: [docs/design/visualization.md](../docs/design/visualization.md) §7.

## Plan

### Inputs

`VisualizationModel` observes, and Debug hooks stand in for (tests can't change system settings):

- Reduce Motion: `NSWorkspace.shared.accessibilityDisplayShouldReduceMotion` + `NSWorkspace.accessibilityDisplayOptionsDidChangeNotification`; hook `-RoadieVisReduceMotion 1`.
- Dim Flashing Lights: `MADimFlashingLightsEnabled()` (MediaAccessibility, macOS 14) + `kMADimFlashingLightsChangedNotification`; hook `-RoadieVisDimFlashing 1`. Link `MediaAccessibility.framework` in `project.yml` if it isn't implicit.
- VoiceOver: `NSWorkspace.shared.isVoiceOverEnabled` (KVO); hook `-RoadieVisVoiceOver 1`.

### Policy (one pure function, tested)

`VisualizationAccessibilityPolicy.make(reduceMotion:dimFlashing:voiceOver:changeWithReduceMotion:)` (App, or `VisualizationKit` if it needs nothing from AppKit) → `suspendsAutoAdvance`, `hardCutBecomesBlend`, `minimumBlend`, `crossfadeOnly`, `dimsPicture`, `overlayNeverHides`, `announcesPresetChanges`, `animatesOverlay`:

| | Reduce Motion | Dim Flashing Lights | VoiceOver |
|---|---|---|---|
| Automatic preset changes | paused unless "Change them anyway" | — | — |
| H | blends (key blend) | blends (≥ 5 s) | — |
| Transitions | crossfade | crossfade, ≥ 5 s | — |
| Picture | — | under a 40 % black layer | — |
| Song title, overlay, toast | fade only / no animation | — | — |
| Overlay and cursor | — | — | never hide |
| Announcements | — | — | preset changes by key or list |

Applied through: `clock.suspend` (reason `reduceMotion`), `renderer.setReducedMotion(true)` (classic: crossfade only; MilkMetal in #0243: `transitionPattern = .crossfade`), a dimming `CALayer` in the host view above the renderer view, `overlay.setHolds([.voiceOver])`, and `NSAccessibility.post(element: hostView, notification: .announcementRequested, userInfo: [.announcement: name, .priority: NSAccessibilityPriorityLevel.medium.rawValue])`.

### Settings

`VisualizationSettingsView` (#0241): under "Change presets automatically", when Reduce Motion is on: "Paused while Reduce Motion is on." and a "Change them anyway" toggle (`visualization.changeWithReduceMotion`, `vis.settings.changeAnyway`).

## Resolution

Commit 6d035fd. `VisualizationAccessibilityPolicy` (App/Visualization/VisualizationModel+Accessibility.swift) turns Reduce Motion, Dim Flashing Lights and VoiceOver into one policy:

- Reduce Motion: automatic changes pause (a `.reduceMotion` suspension), unless the new Settings toggle "Change them anyway" is on.
- Reduce Motion or Dim Flashing Lights: the renderer uses crossfades only, and H blends (1.7 s).
- Dim Flashing Lights: every change blends for at least 5 s, and the picture sits under a 40 % pass-through dimming view.
- VoiceOver: an overlay hold keeps the overlay and pointer up. Preset changes by key or list, list ↑↓ moves and song titles are announced.
- Reduce Motion: the overlay and toast appear without animation, and the song title fades (`reducesMotion` now reads the same inputs).

The flashing notice (`VisualizationFlashNoticeView.swift`) comes up from the window's `show()` the first time only. Starting it there instead of `open()` keeps the unit tests clear of it. While it's up, the picture is dimmed, auto-advance is suspended and the overlay is held. Continue or Return sets `flashNoticeShown`.

Debug arguments `-RoadieVisReduceMotion`, `-RoadieVisDimFlashing` and `-RoadieVisVoiceOver` stand in for the system settings. The probe gains `autoAdvance`, `dimmed` and `flashNotice`. UI tests pass `RoadieUIApp.Visualization.flashNoticeShown`, except the notice's own test. The commit also adds the Help page's Visualization section, the §5.12 row and the CHANGELOG line.
