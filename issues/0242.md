# 0242 — The visualization ignores Reduce Motion, Dim Flashing Lights and VoiceOver

| | |
|---|---|
| **Status** | open |
| **Module** | App |
| **Platform** | macOS |
| **First seen** | 2026-10-29 |

## Description

A MilkDrop visualization is fast motion and, for some presets, flashing. After #0238–#0241 Roadie's window changes presets every 16 s whatever the system's accessibility settings say, cuts between presets on H, hides its overlay (and with it the only text VoiceOver could read) after 3 s, announces nothing, and gives no warning about flashing. Winamp never handled any of this; a Mac app should.

Design: [docs/design/visualization.md](../docs/design/visualization.md) §7.

## Plan

### Inputs

`VisualizationModel` observes, and Debug hooks stand in for (tests can't change system settings):

- Reduce Motion: `NSWorkspace.shared.accessibilityDisplayShouldReduceMotion` + `NSWorkspace.accessibilityDisplayOptionsDidChangeNotification`; hook `-RoadieVisReduceMotion 1`.
- Dim Flashing Lights: `MADimFlashingLightsEnabled()` (MediaAccessibility, macOS 14) + `kMADimFlashingLightsChangedNotification`; hook `-RoadieVisDimFlashing 1`. Link `MediaAccessibility.framework` in `project.yml` if it isn't implicit.
- VoiceOver: `NSWorkspace.shared.isVoiceOverEnabled` (KVO); hook `-RoadieVisVoiceOver 1`.

### Policy (one pure function, tested)

`VisualizationAccessibilityPolicy.make(reduceMotion:dimFlashing:voiceOver:changeWithReduceMotion:)` (App, or `VisualizationKit` if it needs nothing from AppKit) → `suspendsAutoAdvance`, `hardCutBecomesBlend`, `minimumBlend`, `crossfadeOnly`, `dimsPicture`, `overlayNeverHides`, `announcesPresetChanges`, `animatesOverlay`:

| | Reduce Motion | Dim Flashing Lights | VoiceOver |
|---|---|---|---|
| Automatic preset changes | paused unless "Change them anyway" | — | — |
| H | blends (key blend) | blends (≥ 5 s) | — |
| Transitions | crossfade | crossfade, ≥ 5 s | — |
| Picture | — | under a 40 % black layer | — |
| Song title, overlay, toast | fade only / no animation | — | — |
| Overlay and cursor | — | — | never hide |
| Announcements | — | — | preset changes by key or list |

Applied through: `clock.suspend` (reason `reduceMotion`), `renderer.setReducedMotion(true)` (classic: crossfade only; MilkMetal in #0243: `transitionPattern = .crossfade`), a dimming `CALayer` in the host view above the renderer view, `overlay.setHolds([.voiceOver])`, and `NSAccessibility.post(element: hostView, notification: .announcementRequested, userInfo: [.announcement: name, .priority: NSAccessibilityPriorityLevel.medium.rawValue])`.

### Settings

`VisualizationSettingsView` (#0241): under "Change presets automatically", when Reduce Motion is on: "Paused while Reduce Motion is on." and a "Change them anyway" toggle (`visualization.changeWithReduceMotion`, `vis.settings.changeAnyway`).

### Flashing notice

The first time the window opens (`flashNoticeShown` false): a centred card (`vis.flashNotice`): "Some visualizations flash or change quickly. If flashing lights affect you, turn on Reduce Motion or Dim Flashing Lights in System Settings › Accessibility." with **Continue** (`vis.flashNotice.continue`, default button, Return). While it's up: the picture is dimmed (the same layer), auto-advance is suspended, overlay hold `.notice`. Continue sets `flashNoticeShown`. UI tests pass `-visualization.flashNoticeShown YES` by default in the `RoadieUIApp.Visualization` helper, except the test of the notice itself; update the earlier `VisualizationUITests` launches through that helper.

### Labels audit

Check every element from #0235–#0240 has a label and the card reads as one "Now playing" group; the canvas's value is the preset name; the toast and song title are announced only with VoiceOver (they're transient, so an `announcementRequested`, not focus).

### Docs

- `docs/design/test-automation.md` §5.12 rows: "Reduce Motion pauses automatic changes, crossfades, softens the title; Dim Flashing Lights dims and crossfades; VoiceOver keeps the overlay up and hears preset changes; flashing notice on first open (#0242)" → UI `VisualizationUITests.testReduceMotionPausesAutomaticChanges`, `.testDimFlashingLightsDimsAndNeverCuts`, `.testVoiceOverKeepsTheOverlayUp`, `.testFlashingNoticeOnFirstOpen`; Unit `RoadieTests.VisualizationAccessibilityTests`; *by hand* with the real settings and VoiceOver.
- `website/help.html`: a new section `<h2 id="visualization">Visualization</h2>`: how to open it, full screen, the overlay, the key table from design §2.5, Settings, the Music Assistant note, and the accessibility behaviour (Reduce Motion, Dim Flashing Lights; the dimming is blanket, Roadie can't detect flashes). Run `scripts/check-website.sh` through the fast tier (it's a `verify.sh` step).
- `CHANGELOG.md` › Added: "The Visualization window respects Reduce Motion and Dim Flashing Lights, keeps its overlay up for VoiceOver, and warns about flashing the first time it opens."

## By hand

1. First open on a fresh install: the flashing notice, picture dimmed behind it; Continue; never again.
2. System Settings › Accessibility › Display › Reduce Motion on: presets stop changing on their own (Settings says why; "Change them anyway" brings it back); H blends; the title fades.
3. Dim Flashing Lights on (Accessibility › Display): the picture is darker; changes are slow crossfades.
4. VoiceOver on (⌘F5): the overlay never hides; → announces the new preset's name; the card reads as "Now playing" with title, artist, time; the right-click menu lists every command.
5. Help page: roadie.sstools.co/help.html#visualization (after deploy) lists the keys.
