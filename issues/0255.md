# 0255 — New Playlist… can post an earlier failure's notice when the playlist isn't created

| | |
|---|---|
| **Status** | open |
| **Module** | PlayerKit / LibraryBrowser |
| **Platform** | macOS |
| **First seen** | 2026-10-29 |

## Description

Found while writing #0215's tests. `PlaylistsModel.create(named:adding:)` (`Packages/PlayerKit/Sources/LibraryBrowser/PlaylistsModel.swift:98-99`) returns `message` when `create(named:)` returns nil:

```swift
guard let created = await create(named: name) else { return message }
```

`create(named:)` returns nil without touching `message` when the backend can't edit playlists (`canEdit` false) or the name is blank (line 147), and only clears `message` after that guard (line 148). So a `message` left over from an earlier failure (a refused rename, add or delete) comes back as the result of New Playlist…, and the caller posts that stale notice.

Expected: a create that doesn't happen returns nil (blank name) or a notice about creating (can't edit), never an earlier operation's message.

## Plan

Clear `message` before the guard in `create(named:)`, or have `create(named:adding:)` return a create-specific notice for the `canEdit == false` case and nil for a blank name. Regression unit test in LibraryBrowserTests: fail an operation to set `message`, then `create(named:adding:)` on a backend without `.playlistEditing` and with a blank name; assert neither returns the old message. Proven to fail first.
