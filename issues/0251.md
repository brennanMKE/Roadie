# 0251 — Clicking a Music Assistant playlist's name in the Library doesn't select it, and the double-click gesture may block dragging it

| | |
|---|---|
| **Status** | open |
| **Module** | App |
| **Platform** | macOS |
| **First seen** | 2026-10-29 |

## Description

Found while fixing #0205. Album rows had the same problem and #0205 fixed it there: a row-level `.simultaneousGesture(TapGesture(count: 2))` on a row whose `.contentShape(Rectangle())` covers all its content swallows single clicks (no selection) and blocked the album drag onto the playlist editor (#0188's area).

Playlist rows in the Library (Music Assistant only) still use that gesture: `App/Browser/ArtistListView.swift:114`, in `PlaylistListView`:

```swift
.simultaneousGesture(TapGesture(count: 2).onEnded { player.playFromLibrary(.play(container: playlist.id)) })
.libraryDraggable([playlist.id])
```

Expected, as for albums after #0205: a single click on a playlist's name selects it and shows its tracks; dragging a playlist onto the playlist editor adds its tracks; double-click plays it.

## Plan

Do what #0205 did for albums: move the double-click to the List's `contextMenu(forSelectionType:primaryAction:)` (via `PagedListView`'s `primaryAction`/`menu`, if the playlist list uses it) and drop the row gesture. Regression UI test in #0206's `MusicAssistantUITests` (click the name selects; drag lands), proven to fail first.
