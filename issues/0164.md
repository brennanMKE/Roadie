## Description

M14 work item W13 from [docs/design/release.md](../docs/design/release.md). Depends on: W7.

## Expected behavior

`scripts/setup-notary.sh`, credential export/import scripts: refuse to write inside the repo, never pass `-P` or print secrets, never overwrite an existing key.

## Resolution notes

> 🟢 Resolved 2026-10-23 — notary setup and credential export/import scripts follow the secrets rules; the all-identities `.p12` export is documented.

## Root cause

Release credentials (Developer ID identity, notary profile, Sparkle key) had no scripted setup, backup or move.

## Fix

- `scripts/setup-notary.sh [--profile NAME] [--force]`: prompts for the `.p8` path (refused inside the repo), key id
  and issuer; `notarytool store-credentials --key` (no password on the command line); skips a working profile.
- `scripts/export-release-credentials.sh [--sparkle-bin DIR] [--p8 PATH] DEST`: refuses a destination inside the repo
  (real paths) or not empty; mode 700/600; `generate_keys -x`, `security export -t identities` with the passphrase in
  its own dialog (no `-P`).
- `scripts/import-release-credentials.sh [--sparkle-bin DIR] SRC`: `generate_keys -f` only when `-p` finds no key;
  skips the `.p12` when a Developer ID identity exists.
- All refuse xtrace. `docs/release-credentials.md` covers setup, moving and backups.
- Review fix (ddc23be): `setup-notary.sh` now ends with `preflight.sh --credentials-only` like the others; the import's
  identity check no longer pipes into `grep -q` under `pipefail`; the export message and the doc say plainly that
  `DeveloperID.p12` holds **every** identity in the login keychain (`security export` can't select one), with the
  Keychain Access alternative for exporting just the Developer ID identity. A temporary single-identity keychain was
  judged too complex for this.

## Files changed

- `scripts/setup-notary.sh`, `scripts/export-release-credentials.sh`, `scripts/import-release-credentials.sh`,
  `docs/release-credentials.md`
