# 0055 — Real-time gapless test intermittently finds a gap between tracks in the VM

| | |
|---|---|
| **Status** | open |
| **Module** | AudioCore |
| **Platform** | macOS |
| **First seen** | 2026-10-13 |

## Description

`MixedFormatRealtimeTests.mixedFormatsAdvanceWithoutGapRealtime` failed once in a Tart VM run during #0011 (run `20261013-115928-87225`) and passed on the next run with no change. The recorder at the EQ output found 21 consecutive silent 128-frame blocks (about 2,700 frames, roughly 56 ms) between the first and last audible block, on both channels. That is either a real gap at a track boundary under load, which is exactly what #0003 and #0042 promise never happens, or an artifact of the test or the guest's virtual output device.

## Steps to reproduce

1. Run `scripts/run-tests-vm.sh` repeatedly (the real-time tests are enabled in the guest with `AUDIOCORE_REALTIME=1`).
2. Occasionally `mixedFormatsAdvanceWithoutGapRealtime` fails at `MixedFormatTests.swift:265–266`.

## Expected behavior

No silent blocks between the first and last audible block; the test passes on every run.

## Actual behavior

Intermittently, a run of zero-peak blocks appears mid-stream. See [the log excerpt](0055/playerkit-tests-excerpt.log).

## Notes

Seen again in #0011's review, run `20261013-120336-93454`; the re-run passed. Two failures in about eight VM runs on 2026-10-13.

To find out which it is: record which track boundary (if any) the silent blocks fall on and when the next file was scheduled relative to the boundary (`GaplessScheduler` pre-scheduling runs on the main actor, which a loaded guest may delay); check whether the engine reported an overload or the guest's output device glitched; run the test in a loop in one VM clone to get a failure rate. If it is the guest's device, the test needs to tell an underrun apart from a scheduling gap rather than be loosened. #0044 fixed a different intermittent real-time test (seek).
