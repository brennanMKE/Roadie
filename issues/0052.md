# 0052 — Playback does not use an enhanced-buffering stack

| | |
|---|---|
| **Status** | open |
| **Module** | AudioCore |
| **Platform** | macOS |
| **First seen** | 2026-10-13 |

## Description

AirPlay 2 enhanced buffering, and with it multi-room sync and dropout resilience, is only available to `AVPlayer`/`AVQueuePlayer` or `AVSampleBufferAudioRenderer` + `AVSampleBufferRenderSynchronizer`. AudioCore plays through `AVAudioEngine`, which gets none of it. Move the output stage to the stack #0050 recommends without losing what M1 built.

## Acceptance criteria

- A `PlaybackEngine` boundary (play, pause, seek, enqueue, current time, rate) with the chosen implementation behind it; `Player`'s public API and its tests keep working.
- Gapless playback, mixed sample rates back to back, the 10-band EQ, preamp, balance and the analyzer tap all still work, inside a single pipeline (only one renderer per synchronizer under long-form; never two players at once).
- If option B: enqueue from `requestMediaDataWhenReady(on:using:)` while `isReadyForMoreMediaData`, 1–2 s interleaved sample buffers, one continuous timeline, boundary time observers advance the current track and Now Playing, seek is rate 0 → stop requesting → flush → reposition → resume, and playlist edits after the next track is enqueued use `flush(fromSourceTime:)` with its failure handled. The pipeline tolerates the requested-ahead amount jumping from seconds to minutes when the route changes.
- Volume uses the renderer's/player's `volume`, not sample scaling, so it is not delayed by the buffer.
- Pause/resume sets rate without flushing.
- Deterministic unit tests for timeline offset math, boundary handling and flush failure, rendered silently (no output device; see `docs/testing-in-vm.md`).

## Notes

See "Architecture options" and "Implementation plan" in [docs/airplay-macos-handoff.md](../docs/airplay-macos-handoff.md). Option B is modeled on Apple's "Playing custom audio with your own player" sample.
