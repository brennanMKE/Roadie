## Description

After #0235–#0242 the visualization window, its keys, overlay, list, settings and accessibility all work, but they draw only Roadie's five classic visualizations: no `.milk` preset renders. The renderer is MilkDropMetalKit's `MilkMetal` (`MilkRenderer`, `MilkPreset`), which the user tagged `1.0.0` on 2026-10-30 (https://github.com/brennanMKE/MilkDropMetalKit, tag `1.0.0` → `d9c4fb4`). The user wants it adopted with `.package(url: "https://github.com/brennanMKE/MilkDropMetalKit.git", from: "1.0.0")`, product `MilkMetal`, and wants MilkDrop in 0.0.5.

This issue is the first of three (replanned 2026-10-30, see `## Notes`): the dependency and a `MilkVisualizer` that draws a `.milk` preset through Roadie's renderer seam, proven by unit tests. Showing MilkDrop presets in the window beside the classics is [#0257](0257.md); the bundled presets, the folder setting in Release and the end-to-end UI test are [#0258](0258.md).

Design: [docs/design/visualization.md](../docs/design/visualization.md) §3.2, §4.2, §9; [docs/milkdrop-metal-handoff.md](../docs/milkdrop-metal-handoff.md) §8. Package docs at the tag: `README.md`, `CHANGELOG.md` (1.0.0), `docs/api-1.0.md`.

## Root cause

Roadie had no dependency on MilkDropMetalKit and no renderer behind its seam that could draw a `.milk` preset.

## Fix

Followed the plan. `project.yml` adds MilkDropMetalKit by URL, `from: 1.0.0`, and the Roadie target links product `MilkMetal`. RoadieTests imports it through the host app; it didn't need its own dependency. `MilkVisualizer` (`App/Visualization/MilkVisualizer.swift`) draws into a new `MetalVisualizationView` (a `CAMetalLayer` in `.bgra8Unorm` with no display link). It parses with `MilkPreset(contentsOf:)` on the main actor and commits every command buffer it makes. It also has `reset()` for #0257 and a static `make()` (nil and logged when there's no device), ready for #0257's factory. The factory and the window are unchanged. NOTICE adds MilkDropMetalKit and Butterchurn. No coverage-script change: package checkout paths don't match its `App/` rows. The docs update is a separate commit, 40d38db.

## Plan

### What 1.0.0 is (read at the tag, 2026-10-30)

- **One library product, `MilkMetal`** (api-1.0.md F1). `MilkPresetFormat` and `MilkEEL` are no longer products; nothing else is importable. Requires macOS 14 and Swift 6 (Roadie: 14.0, Swift 6.0). No dependencies, no network, no entitlements, no resources.
- **`MilkRenderer`** is `@MainActor`: `init(device:pixelFormat:) throws(MilkRendererError)`, `load(_ preset: MilkPreset, transition: TimeInterval = 0) throws` (untyped, never throws today, F17), `render(to:commandBuffer:time:)`, `reset()`, `presetErrors: [String]`, `transitionPattern: MilkTransitionPattern` (`.random` default; `.crossfade`, `.wipe`, `.plasma`, `.radial`), `isTransitioning`, `compilesShadersInBackground` (default `true`), `isCompilingShaders`, `meshSize` (48×36), `static supportedPixelFormats`.
- **`feed(samples:channels:sampleRate:)`** is `nonisolated` and **single-producer** (one thread at a time, F4). **The renderer now paces audio itself** (F5 option b): any chunk size, in playback order; each `render` analyzes the 1,024 frames that should be playing at its `time`. Underrun holds the last window, then decays to silence after 0.25 s (no need to feed zeros while paused); at most 0.25 s waits (older is dropped); a sample-rate change drops what's unplayed. Fed just in time, audio plays straight through one tick later.
- **Errors** (F2): `MilkRendererError` (`unsupportedPixelFormat(MTLPixelFormat)`, `noCommandQueue`, `pipelineCompilation(function:message:)`, `resourceCreation(resource:)`); `MilkPresetError` (`unreadableFile(URL, reason:)`, `unreadableText(URL)`, `empty(URL)`, `bundleMissingPreset(URL)`, plus `url`). Both `LocalizedError`; switch with a `default`. `MilkViewError` is gone.
- **`MilkPreset`** (`Sendable`): `name`, `isMilkDrop2`, `init(contentsOf:)` (a `.milk` file or a `.milkpreset` bundle folder), `init(text:name:)`, `init(data:name:)`, all `throws(MilkPresetError)`. **The parser skips lines it doesn't understand**: a file throws only when it can't be read, isn't UTF-8/Windows-1252, or has no `key=value` line at all (`.empty`). Bad equations and shaders don't throw; they're skipped (shaders fall back to the fixed-function passes) and listed in `presetErrors`, possibly a moment after `load` while shaders compile in the background.
- **`MilkView`** still has no pause, frame-rate cap or shared clock (F7 not taken): an `NSView` with its own display link. Roadie keeps its own render loop (§3.2), so `MilkVisualizer` draws into its own `CAMetalLayer` view with `render(to:commandBuffer:time:)` and **commits every command buffer** (F3: three frames in flight on a semaphore; an uncommitted buffer blocks the main thread forever).
- **Presets are not vended**: the `MilkMetal` target has no resources and there's no list API. `Presets/` (42 `.milk` files, `gallery.json`, `README.md`, MIT, written for the package) is repo content only. Bundling them is #0258.

### `MilkVisualizer`

`App/Visualization/MilkVisualizer.swift`: `@MainActor final class MilkVisualizer: VisualizationRenderer`, `kindName "milk"`.

- `init(device: MTLDevice) throws(MilkRendererError)` (or `init?` that logs `error.localizedDescription` and returns nil): `MilkRenderer(device:pixelFormat: .bgra8Unorm)` (not `_srgb`: MilkDrop's output is display-referred, api-1.0.md F11), and a `MTLCommandQueue` from the device (`.noCommandQueue` if nil). Keep the defaults `compilesShadersInBackground = true` and `meshSize` 48×36. Expose the renderer `internal` for tests.
- `view`: a new `MetalVisualizationView` (same file or `App/Visualization/MetalVisualizationView.swift`): an `NSView` whose backing layer is a `CAMetalLayer` with the renderer's `device` and `pixelFormat`, `framebufferOnly = true`, opaque, `drawableSize` = bounds × backing scale (min 1×1), updated in `setFrameSize` and `viewDidChangeBackingProperties`, `layerContentsRedrawPolicy = .never`. Model it on the tag's `MilkView.swift` minus the display link. No display link of its own: `VisualizationModel.tick` (#0235) drives it.
- `canLoad`: `.milk` yes, `.classic` no. (In Debug the classic renderer also accepts `.milk` today; that rule and the factory change are #0257, so this issue doesn't change what the window shows.)
- `load(_:transition:)`: `guard let url = preset.url` (throw a small `MilkVisualizerError.noFile` otherwise), `let milk = try MilkPreset(contentsOf: url)` on the main actor, then `try renderer.load(milk, transition: transition)`. Parse synchronously: the files are a few KB and `renderer.load` already compiles equations and translates shaders on the main actor (F18), so a detached parse would save little and would make the seam async. A `MilkPresetError` propagates to `VisualizationModel.load`'s existing failure path (`markFailed`, skipped, previous preset stays; the list shows "Couldn't load", #0240). After a load, log `renderer.presetErrors` (count and first line, `.public`) at `notice`.
- `problems`: `renderer.presetErrors` (computed, so background shader errors appear when they arrive).
- `feed`: `renderer.feed(samples:channels:sampleRate:)` with `StereoFeedReader`'s output, unchanged from the seam: the model calls it on the main actor only, which satisfies the single-producer rule. **No pacing change in Roadie**: the reader already returns the frames played since the last tick, so the renderer plays them straight through one tick later (F5's "just in time" case). Feeding the ring's newest frames without the reader's lag would trail by up to one tap delivery anyway, the same latency, so keep the reader (and AudioCore untouched, so no `--full`). By hand step 2 checks the beat.
- `draw(at:)`: `guard let layer, let drawable = layer.nextDrawable()` (skip the frame when nil or the drawable size is 0), `commandQueue.makeCommandBuffer()`, `renderer.render(to: drawable.texture, commandBuffer:time:)`, `present(drawable)`, **`commit()` on every path that made a buffer**. `time` is the model's `renderTime` (rises steadily, paused time excluded).
- `setReducedMotion(on)`: `renderer.transitionPattern = on ? .crossfade : .random`.
- `setColors`: no-op (MilkDrop presets carry their own colours).
- `reset()` passthrough (`renderer.reset()`), for #0257: it drops queued audio and restarts the clock, which the mixed renderer needs when MilkDrop becomes the active kind again after the classic one drew (otherwise up to 0.25 s of stale audio stays queued and the picture lags by that much from then on).

## Tests

Fast, XCTest, `Tests/RoadieTests/MilkVisualizerTests.swift` (new). The guest's paravirtual GPU runs MilkMetal's shaders (the package's own VM tests render there), so these run in the fast tier; each `XCTSkip`s when `MTLCreateSystemDefaultDevice()` is nil. Presets are written to a temp directory by the test (no bundled presets yet), e.g. a MilkDrop 1 preset with `zoom=1.01`, a per-frame equation and `nWaveMode=0`:
- `testCreatesARendererOnTheSystemDevice`: `kindName == "milk"`, the view's layer is a `CAMetalLayer` in `.bgra8Unorm`.
- `testCanLoadOnlyMilkPresets`: `.milk` yes, every classic no.
- `testLoadingAMilkPresetSucceeds`: the temp preset loads; `renderer.preset?.name` matches; `problems` empty (set `compilesShadersInBackground = false` in the test so the result is final).
- `testAnEmptyPresetThrows`: a file with no `key=value` line throws `MilkPresetError.empty`; the renderer keeps the previous preset.
- `testAMissingFileThrows`: a URL that doesn't exist throws `MilkPresetError.unreadableFile`.
- `testABrokenEquationIsReportedNotThrown`: a preset whose `per_frame_1=` line doesn't parse loads, and `problems` is non-empty.
- `testDrawCommitsEveryCommandBuffer`: with the view at 64×64 (frame and drawable size set), 10 `draw(at:)` calls return (no stall on the in-flight semaphore) and a command buffer added after them completes within 2 s (`waitUntilCompleted` on a timeout thread, or `addCompletedHandler` + expectation).
- `testFeedThenDrawKeepsThePreset`: a 1 kHz stereo sine fed in 800-frame chunks over 30 draws doesn't crash and the preset stays.
- `testReducedMotionMakesTransitionsCrossfades`: `setReducedMotion(true)` → `.crossfade`, `false` → `.random`.

No `--expect-fail` (an addition).
