# 0211 — `PlayerModel`'s dispatchers, persistence and menus have no unit tests

| | |
|---|---|
| **Status** | open |
| **Module** | App |
| **Platform** | macOS |
| **First seen** | 2026-10-24 |

## Description

`PlayerModel` and its extensions (1,700 lines) hold the dispatch from menus, hotkeys and the playlist's LIST/SORT menus to the packages, the output selection, the This Mac feed, the queue and EQ persistence, the skin loading and the notices. With #0194's configuration it can be built in a test; this issue adds the first `RoadieTests` over it, prioritising the paths the UI tests cross most. Design: [docs/design/test-automation.md](../docs/design/test-automation.md) §2.1.

## Plan

All tests build `PlayerModel(configuration:)` with a temp data directory, a temp defaults suite, `musicAssistant: .scripted("queueLoaded")` or `.none`, `discovery: false`, `museum: .fixtures`, and the folder backend on `AudioFixtures.makeLibrary(at:)` (#0195). A shared `makeModel(scenario:folder:)` helper in `Tests/RoadieTests/Support/`.

### `PlayerModelDispatchTests`

- `mainMenuCommandsDispatch`: for every `MainMenuCommand` case, `perform(_:)` has the expected effect or recorder: `.toggleEQWindow` flips `isEQWindowOpen`; `.timeRemaining` sets `timeMode`; `.toggleDoubleSize` doubles `scale`; `.jumpToFile` opens the panel (`JumpToFilePanel.shared.isVisible`, then close); `.openFiles`/`.addFiles` record a panel request (test-mode probe from #0202's stand-ins); `.quit` records; `.play`… send transport commands (assert `nowPlaying.state` or the scripted server's `receivedCommands` on a speaker). Use a table of `(command, assertion)`; the test fails if a new case isn't in the table (`CaseIterable` on `MainMenuCommand` if it isn't already).
- `hotkeysDispatch`: `perform(WinampHotkey)` for all 13 cases (seek by 5 s on the local player from a known position: `Player.seek` then `elapsed`; volume ±; shuffle/repeat; openFile records; jumpToFile opens).
- `mainMenuStateFollowsTheModel`: `mainMenuState` reflects shade flags, repeat, shuffle, `canNavigateSkins`, `canCheckForUpdates == false`.

### `PlayerModelQueueTests`

- `loadListChoosesByTarget` (#0190): local queue with Music Assistant `.none` → `loadList()` records an open-panel request; with `.scripted` and the Library on Music Assistant → the pop-up with two choices (assert through a test hook that captures `PlaylistContextMenus.popUp` items when `isUITest`; add `PlaylistContextMenus.popUpOverride`); on a remote queue → the picker (`isPickingPlaylist == true`).
- `pickLibraryPlaylistOpensTheEditorAndPicker`, `loadPlaylistPlaysThroughTheLibrary` (scripted server gets `play_media` with the playlist URI).
- `saveQueueTargets`: `canSaveQueue` per `QueueSaveTarget` (local without Music Assistant → false; remote → true).
- `playFromLibraryOnTheFolderBackend`: `.play(container: album)` → the local queue holds the album, `playsLocalQueue`; `.next(ids)` → up-next; `.append`.
- `playFromLibraryOnMusicAssistant`: with a speaker selected → `play_media`.
- `queuePersistsAcrossModels`: enqueue, `flushQueue()`, build a second model on the same data directory → the same rows, stopped at the saved index.
- `playRemoteQueueRowSendsPlayIndex` (#0187 end to end at the model level): `playlist.playRow(3)` on the scripted queue → `receivedCommands.last` is `play_index 3`.

### `PlayerModelOutputTests`

- `selectOutputMovesPlayback`: This Mac → speaker (`OutputMove`), the scripted server gets `play_media`/`transfer` as `OutputMoveTests` describe; back to This Mac.
- `toggleOutputBuildsGroups`: two speakers → `set_members`.
- `feedFollowsStreamEvents`: `applyFeed(.streamStarted)` → `thisMacFeed == .musicAssistant`, `playsLocalQueue == false`; `.streamStopped` back.
- `refusedBalanceOnASpeakerIsQuiet`: `setBalance` with a speaker → no notice posted.

### `PlayerModelPersistenceTests`

- `eqStateRoundTrips` (`equalizer` default), `timeModePersists`, `windowFlagsPersist` (`eqWindowOpen`, shade keys, `alwaysOnTop`, `doubleSize`), `lastSkinPathIsLoadedAtInit` (a generated skin: `skin != nil`), `loadSkinFailurePostsANotice` (a junk file → notice text, skin unchanged).

### `PlaylistMenusTests` and `SkinLibraryModelTests`

- `rowMenuTitlesFollowTheSelection` (Queue/Dequeue/Clear Queue/File Info… enabled), `sortMenuIsDisabledOnRemote` (via the capture hook), `miscOptionsHasGenerateHTML`.
- `SkinLibraryModel`: folder set/clear, `countsText` after a scan of the test skins (needs the cache in the VM: skip with a message when `ROADIE_TEST_SKINS` is unset), `applyDefaultFolderIfNeeded`.

### `WindowLayoutTests`

- `SkinWindowController(kind:model:rootView:)` for the three kinds, never shown: `applyLayout` sizes at scale 1 and 2 and in shade; `WindowDockingCoordinator` layout data round trip (`windowLayout`).

### `LegacyDataCleanupTests`

- `LegacyDataCleanup.run()` against a temp home (if it takes a root; add one): removes exactly the legacy paths and nothing else.

## Tests
