# 0211 — `PlayerModel`'s dispatchers, persistence and menus have no unit tests

| | |

## Description

`PlayerModel` and its extensions (1,700 lines) hold the dispatch from menus, hotkeys and the playlist's LIST/SORT menus to the packages, the output selection, the This Mac feed, the queue and EQ persistence, the skin loading and the notices. With #0194's configuration it can be built in a test; this issue adds the first `RoadieTests` over it, prioritising the paths the UI tests cross most. Design: [docs/design/test-automation.md](../docs/design/test-automation.md) §2.1.

## Root cause

Nothing was broken; there was no coverage. `PlayerModel` and its extensions had no unit tests because, until #0194, a model couldn't be built without the real Keychain, network and disk. Their panels and pop-up menus (`NSOpenPanel`, `NSMenu.popUp`, the About panel, `NSApp.terminate`, Jump to File, the Library window) would also block or touch real state in a hosted test.

## Fix

Six new test classes in `Tests/RoadieTests`, on a shared `PlayerModelTestCase` (`Support/`). Every model gets its own `RoadieConfiguration`: a temp data directory, a temp defaults suite, `.scripted` or `.none` Music Assistant, the fixture Museum, no discovery and recorded external opens. The folder backend runs on #0195's `AudioFixtures.makeLibrary(at:)`. The app hooks are test-only and small:

- `PlayerModel.systemRequestOverride`: when set, the open panels (files, folder, skin, playlist file), About, Quit, Jump to File and the Library window report a `SystemRequest` instead of showing anything.
- `PlaylistContextMenus.popUpOverride`: captures the menu items and their enabled state.
- `MainMenuCommand` is now `CaseIterable`, so a new case without a row in the dispatch table fails the test.
- `PlayerKitTestFixtures` is a package product, linked only by the `RoadieTests` target in `project.yml`.

`git diff --stat App/` is 4 files, +34/-3: only these hooks.

**Not done, or lighter than the plan:**

- **`WindowLayoutTests`: not written in this issue.** This is scope, not a blocker. `SkinWindowController.init(kind:model:rootView:)` builds its window without showing it or registering with `WindowDockingCoordinator`, so `applyLayout` sizing at scale 1 and 2 and in shade, plus the `windowLayout` round trip, can be tested on an isolated model. Left for a follow-up issue.
- **`LegacyDataCleanupTests`: not written.** `LegacyDataCleanup.run` takes `defaults:` and `bundleIdentifier:` but no root. It queries and deletes the real login Keychain item (`com.brennanmke.SkinAmp.plex`) and removes a directory under the real `URL.cachesDirectory`. Testing it in isolation needs an injectable Keychain and caches root, which is an app refactor rather than a hook. Left for a follow-up.
- **`SkinLibraryModel`:** `countsText` is checked only as `"No folder chosen"`. There is no scan of the test skins with a count; that needs `ROADIE_TEST_SKINS` and was not added. `applyDefaultFolderIfNeeded` is checked only when a folder is already set (it keeps it): the real default folder is under the user's home, so the "no folder yet" path is not exercised.
- **Seek hotkeys:** checked stopped, as no-ops (`positionFraction == nil`), not as a 5 s seek from a known position. The test queue has no real files, so the local player has no position to seek from.
- **Jump to File:** asserted through the captured `.jumpToFile` request, not `JumpToFilePanel.shared.isVisible`, so no panel is shown in the hosted test.
- **Transport commands (`.previous`/`.play`/`.pause`/`.next`):** checked only as reaching the local queue (`playsLocalQueue`), not by `nowPlaying.state` or scripted-server commands. `.stop` is checked by `player.state == .stopped`. The remote transport path is covered by `testPlayRemoteQueueRowSendsPlayIndex` and the `play_media` tests.
- **`selectOutputMovesPlayback`:** speaker to This Mac, as the plan describes it, is only possible with a Sendspin session, and the scripted configuration turns Sendspin off. See the second correction below.

**Three test corrections after run `20261024-221002-81868`** (3 of 12 expected tests failed; all were test mistakes, no app bug):

1. **`folderAlbums` (`PlayerModelTestCase.swift:130`), which failed `testLoadListChoosesByTarget` and `testPlayFromLibraryOnTheFolderBackend`.** The helper asserted that `sources.select(folder, persist: false)` returns true. Without Music Assistant, the source fallback has already switched to the folder, and `select` documents false for the current source. It now selects only when needed, then asserts `selectedID == folder`.
2. **`testSelectOutputMovesPlayback` timed out waiting for `transfer`.** Moving onto This Mac needs the Music Assistant player that wraps Roadie's Sendspin client, and Sendspin is off in the scripted configuration. The app correctly refused with `thisMacNotRegisteredText`. The test now checks both paths:
   - Without Sendspin: the refusal notice, the feed back to `.local`, and no `transfer`.
   - With the client registered through `musicAssistant.setLocalSendspinClientID`, as `SendspinController.begin` does (the recording's hidden native Sendspin player `AslV4UN6…`): `player_queues/transfer` from the speaker's queue to that player with `auto_play: true`, no notice, and the feed stays `.musicAssistant`.
3. **`testLoadListChoosesByTarget`, local part.** An `if canLoadLibraryPlaylist` branch accepted either outcome. It now asserts that the folder backend has no playlists, then the recorded `.openPlaylistFile` request and no pop-up.

## Review notes

Review 2026-10-24 (code 097ba77; main merged in 2b16256, which brings #0210's `PlayerKitTestFixtures` product and `RoadieTests` dependency: the conflicts were the two comments in `Packages/PlayerKit/Package.swift` and `project.yml`, so the next run re-verifies the merge too). Bounced. The isolation, the panel and menu capture, the queue, output, persistence and menu tests are good: temp data directories and defaults suites removed in `tearDown`, `.scripted`/`.none` Music Assistant, no discovery, recorded opens, polling waits with 5 s deadlines, and the three corrections after run `20261024-221002-81868` are right. The problem is the dispatch test, whose job is to catch a mis-wired switch: about a third of its rows would still pass if the command did nothing.

What the next pass must fix:

1. **Tautological rows in `testMainMenuCommandsDispatch` and `testHotkeysDispatch`.** Each row must fail if its case were dispatched to nothing or to the wrong action.
   - `.previous`/`.play`/`.pause`/`.next` (both tables) assert `playsLocalQueue`, which is true for a `.none` model whatever happens. `.stop` waits for `.stopped`, which the restored queue already is. All five go through `send(_:)` with `selectedOutput`, so run the transport rows on a `.queueLoaded` model with the scripted speaker selected (`selectSpeakerWithQueue`), as the plan says, and assert the command each one sends: `player_queues/next`, `player_queues/previous` and the play, pause and stop commands the backend sends (look them up in `MusicAssistantKit`). Each row checks the *new* command after its own perform, not just `contains`.
   - `.seekBack`/`.seekForward` assert `positionFraction == nil` before and after, so they're a no-op check of a no-op. On the playing scripted speaker `positionFraction` is non-nil: assert `players/cmd/seek` with the position `WinampHotkeys.seekTarget` gives (±5 s from the reported elapsed time).
   - `.checkForUpdates` asserts `updateActions == nil`, which nothing in the command changes. `updateActions` is a tuple of closures: set `(canCheck: { true }, check: { called = true })` and assert `called`. That also lets `testMainMenuStateFollowsTheModel` check `canCheckForUpdates == true` with it set, as well as `false` without.
   - `.timeElapsed` runs before `.timeRemaining` on a fresh model that is already `.elapsed`. Set `.remaining` first (or check `.timeElapsed` after `.timeRemaining`).
   - `.nextSkin`/`.previousSkin`/`.randomSkin` assert `canNavigate == false`, which they don't change. If a test skins list can't be seeded cheaply, say in the table's comment that these three rows are crash checks only, and list them in the follow-ups below; don't present them as dispatch checks.
2. **Compile the hooks in Debug only**, as #0194 does for the scripted Music Assistant and the stubs. `systemRequestOverride` and `PlaylistContextMenus.popUpOverride` are inert when nil and nothing in `App/` sets them, but they're internal, settable stored statics/properties in the Release binary, and the Release app has no tests to set them. Put the two stored properties under `#if DEBUG`, and have `intercepted(_:)` return false and `popUp` skip the check in Release, so the call sites stay unconditional. `SystemRequest` can stay unconditional.
3. **`testRefusedBalanceOnASpeakerIsQuiet` relies on a 300 ms sleep.** The comment says the volume is queued after the balance "once it lands", but the test never waits for it. Wait for `players/cmd/volume_set` to reach the scripted server, then assert `notice == nil`, so the negative check is ordered by the command stream rather than the clock.
4. **`testToggleOutputBuildsGroups` can skip silently.** `players-all.json` has several available speakers (Living Room, Kitchen, Living Room Display), so replace the `XCTSkip` with `XCTUnwrap`, assert the `set_members` arguments name the other speaker, and add `toggleOutputBuildsGroups` to `--expect`.
5. **Mute the folder-backend play.** `testPlayFromLibraryOnTheFolderBackend` starts the fixture sines at the default volume. In the VM that's the guest's muted device (design §Risks, and the `AUDIO` check passed), but a hosted `⌘U` on a dev Mac would play them aloud (`silentOutput` isn't read yet). Set the volume to 0 before `playFromLibrary(.play…)`.

Re-run `scripts/verify.sh` with the expect list above plus `toggleOutputBuildsGroups`.

The other scope gaps in `## Fix` are acceptable for this issue and are recorded under `## Follow-ups` so they aren't lost.

## Plan

All tests build `PlayerModel(configuration:)` with a temp data directory, a temp defaults suite, `musicAssistant: .scripted("queueLoaded")` or `.none`, `discovery: false`, `museum: .fixtures`, and the folder backend on `AudioFixtures.makeLibrary(at:)` (#0195). A shared `makeModel(scenario:folder:)` helper in `Tests/RoadieTests/Support/`.

### `PlayerModelDispatchTests`

- `mainMenuCommandsDispatch`: for every `MainMenuCommand` case, `perform(_:)` has the expected effect or recorder: `.toggleEQWindow` flips `isEQWindowOpen`; `.timeRemaining` sets `timeMode`; `.toggleDoubleSize` doubles `scale`; `.jumpToFile` opens the panel (`JumpToFilePanel.shared.isVisible`, then close); `.openFiles`/`.addFiles` record a panel request (test-mode probe from #0202's stand-ins); `.quit` records; `.play`… send transport commands (assert `nowPlaying.state` or the scripted server's `receivedCommands` on a speaker). Use a table of `(command, assertion)`; the test fails if a new case isn't in the table (`CaseIterable` on `MainMenuCommand` if it isn't already).
- `hotkeysDispatch`: `perform(WinampHotkey)` for all 13 cases (seek by 5 s on the local player from a known position: `Player.seek` then `elapsed`; volume ±; shuffle/repeat; openFile records; jumpToFile opens).
- `mainMenuStateFollowsTheModel`: `mainMenuState` reflects shade flags, repeat, shuffle, `canNavigateSkins`, `canCheckForUpdates == false`.
