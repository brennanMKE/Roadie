## Description

M14 work item W9 from [docs/design/release.md](../docs/design/release.md). Depends on: W6, W7.

## Expected behavior

`scripts/preflight.sh` (`--release X.Y.Z`, `--credentials-only`): one line per gate, non-zero on missing identity, notary profile, Sparkle key mismatch, version/build mismatch. Never prints secrets; stub-based tests.

## Resolution notes

> 🟢 Resolved 2026-10-23 — `scripts/preflight.sh` prints one line per gate and fails on a missing identity, notary profile, Sparkle key or version bump; stub-based tests run in the VM.

## Root cause

There was no single check that a Mac and the repo were ready to release a given version.

## Fix

- `scripts/preflight.sh --release X.Y.Z | --credentials-only [--strict] [--build-number N] [--identity NAME]
  [--notary-profile NAME] [--sparkle-bin DIR]`: tools; clean tree on `main`; `MARKETING_VERSION` (from
  `project.yml` `settings.base`) equals X.Y.Z and is newer than the appcast's newest `sparkle:shortVersionString`; tag
  absent locally and on origin; `## [X.Y.Z]` in `CHANGELOG.md`; build number greater than the appcast's highest
  `sparkle:version`, compared as (date, time); Developer ID identity (default: the first one) and its expiry (WARN
  under 30 days); notary profile; `generate_keys --account Roadie -p` equals `ROADIE_PUBLIC_ED_KEY`; `gh auth status`.
  Refuses xtrace, prints only names and match/no match.
- Review (99e3c3a): `scripts/tests/test_release_tools.py` (VM step `release-tools`) runs preflight in a throwaway repo
  with stubbed `security`, `openssl`, `xcrun`, `gh` and `generate_keys`, and checks it parses an appcast written by
  `appcast-item.sh`.
