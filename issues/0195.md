# 0195 — The tests have no real mp3, m4a or flac files

## Description

Every audio test writes a WAV at run time (`writeWAV`, `writeSine`; one `writeTaggedM4A`). MP3, AAC, ALAC and FLAC decoding, their tags, their encoder delay and gapless joins are never exercised, and the UI tests will need a music folder of real files. This issue commits a tiny, licence-clean set of generated audio files with real tags, a script that regenerates them, a script that lays them out as an `Artist/Album/Track` library, and the first tests over them. Design: [docs/design/test-automation.md](../docs/design/test-automation.md) §2.3.

## Plan

### 1. Generator (`scripts/make-test-audio.sh`, new; host, run once)

zsh. Writes into `Packages/PlayerKit/Sources/PlayerKitTestFixtures/Audio/`:

| File | How |
|---|---|
| `06 Tone F.wav` | `swift scripts/make-test-tone.swift <out.wav> <hz> <seconds>` (new, ~30 lines: `AVAudioFile` 44.1 kHz stereo 16-bit; the same shape as `writeSine`) |
| `03 Tone C.m4a` (AAC 96 kbps), `04 Tone D.m4a` (ALAC) | `afconvert -f m4af -d aac -b 96000` / `-d alac` from a generated WAV; tags with `AVAssetExportSession`? No: `afconvert` writes no tags. Use the existing `writeTaggedM4A` logic moved into `make-test-tone.swift` (`AVAssetWriter` with `AVMetadataItem`s: title, artist, album, track number, year) for the AAC file; for ALAC write via `AVAssetWriter` with `AVFormatIDKey: kAudioFormatAppleLossless`. |
| `05 Tone E.flac` | `afconvert -f flac -d flac` from the WAV; Vorbis comments: `afconvert` can't write them, so the generator writes `TITLE=`/`ARTIST=` with a 40-line stdlib Python (`scripts/flac-tag.py`, `-I`) that inserts a `VORBIS_COMMENT` block. If that proves fiddly, leave the FLAC untagged and test the file-name fallback title for it. |
| `01 Tone A.mp3`, `02 Tone B.mp3` (64 kbps, 2.5 s, 440 Hz and 660 Hz) | `lame -b 64 --tt --ta --tl --tn` when `lame` is on PATH; otherwise print `lame not installed (brew install lame); mp3 fixtures unchanged` and exit 0. The script writes `Audio/MANIFEST.txt` with each file's md5, duration, format and the generator versions. |
| `cover.jpg` | the `writeJPEG` logic (64 px) moved into `make-test-tone.swift` (`--jpeg`) |

Each tone has its own frequency (A 440, B 660, C 880, D 1100, E 1320, F 1760 Hz) so a test can tell files apart by analysing samples. Total under 400 KB; the script fails if any file exceeds 150 KB.

### 2. The fixture target (`Packages/PlayerKit/Package.swift`)

`.target(name: "PlayerKitTestFixtures", resources: [.copy("Audio")])` with one file, `AudioFixtures.swift`:

```swift
public enum AudioFixtures {
    public enum File: String, CaseIterable { case toneAmp3 = "01 Tone A.mp3", … }
    public static func url(_ file: File) -> URL   // Bundle.module
    public static var all: [URL]
    /// Copies the files into `root` as Artist/Album/Track (two artists, three albums, a two-disc album,
    /// one single in the artist folder, one M3U) and returns the expected (artist, album, tracks) listing.
    public static func makeLibrary(at root: URL) throws -> ExpectedLibrary
}
```

`AudioCoreTests`, `FolderBackendKitTests`, `LocalPlaybackTests` and `LibraryBrowserTests` depend on it. `.gitignore`: add `!Packages/PlayerKit/Sources/PlayerKitTestFixtures/Audio/*.mp3` after the `*.mp3` line (negations must follow the pattern they override).

### 3. `scripts/make-test-library.sh <out>` (new) and `scripts/check-fixtures.sh` (new)

- `make-test-library.sh`: the shell twin of `makeLibrary(at:)` for the guest (the UI tests' music folder): copies the fixture files from the package directory into `<out>/Tone Artist/Tone Album/…`, `<out>/Tone Artist/Two Discs/Disc 1|Disc 2/…`, `<out>/Other Artist/Single.m4a`, and writes `Party.m3u`. Keep the two in step with a test (`makeLibraryMatchesTheScript` runs the script into a temp dir and compares the listing).
- `check-fixtures.sh`: fails if `git ls-files` shows any `*.mp3|*.m4a|*.flac|*.wav` outside `Packages/PlayerKit/Sources/PlayerKitTestFixtures/Audio/` and `Packages/*/Tests/**/Fixtures/`, or any file there over 200 KB, or `MANIFEST.txt`'s md5s don't match. Add it as step `fixtures` after `identifiers` in `run-tests-vm.sh`.

### 4. Tests

`Packages/PlayerKit/Tests/AudioCoreTests/AudioFixtureDecodeTests.swift`:

- `everyFixtureDecodesOffline`: for each `AudioFixtures.all`, `LocalTrackLoader.loadTrack(at:)` gives a duration within 0.1 s of `MANIFEST.txt`'s, and `renderSilently` over the whole file yields a frame count within 1 % (encoder priming and padding are trimmed; if the decoder reports gapless metadata for the MP3s, require exactness there).
- `tagsAreRead`: title/artist/album for the MP3 (ID3v2), AAC (iTunes atoms), FLAC (Vorbis comment, or the file-name fallback if step 1 left it untagged; say which in the test name).
- `gaplessMP3JoinHasNoSilence`: schedule `01 Tone A.mp3` then `02 Tone B.mp3`, render across the boundary with `GaplessRenderTests`' helpers, and assert no run of more than 5 ms of near-zero samples at the join and that the frequency changes from 440 to 660 Hz (zero-crossing count over 50 ms windows).
- `mixedFormatQueueRenders`: WAV → AAC → FLAC → ALAC → MP3 in one queue, following `mixedFormatsRenderOffline`.

`Packages/PlayerKit/Tests/FolderBackendKitTests/FolderBackendFixtureLibraryTests.swift`:

- `fixtureLibraryIndexesArtistsAlbumsAndDiscs`: `makeLibrary(at:)` then index; artists, albums, disc ordering and the single match `ExpectedLibrary`.
- `makeLibraryMatchesTheScript` (runs `scripts/make-test-library.sh` with `Process`; skip if the script isn't found relative to `#filePath`).

Slow tier (`ROADIE_SLOW_TESTS=1`, same gate as the scale tests): `fixtureCorpusDecodesEndToEnd` renders every fixture through the full `Player` graph (`Player` in manual rendering mode) and checks the analyzer saw energy at the expected frequency bin.

Expect list: `everyFixtureDecodesOffline,tagsAreRead,gaplessMP3JoinHasNoSilence,mixedFormatQueueRenders,fixtureLibraryIndexesArtistsAlbumsAndDiscs,makeLibraryMatchesTheScript`

## Which tier

**Full:** `scripts/verify.sh --full --expect everyFixtureDecodesOffline,tagsAreRead,gaplessMP3JoinHasNoSilence,mixedFormatQueueRenders,fixtureLibraryIndexesArtistsAlbumsAndDiscs,makeLibraryMatchesTheScript,fixtureCorpusDecodesEndToEnd`. It adds a slow test and touches `AudioCoreTests`; no `AudioCore` source changes are expected, but run `--full` so the new slow test is seen to pass.

## By hand

1. `scripts/make-test-audio.sh` on the host with `lame` installed regenerates the files and `MANIFEST.txt`; `git status` shows only intended changes (the m4a/flac/wav are byte-identical on rerun, or the script says why not: AAC encoders aren't deterministic, so the manifest records the md5 of the committed file and the script only replaces a file when `--force`).
2. Open `Packages/PlayerKit/Sources/PlayerKitTestFixtures/Audio/` in Finder; QuickTime plays each tone; Get Info shows the tags.
3. `scripts/make-test-library.sh /tmp/lib` and point Roadie's Settings › Library at it: two artists, three albums, the disc order right, `Party.m3u` loads from LIST › Load.
