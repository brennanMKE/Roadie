# 0253 — Opening an album from an artist or Favorites waits a double-click interval even for keyboard and VoiceOver users

| | |
|---|---|
| **Status** | open |
| **Module** | App |
| **Platform** | macOS |
| **First seen** | 2026-10-29 |

## Description

#0205 fixed double-click on albums in NavigationStack album lists (an artist's albums, Favorites' albums and playlists) by deferring the push of the track list: `pushAfterDoubleClick` in `App/Browser/AlbumListView.swift:91-107` waits `NSEvent.doubleClickInterval` after a selection before pushing, so a double-click's second click reaches the list's primary action (play).

Side effects found in #0205's review (Opus, medium):

- Every new selection waits the interval, about 0.5 s by default and several seconds if the user set a slow double-click speed in Accessibility, including selections that didn't come from a mouse click: arrow keys, VO-Space, and selection set in code.
- `ArtistAlbumsView` keys the delay's `task(id:)` on the whole `LibraryAlbum` value, not its id; an in-place change (e.g. `isFavorite` after a reload) restarts the wait. `FavoritesDetailView` keys on the id.

## Plan

Push at once when the selection didn't come from a mouse click (e.g. `NSApp.currentEvent?.type != .leftMouseDown`), keep the wait only for a click that could be the first of a double-click, and key `ArtistAlbumsView`'s task on the album id. Tests: keyboard selection in the artist detail opens the album without waiting (assert within well under the interval); #0205's `testDoubleClickAlbumInArtistDetailPlays` keeps passing.

## By hand

With a slow double-click speed (System Settings › Accessibility › Pointer Control) and with VoiceOver: select an album in an artist's detail and check it opens promptly.
