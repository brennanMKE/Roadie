# 0221 — A playlist the user created in Music Assistant is listed under "Built-in" and can't be renamed or deleted

| | |
|---|---|
| **Status** | open |
| **Module** | PlayerKit / MusicAssistantKit / LibraryBrowser |
| **Platform** | macOS |
| **First seen** | 2026-10-27 |

## Description

On the user's server (read-only look, 2026-10-27) `music/playlists/library_items` returns 9 playlists, all with `provider: "library"`, one provider mapping `builtin`/`builtin`, and `owner: "Music Assistant"`. Eight are MA's generated playlists (`is_editable: false`: 500 Random tracks, All favorited tracks, Infinite Mix ×2, Random Album, Random Artist, Recently added, Recently played). The ninth, **Party** (item_id 9), is one the user made: `is_editable: true`.

`MAMapping.playlistSource` (`Packages/PlayerKit/Sources/MusicAssistantKit/MAMapping.swift:28`) returns `.builtIn` for the `builtin` domain when `owner == "Music Assistant" || isEditable != true`. MA sets that owner on user-created playlists too, so Party is classified `.builtIn`:

- the Library's Playlists list shows no "My Playlists" group; Party sits in "Built-in" among the generated ones;
- `LibraryPlaylist(ma:)` leaves `.rename` and `.delete` out of `editing` for `.builtIn`, so Party can't be renamed or deleted from Roadie.

The synthetic fixtures gave user playlists `owner: "user"` (`ScriptedMusicAssistant.swift:862`), so nothing caught it.

## Expected

An editable playlist on the `builtin` provider is the user's: grouped under "My Playlists", renamable and deletable (as the server allows). MA's generated playlists stay "Built-in".
