# 0202 — The main window, hotkeys and menus have no UI tests

| | |
|---|---|
| **Status** | open |
| **Module** | App |
| **Platform** | macOS |
| **First seen** | 2026-10-24 |

## Description

Nothing drives the main window: its transport, sliders, toggles, time display, marquee, clutter bar, title bar, shade mode, the skinned pop-up menu, the menu bar, the Winamp bare keys, or window docking. This issue adds `MainWindowUITests` and `MenuBarUITests` over the folder library with the base skin, covering the rows marked `MainWindowUITests` / `MenuBarUITests` in [docs/design/test-automation.md](../docs/design/test-automation.md) §5.1–§5.3.

## Plan

Each test launches with `app.launch(library: .folder, windows: [.main, .eq, .playlist])` (#0200's harness), loads the fixture library's first album through the probe-free path (`⌘L`, double-click the album, or the faster `-RoadieOpenFiles <folder>` launch argument #0194 accepts, which opens files as File › Open… would), and waits for `playing`.

### `Tests/RoadieUITests/MainWindowUITests.swift`

- `transportButtons`: play → `main.state == playing`; pause → `paused` and `main.time` stops changing; stop → `stopped`, time `00:00`; next/previous → `probe.currentIndex` 1 then 0; eject → `-RoadieOpenFiles` isn't a panel, so assert the probe records `openFilesRequested` (a test-mode hook in `PlayerModel.openFiles` that records instead of showing `NSOpenPanel` when `isUITest`).
- `seekAndTimeMode`: drag `main.position` to 50 % → `main.time` within 10 % of half the duration; click `main.time` → value starts with `remaining`; click again → `elapsed`.
- `volumeAndBalance`: `adjust(toNormalizedSliderPosition: 0.3)` on `main.volume` → value `30` and `main.marquee` shows `Volume: 30%` while dragging; balance to 0.75 → `50` and `Balance: 50% right`; the marquee returns to the track after `endSliderDrag`.
- `shuffleRepeatToggles`: click `main.shuffle` → `.isSelected`; Playback menu shows Shuffle checked; ⌃⌘S turns it off. Same for repeat.
- `eqAndPlaylistToggles`: click `main.eq` → the EQ window disappears (`app.windows` count); click again → back and docked below main (its frame's `minY` equals main's `maxY` in screen coordinates: read `window.frame`); `main.playlist` the same; ⌘2/⌘3 too.
- `marqueeShowsTheTrack`: `main.marquee` value is `1. Tone Artist - Tone A (0:02)` form (check `PlaylistText.displayName` and `marqueeText`); after next it is `2. …`.
- `formatIndicators`: with the fixture MP3 playing, `main.kbps == 64`, `main.khz == 44`, `main.stereo == stereo`; switch to the WAV (next twice) → `1411`.
- `visualizerMenu`: click `main.clutter.v` → `app.menuItems["Oscilloscope"]` → `main.visualizer == oscilloscope`; `Off`.
- `clutterBar`: `A` toggles `probe.alwaysOnTop` (and Options › Always On Top shows checked); `D` doubles the window frame; `I` opens the File Info panel (`app.windows["File Info"]`, close it); `O` pops the options menu.
- `titleBar`: `main.title.shade` → `shade.main.play` exists and the window is 14 skin px tall; double-click the title bar → back; `main.title.minimize` → `window.isMiniaturized` isn't exposed, so check `app.windows.count` dropped and reopen with `open -a` (Dock reopen path, `reopenShowsWindows`); `main.title.close` ends the app (`app.wait(for: .notRunning)`).
- `shadeMode`: in shade: transport works (`shade.main.play`/pause), `shade.main.time` advances, `shade.main.marquee` holds the title.
- `alwaysOnTopAndDoubleSize`: set both, relaunch (`app.terminate(); app.launch(keepingDefaults: true)`), both persist (`probe`).
- `dragDocksTheEqualizer`: drag the EQ window by its title bar 40 pt down-right and release near main's bottom edge → it snaps back docked (frame check); drag it 300 pt away → it stays; relaunch keeps the layout (`windowLayout`).
- `popUpMenuOpens`, `popUpMenuItems`, `popUpTogglesWindows`, `optionsSubmenu`, `playbackSubmenu`: `main.title.menu.click()` → `app.menus.firstMatch` has the titles from `MainMenu.entries` (compare against `MainMenu.entries(MainMenuState())` titles, imported from SkinKit in the test target: add `SkinKit` as a dependency of `RoadieUITests` or hard-code the titles); Options › Double Size toggles; Playback › Next advances; right-click on the main window opens the same menu.
- `bareHotkeys`: with the main window key, `typeKey("x")` plays, `"c"` pauses, `"v"` stops, `"b"`/`"z"` next/previous, `"s"`/`"r"` toggle shuffle/repeat, `"l"` requests Open File (probe), `"j"` opens Jump to File (`jump.search` exists; Esc), arrows seek and change volume (values move by 5 s / 2 %).
- `missingFileShowsANotice`: launch with `-RoadieOpenFiles` naming one fixture plus a nonexistent path; play the missing one → `main.marquee` shows the failure notice text (`PlaybackFailureTests` has the wording), playback moves on.
- `reopenShowsWindows`: close the playlist with its close button, `open -a Roadie` while running (`Process`) → the main window comes forward; the playlist stays closed (as `applicationShouldHandleReopen` says: only persisted-open windows return).

### `Tests/RoadieUITests/MenuBarUITests.swift`

- `menuBarHasEveryItem`: for each menu (Roadie, File, Skins, Playback, Window, Help) the items in design §5.1 exist with the right key equivalents (XCUITest exposes `menuItem.value`? No: check key equivalents through `AXMenuItemCmdChar` via `menuItem.value(forAttribute:)`; if unavailable, assert titles and rely on `MainMenuTests.shortcutsMatchMenuBar` for keys).
- `menuBarTransport`, `seekAndVolumeShortcuts`, `windowMenu` (⌘1 brings the player forward; ⌃⌘W/E/P shade each window; Always on Top / Double Size toggles with check marks).
- `checkForUpdatesIsDisabledInDebug`: Roadie › Check for Updates… is disabled; the pop-up's item too.
- `aboutPanelOpens`: Roadie › About Roadie shows a window containing "Roadie"; close it.
- `fileMenuItems`: Open…, Add to Playlist…, Open Skin…, Load Playlist…, Save Playlist… exist and are enabled; Open… records `openFilesRequested(replace: true)` in the probe (test-mode hook), Add to Playlist… `replace: false`.
- `quitStopsTheApp`: ⌘Q → `app.wait(for: .notRunning, timeout: 5)`; `queue.json` exists in the data dir afterwards (saved on quit).

### Test-mode hooks needed (small `App/` changes)

`PlayerModel.openFiles(replace:)`, `openFolder()`, `openSkin()`, `loadPlaylistFile()`, `savePlaylistFile()`, `loadEQF()`, `saveEQF()`: when `configuration.isUITest`, record the request in the probe (`panelRequests: ["openFiles replace=true"]`) and, if `-RoadieOpenFiles`/`-RoadieSaveTo` is set, act on those paths instead of showing a panel. Keep each a two-line guard at the top of the method.
