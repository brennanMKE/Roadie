## Description

Support shade (collapsed) mode for the main, EQ and playlist windows.

## Acceptance criteria

- Shade sprites from `titlebar`, `eq_ex` and `pledit` match Webamp.

## Plan

### Scope, order and decisions

Shade ("windowshade") collapses a window to a 14 px strip. Three windows, two phases:

- **Phase A, main window** — lands first and on its own; it depends only on #0025 (landed: `SkinWindowController.Mode` with `.normal`/`.shade` sizes and the `region.normal`/`region.windowShade` switch were put there for this issue). Commit as `#0031 Add main-window shade mode`.
- **Phase B, EQ and playlist** — after #0028 (EQ window) and #0029 (playlist window) land, since their windows do not exist yet. Commit as `#0031 Add EQ and playlist shade modes`. If this issue is picked up before both siblings are resolved, land Phase A, leave the issue `in-progress`, and bail with `## Notes` naming Phase B as blocked (per "When the subagent can't finish"); do not stub EQ/playlist windows here. #0030 (docking) is independent, but see "Docking hook" below: a shade toggle changes a window's height and docked neighbours must follow.

Decisions:

- **Shade state lives in `PlayerModel`, persisted in `UserDefaults`, and the window controller follows it.** `isMainWindowShaded` (key `mainWindowShade`), `isEQWindowShaded` (`equalizerWindowShade`), `isPlaylistWindowShaded` (`playlistWindowShade`), all `Bool`, default `false` (Webamp `reducers/windows.ts:42-64`, `types.ts:773-787` `WindowLayout.shadeMode`). The SwiftUI views read the flag to pick the layout; `SkinWindowController.observe()` tracks it and re-runs `applyLayout()`, which already resizes keeping the top-left corner (`setContentSize` + `setFrameTopLeftPoint`, `SkinWindowController.swift:81-83`) and picks the region section (`:86-90`). If #0030 introduces a window-layout store, fold these three flags into it keeping the key names.
- **Three ways to toggle, one path.** The title-bar shade button (`TitleBarView`), a double-click on the title bar / shade strip (`TitleBarDragView.mouseDown` with `clickCount == 2` → `TitleBarDragging.titleBarDoubleClicked()`, already wired to a no-op), and a `Window › Windowshade` menu item (⌃⌘W; Winamp's Ctrl+W is ⌘W = Close on the Mac). All call `model.toggleMainWindowShade()`. Webamp: `MainWindow/index.tsx:86` (`onDoubleClick`), `Shade.tsx:8-14` (button, stops the double-click so a fast double press is one toggle, not two; a SwiftUI `Button` under the drag view's hole never sees a second click as a title-bar double-click, so nothing extra is needed).
- **Geometry is data in SkinKit, tested headless.** A `MainShadeLayout` table (positions from `css/main-window.css:411-510`, `css/mini-time.css`, `MiniTime.tsx`) plus a `VisLayout` for the small visualizer and two `MainSliders` additions. The App views only draw what the tables say, like `MainSliders` today. The drag view's holes come from the same table so a control is never both dead and undraggable.
- **Shade visualizer is a real port, not a crop.** Webamp's shade vis is 76×5 skin px at (79,5) with its own colour ramps, no grid, no peak push-out, and a different column count per pixel density (`Vis.tsx:66-94`, `VisPainter.ts:129-147, 232-257, 292-316, 415-420, 628-631, 650-699`). At the app's default `scale` 2 Webamp draws the strip at device resolution ("pixelDensity 2": 152×10 device pixels, 75 columns, 10 rows); at 1× it draws 38×5 (37 columns, 5 rows). Both variants are implemented; the 1× spectrum is made by averaging adjacent pairs of the 75 analyzer bands (Webamp recomputes 40 log-spaced bands, `VisPainter.ts:298, 322-357`; the pair average of our 75 log-spaced bands is the closest without touching `SpectrumAnalyzer`). Documented deviation.
- **Phase B reuses the same three switches** (size, region section, drag holes) in whatever controller #0028/#0029 add. If they instantiate `SkinWindowController` per window (as #0025's plan suggests for #0030), give it a `SkinWindowSpec` (`normalSize`, `shadeSize`, `normalRegion`/`shadeRegion` as `KeyPath<SkinRegion, [SkinRegion.Polygon]?>?`, `dragExclusions: (Mode) -> [CGRect]` in skin pixels) instead of the hard-coded main-window values; the main window's spec is `275×116 / 275×14`, `\.normal` / `\.windowShade`, `buttonRects` / `MainShadeLayout.dragExclusions`. The EQ spec uses `\.equalizer` / `\.equalizerShade` (`[EqualizerWS]`); the playlist has no region in Webamp (`Skin.tsx:14-26` lists four sections).

### Phase A, step 2: SkinKit visualizer

`Packages/SkinKit/Sources/SkinKit/Vis/VisRenderer.swift`:

```swift
public enum VisLayout: Sendable, Equatable {
    case main                      // 76x16, grid, 75 columns, 15 rows of bars
    case shade(pixelDensity: Int)  // density 1: 76x5 image, background and bars in x < 38, 37 columns, 5 rows
                                   // density 2: 152x10 image (76x5 skin px drawn 1:1 at scale 2), 75 columns, 10 rows
    public var imageSize: (width: Int, height: Int)
    public var columnCount: Int     // 75 / 37 / 75
    public var maxHeight: Int       // 15 / 5 / 10
    public var backgroundWidth: Int // 76 / 38 / 152   (Vis.tsx 73-80)
    public var pointScale: Int      // 1 / 1 / 2       (Image(decorative:scale:))
}

public struct VisRenderer {
    public let layout: VisLayout
    public var width: Int { layout.imageSize.width }   // keep the statics for .main
    public var height: Int { layout.imageSize.height }
    public init(colors: [RGBColor], layout: VisLayout = .main)
    public func alpha(x: Int, y: Int) -> UInt8        // tests: pixels outside backgroundWidth stay transparent
}
```

Port points, each cited:
- Background: colour 0 across `backgroundWidth`, no grid dots in shade (`Vis.tsx:42-49`), the rest of the row transparent (the strip sprite shows through; `Vis.tsx:76-78` makes the bg canvas 38 wide at 1×). `clear()` keeps copying a template.
- Bars: columns `0..<columnCount`, `x & 3 == 3` still skipped (`VisPainter.ts:424`), height clamped to `maxHeight`, `pushDown` 0 (`:232-233`). Row colours top→bottom: density 1, 5 rows `c4, c8, c11, c14, c17` (`colorssmall`, `:129-135`, `:252-254` `colorssmall[-y + 4]`); density 2, 10 rows `c4, c5, c7, c8, c10, c11, c13, c14, c16, c17` (`colorssmall2`, `:136-147`, `:249-251`). Peaks: colour 23 at row `height - peaks[x]`, drawn whenever 0 ≤ row < height; low peaks are not pushed out of view in shade (`:415-418`), so they sit on the bottom row (that is `VisBars`'s job, below).
- Oscilloscope: for each column `x < columnCount`, start from the main path's unclamped `y16 = 7 + round(16·sample)` (`VisRenderer.swift:82`), then `VisPainter.ts:676-699`: density 1 `y = clamp(round((y16 + 6) / 16 · 5) − 2, 0...4)` (that is `y − 5`, then `round((y + 11)/16·5) − 2`); density 2 `y = clamp(round((y16 + 8) / 16 · 10) − 5, 0...9)`. Lines join the previous row as now, but without the `top += 1` nudge (`:738-745`), and the colour is always index 0 of the scope ramp, `colors[18]` (`colorIndex`, `:628-631`).

`Packages/PlayerKit/Sources/AudioCore/Analyzer/VisBars.swift`: add `public var smallVis = false` (Webamp's name). When set, the `barPeak < 1 → -3` push-out at line 59 is skipped (`VisPainter.ts:415-420`), so `peaks[x]` bottoms out at 1 instead of −2. `maxHeight` is already a `public var`; the caller sets 5 or 10. Input columns beyond `spectrum.count` already read as 0, so a 37-value spectrum works unchanged (the chunk-of-four average then matches Webamp's small-mode chunking, `:360-371`).

### Risks

- **Phase B is blocked on #0028/#0029 and their controller shape.** Do not pre-build EQ/playlist windows here; if they land with a different split of view/controller, port the three switches and the geometry tables, not the structure.
- **Device-resolution shade vis.** The 152×10 image under `scaleEffect(2)` must land 1:1; if it looks soft or offset by half a pixel, check `Image(decorative:scale: 2)` plus `.interpolation(.none)` and that the hosting view's frame is integral. Fallback: render 76×5 at density 1 for all scales (a documented loss of fidelity, not a bug).
- **1× spectrum downsampling** is a deviation (pair average vs. 40 recomputed log bands); it is only visible at scale 1, which the app does not expose today.
- **Drag-view holes.** A wrong rect makes a control dead or the strip undraggable; test 4 pins the table and checks (6)–(8) the rest. The holes are in `TitleBarDragView` coordinates (flipped, points × scale), like `buttonRects` today.
- **Double-click vs. drag.** The first click of a double-click starts a drag and may move the window a pixel before the second click toggles; Webamp behaves the same. Do not add a delay to single clicks to "fix" it.
- **Autosave vs. mode.** `setFrameUsingName` restores whatever size was saved; `applyLayout` then re-applies the mode's size keeping the top-left. If the window ever appears at the wrong height for a frame, the fix is to call `applyLayout()` after `setFrameUsingName` in `show()`, not to stop autosaving.
- **Docking (#0030).** A shade toggle changes height; if #0030 lands first, its manager must react to `windowDidResize` so windows docked below move with the edge. If it lands second, it must handle a window that is 14 px tall at launch.
- **Sibling edits.** `MainSliders.swift`, `MainSlidersTests.swift`, `PlayerModel.swift`, `SkinAmpApp.swift` and `SkinWindowController.swift` are also touched by #0028–#0030; the edits here are additive. Rebase, re-run the VM script, do not re-plan.
