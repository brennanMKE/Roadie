## Description

The visualization window (#0235) moves between presets with ← →, Space and ⌫, in random or file-name order, with a lock and a history, and starts on the last preset shown (design §5). None of that exists, and it's pure logic, so it belongs in a package with fast tests rather than in a view. This issue adds a new PlayerKit target, `VisualizationKit` (Foundation only), with the preset type, the catalogue (built-in classic visualizations, `.milk` files from a folder) and the navigator.

Design: [docs/design/visualization.md](../docs/design/visualization.md) §3.1, §5.

## Root cause

An addition, not a bug: Roadie had no preset model at all.

## Fix

Added the new `VisualizationKit` PlayerKit target (Foundation only), following the plan. It has `VisualizationPreset`/`ClassicStyle`, `PresetCatalog` (`classics`, `scan`, `ordered`), `PresetNavigator` and a public `SplitMix64`. The Roadie target links the product.

There's one detail the plan didn't spell out. The navigator keeps its own list of the ids shown most recently (the current one plus 8 before it), separate from the back/forward history, for random's no-repeat rule. The history changes when the user steps back, so it can't serve that rule. If every candidate is excluded, random falls back to any usable preset except the current one.

### Types (`Packages/PlayerKit/Sources/VisualizationKit/`)

`VisualizationPreset.swift`:

```swift
public enum ClassicStyle: String, CaseIterable, Sendable { case spectrum, oscilloscope, spectrumAndScope, mirror, stereoScope
    public var title: String   // "Classic Spectrum", "Classic Oscilloscope", "Classic Spectrum and Scope", "Classic Mirror", "Classic Stereo Scope"
}
public struct VisualizationPreset: Identifiable, Hashable, Sendable {
    public enum Kind: Hashable, Sendable { case classic(ClassicStyle), milk }
    public enum Source: String, Hashable, Sendable { case builtIn, bundled, user }
    public var id: String; public var name: String; public var kind: Kind; public var source: Source; public var url: URL?
    public static func classic(_ style: ClassicStyle) -> VisualizationPreset     // id "classic:<raw>", source .builtIn
    public static func milk(url: URL, relativePath: String, source: Source) -> VisualizationPreset  // id "<source>:<relativePath>", name = file name minus ".milk"/".milkpreset"
}
```

`PresetCatalog.swift`:

- `static let classics: [VisualizationPreset]` in `ClassicStyle.allCases` order.
- `static func scan(folder: URL, source: Source, fileManager: FileManager = .default) -> [VisualizationPreset]`: recursive `enumerator(at:includingPropertiesForKeys: [.isDirectoryKey, .isPackageKey], options: [.skipsHiddenFiles, .skipsPackageDescendants])`; accepts `*.milk` files (case-insensitive) and `*.milkpreset` directories (bundles, counted as one preset, not descended into); relative paths with `/`; a missing or unreadable folder returns `[]`. Synchronous and cheap (names only); the app calls it off the main actor.
- `static func ordered(_ presets: [VisualizationPreset]) -> [VisualizationPreset]`: classics first in their order, then the rest by `name.localizedStandardCompare`, ties by `id`.

`PresetNavigator.swift` (struct, `Sendable`), rules from design §5.3:

- `init(presets:order:isLocked:startingAt:seed:)`: `current` = the preset with `startingAt` id, else the first. Presets are expected already ordered.
- `next()`: if forward history is non-empty, pop it; else sequential → the one after `current` (wrapping); random → uniform over presets not failed, not `current`, not among the last `min(8, count / 2)` shown; push `current` to back history (cap 64). Returns the new current, or nil with fewer than 2 usable presets.
- `previous()`: pop back history (pushing `current` to forward history); with empty history, the usable preset before `current` in list order (wrapping), no forward push.
- `advanceAutomatically()`: nil while `isLocked`; else as `next()` but clears forward history first.
- `select(id:)`: jumps there, pushes `current` to back history, clears forward history; nil for an unknown or failed id.
- `markFailed(id:)`: the id is skipped by every move for the life of the navigator; if it's `current`, `current` stays (the caller decides what to show).
- `replacePresets(_:)`: new list; `current` kept if its id is still present, else the first; history and failures pruned to ids that still exist.
- `var usable: [VisualizationPreset]` (not failed), `var isLocked`, `var order` (changing order keeps current and history).
- Randomness: a small `SplitMix64: RandomNumberGenerator` (in this target, `public` so #0234 shares it) seeded from `seed`; `Int.random(in:using:)`.
