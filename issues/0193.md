# 0193 — The App target has no unit tests

| | |
|---|---|

## Description

Nothing in `App/` (10,060 lines) is reachable from a test. `project.yml` has no test target for the app, and the `Roadie` scheme's test action lists only the package test targets. The bugs of 0.0.4 lived in App code (`PlaylistModel.playRow`, `PlaylistListInputView.performDragOperation`, `PlaylistListView` rows), so this issue adds a hosted unit-test bundle, `RoadieTests`, wires it into the VM run as a new fast-tier step, and lands two first tests that prove the plumbing. Design: [docs/design/test-automation.md](../docs/design/test-automation.md) §2.1.

## Plan

### 1. The target (`project.yml`)

Add:

```yaml
  RoadieTests:
    type: bundle.unit-test
    platform: macOS
    sources: [Tests/RoadieTests]
    dependencies:
      - target: Roadie
    settings:
      base:
        TEST_HOST: $(BUILT_PRODUCTS_DIR)/Roadie.app/Contents/MacOS/Roadie
        BUNDLE_LOADER: $(TEST_HOST)
        PRODUCT_BUNDLE_IDENTIFIER: co.sstools.roadie.tests
        GENERATE_INFOPLIST_FILE: YES
        CODE_SIGN_IDENTITY: "-"
```

and, in the `Roadie` scheme's `test.targets`, `- RoadieTests` first (before the package targets). Use `@testable import Roadie`; the app target's `ENABLE_TESTABILITY` is on in Debug by default. Create `Tests/RoadieTests/` (a new top-level `Tests/` folder, so `App/` stays app sources only).

### 2. Keep the app quiet under a hosted run (`App/AppDelegate.swift`, `App/RoadieApp.swift`)

- Add `App/TestSupport/HostedTestRun.swift`: `enum HostedTestRun { static let isActive = ProcessInfo.processInfo.environment["XCTestConfigurationFilePath"] != nil }` with a doc comment saying XCTest sets it for the host app of a unit-test bundle.
- In `AppDelegate`, make `model` a `lazy var` (it's `let model = PlayerModel()` today) and in `applicationDidFinishLaunching` return at once when `HostedTestRun.isActive` (no `PlayerModel`, no windows, no Welcome). `RoadieApp`'s scenes read `appDelegate.model` lazily, so nothing constructs it until a test does. Check that `SettingsView`/`Window` bodies aren't evaluated at launch (they aren't: the Library and Skins windows are closed in `applicationDidFinishLaunching`'s async block, which the early return skips; SwiftUI still creates the Library window for the first scene, so keep the window-closing loop before the early return, or confirm the window stays hidden under XCTest and note it).
- `LegacyDataCleanup.run()` and `QueueStore.defaultURL()` run inside `PlayerModel.init`, so they don't run until #0194 gives tests a configured model. Fine for this issue.

### 3. First tests (`Tests/RoadieTests/`)

- `FirstRunStateTests.swift`: `PlayerModel.firstRunState(defaults:)` is an instance method today; make it `static func firstRunState(defaults:) -> FirstRunState` (keep an instance wrapper) so it needs no model. Test the five combinations from `FirstRunPolicyTests` with a `UserDefaults(suiteName: "co.sstools.roadie.tests.\(UUID())")` that is `removePersistentDomain`d in `tearDown`: `completedVersion`, `hasSkinsFolder` (`skinsFolderPath`), `hasLastSkin` (`lastSkinPath`), `hasMusicFolder` (`LibraryFolderPath`), `hasVerifiedServer` (whatever `MusicAssistantServerStore.hasVerifiedServer(defaults:)` reads; look at its implementation for the key).
- `MainMenuBuilderTests.swift`: `MainMenuBuilder` (`App/Window/MainMenuBuilder.swift`) builds an `NSMenu` from `MainMenu.entries(state)`. Check its signature; if it needs a `PlayerModel`, refactor it to take `entries` plus a `(MainMenuCommand) -> Void` handler so the test can pass a recorder. Tests: `buildsEveryEntryWithTitleAndShortcut` (walk `MainMenu.entries(MainMenuState())` against the built menu: titles, separators, submenus, `keyEquivalent` and `keyEquivalentModifierMask`, `state == .on` for checked items, `isEnabled`), `clickingAnItemDispatchesItsCommand` (fire `.jumpToFile`'s item action; the recorder got `.jumpToFile`).

### 4. The VM step (`scripts/run-tests-vm.sh`, `scripts/verify.sh`, docs)

- `APP_BUILD` becomes `xcodebuild -project Roadie.xcodeproj -scheme Roadie -configuration Debug -derivedDataPath build/DerivedData build-for-testing` (it builds the app and the test bundle; the Quick Look and plist checks still find `Build/Products/Debug/Roadie.app`).
- New step after `playerkit-tests`: `run_step app-unit-tests "xcodebuild -project Roadie.xcodeproj -scheme Roadie -configuration Debug -derivedDataPath build/DerivedData test-without-building -only-testing:RoadieTests 2>&1 | grep -vE '^$'"`. Keep the raw xcodebuild output (no `-quiet`), because `verify.sh` reads the `Test Case` lines. Add `Executed [0-9]+ tests` to the summary's grep so the pass line shows the count.
- `verify.sh`: in the pass total, also sum XCTest's `Executed N tests, with M failures` lines (`awk` on `Executed`), so the total counts the app tests. The failure grep already includes `Test Case .* failed` and `: error: `.
- `docs/testing-in-vm.md`: add the step to the summary example and the step list; `issues/Issues.md` "Build / verify command": mention `app-unit-tests` in the fast tier sentence (one line; the full process rewrite is #0213).
- Header comment of `run-tests-vm.sh`: add step 4b.
