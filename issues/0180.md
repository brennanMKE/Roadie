# 0180 — Jump to File can't queue a result

| | |
|---|---|
| **Status** | open |
| **Module** | App |
| **Platform** | macOS |
| **First seen** | 2026-10-23 |

## Description

Phase B of M15. Winamp's Jump to File (with the bundled JTFE plugin) had a **Queue** button: it adds the selected entry to the play-next queue without interrupting the current song. In Roadie the panel (#0176) has the button hidden, and ⇧Return does nothing.

With the play-next list (#0177) and the playlist editor's `toggleQueue` (#0179) in place, this issue:

- Shows the Queue button and wires it and ⇧Return.
- Shows `[n]` on queued results.

On a Music Assistant queue, Queue reaches `toggleQueue`'s remote branch, which #0182 fills in. Until then the button is disabled there.

Default until #0174 row 8: Queue leaves the panel open, and it toggles like `Q`. Several selected results queue in result order.

## Plan

### 1. Panel (`App/JumpToFile/JumpToFilePanel.swift`)

- **Queue button:**
  - Remove `isHidden = true`.
  - `queueSelected()`: the selected results' queue indices, in result order (that's playlist order), else the first result. Call `model.playlist.toggleQueue(indices)`.
  - Leave the panel open, and keep the field focused (`makeFirstResponder(searchField)` if the click moved it).
- **⇧Return:** in `control(_:textView:doCommandBy:)`, the `insertNewline(_:)` + shift branch calls `queueSelected()`.
- **Enabling:**
  - Enabled when there are results and `model.playlist.remote == nil && model.queueRowsSource == .local`.
  - Disabled for a remote queue until #0182, which changes this line to "enabled unless the source is `.none`".
  - Re-check after each filter and on a source change.
- **Marker column:** add a `marker` column (about 40 pt, right-aligned) between name and time, showing `PlaylistText.queueMarker(model.player.queue.upNextPosition(of: track.id))` for local rows and "" for remote ones.
- **Refresh:** the panel already watches `model.playlist.tracks`. Also watch `model.player.queue.upNext` in the same `withObservationTracking` block. On a change, reload only the visible rows (`reloadData(forRowIndexes: rows(in: visibleRect), columnIndexes: [marker column])`), not the index, so markers update after Queue and as tracks play.
- **Button title:** "Queue" while any selected result is unqueued, else "Dequeue". This mirrors the playlist menu's `selectionIsQueued` rule, computed over the selected results' tracks.

### 2. CHANGELOG

Extend #0176's line, or add one: "In Jump to File, Queue (or ⇧Return) adds the selected track to the play-next queue without stopping the current song."

### Tests

None new; the logic lives in `PlayQueue` (#0177) and `PlaylistText.queueMarker` (#0179), both tested. Run the earlier tests to confirm nothing moved.

Expect list: `queueMarkerIsBracketedOneBasedOrEmpty,toggleUpNextAppendsTheUnqueuedOrDequeuesWhenAllAreQueued`

### Which tier

**Fast tier:** `scripts/verify.sh --expect queueMarkerIsBracketedOneBasedOrEmpty,toggleUpNextAppendsTheUnqueuedOrDequeuesWhenAllAreQueued`.

### By hand

1. `J`, type a query, then ⇧Return: the result shows `[1]` in the panel and in the playlist editor. The current song keeps playing and the panel stays open.
2. Select three results (⌘-click) and click Queue: they get `[1] [2] [3]` in playlist order. The button now says Dequeue; clicking it removes all three.
3. When the current song ends, the queued tracks play in order and the panel's markers count down while it's open.
4. With a Music Assistant queue showing, Queue is disabled (until #0182).
