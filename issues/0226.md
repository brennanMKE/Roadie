## Description

The user, 2026-10-27: "This can be hard to do when the skin is insufficient. I do not see the load option here. I had to change to a more complete skin to see it. Is there a way to make it more clear?" The skin was 100cc Class, whose playlist editor draws the ADD, REM, SEL, MISC and LIST buttons as kart racers with no labels ([0226/100cc-playlist-editor.png](0226/100cc-playlist-editor.png)). The user wanted to replace the list with another playlist (LIST › Load) and couldn't find it.

The five buttons' pop-up menus are the only way to reach most of the editor's commands. The menu bar has File › Load Playlist… (a file), File › Save Playlist…, Playback › Load Playlist from Library… and Save Queue as Playlist…, but no New List, Remove All, Crop, Select All/None/Invert, Sort, Reverse, Randomize or Add URL/Folder. The skinned pop-ups also don't show up in the accessibility tree (found in #0203), so VoiceOver can't reach them either.

Review notes (non-blocking): the SORT pop-up's items are now disabled on an empty local queue, and MISC OPTIONS › Generate HTML Playlist is disabled on an empty queue (before, both were enabled and did nothing useful). help.html's "with its shortcut" is loose: only sorts, Load and Save have one.

## Root cause

The editor's commands lived only in the skinned pop-ups (`PlaylistMenusView.run(_:)` switched on sprite names), and there was no menu bar equivalent for most of them. A skin with unlabelled buttons (100cc Class) hid them, and VoiceOver couldn't reach the SORT/MISC pop-ups.

## Fix

- `PlaylistMenu` (SkinKit) holds `PlaylistCommand`, `PlaylistMenuState`, titles, enabled rules and shortcuts, plus `menuBarEntries`, `sortEntries`, `miscOptionsEntries` and `command(forSprite:)`.
- `PlayerModel.playlistMenuState` / `perform(_: PlaylistCommand)` is the one switch. The skinned entries, the SORT and MISC OPTIONS pop-ups (via `PlaylistMenuBuilder`, with `popUpOverride` kept as the test seam) and the new menu bar `PlaylistCommands` (after Playback) all use it. Add URL now opens the Library through `openWindowAction` instead of the view's `openWindow`.
- The SORT pop-up titles are renamed to match the menu bar ("Sort by Title", …). `testSortMenu` is updated to match.
- **Divergence (orchestrator decision): shortcuts.** Only ⌥⌘1/2/3 (sorts), ⌥⌘L (Load Playlist…) and ⌥⌘S (Save Playlist…) have shortcuts. Reverse List, Randomize List, File Info…, Select None and Invert Selection have none: as menu bar shortcuts they would fire while typing in the Library's search field, and Reverse/Randomize can't be undone. The collision test (`shortcutsAreUnique` pins exactly these five) and the docs reflect this; the plan's open question is settled.
- I didn't add `testMenuBarShortcutsAreUnique`, which would walk `NSApp.mainMenu` in the hosted run. The SkinKit `shortcutsDontCollideWithTheMenuBar` test checks the same thing.
- The Music Assistant UI test is unit-only (`testStateOnAMusicAssistantQueue`); it's a candidate for #0206.

## Expected

A **Playlist** menu in the menu bar that holds every command the five skinned buttons offer, grouped as they are (Add, Remove, Select, Misc/Sort, List), with keyboard shortcuts where Winamp has them. It works on any skin and with VoiceOver, and is enabled or disabled exactly as the skinned items are (e.g. Music Assistant queue vs local queue).

## Plan

One model of the playlist editor's commands, in SkinKit beside `MainMenu` (same pattern: plain data, one builder, one exhaustive switch in the app). The skinned pop-ups (#0226), the menu bar's **Playlist** menu (#0226) and the right-click menu (#0229) all read it, so titles, actions and enabled state can't drift.

### 1. `Packages/SkinKit/Sources/SkinKit/Menus/PlaylistMenu.swift` (new)

- `public enum PlaylistCommand: Hashable, Sendable, CaseIterable`: `addFile, addFolder, addURL, removeSelected, crop, clearPlaylist, selectAll, selectNone, invertSelection, sortByTitle, sortByFileName, sortByPath, reverse, randomize, fileInfo, generateHTML, loadPlaylist, savePlaylist`. REM › Remove All and LIST › New List are the same action today (`playlist.removeAll()`), so both map to `clearPlaylist`; the menu bar lists it once.
- `public struct PlaylistMenuState: Equatable, Sendable`: `hasRows, hasSelection, isRemote` (the rows are a Music Assistant queue), `canAddURL` (the Library has a Radio section, #0147), `hasFileInfo` (`playlist.fileInfoTrack != nil`), `canSave` (`canSaveQueue`), `canLoad` (`QueueSaveTarget.loadChoices` non-empty).
- `public struct PlaylistMenuItem`: `command, title, isEnabled, shortcut: MainMenuShortcut?` (reuse `MainMenuShortcut`). `public enum PlaylistMenuEntry { case item(PlaylistMenuItem), separator }`.
- `public enum PlaylistMenu`:
  - `static func item(_ command: PlaylistCommand, _ state: PlaylistMenuState) -> PlaylistMenuItem`: the one place titles, enabled rules and shortcuts live.
  - `static func menuBarEntries(_ state:) -> [PlaylistMenuEntry]`, grouped as the buttons are, separators between groups:
    - Add: **Add File…**, **Add Folder…**, **Add URL…**
    - Remove: **Remove Selected**, **Crop**, **Clear Playlist**
    - Select: **Select All**, **Select None** ⇧⌘A, **Invert Selection** ⇧⌘I
    - Misc: **Sort by Title** ⌥⌘1, **Sort by File Name** ⌥⌘2, **Sort by Path and File Name** ⌥⌘3, **Reverse List** ⌘R, **Randomize List** ⌥⌘R, **File Info…** ⌘I, **Generate HTML Playlist**
    - List: **Load Playlist…** ⌥⌘L (LIST › Load's `loadList()`: when the local queue has both a file and Library playlists it pops the same Library Playlist… / Playlist File… chooser at the pointer), **Save Playlist…** ⌥⌘S
  - `static func sortEntries(_ state:)` and `miscOptionsEntries(_ state:)`: what SORT LIST and MISC OPTIONS pop up (today's titles: "Sort List by Title", … are renamed to the menu bar's, so the two read the same).
  - `static func command(forSprite: String) -> PlaylistCommand?`: the skinned entries (`PLAYLIST_ADD_FILE` → `.addFile`, …, `PLAYLIST_NEW_LIST` and `PLAYLIST_REMOVE_ALL` → `.clearPlaylist`). `PLAYLIST_SORT_LIST` and `PLAYLIST_MISC_OPTIONS` are pop-ups, not commands (nil, handled by the view as today); `PLAYLIST_REMOVE_MISC` stays a no-op, as now.
- Enabled rules (an item is disabled only where it would do nothing and say nothing; refusals that post a notice keep their notice for the skinned entries):
  - Remove Selected, Crop: `hasSelection`. Clear Playlist, Select All/None/Invert, Generate HTML: `hasRows`.
  - Sort ×3, Reverse, Randomize: `hasRows && !isRemote` (#0145; `PlaylistContextMenus.sort` already pops them disabled on a remote queue).
  - Add URL: `canAddURL`. File Info…: `hasFileInfo`. Save: `canSave`. Load: `canLoad`.
  - Add File…, Add Folder…: always (the speaker refusal is a notice, #0084).

**Shortcuts** (Winamp's playlist keys, Ctrl → ⌘, where they don't collide). Taken already: ⌘O ⌥⌘O ⇧⌘O ⌘S (File), ⌘K ⌘] ⌘[ ⇧⌘R (Skins), ⌘L ⌘J ⌃⌘Z/X/C/V/B/S/R/L ⌃⌘arrows (Playback), ⌘1 ⌘2 ⌘3 ⌃⌘W/E/P (Window), ⌘A (Edit › Select All, which reaches the track list as first responder), ⌘N (Library's New Playlist), ⌘⌫ (Library's delete playlist), ⇧⌘3/4/5 (system screenshots), bare Z X C V B S R L J Q, Delete, Return.
- Winamp Ctrl+Shift+1/2/3 sort → **⌥⌘1/2/3** (⇧⌘3 is the system screenshot).
- Ctrl+R reverse → **⌘R**; Ctrl+Shift+R randomize → **⌥⌘R** (⇧⌘R is Random Skin).
- Ctrl+I invert → **⇧⌘I**; File Info (Winamp Alt+3) → **⌘I**, the Mac's Get Info key.
- Select None → **⇧⌘A** (the Mac's Deselect All).
- Ctrl+O / Ctrl+S load/save → **⌥⌘L / ⌥⌘S** (⌘O and ⌘S are File's).
- No shortcut: Add File… (File › Add to Playlist… keeps ⌥⌘O; one key, one item), Add Folder…, Add URL… (Ctrl+L is ⌘L, the Library), Remove Selected (Delete in the list), Crop, Clear Playlist (destructive, no undo; ⌘⌫ variants would fire while typing in the Library's search field), Select All (⌘A stays Edit's), Generate HTML Playlist.

### 2. App

- `App/PlayerModel+PlaylistMenu.swift` (new): `var playlistMenuState: PlaylistMenuState` and `func perform(_ command: PlaylistCommand)`, one exhaustive switch moved out of `PlaylistMenusView.run(_:)` (`addFile` → `openFiles(replace: false)`, `addFolder` → `openFolder()`, `addURL` → the radio sheet via `openWindowAction?(id: "library")` instead of the view's `openWindow`, `clearPlaylist` → `playlist.removeAll()`, `loadPlaylist` → `loadList()`, `savePlaylist` → `saveQueue()`, `fileInfo` → `showFileInfo(for:)`, `generateHTML` → `generateHTMLPlaylist()`, sorts → `playlist.sort…`).
- `App/Playlist/PlaylistMenuBuilder.swift` (new, like `MainMenuBuilder`): `[PlaylistMenuEntry]` → `NSMenu` (`autoenablesItems = false`, `isEnabled` and key equivalent from the item; in a pop-up the key equivalent is display only). `PlaylistContextMenus.sort` and `.miscOptions` build through it; keep `popUpOverride` working (pass titles and enabled state) so `PlaylistMenusTests` keeps its seam.
- `PlaylistMenusView.run(_:)`: `PlaylistMenu.command(forSprite:)` → `model.perform(_:)`; SORT and MISC OPTIONS pop the builder's menus. A skinned sprite can't be drawn disabled, so a disabled command run from the skin does what it does today (nothing, or its notice).
- `App/PlaylistCommands.swift` (new, beside `PlaybackCommands`): `CommandMenu("Playlist")`, a view of its own (`PlaylistMenuItems`, so it re-evaluates on observed state as `PlaybackMenuItems` does) that draws `menuBarEntries(model.playlistMenuState)` as `Button`s with `.keyboardShortcut` from the item and `.disabled(!isEnabled)`. Added in `RoadieApp` after `PlaybackCommands`, so the order is … Skins, Playback, Playlist, Window, Help.
- `playlistMenuState` reads observed properties only (`playlist.tracks`, `selection`, `remote`, `library.sections`, `selectedOutput`, `thisMacFeed`, capabilities), so the menu bar's enabled states follow without a refresh.
- The menu bar works with the playlist window closed (it acts on the shown queue, as Save Queue as Playlist… does). File Info… with the editor closed opens the panel as the main window's I does.
- VoiceOver reads the menu bar as is; that is the accessible path for these commands (#0203's finding that the skinned SORT/MISC pop-ups aren't in the tree stays as is).

## Tests

Fast, swift-testing in SkinKit (`Packages/SkinKit/Tests/SkinKitTests/PlaylistMenuTests.swift`):
- `menuBarHasEveryCommandOnce`: every `PlaylistCommand` appears exactly once in `menuBarEntries`; groups in Add, Remove, Select, Misc, List order.
- `everySkinnedEntryMapsToACommand`: every sprite in `PlaylistLayout.menuEntries(_:)` for the five menus maps to a command, except `PLAYLIST_SORT_LIST`, `PLAYLIST_MISC_OPTIONS` (pop-ups) and `PLAYLIST_REMOVE_MISC` (no-op); New List and Remove All both map to `.clearPlaylist`.
- `enabledFollowsTheState`: empty queue → only Add ×3 (Add URL when `canAddURL`) and Load enabled; rows without selection → Remove Selected / Crop off; `isRemote` → sorts, Reverse, Randomize off; `canSave`/`canLoad`/`hasFileInfo` gate their items.
- `shortcutsAreUnique` and `shortcutsDontCollideWithTheMenuBar`: unique among themselves, and disjoint from every `MainMenu` shortcut plus the other menu bar shortcuts listed in §1 (⌘K, ⌘S, ⌘L, ⌘J, ⌘A, ⌘N, ⌘⌫, ⌃⌘ arrows, ⌃⌘L, ⇧⌘3/4/5).
