## Description

`PlaylistFile.resolve` returns `.skip(reason: "nested playlist")` for an entry that is itself a playlist, and `LocalTrackLoader.expandPlaylists` reports it as skipped. Winamp expands a playlist entry that points at another `.m3u`/`.m3u8`/`.pls` in place.

Expected:

- A nested playlist entry is expanded at its position, with its own relative paths resolved against its own folder.
- Cycles (A lists B lists A, or A lists itself) and excessive depth (say more than 8 levels) stop with a skip reason instead of looping.
- Tests with playlist files written to a temp folder in the test: one level, two levels, a cycle, self-reference, missing nested file.

## Plan

Two files of code, two test files. No app changes: the app only calls `LocalTrackLoader.load`, and nothing outside AudioCore and its tests calls `PlaylistFile.resolve`.

**1. `Packages/PlayerKit/Sources/AudioCore/PlaylistFile.swift`, `resolve(_:relativeTo:)`**

- Delete line 86 (`if isPlaylist(url) { return .skip(location: location, reason: "nested playlist") }`). `resolve` now returns `.file(url)` for a playlist entry too; it stays a pure path resolver. Expansion is the loader's job.
- Change nothing else in this file. #0101 and #0102 edit `parse`/`decode` here next.

**2. `Packages/PlayerKit/Sources/AudioCore/LocalTrackLoader.swift`, `expandPlaylists`**

- Add `private static let maxPlaylistDepth = 8` next to `maxConcurrent`.
- Keep the top-level loop in `expandPlaylists`. For an explicitly given playlist (same guard as today: `PlaylistFile.isPlaylist(url) && !isDirectory(url)`), call a new nested function `expand(_ playlist: URL, depth: Int, ancestors: Set<String>)` with `depth: 1, ancestors: []`. Declare it inside `expandPlaylists`, after `skip`, so it can append to `result` and call `skip`.
- `expand` does this, in order:
  1. `let key = playlist.standardizedFileURL.resolvingSymlinksInPath().path`. If `ancestors.contains(key)`, call `skip(playlist, "playlist cycle")` and return. This covers self-reference too.
  2. If `depth > maxPlaylistDepth`, call `skip(playlist, "playlists nested too deeply")` and return.
  3. Read the data. On failure, call `skip(playlist, "could not read playlist")` (unchanged reason; a missing nested file lands here) and return.
  4. Run format, parse and the log line as today.
  5. For each entry, switch on `PlaylistFile.resolve(entry, relativeTo: playlist)`:
     - `.file(let file)` where `PlaylistFile.isPlaylist(file) && !isDirectory(file)`: recurse with `expand(file, depth: depth + 1, ancestors: ancestors.union([key]))`.
     - any other `.file(let file)`: `result.append(file)`.
     - `.skip`: as today, with the URL built against `playlist`'s folder.
- Order: the ancestors check goes before the depth check, and both go before the read, so a cycle never reads a file twice.
- Ancestors follow only the current chain, so a diamond (A lists B and C, both list D) expands D twice, as Winamp does. That isn't a cycle.
- Update the doc comment: entries that are playlists are expanded in place, relative to their own folder, up to 8 levels; cycles, deeper nesting, streams and unreadable playlists are reported as skipped.
- Keep all per-entry handling inside `expand` in one `switch`. #0101 will change `result` to carry each entry's title and duration, and it should only have to touch that switch.

No deviations.
