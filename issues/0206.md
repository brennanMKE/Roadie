## Description

Every 0.0.4 bug the user hit was on Music Assistant: the row index (#0187), playlists that couldn't be played (#0189), LIST › Load with no way to a server playlist (#0190). Nothing drives the app against a Music Assistant server. This issue adds `MusicAssistantUITests` over the scripted server (#0197): connecting at launch, browsing, playing on This Mac and a speaker, the remote queue in the editor, the three regressions, playlists, favorites, discover, radio, the output picker, now-playing events and quit. Rows: [docs/design/test-automation.md](../docs/design/test-automation.md) §5.7 (Music Assistant parts), §5.10, and the Music Assistant rows of §5.5–§5.6.

## Root cause

Not an app bug. The Music Assistant flows had no UI tests, and the first attempt bailed after three runs at 18 of 19 (see Notes). The remaining failure, `testOutputPicker` ("the Output popover lacks 4K Apple TV"), was a fixture artefact. `scripts/record-ma-fixtures.py`'s `scrub` rewrites every `display_name` to "user", so every player in `players-all.json` reads `display_name: "user"` beside its real `name`. `OutputDevice(ma:)` (`MAMapping.swift`) shows a non-empty `display_name` over `name`, which matches the live server, where `display_name` is the player's user-facing name. Through the scripted server, then, every Output row and the toolbar's `library.output` label read "user".

## Gotchas

- **The Output popover's subtree is missing from the accessibility dump.** In run 20261029-225156-6686 the failure dump lists the popover under `library.output` as `Disabled` with no children. Queries still find its rows: "This Mac", "Speakers", the Living Room checkbox and the `Only` buttons all resolved, and the test passes. So the rows are reachable, but `describe(popover)` shows nothing to debug from. The row's `library.output.<id>` identifier sits on its `HStack` and doesn't reach the Toggle or the Only button. Written up in [docs/ui-tests-in-vm.md](../docs/ui-tests-in-vm.md#gotchas-when-writing-ui-tests). No app issue; a by-hand VoiceOver check would be the trigger to file one.
- **Settings' `ma.reason` can't show a refused token.** `ma.reason` is the server ranking's reason, and `MusicAssistantServerRanking.Outcome` covers reachability only (no token outcome). The refusal shows in the Library ("The music source rejected the sign-in."), so the test is `testBadTokenShowsTheRefusalInTheLibrary`.
- The recorder's `display_name` scrub hits players as well as users. Any future scripted flow that shows a player's name needs the override above, or a recorder change that keeps players' `display_name`.
