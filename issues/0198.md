## Description

Third-party skins are never committed (`.gitignore`: `*.wsz`, `Skins/`), and the Tart guest has no network, so the UI tests need a host-side cache of real skins that the VM run carries in. This issue adds a committed manifest of seven Museum skins (name, Museum id, md5, why), a host-only fetch script that downloads them by md5 from the Winamp Skin Museum into a cache and verifies them, and the `run-tests-vm.sh` wiring that copies the cache into the export. The selection and its reasons are in [docs/design/test-automation.md](../docs/design/test-automation.md) §4; every md5 there was verified by download on 2026-10-24.

### 2. Fetch script (`scripts/fetch-test-skins.sh`, new; host only)

zsh, modelled on `scripts/fetch-webamp-references.sh`. `scripts/fetch-test-skins.sh [--cache DIR] [--check] [--manifest FILE]`:

- Cache default `~/Library/Caches/co.sstools.roadie-test-skins` (outside the repo, like `make-screenshots.sh`'s music cache). `--check` only reports `ok|missing|bad-md5` per row and exits 1 if anything isn't `ok`; it never downloads.
- Per row: if the file exists and `md5 -q` matches, `ok (cached)`. Else POST `{"query":"{ fetch_skin_by_md5(md5: \"<md5>\") { download_url filename(normalize_extension: true, include_museum_id: true) nsfw } }"}` to `https://skins.webamp.org/graphql` with `Content-Type: application/json` and the same User-Agent shape as `MuseumUserAgent.make` (`Roadie-tests/<version> (+https://roadie.sstools.co)`), read `download_url` with `python3 -I -c` (no jq on a stock Mac), fall back to `https://r2.webampskins.org/skins/<md5>.wsz` if the GraphQL call fails, `curl -fsSL --retry 2` to `<name>.wsz.part`, verify the md5, rename. Refuse a skin whose `nsfw` is `true` (none are). Sleep 1 s between downloads.
- Prints one line per skin and a summary; exits 1 on any failure. Never touches the repo; `--cache` may point into `build/` (gitignored).
- Header comment: host only; the Museum is one person's hobby infrastructure, so one request per skin and never a re-download.

### 3. VM wiring (`scripts/run-tests-vm.sh`)

- `--test-skins DIR` (default: the cache path above). Only `--ui` (#0200) consumes it; this issue adds the option, the preflight (`scripts/fetch-test-skins.sh --check --cache DIR` must pass, else `fail "test skins missing: run scripts/fetch-test-skins.sh"`) and the copy into `$EXPORT/src/TestSkins/` plus `test-skins.tsv`. When `--ui` is not given, the option is accepted and ignored (so #0200 needs no further plumbing). Log `Copied N test skins from DIR into the export`.
- The existing `--skins` (sample skins for `skintool`) is unchanged.

### 4. Python test (`scripts/tests/test_fetch_test_skins.py`, new)

The script's logic that is worth testing is manifest parsing and md5 checking; a shell script is awkward to unit-test, so put the manifest reader in a 60-line `scripts/test_skins.py` (`-I`, stdlib) that the shell script calls for `parse` and `check`, and test that: `test_parse_manifest_rows`, `test_check_reports_missing_and_bad_md5` (temp dir with one good, one wrong, one absent file), `test_rejects_bad_md5_format`. Run by the `release-tools` step's pattern (widen to `test_*.py` if #0196 hasn't).

### 5. Docs

`docs/testing-in-vm.md`: a "Test skins" paragraph under the UI tests section (fetch once on the host; `--check`; the cache path). `docs/winamp-skin-museum-access.md`: one line that `fetch-test-skins.sh` is a consumer of `fetch_skin_by_md5`.
