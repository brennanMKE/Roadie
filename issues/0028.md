## Description

Build the skinned EQ window from `eqmain`/`eq_ex` sprites, wired to AudioCore's `AVAudioUnitEQ`, including presets and on/auto toggles.

## Acceptance criteria

- Slider sprites and the EQ graph match Webamp.
- Changes apply during playback without glitches.

## Plan

### Scope and decisions

A second skinned window, hosted the way #0025 hosts the main window, drawing the `EQMAIN` sprites at Webamp's positions and driving `Player.eq` (`EQState`: ten gains, preamp, on/off, already wired to `AVAudioUnitEQ` by M1). Status stays `open`; this plan writes no code.

Reference sources: Webamp at the planning scratchpad checkout (`/private/tmp/claude-501/-Users-brennan-Developer-brennanMKE-SkinAmp/5851b7d4-5135-49c1-ac3b-f5d40617c8c8/scratchpad/webamp-src/webamp`, `captbaritone/webamp@79117c66d`), paths below relative to `packages/webamp/`: `js/components/EqualizerWindow/{index,Band,EqGraph,EqOn,EqAuto,EqTitleButtons,PresetsContextMenu}.tsx`, `spline.js`, `js/components/VerticalSlider.tsx`, `js/actionCreators/equalizer.ts`, `js/reducers/equalizer.ts`, `js/media/index.ts` (282–296), `js/marqueeUtils.tsx` (30–45), `js/skinSprites.ts` (424–470, already ported to `SkinSprites.swift` `EQMAIN`/`EQ_EX`), `js/skinSelectors.ts` (154–214), `css/equalizer-window.css`, `presets/builtin.json`, and `packages/winamp-eqf/src/{parser,creator}.ts`. The checkout may be gone by implementation time; re-clone to `References/webamp` (gitignored, never staged) if a citation needs checking. Sample skins: `untitled folder/*.wsz` (19 skins; do not move the folder).

- **Geometry and value math live in SkinKit (`EQLayout`), the graph renderer too (`EQGraph`), both pure and tested headless.** The App target has no test bundle, so every number that can be wrong (origins, band frame rect, thumb travel, pointer mapping, snap, spline, graph pixels) is in SkinKit with Swift Testing tests, like `MainSliders` (#0023) and `VisRenderer` (#0024). `App/` keeps SwiftUI views, gestures and model wiring only.
- **EQ values do not go through `TransportCommand`.** `MusicBackendKit` is Foundation-only and must not know `EQState`; the command stream is asynchronous and one-way, while a band drag needs the graph updated synchronously on every pointer move and the window needs to read the value straight back (Webamp dispatches `SET_BAND_VALUE` and the media layer applies it at once). `PlayerModel` already holds `player` and reads `player.isShuffled`/`repeatMode` directly for the main window; the EQ writes `player.eq` the same way, on the main actor, and `Player.eq`'s setter pushes to the live `AVAudioUnitEQ` ("changes reach the engine immediately, also mid-playback", `Player.swift` 48–61; `EQTests.eqIsStoredAndReachesTheGraph`, `bandBoostAndCutChangeRenderedLevel`). That is the "no glitches" criterion: `AVAudioUnitEQ` band gains are AU parameters, ramped by the unit; no engine stop, no reconnect. For symmetry with the output abstraction, `LocalPlayerOutput` gains a pass-through `var eq: EQState` (one line each way) so a future folder backend or a test can reach it without the player; the app uses `player.eq` because that is what it already owns. **Remote outputs:** the EQ is a property of This Mac's DSP graph. With a remote output selected (`selectedOutput != thisMacID`) the window still edits and persists `player.eq` (it is ready when the output switches back) but nothing audible changes; the ON button stays usable. Documented in `## Gotchas`; an MA-side EQ is a later backend capability, not this issue.
- **Webamp's 0...100 slider scale is the UI value; dB is the stored value.** Webamp stores `sliders[band]` 0...100 (50 = 0 dB) and converts with `db = value/100 * 24 - 12` (`media/index.ts` 293–296). `EQState` stores dB (−12...12). `EQLayout.value(forGain:)` = `(gain + 12) / 24 * 100` and `gain(forValue:)` is the inverse; every sprite-frame and thumb rule below is written in Webamp's 0...100 so the citations hold. Snap: `_snapBandValue` zeroes `|value − 50| < 5` (`actionCreators/equalizer.ts` 4–15), i.e. `|gain| < 1.2 dB → 0`, applied to bands and preamp on every pointer move (so the thumb jumps to centre, as in Winamp) but not to preset values.
- **ON toggles `EQState.isEnabled`; AUTO draws but never turns on.** Webamp's `toggleEqAuto` always dispatches `false` ("We don't actually support this feature yet", `actionCreators/equalizer.ts` 63–69). Port that: AUTO shows `EQ_AUTO_BUTTON_DEPRESSED` while held and is never `_SELECTED`. No state, no persistence. Winamp's auto-preset-per-song is out of scope.
- **Presets: built-in list, plus `.eqf` load and save.** Decided in: the file format is 31 header bytes + 268 bytes per preset (`winamp-eqf/src/parser.ts`), the parser is ~40 lines and round-trips through `EQPreset.decibels(fromWinampValue:)`, which already exists for the built-ins. `EQFFile` goes in AudioCore next to `EQPreset`, with tests on synthesized bytes (no sample files copied). The menu mirrors `PresetsContextMenu.tsx`: **Load ▸** the 18 built-ins, separator, **From EQF…**; **Save…**. The built-in list comes from `EQPreset.builtIn` (its 17 Winamp presets match `builtin.json` name for name; "Flat" is ours, kept). Loading a preset sets gains and preamp and keeps `isEnabled` (`EQState.applying(_:)`); Webamp's `setEqFromObject` likewise only dispatches band values. Save writes one preset named `Entry1` (Webamp's `getEqfData`), default file name `entry.eqf`.
- **The graph is a literal port of `EqGraph.tsx`, including the preamp-line formula.** `drawEqLine` places `EQ_PREAMP_LINE` at `y = round(preamp/100 * 18)`, so preamp 100 (slider top, +12 dB) puts the line at the bottom row and 0 at the top, while the band curve uses `(100 − value)/100` (top = +12). That reads as inverted relative to the curve. The acceptance criterion is "match Webamp" and #0026 compares against Webamp renders, so port it as written and record it in `## Gotchas` with the one-line change (`1 − p`) if the user wants Winamp's direction. The curve uses the natural cubic spline from `spline.js` (Gaussian elimination, ported function for function so the rounded pixels agree).
- **Window hosting reuses #0025 by giving `SkinWindowController` a `kind`.** The controller is instantiated per window (#0025 planned this: "instantiated per window (main now; EQ and playlist in M5)"). A `SkinWindowKind` supplies the skin size, which `region.txt` section to mask with (`equalizer` / `equalizerws`), the frame-autosave name and the title-bar button holes. `SkinWindow`, `SkinShapeView`, `TitleBarDragView` and `TitleBarDragging` are reused unchanged. The EQ window is borderless, region-shaped (Sony and Pika ship `[Equalizer]` sections), key-capable, dragged by its 14-px title bar, closed by its skinned close button (hide, not quit), and reopened from the main window's EQ toggle, **Window › Equalizer** (⌘2) or by relaunch when it was open.
- **The main window's EQ toggle becomes the window's visibility.** #0023 left `PlayerModel.isEQWindowOpen` as a stored Boolean that "M5 replaces with the real window's visibility behind the same property name, so `MainWindowView` does not change". The Boolean stays the source of truth (Webamp's `windows.genWindows.equalizer.open`, flipped by `TOGGLE_WINDOW` from the main button and `CLOSE_WINDOW` from the EQ close button); `AppDelegate` observes it and orders the EQ window in or out, and the controller's `windowWillClose` writes it back to `false`. It is persisted (`eqWindowOpen`), so the EQ comes back after relaunch like Winamp.
- **Persistence of EQ settings is this issue's.** `EQState` is `Codable`; `PlayerModel` stores it as JSON in `UserDefaults` under `equalizer` on every change (in-memory write, flushed by the system) and applies it to `player.eq` in `init` before anything plays. #0030 ("positions, queue and EQ settings persist") finds EQ settings already done and only needs to move the key into its state file if it introduces one; window frames use `setFrameAutosaveName("EqualizerWindow")` until #0030 replaces autosave with its own positions, exactly as `MainWindow` does today.
- **Marquee text while a band is held.** Webamp shows "EQ: 60HZ +3.4 DB" / "EQ: Preamp -2 DB" in the main window while a band is dragged (`selectors.ts` 655–661, `marqueeUtils.getEqText`). `PlayerModel.SliderFocus` gains `.equalizer(band: Int?)` (nil = preamp) and `MarqueeText.equalizer(bandHz:gain:)` formats it; the main window's marquee override path from #0023 carries it.
- **Band drags cross bands.** Webamp lets a drag that started in the band strip move other bands when the pointer enters them (`clickOriginatedInEq`, `requireClicksOriginateLocally`, `VerticalSlider.handlePointerEnter`). Port: one `DragGesture` over the whole band strip, and `EQLayout.bandIndex(atX:)` picks the band whose 18-px column the pointer is in (nearest column in the 4-px gaps); the preamp has its own gesture and never joins a strip drag, as in Webamp (`band !== "preamp"`).
- **Verification is `scripts/run-tests-vm.sh --launch --skins "untitled folder"` only.** No `swift test`, `xcodebuild` or app launch on the host. Tests are silent: `EQFFile`, `EQLayout` and `EQGraph` are pure; the one `Player` test does not start the engine.

### 2. SkinKit: `EQGraph` and `CubicSpline` (`Packages/SkinKit/Sources/SkinKit/Display/EQGraph.swift`, `Display/CubicSpline.swift`, new)

```swift
/// Port of Webamp's EqualizerWindow/spline.js (natural cubic spline, Gaussian elimination). Webamp is MIT; see NOTICE.
enum CubicSpline {
    /// y for every integer x in 0...xs.last, given knots (xs strictly increasing, xs[0] == 0).
    static func interpolate(xs: [Double], ys: [Double]) -> [Double]
}

/// Port of EqGraph.tsx drawEqLine: the 113×19 graph for ten band values and a preamp value (Webamp 0...100).
public enum EQGraph {
    public static let size = CGSize(width: 113, height: 19)
    public static let bandSpacingX = 12          // "Each band is 12 pixels wide"
    public static let paddingLeft = 2
    /// y of each band knot: round((100 − v) / 100 * 18)  (percentToRange(percent, 0, 18)).
    public static func knotY(forValue value: Double) -> Int
    /// Preamp line row: round(p / 100 * 18). Webamp's formula verbatim (see Gotchas: reads inverted vs. the curve).
    public static func preampLineY(forValue value: Double) -> Int
    /// The 109 curve rows (x 0...108) after the spline, each clamped 0...18, as drawEqLine computes them.
    public static func curve(values: [Double]) -> [Int]
    /// Composites background + preamp line + curve from the skin's EQ_GRAPH_* / EQ_PREAMP_LINE sprites.
    /// nil when the skin has no EQ_GRAPH_LINE_COLORS (Webamp draws nothing then).
    public static func render(skin: Skin, values: [Double], preamp: Double) -> CGImage?
}
```

`render` draws into a 113×19 `CGContext` (device RGB, premultiplied alpha, top-left origin, no antialiasing): `EQ_GRAPH_BACKGROUND` at (0,0) if present (a 294-row sheet lacks it: draw the curve over transparent); `EQ_PREAMP_LINE` (113×1) at `preampLineY` if present; then for x in 0...108 with `lastY = knotY(values[0])`: `y = curve[x]`, fill the 1-px column from `min(y, lastY)` with height `1 + |lastY − y|` at `paddingLeft + x`, `lastY = y`. Colour of each pixel row r is pixel (0, r) of `EQ_GRAPH_LINE_COLORS` (Webamp's `createPattern(…, "repeat-x")` anchored at the canvas origin, so the colour depends only on the row). Read the 19 colours once per render through `TestBitmaps.pixel`-style sampling of the cropped sprite (a `CGContext.draw` into a 1×19 buffer). Scale is the view's business: the view draws the `CGImage` with `.interpolation(.none)` like `VisualizerView`.

### 3. AudioCore: `EQFFile` (`Packages/PlayerKit/Sources/AudioCore/EQ/EQFFile.swift`, new) and `EQPreset` (+1)

```swift
/// Winamp .eqf / .q1 preset files. Port of winamp-eqf (parser.ts, creator.ts): header "Winamp EQ library file v1.1",
/// <ctrl-z>, "!--", then per preset a 257-byte NUL-padded name and 11 bytes (hz60…hz16000, preamp) stored as 64 − value.
public enum EQFFile {
    public static let header = "Winamp EQ library file v1.1"
    public enum ParseError: Error, Equatable { case invalidHeader, truncated }
    /// Every preset in the file, in order. Names are Windows-1252, decoded lossily to String.
    public static func parse(_ data: Data) throws -> [EQPreset]
    /// One or more presets; names longer than 256 bytes are cut.
    public static func serialize(_ presets: [EQPreset]) -> Data
}

extension EQPreset {
    /// Inverse of decibels(fromWinampValue:): 33 + round(db · 31/12) above 0 dB, 33 + round(db · 32/12) below; 1...64.
    public static func winampValue(fromDecibels db: Float) -> Int
}
```

Parse: header mismatch → `.invalidHeader`; after the 31 header bytes, each preset needs 268 bytes, else `.truncated` (Webamp reads past the end as `undefined`; we refuse). Values: `64 − byte` → `decibels(fromWinampValue:)` (which clamps to 1...64). Because `decibels` rounds to 0.1 dB and the two slopes are 12/31 and 12/32 dB per step (0.39 / 0.375), the inverse recovers every one of the 64 steps exactly; a test proves it.

`LocalPlayerOutput.swift` (+5 lines): `public var eq: EQState { get { player.eq } set { player.eq = newValue } }`.
