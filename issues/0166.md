## Description

M14 work item W15 from [docs/design/release.md](../docs/design/release.md). Depends on: W7 and the user's key generation.

## Expected behavior

`SU_PUBLIC_ED_KEY` in `project.yml`; Release Info.plist has it; `preflight --credentials-only` key check passes.

## Relation

- Parent: [#0151](0151.md)

## Fix

- Generated the EdDSA key with `build/sparkle/bin/generate_keys --account Roadie` (private half in the login keychain only); set `ROADIE_PUBLIC_ED_KEY` for Release in project.yml. Debug stays empty, so Debug builds keep the updater off.
- preflight.sh read the first `ROADIE_PUBLIC_ED_KEY:` in project.yml, which is Debug's empty one, so it reported the key missing even when set. It now reads the Release config's value; the test fixture gained an empty Debug block to cover it.

## Verification

`scripts/preflight.sh --release 0.0.1`: `PASS sparkle: keychain key matches project.yml`. `scripts/verify.sh --head --launch --dmg` PASS, 16 steps; Release Info.plist carries the key. (The first run failed `app-quicklook` on a Spotlight content-type timing check unrelated to the change; the rerun passed.)
