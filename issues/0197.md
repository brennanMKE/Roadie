# 0197 — The Music Assistant stub can't act as a server for the running app

| | |
|---|---|
| **Status** | open |
| **Module** | MusicAssistantKit |
| **Platform** | macOS |
| **First seen** | 2026-10-24 |

## Description

`MusicAssistantKitStub` replays recorded frames per command (`FixtureScript`), which is right for a unit test of one call. A UI test drives the whole app: it plays an album, expects the queue to show up in the playlist editor, double-clicks row 3, and expects the server to have received `play_index 3` and the row to become current. That needs a stub with state: queues that change when commands arrive, and pushed events that tell the client. This issue adds `ScriptedMusicAssistant`, a small in-memory server built on the recorded fixtures, with named scenarios, used by `RoadieConfiguration.musicAssistant = .scripted(...)` (#0194). Design: [docs/design/test-automation.md](../docs/design/test-automation.md) §2.2.

## Plan

### 1. `ScriptedMusicAssistant` (`Packages/PlayerKit/Sources/MusicAssistantKitStub/ScriptedMusicAssistant.swift`, new)

An `actor`-free, `OSAllocatedUnfairLock`-guarded class (like `StubWebSocketTransport`) that owns:

- **Library** from the recorded fixtures: artists, albums, tracks, playlists, radios, recommendations (`*-page`, `*-count`, `artist-albums`, `album-tracks`, `playlist-tracks`, `search`, `item-by-uri`), answered as `FixtureScript.recorded(token:)` does today. Reuse `recorded(token:)` as the base script and add routes in front.
- **Players** from `players-all` (or `players-all-sendspin` when the scenario says This Mac is a Sendspin player) with mutable `playback_state`, `volume_level`, `current_media`.
- **Queues**: one per player, `items: [QueueItem]` (each the recorded `media_item` shape; `index` **always 0** in what is sent, matching the quirk), `current_index`, `state`, `elapsed_time`, `repeat_mode`, `shuffle_enabled`.
- **Commands it applies** (everything the app sends; grep `client.call(` in `MusicAssistantBackend*.swift` for the list): `player_queues/items` (paged by `offset`/`limit`), `player_queues/get`, `player_queues/all`, `player_queues/get_active_queue`, `player_queues/play_index` (int or `queue_item_id` string), `player_queues/play_media` (`replace`/`next`/`add`/`replace_next`; expands an album/playlist/artist URI to its recorded tracks), `player_queues/move_item`, `player_queues/delete_item`, `player_queues/clear`, `player_queues/shuffle`, `player_queues/repeat`, `players/cmd/play|pause|play_pause|stop|next|previous|seek|volume_set|volume_mute`, `players/cmd/set_members`, `music/favorites/add_item|remove_item`, `music/playlists/create_playlist|add_playlist_tracks|remove_playlist_tracks|update` (on an in-memory copy), `music/library/remove_item`. Unknown commands fall through to the recorded unknown-command error.
- **Events**: after each state change it pushes `player_updated`, `queue_updated` and `queue_items_updated` frames with the envelope from `docs/ma-protocol-notes.md` (and `events-queue.json` when #0196 has recorded it) through `StubWebSocketTransport.push`. Elapsed time advances with an injected clock (`ContinuousClock` in the app, a manual clock in tests).
- **Scenarios** (`enum Scenario: String`): `libraryIdle` (recorded, nothing playing), `queueLoaded` (the recorded loaded queue when `MAFixture.playerQueueItemsLoaded.isRecorded`, else 12 synthetic rows built from `tracks-page.json` with `index: 0`, current index 2, playing on `ap223aed81fe30`), `playingOnSpeaker` (`SyntheticPlayback`), `thisMacIsASendspinPlayer` (`players-all-sendspin`), `unreachable` (`connectError`), `badToken`.
- **Introspection** for tests and the probe: `receivedCommands: [SentRequest]`, `queue(for:)`, `reset(to:)`.
- `static func transportFactory(scenario:) -> any MAWebSocketTransportFactory` returning a factory whose every transport talks to the one shared server instance (reconnects keep state), plus the matching `MAHTTPTransport` stub for `/info` and artwork (`StubHTTPTransport` exists).

### 2. Wire it (`App/RoadieConfiguration.swift`, #0194's `.scripted(scenario:)`)

`PlayerModel` keeps a reference to the server (`scriptedMusicAssistant`) so `testProbe()` (#0199) can report `maRequests` (the last 20 commands with their key arguments: `play_index index=3`).

### 3. Docs

`docs/ma-protocol-notes.md`: a short "Scripted server" paragraph naming the scenarios and the rule that its replies are recorded shapes with state applied, never new shapes.

## Tests

`Packages/PlayerKit/Tests/MusicAssistantKitTests/ScriptedMusicAssistantTests.swift`, through `MusicAssistantBackend` as the app uses it (`connectedBackend(script:)` helper, adapted to the factory):

- `queueLoadedRowsHaveIndexZeroAndPositionsFromPaging`: `MAQueueWatch` over the scripted queue gives positions `0..<n` and `isCurrent` at the scenario's current index.
- `playIndexMovesTheCurrentRowAndPushesAnEvent`: `backend.edit(.play(index: 3), on: speaker)`; the next `queue_updated` event has `current_index == 3`; `receivedCommands.last?.command == "player_queues/play_index"` with `index == 3`.
- `playMediaReplaceExpandsAnAlbum`: `play([album], mode: .replace())` → the queue holds the album's recorded tracks, current 0, state playing; `.next` inserts after current; `.append` appends.
- `deleteAndMoveUpdateTheQueue`: delete item 1, move item 3 to 1; rows and a `queue_items_updated` push follow.
- `transportCommandsChangeThePlayerState`: pause → `playback_state == "paused"` in the next `player_updated`; `volume_set 40`.
- `favoritesAndPlaylistsAreApplied`: add a favorite, create a playlist and add tracks; the library answers show them.
- `unreachableScenarioFailsToConnect`, `badTokenScenarioReturnsTheRecordedAuthError`.
- `repliesKeepRecordedShapes`: every reply the server builds decodes with the same `MA*` models the real fixtures do (`MAQueueItem`, `MAPlayer`, `MAPlayerQueue`), no `try?`.

Expect list: `queueLoadedRowsHaveIndexZeroAndPositionsFromPaging,playIndexMovesTheCurrentRowAndPushesAnEvent,playMediaReplaceExpandsAnAlbum,deleteAndMoveUpdateTheQueue,transportCommandsChangeThePlayerState,favoritesAndPlaylistsAreApplied,unreachableScenarioFailsToConnect,badTokenScenarioReturnsTheRecordedAuthError,repliesKeepRecordedShapes`

## Which tier

**Fast:** `scripts/verify.sh --expect <list above>`. `MusicAssistantKitStub` is a package target; no AudioCore.

## UI tests

## By hand

`open -a Roadie --args -RoadieUITest 1 -RoadieDataDir /tmp/roadie-test -RoadieMAScenario queueLoaded -RoadieNoDiscovery 1 -firstRunVersion 1 -playlistWindowOpen 1`: the playlist editor shows the scenario's rows with row 3 current; double-click row 5 → row 5 becomes current and the marquee shows its title; press Delete on a row → it goes; ⌘L › Albums › double-click an album → the queue is replaced.
