## Description

Install a tap on the mixer that feeds a `vDSP` FFT (spectrum bands) and raw samples (oscilloscope) to the UI at 30–60 Hz.

## Acceptance criteria

- No allocation or locking on the audio thread.
- Exposes 75 spectrum columns and an oscilloscope buffer sized for the 76x16 vis area.
- Unit test feeds a sine wave and checks the peak lands in the right band.

## Plan

### Data flow

```
mainMixerNode tap (non-realtime AVAudioEngine thread; treat as realtime: no alloc, no locks)
  │  mono-mix L+R with vDSP into a preallocated scratch pointer
  ▼
VisSampleRing (preallocated Float ring, atomic write counter)      ← producer side
  │  consumer copies the newest fftSize samples on its own tick
  ▼
SpectrumAnalyzer.analyze(window) → 75 columns (0…1) + 76 scope samples (−1…1)   (runs on the consumer thread, ~10 µs)
  ▼
VisFrame  →  [VisSmoother in #0024]  →  drawn at 30–60 Hz
```

The FFT runs on the **consumer** (UI) tick, not in the tap. Reason: the tap's `bufferSize` is only a request — macOS may deliver 1024 or 4096+ frames per callback — so "one FFT per callback" would pin the visual rate to the callback rate (4096 frames at 44.1 kHz = 10.7 Hz). Analyzing the freshest window at display rate decouples the two. A 1024-point real FFT is microseconds of work on main.

### Where the tap goes

- Node: `engine.mainMixerNode`, bus 0 (post-EQ, so the visualizer reacts to EQ changes like Winamp). `AnalyzerTap.install(on: AVAudioNode, bus: 0)` takes any node so switching is a one-liner.
- `node.installTap(onBus: 0, bufferSize: 1024, format: nil)` — `format: nil` means the node's output format: Float32, **non-interleaved** (`buffer.floatChannelData![c]` is one contiguous pointer per channel), sample rate = output device rate (commonly 44 100 or 48 000; read it from `node.outputFormat(forBus: 0).sampleRate` at install time and pass it to the analyzer so the column map matches).
- Install **after** the graph is connected and `engine.prepare()` has run (before that `outputFormat` can report 0 Hz; guard `sampleRate > 0`, otherwise defer install until the engine starts). `installTap` raises an ObjC exception if a tap is already on that bus — keep an `isInstalled` flag and call `removeTap(onBus:)` first.
- Re-install (remove + install) on `.AVAudioEngineConfigurationChange` (device switch can change the sample rate → rebuild the column map on the main thread, never in the tap). Coordinate with #0002, which owns engine restart on that notification.
- Caveat: a tap on the mixer's output sees the signal **after** `outputVolume`, so turning volume down shrinks the visualizer. Winamp's vis is volume-independent. If that matters, pass `eq` (the EQ node's output, same format) to `install(on:)` instead. Default to the mixer per the issue; note the alternative in `## Fix`.

### Tap block: realtime-safety rules

The AVAudioNode tap runs on a non-realtime thread, but the acceptance criterion still forbids allocation and locking there. The block must:

- Capture **only** the `AnalyzerTap` instance (a `final class`, `@unchecked Sendable`, holding raw pointers). Do not capture the player, arrays, or anything actor-isolated. Never let `AVAudioPCMBuffer` escape the block.
- Do no Swift `Array`/`String` work, no closures, no `print`/`os_log`, no `DispatchQueue`, no `Task`, no `NotificationCenter`.
- Steps, all into buffers allocated once in `init` (`UnsafeMutablePointer<Float>.allocate`, freed in `deinit`):
  1. `guard let ch = buffer.floatChannelData else { return }`; `n = Int(buffer.frameLength)`; `channels = Int(buffer.format.channelCount)`.
  2. If `n > ringCapacity`, use only the last `ringCapacity` frames (offset each channel pointer by `n − ringCapacity`).
  3. Mono mix into `scratch` (capacity `ringCapacity`): stereo → `vDSP_vadd(ch[0],1, ch[1],1, scratch,1, n)` then `vDSP_vsmul(scratch,1, &half, scratch,1, n)`; mono → `memcpy`; more channels → add the first two (fine for v1).
  4. `ring.write(scratch, count: n)`.

### `VisSampleRing` — single-producer / single-consumer, lock-free

```swift
public final class VisSampleRing: @unchecked Sendable {
    public init(capacity: Int)                       // power of two (default 16 384 ≈ 370 ms @ 44.1 kHz); index = count & (capacity − 1)
    // Producer (tap thread) only:
    public func write(_ samples: UnsafePointer<Float>, count: Int)   // ≤ 2 memcpys for wraparound, then writeCount.store(old + count, .releasing)
    // Consumer (one thread, e.g. main) only:
    public var writeCount: Int                       // writeCount.load(.acquiring); monotonic total samples written
    @discardableResult
    public func copyLatest(count: Int, into: UnsafeMutablePointer<Float>) -> Bool
}
```

`copyLatest`: `let end = writeCount.load(.acquiring)`; if `end < count` return `false`; copy ring `[end − count, end)` (two memcpys on wrap); then re-load `writeCount` — if the producer advanced by more than `capacity − count` during the copy the region may have been overwritten (torn read): return `false` and let the caller reuse its previous frame. This makes the hand-off rigorous rather than "fast enough in practice". Only one atomic word is ever shared.

**Atomics:** the deployment target is macOS 14, so `Synchronization.Atomic` (macOS 15+) is unavailable. Add `apple/swift-atomics` (`.package(url: "https://github.com/apple/swift-atomics.git", from: "1.2.0")`, product `Atomics`) and use `ManagedAtomic<Int>` with `.releasing` / `.acquiring` orderings. Fallback if the dependency is unwanted: a tiny C target wrapping `stdatomic.h` — more fiddly; prefer swift-atomics.

### `SpectrumColumnMap` — bins → 75 columns

Pure, `Sendable`, built once per sample rate (allocates; never built in the tap).

```swift
public struct SpectrumColumnMap: Sendable {
    public init(fftSize: Int, sampleRate: Double, columnCount: Int = 75, lowHz: Double = 40, highHz: Double = 16_000)
    public let ranges: [Range<Int>]                  // one per column, each non-empty, lowerBounds non-decreasing
    public func bin(forFrequency hz: Double) -> Int  // Int((hz / sampleRate * fftSize).rounded())
    public func frequencyRange(ofColumn c: Int) -> ClosedRange<Double>
}
```

- Edges: geometric spacing `edgeHz[c] = lowHz * (highHz/lowHz)^(c / columnCount)` for `c = 0…75`, `highHz` clamped to `sampleRate/2 − binWidth`. Convert to bins `e[c] = max(1, round(edgeHz[c] / binWidth))` (skip bin 0 = DC). Column `c` covers `e[c] ..< max(e[c] + 1, e[c+1])`.
- At 1024 points / 44.1 kHz the bin width is 43 Hz, so the lowest ~12 columns share bins 1–2 and overlap; that is expected and resembles Winamp's fat low end. (2048 points halves this at the cost of a 46 ms window; keep `fftSize` a parameter, default 1024.)
- Per-column value = **sum of power** over the column's bins (band energy; wide high columns get a fair share with music). `max` is a one-line alternative — mention in `## Fix` if chosen.

### `SpectrumAnalyzer` — pure, allocation-free per call

```swift
public final class SpectrumAnalyzer {   // owns vDSP setup + scratch; not Sendable; single owner
    public init(fftSize: Int = 1024, sampleRate: Double, columnCount: Int = 75,
                scopeLength: Int = 76, scopeStride: Int = 8, floorDB: Float = -60)
    public let columnMap: SpectrumColumnMap
    /// samples.count == fftSize. Writes columnCount values (0…1) and scopeLength values (−1…1). No allocation.
    public func analyze(_ samples: UnsafeBufferPointer<Float>,
                        spectrum: UnsafeMutableBufferPointer<Float>,
                        scope: UnsafeMutableBufferPointer<Float>)
    public func analyze(_ samples: [Float]) -> VisFrame        // convenience for tests
}
```

FFT with the Accelerate C API (well documented, allocation-free per call; `log2n = 10` for 1024):

1. Once in `init`: `setup = vDSP_create_fftsetup(log2n, FFTRadix(kFFTRadix2))`; `window` via `vDSP_hann_window(window, N, Int32(vDSP_HANN_DENORM))` (standard Hann, peak 1.0, coherent gain 0.5); allocate `windowed[N]`, `realp[N/2]`, `imagp[N/2]`, `power[N/2]`, `dB[N/2]`. `deinit`: `vDSP_destroy_fftsetup`.
2. Per call: `vDSP_vmul(samples, 1, window, 1, windowed, 1, N)`.
3. Pack real → split complex: `windowed.withMemoryRebound(to: DSPComplex.self, capacity: N/2) { vDSP_ctoz($0, 2, &split, 1, N/2) }`.
4. `vDSP_fft_zrip(setup, &split, 1, log2n, FFTDirection(FFT_FORWARD))`; set `split.imagp[0] = 0` (drops the packed Nyquist term; bin 0 is ignored anyway).
5. `vDSP_zvmags(&split, 1, power, 1, N/2)` → |X|² per bin.
6. Normalization: `zrip` output is 2× the DFT, and a full-scale sine (amplitude 1) under a Hann window has |DFT| = N·0.5/2 = N/4, so |X| = N/2. Per column: `vDSP_sve` over the column's `power` bins → `p`; `dB = 10·log10(p / (N/2)² + 1e-12)` (or `vDSP_vdbcon` on the column sums with `ref = (N/2)²`, flag 0 = power). Then `value = clamp((dB − floorDB) / −floorDB, 0, 1)`. A full-scale bin-centered sine reads ≈ 1.0 (allow ±1 dB in tests; calibrate empirically rather than trusting the arithmetic).
7. Oscilloscope: the newest `scopeLength × scopeStride` samples (76 × 8 = 608 ≈ 14 ms at 44.1 kHz — tune `scopeStride` by eye against Webamp in #0024), picking every `scopeStride`-th sample (`cblas_scopy` with a stride, or a 76-iteration loop) from the **unwindowed** input tail; clamp to −1…1. Not trigger-aligned (Winamp's isn't either).

### `VisFrame`

```swift
public struct VisFrame: Sendable, Equatable {
    public static let columnCount = 75
    public static let scopeLength = 76
    public var spectrum: [Float]   // 75 values, 0 = floor (−60 dB), 1 = 0 dBFS
    public var scope: [Float]      // 76 values, −1…1; UI maps to rows 0…15 (e.g. row = 7 − round(v·7))
    public var sampleCount: Int    // ring writeCount at capture; unchanged since last frame ⇒ no new audio (draw decay/floor)
}
```

### `AnalyzerTap` — the piece that touches AVFoundation

```swift
public final class AnalyzerTap: @unchecked Sendable {
    public init(fftSize: Int = 1024, ringCapacity: Int = 16_384)
    public private(set) var isInstalled: Bool
    public func install(on node: AVAudioNode, bus: AVAudioNodeBus = 0)   // call from the engine owner's thread; builds SpectrumAnalyzer for node.outputFormat(forBus:).sampleRate
    public func remove()
    /// Consumer side: call from ONE thread (main). Cheap; safe to call at 60 Hz. nil until ≥ fftSize samples have flowed.
    public func latestFrame() -> VisFrame?
}
```

`latestFrame()`: `ring.copyLatest(count: fftSize, into: window)`; on `false` return the cached previous frame; else `analyzer.analyze(window, spectrum:, scope:)` into preallocated output pointers, then build and cache a `VisFrame` (allocating the two small arrays on the consumer thread is fine).

Hookup in #0002's player (one place): `public let analyzer = AnalyzerTap()`; after connecting the graph and `engine.prepare()`: `analyzer.install(on: engine.mainMixerNode)`; in `deinit`/engine teardown: `analyzer.remove()`; on configuration change: `remove()` then `install(on:)` again. While paused/stopped with the engine running, the mixer renders silence and frames decay to the floor naturally; when the engine is stopped, `sampleCount` stops advancing and the UI should treat the frame as silence.

### `VisSmoother` — falloff and peaks (pure, applied by the UI, not the tap)

Winamp's bars drop at a fixed rate per frame and peak markers hold then fall. That is display-rate animation, so it belongs on the consumer side; ship it here as a pure type so #0024 only draws and it is unit-testable:

```swift
public struct VisSmoother {
    public var barFallPerSecond: Float = 3.0     // in 0…1 units (full height in ~0.33 s); tune in #0024
    public var peakHoldSeconds: Double = 0.5
    public var peakFallPerSecond: Float = 1.5
    public private(set) var bars: [Float]        // 75
    public private(set) var peaks: [Float]       // 75
    public mutating func step(_ frame: VisFrame, dt: Double)   // bars = max(new, bars − fall·dt); peak logic
}
```

### How the UI pulls frames (for #0024; document in `## Fix`, do not build the view here)

On the main thread, a display link (`NSView.displayLink(target:selector:)`, macOS 14+) or a `Timer` at 1/60 s calls `player.analyzer.latestFrame()`, feeds `VisSmoother.step(frame, dt:)`, and redraws the 76×16 area. If `frame.sampleCount` did not change since the last tick, step the smoother with a silent frame so bars decay. No subscriptions, no `@Published` at 60 Hz, no work on the audio side.

### Unit tests (Swift Testing, `Tests/AudioCoreTests`)

Use **48 000 Hz** and `fftSize = 1024` (bin width 46.875 Hz) so test tones sit exactly on bin centers: `f = k × 46.875`. Generate `samples[i] = amplitude × sin(2π f i / sr)` for 1024 samples. No engine, no audio device.

- `SpectrumColumnMapTests`
  - 75 ranges, each non-empty, `lowerBound`s non-decreasing, first range starts at bin ≥ 1, last range's `upperBound ≤ fftSize/2`.
  - `bin(forFrequency: 1500)` == 32 at 48 kHz/1024.
  - Map for 44 100 Hz differs from 48 000 Hz (sample rate is honored).
- `SpectrumAnalyzerTests`
  - **Sine lands in the right column:** for 1500 Hz (bin 32) at amplitude 1.0, `peak = spectrum.firstIndex(of: spectrum.max()!)`; assert `columnMap.ranges[peak].contains(32)` (equivalently `frequencyRange(ofColumn: peak)` contains 1500 Hz). This oracle is independent of how ties between overlapping low columns resolve.
  - **Ordering:** peaks for 93.75 Hz (bin 2), 1500 Hz (bin 32) and 12 000 Hz (bin 256) are strictly increasing, and the 1500 Hz peak falls in the middle of the range (e.g. columns 25…55).
  - **Level:** full-scale sine → peak column ≥ 0.9 (≈ 0 dBFS within 1 dB → `(60 − 1)/60`); amplitude 0.1 (−20 dBFS) → peak column ≈ 0.667 ± 0.03.
  - **Silence:** all-zero input → every column == 0 and every scope sample == 0.
  - **Scope:** a DC-free sine yields 76 values in −1…1 with max ≈ amplitude; a constant 0.5 input yields all 0.5.
  - **Shape:** `spectrum.count == 75`, `scope.count == 76`, for both 1024 and 2048 `fftSize`.
- `VisSampleRingTests`
  - Write 3 000 samples in chunks of 100/1024/4096 (values = running index), `copyLatest(1024)` returns the last 1024 in order across wraparound; `copyLatest` returns `false` before 1024 samples exist; a single write larger than capacity keeps only the tail; `writeCount` equals total samples written.
- `VisSmootherTests` (small): a bar never rises slower than the input and never falls faster than `barFallPerSecond·dt`; peak holds for `peakHoldSeconds` then falls.

### Risks and decisions to flag in `## Fix`

1. **#0002 naming/ordering.** Names above are assumptions; adapt. If #0002 is absent, land the package skeleton and the analyzer without the hookup and say so.
2. **Tap buffer size is a request, not a guarantee.** macOS may deliver 4096+ frames; the consumer-side FFT keeps the display rate independent, but fresh audio then arrives in ~93 ms bursts, so motion may look chunky. If so, next step is a lagging read cursor in `latestFrame()` (advance a consumer position by `elapsed × sampleRate`, staying ≥ one callback behind `writeCount`) — note the observed `frameLength` in `## Gotchas`.
3. **swift-atomics dependency** (macOS 14 blocks `Synchronization.Atomic`). Pin `from: "1.2.0"`; it must resolve offline-free in `swift test` and in the Xcode build via `project.yml`.
4. **Volume-dependent vis** when tapping the mixer (see "Where the tap goes"); the EQ-node tap is the Winamp-faithful alternative.
5. **Configuration change / double install.** `installTap` on a bus that already has one throws an ObjC exception that Swift cannot catch — guard with `isInstalled`. Sample rate can change on device switch; rebuild the analyzer on the engine owner's thread.
6. **Swift 6 strict concurrency.** The tap block must be `@Sendable`-clean: capture only the `@unchecked Sendable` tap; `AVAudioPCMBuffer` is not `Sendable` and must not escape. Mark `latestFrame()` `nonisolated`; document the one-consumer-thread rule.
7. **Test flakiness from spectral leakage.** Use bin-centered frequencies and the "peak column's range contains the bin" oracle; assert levels with tolerances, never exact floats.
8. **Calibration.** The N/2 normalization is derived, not measured; verify with the full-scale sine test and adjust the reference if it is off by a constant factor (e.g. 2×).
9. **No engine in unit tests.** Do not add a test that needs an output device; an `AVAudioEngine` manual-rendering test is optional and must be skipped when it cannot run.
