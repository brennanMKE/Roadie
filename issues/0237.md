# 0237 — The visualization can't go full screen

| | |
|---|---|
| **Status** | open |
| **Module** | App |
| **Platform** | macOS |
| **First seen** | 2026-10-29 |

## Description

MilkDrop was mostly watched full screen: Alt+Enter or a double-click switched, Escape came back. The user's request is about full screen mode first. After #0235 the visualization window is windowed only (its `collectionBehavior` already allows full screen, but nothing in Roadie asks for it, and Esc does nothing).

Design: [docs/design/visualization.md](../docs/design/visualization.md) §1.2, §2.3, §8.3.

## Plan

### Spike first (in the guest)

Before writing the UI test, find out whether native full screen completes in the headless Tart guest: a throwaway test (not committed) that opens the vis window, sends ⌃⌘F and waits 5 s for the probe's `fullScreen` to turn true, with a screenshot attachment. Record the result in `## Verification` and, if it fails, in docs/ui-tests-in-vm.md's gotchas. Then:

- **Native works:** the UI tests use it; no borderless path.
- **Native doesn't complete:** add the Debug-only hook `-RoadieVisFullScreen borderless`: `toggleFullScreen` then turns the window into a borderless, screen-sized window at `.mainMenu + 1` level (saving and restoring its frame and style mask) instead of entering a Space; everything else (overlay, keys, Esc, probe) is the same code. The UI test uses the hook; the native transition is a by-hand step. Release never has the hook.

### Toggling

- `VisualizationWindowController.toggleFullScreen()`: native `window.toggleFullScreen(nil)` (or the borderless path above). Probe `fullScreen` from `windowDidEnterFullScreen` / `windowDidExitFullScreen` (and the borderless equivalents), via `VisualizationModel.isFullScreen`.
- Ways in: ⌥Return (#0234's `toggleFullScreen` command; wire it in `VisualizationModel.perform`), double-click on the host view (`mouseDown` with `clickCount == 2`; single clicks do nothing), ⌃⌘F and the green button (AppKit's own, because of `.fullScreenPrimary`; the Window menu's "Enter Full Screen" item appears while the vis window is key), and the right-click menu's Enter/Exit Full Screen item (enabled now).
- **Esc** (`escape` command): closes help, then the preset list (both from later issues; check their flags if present), else leaves full screen if in it, else nothing.
- Entering full screen: the window keeps its preset and renderer; the display link follows the new screen (the view's own `displayLink`); #0238 shows the overlay on entry.
- Leaving full screen restores the windowed frame (AppKit does; the borderless path restores the saved frame).
- Closing the window while full screen (⇧⌘K): exit first, then close, so the Space doesn't linger; reopening comes back windowed.
- Launch never restores full screen (the window opens windowed even if it was full screen at quit): don't let AppKit restore it (`isRestorable = false`).

### Docs

- `docs/design/test-automation.md` §5.12 row: "Full screen: ⌥Return, double-click, ⌃⌘F; Esc leaves; windowed again at launch (#0237)" → UI `VisualizationUITests.testOptionReturnTogglesFullScreen`, `.testEscapeLeavesFullScreen`, `.testDoubleClickTogglesFullScreen`; Unit `RoadieTests.VisualizationFullScreenTests`; *by hand* for the native Space transition if the borderless hook was needed.

## By hand

1. Open the visualization, ⌥Return: it fills the screen in its own Space; the picture keeps going without a hitch. Esc: back to the window, same size and place.
2. Double-click the picture: full screen; double-click again: back. ⌃⌘F and the green button do the same.
3. With two displays: drag the window to the second display, ⌥Return: full screen there, the player stays on the first.
4. ⇧⌘K while full screen: it leaves full screen and closes; ⇧⌘K reopens windowed.
5. Quit while full screen, relaunch: it reopens windowed.
