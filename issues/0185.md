# 0185 — The skinned menu has no Media Library item, and the Library doesn't open on its search field

| | |
|---|---|
| **Status** | open |
| **Module** | App / SkinKit |
| **Platform** | macOS |
| **First seen** | 2026-10-23 |

## Description

Phase C of M15. In Winamp 5 the Media Library was one menu item away from the main window. In Roadie the skinned windows' pop-up menu (`MainMenu`: right-click on the main window, or the options button) has Equalizer and Playlist Editor, but no Library. The Library exists only in the menu bar (Playback › Library ⌘L and Window › Library, #0115). When the Library does open, the cursor isn't in its search field, so you can't just start typing.

This issue:

- Adds a **Media Library** item, ⌘L, to the pop-up's window group, checked while the Library window is open.
- Makes ⌘L, from the menu bar or the pop-up, bring the Library forward with its search field focused.

**Corrections and decisions:**

- The spec says the main menu has no Library item. That's true only of the skinned pop-up: the menu bar already has ⌘L. So the pop-up reuses ⌘L (`MainMenuShortcut` must match the menu bar's).
- Umbrella decision 3: the item opens the Library or brings it forward, and doesn't close it, the same as the existing ⌘L. The check mark shows when it's open.
- No bare-key binding: bare `L` is already Open File. A key, if any, is decided after #0174 row 4 (Winamp 5 is thought to use Alt+L).
- `searchFocused` needs macOS 15, and the target is 14.0, so focusing uses AppKit's `NSSearchToolbarItem.beginSearchInteraction()` (macOS 11+).
- `PlayerModel` runs the pop-up's commands and has no SwiftUI `OpenWindowAction`. It captures one from `PlayerView`, which already reads `@Environment(\.openWindow)`.

## Plan

### 1. Menu data (`Packages/SkinKit/Sources/SkinKit/Menus/MainMenu.swift`)

- `MainMenuCommand`: add `case toggleLibraryWindow`. The name follows the Equalizer and Playlist Editor siblings; the behaviour is open-or-front.
- `MainMenuState`: add `public var isLibraryWindowOpen: Bool`, with an init parameter defaulting to `false` placed after `isPlaylistWindowOpen`. Keep the existing callers compiling: all of them use labels.
- `entries`: after Playlist Editor, add `.item(MainMenuItem(.toggleLibraryWindow, "Media Library", checked: state.isLibraryWindowOpen, shortcut: MainMenuShortcut("l")))`.

### 2. App model (`App/PlayerModel.swift`, `App/PlayerModel+MainMenu.swift`)

- `PlayerModel`: add `@ObservationIgnored var openWindowAction: OpenWindowAction?`. This needs `import SwiftUI`; check the file's imports.
- Add:
  ```swift
  /// The Library window (a SwiftUI `Window` scene, id "library"), when it exists.
  var libraryWindow: NSWindow? {
      NSApp.windows.first { $0.identifier?.rawValue.hasPrefix("library") == true }
  }
  /// Opens or brings forward the Library and puts the cursor in its search field (#0185).
  func showLibrary(focusSearch: Bool = true)
  ```
  The identifier prefix test is the same one `AppDelegate.applicationDidFinishLaunching` uses.
- `showLibrary`:
  - If `libraryWindow` is visible, `makeKeyAndOrderFront(nil)`.
  - Otherwise `openWindowAction?(id: "library")` and `NSApp.activate()`.
  - Then, if `focusSearch`, call `focusLibrarySearch(attempts: 10)`.
- `focusLibrarySearch` runs on the main actor in a `Task` that retries every 50 ms, because the window and toolbar may not exist yet right after `openWindow`:
  - Find `libraryWindow?.toolbar?.items.compactMap { $0 as? NSSearchToolbarItem }.first`, then `item.beginSearchInteraction()`.
  - Fallback: if there's no `NSSearchToolbarItem` (SwiftUI may host its own), search the toolbar items' `view` hierarchy for an `NSSearchField` and `window.makeFirstResponder(field)`.
  - Give up after `attempts` tries.
- `mainMenuState`: `isLibraryWindowOpen: libraryWindow?.isVisible ?? false`.
- `perform(_ command:)`: `case .toggleLibraryWindow: showLibrary()`.

### 3. Capture `openWindow` (`App/PlayerView.swift`)

On the root view, add `.onAppear { model.openWindowAction = openWindow }`. It already has `@Environment(\.openWindow) private var openWindow`; check the model's environment name there. The main window always exists, so the action is set before any menu can be used.

### 4. Menu bar ⌘L (`App/RoadieApp.swift`, `App/PlaybackCommands.swift`)

- `OpenLibraryWindowButton`: add `var model: PlayerModel?`.
  - When `model` is set (the Playback menu's ⌘L button), the action is `model.showLibrary()`.
  - Otherwise it keeps `openWindow(id: "library")` (the Window menu entry, without focus).
  - Pass `model` from `PlaybackCommands`.
- The other `openWindow(id: "library")` callers don't change: `PlaylistMenusView` Add URL (it opens Radio), and `WelcomeView`.

Under `### Added`: "Media Library in the skinned windows' menu (⌘L); the Library opens with the cursor in its search field."

### By hand

1. Right-click the main window: "Media Library ⌘L" sits under Playlist Editor, with no check while the Library is closed.
2. Choose it: the Library opens with the cursor in its search field, and typing searches at once. Choose it again while it's behind other windows: it comes forward, focused.
3. With the Library open, the item is checked.
4. ⌘L from the menu bar while a skinned window is key: the same, with the search field focused. Window › Library still just opens it.
5. A Library opened from Add URL (Radio) still lands on the Radio section and isn't forced to search.
6. First launch with the Library never opened: the item still works (`openWindowAction` was set by the main window).
