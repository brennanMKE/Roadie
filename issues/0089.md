# 0089 — Music Assistant tracks cannot play through this Mac over HTTP

| | |
|---|---|
| **Status** | open |
| **Module** | MusicAssistantKit / AudioCore / App |
| **Platform** | macOS |
| **First seen** | 2026-10-19 |

## Description

Browsing works and #0064 plays Music Assistant music on its speakers, but nothing plays it through the Mac, so the EQ, balance and visualizer never apply to it. #0066 plans that through Sendspin (no Swift SDK, technical preview, 16-bit). A smaller path may exist: fetch a track's audio from the Music Assistant server over HTTP and feed it to the existing progressive player (`ProgressiveByteSource` / `TrackResolver`, which streams Plex tracks today and which #0074 keeps generic).

This first needs a check that Music Assistant offers a per-track audio URL a client can fetch (its stream server listens on 8097; the web UI has a preview feature), what it requires (auth, player registration), and what format it returns. Read-only probes of the user's server are allowed with `scripts/record-ma-fixtures.py`-style tooling; never print the host, server id or token.

Expected: with This Mac selected and Music Assistant as the source, playing a library track plays it through the Mac's output path with the EQ and analyzer working, gapless where the format allows. If no such endpoint exists, record that in this issue and close the path in favour of #0066.

Unblocks #0074 (removing direct Plex support), which is on hold until Music Assistant can play through the Mac.
