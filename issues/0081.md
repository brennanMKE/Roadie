# 0081 — Playlist Sort, File Info and Misc Options menu entries do nothing

| | |
|---|---|
| **Status** | open |
| **Module** | App |
| **Platform** | macOS |
| **First seen** | 2026-10-18 |

## Description

In the playlist window's MISC menu, the Sort List, File Info and Misc Options entries highlight and close but do nothing (`App/Playlist/PlaylistWindowView.swift`, `run(_:)`, `default: break`). Add URL in the ADD menu does the same, and Add Dir opens the same panel as Add File.

Expected, as in Winamp: Sort List offers sort by title, by file name and by path, reverse list and randomize list. File Info shows the selected track's tags and format details. Misc Options offers at least "Generate HTML playlist" alternatives SkinAmp can support, or is reduced to what applies. Add Dir opens a folder-only panel. Add URL is out of scope while there's no stream support; leave it a no-op and say so in the code comment.

## Plan

### Scope (corrected)

The MISC and ADD menus' dead entries, with Webamp as the reference and Winamp 2 for what Webamp leaves out:

- **Sort List** pops a native menu at the pointer, as Winamp and Webamp do: *Sort List by Title*, *Sort List by File Name*, *Sort List by Path and File Name*, a separator, *Reverse List*, *Randomize List*. Webamp has only the title sort plus reverse and randomize; Winamp 2 adds the two file sorts, and both are cheap here.
- **File Info** shows the info view #0079 adds, for the first selected row, or the current track when nothing is selected. With an empty list it does nothing.
- **Misc Options** pops a native menu with one entry, *Generate HTML Playlist*, which is everything Webamp's misc-options menu has. Winamp 2's other two entries don't apply, so they're dropped: *Read extended info on selection* (SkinAmp already reads tags on import, in `LocalTrackLoader.loadTrack`) and *Playlist preferences* (SkinAmp has no playlist preferences). Generate HTML Playlist writes Winamp's "Winamp Generated PlayList" page (track count, average and total length, numbered `artist - title (m:ss)` list, HTML-escaped) to `FileManager.default.temporaryDirectory/SkinAmp Playlist.html` and opens it with `NSWorkspace.shared.open`, like Winamp (which opens it in the browser and doesn't save it). It never touches the queue.
- **Add Dir** opens a folders-only panel and appends what it finds.
- **Add URL** stays a no-op, with a code comment saying why: SkinAmp has no stream support yet.
- **Out of scope:** the LIST menu (Save/Load List is #0082), Winamp's playlist keyboard shortcuts (Ctrl+Shift+1/2/3, Ctrl+R, Ctrl+Shift+R, Alt+3), and a remote output's queue (`MusicBackend` has no queue API; each action is guarded by `isLocal()` like the other edits).

### Approach

**AudioCore: reordering the queue** (`Packages/PlayerKit/Sources/AudioCore/PlayQueue.swift`)

- Add `@discardableResult public mutating func reorder(_ newOrder: [Int]) -> Bool`, where `newOrder[newPosition] = oldIndex`. It returns false and does nothing unless `newOrder` is a permutation of `tracks.indices` that differs from the identity. It shares `move(_:by:)`'s remapping: build `newPosition`, then remap `tracks`, `currentIndex`, `shuffleOrder` and `nextPass`. The current track keeps its identity, and a shuffled pass keeps the same play order over the new indices. Refactor `move` to finish through the same private helper so the bookkeeping lives in one place.
- Add `public mutating func sort(by key: (Track) -> String) -> Bool`, a stable sort that compares with `localizedStandardCompare` (Finder order: "track 2" before "track 10"; Winamp is case-insensitive too). Swift's `sort` isn't guaranteed stable, so sort `(key, index)` pairs and break ties on the index.
- Add `reverse() -> Bool` and `randomize<G: RandomNumberGenerator>(using: inout G) -> Bool`, plus a `randomize()` overload that uses `SystemRandomNumberGenerator`, the same pattern as `setShuffle`. Randomize permutes the list itself and is separate from shuffle mode (Winamp's Randomize List changes the order; Shuffle changes play order).
- Add `public enum PlaylistSortKey` (new file `Packages/PlayerKit/Sources/AudioCore/PlaylistSortKey.swift`) with `static func fileName(_ track: Track) -> String` (`url.lastPathComponent`) and `static func path(_ track: Track) -> String` (`url.path`). A track that isn't a `.file` (Plex) falls back to its `title`, so it still sorts somewhere sensible. The title sort's key comes from the app (below) because the row text is `PlaylistText.displayName` in SkinKit, and AudioCore doesn't depend on SkinKit.

**AudioCore: Player** (`Packages/PlayerKit/Sources/AudioCore/Player.swift`)

- Add `sortQueue(by:)`, `reverseQueue()` and `randomizeQueue()`, next to `moveTracks`: each one calls the queue method and, when it returns true, calls `reconcileSchedule()`, because the gapless pre-scheduled next file may now be the wrong one. Playback never stops or restarts, and `currentTime` is untouched. `QueueAutosaver` already watches `player.queue`, so the new order is saved without extra code.

**SkinKit: HTML playlist text** (new file `Packages/SkinKit/Sources/SkinKit/Display/PlaylistHTML.swift`)

- `public enum PlaylistHTML { public static func document(entries: [Entry]) -> String }`, where `Entry` is `(name: String, duration: TimeInterval?)` (the name already run through `PlaylistText.displayName`). It's pure string building next to `PlaylistText`, so it's testable headless: escape `& < > " '`, count tracks, compute the average and total over the known durations, and write `m:ss` with `PlaylistText.time`. Webamp's `getPlaylistHtml` (`js/playlistHtml.tsx`) is the reference for the wording and layout; plain inline CSS only, no scripts.

**App** (`App/Playlist/PlaylistModel.swift`, `App/Playlist/PlaylistWindowView.swift`, `App/PlayerModel.swift`, new `App/Playlist/PlaylistContextMenus.swift`)

- `PlaylistModel`: add `sortByTitle()` (key `PlaylistText.displayName(artist:title:fileName:)`, the same text as the row), `sortByFileName()`, `sortByPath()`, `reverse()` and `randomize()`, each guarded by `isLocal()` and forwarding to `Player`. Selection is keyed by track id (`PlaylistSelection`), so it follows the rows with no pruning. Add `var fileInfoTrack: Track?` (first selected by index, else current, else nil) and `var htmlEntries: [PlaylistHTML.Entry]`. Factor the duplicated `fileName` extraction in `rows` and `shadeTrackName` into one private helper, since the title sort needs it too.
- `PlaylistContextMenus.swift`: a small `@MainActor` builder for an `NSMenu` whose items run closures (an `NSMenuItem` subclass holding a `() -> Void`, with itself as target). If #0078 has already added a closure-based menu helper for the options menu, reuse it and skip this file. Present it with `menu.popUp(positioning: nil, at: NSEvent.mouseLocation, in: nil)` (screen coordinates), after the skinned menu has closed (`playlist.openMenu = nil` first, then pop up on the next main-actor turn so the SwiftUI tap finishes).
- `PlaylistMenusView.run(_:)`: `PLAYLIST_SORT_LIST` → sort menu; `PLAYLIST_FILE_INFO` → `model.showFileInfo(for:)` with `playlist.fileInfoTrack`; `PLAYLIST_MISC_OPTIONS` → misc menu → `model.generateHTMLPlaylist()`; `PLAYLIST_ADD_DIR` → `model.openFolder()`; `PLAYLIST_ADD_URL` → explicit no-op case with the comment. Leave the LIST entries as they are (`PLAYLIST_NEW_LIST` keeps clearing; save/load stay on `default: break` for #0082). Update the doc comment above `run(_:)`.
- `PlayerModel`: add `openFolder()` (an `NSOpenPanel` with `canChooseFiles = false`, `canChooseDirectories = true`, multiple selection, prompt "Add", then `importLocalFiles(panel.urls, replace: false)`). Add `generateHTMLPlaylist()`: write `PlaylistHTML.document` atomically as UTF-8 to the temp URL and open it; on failure post a `StatusNotice` and log it, no alert. File Info: #0079 adds the info view for the current track. If its entry point takes no argument, change it to `showFileInfo(for track: Track)`, with the clutter bar's I button passing `player.queue.current`, so both callers share one view. Don't build a second view. If #0079 hasn't landed when this is worked, bail per Issues.md rather than build a stand-in.

### Tests

Package level, in `Packages/PlayerKit/Tests/AudioCoreTests/PlayQueueTests.swift` (using `queue(_:)` / `makeTracks` from `TestSupport.swift`):

- `reorderRejectsNonPermutations`: wrong count, a duplicate, an out-of-range index or the identity returns false and leaves the queue unchanged.
- `sortByKeyIsStableAndFinderOrdered`: "t10" after "t2", case-insensitive, equal keys keep their relative order.
- `sortKeepsTheCurrentTrack`: same `current?.id` after sorting, and `currentIndex` points at it.
- `reverseReversesAndKeepsTheCurrentTrack`.
- `randomizeIsASeededPermutation`: with a seeded generator (add a small `SplitMix64: RandomNumberGenerator` to `TestSupport.swift` if none exists), the result is a permutation of the same ids, deterministic for the seed, and keeps the current track.
- `reorderWhileShuffledKeepsThePlayOrder`: shuffle on, record the ids `next()` would visit, sort, and get the same id sequence (`shuffleOrder` and `nextPass` stay permutations).
- `reorderUpdatesIndexAfterCurrentEnds`: after reverse, `indexAfterCurrentEnds()` names the track that now follows.
- The existing `move…` tests must still pass after the shared-helper refactor.

New `Packages/PlayerKit/Tests/AudioCoreTests/PlaylistSortKeyTests.swift`:

- `fileNameAndPathKeys`, and `nonFileTracksFallBackToTitle` (a `.plex` source).

`Packages/PlayerKit/Tests/AudioCoreTests/PlayerTests.swift`:

- `sortQueueKeepsStateAndCurrentTrack`: a stopped player with a restored queue (`restoreQueue`, no engine); after `sortQueue`, `reverseQueue` and `randomizeQueue`, `state` is unchanged, the current id is unchanged, and the order is as expected. It's offline and silent, with no real-time flag.

New `Packages/SkinKit/Tests/SkinKitTests/PlaylistHTMLTests.swift`:

- `escapesMarkup` (`<b>&"'` in a name), `countsAndTotals` (3 entries, one with unknown duration: count 3, total and average over the known ones), `emptyPlaylist` (renders, says 0 tracks, no divide by zero), and `numbersEntriesInOrder`.

There are no app-target tests (the app has no unit-test target). The menu wiring is checked by hand (below).

### Host checklist (for the user, after review)

1. Add a folder of tracks with ADD › Add Dir: the panel lets you pick only folders, and the tracks append.
2. ADD › Add URL highlights, closes and does nothing.
3. MISC › Sort List: a menu appears at the pointer. Each of the three sorts reorders the rows as expected, the playing track keeps playing (no gap or restart), its row stays highlighted as current, and the selected rows stay selected.
4. Reverse List flips the order. Randomize List mixes it up, and playback continues. With shuffle on, next/previous still behave.
5. Let a track end after a sort: the next track is the one now below it in the list (gapless schedule reconciled).
6. MISC › File Info with a row selected shows that track in #0079's info view. With nothing selected it shows the current track.
7. MISC › Misc Options › Generate HTML Playlist opens a page in the browser listing the tracks with durations and totals. A title containing `&` or `<` displays literally.
8. Quit and relaunch: the sorted order is restored.
9. With a remote output selected, the sort and randomize entries do nothing and nothing crashes.
