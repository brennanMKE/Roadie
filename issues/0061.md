## Description

## Acceptance criteria

- A connection actor over `URLSessionWebSocketTask` (`ws://<host>:8095/ws`): server-info handshake, `auth` with the token, `message_id` correlation with continuations, partial-result assembly, error mapping, a heartbeat, and auto-reconnect with backoff and re-auth.
- Server events as an `AsyncStream`.
- Codable, Sendable models for artist, album, track, playlist, player and queue, with `library://` URIs as identifiers.
- Library listing with paging, search, album tracks, playlist tracks, players and queues, as confirmed in #0060's notes.
- The token is never logged, put in a URL or written outside the Keychain; errors and descriptions never contain it.
- Unit tests against #0060's fixtures through a stubbed WebSocket (no real server). An opt-in integration test runs only when `MA_URL` and `MA_TOKEN` are set, and is skipped in the VM.

## Gotchas

- ATS: `URLSession` applies App Transport Security to `ws://`. `NSAllowsLocalNetworking` covers `.local` names and private IPs only; an `http://` server on a public DNS name or a Tailscale `100.x` address fails with -1022 (reported as `.transport(.appTransportSecurityRequiresSecureConnection)`). `--check-live` is Python and does not prove the app can connect. #0063/#0075 must add an `NSExceptionDomains` entry or `NSAllowsArbitraryLoads` and update `scripts/check-info-plist.sh`.
- `withThrowingTaskGroup` waits for cancelled children, so the stub's and the real transport's `receive()` are cancellation-aware (the real one closes the task on cancel), or the handshake timeout would hang.
- `Route(command:reply:)` is called with an explicit `reply:` label: with `matches` also a defaulted closure parameter, a trailing closure is ambiguous.
- The key-set checks in `--check-live` compare top-level keys of the first item only; they are the drift detector for the Swift decoders, which never see live bytes.
- The opt-in integration test exists and is skipped in the VM; the live evidence is `--check-live`.

## Plan

### Scope and decisions

This issue adds the Music Assistant client and its `MusicBackend` adapter as two new targets in `Packages/PlayerKit`, plus a stub target that replays #0060's recorded fixtures through a scripted WebSocket. It wires nothing into the app: no Settings (#0063/#0075), no `LibrarySource` in `PlayerModel.init` (#0063 prepends it), no remote transport or now-playing (#0064), no local playback (#0066), no Plex removal (#0074). Everything below is written against the recorded protocol in `docs/ma-protocol-notes.md` (MA 2.10.6, schema 65); where the notes say "unverified" (events, #0076; grouped players), the code decodes leniently and says so in a comment.

- **Three targets.** `MusicAssistantKit` (Foundation, Security, os, `MusicBackendKit`; never AudioCore, PlexKit, LocalPlayback or TrackCache), `MusicAssistantKitStub` (fixtures, scripted transports, in-memory token store; depends on `MusicAssistantKit`), `MusicAssistantKitTests`. Mirrors `PlexKit` / `PlexKitStub` / `PlexKitTests`, which #0074 will delete; nothing here imports them.
- **The transport is a seam, not `URLSessionWebSocketTask` itself.** The client actor talks to a `MAWebSocketTransport` protocol (connect, send text, receive frame, ping, close) made by a `MAWebSocketTransportFactory`; the real one wraps `URLSessionWebSocketTask`, the stub replays fixtures. HTTP (`GET /info`, the image proxy) goes through a one-method `MAHTTPTransport` the same way. No `URLProtocol` stub: #0074 deletes `PlexKitStub`'s, and a scripted transport is simpler to reason about for a stateful socket.
- **One client actor, typed requests as values.** `MusicAssistantClient` owns the socket, the handshake, auth, message ids, continuations, partial assembly, events, the heartbeat and reconnect. Commands are `MARequest` values (`command` + `args`) with static builders for every command the app needs now or in #0064; the builders are pure and encode-tested against the arg names in `docs/ma-protocol/commands.json`, so #0064 writes no protocol code, only backend methods over existing builders.
- **Identifiers are URIs.** `MediaID.rawValue` is the item's `uri` (`library://album/27`); `item_id` and `provider_instance_id_or_domain` for a command are parsed back out by a pure `MAURI`. `ArtworkRef.rawValue` is the image's `proxy_id`.
- **Paging.** `music/<kind>/library_items` plus `music/<kind>/count` with identical filters (the notes' trap: the recorded artist last page was empty because the count had no `album_artists_only`). The count is fetched with the first page (`offset == 0`) and cached per connection; later pages reuse it; a failed count gives `total: nil` and `Page.make` falls back to `items.count >= limit`.
- **Controller mode is #0064; the seam is here.** `outputs()` lists MA players as remote `OutputDevice`s now. `play`, `transport` and `nowPlaying(on:)` throw `.unsupported(.remoteOutputs)` / finish at once, and `capabilities` omits `.remoteOutputs` until #0064 implements them over the `MARequest` builders (`playMedia`, `playerCommand`, `seek`, `volumeSet`, ...) and the events stream. "This Mac" is #0066: no `.localOutput` either.
- **Probe for #0067 and #0075.** `MusicAssistantBackend.probe()` is `GET /info` (no socket, no token, no Keychain read) plus a `server_id` comparison when one is stored; `MusicAssistantClient.serverInfo(at:)` is the static form #0075's chooser calls per server. `connect()` repeats the id check on the WebSocket's first frame **before** sending `auth`, so a different server at a known address never receives the token.
- **Token rules.** `MusicAssistantToken` is modelled on `PlexToken` (redacted description, empty mirror, not `Codable`). It is read from a `MusicAssistantTokenStore` (Keychain; one item per server, keyed by an account string #0075 supplies) only inside `connect()`, held in the client actor for re-auth, sent only in the `auth` frame, and never put in a URL (the image proxy needs no header, per the probe), a log line, an error case or a description. The unit tests assert all of that against the stub's recorded outbound frames.
- **Verification is `scripts/run-tests-vm.sh --launch` for the Swift code and a host-side, read-only Python check for the live server.** The VM never gets `.env`; no `swift test`, `xcodebuild` or app launch on the host. The acceptance criterion's opt-in Swift integration test exists (self-skipping on `MA_URL`/`MA_TOKEN`) but under this project's rules it is never executed; the live evidence is `scripts/record-ma-fixtures.py --check-live` (section 9).

### 4. Transports

`MAWebSocketTransport.swift`:

```swift
public enum MAWebSocketFrame: Sendable, Hashable { case text(String), closed(code: Int?) }
public protocol MAWebSocketTransport: Sendable {
    func connect() async throws                 // the HTTP upgrade; throws MusicAssistantError.transport/handshakeFailed
    func send(_ text: String) async throws
    func receive() async throws -> MAWebSocketFrame   // server pings/pongs are answered inside, never surfaced
    func ping() async throws                    // resolves on the pong, throws on failure
    func close(code: Int) async
}
public protocol MAWebSocketTransportFactory: Sendable { func makeTransport(url: URL) -> any MAWebSocketTransport }
public struct URLSessionWebSocketTransportFactory: MAWebSocketTransportFactory { public init(session: URLSession = .shared) }
```

`URLSessionWebSocketTransport` (final class, `@unchecked Sendable` around the task): `connect()` builds `ws(s)://<host>:<port>/ws` from the http(s) base URL (scheme swap, path `/ws`), `session.webSocketTask(with:)`, `resume()`; the upgrade is confirmed by the first successful `receive()` (the server-info frame), and a failed upgrade surfaces from `receive()` as `URLError` → `.transport(code)`. `receive()` maps `.string` to `.text`, `.data` to `.text` (UTF-8), and a task error after a server close to `.closed(code: task.closeCode.rawValue)`. `ping()` is `sendPing(pongReceiveHandler:)` under a continuation. `close(code:)` is `cancel(with: .normalClosure, reason: nil)` (code 1000; the notes say the server accepts it). `URLSessionWebSocketTask` answers server pings itself (the notes: one server ping about every 25 s), so no code is needed for that.

`MAHTTPTransport.swift`: `protocol MAHTTPTransport: Sendable { func get(_ url: URL, headers: [String: String], timeout: Duration) async throws -> MAHTTPResponse }` with `MAHTTPResponse { status: Int; contentType: String?; body: Data }`; `URLSessionHTTPTransport` (ephemeral session, no redirects followed, `Accept: */*`). Only `/info` and `/imageproxy/...` are ever fetched; neither call passes a header with the token.

### 5. `MusicAssistantClient` (actor)

```swift
public actor MusicAssistantClient {
    public enum ConnectionState: Hashable, Sendable {
        case disconnected, connecting, authenticating, connected, reconnecting(attempt: Int), failed(MusicAssistantError)
    }
    public static let supportedSchemaVersion = 65   // what the models were recorded against
    public static let minimumSchemaVersion = 28     // the first schema with auth

    public init(baseURL: URL,
                transports: any MAWebSocketTransportFactory = URLSessionWebSocketTransportFactory(),
                http: any MAHTTPTransport = URLSessionHTTPTransport(),
                clock: any Clock<Duration> = ContinuousClock(),
                pingInterval: Duration = .seconds(25), pongTimeout: Duration = .seconds(10),
                callTimeout: Duration = .seconds(15), reconnect: ReconnectPolicy = .default)

    /// `GET /info`, no token, no socket. #0075's reachability check and `MusicAssistantBackend.probe()`.
    public static func serverInfo(at baseURL: URL, http: any MAHTTPTransport = URLSessionHTTPTransport(),
                                  timeout: Duration = .seconds(5)) async throws -> MAServerInfo

    public private(set) var state: ConnectionState
    public private(set) var serverInfo: MAServerInfo?
    public func states() -> AsyncStream<ConnectionState>        // current value first
    public func events() -> AsyncStream<MAServerEvent>          // pushed frames only; bufferingNewest(64)

    /// Handshake + auth. Checks `expectedServerID` against the first frame BEFORE the token leaves the process.
    @discardableResult
    public func connect(token: MusicAssistantToken, expectedServerID: String? = nil) async throws -> MAServerInfo
    public func disconnect() async                               // close 1000, drop the token, stop reconnecting
    public func call(_ request: MARequest, timeout: Duration? = nil) async throws -> MAJSON
    public func call<T: Decodable & Sendable>(_ request: MARequest, as: T.Type, timeout: Duration? = nil) async throws -> T
    // Tests
    public var pendingCallCount: Int
    public var connectionCount: Int                              // transports created so far
}
```

Behaviour, each rule pinned by a test in section 10:

- **Handshake.** `connect` → state `.connecting`; `transports.makeTransport(url)`, `transport.connect()`, first `receive()` must parse as `.serverInfo` within `callTimeout` else `.handshakeFailed`. Then, in order: `info.minSupportedSchemaVersion <= supportedSchemaVersion && info.schemaVersion >= minimumSchemaVersion` else `.schemaUnsupported` (close, no auth); `expectedServerID == nil || expectedServerID == info.serverID` else `.serverMismatch` (close, no auth). Only then state `.authenticating` and the `auth` frame `{"message_id": "1", "command": "auth", "args": {"token": …}}`. Result `authenticated: true` → `.connected`, `serverInfo` set, the reader and ping loops start. Error 23 → `.tokenRejected`; 20 → `.unauthenticated`; any other error frame → `.server`; the socket is closed on every failure and the token is not retained.
- **Message ids** are a per-connection counter sent as strings (`"1"`, `"2"`, …), `auth` always `"1"`, matching the fixtures. A reconnect restarts the counter.
- **Correlation.** `call` registers a `CheckedContinuation` plus an accumulator under its id, sends, and waits with a timeout (`callTimeout`, or the request's own: `playlistTracks` uses 60 s) through `clock`; on timeout the entry is removed and `.timeout(command:)` thrown (a late frame for an unknown id is dropped at `debug`). Cancellation removes the entry (`withTaskCancellationHandler`) and throws `CancellationError`.
- **Partial assembly.** Frames with the same id: an array `result` is appended to the accumulator; a non-array, non-null result replaces it; `null` never overwrites an accumulated value. The frame with `partial == false` completes the call (its `result` is folded in first: the recorded final frame was `[]`, but it may carry the remainder). An error frame completes with the error.
- **Reader loop.** One task per connection: `receive()` until `.closed` or a thrown error; `.result`/`.error` → the pending entry; `.event` → every `events()` continuation; `.serverInfo` after auth and `.unknown` → dropped. On exit: every pending call fails with `.disconnected`; then the reconnect path unless `disconnect()` was called.
- **Heartbeat.** While `.connected`, every `pingInterval` the ping loop calls `transport.ping()` bounded by `pongTimeout`; a failure or timeout closes the transport and enters the reconnect path. No application-level heartbeat message exists (the notes).
- **Reconnect.** `ReconnectPolicy { steps: [1, 2, 4, 8, 16] s, cap: 30 s, jitter: 0.2 }` (pure, `delay(attempt:using: inout RandomNumberGenerator)`; tests pass `jitter: 0`). State `.reconnecting(attempt: n)`, sleep through `clock`, then the handshake + `auth` with the retained token. Transport and handshake failures retry forever (the server is simply down); `.tokenRejected`, `.unauthenticated`, `.schemaUnsupported` and `.serverMismatch` stop with `.failed(error)` (retrying a dead token or a wrong server would be a loop). `disconnect()` during a sleep cancels it. A successful reconnect yields `.connected`; subscribers of `events()` see no synthetic event: consumers that care (#0064) watch `states()`.
- **Logging.** `Logger(subsystem: "com.brennanmke.SkinAmp", category: "MusicAssistant")`: state transitions, command names, message ids, error codes, frame counts, byte counts. Never a frame body, `args`, a URL, a host or the token. The `auth` request is built by `MARequest.auth(token:)` whose `description` is `"auth(redacted)"`; `MARequest`'s `CustomStringConvertible` prints command names only.

The token stays in `read_env`'s variable, goes only into the `auth` frame, and is never printed, placed in argv, the environment, a URL or a file; `--out` is ignored and no fixture is written. It verifies exactly:

1. `info-http`: `GET /info` answers 200 JSON with the twelve recorded keys; `schema_version >= 28`; a `schema_version != 65` is reported as `ok (schema N; models recorded against 65)` and is not a failure.
2. `handshake`: the first WebSocket frame is bare and its key set equals `/info`'s; `server_id` equals `/info`'s.
3. `unauthenticated`: `players/all` before auth answers `error_code 20` (an error frame, not a close); `time` answers a number.
4. `auth`: the real token answers `result.authenticated == true` on a fresh socket (`error_code 23` → `FAIL (token rejected)`); the user object has `user_id`, `username`, `role`.
5. `shapes`: for each of `artists-page`, `albums-page`, `tracks-page`, `playlists-page`, `players-all`, `player-queues-all`, `search`, the live reply's first item (or the whole object for `search`) has every key the committed fixture's first item has; missing keys fail the check and are named (key names are protocol, not values); extra live keys are counted in the message. The listings use `limit: 1` and the fixture's own filters; `search` uses the first live track's first word, `media_types` and `providers: ["library"]`.
6. `counts`: `music/<kind>/count` answers an integer for the four kinds, with `album_artists_only: true` for artists.
7. `paging`: `music/artists/library_items` at `offset = count - 1` (same filters) answers exactly one item.
8. `partial`: `music/playlists/playlist_tracks` on the first playlist answers one or more `partial: true` frames followed by one `partial: false` frame with the same `message_id`, and every `result` is an array.
9. `null-result`: `players/get` with `skinamp-no-such-player` answers `result: null` with `partial: false`.
10. `error-frame`: `skinamp/no_such_command` answers `error_code 12` with a string `details`.
11. `artwork`: the first `proxy_id` seen answers 200 `image/*` at `/imageproxy/<id>?size=256` **without** an `Authorization` header, and 400 at `size=200`.
12. `ping`: the server sends at least one ping within a 30 s idle window (informational: `ok (0 pings in 30 s)` is not a failure, since the client pings on its own).
13. `close`: the server accepts a close 1000 (no error on our close).

What it does not prove: that the app's own `URLSession` can reach the host (ATS, section 12) or that the Swift decoders accept the live bytes; the key-set checks are the drift detector for the second, and the fixtures are the ground truth the Swift tests run against.

### 12. Risks and gotchas

- **ATS and `ws://`.** `URLSession` applies App Transport Security to WebSockets. `NSAllowsLocalNetworking` covers `.local` names and private IPs, but an `http://` server reached by a public DNS name or a Tailscale `100.x` address (both named in #0075) fails with `URLError(-1022)`, which the client reports as `.transport(.appTransportSecurityRequiresSecureConnection)` with the same hint `PlexError` gives. `--check-live` is Python and is not subject to ATS, so a green live check does not prove the app can connect. #0063/#0075 must add an `NSExceptionDomains` entry or `NSAllowsArbitraryLoads` and update `scripts/check-info-plist.sh`; say so in `## Gotchas`.
- **`URLSessionWebSocketTask` and Swift 6.** The task type's `Sendable`-ness varies by SDK; wrap it in the transport class marked `@unchecked Sendable` with its own lock, never store it in the actor. The upgrade failure surfaces from the first `receive()`, not from `resume()`.
- **Events are unverified (#0076).** `MAServerEvent` is lenient by design; the event tests use the API page's shape and say so in their names. If #0076 records `object_id` absent or `data` nested differently, only the hand-written frames in `ModelDecodingTests` change.
- **Counts must carry the listing's filters.** The recorded artist last page was empty for exactly this reason. The backend builds both requests from one `filters` value; `artistsPageUsesTheCountWithTheSameFilters` pins it.
- **`playlist_tracks` chunks are not cumulative** (500 per chunk, then an empty final frame); the assembler concatenates. The committed fixture is truncated to 5 items per frame, so a scripted multi-chunk route is what tests the general case.
- **Empty album names.** Three of the first albums have `name: ""`; the mapping falls back to the provider mapping's item id (the folder name). MA's own UI shows blanks; the fallback is a SkinAmp choice, noted in the mapping's doc comment.
- **`volume_level` is null for universal players**, `elapsed_time` null when idle; keep every such field optional (#0064 will read them).
- **Actor reentrancy.** The reader loop, the ping loop and `call` all mutate `pending`; every mutation happens inside the actor, and continuations are resumed after the entry is removed. A reconnect must fail the old entries before the new transport exists, or a stale frame could resolve a new call: the message-id counter restarts per connection, so entries are also keyed by connection generation.
- **Timeouts through an existential clock.** `clock.sleep(for:)` on `any Clock<Duration>` compiles in Swift 6; if the toolchain in the golden image objects, make the client generic in `init` only and store sleep/now closures, as `LibraryFallbackController` does.
- **Token lifetime in memory.** The client keeps the token for re-auth as `PlexClient` keeps its own; `disconnect()` drops it. There is no way to re-auth without it, and the Keychain read stays in `connect()`.
- **`events()` buffering.** `bufferingNewest(64)`: a slow subscriber drops old events rather than growing without bound; #0064 derives now-playing from the latest state anyway.
- **Stub drift.** The stub answers from recorded frames, so a decoding change that the live server would reject is caught only by `--check-live`'s key-set checks or a re-recording. Run `--check-live` whenever the models change.
- **Fixture filters in routes.** Listing routes match on `offset` and `summary`; a test that asks for an unrouted combination gets the unknown-command error frame, which is loud rather than silent.
- **Keychain in the guest.** Nothing in this issue's targets calls `SecItem*` at runtime except `KeychainMusicAssistantTokenStore`, which only #0063's composition will construct; the tests use the in-memory store. A Keychain prompt in the headless guest would hang `app-launch`.
