# 0047 — Open Skin panel will not select .wsz files

| | |
|---|---|
| **Status** | open |
| **Module** | App |
| **Platform** | macOS |
| **First seen** | 2026-10-13 |

## Description

File › Open Skin… (and the placeholder's Open Skin… button) shows `.wsz` files greyed out, so a skin can only be loaded by dropping it on the window. Found while hand-testing #0006.

## Steps to reproduce

1. Launch SkinAmp.
2. Choose Open Skin… and browse to `Skins/`.

## Expected behavior

`.wsz` files are selectable.

## Actual behavior

They are greyed out; only `.zip` files can be chosen.

## Root cause

Nothing on the system declares a type for `.wsz`, so Launch Services gives each file the dynamic type `dyn.ah62d4rv4ge81s654`, which conforms only to `public.data`. `App/PlayerView.swift` builds its filter with `UTType(filenameExtension: "wsz", conformingTo: .zip)`, which returns a *different* dynamic type (`dyn.ah62d46…`) that exists only inside the app. The file's type matches neither that nor `.zip`, so the panel disables it.

## Notes

The fix is step 1 of #0043's plan: export a declared type (`com.brennanmke.skinamp.wsz`, conforming to `public.zip-archive`, extension `wsz`) in the app's Info.plist and use `UTType(exportedAs:)`. Only the type declaration is pulled forward; the document-type claim and `onOpenURL` stay with #0043.
