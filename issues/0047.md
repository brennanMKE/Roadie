# 0047 — Open Skin panel will not select .wsz files

| | |
|---|---|
| **Status** | open |
| **Module** | App |
| **Platform** | macOS |
| **First seen** | 2026-10-13 |

## Description

File › Open Skin… (and the placeholder's Open Skin… button) shows `.wsz` files greyed out, so a skin can only be loaded by dropping it on the window. Found while hand-testing #0006.

## Plan

Written 2026-10-18. **The fix is already in the tree; this issue was never moved past `open`.** Two code commits landed on 2026-10-13 right after the issue was filed:

- `805f7d1` *#0047 Declare the .wsz type so Open Skin can select skins*: exports `com.brennanmke.skinamp.wsz` (conforms to `public.zip-archive`, extension `wsz`) under `UTExportedTypeDeclarations` in `project.yml` → `App/Info.plist`, and replaces the dynamic type with `UTType(exportedAs: "com.brennanmke.skinamp.wsz", conformingTo: .zip)` (`App/PlayerView.swift`, `extension UTType`).
- `70787bd` *#0047 Accept skins in every open panel*: `PlayerModel.openSkin()` (`App/PlayerModel.swift`) is now an `NSOpenPanel` with `allowedContentTypes = [.wsz, .zip]`, used by File › Open Skin… (`App/SkinAmpApp.swift`), the placeholder button (`App/PlayerView.swift`) and the playlist/equalizer context menus; `openFiles(replace:)` (Cmd-O, Add, eject) also accepts `.wsz` and routes through `open(_:replace:)`.

Since then #0043 has built on it (document-type claim), and the guest already checks the type in two places: `scripts/check-info-plist.sh` (`app-plist` step) asserts `UTExportedTypeDeclarations.0.UTTypeIdentifier`, and `scripts/check-quicklook.sh` (`app-quicklook` step) asserts `mdls kMDItemContentType` of a generated `test.wsz` is `com.brennanmke.skinamp.wsz` (`content-type-registered`). That second check is the root cause in reverse: Launch Services now gives the file the declared type, not `dyn.ah62d4rv4ge81s654`.

### For the user to check on their Mac

The open panel's greyed-out state can't be checked headlessly in the guest. With an installed build: File › Open Skin… → browse to `Skins/` → `.wsz` files are selectable and loading one changes the skin. Do the same from the placeholder's Open Skin… button and from Cmd-O (a `.wsz` there should load as the skin). If files are still grey, `mdls -name kMDItemContentType some.wsz` should print `com.brennanmke.skinamp.wsz`; if it doesn't, an older SkinAmp build is registered (`lsregister -dump | grep skinamp.wsz`), so run the new build once or re-register it.

## Steps to reproduce

1. Launch SkinAmp.
2. Choose Open Skin… and browse to `Skins/`.

## Expected behavior

`.wsz` files are selectable.

## Actual behavior

They are greyed out; only `.zip` files can be chosen.

## Root cause

Nothing on the system declares a type for `.wsz`, so Launch Services gives each file the dynamic type `dyn.ah62d4rv4ge81s654`, which conforms only to `public.data`. `App/PlayerView.swift` builds its filter with `UTType(filenameExtension: "wsz", conformingTo: .zip)`, which returns a *different* dynamic type (`dyn.ah62d46…`) that exists only inside the app. The file's type matches neither that nor `.zip`, so the panel disables it.

## Notes

The fix is step 1 of #0043's plan: export a declared type (`com.brennanmke.skinamp.wsz`, conforming to `public.zip-archive`, extension `wsz`) in the app's Info.plist and use `UTType(exportedAs:)`. Only the type declaration is pulled forward; the document-type claim and `onOpenURL` stay with #0043.
