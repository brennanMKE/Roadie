## Description

Winamp's Ctrl+K opened Preferences › Visualization, and MilkDrop's config (Alt+K) set the time between automatic preset changes, the blend time, the presets folder and the song title animation. After #0236 Roadie's visualization has those behaviours with fixed defaults and no place to change them, no way to add a folder of `.milk` presets, and no Winamp-style "open the visualization when playback starts".

Design: [docs/design/visualization.md](../docs/design/visualization.md) §1.1, §2.9, §5.1, §6.

## Resolution notes

> 🟢 Resolved 2026-10-29 — Settings › Visualization (⌥⌘K, and Visualization Settings… in the Window menu, the skinned main menu, the clutter V and built-in vis menus, and the vis window's right-click menu) sets automatic changes, interval, vary, blend, order, a presets folder, the overlay idle time, the song title and open on play. ## Root cause

This was a missing feature: #0236 shipped the behaviours with fixed defaults and no settings UI.

## Fix

- `App/Settings/VisualizationSettingsView.swift` (new) is a grouped `Form` bound to `VisualizationModel.settings`. It is a new `SettingsTab.visualization`, placed after Skins and using the `waveform` symbol. The model is injected into the `Settings` scene with `.environment(model.visualization)`.
- `VisualizationModel.updateSettings(_:)` clamps each change, saves it with `VisualizationSettings.save` and applies it live: `clock.policy`, `navigator.order` and `isLocked`, and a folder rescan.
- `overlayIdleTimeout` is nil for Never. #0238 reads it; this issue implements no overlay behaviour.
- **Presets folder:** `reloadCatalogue()` scans on `Task.detached` with a generation guard, then lists classics + user presets through `replacePresets`. If the current preset is gone, it loads what the navigator moved to. The scan runs on a folder change, at init when a folder is set, and on each open. `folderStatus` is none, scanning, notFound or found(N).
- **The folder section is Debug-only for now** (`showsPresetsFolder`). The design (§5.1, and the line after the §6 mock-up) says the row "appears only when the active renderer can draw `.milk` presets (after #0243; in Debug, the classic renderer claims it for tests, §3.3)". The Release classic renderer's `canLoad` refuses `.milk`, so showing the row there would add a folder whose presets never appear. #0243 should make `showsPresetsFolder` follow the renderer.
- **Open on play:** a `PlayerModel.nowPlaying` `didSet` calls `VisualizationModel.playbackStateChanged(to:)`. It ignores `.loading` and opens only when the last settled state was `.stopped`. Resuming from pause and track changes don't open it.
- **⌥⌘K:** there is a new `MainMenuCommand.visualizationSettings`. `PlayerModel.showSettings(_:)` writes `settingsSelectedTab`, then calls the `openSettings` environment action captured in `PlayerView` (macOS 14). If that action isn't there, it sends `showSettingsWindow:`. The call is behind a new `SystemRequest.settings`, so hosted tests don't open the window.
- **Test hooks (Debug):** `-RoadieVisPresetsFolder <path>` (the folder at launch, and Choose…'s answer) and `-RoadieVisSeedPresets N`.
- **Deviation:** the UI test can't assert that the overlay stays up with Never, because #0238 isn't on main. It asserts that the probe shows `order: sequential` and that the idle pop-up reads Never.

## Plan

### Settings tab

- `SettingsTab.visualization`; `SettingsView` gains `VisualizationSettingsView()` with `Label("Visualization", systemImage: "sparkles.tv")` (if the symbol isn't on macOS 14, `waveform`), after Skins, before Updates. The model is passed through `.environment(appDelegate.model.visualization)` in `RoadieApp`'s `Settings` scene.
- `App/Settings/VisualizationSettingsView.swift` (`Form`, `.formStyle(.grouped)` like the other tabs), bound to `VisualizationModel.settings` (each change saved through `VisualizationSettings.save` and applied live):
  - **Presets:** "Change presets automatically" toggle (`vis.settings.autoAdvance`); "every" a `TextField` with a `Stepper` 5…300 s (`vis.settings.interval`); "Vary the time" toggle (`vis.settings.vary`); "Blend time" `Slider` 0…10 s step 0.1 with the value as text (`vis.settings.blend`); "Order" picker Random / In order (`vis.settings.order`).
  - **Your presets folder** (shown only when the renderer can draw `.milk` presets: Debug always, Release after #0243): the path or "None", Choose… (`NSOpenPanel`, directories only; test mode takes `-RoadieVisPresetsFolder <path>` instead of the panel, as `-RoadieAddFolder` does), Clear, Show in Finder, and "N presets found" / "Folder not found" (`vis.settings.folder`, `vis.settings.folderCount`).
  - **Overlay:** "Hide the overlay and pointer after" picker 2 / 3 / 5 / 10 seconds / Never (`vis.settings.idle`); "Show the song title when the track changes" (`vis.settings.songTitle`).
  - **Window:** "Open the visualization when playback starts" (`vis.settings.openOnPlay`).
- Live effects: interval / vary / enabled → `clock.policy`; order → `navigator.order`; idle → `overlay.idleTimeout`; folder → rescan (below).

### Presets folder

- `VisualizationModel.reloadCatalogue()`: `PresetCatalog.classics` + (#0243's bundled) + `PresetCatalog.scan(folder:source: .user)` on a background task (`Task.detached`, the scan is synchronous I/O), then on the main actor `navigator.replacePresets(PresetCatalog.ordered(all).filter(renderer.canLoad))`. Runs when the folder setting changes and each time the window opens; generation-guarded so an older scan can't overwrite a newer one.
- Roadie isn't sandboxed (`App/Roadie.entitlements` has no `app-sandbox`), so a plain path is enough, as `LibraryFolderPath` is.

### Open on play

- `PlayerModel` observes `playbackState`: a transition from `.stopped` (or idle) to `.playing` with `settings.openOnPlay` opens the window (windowed) unless it's open; not on track changes or resume from pause.

### Visualization Settings… everywhere

- `MainMenuCommand.visualizationSettings`; `MainMenu.visualizationEntries` gains "Visualization Settings…" ⌥⌘K after Start/Stop; `PlayerModel.perform` sets `settingsSelectedTab = visualization` and opens Settings (the `openSettings` environment action, held the way `WelcomeView` uses it, or `NSApp.sendAction(Selector(("showSettingsWindow:")), …)` as a fallback; whichever `MainMenuBuilder`-reachable path works on 14, say which in `## Fix`).
- Window menu: "Visualization Settings…" ⌥⌘K after Visualization. Clutter V menu and the built-in vis's right-click menu (`VisualizerMenu`): the same item. The vis window's right-click menu: its last item.

## By hand

1. ⌥⌘K (and Window › Visualization Settings…, the skinned main menu, the clutter V menu): Settings opens on Visualization.
2. Set 5 s and Vary off with the vis window open: presets change every 5 s. Blend 0: they cut; 8 s: slow blends.
3. Choose a folder of `.milk` files (a Debug build, or after #0243): the count appears; L lists them. Clear: they go.
4. Idle Never: the overlay stays; 10 s: it waits longer.
5. Open on play: stop, close the vis window, press play: it opens. Pause and resume: it doesn't reopen if you closed it.
