## Description

Reported by the user on 0.1.0-2671617. The Library toolbar's Output menu is single-choice, so playing to both HomePods at once isn't possible unless a group already exists in Music Assistant. The user wants to select several outputs.

## Expected behavior

- Each output (This Mac and every speaker) has a checkbox; checking several plays to all of them in sync, using Music Assistant's player grouping (the first checked becomes the group leader).
- Checking or unchecking a speaker while playing adds it to or drops it from the running playback, without restarting the track.
- The toolbar label names the selection (one name, or "Kitchen + 1").
- Existing Music Assistant groups still appear and can be picked.

## Plan

**Builds on #0117.** #0117 makes a change of `selectedOutput` move what is playing to the new output (`player_queues/transfer`). This issue keeps `selectedOutput` as the **leader**: transport, now-playing, the local-files gate and #0117's move all keep keying on it. It adds the other members next to it. Whenever the leader changes, this issue calls #0117's move and doesn't transfer queues itself. If #0117 names its entry point differently than assumed here (say `PlayerModel.moveOutput(to:)`), use that name. The one requirement: the reconcile path (a selected player disappeared) must be able to set the leader **without** a transfer, as #0117 must also allow for `refreshOutputs`.

Grouping uses only `players/cmd/set_members` (`target_player`, `player_ids_to_add`, `player_ids_to_remove`; in `docs/ma-protocol/commands.json`). `group` and `group_many` are documented as aliases of it (`group_many` is deprecated), so they aren't used. `ungroup` and `ungroup_many` aren't needed, because removing every member through `set_members` does the same job.

### UI decision: a popover, not a Menu

A SwiftUI `Menu` on macOS closes after every click, Toggles included. Checking two speakers would mean opening it twice, and a menu row can't offer both "add this" and "play only here". So the toolbar item becomes a `Button` that opens a `.popover`, which stays open while the user checks rows:

- **This Mac** and **Speakers**: one row each, `Toggle(isOn:)` with `.toggleStyle(.checkbox)` for membership, then a trailing `Button("Only")` (`.borderless`, `.controlSize(.small)`, secondary color). "Only" is the old single pick: it ungroups and moves (#0117). Unavailable rows, and rows that `OutputSelection.canAdd` rejects, are disabled. The leader's row shows a small "leader" caption, or a `.help` tooltip.
- **Groups** (Music Assistant group players): no checkbox. A plain button row with a checkmark when selected. A group is one player, so choosing it acts as "Only".
- The hint text stays at the bottom. `refresh()` runs when the popover appears.
- The toolbar label is `OutputSelection.label(names:)`: "Kitchen", or "Kitchen + 1" (leader name, then the count of other members). The icon is `hifispeaker`, or `hifispeaker.2` with more than one member. Keep `accessibilityIdentifier("library.output")` on the button and `.help("Output")`. Rows get `library.output.<id>`.

### 1. Pure selection rules: `Packages/PlayerKit/Sources/LibraryBrowser/OutputSelection.swift` (new)

```swift
/// The Output popover's selection (#0118): the leader (the old single `selectedOutput`) plus synced members.
public struct OutputSelection: Hashable, Sendable {
    public private(set) var leader: OutputDevice.ID
    /// Non-leader members, in the order they were checked.
    public private(set) var members: [OutputDevice.ID]
    public var all: [OutputDevice.ID] { [leader] + members }
    public static let thisMac = OutputSelection(leader: OutputDevice.thisMacID, members: [])

    /// What the app must do, in order, to reach the new selection.
    public enum Step: Hashable, Sendable {
        case setMembers(leader: OutputDevice.ID, add: [OutputDevice.ID], remove: [OutputDevice.ID])
        /// #0117's move: set `selectedOutput`, which moves what plays.
        case move(to: OutputDevice.ID)
    }

    public func toggling(_ id: OutputDevice.ID, devices: [OutputDevice]) -> (OutputSelection, [Step])
    public func selectingOnly(_ id: OutputDevice.ID) -> (OutputSelection, [Step])
    /// Drops members no longer listed or unavailable. A lost leader is replaced by the next member, or by This Mac.
    /// Never returns steps: the server already dropped those players.
    public func reconciled(with devices: [OutputDevice]) -> OutputSelection
    public static func canAdd(_ device: OutputDevice, to selection: OutputSelection) -> Bool
    public func label(names: (OutputDevice.ID) -> String) -> String
}
```

Rules (each is a test below):
- **Check a non-member speaker or This Mac.** If the selection is a group player, this works as `selectingOnly`. Otherwise append it to `members` and return `[.setMembers(leader, add: [id], remove: [])]`.
- **Uncheck a non-leader member.** `[.setMembers(leader, add: [], remove: [id])]`.
- **Uncheck the only output.** Ignored, so the result is the same selection with no steps. There is always one output.
- **Uncheck the leader while others remain.** The next member `A` becomes leader. Steps: `.setMembers(old, remove: members)`, `.move(to: A)`, then `.setMembers(A, add: rest)` only if `rest` isn't empty. Only this case restarts the stream. #0117's transfer keeps the track and its position, with a short gap.
- **`selectingOnly(id)`.** Ungroup first if there are members (`.setMembers(leader, remove: members)`), then `.move(to: id)` if `id != leader`. The selection becomes `[id]`.
- **Groups.** Choosing a group player always goes through `selectingOnly`.
- **`canAdd`.** The device must be available and not a group. If `device.groupableWith` is known, it must contain every current member other than the device itself. `nil` means unknown, which allows it, and the server's error then becomes the notice.
- **`label`.** `members.isEmpty ? name(leader) : "\(name(leader)) + \(members.count)"`.

### 2. Model: `MusicBackendKit/Playback.swift`, `MusicBackend.swift`

- `OutputDevice` gets `public var groupableWith: Set<ID>?`, with an init parameter defaulting to `nil`. `thisMac` keeps `nil`.
- `MusicBackend` gets a new requirement, declared in the protocol so it dispatches dynamically, with a default in an extension:
  ```swift
  /// Syncs `adding` to `leader` and unsyncs `removing` (#0118). Default: `.unsupported(.remoteOutputs)`.
  func setGroupMembers(of leader: OutputDevice.ID, adding: [OutputDevice.ID], removing: [OutputDevice.ID]) async throws
  ```
  `FolderBackend` keeps the default.
- `MusicBackendStub/StubMusicBackend.swift` adds `Method.setGroupMembers` and `Call.setGroupMembers(OutputDevice.ID, [OutputDevice.ID], [OutputDevice.ID])`. It records the call and honours `setError`/`gate` like `transport`.

### 3. Music Assistant: `MusicAssistantKit`

- `MARequest.setMembers(target: String, add: [String], remove: [String])` sends `players/cmd/set_members`. Leave out an empty list instead of sending `[]`.
- `MAPlayer` decodes `canGroupWith: [String]?` (`can_group_with`).
- `MusicAssistantBackend.setGroupMembers`: works inside `guarded`. `thisMacID` maps to `resolveLocalPlayer().playerID`, as the leader or as a member, so This Mac with Sendspin off throws `thisMacNotRegisteredText`. Other ids go through `requireOutput`. Does nothing when both lists are empty. Afterwards, drop the leader and the members from `players` so the next `requireOutput` refetches.
- `outputs()`: work out `hostingIDs` (players that host `localClientID`). Map each `can_group_with` entry in `hostingIDs` to `thisMacID`. `OutputDevice(ma:)` gets a `groupable:` parameter for the mapped set. That way a HomePod row knows whether it can join This Mac (in `sendspin-probe.json`, This Mac's wrapper and the HomePods list each other).
- **Gotcha, fix the group rule in `MAMapping.swift`.** Today a `type == "player"` with non-empty `group_members` counts as a group. That is exactly what a **sync leader** looks like after `set_members`, so Kitchen would jump into the Groups section and lose its checkbox. New rule: `type == "group" || (type == nil && !(groupMembers ?? []).isEmpty)`. Update `outputsMarkGroups` so `p1` (a player with members) is `false`, and add a typeless row with members that stays `true`.

### 4. App

**`App/PlayerModel.swift`**
- Add `private(set) var outputSelection = OutputSelection.thisMac`. `selectedOutput` stays the stored leader, with #0117's `didSet`. The invariant is `outputSelection.leader == selectedOutput`. Every place that writes `selectedOutput` keeps them in step: the server-change reset to This Mac, and `refreshOutputs`.
- `func toggleOutput(_ id:)` and `func selectOnlyOutput(_ id:)` compute `(next, steps)` and set `outputSelection = next` first, so the popover updates at once. They then run the steps in order in one `Task`:
  - `.setMembers` calls `try await musicAssistant.setGroupMembers(...)`.
  - `.move` sets `selectedOutput = to`, which is #0117's move. Await it if #0117 makes the move async.
- If a step fails, set `outputSelection` back to the previous value. Set `selectedOutput` back only if no `.move` ran. Call `showBackendFailure(error)`; the This Mac text already explains Sendspin being off.
- Serialize: a second toggle while a step `Task` runs waits for it. Chain on the previous task, as `skinLoadGeneration` does, or keep a `pendingOutputTask` and await it first. This prevents overlapping `set_members` calls.
- `refreshOutputs()`: `outputSelection.reconciled(with: outputPicker.devices)`. If the leader changes, assign `selectedOutput` without a move and post "Output switched to <name>" (today's text says This Mac). `activeMusicAssistantServerChanged` resets to `.thisMac`.
- Volume stays on the leader. `group_volume` is a possible follow-up and is out of scope.

**`LibraryBrowser/PlaybackRouter.swift`, `LocalPlaybackGate`**
- Add `refusal(forLocalFilesOn selection: OutputSelection) -> String?`. It returns `switchToThisMac` unless `selection == .thisMac`. Local files never sync to speakers; they play only through AudioCore. Use it in the `refusal(forLocalFilesOn: selectedOutput)` call sites (`PlayerModel.swift` and `PlayerModel+PlaylistFiles.swift`). In `playFromLibrary`, refuse when the selection has members and the source lacks `.remoteOutputs`. Keep the single-id overloads for existing callers and tests.

**`App/Browser/OutputPickerView.swift`**
- Rewrite it as the popover described above: `@State private var isPresented = false`, rows calling `player.toggleOutput` / `player.selectOnlyOutput`, and the label from `outputSelection.label`, with names from `outputPicker.devices`.
- Keep the fallback names ("This Mac", "Speaker").

## Root cause

The Output menu was a single-choice `Menu` bound to one `selectedOutput`, and SkinAmp never sent `players/cmd/set_members`. Speakers couldn't be synced unless a group already existed in Music Assistant. `OutputDevice(ma:)` also counted any player with `group_members` as a group, so a sync leader would have moved into the Groups section.

## Fix

The plan was followed: `OutputSelection` (leader + members, with steps), `MusicBackend.setGroupMembers`, `MARequest.setMembers`, `MAPlayer.canGroupWith`, `OutputDevice.groupableWith` (the This Mac wrapper is mapped to `thisMacID`), the fixed group rule, the selection-based local-files gate, the `PlayerModel` toggle/only/reconcile wiring, and the popover `OutputPickerView`.

Adaptations to #0121's ownership model:
1. `selectedOutput`'s `didSet` resets the selection to that single output whenever a write changes the leader outside the selection (`adopt`, fallbacks, a plain pick). The invariant leader == `selectedOutput` holds.
2. `stopOthers` doesn't count This Mac as playing while it is a member. Review note 1: `PlaybackOwnership.stops` also skips This Mac when the activity shows it synced to the target, so no stop reaches the leader through the redirect.
3. `streamStarted` doesn't adopt This Mac when it is a member. This checks membership directly, not the 150 ms activity (review note 2). A grouping made in Music Assistant's web UI still relies on the refreshed activity.
4. `QuitStop.targets(members:)` stops the members too.
5. Review note 3: on `.connected`, `activityAfterConnect` is set only when no snapshot has arrived yet.

Divergences from the plan:
- When a step fails after a move ran, the selection becomes the current leader alone, not the previous selection.
- `canAdd` also checks the leader against `groupableWith`.
- `outputsCarryGroupableWithAndMapThisMac` is in `MusicAssistantThisMacTests` with a hand-built `players/all`. No speaker in the recorded fixture lists the wrapper in `can_group_with`.
- The `setGroupMembers` transport tests call `outputs()` first to cache the players.
