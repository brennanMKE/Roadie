## Description

The playlist editor is where 0.0.4's bugs showed. On the local queue nothing drives its rows, selection, double-click, menus, `[n]` markers, scrolling, resizing or shade mode. This issue adds `PlaylistUITests` over the folder library (the Music Assistant queue is #0206), covering the `PlaylistUITests` rows of [docs/design/test-automation.md](../docs/design/test-automation.md) §5.5, including the local half of the #0187 regression (double-click plays that row, not row 0).

## Plan

Launch: `app.launch(library: .folder, windows: [.main, .playlist], extra: ["-RoadieOpenFiles", musicFolder])` so the queue holds the fixture library's 9 tracks in Finder order (#0195's `ExpectedLibrary` gives the titles), stopped at row 0. The playlist is 3 steps tall (`-playlistWindowSize 0 3`): rows 0–11 visible, so 9 rows fit without scrolling; `scrollResizeShade` adds the folder twice.

### `Tests/RoadieUITests/PlaylistUITests.swift`

- `rowsShowTheQueue`: `pl.row.0…8` labels are `1. Tone Artist - Tone A` … in the expected order; values carry `duration=0:02`; `pl.runningTime` is the sum.
- `selection`: click row 1 → selected; ⌘-click row 3 → both; ⇧-click row 5 → 1–5 (shift extends from the anchor: check `PlaylistSelection` semantics); ⌘A → all; `SEL › zero` → none; `SEL › invert`.
- `doubleClickPlaysThatRow` (**#0187, local**): double-click `pl.row.3` → `pl.row.3` has `current=true`, `probe.currentIndex == 3`, `main.marquee` starts with `4. `; `pl.row.0` is not current. Then select row 5 and `typeKey(.return)` → row 5 plays.
- `removeCropClear`: select row 2, `typeKey(.delete)` → 8 rows, the former row 3 is now row 2; select rows 0–1, `REM › crop` → 2 rows; `REM › all` → 0 rows and `main.marquee` shows the placeholder; `LIST › new` same.
- `dragReordersRows`: press row 0, drag to row 4's position → the former first title is at `pl.row.4`; the current row's marker follows the track (`probe.currentIndex`).
- `scrollResizeShade`: add the folder again (`-RoadieOpenFiles` can't be re-sent; use `ADD › dir` with the test-mode hook `-RoadieAddFolder <path>` acting on click) → 18 rows; `pl.scroll.down` scrolls by 4 rows (`pl.row.0` disappears, `pl.row.4` is first visible: check `frame.minY`); scroll wheel (`app.playlist.element.scroll(byDeltaX: 0, deltaY: -3)`); drag `pl.scrollbar` to the bottom → last row visible; drag `pl.resize` down 2 steps → more rows visible; `pl.title.shade` → `shade.pl.*` shows the current track name and duration; ⌃⌘P back.
- `addURL`: `ADD › url` → the URL sheet; type `https://example.invalid/stream`; Add → a row appears with the URL as its name (`PLAYLIST_ADD_URL` path); play it → failure notice (no network), nothing hangs.
- `selectMenu`: covered in `selection`; keep a short test that the three entries exist and are clickable.
- `sortMenu`: `MISC › sort` pops the native menu; `Reverse List` → row labels reversed; `Sort List by Title` → alphabetical; `Randomize List` → same set, different order (retry once if the shuffle is identity).
- `fileInfoPanel`: select row 0, `MISC › info` → a window titled File Info with the title, format and path; close it. Also the row menu's File Info….
- `listMenuLocal`: `LIST › save` → with the local queue the save panel is replaced by `-RoadieSaveTo <tmp>/Saved.m3u` → the file exists and holds 9 entries (`PlaylistFile` parses it: read it in the test); `LIST › load` with `-RoadieOpenFiles <tmp>/Saved.m3u` → rows reload; `Playback › Save Queue as Playlist…` is disabled on the local queue without Music Assistant (`QueueSaveTarget` refuses) and the marquee says so when LIST › save is clicked in that state (check the actual behaviour: `canSaveQueue`).
- `bottomBar`: `pl.transport.play|pause|stop|next|previous` act (`main.state`, `probe.currentIndex`); `pl.miniTime` matches `main.time`.
- `rowMenu`: right-click row 2 → menu has Play, Queue, Remove, File Info…; Play → row 2 current; right-click row 4 → Queue → `pl.row.4` value has `marker=[1]` and the menu now shows Dequeue and Clear Queue; Remove removes.
- `queueMarkers`: select rows 6 and 7, `typeKey("q")` → `[1]`, `[2]`; `q` again on row 6 → dequeued and row 7 becomes `[1]`; play row 0, next → row 7 plays (up-next wins), then row 1 (`UpNextTests` semantics); Jump to File's Queue button is #0204.
- `queueSurvivesRelaunch`: play row 3, pause; `app.terminate(); app.launch(keepingDefaults: true, keepingData: true)` → 9 rows, row 3 current, state stopped (restored stopped at the saved track).
- `missingFileShowsANotice` is in #0202; `openFilesReplacesTheQueue`: launch with two files via `-RoadieOpenFiles` → 2 rows; `File › Add to Playlist…` with `-RoadieAddFiles <one file>` → 3 rows.
