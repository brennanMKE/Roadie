# 0068 — Playback errors are never shown to the user

| | |
|---|---|
| **Status** | open |
| **Module** | App / AudioCore |
| **Platform** | macOS |
| **First seen** | 2026-10-13 |

## Description

When a track fails to open or play, `Player.fail(_:)` (`Packages/PlayerKit/Sources/AudioCore/Player.swift`) stops playback and sets `Player.errorMessage`, but nothing in the app displays it. Playback just stops with no explanation, whether a local file is unreadable or a Plex download fails.

## Expected behavior

The failure is shown briefly in the skinned window, the way #0045 shows the skipped-file notice (a marquee takeover), and playback state is consistent.

## Plan

### Scope and decisions

Status stays `open`; this plan writes no code. **Blocked by #0045**: this issue posts its messages through #0045's `StatusNotice` (AudioCore), `PlayerModel.post(_:)` / `clearNotice()`, `placeholderText` and the `notice?.text ?? …` precedence in `marqueeText`. If #0045 is not `resolved` when this issue is picked up, bail per Issues.md ("When the subagent can't finish") with a `## Notes` line "blocked by #0045"; do not re-implement the notice here. #0021 (marquee) has landed, #0062 (`MusicBackend`, `send(_:)`) has landed.

Three things are wrong today, and the plan fixes all three because they share one slot:

1. `Player.fail(_:)` sets `Player.errorMessage` and nothing reads it (`Packages/PlayerKit/Sources/AudioCore/Player.swift` 528–532). The model follows `backend.nowPlaying(on:)`, whose `NowPlaying` snapshot has no error field, so the marquee just goes from "Buffering…" to the stopped title.
2. `PlayerModel` writes two more messages nobody shows: the transport loop in `init` (`App/PlayerModel.swift` 141, `self?.errorMessage = error.localizedDescription`) and `playFromLibrary` (271). After #0045, `errorMessage` means only "why there is no skin", so both lines must go through the notice instead.
3. The player stops dead on the first bad track. Winamp 2 skips an unplayable playlist entry and goes on; Webamp does the same: its `ElementSource` error handler says "Rather than just getting stuck in this error state, we can just pretend this is [the end of the track]" and triggers `ended`, which advances the playlist (`js/media/elementSource.ts` 66–95, fetched 2026-10-14 from `captbaritone/webamp` master into the planner's scratchpad `plan0068/webamp/`; re-fetch with `curl -sS -f -o <dest> https://raw.githubusercontent.com/captbaritone/webamp/master/packages/webamp/js/media/elementSource.ts` into an empty scratchpad directory, never under the repo).

Decisions:

- **Skip on a per-track failure (recommended, chosen).** A queue of 200 local files with one deleted or corrupt entry should not end the listening session; that is the Winamp contract and it is what the notice makes safe (the user sees "Could not play X" for 3 s while X+1 starts). Three guards keep it from running away: (a) the player **stops** when the error says the whole source is down (engine would not start, Plex not set up or unreachable, sign-in rejected, cache disk failure), since the next track would fail the same way and a 500-track Plex queue would otherwise hammer a dead server at up to 30 s per request (`PlexPartDownloader.makeSession` request timeout); (b) it stops when `repeatMode == .one`, where "next" is the same track; (c) it stops once every queued track has failed in a row (one pass: `consecutiveFailures < queue.tracks.count`), so repeat-all over an all-bad queue does not spin. The error classification lives where the errors are defined, through one small protocol in AudioCore that `TrackCacheError` adopts; unknown errors (the `AVAudioFile` open failures from CoreAudio) count as per-track.
- **The player reports each failure as an event, not only as `errorMessage`.** With skipping, `errorMessage` would be overwritten by the next track's load before the model could read it, and an `@Observable` property cannot carry a sequence anyway. `Player` already has `addEventObserver` (used by `NowPlayingBridge`, `CachePinner`, `LocalPlayerOutput`), so `PlayerEvent` gains `.failed(PlaybackFailure)`; the model registers one observer next to `nowPlayingBridge.install()`. `errorMessage` stays (the tests and the cache's doc comment rely on it) with one sharpened rule: set by every failure, cleared when a track **opens** (`begin`) rather than when a load starts, so after a skip run that ends in `stopped` it still holds the last message.
- **Message wording: a fixed phrase plus the track title or a count, never the error text.** Marquee texts: `Could not play <title>` (one track, skipped or not), `Could not play 3 tracks` (a run that ended in stop after more than one failure), `Could not play this track` (no current track, e.g. an engine failure while paused with an empty title). The error's `localizedDescription` goes to `StatusNotice.detail` (shown only on the no-skin placeholder, which has room) and to Console (`Playback` category, `privacy: .public` as `TrackCache` already logs). This is what keeps tokens, URLs and headers out of the strip by construction: the sources of `detail` are already documented token-free (`MusicBackendError`: "No case carries a URL, a request, a header or a token"; `TrackCacheError.errorDescription`: "None interpolates a URL, a request or a header"; `PlexError` prints codes and statuses only; Foundation's file errors name the file, not the path), and a test pins that the marquee text never contains the message. Backend failures from `playFromLibrary` and `send(_:)` throw `MusicBackendError`, whose `errorDescription` is written for the user by contract, so that text is the notice (`Not connected to the music source.`, `That output is not available.`); any other error type shows `Could not play` with its description as `detail`. `CancellationError` is never shown. No `String(localized:)` (the marquee font has no localization). A long title scrolls like a long skin name in #0045; fine for 3 s.
- **Dedup and coalescing.** The player bounds a run to one event per queued track (the one-pass cap), and the model keeps #0045's "last message wins, clock restarts" rule, so a run of three bad files shows `Could not play A`, `Could not play B` for a few ms each and then `Could not play 3 tracks` for 3 s. A repeated identical failure (the user presses Play on the same bad track) restarts the clock, which is the right response to the click. No queueing, no "same text within N seconds" rule: the cap and last-wins already bound the cost (a cancelled `Task` per replaced notice), and the Console keeps every failure.
- **State after a failure.** Skip: `errorMessage` set, `.failed` emitted, `queue.advanceAfterTrackEnd()` (same path as a finished track, so shuffle and repeat-all are honoured), `startCurrentTrack(autoplay: autoplayAfterLoad)` so a Pause pressed during the load still parks the next track at 0:00; `state` stays `.loading` throughout (no `stop()`, so the stream never shows a `stopped` blip and the marquee keeps "Buffering…" under the notice). Stop: unchanged (`stop()`, then `errorMessage`), the queue stays on the last tried track so Play retries from there and a fresh pass begins (the counter resets in `stop()` and `begin(_:)`). `currentTime`, `currentFormat` and `file` are reset by `startCurrentTrack`/`stop()` as today. Engine failures from `play()`-while-paused and `handleConfigurationChange` keep stopping and now emit `.failed` too.
- **Not in scope:** an error field on `NowPlaying` for remote outputs (#0064 decides how MA reports errors; the local player is the only output today, and `PlayerModel` already holds `player` for the spectrum, time and local files), a playlist-window marker for failed entries (M5), `LocalTrackLoader` (it already drops unreadable files at import with its own notice from #0045).

### 1. AudioCore: failure scope and the event (`Packages/PlayerKit/Sources/AudioCore/AudioCoreError.swift`, `Player.swift`)

In `AudioCoreError.swift`, add and conform:

```swift
/// Adopted by errors a `TrackResolver` can throw when they know whether the whole source is unavailable
/// (the player stops) or only this track is unplayable (the player skips it, like Winamp). Errors that
/// do not conform count as per-track.
public protocol SourceScopedError: Error {
    var affectsWholeSource: Bool { get }
}

extension AudioCoreError: SourceScopedError {
    public var affectsWholeSource: Bool {
        switch self {
        case .engineStart: true
        case .unresolvableSource: false
        }
    }
}
```

In `Player.swift`:

- `PlayerEvent` gains `case failed(PlaybackFailure)` with, next to it:

```swift
/// One track that could not be resolved or opened, or an engine failure. `skipped` says the player moved on
/// to the next track; `consecutiveFailures` counts this run of failures (resets when a track opens or the
/// player stops), so a listener can say "3 tracks" when a whole pass failed.
public struct PlaybackFailure: Sendable, Equatable {
    public let track: Track?
    public let message: String
    public let consecutiveFailures: Int
    public let skipped: Bool
}
```

- Add `private(set) var consecutiveFailures = 0` (internal, `@ObservationIgnored`; tests read it through `@testable`). Reset it to 0 in `stop()` and in `begin(_:)`.
- Move `errorMessage = nil` from `startCurrentTrack` (288) to `begin(_:)` and reword the property's doc comment: "The last failure's message: set by every failure, cleared when a track opens. Listeners that need each failure observe `PlayerEvent.failed`."
- The load task's `catch` (301) calls `trackFailed(error)` instead of `fail(error)`:

```swift
/// A track could not be resolved or opened. Winamp skips it and plays on; Webamp turns a media error
/// into "ended". The player stops instead when the error says the whole source is down, when repeat is
/// `.one` (the same track would fail again), or when every queued track has failed in a row (one pass).
private func trackFailed(_ error: any Error) {
    let sourceWide = (error as? any SourceScopedError)?.affectsWholeSource ?? false
    let count = consecutiveFailures + 1
    guard !sourceWide, queue.repeatMode != .one, count < queue.tracks.count,
          let failed = queue.current, queue.indexAfterCurrentEnds() != nil else {
        fail(error)
        return
    }
    consecutiveFailures = count
    let message = error.localizedDescription
    errorMessage = message
    emit(.failed(PlaybackFailure(track: failed, message: message, consecutiveFailures: count, skipped: true)))
    queue.advanceAfterTrackEnd()   // emits .trackChanged after .failed
    startCurrentTrack(autoplay: autoplayAfterLoad)
}

private func fail(_ error: any Error) {
    consecutiveFailures += 1
    let failure = PlaybackFailure(
        track: queue.current, message: error.localizedDescription,
        consecutiveFailures: consecutiveFailures, skipped: false)
    stop()   // resets consecutiveFailures; the event above already captured it
    errorMessage = failure.message
    emit(.failed(failure))
}
```

  `startCurrentTrack` is called from inside the finishing load task; its `loadTask?.cancel()` cancels the task that is about to return, which is harmless (the guard already passed), and it assigns a fresh task. Re-assigning `state = .loading` while already loading emits a second `.stateChanged(.loading)`; a repeated `play(at:)` does the same today and every observer tolerates it. `begin(_:)` throwing `AudioCoreError.engineStart` lands in `trackFailed` and is source-wide, so an engine that will not start still stops.

### 8. Risks

- **#0045 not landed.** Everything in section 3 and 4 builds on it; bail, do not stub a notice. The two `errorMessage =` lines this issue removes from `PlayerModel` are also ones #0045's end state lists ("plus the transport-failure line in `send(_:)`"); if #0045's implementer already routed `send(_:)` through `post`, keep theirs and only add `playFromLibrary` and the event observer.
- **A new `PlayerEvent` case breaks every exhaustive `switch`.** Only the two tests listed in section 5 switch exhaustively today; the compiler will find any added since.
- **Slow failures.** A per-track Plex failure that times out (server up but silent) costs one request timeout per track, bounded by one pass; the user's Stop ends it, as in Winamp. If this bites, lower the cap (e.g. `min(queue.tracks.count, 10)`) in one place, `trackFailed`.
- **`errorMessage` is now cleared at open, not at load start.** No test asserts `errorMessage == nil` while loading after an earlier failure; `PlexPlaybackBufferingTests` and `MixedFormatTests` assert nil only after successful opens, which `begin(_:)` still clears.
- **The skip path does not call `stop()`.** `discardSchedule()`, `playerNode.stop()`, `file = nil` and `currentFormat = nil` all happen in `startCurrentTrack`, so nothing from the failed track survives; the only difference from a stop is that `state` stays `.loading`, which is the point.
- **Event order on a skip** is `.failed(t0)`, `.trackChanged(t1)`, `.stateChanged(.loading)`. `LocalPlayerOutput` snapshots on each (`bufferingNewest(1)`), so a subscriber may see only the last; the model does not use the stream for failures, which is why the event exists.
- **Observer registration in `init`.** Capturing `self` before every stored property is initialised is a compile error; place the `addEventObserver` call where the plan says. The token is dropped on purpose: model and player live for the process (`NowPlayingBridge` keeps its own token because it supports `uninstall`).
- **`CachePinner` and `NowPlayingBridge` react to every event**, so a run of N failures triggers N pin updates and N publishes; both are cheap and already happen N times for N track changes.
- **Remote outputs (#0064).** Failures of a remote player will not come through `Player`; they belong in `NowPlaying` or a transport error, and `showBackendFailure` is the hook for the latter.
