## Description

#0209's `FirstLaunchUITests` and `SettingsUITests` (merged in main 8d452b1) closed most of what this issue named. In #0212's run `20261029-202842-54408`, the newer measurement, `MusicAssistantSettingsView` is at 94.2 % (586 of 622 lines; it was 0.3 % in run `20261029-191545-21712`), `MusicAssistantDiscoveryViews` 91.3 %, `WelcomeView` 93.2 %, `WelcomeWindowController` 100 %, `UpdatesSettingsView` 97 % and `LibrarySettingsView` 95.8 %. What remains:

- The system network wrappers are still at 0 %: `SystemServiceBrowser` (131 lines; Bonjour), `SystemWiFiNetwork` (48; the Location-gated SSID) and `SystemNetworkEvents` (30; the `NWPathMonitor` change stream). No UI test can reach them, since the guest has no Bonjour peers, no Location prompt and no network changes.
- Small view branches the UI tests don't drive: `MusicAssistantSettingsView.statusLine`'s server-mismatch text and Replace button (6 of 13 lines), and `DiscoveredServersSection`'s and the Library banner's offer rows (16 lines in all). The panel inside `chooseMusicFolder(startingAt:)` (8 of 17) can't run headless, and #0209's stand-in covers what follows it.

## Plan

1. `SystemServiceBrowser.host(of:type:)`: make it `internal static` and test it with `NWEndpoint.hostPort` values (IPv4, a name, IPv6 skipped) and `.service`/`nil` for both service types. No browsing.
2. `SystemNetworkEvents`: move the "skip the first path" rule out of `MonitorBox` into a value that the test can feed path updates to. Check that the first update yields nothing and each later one yields once.
3. `SystemWiFiNetwork`: map `CLAuthorizationStatus` to `WiFiAuthorization` in a `static` function and test every case. Check that two `requestAuthorization()` calls share one pending request by injecting the request call. No real Location prompt.
4. `MusicAssistantSettingsView`: move the status line's choice (message only, or message plus the mismatch explanation and Replace) into a `static` function over `MusicAssistantSettingsModel.Status`, with no behaviour change, and test it for `.failed(.serverMismatch)` and the other statuses.

## Tests

`serviceEndpointBecomesHost`, `networkEventsSkipFirstPath`, `wifiAuthorizationMapping`, `wifiRequestsShareOnePrompt`, `mismatchStatusOffersReplace`. Expect list: all of them.

## Which tier

**Fast:** `scripts/verify.sh --expect <the tests above>`. The new tests must not need the network, a real Keychain or a speaker. They use the stubs and injectable seams the plan names.
