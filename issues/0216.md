## Description

All of these are at 0 % in #0212's baseline: `MusicAssistantSettingsView` (622 lines, the largest gap in the app), `LibrarySettingsView` (303), `SkinsSettingsView` (290), `WelcomeView` (222), `SystemServiceBrowser` (131) and `UpdatesSettingsView` (100). `MusicAssistantDiscoveryViews` is at 30 %. The panes are SwiftUI and their clicks are #0209's. They also hold logic a unit test can reach: adding and validating a server draft, the discovery banner's rule, and how a found Bonjour endpoint becomes a host. This issue tests that logic.

## Plan

1. `MusicAssistantSettingsView.addDraft()` and `ServerRow`'s state: move the draft validation and the add/remove/select rules into a small `MusicAssistantServerDraft` value, or into a `PlayerModel` method if one already owns them. Test URL normalisation, duplicates, blank fields and the selected server after a remove. Test file: `Tests/RoadieTests/MusicAssistantSettingsLogicTests.swift`.
2. `MusicAssistantDiscoveryViews`: when `LibraryDiscoveryBanner` shows (servers found, none configured, dismissed), and which discovered servers `DiscoveredServersSection` lists (configured ones hidden). Feed it a fake `MusicAssistantServiceBrowser`.
3. `SystemServiceBrowser.host(of:type:)`: make it `internal static` and test it with `NWEndpoint.hostPort` and `.service` values for both service types. No browsing; the guest has no Bonjour peers.
4. `LibrarySettingsView` and `WelcomeView`: the folder choice goes through `chooseMusicFolder(startingAt:)`. Inject the panel, and check that the chosen URL reaches the folder backend. Also cover `WelcomeView.refreshServer`/`openMuseum` against the model.
5. `SkinsSettingsView` / `UpdatesSettingsView`: whatever logic remains once the bindings are excluded, which should be little. Note the rest under `## Notes` as #0209's.

## Tests

`serverDraftValidates`, `serverDraftRejectsDuplicates`, `removingSelectedServerSelectsNext`, `discoveryBannerRule`, `discoveredServersHideConfigured`, `serviceEndpointBecomesHost`, `chosenMusicFolderReachesBackend`, `welcomeActionsReachModel`. Expect list: all of them.

## Which tier

**Fast:** `scripts/verify.sh --expect <the tests above>`. The new tests must not need the network, a real Keychain or a speaker. They use the stubs and injectable seams the plan names.
