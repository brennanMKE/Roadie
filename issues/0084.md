## Description

Found in the #0064 review (code commit 11f05b5). With a Music Assistant speaker selected as the output, File › Open, Add, eject or dropping local files onto a skinned window queues and plays them on This Mac, but `selectedOutput` stays on the speaker, so the skinned main window, marquee and transport buttons keep showing and driving the speaker.

Expected: opening local files either switches the output to This Mac (with a notice) or is refused with a notice, the way `playFromLibrary` handles a source/output mismatch.

## Plan

Written on top of `df704e0`.

### Decision: refuse with a notice, don't switch

While a speaker is selected, opening, adding or dropping local audio is **refused** with the notice `playFromLibrary` already posts, "Switch the output to This Mac to play local files.". The queue and the speaker are left alone. Reasons:

- **It matches the existing behaviour.** `playFromLibrary` refuses a folder or Plex source on a speaker (#0064), and `PlaylistModel` already treats the local queue as hidden and read-only off This Mac (`isLocal()` guards on play, remove, move and so on). A drop that changes the output would be the one place where a local action takes the output away from the speaker.
- **Switching would leave two things playing.** Changing `selectedOutput` doesn't stop the speaker, so the HomePod keeps playing its queue while This Mac starts the dropped files. Stopping the speaker as part of a drop would be worse: a stray drag would cut off music in another room.
- **For a Winamp user,** the output is a deliberate choice (like picking an output plugin in Winamp). Winamp never changes it because you opened a file. Saying in the marquee why nothing happened is less surprising than audio quietly moving to the laptop. The notice says how to fix it, and switching to This Mac afterwards takes one click in the Output menu.

**Skins still load.** A `.wsz` in a drop, in File › Open, or opened from Finder loads as before. Only the audio part is refused.

### Entry points (all funnel into `importLocalFiles`)

| Entry point | Path today |
|---|---|
| File › Open…, File › Add to Playlist… (`SkinAmpApp.swift`), main window options menu Open/Add (`PlayerModel+MainMenu.swift`), `.openFile` hotkey/command (`PlayerModel.swift` ~670), eject button (`eject()`), playlist ADD › Add File | `openFiles(replace:)` → `open(_:replace:)` → `importLocalFiles` |
| Drop on the main window (`PlayerView.swift` `dropDestination`), drop on the playlist window (`PlaylistWindowView.swift`), Finder / Dock / `open -a` (`AppDelegate.application(_:open:)`) | `open(_:replace: false)` → `importLocalFiles` |
| Playlist ADD › Add Dir | `openFolder()` → `importLocalFiles` |
| Playlist LIST › Load List, File › Load Playlist… (#0082) | `loadPlaylistFile()` → `importLocalFiles([url], replace: true)` |
| A playlist file (`.m3u`/`.m3u8`/`.pls`) chosen in File › Open or dropped | `open` → `importLocalFiles` (the loader expands it) |

Nothing else calls `player.enqueue` or `player.play(at:)` outside `PlaylistModel` (already `isLocal`-gated). The queue restore at launch runs while This Mac is selected, because the selected output is not persisted. `playFromLibrary` is already handled.

### Approach

1. **Pure seam in LibraryBrowser.** Add the following to `Packages/PlayerKit/Sources/LibraryBrowser/PlaybackRouter.swift`, next to the router so the routing rules stay in one place:
   ```swift
   public enum LocalPlaybackGate {
       public static let switchToThisMac = "Switch the output to This Mac to play local files."
       /// nil when local files may play on `output`, else the notice text.
       public static func refusal(forLocalFilesOn output: OutputDevice.ID) -> String?
       /// playFromLibrary's rule: a source without `.remoteOutputs` can only play on This Mac.
       public static func refusal(source: BackendCapabilities, output: OutputDevice.ID) -> String?
   }
   ```
   These are nonisolated pure functions with no backend instance. The first returns nil for `OutputDevice.thisMacID` and `switchToThisMac` otherwise. The second returns nil when `output == thisMacID` or `source.contains(.remoteOutputs)`.
2. **`PlayerModel.playFromLibrary`**: replace the inline check and the string literal with `LocalPlaybackGate.refusal(source: backend.capabilities, output:)`. The behaviour stays the same; this just keeps the one text in one place.
3. **`PlayerModel.importLocalFiles(_:replace:)`**: this is the single funnel.
   - Return early when `urls` is empty (as today).
   - Before loading: `if let text = LocalPlaybackGate.refusal(forLocalFilesOn: selectedOutput) { post(StatusNotice(text: text)); return }`.
   - **Re-check after `await LocalTrackLoader.load(urls)`**: a large folder can take seconds, and the user can pick a speaker in the meantime. Post the same refusal and drop the result. Don't post the "skipped" notice in that case.
4. **Check before showing a panel on the audio-only panels**, so nobody browses for files only to have them refused. At the top of `openFolder()` and `loadPlaylistFile()`, post the refusal and return. Leave `openFiles(replace:)` and `eject()` showing their panel: that panel also picks skins, and the funnel refuses only the audio part. **Why not refuse before that panel too:** File › Open… is also how people open a `.wsz`, so refusing up front would block skin loading. Note this deviation-from-symmetry in a doc comment.
5. **Mixed drop (skin + audio) on a speaker.** `open(_:replace:)` keeps calling `loadSkin` and then `importLocalFiles`. The refusal notice is posted synchronously. `loadSkin` may post its own notice later from its task, and the last one posted wins. That's acceptable. Don't add ordering code; note it on the host checklist.
6. `open(_:replace:)` keeps returning `true` for a drop that only had refused audio. The drop was received and the notice explains why nothing played, so the drag shouldn't animate as rejected. Say so in its doc comment.
7. No change to `selectedOutput`, `refreshOutputs`, `OutputPickerModel` or the router's `backend(for:)`.

## Resolution notes

> 🟢 Resolved 2026-10-18 — Every way of queuing local audio now goes through `importLocalFiles`, which refuses with the `playFromLibrary` notice while a speaker is selected. Skins still load, and This Mac behaves as before.

## Root cause

`importLocalFiles`, the funnel for File › Open/Add, eject, drops, Finder opens, Add Dir and Load List, never looked at `selectedOutput`. It always queued on the local `Player`, while the window, marquee and transport follow the selected output's backend.

## Fix

As planned: refuse, don't switch. `LocalPlaybackGate` in `PlaybackRouter.swift` holds the rule and the single notice text. `playFromLibrary` uses it. `importLocalFiles` refuses before loading and again after `LocalTrackLoader.load` (the output may change during a long load). `openFolder` and `loadPlaylistFile` refuse before showing their panels. `openFiles`/`eject` still show the panel since it also picks skins; `open` still returns true for a refused drop. Doc comments note both. No deviations.
