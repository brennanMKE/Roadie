# 0073 — With several displays a dragged window can stop in a gap or under the menu bar

| | |
|---|---|
| **Status** | open |
| **Module** | App |
| **Platform** | macOS |
| **First seen** | 2026-10-14 |

## Description

`WindowDockingCoordinator.dragBounds` clamps a drag to the work area of the only screen, but with two or more displays it clamps to the bounding box of all screens' `visibleFrame`s, so windows can cross from one display to the next (#0030 Gotchas). That box also covers areas no screen shows:

- Displays of different sizes or offsets leave gaps in the box. A docked EQ or playlist carried by the main window can be left entirely in such a gap; only the dragged window's title bar stays near the cursor.
- If a secondary display sits higher than the primary, the box's top is above the primary's menu bar, so the main window can be dropped with its title bar under the menu bar, where it can no longer be grabbed. The skinned windows are borderless, so AppKit does not constrain them.

`ensureOnScreen()` (Webamp's `ensureWindowsAreOnScreen`) fixes both, but only at launch and on `didChangeScreenParametersNotification`, not at the end of a drag.

## Expected behavior

A window cannot be left where no screen shows it. Candidates: per screen, clamp only the edges that do not border another display (so only real outer edges and the menu bar/Dock attract); or at `dragEnded` pull back any moving window that is not mostly on some screen's work area, without disturbing a window deliberately left straddling two displays. Verify with two displays of different heights and with the secondary above the primary.

## Plan

### Scope and decisions

Keep the union-of-screens drag bounds from #0030 (they are what lets a group cross between displays, since `snapWithin` clamps) and add one invariant on top, as a pure engine rule with tests: **every moving window's title bar stays grabbable on some screen's work area.** When the invariant fails, the moving group is shifted as one onto the nearest screen with the same arithmetic `LayoutRules.recovery` already uses. The rule runs on every drag event (it is a few comparisons over at most three boxes and a handful of screens, so the window never enters a gap or slides under the menu bar) and once more at `dragEnded` as the safety net for the persisted layout. Status stays `open`; this plan writes no code.

**Reference.** Webamp checkout in the session scratchpad (`…/scratchpad/webamp-src/webamp/packages/webamp/js`): `actionCreators/windows.ts` 250–315 (`ensureWindowsAreOnScreen`: the "constant shift" arithmetic at 283–306 that `LayoutRules.recovery` ports), `components/WindowManager.tsx` 53–92 (`snapWithinDiff` against one viewport; Webamp has a single rectangle and no gaps, so there is nothing to port for the gap case itself). Line numbers are to those files.

- **Grabbable means: some screen's `visibleFrame` shows the full height of the window's drag strip over at least `minimumGrabWidth` (50 pt) of its width** (the whole strip when the window is narrower). The strip is the top `titleBarHeight` points of the window: the main/EQ title bar (14 skin px × scale), the playlist's 20 px bar, or the whole 14 px strip in shade, exactly `TitleBarDragView`'s frame height, which the controller exposes. `visibleFrame` already excludes each display's menu bar and the Dock, so "under the menu bar" and "under the Dock" fall out of the same test as "in a gap".
- **A deliberate straddle is not disturbed.** A window across two same-height displays has its full strip height on both, so it is grabbable; a window hanging off the bottom of a screen with its strip on screen is grabbable too (Winamp allows it; the union bounds already stop that on one display). Only a strip that no single screen shows enough of triggers a shift.
- **Shift, never reset, during a drag.** `recovery`'s `.reset` (playlist size to zero, stack, centre) is right at launch and on display changes but would wreck a drag. The drag rule reuses the constant-shift arithmetic when the group's bounding box fits the chosen screen (every window is then fully on it); when the group is taller or wider than that screen, it shifts just enough to show the bounding box's top-left corner (`minimumGrabWidth` × the topmost window's strip height), so the window the user is most likely holding is grabbable, and the rest may hang off. Documented; a group that cannot fit any screen is the one case Webamp gives up on too (310–313).
- **Nearest screen, not the primary.** A window dropped wholly in the gap below a shorter secondary display goes back up onto that display, not across to the primary: `ScreenSelection.nearest` picks the largest intersection as `bounds(for:)` does, and with no intersection the smallest gap (ties to the first screen). Mid-drag this means a window dragged through a gap jumps from one display's edge to the other's as the cursor passes the midpoint, which is how macOS itself treats a titled window; the drag is anchored at mouse-down, so there is no cursor drift.
- **The engine stays pure and AppKit-free.** Screens come in as boxes in desktop space (y down), strip heights as `[WindowKind: CGFloat]`. The union-bounds rule moves from the coordinator into a small `DragLimits` value so it is tested too. `ensureOnScreen` / `recovery` are unchanged in behaviour (a layout saved by an older build with a window under the menu bar is already repaired at launch: its bounding box is not inside any screen's work area, so `recovery` shifts it).

### 1. Engine (`Packages/SkinKit/Sources/WindowDocking/`)

`ScreenSelection.swift`, add:

```swift
/// The screen with the largest intersection with `box` (as `bounds(for:)`); with no intersection the screen with the
/// smallest gap to `box` (dx = max(0, screen.left - box.right, box.left - screen.right), likewise dy, smallest dx²+dy²),
/// ties to the first; `fallback` when `screens` is empty.
public static func nearest(to box: Box, among screens: [Box], fallback: Box) -> Box
```

`LayoutRules.swift`, add (and refactor `recovery` to call `shift(toFit:in:)`; its result for every existing test is unchanged):

```swift
/// How much of a drag strip must show side to side for the window to count as grabbable (all of it when narrower).
public static let minimumGrabWidth: CGFloat = 50
/// True when some screen's work area shows the full height of the window's top `titleBarHeight` points over at least
/// `minimumGrabWidth` of its width. A strip partly under the menu bar, the Dock or in a gap between displays is not.
public static func isGrabbable(_ box: Box, titleBarHeight: CGFloat, on screens: [Box]) -> Bool
/// Webamp's constant shift (actionCreators/windows.ts 283-306): `top <= bounds.top` → down, else `bottom > bounds.bottom`
/// → up; same for x. Shared by `recovery` and `dragRecovery`.
static func shift(toFit bounding: Box, in bounds: Box) -> Offset
/// After (and during) a drag. nil when every window in `moving` is grabbable. Otherwise the offset that moves the group
/// as one onto the nearest screen: the whole bounding box when it fits that screen, else its top-left corner
/// (`minimumGrabWidth` wide, the topmost window's strip tall; ties to the first window). Never `.reset`.
public static func dragRecovery(
    moving: [DockedWindow], titleBarHeights: [WindowKind: CGFloat], screens: [Box], primary: Box
) -> Offset?
```

`isGrabbable`: `strip = Box(x: box.x, y: box.y, width: box.width, height: min(titleBarHeight, box.height))`, `needed = min(strip.width, minimumGrabWidth)`; for each screen, `width = min(strip.right, screen.right) - max(strip.left, screen.left)`, `height = min(strip.bottom, screen.bottom) - max(strip.top, screen.top)`; grabbable when some screen gives `height >= strip.height && width >= needed`. A missing height (`titleBarHeights[kind] ?? 0`) degrades to "the top edge is on screen".

`dragRecovery`: `screenList = screens.isEmpty ? [primary] : screens`; return nil when all grabbable; `bounding = SnapUtils.boundingBoxOrNil(moving.map(\.box))` (nil → nil); `chosen = ScreenSelection.nearest(to: bounding, among: screenList, fallback: primary)`; if `bounding.width <= chosen.width && bounding.height <= chosen.height` return `shift(toFit: bounding, in: chosen)`; else `corner = Box(x: bounding.x, y: bounding.y, width: min(bounding.width, minimumGrabWidth), height: strip height of the topmost window)` and return `shift(toFit: corner, in: chosen)`.

`DragSession.swift`, add:

```swift
/// What limits a drag: where the group's bounding box may go (`snapWithin`), and the screens its strips must stay on.
public struct DragLimits: Sendable {
    public var bounds: Box
    public var screens: [Box]
    public var primary: Box
    public var titleBarHeights: [WindowKind: CGFloat]
    /// `bounds` is the one screen's work area, or with several displays the box they span (#0030: a per-screen bound
    /// would trap a window on its display); no screens → `primary`.
    public init(screens: [Box], primary: Box, titleBarHeights: [WindowKind: CGFloat])
}
/// `positions(forMouseDelta:within:)` followed by `LayoutRules.dragRecovery` on the result, applied to every moving
/// window, so no window can be left in a gap between displays or under a menu bar even mid-drag.
public func positions(forMouseDelta delta: Offset, limits: DragLimits) -> [WindowKind: Offset]
```

The existing `positions(forMouseDelta:within:)` and `groupDiff` stay (their tests stay).

### 6. Risks

- **Per-event shifting feels like a clamp at a gap edge.** That is intended (it is what `snapWithin` already does at outer edges); because the drag is anchored at mouse-down there is no accumulated drift. If the jump across a gap's midpoint is disliked, keep `dragRecovery` only in `dragEnded` (one line to remove from `positions(forMouseDelta:limits:)` and one test to adjust); note the choice in `## Gotchas`.
- **`minimumGrabWidth`.** 50 pt is a guess at "enough to grab": the main title bar's draggable area at 2x is 550 pt wide with 18 pt of buttons on the left and 62 on the right, so 50 pt of visible strip can still be all buttons at the extreme. If the user reports an edge case, raise the constant (it is one value with tests pinned to it); do not add per-window exclusion geometry to the engine.
- **A group that cannot fit** (test 9) only guarantees the topmost window's strip; the others may hang off into a gap. Webamp gives up on this case entirely; acceptable, documented in `## Gotchas`.
- **Fractional `visibleFrame`s.** Screens with a fractional Dock height give fractional work areas; `isGrabbable` compares with `>=`, and positions are not rounded before `setFrameOrigin` (#0030's noted minor). Harmless for grabbability; do not round in the engine.
- **Displays changing mid-drag.** `dragLimits` is recomputed on every event from `NSScreen.screens`, and `dragEnded` re-runs the rule, so the persisted layout is always correct; `ensureOnScreen` still runs on `didChangeScreenParametersNotification` for the stationary windows.
- **Sibling merge with #0072.** Both issues touch the coordinator and the controller in separate methods; additive, rebase and re-run.
