## Description

"As comprehensive as possible" needs a number. No run measures coverage, so nobody knows which files the 1,670 tests never touch. This issue adds `--coverage` to the VM run: coverage on every test step, a per-target report, the twenty least-covered files, floors that fail only the milestone run, and the first gap list filed as follow-ups. Design: [docs/design/test-automation.md](../docs/design/test-automation.md) §2.4.

## Plan

### 1. `scripts/run-tests-vm.sh --coverage`

- Build stage: `swift build --build-tests --enable-code-coverage` for both packages (needed so the profiles are emitted); `xcodebuild … build-for-testing -enableCodeCoverage YES`.
- Test steps: `swift test --skip-build --enable-code-coverage`; `xcodebuild test-without-building -enableCodeCoverage YES` for `app-unit-tests` and, with `--ui`, `ui-tests` (the UI run's coverage of the app counts).
- New step `coverage-report` after the tests: `scripts/coverage-report.sh $GUEST_RESULTS/coverage` (below). Its `coverage/report.md`, `lowest.txt` and `summary.txt` come back with the results. The summary grep adds `^coverage:` lines, and a `COVERAGE` summary line: `==> COVERAGE  SkinKit 88%  PlayerKit 86%  App 63%` (per package: the weighted line coverage of its non-test targets).
- Floors: `--coverage` reads `scripts/coverage-floors.tsv` (`target  floor`), and `coverage-report` exits 1 when a target is under its floor, printing `coverage: FLOOR <target> <pct> < <floor>`. The milestone-end command includes `--coverage`; per-issue runs don't, so floors never block an issue.

### 2. `scripts/coverage-report.sh <out>` (new; runs in the guest)

- Packages: `swift test --skip-build --show-codecov-path --package-path Packages/<P>` gives the JSON path; prefer `xcrun llvm-cov report <test binary> -instr-profile <default.profdata> -ignore-filename-regex 'Tests/|\.build/'` (the binary and profdata paths are next to the codecov JSON under `.build/debug/codecov/`), one row per source file; aggregate per target by path prefix `Sources/<Target>/`.
- App: `xcrun xccov view --report --json build/DerivedData/Logs/Test/*.xcresult` (merge the unit and UI result bundles: `xccov` accepts several; else report both and take the max per file), filter to `App/`.
- Writes `report.md` (table: target, lines, covered, %, floor, status), `lowest.txt` (twenty least-covered non-test source files over 40 lines, with %), `summary.txt` (`coverage: <target> <pct>` lines). Floors from `scripts/coverage-floors.tsv`:

### First coverage run (20261024-232610-35692, `--full --ui --coverage`): failed at coverage-report

- **Every package target came back MISSING.** Two causes, both in the package half of `coverage-report.sh`. (1) SwiftPM (Xcode 27) builds one `<TestTarget>.xctest` per test target (`AudioCoreTests-product`, `SkinBrowserTests-product`, … in the build logs), not one `<Pkg>PackageTests.xctest`; the script's fallback took the first bundle only (`AudioCoreTests`, `SkinBrowserTests`), so `llvm-cov` saw only the targets those tests import. (2) `llvm-cov report` strips the common prefix of the files it lists (`/Users/admin/src/Packages/<P>/Sources/`), so rows read `AudioCore/Player.swift`; `coverage_report.py` keyed on `Sources/<Target>/` and dropped every row. Fix: all test binaries go to one `llvm-cov report <first> -object <rest>…` call, and a relative path with no `Sources/` is keyed by its first component. `scripts/tests/test_coverage_report.py` now parses the two real reports from this run (`scripts/tests/fixtures/coverage/`). A floored target with no files measured now fails the run (`coverage: MISSING`) instead of passing quietly.
- **App 40.5 %** (13,368 lines, 5,411 covered; unit + UI bundles, max per file) against the 60 % goal. The floor is lowered to the baseline, **40 %**; the goal (60 %, then +10 per milestone to 80 %) stays in design §2.4. Package floors were left at their goals until run 20261024-234000-43501 measured them (below).
- The App's twenty least-covered files are all at 0 %: the Settings panes (`MusicAssistantSettingsView` 622 lines, `LibrarySettingsView`, `SkinsSettingsView`, `UpdatesSettingsView`), `JumpToFilePanel`, the Library browser views (`SearchResultsView`, `TrackListView`, `FavoritesView`, `PlaylistTracksView`, `RadioListView`, `AddToPlaylistMenu`), `WelcomeView`, the Museum and skin cells, `PlaylistPickerSheet`, `SystemServiceBrowser`, `MainShadeView`, `LegacyDataCleanup` and `FileInfoPanel`.

App is then reported as `coverage: PARTIAL App <pct> (floor 60% not checked: ui-tests timed out)`, `report.md` marks it `partial`, and the `COVERAGE` line reads `App N% (partial)`. That is not a floor failure on its own; the run still fails on `ui-tests`. `verify.sh` now shows the `COVERAGE` line on a failure too.
- Tests: `scripts/tests/test_ui_timeout.py` (new, in `release-tools`), three partial-App tests in `test_coverage_report.py`, and `test_timeout_is_reported` in `test_verify_report.py` now checks the `TIMEOUT` and partial `COVERAGE` lines.
