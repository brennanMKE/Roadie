# 0257 — The visualization window can't show MilkDrop presets beside the classic ones

| | |
|---|---|
| **Status** | open |
| **Module** | App |
| **Platform** | macOS |
| **First seen** | 2026-10-30 |

## Description

Once [#0243](0243.md) adds `MilkVisualizer`, the window still builds only `ClassicVisualizer` (`VisualizationRendererFactory` logs "MilkMetal isn't linked yet" for `-RoadieVisRenderer milk`), and in Debug the classic renderer pretends to draw `.milk` presets as Classic Spectrum. The navigator should list classic and MilkDrop presets together (design §5.1), each drawn by the renderer that can draw it, with a crossfade when → crosses from one kind to the other.

Split from #0243 on 2026-10-30 (see its `## Notes`). Design: [docs/design/visualization.md](../docs/design/visualization.md) §3.2, §3.3, §3.4, §5.1, §5.2.

## Plan

### `MixedVisualizer`

Keep the model's single-renderer seam (`VisualizationModel.renderer`, `makeRenderer`, `prepareRenderer`, `tick`): add `App/Visualization/MixedVisualizer.swift`, `@MainActor final class MixedVisualizer: VisualizationRenderer`, which owns a `ClassicVisualizer` and an optional `MilkVisualizer` (any `VisualizationRenderer`s, so tests can pass doubles) and routes to them. The model, window controller and host view don't change, except where noted.

- `view`: a container `NSView` with both renderers' views as full-size subviews (`autoresizingMask [.width, .height]`); only the active one is visible (`isHidden`/`alphaValue`). The host view's accessibility (`vis.canvas`) stays on the container; the subviews are not accessibility elements.
- `kindName`: the **active** renderer's (`"classic"` or `"milk"`), so the probe's `renderer` says what's drawing now. Before any load: classic.
- `canLoad`: true when any inner renderer can load it. Without a `MilkVisualizer`, `.milk` presets drop out of the navigator (the model already filters by `canLoad`).
- `load(preset, transition)`: pick the inner renderer whose `canLoad` is true.
  - Same kind as the active one: forward (`try inner.load(preset, transition:)`).
  - Other kind: load it into the incoming renderer first (a throw leaves everything as it was, so the model's failure path keeps the old preset on screen). Whenever MilkDrop becomes the active kind (the first time too), call `MilkVisualizer.reset()` before its `load` (#0243: drops audio queued while it wasn't drawing, so the picture doesn't lag by 0.25 s), and load with `transition: 0` (the blend is the view crossfade). Then crossfade the views over `transition` seconds (`NSAnimationContext` on `alphaValue`, or Core Animation on the layers; 0 cuts, which is what H and Reduce Motion's `accessibility.transition` already decide). The outgoing renderer keeps receiving `feed` and `draw` until the crossfade ends, then is hidden and no longer drawn.
- For the reset, add `func reset()` to `VisualizationRenderer` with a no-op default in a protocol extension (`MilkVisualizer` has it from #0243), so the doubles can count it.
- `feed`: to the active renderer and, during a crossfade, the outgoing one. Not to a hidden one (MilkMetal would queue up to 0.25 s of it).
- `draw(at:)`: the visible renderer(s) only.
- `setReducedMotion`, `setColors`: forwarded to both.
- `problems`: the active renderer's.

### Factory

`VisualizationRendererFactory.make(configuration:colors:)`:
- `-RoadieVisRenderer classic` (Debug, the UI tests' default): `ClassicVisualizer` alone, as today.
- No hook, or `-RoadieVisRenderer milk`: `MixedVisualizer(classic:milk:)` with `MilkVisualizer(device:)` when `MTLCreateSystemDefaultDevice()` is non-nil and the renderer initializes; else `milk: nil` and a `notice` log (`.public` reason). Release always takes this branch.
- An unknown value logs and uses classic, as today.

### The Debug stand-in goes

- `ClassicVisualizer.canLoad` returns false for `.milk` in every configuration, and its `load` no longer maps `.milk` to Spectrum. Update its doc comment and design §3.3's last sentences.
- Tests that relied on it: `RoadieTests` that list or load `.milk` with `configuration.visRenderer = "classic"` (`VisualizationSettingsModelTests.testFolderScanAddsUserPresets`, `.testClearingTheFolderRemovesThemAndKeepsTheCurrentClassic`, and any in `VisualizationListTests`/`VisualizationModelTests` that do the same) switch to a model whose `makeRenderer` returns `MixedVisualizer(classic: ClassicVisualizer(...), milk: StandInMilkRenderer())`, a test double in `Tests/RoadieTests/Support` that accepts `.milk` and records loads. `VisualizationUITests.testPresetsFolderAddsItsPresets` launches without the hook, so it gets the mixed renderer; the seeded presets (`[preset00]\nfRating=3.0`) load in MilkMetal (they have a `key=value` line). Its list rows need a MilkDrop renderer now, so it would fail if the guest ever lost its Metal device: leave it unchanged, so that shows up loudly rather than as a skip.
- `showsPresetsFolder` (Settings' folder row) is still Debug-only here; #0258 shows it in Release.

## Tests

Fast, XCTest, `Tests/RoadieTests/MixedVisualizerTests.swift` (new), with two recording doubles (one classic-only, one milk-only), so no Metal needed; plus one factory test that `XCTSkip`s without a device:
- `testRoutesEachPresetToTheRendererThatCanLoadIt`
- `testCanLoadMilkOnlyWithAMilkRenderer`: `milk: nil` → `.milk` false, classics true.
- `testKindNameFollowsTheActiveRenderer`: classic → milk → classic.
- `testSwitchingKindsSwapsTheVisibleView`: after a cut (transition 0) only the new kind's view is visible; with a blend both are visible, and after the blend time (drive it with a test hook on the crossfade's completion, or `transition: 0.01` and an expectation) only the new one.
- `testAFailedLoadOfTheOtherKindKeepsTheCurrentOne`: the incoming double throws → `kindName` and the visible view unchanged, the error propagates.
- `testHiddenRendererGetsNoFeedOrDraw`: the inactive double records no `feed`/`draw` calls after the crossfade.
- `testMilkIsResetWhenItBecomesActiveAgain`: classic → milk → classic → milk: the milk double's `reset` count is 2, and a milk → milk change doesn't reset.
- `testReducedMotionAndColorsReachBothRenderers`
- `testFactoryBuildsMixedWithAMetalDevice` (skips without Metal): no hook → `MixedVisualizer` whose `canLoad` of a `.milk` preset is true; `testClassicHookBuildsOnlyClassic`: `-RoadieVisRenderer classic` → `ClassicVisualizer`, `.milk` false.
- `ClassicVisualizer`: `testClassicRendererNoLongerLoadsMilkPresets` (in `VisualizationModelTests`): `canLoad(.milk)` false. It fails on the current code (the Debug rule), so run it with `--expect-fail` first.

## By hand

1. Debug build, Settings › Visualization › presets folder with a few `.milk` files: L lists the classics then them; → from Classic Stereo Scope crossfades into the first MilkDrop preset, ← crossfades back; H cuts.
2. Reduce Motion on: crossing kinds is a plain crossfade (Dim Flashing Lights: slower).
3. Cross back and forth a few times on a beat-heavy track: the MilkDrop picture is on the beat each time (no growing lag).
4. Activity Monitor: while a classic preset shows, GPU use is the classic's (the hidden Metal view isn't drawing).
