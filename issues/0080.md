# 0080 — Transport has no Winamp keyboard shortcuts or Playback menu

|---|---|

## Description

The skinned windows ignore Winamp's transport keys. Winamp uses **Z** previous, **X** play, **C** pause, **V** stop, **B** next, left/right arrows to seek 5 s, up/down for volume, **L** open file. SkinAmp's menu bar (`App/SkinAmpApp.swift`) has File and Window commands but no Playback menu, so the transport is only reachable by clicking the skin or with media keys.

Expected: a Playback menu with Previous, Play, Pause, Stop, Next, Seek Forward/Back, Volume Up/Down, Shuffle and Repeat, and the Winamp letter keys working while any skinned window is key. Shortcuts must not fire while a text field (for example Library search or Settings) has focus, and must not clash with existing commands (⌘L, ⌘K, ⌘O and the window shortcuts).

## Plan

### Scope and decisions

This lands after #0078 (options menu) and #0079 (clutter bar). Status stays `open`; this plan writes no code.

- **The bare Winamp keys and the menu shortcuts are separate mechanisms.**
  - **Bare keys** (Z X C V B, the arrows, plus S, R and L) go through `SkinWindow.keyDown(with:)`.
  - **Menu items** use modifier chords.

  A menu key equivalent with no modifier is matched by `NSApp`/`NSMenu.performKeyEquivalent` *before* the focused view's `keyDown`, so a bare "z" in the menu bar would swallow the letter typed into the Library or Skins search field (`.searchable` in `App/Browser/LibraryWindowView.swift:20`, `App/SkinBrowser/SkinBrowserWindowView.swift:16`) or a Settings `TextField`. `SkinWindow.keyDown` runs only at the end of a skinned window's responder chain. Skinned windows hold no text views, so a text field can't lose a key to it: when a text field has focus, its own (non-skinned) window is key and `SkinWindow` never sees the event. That is the "only when a skinned window is key" rule, enforced by where the code sits rather than by a check.
- **The Playback menu uses ⌃⌘ + the Winamp key.** This extends the existing ⌃⌘W / ⌃⌘E / ⌃⌘P shade convention:

  | Item | Menu shortcut | Bare key (skinned window key) |
  |---|---|---|
  | Previous | ⌃⌘Z | Z |
  | Play | ⌃⌘X | X |
  | Pause | ⌃⌘C | C |
  | Stop | ⌃⌘V | V |
  | Next | ⌃⌘B | B |
  | Seek Back 5 Seconds | ⌃⌘← | ← |
  | Seek Forward 5 Seconds | ⌃⌘→ | → |
  | Volume Up | ⌃⌘↑ | ↑ |
  | Volume Down | ⌃⌘↓ | ↓ |
  | Shuffle (checkmark toggle) | ⌃⌘S | S |
  | Repeat (checkmark toggle) | ⌃⌘R | R |
  | (no menu item; File › Open… is ⌘O) | | L, open file (`openFiles(replace: true)`) |

  Why ⌃⌘:
  - It avoids every existing chord: ⌘L, ⌘K (twice: the Skins window scene and Skins › Skin Library…, already duplicated today), ⌘O, ⌥⌘O, ⇧⌘O, ⌘1/2/3, ⌃⌘W/E/P, ⌘[ / ⌘], ⇧⌘R, and the standard ⌘Z/X/C/V/A/W/M/Q/H/,.
  - Plain ⌘Z/X/C/V are Edit commands. ⌘←/→/↑/↓ and ⌥ arrows are text-field cursor moves the menu would steal. ⌃ letters and ⌃ arrows are Emacs bindings and Spaces/Mission Control.
  - ⌃⌘ letters and arrows are not standard text-editing bindings, so they type nothing. Firing them while the Library window is key (search field included) is intended, like ⌘1/2/3.
  - System-reserved ⌃⌘ chords are avoided: ⌃⌘Q lock screen, ⌃⌘F full screen, ⌃⌘D Look Up, ⌃⌘Space emoji. #0079's double size must not take ⌃⌘D either; flag it there if it did.
  - **Before coding, re-grep `keyboardShortcut` across `App/`.** #0078, #0079 (and #0081 and #0082 if they landed) may have added chords. Rebind here, not there, on any clash, and list the final table in `## Fix`.
- **The bare-key rule.** A key maps only when the event's device-independent modifiers contain none of ⌘ ⌃ ⌥ ⇧. Caps Lock is ignored by lowercasing, and arrows' `.function`/`.numericPad` flags are ignored. So ⌘Z, ⌘C and similar still reach the Edit menu. Auto-repeat (`isARepeat`) applies only to the arrows (seek and volume ramp while held). Repeated letters are dropped so holding B doesn't skip through the playlist. Unmapped keys call `super.keyDown`, which keeps today's behaviour.
- **The playlist window keeps its keys.** `PlaylistListInputView.keyDown` (`App/Playlist/PlaylistWindowOverlays.swift:144`) handles Delete and Return and calls `super` for everything else. `super` walks the responder chain (shape view, then the window) to `SkinWindow.keyDown`, so Z/X/C/V/B and the arrows work there too. Webamp's playlist up/down selection is not built yet. Arrows mean volume in every skinned window, as Webamp's global hotkeys do; note this in `## Gotchas`.
- **Semantics:**
  - X → `model.play()`.
  - C → `model.pause()` (already `.togglePlayPause`, Winamp's pause toggle).
  - V → `stop()`, Z → `previous()`, B → `next()`.
  - S → `toggleShuffle()`, R → `toggleRepeat()`.
  - L → `openFiles(replace: true)`.
  - Seek is ±5 s from `mainWindowStatus.elapsed`, clamped to `0...duration`. It is a no-op when `positionFraction == nil` (stopped, loading, unknown length).
  - Volume is ±1 % per press (Webamp's `adjustVolume(±1)` on its 0–100 scale), clamped to 0...1. If a Webamp checkout is at hand, confirm the step in `hotkeys.ts` and note it in `## Fix`.
  - Volume keys set `volume` and send `.setVolume`. They do **not** touch `sliderFocus` or `marqueeOverride`, because `setVolume(_:)` sets those for a drag and expects `endSliderDrag()`.
  - Media keys (#0007, `NowPlayingBridge`) are untouched.

### Files

New:
- `Packages/SkinKit/Sources/SkinKit/Layout/WinampHotkeys.swift`: pure, with no AppKit (SkinKit's other Winamp-semantics types, `MainSliders` and `MainWindowStatus`, live beside it).
  - `public enum WinampHotkey: Sendable, CaseIterable { previous, play, pause, stop, next, seekBack, seekForward, volumeUp, volumeDown, toggleShuffle, toggleRepeat, openFile }`.
  - `static func hotkey(charactersIgnoringModifiers: String, command: Bool, control: Bool, option: Bool, shift: Bool, isRepeat: Bool) -> WinampHotkey?`. Arrows arrive as the AppKit function-key characters `\u{F700}`–`\u{F703}`, so a `String` is enough.
  - `static let seekStep: TimeInterval = 5`, `static let volumeStep: Float = 0.01`.
  - `static func seekTarget(elapsed:duration:forward:) -> TimeInterval?` (nil when `duration <= 0`) and `static func nudgedVolume(_:up:) -> Float`.
- `App/PlaybackCommands.swift`: `struct PlaybackCommands: Commands` with `CommandMenu("Playback")`, modelled on `App/SkinBrowser/SkinsCommands.swift`. The buttons live in a private `View` struct so the menu re-evaluates when observed state changes: Seek is `.disabled(model.positionFraction == nil)`, and Shuffle/Repeat are `Toggle`s bound to `isShuffled`/`isRepeating` with setters calling `toggleShuffle()`/`toggleRepeat()`. Groups are separated by `Divider()`: transport / seek / volume / shuffle-repeat.

Edited:
- `App/PlayerModel.swift`:
  - `func seek(forward: Bool)`: guards `positionFraction != nil`, then `send(.seek(target))` using `WinampHotkeys.seekTarget`.
  - `func nudgeVolume(up: Bool)`.
  - `func perform(_ hotkey: WinampHotkey)`: one switch onto the existing actions. The menu, the keys and #0078's options menu (if it has transport entries, switch them to this) all call it.
- `App/Window/SkinWindow.swift`:
  - Add `var onHotkey: ((WinampHotkey) -> Void)?`.
  - Override `keyDown(with:)`: read `event.charactersIgnoringModifiers` and `event.modifierFlags.intersection(.deviceIndependentFlagsMask)`, call `WinampHotkeys.hotkey(...)`, and on a match call `onHotkey` and return. Otherwise call `super.keyDown(with: event)`.
- `App/Window/SkinWindowController.swift`: in `init`, next to `window.onLeftMouseDown`, set `window.onHotkey = { [weak self] in self?.model.perform($0) }`, matching the `onLeftMouseDown` closure's style.
- `App/SkinAmpApp.swift`: add `PlaybackCommands(model: appDelegate.model)` after `SkinsCommands(...)` in `.commands`, so the menu bar reads … Skins, Playback, Window.
- `docs/` only if a keyboard/shortcuts doc exists by then (none today). Otherwise nothing.

### Tests (Swift Testing, `Packages/SkinKit/Tests/SkinKitTests/WinampHotkeysTests.swift`)

- `lettersMapToTransport`: z/x/c/v/b → previous/play/pause/stop/next; s/r/l → toggleShuffle/toggleRepeat/openFile.
- `capsLockLettersStillMap`: "Z" with no modifier flags maps like "z".
- `arrowsMapToSeekAndVolume`: `\u{F702}`/`\u{F703}` → seekBack/seekForward; `\u{F700}`/`\u{F701}` → volumeUp/volumeDown.
- `modifiedKeysAreIgnored`: ⌘Z, ⌃X, ⌥C, ⇧B, ⌘← and ⌃⌘V all return nil, so the menu chords and Edit commands are never double-handled.
- `repeatsOnlyForArrows`: an `isRepeat` letter returns nil; an `isRepeat` arrow still maps.
- `unmappedKeysAreIgnored`: "a", "1", space, return, delete and an empty string return nil.
- `seekTargetClampsToTrack`: at elapsed 2 of 100, back → 0; at 98, forward → 100; at 50 → 45 / 55.
- `seekTargetNeedsDuration`: duration 0 → nil.
- `volumeNudgeClampsAndSteps`: 0.5 up → 0.51; 1.0 up → 1.0; 0.0 down → 0.0.
