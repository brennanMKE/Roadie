# 0110 — Find Servers in the Library cannot be retried after a search finds nothing

| | |
|---|---|
| **Status** | open |
| **Module** | App / MusicAssistantKit |
| **Platform** | macOS |
| **First seen** | 2026-10-19 |

## Description

Found in review of #0104. In the Library's "no Music Assistant server reachable" state, pressing **Find Servers on This Network** runs discovery. If it finds nothing, the button stays disabled until the banner goes away, so the user can't search again (for example after joining the right Wi-Fi network or starting the server).

Also from the same review, minor: `MusicAssistantSettingsModel.adoptDiscoveredAddress` does not re-check the row's stored `server_id` against the discovered one at the moment it applies the change. The caller only passes matching ids today, so this is harmless, but the model should refuse a mismatch itself.

## Expected behavior

- After a search ends with nothing found, Find Servers is enabled again and starts a fresh search.
- `adoptDiscoveredAddress` changes nothing unless the row's `server_id` equals the discovered server's id, and a test covers the mismatch.

## Plan

Status stays `open`; this plan writes no code. It was written against `main` at 689fc05. #0105 works only in the new `Packages/PlayerKit/Sources/SendspinKit/`, so the two don't overlap.

### 1. Search again (`MusicAssistantDiscovery.swift`, `MusicAssistantDiscoveryViews.swift`)

`MusicAssistantDiscoveryModel.start()`/`stop()` are reference-counted. Settings may hold a `start()` while the banner is up, so a banner-side `stop(); start()` would not restart anything. Add a restart to the model instead:

- Move the body of `start()` after `guard users == 1` (generation bump, the resets, the log line, the well-known probes, the `browser.hosts()` stream and `browseTask`) into `private func beginSearch()`. `start()` becomes `users += 1; guard users == 1 else { return }; beginSearch()`.
- Add `public func searchAgain()` with a doc comment ("Starts a fresh search for whoever already called `start()`; does nothing when no one has, or while a search is running"). The body is: `guard users > 0, !isSearching else { return }`, then `browseTask?.cancel()`, `browseTask = nil`, `for task in probeTasks.values { task.cancel() }`, `probeTasks = [:]`, then `beginSearch()`. `beginSearch()` bumps `generation`, so late results from the old stream are dropped. `users` doesn't change, so a single `stop()` still ends everything.
- In `LibraryDiscoveryBanner`, the button action becomes `if started { discovery.searchAgain() } else { started = true; discovery.start() }`. Replace `.disabled(started)` with `.disabled(started && (discovery.isSearching || !discovery.hasSearched))`, so the button is enabled again once a search goes idle. Keep the title and the `library.findServers` identifier. `.onDisappear` stays as it is (one `stop()`).

### 2. `adoptDiscoveredAddress` checks the server id (`MusicAssistantSettingsModel.swift`, `MusicAssistantDiscovery.swift`, `App/PlayerModel.swift`)

- Change the signature to `public func adoptDiscoveredAddress(_ url: URL, for id: UUID, serverID: String)`. Extend the guard to `guard let index = …, servers[index].address.serverID == serverID, servers[index].address.baseURL != url else { return }`. Update the doc comment to say it changes nothing unless the row's stored `server_id` equals `serverID`.
- Change `onConfiguredServerMoved` to `(@MainActor (_ id: UUID, _ serverID: String, _ url: URL) -> Void)?`. In `handle(_:at:purpose:)` `.storedCheck`, call `onConfiguredServerMoved?(id, serverID, newURL)`.
- In `App/PlayerModel.swift` (around line 357), the closure becomes `{ … id, serverID, url in settings?.adoptDiscoveredAddress(url, for: id, serverID: serverID) }`.
- Tests that need updating for the new signatures:
  - `DiscoveryRig.moves` becomes `[(UUID, String, URL)]` and the hook appends `($0, $1, $2)`.
  - In `configuredServerAtNewAddressIsReportedWhenItsStoredAddressFails`, check `.1 == "id-x"` and `.2 == DiscoveryRig.wellKnown`.
  - In `adoptDiscoveredAddressMovesOnlyTheMatchingServer`, pass `serverID: "id-a"`.

### Tests to add

- `searchAgainProbesAfreshAfterAnEmptySearch`: the well-known host `.fail`s. `start()`, `settle(calls: 1)`, then expect `hasSearched`, `!isSearching` and no offers. Set the well-known host to `.answer("id-x")`, call `searchAgain()` and `settle(calls: 2)`. Expect `fake.calls.count == 2`, one offer with id `id-x`, `browser.started == 2`, `browser.terminated == 1`. Then a single `stop()` terminates the second browse (`pollUntil { browser.terminated == 2 }`).
- `searchAgainDoesNothingWithoutStartOrWhileSearching`: `searchAgain()` before `start()` means no fetches and `browser.started == 0`. With the well-known host `.hang`, `start()`, wait for 1 call, then `searchAgain()` leaves `browser.started == 1` and `fake.cancelled` empty. Then `stop()`.

Check the `StubServiceBrowser` `started`/`terminated` counters behave as above across two `hosts()` calls; adjust the stub if it supports only one stream.
