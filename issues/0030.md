## Description

Snap and dock the main, EQ and playlist windows together like Winamp and persist positions, queue and EQ settings.

## Acceptance criteria

- Port snapping logic from Webamp's `snapUtils.ts`.
- State restores on relaunch.

## Plan

### Scope and decisions

Three parts, in this order: a pure docking engine in a new package target (ports of Webamp's `snapUtils.ts` and `resizeUtils.ts`, plus the layout/recovery rules from `actionCreators/windows.ts`), a coordinator in `App/Window/` that owns every skinned window's position and drives the engine from the `TitleBarDragging` hook that #0025 left for this issue, and persistence of the window layout, the queue and the EQ settings. Status stays `open`; this plan writes no code.

**Ordering.** This issue lands after #0028 (EQ window) and #0029 (playlist window) exist, and before or alongside #0031 (shade). The engine and its tests do not depend on them. The coordinator needs windows to coordinate: it is written against the main window first (snapping to screen edges, persistence, off-screen recovery all work with one window) and registers the EQ and playlist windows through the small contract in section 2, which #0028/#0029 adopt in one or two lines each. If a sibling has not merged when this is implemented, the registration line for that window waits for it; nothing else does.

**Webamp reference.** `References/webamp` is gitignored and absent. The planner read `captbaritone/webamp@master`, `packages/webamp/js/`, from the session scratchpad (`…/scratchpad/webamp-src/webamp`): `snapUtils.ts`, `snapUtils.test.ts`, `resizeUtils.ts`, `resizeUtils.test.ts`, `components/WindowManager.tsx`, `reducers/windows.ts`, `actionCreators/windows.ts`, `selectors.ts` (468–482, 509–549, 612–623), `utils.ts` (339–355), `types.ts` (25–45, 772–800), `constants.ts` (41–44). Line numbers below are to those files. Re-fetch with `curl -sS -f -o <dest> https://raw.githubusercontent.com/captbaritone/webamp/master/packages/webamp/<path>` into an empty scratchpad directory, never under the repo.

- **The engine is pure, Foundation + CoreGraphics only, in a new target `WindowDocking` in `Packages/SkinKit`** (`.library(name: "WindowDocking")`, `.testTarget(name: "WindowDockingTests")`). No AppKit, no `NSScreen`, no `UserDefaults.standard`: screens come in as boxes, the store takes a `UserDefaults` instance. `swift test --package-path Packages/SkinKit` (the VM script's first step) picks the new test target up with no script change. SkinKit itself is not touched; the target is a sibling because it is window geometry, not skin data.
- **Coordinates: the engine works in Webamp's space, y down, in points.** `Box {x, y, width, height}` with `y` growing downward from the top-left of the primary screen. One converter (`DesktopSpace`, in the engine, tested) flips to and from AppKit: `box.y = primaryTop - frame.maxY`, where `primaryTop = NSScreen.screens[0].frame.maxY` (the primary screen's origin is `(0, 0)`). Every algorithm is then a line-for-line port with Webamp's test values; nothing in the engine is flipped by hand.
- **`SNAP_DISTANCE` is 15 points, unscaled** (`snapUtils.ts` 3). Webamp compares pixel boxes that already include the doubled size and keeps 15; so do we, with the window's point size (skin pixels × `model.scale`). Not 15 × scale.
- **The drag is anchored at the mouse-down point, not incremental.** Webamp computes `proposedDiff = mouse - mouseStart` and applies it to the positions captured at mouse-down (`WindowManager.tsx` 53–92). #0025's `TitleBarDragView` instead adds each movement to the *current* frame, which with snapping would make the window stick and the cursor drift. Change the view to keep `startOrigin` and `mouseStart` from `mouseDown` and propose `startOrigin + (mouse - mouseStart)`; the `TitleBarDragging` signature stays as it is.
- **Only the main window drags its docked group; a child drags alone and so detaches** (`WindowManager.tsx` 139–147: `movingSet = traceConnection(abuts)(windows, main)` for `main`, else `{target}`). "Docked" is Webamp's `abuts` (10–15): `snap(a, b)` yields an `x` or a `y`, i.e. within `SNAP_DISTANCE`, overlapping included (their TODO; kept). The group's snap is `snapDiffManyToMany(moving, stationary)` and the group's bounding box is snapped within the screen (`snapWithinDiff`); the two diffs and the proposed diff combine with `applyMultipleDiffs` (69–92). Hidden windows (closed or miniaturized) are neither moving nor stationary (131–133).
- **The group moves as one window.** At `dragBegan` on main the coordinator makes each other moving window a child of the main `NSWindow` (`addChildWindow(_:ordered: .above)`); during the drag only main's origin is set and the window server moves the children with it, so the group never tears; at `dragEnded` the children are removed again. Child status exists only for the duration of a drag, so AppKit's "children follow the parent" rule never fights the engine.
- **Size changes keep the edge graph** (`withWindowGraphIntegrity`, `actionCreators/windows.ts` 22–50): capture `generateGraph(windows)` before the change, apply it, compute `getPositionDiff(graph, sizeDiff)` after, move the windows that were below/right of the grown or shrunk one. Webamp wraps double-size and the three shade toggles in it (52–79) and does **not** wrap the playlist's drag-resize (`PlaylistResizeTarget.tsx` 19–21 dispatches `setWindowSize` directly), so: `model.scale` changes and #0031's shade toggles go through `coordinator.resize { … }`; #0029's resize does not push neighbours (it only re-saves the layout). Positions are top-left anchored, which `SkinWindowController.applyLayout` already does.
- **Screen-edge snapping and multi-screen.** `snapWithin` is generalized to a bounds box with an origin (Webamp's viewport is always at `(0, 0)`, 87–103); the bounds are the `visibleFrame` (menu bar and Dock excluded, like Winamp's work area) of the screen with the largest intersection with the proposed group bounding box, falling back to the dragged window's current screen, then the primary. Crossing between screens is therefore free; only the chosen screen's edges attract.
- **Persistence is one Codable `WindowLayout` under one `UserDefaults` key,** shaped like Webamp's `WindowLayout` (`types.ts` 772–800): per window `left`/`top` (points, desktop space), `shade`, `closed`, and for the playlist `size` as resize segments `[w, h]` (`constants.ts` 41–42: 25 × 29 skin px per segment; the stored unit is segments so #0029's increments and the 2x scale do not matter to the store). `setFrameAutosaveName("MainWindow")` goes away: two authorities over one window's frame is how positions get lost. The old autosaved frame seeds the first layout once (see section 3).
- **Restore runs Webamp's `ensureWindowsAreOnScreen`** (250–315) at launch and on `NSApplication.didChangeScreenParametersNotification`: nothing if the layout is visible, a constant shift if the group fits a screen, else reset the playlist size, stack and centre (`stackWindows` 198–204, `getStackedLayoutPositions` `selectors.ts` 612–623, `centerWindows` 144–178 with `ceil`). The same stack-and-centre is the first-launch layout, with all three windows open like Webamp's defaults (`reducers/windows.ts` 36–70: `open: true`); the EQ/playlist `closed` flags then replace `PlayerModel.isEQWindowOpen`/`isPlaylistWindowOpen` as the persisted source of truth.
- **Queue and EQ persist too** (docs/plan.md M5 item 3): `EQState` is already `Codable`; it goes under a `UserDefaults` key. The queue (`Track` gains synthesized `Codable`) goes to a JSON file in Application Support, since a queue can be thousands of tracks. Both restore before the first window shows; the queue restores stopped at its saved index, never auto-playing (Winamp reads `winamp.m3u` the same way). If #0028 ships its own EQ persistence first, this issue adopts its key rather than adding a second.
- **Z-order moves as a set.** When any skinned window becomes key, the other visible skinned windows are ordered directly beneath it (`orderWindow(.below, relativeTo:)`), so clicking the player brings EQ and playlist forward with it, as Winamp's owned windows do. One method in the coordinator; no child windows outside drags.

public struct Box: Equatable, Hashable, Sendable, Codable {

`SnapUtils.swift` (`public enum SnapUtils`), one function per Webamp export, with the quirks and their line numbers in doc comments so a later "fix" is a deliberate divergence:
- `snapDistance: CGFloat = 15` (3); `near(_:_:)` is strict `<` (10); `overlapX/overlapY` use `<=` plus `snapDistance` (13–16).
- `snap(_ a: Box, to b: Box) -> SnapResult` (19–47): the four x cases in that order (left→right, right→left, left→left, right→right) only when `overlapY`; the four y cases only when `overlapX`; first match wins per axis.
- `snapDiff(_:_:) -> Offset` (49–55): `0` where the axis did not snap.
- `snapDiffManyToMany(_ as: [Box], _ bs: [Box]) -> Offset` (58–72): `x = x || diff.x` keeps the **first non-zero** per axis; the early `break` fires only when both are **positive** (66), so a negative snap keeps scanning but is never replaced. Ported as written.
- `snapWithin(_ box: Box, in bounds: Box) -> SnapResult` (87–103), generalized to `bounds.x`/`bounds.y`: `x = bounds.x` when `box.x - 15 < bounds.x`, else `bounds.maxX - width` when `box.maxX + 15 > bounds.maxX`; same for y. With `bounds` at `(0, 0)` it is Webamp's function. `snapWithinDiff` (105–111).
- `applyDiff(_:_:)` (169–172) and `applyMultipleDiffs(_ initial: Offset, _ diffs: Offset...) -> Offset` (175–183): per axis, zero yields to the other, otherwise `min` (signed, not absolute; their TODO, kept).
- `boundingBox(_ boxes: [Box]) -> Box` (123–149), precondition non-empty; `boundingBoxOrNil` for the recovery path (`utils.ts` 339–355).
- `traceConnection(_ candidates: [DockedWindow], from node: DockedWindow, areConnected:) -> Set<WindowKind>` (151–167): depth-first, a candidate joins once; `abuts(_:_:)` = `snap(a, b)` has a non-nil axis (`WindowManager.tsx` 10–15).
- Not ported: `snapToMany` and `applySnap` (unused by `WindowManager`).

`WindowGraph.swift` (`resizeUtils.ts`): `Edges { below: WindowKind?; right: WindowKind? }` where `below: X` means "this window's top is X's bottom" and `right: X` "this window's left is X's right" (87–141: exact edge equality, and the other axis must overlap, with strict `<`/`>` on the non-overlap test). `generateGraph(_ windows: [DockedWindow]) -> [WindowKind: Edges]`; `positionDiff(graph:sizeDiff: [WindowKind: (width, height)]) -> [WindowKind: Offset]` (24–75): invert the graph, then walk down from every node with no `below` and right from every node with no `right`, accumulating `diff + parent's diff`. Boxes are rounded to whole points before graph generation so a `visibleFrame` fraction cannot break edge equality.

`DragSession.swift`: the port of `useHandleMouseDown` (`WindowManager.tsx` 29–156), as a value.

```swift
public struct DragSession: Sendable {
    public let moving: [DockedWindow]        // positions at mouse-down
    public let stationary: [DockedWindow]
    public let boundingBox: Box
    /// `windows` = the visible skinned windows; main brings its connected group, anything else moves alone.
    public init(dragging kind: WindowKind, windows: [DockedWindow])
    /// Positions for a cumulative mouse delta since mouse-down, snapped to the stationary windows and
    /// within `bounds` (the chosen screen's visible frame). Pure; call it on every mouseDragged.
    public func positions(forMouseDelta delta: Offset, within bounds: Box) -> [WindowKind: Offset]   // top-left per moving window
    public func groupDiff(forMouseDelta: Offset, within: Box) -> Offset                                 // what the coordinator applies to main
}
```

`ScreenSelection.swift`: `bounds(for box: Box, among screens: [Box], fallback: Box) -> Box` picks the largest intersection area; ties go to the first; no intersection gives `fallback`.

`WindowLayout.swift` + `LayoutRules.swift`:

```swift
public struct WindowLayout: Codable, Equatable, Sendable {
    public struct Entry: Codable, Equatable, Sendable {
        public var left: CGFloat, top: CGFloat       // desktop space, points
        public var shade = false, closed = false
        public var size: [Int]?                      // playlist only: resize segments [w, h], like Webamp's size tuple
    }
    public var version = 1
    public var windows: [WindowKind: Entry]
}
public enum LayoutRules {
    /// selectors.ts 612–623 + actionCreators/windows.ts 144–178: stack the open windows at x 0 in `order`, then centre the group in `bounds` (ceil).
    public static func stackedAndCentered(sizes: [WindowKind: CGSize], order: [WindowKind], in bounds: Box) -> [WindowKind: Offset]
    /// actionCreators/windows.ts 250–315, generalized to several screens. nil = nothing to do.
    public static func recovery(windows: [DockedWindow], screens: [Box], primary: Box) -> Recovery?
    public enum Recovery: Equatable { case shift(Offset); case reset }   // reset = playlist size 0, stack, centre on primary
}
```

`recovery`: "good" when the group bounding box lies within one screen's visible frame, or when every window individually lies within some screen (a group straddling two displays is fine). Otherwise, if the bounding box fits the chosen screen (largest intersection, else primary), `shift` by Webamp's constant offset (283–306: `moveY = top` when `top <= bounds.y`, else `bottom - bounds.maxY`; same for x). Otherwise `reset`.

`WindowLayoutStore.swift`: `public struct WindowLayoutStore { init(defaults: UserDefaults, key: String = "windowLayout"); func load() -> WindowLayout?; func save(_:) }`, JSON via `JSONEncoder`/`JSONDecoder`; a corrupt value or an unknown `version` loads as `nil`; unknown window kinds in the JSON are dropped, not fatal (decode into `[String: Entry]` and filter), so a later window kind does not brick older builds.

`DesktopSpace.swift`: `public struct DesktopSpace { let primaryTop: CGFloat; func box(_ rect: CGRect) -> Box; func rect(_ box: Box) -> CGRect }`.

### 2. App: coordinator (`App/Window/`)

New `App/Window/WindowDockingCoordinator.swift`:

```swift
@MainActor
final class WindowDockingCoordinator: NSObject, NSWindowDelegate {
    init(model: PlayerModel, store: WindowLayoutStore = .init(defaults: .standard))
    /// #0028 / #0029 / the main window register here; the coordinator becomes each window's delegate.
    func register(_ controller: SkinWindowController)
    /// Size changes that keep docked edges (scale, shade). The playlist's drag-resize calls `layoutDidChange()` instead.
    func resize(_ change: () -> Void)
    func setOpen(_ kind: WindowKind, _ open: Bool)   // show/hide + persist; main's close keeps #0025's hide behaviour
    func restoreOrDefaultLayout()                    // called once from AppDelegate before the first show
    func ensureOnScreen()                            // launch + didChangeScreenParameters
    func layoutDidChange()                           // persist (coalesced to the next run loop turn)
    // TitleBarDragging, forwarded by every SkinWindowController:
    func dragBegan(_ kind: WindowKind); func drag(_ kind: WindowKind, to proposedOrigin: NSPoint); func dragEnded(_ kind: WindowKind)
}
```

Contract for the skinned windows (what #0028/#0029 adopt): a window is a `SkinWindowController` (or shares its `TitleBarDragging` forwarding) with a `kind: WindowKind`, a `window: SkinWindow`, a `skinSize` (points = skin px × scale, so the coordinator can build `DockedWindow`s from `window.frame`), and an `applyLayout()`. `SkinWindowController` gains `let kind: WindowKind` (main by default) and `weak var coordinator`; its three `TitleBarDragging` methods forward to the coordinator when set and keep today's `setFrameOrigin` fallback when not (previews, #0026's offscreen render). Its `observe()` keeps reacting to `model.skin` (same size, no graph work) but no longer to `model.scale`: the coordinator observes `model.scale` and re-applies every registered window's layout inside `resize { }`. `window.setFrameAutosaveName`/`setFrameUsingName` are removed from `SkinWindowController`; `show()` no longer centres.

Drag: `dragBegan(kind)` builds `DragSession(dragging: kind, windows: visible)` from `DesktopSpace`-converted frames, records `startOrigin` of the dragged window, and for `.main` adds the other moving windows as children. `drag(kind, to:)` converts `proposed - startOrigin` to a y-down `Offset`, picks `bounds` with `ScreenSelection` over `NSScreen.screens.map { visibleFrame }`, applies `session.groupDiff` to main (children follow) or `session.positions` to the lone window. `dragEnded` removes the children and calls `layoutDidChange()`.

`resize`: `before = generateGraph(visible)` and the sizes; run `change`; `diff = positionDiff(graph: before, sizeDiff:)`; `setFrameOrigin` on the moved windows (rounded); persist.

`setOpen`: EQ/playlist `performClose` and the main-window toggle buttons route here. `PlayerModel.isEQWindowOpen`/`isPlaylistWindowOpen` become computed from the coordinator's layout (the model keeps the API the toggle buttons use; `toggleEQWindow()` calls `coordinator.setOpen`). Main's close keeps hiding the app's windows as #0025 decided, and ⌘1 restores the layout.

`restoreOrDefaultLayout`: `store.load()` → place windows, apply `shade` through #0031's hook when present, `size` through #0029's, `closed` through `setOpen`; then `ensureOnScreen()`. No layout: if `UserDefaults` still has `NSWindow Frame MainWindow` (the #0025 autosave), parse its first two numbers as main's origin and stack EQ and playlist below it; otherwise `LayoutRules.stackedAndCentered` on the primary screen's `visibleFrame`, order `[main, equalizer, playlist]` (`getNormalizedWindowOrder` puts main first). Delete the old autosave key after seeding.

`ensureOnScreen`: `LayoutRules.recovery` → `.shift` moves every visible window by the offset; `.reset` sets the playlist size to `[0, 0]`, stacks and centres.

Z-order: as each registered window's delegate, `windowDidBecomeKey` orders the other visible skinned windows directly below the key one.

`App/Window/SkinShapeView.swift`: `TitleBarDragView` keeps `startOrigin`/`mouseStart` from `mouseDown` and proposes `startOrigin + (NSEvent.mouseLocation - mouseStart)`; `lastMouse` goes.

`App/AppDelegate.swift`: owns `docking = WindowDockingCoordinator(model:)`, registers `player`, calls `restoreOrDefaultLayout()` before `player.show()`, observes `NSApplication.didChangeScreenParametersNotification` → `ensureOnScreen()`, and in `applicationWillTerminate` flushes the layout, the queue and the EQ.

### 7. Risks

- **Child windows during a drag.** `addChildWindow` also orders the child above its parent and brings it along on `orderFront`; both are harmless for the drag's duration, but the children must be removed in `dragEnded` *and* in `windowDidResignKey`/`windowWillClose` of main (a drag can end with a lost mouse-up). If AppKit visibly lags children on fast drags on the VM's or the user's macOS, fall back to setting each moving window's origin per event (the engine already returns per-window positions). Note the choice in `## Gotchas`.
- **Edge equality after conversion.** `generateGraph` needs `bottom == top` exactly; `visibleFrame` and backing-scale conversions can produce fractional points. Boxes are rounded before graph generation and `setFrameOrigin` receives rounded points. Test 17 covers the engine; check (5) covers the app.
- **Two sources of truth for open windows.** `PlayerModel.isEQWindowOpen` and `isPlaylistWindowOpen` (#0023) and the EQ/playlist windows' own close buttons (#0028/#0029) must all go through `setOpen`, or the toggle buttons and the persisted `closed` flags drift. Review this when rebasing on the siblings.
- **`ensureWindowsAreOnScreen` is coarse.** Webamp gives up with a full reset when the group does not fit; on a small screen with a tall playlist that is a visible jump at launch. Acceptable and faithful; `reset` is the documented behaviour.
- **Queue restore and Plex.** A restored Plex track's `partKey`/`cacheKey` may be stale (server library changed); play then fails with the usual transport error in `errorMessage`, nothing worse. `Track.id` is regenerated on decode only if it collides; it is stored so the pinner's keys keep matching.
- **Sibling merges.** `SkinWindowController.swift` is edited by #0031 (shade) and the EQ/playlist controllers by #0028/#0029; this issue's edits to each are the `kind`/`coordinator` forwarding and one `register` call. Rebase, re-run the VM script, do not re-plan.
- **`model.scale` observation moves.** Removing `model.scale` from `SkinWindowController.observe()` must not leave the main window unscaled when there is no coordinator (previews, #0026's offscreen render): keep the fallback path that re-applies on scale when `coordinator == nil`.

## Root cause

Each skinned window moved independently with an incremental `setFrameOrigin` (the `TitleBarDragging` hook #0025 left for this), nothing knew about the other windows or the screen edges, and the only persistence was AppKit's per-window frame autosave, which ignored docking, display changes and size changes of neighbours.

## Fix

Plan followed with these adaptations to the landed code (#0028, #0029, #0031):
- New SkinKit target `WindowDocking` (`Geometry`, `SnapUtils`, `WindowGraph`, `DragSession`, `DesktopSpace`, `ScreenSelection`, `LayoutRules`, `WindowLayout` + `WindowLayoutStore`): ports of `snapUtils.ts`, `resizeUtils.ts` and the recovery/stack rules, quirks kept. App side is `App/Window/WindowDockingCoordinator.swift`; `SkinWindowKind` gained `windowKind`, `SkinWindowController` gained `coordinator` and `isPositioned` and forwards the three `TitleBarDragging` calls. `TitleBarDragView` is now anchored at mouse-down.
- `applyLayout()` (made internal) is the hook, as #0031 said: when the scale or the shade mode changed on a visible window it runs inside `coordinator.resize(...)`, which moves windows docked below/right by the size difference. Playlist drag-resize (steps change only) does not push neighbours, as in Webamp. Since each controller observes the model separately, a scale change re-lays out the windows one after another; each step keeps the graph, so the result is the same as one combined change.
- Persisted layout holds positions only (`windowLayout` key, `{version, windows:{main:{left,top},...}}`, desktop space y-down). Open/closed, shade, playlist size (`playlistWindowSize`) and EQ (`equalizer` key) already persist in `PlayerModel`/`PlaylistModel` (#0028/#0029/#0031), so the plan's `closed`/`shade`/`size` fields and `eqState` were not added.
- Group move is done by setting every moving window's origin per event (the engine returns per-window positions, the plan's stated fallback), not with child windows; so there is no child-window cleanup to fail.
- Multi-display: dragging clamps to the work area of one screen when there is one, and to the bounding box of all screens' work areas when there are several (the plan's "largest-intersection screen" bounds would have clamped a window to its first display and made crossing impossible). `ScreenSelection` is used for recovery.
- Launch: `restoreOrDefaultLayout()` (saved layout; else the old `NSWindow Frame ...` autosave values, read once and deleted; else stack/centre main plus the open windows on the primary work area) runs before `player.show()`; windows without a position still sit under their reference on first show (existing behaviour). `ensureOnScreen()` runs after the windows show and on `didChangeScreenParametersNotification`. `applicationWillTerminate` saves.
- Not done, by decision: queue persistence (`QueueStore`/`Track: Codable`/`Player.restoreQueue`) touches PlayerKit and the model's init and is a separate risk; left out, window positions/open state/EQ are the core. Also not done: key-window z-order grouping (windows are not raised together). Both are worth separate issues.
