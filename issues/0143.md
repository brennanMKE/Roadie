## Root cause

SkinAmp never called `music/recommendations` or `music/recommendations/items`. The backend API had no way to describe a recommendation row, so the Library had no Discover group.

## Fix

- `MusicBackendKit`: a new `Recommendations.swift` holds `RecommendationRow` and `RecommendationItem`. `RecommendationItem` covers artist, album, track and playlist; anything else is `.other`, which carries a slim mapping and is played by URI. `MusicBackend` gains the `.recommendations` capability and `recommendationRows()`, `recommendationItems(_ row:)` and `resolve(_:)`. Their defaults are unsupported and identity. They take the row itself, not its id, because an `item_id` can contain `/`.
- `MusicAssistantKit`: `Models/MARecommendations.swift` holds `MARecommendationFolder` (lenient: only `item_id` is required, and `enabled_by_default` defaults to true) and `MARecommendationItem`. Items are decoded by `media_type`. An item that doesn't decode falls back to `ItemMapping`, and anything else becomes `.unknown` and is dropped, so one bad item never fails a row. The same file adds the `MARequest` builders. `MusicAssistantBackend+Discover.swift` holds the rows, the items, and `resolve` through `music/item_by_uri`. `requireClient`/`guarded` are now internal instead of private.
- `LibraryBrowser`: `DiscoverRows`, `MDIIcon.symbol` (falls back to `sparkles`), and `DiscoverModel`. The model loads rows once per session and loads, refreshes and fails each row on its own, with stale results dropped by generation. It has Show all rows (UserDefaults `discover.showAllRows`), `selectedRowID`, and a debounced `scheduleRefresh()` (1.5 s). `LibrarySection.discover`, `LibraryBrowserModel.discover` and `select(discoverRow:)` are added, and rows load on connect.
- App: the sidebar has a "Discover" section with the rows (SF Symbol icons, provider tooltip) and a Show all rows checkbox. `DiscoverView.swift` shows the row's items. It has Play All and Refresh, double-click plays, the context menu has Play and Add to Queue, and an empty row shows "Nothing here yet". Add to Playlist is waiting for W3 (#0135/#0136). Favorite is waiting for #0141, which can call `resolve(_:)`. The `.played` server-event hook waits for W5; for now a play from Discover schedules the refresh.
