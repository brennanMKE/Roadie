## Description

In #0212's run `20261029-191545-21712`, #0202's UI tests left `MainShadeView` at 98.4 %, `FileInfoPanel` at 100 % and `SkinWindowController` at 95 % (323 of 340 lines). Two gaps remain. `LegacyDataCleanup` (79 lines) is at 0 %: no test runs it, and it needs an injectable Keychain and caches root before one can (#0211's follow-up `LegacyDataCleanupTests`). `WindowDockingCoordinator` is at 83.2 % (237 of 285): the default layout for a first launch (`stackDefaultLayout`), the seeding from the pre-docking autosaved frames (`seedFromLegacyFrames`, `SkinWindowKind.legacyAutosaveName`), and the off-screen and end-of-drag branches of `ensureOnScreen`, `drag(_:to:)` and `dragEnded(_:)` never run. This issue tests both.

## Root cause

Nothing tested `LegacyDataCleanup` or `WindowDockingCoordinator`'s launch and drag paths. `LegacyDataCleanup.run` could not run in a test: it called the real Keychain and deleted under `URL.cachesDirectory`. `SkinCursorController.step(at:)` only runs while an animated cursor is showing, so its coverage depended on timing.

The first attempt bailed after three failed runs (`## Notes`). Three cleanup tests called the file's private helper `run(onCacheRemoved:)` as a bare `run()`. In an `XCTestCase` that resolves to `XCTest.run()`, which starts the test run again ("Invalid attempt to start a test run that has already been started", or the "freed pointer" crash). The cache test passed because it called the helper with an argument. In the first run `testDragEndDocksWithinThreshold` also failed (equalizer at 290 instead of 216, layout delta -26 instead of -100). Its starting layout let the drag snap to something other than the main window's bottom edge.

## Fix

- `LegacyDataCleanup.run` takes `removeKeychain: () -> String` (default: the real attribute-only `removeKeychainItems()` query), `cachesRoot: URL` (default `.cachesDirectory`) and `onCacheRemoved`, which runs after the detached cache removal finishes. Production call sites are unchanged.
- `LegacyDataCleanupTests` runs the cleanup on a throwaway defaults suite and a temp caches root with a stub Keychain remover that counts its calls. The helper is `runCleanup(onCacheRemoved:)`. The first attempt's workarounds (a note about async setUp and a `Counter` box) are gone; the count is a plain stored property.
- `WindowDockingCoordinatorTests` (named so it doesn't clash with the `WindowDocking` package's `WindowDockingTests`) builds the three `SkinWindowController`s on an isolated model and covers plan steps 2 and 3. The first-launch test also checks that the group is centred on the primary screen's work area, and the `show()` test that the window is centred horizontally. The drag test now puts the main window near the top centre of the screen with the equalizer 40 points below it, so every edge is beyond the snap distance from the screen's. The first drag ends undocked at that gap; the second ends 5 points below and docks.
- `SkinCursorController.step(at:)`'s frame choice is the pure `nonisolated static stepFrame(at:steps:frameCount:)` (wrap, clamp to the built frames, at least one 60 Hz interval). `SkinCursorControllerTests.testCursorStepWrapsAndClampsFrames` drives it with explicit steps.
- Remaining gap: `step(at:)`'s timer and `NSCursor.set()` lines still run only with an animated `SkinCursor`, whose init is internal to SkinKit, so their coverage still depends on timing. Plan step 3 ran headless, so nothing is left for `## Notes` there.

## Gotchas

- Never name an `XCTestCase` helper `run`, especially one whose arguments all have defaults: a bare `run()` calls `XCTest.run()`. `PlayerModelDispatchTests.run(_:local:speaker:perform:)` is safe only because its arguments are required.
- Drag tests on a real screen must keep every window edge beyond the snap distance from the screen's edges, or the drag snaps there instead.

   - a drag that ends undocked and one that ends within the snap threshold: `dragEnded` stores the layout either way, and docks only the second
   The geometry rules themselves are already tested in `WindowDocking`; these check the coordinator's use of them.
3. `SkinWindowController.windowDidChangeBackingProperties(_:)` and the `show(below:)` branch with no reference window, if they can run headless; else note them under `## Notes`.
