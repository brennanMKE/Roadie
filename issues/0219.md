## Description

In #0212's run `20261029-191545-21712`, #0202's UI tests left `MainShadeView` at 98.4 %, `FileInfoPanel` at 100 % and `SkinWindowController` at 95 % (323 of 340 lines). Two gaps remain. `LegacyDataCleanup` (79 lines) is at 0 %: no test runs it, and it needs an injectable Keychain and caches root before one can (#0211's follow-up `LegacyDataCleanupTests`). `WindowDockingCoordinator` is at 83.2 % (237 of 285): the default layout for a first launch (`stackDefaultLayout`), the seeding from the pre-docking autosaved frames (`seedFromLegacyFrames`, `SkinWindowKind.legacyAutosaveName`), and the off-screen and end-of-drag branches of `ensureOnScreen`, `drag(_:to:)` and `dragEnded(_:)` never run. This issue tests both.

## Plan

1. `LegacyDataCleanup.run`: inject a Keychain remover (`() -> OSStatus`, defaulting to the real `SecItemDelete` query) and a caches root URL. Test file: `Tests/RoadieTests/LegacyDataCleanupTests.swift`. Check that:
   - the Plex defaults keys and a stored `plex` source are removed and a `folder` choice is kept
   - the `Tracks` cache directory under the injected root is deleted
   - `versionKey` makes the second run a no-op
   - the real Keychain is never touched in tests
2. `Tests/RoadieTests/WindowDockingTests.swift`, with the three `SkinWindowController`s built off screen with a base skin:
   - no stored layout and no legacy frames: `restoreOrDefaultLayout` stacks main, EQ and playlist under each other (`stackDefaultLayout`)
   - legacy autosaved frames under each `legacyAutosaveName` and no stored layout: the windows take those frames (`seedFromLegacyFrames`)
   - a window moved off every screen: `ensureOnScreen` brings it back
   - a drag that ends undocked and one that ends within the snap threshold: `dragEnded` stores the layout either way, and docks only the second
   The geometry rules themselves are already tested in `WindowDocking`; these check the coordinator's use of them.
3. `SkinWindowController.windowDidChangeBackingProperties(_:)` and the `show(below:)` branch with no reference window, if they can run headless; else note them under `## Notes`.

- 2026-10-29: `App/Window/SkinCursorController.swift` fell from 94.7 % (run 20261029-191545-21712) to 70.7 % (run 20261029-202842-54408) because `step(at:)`, the animated cursor's frame step, never ran in the newer run. - 2026-10-30: remaining gap: `SkinCursorController.step(at:)`'s timer and cursor-set lines still run only with an animated `SkinCursor`, whose init is internal to SkinKit. The frame choice is now the pure `stepFrame(at:steps:frameCount:)`, which `testCursorStepWrapsAndClampsFrames` covers. Plan step 3 is covered by `testBackingChangeReappliesLayout` and `testShowWithoutReferenceCentresUnpositionedWindow`.
- 2026-10-30: **bail after three runs.** Runs `20261030-003824-50667`, `20261030-004351-53216` and `20261030-004932-55329` failed: `testLegacyCleanupRemovesPlexState`, `testLegacyCleanupKeepsFolderChoice` and `testLegacyCleanupRunsOnce` raised "Invalid attempt to start a test run that has already been started" (`NSInternalInconsistencyException` from `-[XCTestCaseRun start]`) or crashed with "freed pointer was not the last allocation". `testLegacyCleanupDeletesTrackCache` and every `WindowDockingTests` test passed in the last run. Making the class fully synchronous and moving the stub's call count into a box did not help. Root cause (found by the orchestrator): the test file's private helper was named `run(onCacheRemoved:)` with a default argument, and inside an `XCTestCase` a bare `run()` resolves to `XCTest.run()`, which starts the test run again. The three failing tests called `run()`; the passing one called `run(onCacheRemoved:)` with an argument and reached the helper. Next: rename the helper (`runCleanup(onCacheRemoved:)`) and update its call sites.
