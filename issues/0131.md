# 0131 — Skins can't be deleted from the Skins window

| | |
|---|---|
| **Status** | open |

## Description

Requested by the user: "Add the option to delete a skin. This could be done with a context menu from the library view." The Library tab of the Skins window (⌘K) lists every indexed skin, and with the Museum (#0126) it's now easy to collect skins you don't want, but the only way to remove one is to find the file in Finder and wait for the next index pass.

## Expected behavior

- Right-click a skin in the Library tab › **Move to Trash**. Also on the Delete key / ⌘⌫ for the selected skin(s) and from the Museum grid's context menu for a downloaded skin. Multiple selection works if the grid supports it.
- The file goes to the Trash (recoverable; `FileManager.trashItem`), not a permanent delete, so no extra confirmation is needed. If two index rows point at the same file content (linked duplicates), only the chosen file is trashed.
- The skin's row and its thumbnail are removed from the index right away (no full rescan); the grid updates; a Museum skin loses its "Downloaded" badge.
- If the trashed skin is the one currently applied, it stays applied for this session (it's already loaded), and the next launch falls back the way a missing skin does today.
- Errors (file locked, outside the skins folder, already gone) show a short message; an already-missing file is just removed from the index.
- Tests: index removal by id (row + thumbnail), trashing through an injectable file-remover so no test touches the real Trash, the Museum badge clearing.
