## Description

Two loose ends from #0237's review (dfdc2bd):

1. **The `-RoadieVisFullScreen borderless` Debug fallback is dead code and probably broken.** Native full screen works in the guest, so no test uses the hook (design §1.2 says the fallback exists only if the guest can't do native). A plain `NSWindow` switched to `.borderless` returns false for `canBecomeKey`, so keys and Esc would likely stop working in that mode.
2. **A close during the exit animation can misbehave.** `close()` while full screen asks AppKit to leave full screen and sets `closesAfterFullScreen`. If AppKit ignores the toggle because a transition is already running (e.g. ⇧⌘K pressed twice quickly), the flag stays set and the window closes whenever full screen later ends.

## Expected behavior

1. Remove the borderless hook and its `RoadieConfiguration` entry (or, if kept, use a window subclass that can become key, and give it a test).
2. A second close during a full-screen transition closes the window once the transition ends, and a stale `closesAfterFullScreen` never closes the window later.

## Resolution notes

### Root cause

`close()` while full screen set `closesAfterFullScreen` and asked for the exit, but AppKit ignores `toggleFullScreen` while a transition is already running. The flag stayed set, so the window closed whenever full screen later ended. A second close asked for the exit a second time. The `-RoadieVisFullScreen borderless` Debug hook was never used, because native full screen works in the guest.

### Fix

- `VisualizationModel.close()`: if a close is already pending, a second one does nothing. `setFullScreen(_:)`: a transition that ends in full screen with a close pending asks for the exit again, and leaving full screen finishes the close, which clears the flag.
- Removed the borderless hook: `visFullScreenBorderless` and the `-RoadieVisFullScreen` argument, plus the `#if DEBUG` path and `BorderlessSaved` in `VisualizationWindowController`. Updated the comments and design `visualization.md` (§1.2 row, open question 4).
- No CHANGELOG line: full screen hasn't shipped yet (Unreleased "Added").

## Plan

1. **Remove the borderless hook.** Delete `visFullScreenBorderless` and its `-RoadieVisFullScreen` argument from `RoadieConfiguration`, the `#if DEBUG` branch, `enterBorderless` / `restoreFromBorderless` / `BorderlessSaved` and `borderlessSaved` from `VisualizationWindowController` (`toggleFullScreen()` is just `window.toggleFullScreen(nil)`), and the "or the Debug borderless hook" comments (`VisualizationModel.isFullScreen`, the probe's `fullScreen`). Docs: design `visualization.md` §1.2 table row and open question 4 say native only. `docs/ui-tests-in-vm.md` doesn't mention the hook.
2. **Pending close in `VisualizationModel`.** `close()` while full screen: if a close is already pending, do nothing (a second close is idempotent); else set `closesAfterFullScreen` and ask for the exit. `setFullScreen(_:)` (every finished transition): leaving full screen with a close pending finishes the close (which clears the flag); a transition that ends *in* full screen with a close pending re-issues the exit, since AppKit ignored the earlier toggle mid-transition. `windowWillClose` already reports `setFullScreen(false)` and closes, so every path out of full screen clears the flag.
