# 0126 — Skins from the Winamp Skin Museum can't be browsed or downloaded in the app

| | |
|---|---|
| **Status** | open |
| **Module** | App / SkinLibrary |
| **Platform** | macOS |
| **First seen** | 2026-10-20 |

## Description

Requested by the user: "what about getting skins from the Skins Museum? https://skins.webamp.org". Today the Skin Library (⌘K) only shows skins already on disk; getting a new skin means finding it on the Museum in a browser, downloading the `.wsz` and dropping it in. The Museum has about 103,000 classic skins with a public GraphQL API (`docs/winamp-skin-museum-access.md`).

## Expected behavior

- A Museum section in the Skin Library: browse and search the Museum's classic skins with their screenshots, without leaving the app.
- One click downloads a skin into the user's skins folder, indexes it (#0033) and applies it; already-downloaded skins are marked and not downloaded twice (md5).
- NSFW-flagged skins hidden by default, with a setting to show them.
- Works offline-gracefully: an error state, no hang, when the Museum is unreachable. Screenshots and search results are cached.
- Modern (`.wal`) skins are excluded; SkinAmp renders classic skins only.

## Plan

### What the live API returned (checked 2026-10-20)

The planner made one read-only POST to `https://skins.webamp.org/graphql` from the host (3 rows, plus an introspection of `Query`). It returned HTTP 200 with no errors.

- `statistics`: 103,332 unique classic skins, 1,523 NSFW, 12,707 approved.
- **`search_classic_skins(query: String!, first: Int! = 10, offset: Int! = 0, nsfw: Boolean = null): [ClassicSkin]`**. Classic only, offset-paged, and it has a **server-side `nsfw` argument**, which `docs/winamp-skin-museum-access.md` doesn't mention. It returns a plain list with no total count.
- **`skins(filter: SkinsFilterOption, first: Int! = 10, offset: Int! = 0, sort: SkinsSortOption): SkinsConnection { count nodes }`**. Classic only, and `count` is the total. It has **no "not NSFW" filter**: the default listing includes `nsfw: true` rows (row 2 of the first page is one). The enum values weren't captured. The doc and the webamp source give `filter` as `APPROVED | NSFW | REJECTED | TWEETED` and `sort` as `MUSEUM`. Step 1 confirms them against the source before relying on them, and sends `sort` only if confirmed.
- `search_skins` returns the `Skin` interface (modern skins included), so don't use it. Leave `bulkDownload` to crawlers; the app never uses it.
- Every row carried `__typename: "ClassicSkin"`, a 32-hex `md5`, `filename(normalize_extension: true, include_museum_id: true)` such as `ZeldaXtreme_[S130283].wsz`, `screenshot_url` (`https://r2.webampskins.org/screenshots/{md5}.png`), `download_url` (`https://r2.webampskins.org/skins/{md5}.wsz`), `museum_url` and `nsfw` (Bool, nullable per the schema).

### Design decisions

- **New package target `SkinMuseum`** in `Packages/SkinKit`. It depends on Foundation and CryptoKit only: no SkinKit, no SkinLibrary, no UI. A matching `SkinMuseumTests` target declares `resources: [.copy("Fixtures")]`. Its network seam follows `MAHTTPTransport` (`PlayerKit/Sources/MusicAssistantKit/MAHTTPTransport.swift`):
  `protocol MuseumTransport: Sendable { func send(_ request: URLRequest) async throws -> (Data, HTTPURLResponse) }`.
  `URLSessionMuseumTransport` is the only type that touches `URLSession`, and no test constructs it. Tests use `StubMuseumTransport`, which answers from fixtures by operation name and records each request so tests can assert on the body and headers.
- **Two queries, both classic-only by construction**, with named operations and variables and no string interpolation of user text:
  - `MuseumSearch($query, $first, $offset, $nsfw)` maps to `search_classic_skins`.
  - `MuseumBrowse($first, $offset, $filter)` maps to `skins`.

  Both select `__typename md5 filename(normalize_extension: true, include_museum_id: true) screenshot_url download_url museum_url nsfw` and nothing heavier: no `readme_text`, `archive_files` or `reviews`. Rows whose `__typename` isn't `ClassicSkin` are dropped anyway.
- **Paging:** 60 rows a page (a grid screen or two). The next page loads on scroll, never ahead of it. Only one Museum query is in flight at a time. Search waits 400 ms after typing and needs at least 2 characters. An empty search box browses instead.
- **NSFW:**
  - Search passes `nsfw: false` when NSFW is hidden. Browse with NSFW hidden uses `filter: APPROVED` (12.7k reviewed skins, which also avoids unreviewed ones). With NSFW shown, browse is unfiltered.
  - On top of that, the client drops any `nsfw == true` row when hidden, since `nsfw: false` may not exclude everything and a short page is fine.
  - `nsfw == null` (never reviewed) is shown. The Museum's own default does the same, and hiding unreviewed skins would empty search results. This is a user decision below.
- **"Downloaded" needs md5 in the index.** The index keys skins by SHA-256 (`SkinContentHash`, `skins.hash`). The Museum keys them by md5. Schema **v2** adds a nullable `md5 TEXT` column to `skins`, plus `CREATE INDEX skins_md5 ON skins(md5)`.
  - The ingester computes both digests from the one read it already does.
  - Rows from v1 are backfilled by a hash-only step at the end of a pass: read the file, MD5 it, no ZIP parse. It's cancellable and batched like ingest, and runs once.
  - A new `SkinIndexStore.skins(md5s:) -> [String: SkinRecord]` badges a whole result page in one query. This also badges Museum skins the user already had before this feature, such as a bulk download.
- **Downloads** go into `<skins folder>/Museum/<filename>`. The filename is the Museum's `filename(...)` value, sanitized: path separators and leading dots stripped, kept a `.wsz`, and suffixed `-2` on a collision with different bytes. The skin is fetched from `download_url` (https only, host not pinned, per the doc) into a temp file in the same volume's `Museum/.partial/` folder. Then:
  1. **Size check:** abort above 16 MB.
  2. **md5 check:** a mismatch deletes the file and reports "The download was corrupted".
  3. **Dedupe:** compute the SHA-256 and look it up. If the skin is already indexed under another path, delete the temp file and apply the existing file. Never write a second copy.
  4. Otherwise move it into place atomically.
  5. **Index just that file** through a new `SkinIndexer.add(paths:)`, which reuses the batch `ingest`. No folder walk over 100k files.
  6. Apply through `PlayerModel.loadSkin(from:)`.

  `SkinThumbnailCache` renders the local thumbnail lazily, as for any indexed skin, so nothing extra is needed there. If an index pass is running, `add(paths:)` throws `.passAlreadyRunning`. `SkinLibraryModel` then queues a normal incremental `scan()` after the pass, and the skin is still applied right away by URL.
- **No skins folder set:** browsing works. Download is replaced by "Choose Skins Folder…" (`SkinLibraryModel.chooseFolder()`). This is a user decision below.
- **Caches** go under `~/Library/Caches/com.brennanmke.SkinAmp/Museum/`, so they're purgeable (unlike the index, which lives in Application Support):
  - **Screenshots:** `Screenshots/{md5}.png`, with a disk LRU capped at **200 MB** (about 4k screenshots at ~50 KB) evicted by access date, plus an in-memory LRU of 300 decoded `CGImage`s. Fetches run at most 4 at once, are cancelled when a cell scrolls away, and only a 32-hex md5 becomes a path (as `SkinContentHash.isValid` guards thumbnails).
  - **Results:** `Results/{sha256 of operation+variables}.json`, valid for **24 h**, capped at **500 entries / 20 MB**. A cached page is shown immediately. Past its TTL it's shown and refreshed. Offline, it's shown with an "Offline, showing cached results" note.
- **User-Agent:** `SkinAmp/<CFBundleShortVersionString> (+https://github.com/brennanMKE/SkinAmp)`, on both GraphQL and CDN requests. It uses the repo URL rather than the user's email. This is a user decision below.
- **Errors and offline:** timeout of 15 s for GraphQL and 30 s for a skin download. `URLError` (not connected, timeout, cannot find host), any non-2xx status, or a GraphQL `errors` array maps to `MuseumError` (`.offline`, `.http(Int)`, `.graphQL(String)`, `.decoding`, `.checksumMismatch`, `.tooLarge`, `.noFolder`), each with an `errorDescription`. The model shows a `ContentUnavailableView` with Retry, and never a spinner forever. A 429 or 503 gets one retry after its `Retry-After` (capped at 10 s), then the error.
- **Network only on demand.** Nothing contacts the Museum until the Museum tab is shown. The `--launch` smoke test never opens the Skins window (the #0035 launch guard), so the VM run makes no request.
- **Entitlements:** none to add. `project.yml` has `ENABLE_APP_SANDBOX: NO` and hardened runtime only. HTTPS to public hosts needs no ATS exception (`NSAllowsLocalNetworking` covers only local hosts). The existing comment says `com.apple.security.network.client` is needed only if the sandbox is ever turned on, which applies here too. The Quick Look extensions don't touch this.

Host checklist for the user (needs the network, so never in agents):
1. Open ⌘K → Museum: the browse grid fills with screenshots.
2. Search "zelda": results appear.
3. Download one: it appears in `<skins folder>/Museum`, the main window takes the skin, and the Library tab shows it with its rendered thumbnail.

### Risks

- **Schema drift.** The `skins` filter and sort enum values are unverified (step 1 checks the source). Field names are a snapshot. The client should fail with `.graphQL`/`.decoding` and the UI with the error state, never a crash.
- **NSFW coverage is partial.** `nsfw` only marks reviewed skins, so unreviewed (`null`) skins can still be NSFW. "Approved" browse avoids them, but search does not.
- **Museum etiquette.** It's one person's hobby infrastructure. Pages of 60, one query in flight, debounced search, no prefetching of further pages, cached screenshots and results, and no `bulkDownload`. Screenshot fetches are the largest load (60 PNGs a page), so the 4-at-a-time cap and the cancel-on-scroll-away matter.
- **The v2 migration and backfill** read every existing skin file once (~56 KB each, so about 5–6 GB for 100k). The backfill runs at utility priority after the normal pass, shows progress, and can be cancelled. The migration is one-way: an older build refuses a v2 index (`incompatibleDatabase`) and offers Reset.
- **The download folder lives inside the indexed folder**, so a later full pass sees `Museum/*.wsz` like any other file, which is intended. The `.partial/` folder is hidden (`skipsHiddenFiles`), so half-written files are never indexed.
- **Licensing.** Downloaded skins stay on the user's disk. Nothing is redistributed or committed, as the doc requires.

### Decisions for the user

1. **NSFW default:** hidden, with a Settings toggle. Also, should unreviewed (`nsfw == null`) skins be hidden when NSFW is hidden? The plan shows them. Hiding them would cut search results heavily.
2. **Default browse when NSFW is hidden:** "Approved" (12.7k curated) or the full listing with flagged rows filtered client-side. The plan uses Approved.
3. **Where downloads go:** `<skins folder>/Museum/`. With no skins folder set, the plan asks the user to choose one. The alternative is a default folder such as `~/Music/SkinAmp Skins`.
4. **User-Agent contact:** the repo URL, as planned, or an email address.
5. **md5 backfill of existing skins**, which reads every file once, so that skins the user already owns show "Downloaded". The alternative is to badge only skins downloaded through the app (no backfill) and keep the rest of step 3.

- Tests must not touch the network (the VM guest has none): the API client takes an injectable transport, with recorded fixtures.
- Respect the Museum: paged queries, no bulk crawling from the app, a descriptive User-Agent.
