## Description

Host the SwiftUI main window in a borderless `NSWindow` via `NSHostingView`, with title-bar dragging, close/minimize buttons, and the `region.txt` shape.

## Acceptance criteria

- Parse `region.txt` in SkinKit (port Webamp's `regionParser.ts`) with tests.
- Clicks outside the region pass through; window shape updates on skin switch.

## Plan

- **The region lives in SkinKit as data; the window is the only consumer.** `Skin` gains `region: SkinRegion` (polygons per section, in skin pixels, y down). The mask bitmap and the hit-test path are built by SkinKit from that data, so they are unit-tested without AppKit and reusable by `skintool --png` (#0026), the EQ and playlist windows (M5) and shade mode (#0031).
- **The main window is an `NSWindow` subclass created by an `NSApplicationDelegate`, not a SwiftUI `Window` scene.** A borderless window must override `canBecomeKey` (AppKit returns `false` for borderless windows, so menus and `.commands` would never see a key window) and must own `performClose`, which needs a subclass; SwiftUI does not let the app subclass the window it creates. The SwiftUI tree (`PlayerView`) is unchanged and hosted in an `NSHostingView`. The `Settings` scene stays and carries the `.commands` block, which is app-wide regardless of which scene declares it.
- **Dragging is implemented by hand, not with `performDrag(with:)`.** A small AppKit view over the title bar computes a proposed origin on every `mouseDragged` and passes it through a hook before moving the window. That hook is where #0030 (snapping, `snapUtils.ts`) plugs in; `performDrag` gives no such hook. Webamp does the same thing in `WindowManager.tsx` (`handleMouseMove`: proposed diff → snap → `updateWindowPositions`).
- **Clicks outside the region pass through at the WindowServer level.** The window is non-opaque with a clear background and a layer mask built from the region; the WindowServer hit-tests non-opaque windows by their alpha, so a click on a fully transparent pixel reaches the window beneath. The shadow is also computed from those pixels, so every mask change calls `invalidateShadow()`. As a second layer, the content view's `hitTest(_:)` returns `nil` outside the region path so nothing in our own view ever reacts out there (including drop targets, which AppKit finds through `hitTest`).
- **Close hides, it does not quit.** Winamp's close button quits; a Mac app keeps running after its window closes, playback included, which is what Webamp's `close` does too (it hides the player). The window comes back from the Dock icon (`applicationShouldHandleReopen`) and a `Window › Player` command (⌘1). ⌘Q quits as before. If the user wants Winamp's behaviour later it is one line in `performClose`.
- **Title-bar buttons follow Webamp's quirk.** `ClickedDiv.tsx`: until first clicked the button draws nothing, so the title-bar strip's own pixels show; afterwards the dedicated sprite; while pressed the `_DEPRESSED` sprite. The button sprites are only drawn on the selected (key) title bar (`skinSelectors.ts` 249–261); an unfocused window shows `MAIN_TITLE_BAR` with nothing on top. Positions come from `main-window.css` 22–48: 9×9 at y 3, x 6 (options), 244 (minimize), 254 (shade), 264 (close); the bar itself is 275×14 at (0,0). Options and shade are drawn with the right sprites but do nothing yet (the menu is later work; shade is #0031).
- **Scale and sibling issues.** `PlayerModel.scale` (2) stays; the window's content size is `275×116 × scale` and the mask is rendered at that size. `MainWindowView` stays window-agnostic (no AppKit types), so #0026 can render it offscreen and #0021–#0024 keep editing the same `ZStack`. The only line of `MainWindowView` this issue changes is the title-bar line; #0020 touches `SkinParser.swift`/`Skin.swift` too, and both edits here are two lines. Whichever of #0020/#0025 lands second rebases; no ordering constraint beyond that. For #0031, the controller takes a `mode` (`.normal`/`.shade`) that picks the content height and the region section; for #0030, the controller is instantiated per window (main now; EQ and playlist in M5) and exposes the drag hook and `windowDidMove`.

### 1. SkinKit: `IniParser`, `RegionParser`, `SkinRegion`

New `Packages/SkinKit/Sources/SkinKit/Parsers/IniParser.swift` (internal; `pledit.txt` in M5 reuses it, Webamp parses it with the same function):

```swift
/// Port of Webamp's `parseIni` (js/utils.ts): sections and keys lowercased and trimmed, values
/// cut at a second `=`, trimmed, one leading/trailing quote stripped. Properties before the first
/// section are ignored; a repeated section name starts over; a repeated key overwrites.
enum IniParser {
    static func parse(_ text: String) -> [String: [String: String]]
}
```

Lines split on `\r` or `\n` (runs collapse, like `/[\r\n]+/`). Section: `^\s*\[(.+?)\]\s*$`. Property: `^\s*([^;][^=]*)\s*=\s*(.*)\s*$`, i.e. a line whose first non-blank character is `;` is a comment. Note the consequence, kept on purpose because Webamp has it: `//[Equalizer] …` is neither a section nor a comment, so the `NumPoints`/`PointList` lines under it overwrite the current section's values (the Sony sample's `[Equalizer]` ends up with its 24-point variant). Write that as a test so a later "fix" is a deliberate divergence.

New `Packages/SkinKit/Sources/SkinKit/Parsers/RegionParser.swift` (public):

```swift
/// Port of Webamp's `regionParser` (js/regionParser.ts). Webamp is MIT licensed; see NOTICE.
public enum RegionParser {
    public static func parse(_ data: Data) -> SkinRegion       // UTF-8, lossy; digits are ASCII
    static func parse(text: String) -> SkinRegion
}
```

Algorithm, line-cited to `regionParser.ts`:
- For each INI section with both `numpoints` and `pointlist` (17–20); sections lacking either are skipped.
- `counts` = `numpoints` split on `\s*,\s*`, empties dropped (21). `values` = `pointlist` split on `\s*[, ]\s*`, empties dropped (22–25); so `, ,275,3,` and trailing commas are fine (Sony sample). Pair consecutive values into points (`pointPairs`, 3–9). A dangling odd value is dropped (Webamp emits `x,undefined`, which the browser ignores; this is the one documented deviation). A value that is not an `Int` is parsed as `Double` and truncated; if that fails too, the pair is dropped.
- Walk `counts` with a cursor (26–41): `num = Int(count)`; a non-numeric count (Webamp: `NaN`) produces an empty slice → no polygon, cursor unchanged; `num < 3` → cursor += num, no polygon (29–33); otherwise the slice `points[cursor ..< min(cursor + num, points.count)]`; empty → no polygon and no advance (35–38); else keep it, even when shorter than `num` (Webamp keeps the partial slice), cursor += num.
- A section is stored only if it has at least one polygon (45–47).

New `Packages/SkinKit/Sources/SkinKit/SkinRegion.swift`:

```swift
/// `region.txt`: per window state, the polygons (skin pixels, y down, union) that are drawn.
public struct SkinRegion: Sendable, Equatable {
    public struct Point: Sendable, Hashable { public let x: Int; public let y: Int }
    public typealias Polygon = [Point]
    /// Lowercased section name → polygons; Webamp's `RegionData`.
    public let sections: [String: [Polygon]]
    public static let empty = SkinRegion(sections: [:])
    public var isEmpty: Bool { sections.isEmpty }
    // Webamp's mapRegionNamesToIds (Skin.tsx 14–19); nil = rectangular.
    public var normal: [Polygon]?          { sections["normal"] }
    public var windowShade: [Polygon]?     { sections["windowshade"] }
    public var equalizer: [Polygon]?       { sections["equalizer"] }
    public var equalizerShade: [Polygon]?  { sections["equalizerws"] }

    /// The polygons as one path in points×scale, nonzero winding (ClipPaths.tsx draws one
    /// SVG `<polygon>` per entry inside one `<clipPath>`: a union).
    public static func path(_ polygons: [Polygon], scale: CGFloat) -> CGPath
    /// An alpha mask of `size` (skin pixels) at `scale`, filled without antialiasing so edges land
    /// on whole pixels like Winamp's Win32 region. Top-left origin.
    public static func maskImage(_ polygons: [Polygon], size: CGSize, scale: CGFloat) -> CGImage?
}
```

`maskImage` draws into a `CGContext` (`CGColorSpaceCreateDeviceRGB`, premultiplied alpha, `size × scale` pixels) with `setShouldAntialias(false)`, `setAllowsAntialiasing(false)`, a top-left coordinate system (translate/scale flip), `addPath(path)`, `fillPath(using: .winding)`. Integer coordinates × an integer scale give pixel-exact edges.

`Skin.swift`: add `public let region: SkinRegion` (after `visColors`). `SkinParser.swift`: replace the `region.txt` item in the TODO comment with `let region = archive.file("region", extensions: ["txt"]).map(RegionParser.parse) ?? .empty` and pass it to `Skin(...)`. No new warning: a region file with no usable section is normal (all-comment files ship in real skins), so `skintool`'s output does not change and #0020's "all 10 sample skins ok" is untouched.

New `App/Window/SkinShapeView.swift`: two `NSView`s.

```swift
/// Flipped, layer-backed container: masks its content to the skin region and refuses hits outside it.
final class SkinShapeView: NSView {
    override var isFlipped: Bool { true }
    var regionPath: CGPath?           // skin pixels × scale; nil = rectangular
    func apply(mask: CGImage?, scale: CGFloat)   // layer.mask = CALayer(contents:), contentsScale = scale; nil removes
    override func hitTest(_ point: NSPoint) -> NSView?   // nil when regionPath exists and !contains(point, using: .winding)
}

/// Sits over the title bar, above the hosting view. Drags the window; excludes the button rects.
final class TitleBarDragView: NSView {
    weak var delegate: TitleBarDragging?
    var excludedRects: [CGRect]                   // button rects × scale, local coordinates
    override var isFlipped: Bool { true }
    override func acceptsFirstMouse(for event: NSEvent?) -> Bool { true }   // drag an inactive window at once, like Winamp
    override func hitTest(_ point: NSPoint) -> NSView?   // nil inside excludedRects (the SwiftUI buttons get those)
    override func mouseDown(with:)     // clickCount == 2 → delegate.titleBarDoubleClicked(); else dragBegan
    override func mouseDragged(with:)  // proposed = window.frame.origin + (mouseLocation - start); delegate.drag(to: proposed)
    override func mouseUp(with:)       // delegate.dragEnded()
}

@MainActor protocol TitleBarDragging: AnyObject {
    func dragBegan()
    func drag(to proposedOrigin: NSPoint)   // default: window.setFrameOrigin; #0030 snaps here
    func dragEnded()
    func titleBarDoubleClicked()            // no-op now; #0031 toggles shade
}
```

Mouse positions use `NSEvent.mouseLocation` (screen coordinates), so the drag stays correct while the window moves under the cursor. The drag view is a *sibling above* the `NSHostingView`, not an `NSViewRepresentable` inside SwiftUI: representables under `.scaleEffect` are not reliably transformed, and keeping it in AppKit keeps `MainWindowView` free of window code.

### 6. Risks

- **Mask orientation.** `SkinShapeView` is flipped; a `CALayer` on a flipped, layer-backed view is geometry-flipped by AppKit, and `maskImage` draws top-left-origin. If check (6) shows the Sony notches upside down, the fix is in one place: draw `maskImage` bottom-up (drop the flip transform) or set `mask.isGeometryFlipped`. The hit-test path is in view coordinates (flipped) and is not affected.
- **Pass-through.** If a click on a transparent pixel does not reach the window behind on the current macOS, `hitTest` still keeps it from doing anything in our window; the degraded behaviour is "dead" rather than "wrong". Note it in `## Gotchas`; there is no per-pixel public API beyond the alpha-based shape (`ignoresMouseEvents` is all-or-nothing).
- **`.miniaturizable` on a borderless window.** If `miniaturize(nil)` does nothing in check (4), fall back to `orderOut` for the button and ⌘M, and say so.
- **SwiftUI with only a `Settings` scene.** The app must not auto-open anything at launch; `Settings` does not. If SwiftUI logs a warning about a missing primary scene it is harmless; do not add a `WindowGroup` to silence it. `@NSApplicationDelegateAdaptor` instantiates the delegate, and so `PlayerModel`, before the App's `body`; `PlayerModel.init` already runs this early today as `@State`.
- **Observation re-registration.** `withObservationTracking` fires `onChange` once; forgetting to re-register makes the second skin switch keep the first shape. Test (6) switches at least twice.
- **Sibling merges.** `MainWindowView.swift` (#0021–#0024) and `SkinParser.swift`/`Skin.swift` (#0020) are edited in parallel; the edits here are one or two lines each. Rebase, re-run the VM script, do not re-plan.
- **`region.txt` encodings.** Comments in real skins are Windows-1252; the lossy UTF-8 decode only mangles comments, and digits, brackets and `=` are ASCII. The corpus test is the safety net.

## Root cause

The main window was a SwiftUI `Window` scene with a hidden title bar: a standard, rectangular, opaque window with no title-bar drag area, no skinned close/minimize buttons and no `region.txt` shape. SkinKit did not parse `region.txt` at all.

## Fix

SkinKit: `IniParser` (port of Webamp's `parseIni`), `RegionParser` (port of `regionParser.ts`) and `SkinRegion` (polygons per section, `path(_:scale:)`, non-antialiased `maskImage(_:size:scale:)`); `Skin.region` is filled by `SkinParser` (absent or unusable file gives `.empty`, no warning). NOTICE mentions the ported parsers.

App: the SwiftUI main `Window` scene is gone. `AppDelegate` owns `PlayerModel` and a `SkinWindowController`, which builds a borderless, non-opaque `SkinWindow` (key/main, `performClose` hides). Its content view is a `SkinShapeView` (layer mask from the region, `hitTest` nil outside the region path) holding an `NSHostingView(PlayerView)` and a `TitleBarDragView` sibling above it that drags by hand through `TitleBarDragging.drag(to:)` (the hook for #0030) with holes over the four button rects. `withObservationTracking` on `model.skin`/`model.scale` re-applies size, mask, path and shadow and re-registers itself. `TitleBarView` (Webamp `ClickedDiv` behaviour: buttons drawn only on the key window, blank until first pressed, `_DEPRESSED` while held) replaces the title-bar line in `MainWindowView`. The no-skin placeholder gets a window-background. Window > Player (cmd-1) and Dock reopen show the window; frame autosave name `MainWindow`.

Adaptations to the landed code (from the plan): the `Library` `Window` scene (cmd-L), `Settings`, and all `.commands` (Open, Add to Playlist, Open Skin) are kept; `.commands` now hang off the `Settings` scene. With the player scene removed, the Library would be the only `Window` scene and SwiftUI would open it at launch; `defaultLaunchBehavior(.suppressed)` needs macOS 15 and `SceneBuilder` rejects `if #available` (target is 14), so `AppDelegate` closes any non-player window whose identifier starts with `library` on the next run-loop turn after launch. Other deviations: `SkinShapeView` is not flipped (the region path is flipped into view coordinates instead) so the mask layer's contents are upright without relying on geometry-flip behaviour of flipped layer-backed views; `apply(path:mask:)` replaces `apply(mask:scale:)` since `contentsScale` is irrelevant when the mask is stretched (nearest-neighbour) to the view; `hitTest` implementations convert from the superview coordinate system, which is what AppKit passes. The mask is rendered at the skin `scale` (not backing scale); edges land on whole skin pixels either way. No `References/webamp` clone was needed: the parser was ported from the scratchpad Webamp checkout.
