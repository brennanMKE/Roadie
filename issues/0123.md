# 0123 — Output selection can drift from the leader in two edge cases

| | |
|---|---|
| **Status** | open |
| **Module** | App / LibraryBrowser |
| **Platform** | macOS |
| **First seen** | 2026-10-20 |

## Description

Non-blocking findings from the #0118 review (code 60eafe8), on top of #0121's ownership model:

1. A `refreshOutputs` that finishes while a leader change is mid-step (inside `applyOutputSelection`) can set `selectedOutput` directly, so the leader changes without a `player_queues/transfer`: playback stays on the old leader while SkinAmp targets the new one.
2. A `previousTarget` that has just become a member of the new selection is protected from `stopOthers` only by the activity snapshot, not by checking membership in `outputSelection`; with a stale snapshot SkinAmp could stop a speaker the user just added.
3. While a Music Assistant group player is selected, `canAdd` disables speakers that report `can_group_with`, but "Only" on such a speaker still works. Confirm that's the intended behavior and label it, or make the rows consistent.

## Expected behavior

- A reconcile during a leader change is serialized with it (or deferred), so the leader never changes without a transfer.
- `stopOthers` skips any player in the current selection by membership, not only by snapshot.
- Speaker rows behave consistently while a group is selected.
