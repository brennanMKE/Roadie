## Description

`PlayerModel.init()` (`App/PlayerModel.swift:330–500`) wires the real world: `KeychainMusicAssistantTokenStore`, `URLSessionWebSocketTransportFactory`, `SystemServiceBrowser`, `SystemWiFiNetwork`, `SystemNetworkEvents`, `URLSessionMuseumTransport`, `QueueStore.defaultURL()`, `SkinIndexStore.defaultURL`, the caches directory. A unit test can't construct it without touching the Keychain (a dialog hangs the headless guest) and the network, and a UI test can't point the app at a scripted Music Assistant server. This issue adds `RoadieConfiguration`: one struct, read from launch arguments for UI tests and passed directly by unit tests, that swaps each dependency for the stub its package already has. Design: [docs/design/test-automation.md](../docs/design/test-automation.md) §2.2.

## Root cause

`PlayerModel.init()` built every dependency itself (Keychain token store, URLSession sockets and HTTP, Bonjour, Wi-Fi, network events, the Museum's URLSession transport, Application Support and Caches paths, `UserDefaults.standard`), with no seam for a test to pass stubs. So neither a hosted unit test nor a UI test could build the model without the real Keychain, network and disk.

## Plan

### 1. `RoadieConfiguration` (`App/RoadieConfiguration.swift`, new)

```swift
struct RoadieConfiguration: Sendable {
    enum MusicAssistantMode: Sendable { case live, scripted(scenario: String), none }
    enum MuseumMode: Sendable { case live, fixtures(skinsFolder: URL) }
    enum ExternalOpenMode: Sendable { case workspace, record }

    var dataDirectory: URL? = nil          // nil: the real Application Support / Caches paths
    var defaults: UserDefaults = .standard
    var musicAssistant: MusicAssistantMode = .live
    var museum: MuseumMode = .live
    var discovery = true                   // Bonjour, Wi-Fi name, network events, wake notifications
    var externalOpens: ExternalOpenMode = .workspace
    var isUITest = false                   // -RoadieUITest 1: the state probe (#0199) and test-only menu behaviour
    var silentOutput = false               // reserved; not read yet (design §8)

    static let standard = RoadieConfiguration()
    /// From `-RoadieDataDir`, `-RoadieMAScenario`, `-RoadieMuseum fixtures`, `-RoadieNoDiscovery`, `-RoadieExternalOpens record`, `-RoadieUITest`.
    static func fromProcess(_ info: ProcessInfo = .processInfo) -> RoadieConfiguration
}
```

`fromProcess` reads `UserDefaults.standard` for the `-key value` arguments (they land in `NSArgumentDomain`), so the same strings work from `open --args` and `XCUIApplication.launchArguments`. Test mode only switches on when `-RoadieUITest 1` is set, so a stray `-RoadieDataDir` alone does nothing.

### 2. Thread it through `PlayerModel` (`App/PlayerModel.swift`)

- `init(configuration: RoadieConfiguration = .standard)`; `AppDelegate` passes `RoadieConfiguration.fromProcess()`.
- **Storage.** `QueueStore(fileURL: configuration.queueFileURL)` where `queueFileURL` is `dataDirectory/queue.json` or `QueueStore.defaultURL()`; `SkinLibraryModel(defaults:databaseURL:)` gets `dataDirectory/skins.sqlite`; `SkinThumbnailCache(directory:)`, the Museum caches and `FolderBackend`'s index cache get subfolders of `dataDirectory`. Check `FolderBackend.settingsProvider(defaults:)` and `FolderIndex`'s caches path for an existing parameter; add one if there isn't (package change, PlayerKit, keep the default).
- **Defaults.** Every `UserDefaults.standard` read in `PlayerModel`, its extensions and `SkinLibraryModel` goes through `configuration.defaults` (grep `UserDefaults.standard` under `App/`; the `@AppStorage` in SwiftUI views stays on `.standard`, which is what the UI tests set through launch arguments anyway).
- **Music Assistant.** `.live`: today's wiring. `.scripted(scenario)`: `MusicAssistantBackend(server:token:hasVerifiedServer:transports:)` with `ScriptedMusicAssistant.transportFactory(scenario:)` from `MusicAssistantKitStub` (#0197 builds the stateful server; until it lands, this issue ships a `FixtureScript.recorded(token:)`-backed factory under the same name with the single scenario `libraryIdle`), `token: { _ in MusicAssistantToken("roadie-test-token") }` through an `InMemoryMusicAssistantTokenStore`, and a `MusicAssistantServerStore(defaults:)` seeded with one verified server at `http://ma.example:8095` (the recordings' scrubbed host; look at `ServerStoreTests` for how a verified record is written). `MusicAssistantSettingsModel` gets the in-memory token store and a `MusicAssistantConnectionTest` whose transport is the same factory. `.none`: Music Assistant unconfigured (no server), for folder-only tests.
- **Discovery off.** `discovery == false` passes inert stand-ins: a `SystemServiceBrowser` replacement that never reports, a Wi-Fi provider returning nil, an empty network-events stream. Check the protocols those three conform to (`MusicAssistantDiscoveryModel(browser:)`, `MusicAssistantSelectionController(wifi:network:)`) and add `Inert*` types in `App/TestSupport/` conforming to them. Skip the `NSWorkspace.didWakeNotification` observer.
- **Museum.** `.fixtures(skinsFolder:)`: `MuseumClient(transport: StubMuseumTransport(...))` loaded with `SkinMuseumTests/Fixtures/skins-page1.json` and `search-zelda.json`, and a `MuseumDownloader` whose fetch copies `<skinsFolder>/<filename>` when a file with that md5 exists there. `StubMuseumTransport` lives in the test target today: move it to a new `SkinMuseumStub` library product in `Packages/SkinKit` (with the two fixtures as resources) so the app can link it; `SkinMuseumTests` depends on it instead.

Sparkle stays as is (off in Debug).

## Review notes

Bounced 2026-10-24 (review of 8844957, merged with main 52a7ed6 cleanly). The live configuration is right: `.standard` keeps `UserDefaults.standard`, the same keys and the same Application Support / Caches paths (`QueueStore.defaultURL()`, `SkinIndexStore.defaultURL`, `SkinThumbnailCache.defaultDirectory()`, `FolderIndexCache.defaultDirectory()`, the Museum caches path verbatim); the Keychain token store, `URLSessionWebSocketTransportFactory`/`URLSessionHTTPTransport` (same as the package defaults, stateless), `urlSessionFetcher`, `System*` discovery, the wake observer and `NSWorkspace` opens are unchanged; `LegacyDataCleanup` still runs; the window flags read in `restoreWindowState()` are read before anything uses them. `fromProcess` enters test mode only with `-RoadieUITest 1` or `HostedTestRun.isActive`, so the scenario `fatalError`s can't fire on a normal launch. What has to change:

1. **The folder settings model still uses the real defaults and caches in test mode.** `PlayerModel.init` builds `FolderSettingsModel(backend: folderBackend)` with its defaults, so it uses `.standard` and `FolderIndexCache.defaultDirectory()`. In a UI-test or hosted run, its init shows the real user's music folder (`storedFolder(in: .standard)`). `choose(_:)` (Settings › Library, and `WelcomeView`'s "Choose Music Folder") writes the real `musicFolder` key and deletes the real index cache for the old folder (`clear()` does too). Meanwhile the backend reads the suite, so a folder chosen in a test never reaches it. Fix: `FolderSettingsModel(backend:defaults: defaults, cacheDirectory: configuration.folderIndexDirectory)`. Then add a check to `testDataDirectoryHoldsEveryStore` (or a new test): `folderSettings.choose(tempFolder)` leaves `UserDefaults.standard` without the key and stores the folder in the suite.
2. **In test mode, the `@AppStorage` pairs split across two stores, and `@AppStorage` writes reach the real defaults.** `museumShowsNSFW`: the Museum browser reads and writes `configuration.defaults`, but `SkinsSettingsView` and `MuseumStatusView` use `@AppStorage` on `.standard`. Under a test configuration, the toggle and the browser disagree, and a UI test that toggles it writes the user's real defaults. The same goes for `QuitStop`, `SettingsTab`, `library.playlists.reorderCaptionDismissed`, `PlaylistsModel`'s recent targets (built by `LibraryBrowserModel` with the default `.standard`), and `WindowDockingCoordinator.seedFromLegacyFrames()`, which *removes* `NSWindow Frame …` keys from `.standard`. Fix: put `.defaultAppStorage(appDelegate.model.defaults)` on every scene/hosting root (`RoadieApp` scenes, `SkinWindowController`, `WelcomeWindowController`). Move `PlayerModel+Ownership`'s QuitStop read and `WelcomeView`'s Settings-tab write to `defaults`, and pass `defaults` through to `PlaylistsModel` and the legacy-frames read. Then update the "`@AppStorage` stays on `.standard`" comments and the Fix text. On a live launch nothing changes, because `defaults` is `.standard`.
3. **The release app now ships the test fixtures.** Linking `MusicAssistantKitStub` and `SkinMuseumStub` into the Roadie target copies their resource bundles into every Release build's `Contents/Resources`, along with the stub code. That is about 600 KB and 48 recorded Music Assistant fixtures. Hosts, ids and the user are scrubbed, but the user's real library and room/device names remain: artists, albums, tracks, playlists, queue rows, and player names such as "Living Room Display" and "user-mac-mini-m4". Nothing loads them on a normal launch, and they add no network or entitlement surface. Still, a release shouldn't carry the user's library. Keep them out of Release. One option: a Release-only post-build phase removes `*_MusicAssistantKitStub.bundle` and `*_SkinMuseumStub.bundle`, and `RoadieConfiguration.fromProcess` ignores `-RoadieUITest` in Release builds (`#if DEBUG`), so a stripped app can't reach the `fatalError` paths. If the user decides shipping them is acceptable, say so explicitly in the Fix section instead. Either way, `scripts/release.sh` or `check-website.sh`-style verification should assert what the shipped bundle contains.

Minor, fix while there: `isIsolated` is `dataDirectory != nil`, but its doc says "talks to the real Keychain or a real Music Assistant server". Either derive it from `musicAssistant != .live`, or reword it to "uses the real data directory". As written, a hand-built `.scripted` configuration without a data directory would still run `LegacyDataCleanup` against the real Keychain. `testDataDirectoryHoldsEveryStore` lists only Application Support; also list `~/Library/Caches/co.sstools.roadie` (thumbnails, folder index, Museum).
