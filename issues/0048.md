## Description

Choosing a HomePod as the Mac's sound output has no effect on SkinAmp: playback keeps coming from the Mac mini's built-in speaker. SkinAmp should play through whatever output the user picks, including AirPlay 2 speakers, and should support playing to several speakers at once the way Music.app does (for example, two HomePods together).

## Plan

### Scope and decisions

This issue makes `AudioCore` follow the **system default output device** (option C in [docs/airplay-macos-handoff.md](../docs/airplay-macos-handoff.md)): whatever the user picks in Control Center › Sound or System Settings › Sound, including a HomePod that macOS exposes as an AirPlay output device, a Multi-Output Device from Audio MIDI Setup, headphones or a USB interface. It changes `AudioCore` only; no `App/`, `project.yml` or script change. Out of scope and left to their own issues: an in-app route picker (#0051), AirPlay 2 enhanced buffering and multi-speaker selection from inside SkinAmp (#0052, after the #0050 spike), and the EQ/visualizer latency work that only matters under enhanced buffering (#0053, #0054). The second bullet under "Expected behavior" (a route picker) is therefore not an acceptance criterion here.

- **Why it fails today (working theory, to be confirmed by the diagnostics below).** `AVAudioEngine`'s output node on macOS is a HAL output unit bound to one `AudioDeviceID`, chosen when the engine is created. The engine posts `AVAudioEngineConfigurationChange` only when its I/O unit sees the *format* of its device change (rate or channel count), not when the system default moves to another device, and even then the engine restarts on the device it already had. `Player.handleConfigurationChange()` restarts the engine but never tells it which device to use, so audio stays on the built-in speaker. A second gap: `Player.stop()` leaves the engine running, so a device change while stopped is not picked up by the next `play()` either.
- **Mechanism.** Listen to CoreAudio's `kAudioHardwarePropertyDefaultOutputDevice` on `kAudioObjectSystemObject` (`AudioObjectAddPropertyListenerBlock`). On each change: stop the engine, bind its output unit to the new default (`engine.outputNode.auAudioUnit.setDeviceID(_:)`; fallback `AudioUnitSetProperty(kAudioOutputUnitProperty_CurrentDevice)` on `outputNode.audioUnit`), restart through the existing `AudioGraph.start()` (which already reconnects player → EQ → mixer at the new output rate while stopped, #0042, and re-installs the analyzer tap at that rate), and reschedule the current file from the saved position plus the pre-scheduled next file. That is the body of today's `handleConfigurationChange()` with a device bind added, so both triggers (our listener and the engine's own notification) funnel into one coalesced handler.
- **What is preserved across a switch.** Position (`currentTime` → file frame, as today), the queue (untouched), gapless state (`discardSchedule()` then reschedule current + `scheduleNextIfNeeded()`, recomputed in node frames at the new rate), EQ (same `AVAudioUnitEQ` instance; reconnecting it while stopped keeps bands, preamp and bypass, verified in #0042), volume and balance (mixer `outputVolume` and `pan` live on the nodes), the analyzer tap (re-installed by `start()` with the new rate), play/pause intent (`playing` resumes, `paused` stays parked with the segment scheduled, `loading` lets `begin` start the engine, `stopped` binds on the next start).
- **Testable silently by injection.** The device source and the device binding are one protocol, `OutputDeviceProvider`. The real one touches CoreAudio; tests use `ManualOutputDeviceProvider`, which yields a fake device id on demand and records binds, with the engine in offline manual rendering mode. **No test ever changes a device**, on the host or in the guest: the only CoreAudio calls a test makes are reads (default device id, name, nominal rate) and, in one real-time test, binding the engine to the device it is already on.
- **Verification is `scripts/run-tests-vm.sh` only**, never a build or test on the host. Playing to a HomePod can only be hand-tested by the user on the host (section 5); the VM has one virtual device and no AirPlay path.

### 1. `OutputDeviceProvider` (new file `Packages/PlayerKit/Sources/AudioCore/Output/OutputDeviceProvider.swift`)

```swift
import AVFoundation
import CoreAudio

/// Where the system default output device comes from, and how the engine is bound to it.
/// The real one talks to CoreAudio; tests inject a manual one. Nothing here ever changes the default.
public protocol OutputDeviceProvider: Sendable {
    /// The system default output device now; nil when there is none.
    func defaultOutputDevice() -> AudioDeviceID?
    /// One element per change of the default, carrying the new id. Installing the listener is lazy
    /// (first iteration); cancelling the consuming task removes it (`onTermination`).
    func defaultOutputDeviceChanges() -> AsyncStream<AudioDeviceID>
    /// Device the output node is bound to now (0 / nil if none, e.g. manual rendering mode).
    @MainActor func boundDevice(of outputNode: AVAudioOutputNode) -> AudioDeviceID?
    /// Binds the output node to `device`. Called only while the engine is stopped. Must be a no-op
    /// when the node's engine is in manual rendering mode (no device behind it).
    @MainActor func bind(_ device: AudioDeviceID, to outputNode: AVAudioOutputNode) throws
    /// For logs and the hand test: device name, transport type (built-in, AirPlay, USB…), nominal rate.
    func describe(_ device: AudioDeviceID) -> OutputDeviceDescription?
}

public struct OutputDeviceDescription: Sendable, Equatable {
    public let id: AudioDeviceID
    public let name: String
    public let transport: String      // kAudioDevicePropertyTransportType as text ("AirPlay", "Built-in", …)
    public let nominalSampleRate: Double
}

/// CoreAudio implementation.
public struct SystemOutputDeviceProvider: OutputDeviceProvider { public init() {} … }
```

`SystemOutputDeviceProvider` details:

- Property address `kAudioHardwarePropertyDefaultOutputDevice` / `kAudioObjectPropertyScopeGlobal` / `kAudioObjectPropertyElementMain` (not `DefaultSystemOutputDevice`, which is the alert-sound device). `defaultOutputDevice()` is one `AudioObjectGetPropertyData`; a `kAudioObjectUnknown` result maps to nil.
- `defaultOutputDeviceChanges()`: `AsyncStream { continuation in … }` that installs `AudioObjectAddPropertyListenerBlock` on a private serial `DispatchQueue(label: "com.brennanmke.SkinAmp.AudioOutput")`; the block re-reads the default and `yield`s it (so the element is the device, not just "something changed"); `continuation.onTermination` removes the listener. Buffering policy `.bufferingNewest(1)`: a burst of changes collapses to the latest.
- `boundDevice(of:)`: `outputNode.auAudioUnit.deviceID` (0 → nil). `bind(_:to:)`: `guard outputNode.engine?.isInManualRenderingMode != true`; skip if already bound to that id; `try outputNode.auAudioUnit.setDeviceID(device)`. If that throws `kAudioUnitErr_PropertyNotWritable`/`InvalidProperty` on this macOS (it would mean the output unit is the default-output subtype that follows the default by itself), fall back to `AudioUnitSetProperty(outputNode.audioUnit!, kAudioOutputUnitProperty_CurrentDevice, kAudioUnitScope_Global, 0, …)`; if that fails too, throw `AudioCoreError.outputDevice(underlying:)` (new case) and log the component description of the output unit (`AudioComponentGetDescription`) so the hand test shows what the engine actually uses.
- `describe(_:)`: `kAudioObjectPropertyName` (CFString), `kAudioDevicePropertyTransportType` mapped to text (at least `kAudioDeviceTransportTypeAirPlay`, `BuiltIn`, `USB`, `Bluetooth`, `Aggregate`, `Virtual`, else the four-char code), `kAudioDevicePropertyNominalSampleRate`.
- Logging through `Logger(subsystem: "com.brennanmke.SkinAmp", category: "AudioOutput")` (the project's subsystem): one line when the default changes, one when the engine is bound (device, name, transport, nominal rate, processing rate chosen by `connectIfNeeded`), one on failure. These lines are what the hand test reads.

### 2. `AudioGraph` (`Packages/PlayerKit/Sources/AudioCore/AudioGraph.swift`)

- `init` takes `outputDevices: any OutputDeviceProvider` (store it) and keeps its other parameters.
- New `var outputDevice: AudioDeviceID?`: the device the output unit should use; nil means "whatever the engine chose at creation" (no eager bind at first start, so existing behaviour and tests are unchanged until a change arrives).
- `start()`: after `guard !engine.isRunning`, before `connectIfNeeded()`, call a new private `bindOutputDeviceIfNeeded()`: `if let outputDevice, outputDevices.boundDevice(of: engine.outputNode) != outputDevice { try outputDevices.bind(outputDevice, to: engine.outputNode) }`. Bind first, then read the rate: `connectIfNeeded()` keeps reading `engine.outputNode.outputFormat(forBus: 0).sampleRate`, which reflects the newly bound device once the unit has it. Log the bound device and the chosen processing rate; if the node reports 0 or a rate that differs from `describe(outputDevice)?.nominalSampleRate`, log both (the mixer converts, so it still plays; this is diagnostic for section 5).
- New `func stopEngine()`: `if engine.isRunning { engine.stop() }`. `AudioGraph` never restarts by itself; `Player` decides.
- `connectIfNeeded()` and the -10868 rule are unchanged: it still only runs from `start()` while stopped, now after the device bind, so a device with another rate reconnects player → EQ → mixer at that rate (the path #0042 verified) and the analyzer is re-installed with it.

### 3. `Player` (`Packages/PlayerKit/Sources/AudioCore/Player.swift`)

- `public init(resolver: any TrackResolver = FileTrackResolver(), outputDevices: any OutputDeviceProvider = SystemOutputDeviceProvider())`; store `outputDevices`, pass it to `AudioGraph` in `ensureGraph()`. The app's `PlexPlaybackStack`/`PlayerModel` keep calling the existing initialiser; nothing in `App/` changes.
- In `ensureGraph()`, next to `configTask`, start `outputTask`: `for await id in outputDevices.defaultOutputDeviceChanges() { guard let self else { break }; self.outputDeviceChanged(to: id) }`. Started lazily with the graph, so players that never play install no listener. Add `deinit { configTask?.cancel(); outputTask?.cancel() }` (today `configTask` is never cancelled; tests create many players).
- `outputDeviceChanged(to id:)`: `guard let graph = _graph else { return }` (no engine yet: the one created later picks the current default), `graph.outputDevice = id`, log, `requestOutputReconfigure()`.
- The `AVAudioEngineConfigurationChange` loop calls `requestOutputReconfigure()` too.
- `requestOutputReconfigure()`: coalesces. `guard !outputReconfigurePending`; set it; `Task { @MainActor [weak self] in self?.outputReconfigurePending = false; self?.reconfigureOutput() }`. Two triggers for one switch (our listener plus the engine's own notification, in either order, or two listener callbacks) become one restart when they land in the same turn; a later one simply repeats the idempotent handler (one more restart from the current position, a render quantum of discontinuity).
- `reconfigureOutput()` replaces `handleConfigurationChange()`:

```swift
private func reconfigureOutput() {
    guard let graph = _graph else { return }
    graph.stopEngine()                       // also when the engine stopped itself already (no-op)
    // Stopped or loading: nothing is scheduled; the next start() (play / begin) binds and connects.
    guard state != .stopped, state != .loading else { return }
    let resumeTime = currentTime
    do {
        discardSchedule()
        graph.playerNode.stop()
        try graph.start()                    // bind → connectIfNeeded at the new rate → analyzer
        if let file {
            let frame = AVAudioFramePosition(resumeTime * file.processingFormat.sampleRate)
            schedule(file, from: min(frame, max(file.length - 1, 0)))
            if state == .playing { graph.playerNode.play() }
            scheduleNextIfNeeded()
        }
    } catch {
        fail(error)
    }
}
```

  Differences from today: the explicit `stopEngine()` first (covers the listener path, where the engine is still running, and the `stopped`/`paused` cases where `stop()` left it running), and the bind inside `start()`. `pause`/`play`/`seek`/`reconcileSchedule` are untouched: `startedGraph()` and `begin` already call `graph.start()`, which now binds when `outputDevice` is set and the engine is stopped.
- A device that disappears (HomePod powered off, headphones unplugged) makes macOS move the default back to another device, which arrives as a normal change. If `engine.start()` throws on the new device, `fail(error)` stops with `errorMessage` as today; the user presses Play again. Do not retry in a loop.
- Optional, cheap: after a successful reconfigure while playing, `emit(.seeked(resumeTime))` so `NowPlayingBridge` refreshes elapsed time after the restart gap. Only if it does not disturb `NowPlayingTests`; otherwise skip and say so in `## Fix`.

`AudioCoreError`: add `case outputDevice(underlying: any Error)` with a description ("Could not switch the audio output device: …").

### 7. Risks

- **The working theory may be partly wrong.** If the output unit turns out to follow the default by itself (default-output subtype) and `setDeviceID` is refused, the real provider's fallback paths and the test-11 diagnostics tell the implementer; the stop/restart on the listener event is still the fix, and the bind becomes a no-op. Record which it was in `## Fix`.
- **Output rate after the bind.** `connectIfNeeded()` reads the output node's format; if it is stale right after `setDeviceID`, the graph connects at the old rate and the mixer converts (audible but wasteful, and the EQ/analyzer stay at the old rate). The bind line logs both rates so the hand test catches it; the fallback is to use `describe(outputDevice)?.nominalSampleRate` in `connectIfNeeded` when the node reports a different value.
- **Double restart.** Our listener and the engine's own notification can both fire for one switch; `requestOutputReconfigure()` coalesces same-turn triggers, and a straggler costs one idempotent restart from the current position (a render quantum of discontinuity), not a wrong state. Test 6 pins the same-turn case.
- **AirPlay latency.** A system-level AirPlay device has ~2 s of output latency. `currentTime` is node time, so the time display and the visualizer lead what is heard by that much. Accepted for option C; the fix for that is enhanced buffering plus PTS-keyed analysis (#0052, #0054), not this issue.
- **Listener thread.** The CoreAudio block runs on our serial queue; the only thing it does is read the default and yield into the stream, which the main-actor task consumes. No engine or player state is touched off the main actor.
- **Device loss.** A failing `engine.start()` on a vanished device ends in `fail(error)` (stopped, message), matching today's error handling; no retry loop.
- **Tests and the real provider.** Every existing test still constructs `Player()` with the real provider: it only installs a listener lazily, the guest's default never changes, and `bind` no-ops in manual rendering mode, so the offline suite stays silent and device-free. The two real-time tests touch only the device the engine already uses.
- **Gapless regression.** `reconfigureOutput()` is the #0042 configuration-change path with a bind added; the pre-schedule happens after the restart as before. The optional `--stress 10` run covers #0055's gap detector.

## Root cause

`AVAudioEngine`'s output node on macOS is a HAL output unit (confirmed in the guest: unit subtype `ahal`, bound to the Apple Virtual Sound Device, id 68) tied to the `AudioDeviceID` it was created on. A new system default output never reached it, and `handleConfigurationChange()` restarted the engine without telling it which device to use, so audio stayed on the built-in speaker. `Player.stop()` also leaves the engine running, so a device change while stopped was never picked up by the next `play()`.

## Fix

The plan was followed (option C, follow the system default). `OutputDeviceProvider` (new) wraps CoreAudio: `kAudioHardwarePropertyDefaultOutputDevice` listener as an `AsyncStream` (lazy install, removed on cancel), `auAudioUnit.setDeviceID` with an `AudioUnitSetProperty` fallback, and a device description (name, transport, nominal rate) for the `AudioOutput` log category. `AudioGraph` binds in `start()` before `connectIfNeeded()` reads the rate, and gained `stopEngine()`. `Player` starts the listener with the graph, coalesces it with the engine's configuration-change notification in `requestOutputReconfigure()`, and `reconfigureOutput()` replaces `handleConfigurationChange()`: refresh `currentTime` while the node still renders, stop the engine, restart through `start()`, reschedule from the saved position (plus the next file), and emit `.seeked`. `AudioCoreError.outputDevice` added (whole-source scoped).

Adaptations to landed work: (1) #0039 progressive tracks: `reconfigureOutput()` keeps the `.loading`-with-progressive case and restarts the feeder (`startFeeder(... preroll: state == .loading)`) instead of rescheduling a file; the two existing #0039 tests were renamed to call `reconfigureOutput()`. (2) `ScheduleDiagnostic` gained `seekOffset` (set in both schedule sites, the progressive one included). (3) `Player.init` gained `outputDevices:` with a default, so `App/` is unchanged; `AudioGraph.init` has the same default so existing tests compile. (4) The `.seeked` emit was kept; `NowPlayingTests` pass. (5) Real-time test 12 differs from the plan: `AudioGraph` skips the bind when the unit already reports the target device, so with the real default no bind is recorded; the test instead calls `setDeviceID(current)` on the stopped output unit directly (accepted) and asserts the player restarts and finishes with `.reachedEnd` and no error.

## Notes

Starting points, unverified:

- `AVAudioEngine`'s output node binds to an output device. `Player.handleConfigurationChange()` (`Packages/PlayerKit/Sources/AudioCore/Player.swift`) restarts the engine on `AVAudioEngineConfigurationChange`, but that may not fire for a default-output change, and the engine may stay on the device it started with. Check whether the output unit follows `kAudioHardwarePropertyDefaultOutputDevice`, or set the device explicitly when the default changes. Since #0042 the graph is connected once at the output rate; a new device with a different rate needs that revisited.
- Music.app's multi-speaker selection is AirPlay 2 multi-room, which Apple exposes for long-form audio through `AVRoutePickerView` / `AVRouteDetector` and an `AVPlayer` or `AVSampleBufferAudioRenderer` pipeline, not a raw `AVAudioEngine` output. Supporting it may mean changing the output stage (for example, rendering the engine offline and feeding an `AVSampleBufferAudioRenderer`) while keeping the EQ, gapless scheduling and analyzer tap.
- See [docs/airplay-macos-handoff.md](../docs/airplay-macos-handoff.md). This issue covers following the system output choice (option C, the fallback and local path); in-app multi-speaker selection is #0051 and #0052.

Hand-testing only: tests must stay silent, and the VM has no AirPlay path.
