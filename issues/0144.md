## Root cause

`MusicBackend` had no API for reading a queue, so `PlaylistModel` could only show AudioCore's local queue. With a speaker selected the list was empty, and while Music Assistant fed This Mac it showed the local queue.

## Fix

- **Backend API:** `MusicBackendKit/RemoteQueue.swift` adds `RemoteQueueItem`, `RemoteQueueSnapshot`, `QueueEdit.play(index:)` and `BackendCapabilities.queueEditing` (1 << 9). `queue(on:)` and `edit(_:on:)` become protocol requirements, with defaults that return an empty snapshot and throw unsupported.
- **Queue watcher:** `MusicAssistantKit/MAQueueWatch.swift` fetches the queue (`player_queues/get`), then its items (`player_queues/items`):
  - It pages 500 items at a time up to the 2,000-item cap (decision 10) and shows the first page at once.
  - It refetches on `queue_items_updated`/`queue_updated` for its own queue id only, with a 150 ms debounce. It also refetches on a 30 s poll and after a reconnect.
  - It decodes `media_item` as a track leniently, through `MAQueueItem.track`.
- **Backend wiring:** `MusicAssistantBackend+Queue.swift` adds `queue(on:)` and `edit(.play)`, which sends `player_queues/play_index`. Both resolve the queue through the active queue, so a synced speaker uses its leader's queue and This Mac uses its Sendspin wrapper. The queue watchers restart and stop alongside the now-playing watchers.
- **Row source:** `LibraryBrowser/QueueRows.swift` adds `QueueRowsSelection.choose` and the `QueueRows` text and time helpers.
- **App:** `PlayerModel.observeQueue()` follows `selectedOutput` and `thisMacFeed`. `PlaylistModel.remote` maps the snapshot onto `Track` rows, keeping each row's id stable per queue item, so rows, selection, running time, shade text, the HTML export and File Info all work unchanged. Double-click and Return play the row through `edit(.play(index:))`. Remove, crop, sort and drag show the marquee notice "Not for Music Assistant queues" (#0145 adds these edits).

Deviations from the plan:
- The types are named `RemoteQueue*` because LocalPlayback already has a `QueueSnapshot`.
- The new request builder lives in `MAQueueWatch.swift` rather than `MARequest.swift`.
- `StubMusicBackend` and `PlaylistWindowView` are unchanged: the protocol defaults cover the stub, and `run` already routes through `PlaylistModel`.
- The notice text is shortened to fit the marquee's 31-character limit.
- `capabilitiesIncludeRemoteOutputs` now uses `isSuperset`, so capability bits added by other M13 items don't break it.
