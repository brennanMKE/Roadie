## Description

#0060 recorded every request/response shape from the Music Assistant server, but no pushed event arrived in any recording window (nothing was playing, and the recorder never sends a transport command). The event envelope (`event`, `data`, and whether `object_id` is present) and the payloads of `player_updated`, `queue_updated` and `queue_time_updated` are therefore taken from the API landing page, not from the server. `events.json` in `Packages/PlayerKit/Sources/MusicAssistantKitStub/Fixtures/` is empty.

## Acceptance criteria

- Re-run `/usr/bin/python3 -I scripts/record-ma-fixtures.py --events-seconds 60` on the host while the user, by hand from the MA web UI, pauses and resumes (or skips on) a speaker that is already playing. The recorder stays read-only; the hand action is the only thing that changes player state.
- `events.json` holds the captured frames (scrubbed; the secret gate and `--check` pass).
- `docs/ma-protocol-notes.md` section 8 records the envelope keys, whether `object_id` is present, and the `player_updated` / `queue_time_updated` payload fields, and #0061's event decoding and #0064's now-playing mapping are checked against them.

## Notes

Until then #0061 should decode events leniently: `event` string, optional `object_id`, `data` kept as raw JSON. Needs a user hand action, so it cannot run unattended.
