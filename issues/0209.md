## Description

The Welcome window (#0169), the four Settings tabs, the Help menu and the Debug-build update UI have no automated coverage beyond the pure `FirstRunPolicy`. This issue adds `FirstLaunchUITests` and `SettingsUITests`. Rows: [docs/design/test-automation.md](../docs/design/test-automation.md) §5.9 and the Help/Updates rows of §5.1.

## Plan

### `Tests/RoadieUITests/FirstLaunchUITests.swift`

- `welcomeOnFreshDefaults`: launch with `firstRun: true` (`-firstRunVersion 0`, no skins folder, no `lastSkinPath`, no `LibraryFolderPath`, Music Assistant `.none`) → the Welcome window exists with its three sections (texts "Skins", "Music Folder", "Music Assistant (optional)"), the skins folder shows the default folder (`DefaultSkinsFolder`) with `0 skins`; "Browse the Skin Museum…" opens the Skins window on the Museum tab; "Open Library" opens the Library; "Set Up Music Assistant…" opens Settings on the Music Assistant tab (`settingsSelectedTab`); "Continue" closes it and `defaults read co.sstools.roadie firstRunVersion` is 1 (read with `Process`, or relaunch and assert no Welcome).
- `existingUserSkipsWelcome`: `-firstRunVersion 0 -lastSkinPath <skin>` → no Welcome; after launch `firstRunVersion` is 1 (`.markCompleted`).
- `welcomeOpensMuseum`: as above, Browse the Skin Museum… → the Museum tab (also when the default folder has no skins, the Welcome opens the Museum at once: `welcome.show(openMuseum: true)`; assert the Skins window is up with Museum selected).
- `helpMenu`: Help › Welcome to Roadie… reopens the window; Help › Playlists and the Queue… → `probe.lastExternalOpen == "https://roadie.sstools.co/help.html#playlists"`.
- `chooseMusicFolderFromWelcome`: "Choose Music Folder…" is a panel; with `-RoadieChooseFolder <music>` (test-mode stand-in from #0202/#0203's `PanelStandIns`) → the folder text updates and the status reads the indexing result.

### `Tests/RoadieUITests/SettingsUITests.swift`

- `libraryTab`: Settings (⌘,) › Library: the source picker lists Music Assistant and the folder; with the folder configured and Music Assistant `.none`, the folder is selected; `library.folder` shows the path; Reindex → `library.status` goes through indexing to the track count; Clear → the folder is unset and the Library window shows the "needs a folder" state; the picker switch to Music Assistant with `scenario: .libraryIdle` changes the Library's sidebar (Playlists appears); `library.sourceStatus`/`library.sourceRetry` show when the source fails (`scenario: .unreachable`).
- `musicAssistantTab`: with `scenario: .libraryIdle`: the server list has the seeded row (`ma.servers`), name and address fields hold its values, the token field shows the "stored" prompt, "Test Connection" → green dot and `Verified: <name>` (the scripted server answers), "Check Now" → status refresh; Add Server → an empty row, fill `ma.name`/`ma.address` with `ma2.example:8095`, Test Connection → the scripted factory answers for any host, so it verifies (or, with `-RoadieMAScenario unreachable` on the second host, fails with the reason in `ma.reason`); Remove Server; "Play Music Assistant on this Mac" toggle flips `probe.sendspinEnabled`; "Stop playback when Roadie quits" persists; Wi-Fi networks: add a name, remove it; "Use Current Network" is disabled/no-op without Wi-Fi access in the guest (assert it doesn't crash and the list is unchanged); "Find Servers on This Network" shows "No servers found" with discovery off.
- `skinsTab` is in #0208; keep a one-line existence check here.
- `updatesTab`: in Debug both toggles are disabled, "Check Now" disabled, the text "Updates are off in development builds." is shown; Roadie › Check for Updates… disabled (also asserted in #0202; keep both, they're cheap).
- `settingsTabPersists`: select the Skins tab, close Settings, reopen → Skins (the `settingsSelectedTab` default).

## Resolution notes

> 🟢 Resolved 2026-10-29 — FirstLaunchUITests and SettingsUITests cover the Welcome, the Help menu and the Settings tabs, each checking the outcome a user sees.

Proven by UI `FirstLaunchUITests` (`welcomeOnFreshDefaults`, `existingUserSkipsWelcome`, `welcomeOpensMuseum`,
`helpMenu`, `chooseMusicFolderFromWelcome`) and `SettingsUITests` (`libraryTab`, `musicAssistantTab`, `updatesTab`,
`settingsTabPersists`), and unit `SkinLibraryModelTests.applyDefaultFolderCreatesAndStoresTheDefault` and
`.testConfigurationDefaultSkinsFolderIsInItsDataDirectory`. Passing run: 20261029-194323-33034.

Review: bounced once (Opus, medium; nine findings, all fixed in f464e8e), then the re-review (Opus, medium) approved
f464e8e.

## Root cause

No bug: the Welcome (#0169), Settings' tabs, the Help menu and the Debug update UI had no UI tests. Two things blocked
them. A fresh install created `~/Roadie/Skins` even in test mode. The music-folder panel had no test stand-in.

## Fix

- `FirstLaunchUITests` (`welcomeOnFreshDefaults`, `existingUserSkipsWelcome`, `welcomeOpensMuseum`, `helpMenu`,
  `chooseMusicFolderFromWelcome`) and `SettingsUITests` (`libraryTab`, `musicAssistantTab`, `updatesTab`,
  `settingsTabPersists`). `settingsTabPersists` also checks that all five tabs exist, Visualization (#0241) included.
  It doesn't repeat what `VisualizationUITests` covers.
- Test hooks:
  - `RoadieConfiguration.defaultSkinsFolder`: a test configuration's default skins folder is `<data>/Roadie/Skins`.
    `SkinLibraryModel` takes it as `defaultFolderURL`.
  - `-RoadieChooseFolder <path>` answers `chooseMusicFolder(startingAt:)`. It is Debug and UI-test mode only, and is
    listed in `PanelStandIns.swift`.
  - The probe's `sendspinEnabled` and `firstRunVersion`. The second is read from the suite's persistent domain, because
    the `-firstRunVersion` argument shadows reads.
  - Welcome section-header identifiers.
- The tests use #0202's `launch(skinsFolder: .none, loadsSkin: false)` for a fresh install. Rows added in design §5.9.
  `docs/testing-in-vm.md` lists the new argument.
- After review (bounce 1):
  - `musicAssistantTab` waits for `ma.status` to read "Connected to Scripted Music Assistant" (absent before the
    click), not the "Verified:" line the seeded server shows anyway. Check Now is proven by the probe's new
    `maResolutions` (`MusicAssistantSelectionController.resolutionCount`, now public): the scripted resolution is too
    fast to see the button disabled. The second server first reads "Enter a token.", then with a typed token
    "Connected to Second"; Remove Token is clicked and the prompt goes back to the Music Assistant one.
  - Find Servers moved to `libraryTab`: with no server and Music Assistant preferred, the Library shows the banner,
    and the stub `/info` answers the well-known `homeassistant.local`, so an offer appears. The skipped branch in
    `musicAssistantTab` is gone. `libraryTab` also clicks Choose… (`-RoadieChooseFolder`).
  - `settingsTabPersists` relaunches with `keepingDefaults: true` and Settings opens on Skins.
  - `welcomeOnFreshDefaults` no longer clicks Browse the Skin Museum… (it checks the automatic open and clicks Open
    Skin…, recorded in `panelRequests`); `welcomeOpensMuseum` closes the Skins window first, so its check sees the
    button's Museum. `chooseMusicFolderFromWelcome` clicks Open Library. `updatesTab` checks the Last checked row.
  - Unit `SkinLibraryModelTests.applyDefaultFolderCreatesAndStoresTheDefault` and
    `.testConfigurationDefaultSkinsFolderIsInItsDataDirectory`.
  - Run 20261029-193431-29071 (10 of 11): Test Connection was disabled, because the recordings' host
    `http://ma.example:8095` is neither local nor Tailscale ("Use https for this address…"; the screenshot). The test
    now moves the seeded server to `ma.local:8095` (the stub answers `/info` for any host with the same server id)
    and the second to `ma2.local:8095`, and waits for the button to be enabled.
  - Design §5.9 rows trimmed to what is tested: Skins › Choose Folder… is by hand (a real panel), Retry Now is only
    shown, Cancel and Replace With This Server… aren't clicked.

## Gotchas

- Review note (non-blocking): `musicAssistantTab` reads the Check Now baseline after a fixed 2 s pause
  (SettingsUITests.swift:271-279), to let the resolution that the address change starts finish first. The pause can't
  make the test fail. A resolution scheduled late, though, could raise `maResolutions` after the baseline is read and
  let the test pass without Check Now. To harden it, wait until `maResolutions` has stayed the same for about 1 s
  before reading the baseline.
