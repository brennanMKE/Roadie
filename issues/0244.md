# 0244 — The Music Assistant drop tests sometimes time out waiting for play_media

| | |
|---|---|
| **Status** | open |
| **Module** | Tests |
| **Platform** | macOS |
| **First seen** | 2026-10-29 |

## Description

Two of #0228's `PlayerModelDropTests` fail now and then in VM runs for issues that don't touch the app. Each time, the 10 s `waitUntil` for a `player_queues/play_media` command runs out, and the scripted server's command list stops at `get_active_queue`:

- `testDropOnAMusicAssistantQueueAppends`: #0233 run 20261029-015601-98926 (`["auth", "auth", "all", "time", "all", "all", "get", "all", "get", "get_active_queue"]`), passed on rerun 20261029-020638-3932.
- `testOptionDropOnAMusicAssistantQueueReplaces`: #0234 review run 20261029-024649-26536, passed on rerun 20261029-025155-29255.

Both runs had two VM guests busy. The test connects, sets `model.selectedOutput` to the scripted speaker, then drops; the failures look like the drop arriving before the speaker's queue is active (a connect-then-select race, like the one fixed in #0221's UI test), so the drop goes to the local queue or is dropped.

## Expected behavior

The tests wait for the selected speaker's queue to be ready before dropping, or the model queues the drop until it is, and they pass on every run.
