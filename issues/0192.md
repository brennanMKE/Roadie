## Description

Umbrella for milestone **M16: Test automation**. 0.0.4 shipped with bugs that every automated check passed over ([#0186](0186.md)–[#0191](0191.md)): double-clicking a row of a Music Assistant queue played the first track (the real server sends `"index": 0` for every item; the hand-made fixtures numbered rows), Library → playlist drags never worked, playlists couldn't be played. There is no UI test target, the App target has no unit tests, and the VM's `app-launch` step only checks the app is still up after 5 s. This milestone builds the test automation that would have caught each of them, and changes the workflow so every later issue adds to it. It ships no user-visible change and stays open until every child is resolved, closed or won't-fix.

Design: [docs/design/test-automation.md](../docs/design/test-automation.md) (tiers, test mode, fixtures, UI test strategy, skin selection, the feature inventory in §5, runner changes, process changes, risks). The children follow its order: infrastructure first, then UI tests by feature area, then backfilled unit tests, then the process docs.

The user's requirements, verbatim, are quoted at the top of the design doc. In short: fast unit tests with mocks and real audio files, run and passing before review; slower regression tests once per milestone; UI tests over a cached selection of Museum skins covering everything the user can do; a Haiku runner that keeps logs out of context and returns only failures.

## Findings (checked against the code, 2026-10-24)

- **No App tests.** `project.yml` has one app target and two Quick Look extensions; the `Roadie` scheme's test action lists only the 13 package test targets. `App/` is 10,060 lines in 86 files; `PlayerModel.swift` is 1,171 of them.
- **The composition root hard-wires the world.** `PlayerModel.init()` (`App/PlayerModel.swift:330–500`) builds `LocalPlaybackStack.standard()`, `KeychainMusicAssistantTokenStore`, `MusicAssistantBackend` with the default `URLSessionWebSocketTransportFactory`, `SystemServiceBrowser`, `SystemWiFiNetwork`, `URLSessionMuseumTransport`, `QueueStore.defaultURL()` and `SkinIndexStore.defaultURL`. Every one of those already has an injectable seam in its package (`MusicAssistantBackend(transports:)`, `InMemoryMusicAssistantTokenStore`, `StubWebSocketTransport`, `StubMuseumTransport`, `QueueStore(fileURL:)`, `SkinLibraryModel(defaults:databaseURL:)`), so test mode is wiring, not new abstractions.
- **Launch arguments already reach `UserDefaults.standard`.** `run-tests-vm.sh --launch` passes `-firstRunVersion 1` and `make-screenshots.sh` writes `lastSkinPath`, `eqWindowOpen`, `playlistWindowOpen`, `playlistWindowSize`, `windowLayout` with `defaults write`. `NSArgumentDomain` wins over the persisted domain, so UI tests can set every persisted setting on the command line.
- **Accessibility identifiers exist only in SwiftUI settings views** (`library.*`, `skins.*`, `ma.*`, `player.browseMuseum`). None of the skinned windows' controls have one; their `Button`s have `EmptyView` labels, so XCUITest sees unlabeled buttons. The playlist rows are drawn by SwiftUI (`PlaylistTrackListView`) under an AppKit `PlaylistListInputView` that owns the mouse.
- **The fixtures are real but idle.** `MAFixture` lists 42 recorded files; `player-queue-items.json` was recorded against an empty queue (`"result": []`), which is why `BackendQueueTests.itemJSON` invented `"index": n`. The #0133 captures (`player-queue-items-loaded` and friends) are declared but not recorded (`isRecorded == false`). The recorder (`scripts/record-ma-fixtures.py`) is read-only with an allow-list, scrubs in process and gates secrets; it already has the structure for one more read-only recipe.
- **Audio fixtures are generated WAVs.** `writeWAV`/`writeSine` in the test supports; one tagged M4A is written at test time (`writeTaggedM4A`). No MP3, AAC-from-file, ALAC or FLAC decode is tested. `.gitignore` ignores `*.mp3` everywhere.
- **Skins.** `scripts/make-test-skin.swift` writes a three-sheet skin for Quick Look; `GeneratedBaseSkin` fills missing sheets in code. The Museum's GraphQL (`https://skins.webamp.org/graphql`, `fetch_skin_by_md5`, `search_classic_skins`) and CDN (`https://r2.webampskins.org/skins/<md5>.wsz`) were reachable from the host on 2026-10-24; the seven skins in the design doc's table were downloaded and their md5s and contents checked.
- **The runner needs no change.** `verify.sh` already matches XCTest's `Test Case '…' passed` lines for `--expect`; it needs the XCTest failure format, screenshot paths and a `UI` line.
- **The golden image** has admin auto-login, "Automation Mode without authentication" and developer mode baked in (docs/testing-in-vm.md), which is what XCUITest needs. Unproven for Roadie until #0200's smoke test runs.

## Open decisions (defaults in the plans; say if you want otherwise)

1. **Per-issue UI runs** are required when the plan's `## UI tests` names classes, i.e. when the change touches `App/` UI; package-only issues skip them. Alternative: every `App/` change runs `--ui`.
2. **Audio in UI tests** plays through the guest's muted virtual device (as `make-screenshots.sh` does); manual rendering is reserved as a fallback (`RoadieConfiguration.silentOutput`).
3. **Coverage floors** (design §2.4): 85 % packages, 70/80 % AudioCore, 60 % App rising to 80 %. They fail only the milestone run.
4. **Skin selection** (design §4): `base-2.91`, `Expensive_HI_FI_Sony_2005`, `base` (S190947), `Windows_Classic` (S210427), `Pika_Amp`, `Windows_98_Amp`, the Internet Archive skin. The cache lives in `~/Library/Caches/co.sstools.roadie-test-skins/`.
5. **Regression-test-first** costs one extra Haiku run per bug fix (`--expect-fail`). Alternative: trust the plan's description of the failing assertion.
6. **`--record-queue`** needs you to run the recorder once with a queue loaded on your server; until then the loaded-queue scenario is synthetic with `index: 0` applied on purpose.
