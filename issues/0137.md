## Root cause

SkinAmp never asked the server which commands it offers, so features missing on the recorded 2.10.6 server (`music/playlists/move_playlist_track`) could not be hidden, and an error 12 was only a generic backend error.

## Fix

- New `MusicAssistantKit/MAServerCommands.swift`: `MAServerCommands` parses only the `command` names of `GET <base>/api-docs/commands.json` (no auth); any failure yields `.empty`. A backend extension adds `commands`, `supports(_:)`, `awaitCommandProbe()`, `perform(_:)` and `noteUnsupported(_:command:)`: error 12 removes the command for the session (and from the cache) and maps to `MusicBackendError.unsupported` (`.playlists` for playlist commands).
- `MusicAssistantBackend.connect()` starts the probe as a non-blocking `Task` after the handshake, reusing a cached result per `server_id|server_version`; `disconnect()` cancels it and clears the set. `http` became internal for the extension.
- `StubHTTPTransport` answers `/api-docs/commands.json` from the new `Fixtures/commands-names.json` (the 310 recorded entries trimmed to `command`).
- `BackendLibraryTests.artworkAsksTheProxyForAnAllowedSizeWithoutAuth` now picks the last image-proxy request, since the probe request can land after it.
