## Review

Reviewed `git show 30a5c09` against the plan in design §3.6 and §4 W4a. **Connect is never blocked.** `connect()` starts the probe as an unstructured `Task` after the handshake. The task captures `self` weakly and the transport by value. The previous probe is cancelled on reconnect, and `disconnect()` cancels it and clears the set, so no task outlives the backend. `MAServerCommands.probe` never throws: a transport error, a non-200 status or an unreadable body all give `.empty`. **No credentials are sent.** The probe passes `headers: [:]`. `URLSessionHTTPTransport` adds only `Accept: */*`, uses an ephemeral session and refuses redirects. The test asserts empty headers on the recorded request. **Cache key:** `server_id|server_version`, falling back to the base URL if there is no server info. A server upgrade therefore probes again. An empty result is not cached, so a failed probe is retried on the next connect. **Error 12:** `MusicAssistantError.server(code: 12, …)` removes the command from the live set and the cache, and maps to `MusicBackendError.unsupported(.playlists)` for playlist commands. Every other error still goes through `Self.map`. For now only `perform(_:)` sends its errors through it; W4 and the later writers are expected to use `perform`/`noteUnsupported`, as the plan says. **Artwork test:** it now filters to `/imageproxy/` requests and still checks the path, each size mapping and that headers are empty. It is as strict as before; it just ignores the probe's request, which can arrive at any time. **Thread safety:** all state is actor-isolated. The probe's result returns to the actor through `installCommands`. Two minor, non-blocking races: (1) a probe that finishes just as `disconnect()` runs can still install its set after the clear; (2) `await fresh.serverInfo` is a reentrancy point in `connect()`. Both only fill a set that the next connect resets, and neither touches the token. A generation check in `installCommands` would close the first if it ever matters. ## Root cause

SkinAmp never asked the server which commands it offers, so features missing on the recorded 2.10.6 server (`music/playlists/move_playlist_track`) could not be hidden, and an error 12 was only a generic backend error.

## Fix

- New `MusicAssistantKit/MAServerCommands.swift`: `MAServerCommands` parses only the `command` names of `GET <base>/api-docs/commands.json` (no auth); any failure yields `.empty`. A backend extension adds `commands`, `supports(_:)`, `awaitCommandProbe()`, `perform(_:)` and `noteUnsupported(_:command:)`: error 12 removes the command for the session (and from the cache) and maps to `MusicBackendError.unsupported` (`.playlists` for playlist commands).
- `MusicAssistantBackend.connect()` starts the probe as a non-blocking `Task` after the handshake, reusing a cached result per `server_id|server_version`; `disconnect()` cancels it and clears the set. `http` became internal for the extension.
- `StubHTTPTransport` answers `/api-docs/commands.json` from the new `Fixtures/commands-names.json` (the 310 recorded entries trimmed to `command`).
- `BackendLibraryTests.artworkAsksTheProxyForAnAllowedSizeWithoutAuth` now picks the last image-proxy request, since the probe request can land after it.
