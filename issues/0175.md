# 0175 — The queue can't be filtered Winamp-style, and the playlist can't scroll a row into view

## Description

Phase A of M15, the pure groundwork for Jump to File (#0176). Two pieces:

- A matcher that filters the playlist's rows the way Winamp's `J` dialog did. Case and diacritics are folded, every whitespace-separated token must match, and results keep playlist order.
- A playlist scroll rule that brings a given row into view, so a Jump can move the playlist editor to the row it plays.

Both live in packages, so they can be unit-tested. No App code changes.

Spec: [docs/music-selection-features.md](../docs/music-selection-features.md) §3 Phase A, "Matching".

## Plan

### 1. Matcher (`Packages/PlayerKit/Sources/LibraryBrowser/JumpToFileMatcher.swift`, new)

LibraryBrowser has no AudioCore dependency (`Package.swift`: `["MusicBackendKit", "MusicLibraryKit"]`). So the matcher takes plain strings, not `Track`.

```swift
/// One playlist row as Jump to File searches it (#0175). Empty strings for unknown fields.
public struct JumpToFileEntry: Hashable, Sendable {
    public var artist: String
    public var title: String
    public var album: String
    /// The file name for a local file; "" for a remote queue row.
    public var fileName: String
    public init(artist: String, title: String, album: String = "", fileName: String = "")
}

/// Winamp's Jump to File filter over a playlist (#0175): built once per queue, queried per keystroke.
public struct JumpToFileIndex: Sendable {
    public init(_ entries: [JumpToFileEntry])
    public var count: Int { get }
    /// Row indices, in playlist order, whose text contains every token of `query`. An empty or whitespace-only
    /// query gives every row.
    public func matches(_ query: String) -> [Int]
    /// The same, but gives up and returns nil when `isCancelled()` turns true (checked every 1,024 rows).
    public func matches(_ query: String, isCancelled: () -> Bool) -> [Int]?
    /// Case-, diacritic- and width-insensitive folding, locale-independent.
    public static func fold(_ text: String) -> String
    /// `fold(query)` split on whitespace and newlines, empty pieces dropped.
    public static func tokens(_ query: String) -> [String]
}
```

- `fold`: `text.folding(options: [.caseInsensitive, .diacriticInsensitive, .widthInsensitive], locale: nil)`.
- **Haystack per row**, folded once in `init` (not per keystroke): `"\(artist) - \(title)\n\(album)\n\(fileName)"`. Tokens can't hold `\n`, so a token never matches across two fields. The ` - ` lets a query copied from the displayed text ("Daft Punk - Technologic") match.
- **Storage for speed:** one flat `[UInt8]` buffer of every folded haystack's UTF-8, plus `[Int]` start offsets (count + 1). Match each token with `memmem` (`import Darwin`) over the row's slice, inside `withUnsafeBufferPointer`. A row matches when every token is found. Check the longest token first, so rows fail sooner.
- **Order:** keep playlist order; there is no ranking (Winamp didn't rank).
- **Incremental narrowing:** not needed. A linear `memmem` scan over 50,000 rows of about 60 bytes is about 3 MB.

### 2. Reveal a row (`Packages/SkinKit/Sources/SkinKit/Display/PlaylistScroll.swift`)

Add:

```swift
/// The position (0...100) that brings row `index` into view with the least scrolling: unchanged when it is already
/// visible, else it becomes the first visible row (when above) or the last (when below). 0 when nothing overflows.
public static func position(revealing index: Int, position: Double, count: Int, visibleRows: Int) -> Double
```

- `overflow = overflow(count:visibleRows:)`. If overflow is 0, return 0.
- `start = offset(position:...)`. If `start..<start+visibleRows` contains `index`, return `position` unchanged.
- Otherwise the target offset is `index` when `index < start`, else `index - visibleRows + 1`. Clamp it to `0...overflow` and return `Double(target) / Double(overflow) * 100`. `offset(position:)` rounds `p/100 × overflow`, so that maps back to exactly `target`.
- Clamp an out-of-range `index` to `0..<count`. With `count == 0`, return 0.

### Tests

`Packages/PlayerKit/Tests/LibraryBrowserTests/JumpToFileMatcherTests.swift` (new, `@Suite struct JumpToFileMatcherTests`):

- `emptyQueryMatchesEveryRowInOrder`: `""` and `"   "` give `[0, 1, 2]`.
- `everyTokenMustMatch`:
  - `"daft tech"` finds Daft Punk - Technologic, but not Daft Punk - One More Time or Tech N9ne - Fragile.
  - The token order doesn't matter: `"tech daft"` gives the same result.
- `matchingFoldsCaseAndDiacritics`:
  - `"beyonce"` finds "Beyoncé".
  - `"SIGUR ROS"` finds "Sigur Rós".
  - `"ｄａｆｔ"` (fullwidth) finds "Daft".
- `tokensMatchArtistTitleAlbumOrFileName`: one token each for the artist, the title, the album, and a file name like `03 Intro.flac`.
- `tokensDoNotSpanFields`: artist "Daft", title "Punk". `"daftpunk"` doesn't match; `"daft punk"` does.
- `displayedTextMatches`: `"daft punk - technologic"` matches.
- `resultsKeepPlaylistOrder`: matching rows 7, 2 and 5 come back as `[2, 5, 7]`.
- `cancelledMatchReturnsNil`: `matches("a", isCancelled: { true })` on 5,000 rows is nil.
- `fiftyThousandRowsFilterQuickly`:
  - 50,000 synthetic entries (artist `"Artist \(i % 997)"`, title `"Title \(i)"`, album `"Album \(i % 4001)"`).
  - Measure with `ContinuousClock`. `init` takes under 3 s and `matches("artist 42 title 1")` under 0.2 s. The bounds are loose for a debug build in the VM; they catch an accidental O(n²).
  - Print both durations with `print` so a run records them.
