## Root cause

No bug. The views' decisions (what a selection plays, titles, symbols, which footer or bar shows) were written inline in private view members, where a unit test can't reach them. `PlayerModel`'s Add to Playlist and favourite paths had no model test. `SkinThumbnailView` lost its last caller when #0035's grid drew its own cells.

## Fix

- **Views (plan step 3):** the inline logic moved into `static` helpers next to each view, and the views now call them, with no behaviour change:
  - `DiscoverRowView.playable` and `request`
  - `TrackListView.heading`, `albumArtist` and `openPlaylist(album:playlist:)`
  - `PlaylistTracksView.confirmTitle(count:playlist:)` and `PlaylistEditingModifier.deleteTitle(_:)`
  - `RadioListView.request(_:in:)` and `AddRadioSheet.canAdd(url:adding:)`
  - `OutputPickerView.name(of:devices:)`, `RowState` with `rowState(_:selection:)`, and `groupIsChecked`
  - `PlaylistEditBar.Content` and `content(pending:error:)`
  - the new `PagedListFooter` enum, which `PagedListView`'s footer switches on
  - `SearchResultsView.ResultSection` and `sections(_:)`

  `FavoriteKindsView.title` and `symbol` were already static. #0205's `primaryAction`, `menu` and `pushAfterDoubleClick` are untouched.
- **`LibraryPlaybackActions.swift` (plan step 4):** a new `LibraryPlayAction` enum (play, next, append) builds the `PlayRequest`s that the track and container menus use.
- **Step 5:** `SkinThumbnailView.swift` is deleted, `SkinThumbnailPlaceholder` with it. A grep found no references.
- **Departure, no `MusicBackendStub`:** RoadieTests doesn't link it, and `PlayerModel` has no seam to inject a backend. The model tests use the scripted Music Assistant server for the paths that reach a backend, and the folder backend (no playlist editing, no favourites) for the refusals.
- **Departure, "Added to favorites" untested:** the scripted server answers `players/add_currently_playing_to_favorites` with "unknown command". `favoriteCurrentTrack` is tested for the command it sends and for the "Couldn't favorite" notice; testing the success text would need a handler in `MusicAssistantKitStub`.
- **Departure, `PlaylistMessageBar`:** covered through `playlistsModel.message` after a refused add, not through a separate helper.
- **Departure, test names:** they carry XCTest's `test` prefix, matching the surrounding files.
- **Found, filed separately:** `PlaylistsModel.create(named:adding:)` can return a stale `message` from an earlier failure, filed as [#0255](0255.md). The tests here avoid that order.
