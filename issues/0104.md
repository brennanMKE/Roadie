# 0104 — SkinAmp does not find a Music Assistant server on the network it is on

| | |
|---|---|
| **Status** | open |
| **Module** | MusicAssistantKit / App |
| **Platform** | macOS |
| **First seen** | 2026-10-19 |

## Description

The user moves between more than one network, each with its own Home Assistant and Music Assistant, and wants SkinAmp to detect which server is reachable and use it. #0075 picks the reachable one among servers already added and tested in Settings › Music Assistant, but a server only becomes a candidate after the user types its address, pastes a token and presses Test Connection while on that network. Nothing finds a server for them, so on a network they haven't set up yet the app just says no server is reachable.

#0060 found that the Music Assistant add-on does not advertise `_music-assistant._tcp`. Home Assistant itself does advertise `_home-assistant._tcp` over Bonjour, and the add-on serves Music Assistant on the same host at port 8095 (`GET /info` needs no auth and returns `server_id`).

## Expected behavior

- On the current network, SkinAmp finds Music Assistant servers without the user typing an address: browse `_home-assistant._tcp` (and any `_music-assistant._tcp` if a future server advertises it), plus well-known names such as `homeassistant.local`, then probe `http://<host>:8095/info`.
- A found server that isn't configured yet is offered in Settings › Music Assistant (and in the Library's "no server reachable" state) with one action to add it; the user pastes a token for it once. The token is still sent only after the `server_id` check, as today.
- A found server that is already configured (same `server_id`) under another address is recognised as the same server, not offered again; reaching it at the discovered address counts as reachable for #0075's selection.
- After that, moving between networks needs no user action: #0075's selection picks whichever configured server answers.
- Discovery never sends a token, never prompts at launch, and logs no host names, addresses or server ids.
- `NSBonjourServices` gains `_home-assistant._tcp` (and `_music-assistant._tcp` if used); `scripts/check-info-plist.sh` is updated to match (it currently asserts the key is absent, #0063).

### Design in one paragraph

Discovery runs only while someone is looking: while Settings › Music Assistant is on screen, and in the Library after the user presses **Find Servers on This Network**. It never runs at launch or in the background, so the macOS Local Network prompt can only follow a user action. It collects candidate hosts from two sources:
- the well-known name `homeassistant.local`;
- Bonjour browses for `_home-assistant._tcp` and `_music-assistant._tcp`.

It turns each host into `http://<host>:8095`, but only for hosts ATS treats as local (`MusicAssistantAddressInput.isLocalHost`). It probes each base URL once with the existing unauthenticated `/info` fetcher (`MusicAssistantServerSelector.InfoFetcher`, so no header and no token) and a 3 s timeout. Each answer is then sorted:
- **Not configured:** the `server_id` matches no stored server, and the URL matches no stored row. It becomes an **offer**, deduped by `server_id` (the first URL wins).
- **Configured at another address:** the `server_id` matches a stored server but the URL doesn't. It is not offered. If exactly one stored server has that id and its address is plain `http` and not Tailscale, discovery probes that stored address once. If the stored address does not answer with the same id, the stored address is replaced by the discovered one through the settings model. The persist then re-runs #0075's selection (`serversEdited` → `serversChanged`), so the server counts as reachable at the new address. #0075's selector, ranking and controller are unchanged.

Adding an offer creates an **untested** row: the address and the server's name, no `serverID`. The user pastes the token and presses Test Connection, exactly as today, so the token goes only through the existing test path (`/info` first, then the socket's id check).

### 1. `MusicAssistantDiscovery.swift` (package)

```swift
/// A host found on the network. `port` nil means Music Assistant's default (8095), as for a Home Assistant host.
public struct MusicAssistantDiscoveredHost: Hashable, Sendable {
    public var host: String
    public var port: Int?
    public init(host: String, port: Int? = nil)
}

/// Bonjour behind a protocol (#0104). Browsing starts when the stream is iterated and stops when it terminates.
/// Yields each host once per browse; never logs names or addresses.
public protocol MusicAssistantServiceBrowser: Sendable {
    func hosts() -> AsyncStream<MusicAssistantDiscoveredHost>
}

/// A Music Assistant server found on the network that is not configured yet. `id` is its `server_id`. User data: UI only, never logged.
public struct MusicAssistantDiscoveredServer: Identifiable, Hashable, Sendable {
    public var id: String
    public var url: URL
    public var name: String?
}

public enum MusicAssistantDiscovery {
    public static let serviceTypes = ["_home-assistant._tcp", "_music-assistant._tcp"]
    public static let wellKnownHosts = ["homeassistant.local"]
    /// `http://host:port`, port default 8095. Lowercased, a trailing dot dropped, IPv6 bracketed. nil for a host ATS
    /// does not treat as local (`MusicAssistantAddressInput.isLocalHost`), a scoped IPv6 (`%`), or an empty host.
    public static func baseURL(for host: MusicAssistantDiscoveredHost) -> URL?
    /// Home Assistant's TXT record: the host of `internal_url`, else of `base_url`. nil when neither parses or the host is not local.
    public static func host(fromTXT txt: [String: String]) -> String?
}
```

`MusicAssistantDiscoveryModel` is `@MainActor @Observable public final class`, with a redacted `CustomStringConvertible` like the settings model.
- **init:** `init<C: Clock>(store: MusicAssistantServerStore, browser: any MusicAssistantServiceBrowser, fetch: @escaping MusicAssistantServerSelector.InfoFetcher, clock: C, probeTimeout: Duration = .seconds(3)) where C.Duration == Duration`. It does no I/O.
- **Observed state:** `public private(set) var offers: [MusicAssistantDiscoveredServer] = []` and `public private(set) var isSearching = false`, which is true while the browse runs or any probe is in flight.
- **`onConfiguredServerMoved`:** `@ObservationIgnored public var onConfiguredServerMoved: (@MainActor (_ id: UUID, _ url: URL) -> Void)?`.
- **`start()`:** reference-counted (`users += 1`), because Settings and the Library can both be showing it. The first user clears the `probed` set, the found servers and `offers`, then:
  1. probes `wellKnownHosts`;
  2. starts one task with `for await host in browser.hosts()`.
  
  Every host goes through `baseURL(for:)`. A URL that is nil or already in `probed: Set<URL>` is skipped; any other URL gets a probe task.
- **`stop()`:** `users -= 1`; at 0, cancels the browse task and every probe task. Offers are kept until the next start.
- **`refreshOffers()`:** recomputes `offers` from the found servers minus the configured ones (see below). Called after every probe answer and by the views after an add or a list change.
- **`waitForIdle()`:** for tests; awaits the outstanding probe tasks.
- **Probe:** `fetch(url)` raced against `clock.sleep(for: probeTimeout)` in a task group, the same shape as the selector's private `probe`. Copy those ~15 lines; don't make the selector's internals public. Any error, a timeout or a cancellation means no answer.
- **On an answer `info` at `url`:** load `store.load()` and handle it as follows.
  1. If any stored server has `address.baseURL == url`, do nothing; that row is already there, tested or not.
  2. Else, if any stored server has `address.serverID == info.serverID`, the server is configured at another address:
     - Collect the stored servers with that id. Proceed only if exactly one exists, its scheme is `http`, and `!MusicAssistantServerRanking.isTailscale(baseURL)`.
     - Probe its stored `baseURL` the same way.
     - If that probe doesn't answer with `info.serverID`, call `onConfiguredServerMoved?(server.id, url)`. This happens at most once per server per `start()`.
  3. Else, record `MusicAssistantDiscoveredServer(id: info.serverID, url: url, name: info.name)` in `found` if that id isn't there yet, then `refreshOffers()`.
  
  The filter in `refreshOffers()` drops a found server whose id matches a stored `serverID`, or whose url matches a stored `baseURL`. Order: well-known first, then the browse order.
- **Logging** (`Logger` subsystem `com.brennanmke.SkinAmp`, category `MusicAssistantDiscovery`): start/stop and, on idle, `"\(probed) probed, \(answered) answered, \(offers.count) offered, \(moved) moved"`, with integers only. Never a host, URL, name, TXT value or server id. The fetcher has no token parameter, so discovery cannot send one.

### 2. `App/Network/SystemServiceBrowser.swift` (app, `import Network`)

`struct SystemServiceBrowser: MusicAssistantServiceBrowser`. `hosts()` makes an `AsyncStream` (`bufferingPolicy: .unbounded`) and a private `@unchecked Sendable` box that owns everything on one serial `DispatchQueue(label: "com.brennanmke.SkinAmp.bonjour")`, as `MonitorBox` does.
- For each `MusicAssistantDiscovery.serviceTypes` entry, start `NWBrowser(for: .bonjourWithTXTRecord(type: type, domain: nil), using: .tcp)`.
- `browseResultsChangedHandler`: handle only `.added` changes, as follows.
  - **TXT first:** if `result.metadata` is `.bonjour(let txt)` and `MusicAssistantDiscovery.host(fromTXT: txt.dictionary)` gives a host, yield `MusicAssistantDiscoveredHost(host: host)`. For `_music-assistant._tcp`, take the port by resolving, below, instead.
  - **Otherwise resolve:** `NWConnection(to: result.endpoint, using: .tcp)` on the same queue. On `.ready`, read `connection.currentPath?.remoteEndpoint`:
    - `.hostPort(.ipv4(let a), let p)` gives the dotted string from `a.rawValue`'s four bytes;
    - `.hostPort(.name(let n, _), let p)` gives `n`;
    - skip IPv6.
    
    Yield with `port: nil` for `_home-assistant._tcp` (its advertised port is 8123) and `port: Int(p.rawValue)` for `_music-assistant._tcp`, then `cancel()`. Cancel on `.failed`/`.waiting`, and after 3 s via `queue.asyncAfter`. Nothing is sent on the connection.
- `continuation.onTermination` cancels every browser and pending connection.
- Log only state kinds and counts (for example `browser failed`, with the `NWError` code `.public`), never names, endpoints or TXT.

### 3. Settings model (`MusicAssistantSettingsModel.swift`)

Both methods may run when Settings never appeared, which leaves `servers == []`. So each starts with `commitEdits()` and then `servers = store.load()`. Every mutation persists, so reloading loses nothing, and `persist()` can't then wipe the stored list.

- `public func addDiscoveredServer(_ found: MusicAssistantDiscoveredServer)`:
  - If a stored row has `baseURL == found.url` or `serverID == found.id`, `select` it and return.
  - Otherwise append `MusicAssistantServerConfiguration(name: found.name nonEmpty ?? defaultName, address: MusicAssistantServerAddress(baseURL: found.url))`, deliberately with **no `serverID`**: an untested row is not a selection candidate and gets its id from Test Connection.
  - Then `persist()`, `select(new.id)`, and log `"discovered server added: N now"`.
- `public func adoptDiscoveredAddress(_ url: URL, for id: UUID)`:
  - Find the row and set `address.baseURL = url`, keeping `serverID`, `networks`, `name` and the token (same Keychain account).
  - `persist()`. This calls `onServersChanged`, so the selection re-checks.
  - If that row is selected, `loadDraft()`.
  - Log `"server address updated from discovery"`.

### Host checklist (needs the user's Mac and networks; not verifiable in the guest)

1. Open Settings › Music Assistant on a network with Home Assistant. macOS asks for Local Network access once. The server appears under "On This Network". Add it, paste a token and Test Connection; it connects and turns green, and the offer disappears.
2. On a network whose server is already configured (by IP), it is not offered.
3. Change that server's IP (or configure it at a stale IP), open Settings. The row's address becomes the discovered one and Check Now picks it.
4. In the Library with no server reachable, **Find Servers on This Network** lists the server, and **Add…** opens Settings on the new row.
5. Console (`subsystem:com.brennanmke.SkinAmp category:MusicAssistantDiscovery`) shows counts only.
6. A fresh launch with the Library window restored shows no Local Network prompt until a discovery button or the Settings tab is used.

### For the user to decide (defaults in brackets)

- **Rewrite the stored address when the same server is found elsewhere and the old address is dead?** [Yes: plain-http, non-Tailscale rows only.] The alternative keeps discovered addresses in memory and teaches the selector to probe alternates. It is larger: candidate alternates, a reached-URL result, and identity checks in `MusicAssistantActiveServer` and `refreshActive`.
- **Also browse `_sendspin-server._tcp`?** [No.] #0060 saw Music Assistant itself advertise it, so it would find standalone (Docker) Music Assistant servers without Home Assistant. It needs one more `NSBonjourServices` entry and a `port: nil` mapping.
- **Discovery in Settings starts on opening the Music Assistant tab** [yes]. The Library requires a button press so a restored window can't trigger the Local Network prompt at launch.
