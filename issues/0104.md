# 0104 — SkinAmp does not find a Music Assistant server on the network it is on

| | |
|---|---|
| **Status** | open |
| **Module** | MusicAssistantKit / App |
| **Platform** | macOS |
| **First seen** | 2026-10-19 |

## Description

The user moves between more than one network, each with its own Home Assistant and Music Assistant, and wants SkinAmp to detect which server is reachable and use it. #0075 picks the reachable one among servers already added and tested in Settings › Music Assistant, but a server only becomes a candidate after the user types its address, pastes a token and presses Test Connection while on that network. Nothing finds a server for them, so on a network they haven't set up yet the app just says no server is reachable.

#0060 found that the Music Assistant add-on does not advertise `_music-assistant._tcp`. Home Assistant itself does advertise `_home-assistant._tcp` over Bonjour, and the add-on serves Music Assistant on the same host at port 8095 (`GET /info` needs no auth and returns `server_id`).

## Expected behavior

- On the current network, SkinAmp finds Music Assistant servers without the user typing an address: browse `_home-assistant._tcp` (and any `_music-assistant._tcp` if a future server advertises it), plus well-known names such as `homeassistant.local`, then probe `http://<host>:8095/info`.
- A found server that isn't configured yet is offered in Settings › Music Assistant (and in the Library's "no server reachable" state) with one action to add it; the user pastes a token for it once. The token is still sent only after the `server_id` check, as today.
- A found server that is already configured (same `server_id`) under another address is recognised as the same server, not offered again; reaching it at the discovered address counts as reachable for #0075's selection.
- After that, moving between networks needs no user action: #0075's selection picks whichever configured server answers.
- Discovery never sends a token, never prompts at launch, and logs no host names, addresses or server ids.
- `NSBonjourServices` gains `_home-assistant._tcp` (and `_music-assistant._tcp` if used); `scripts/check-info-plist.sh` is updated to match (it currently asserts the key is absent, #0063).
