## Description

With Music Assistant as the default, Plex as the alternative and a local folder as the last fallback, SkinAmp should still have a library when the chosen source isn't set up or can't be reached.

## Acceptance criteria

- If the selected source isn't configured, the app uses the next configured source in the order Music Assistant → Plex → local folder, and Settings and the browser say which source is in use and why.
- If the selected source is configured but unreachable at launch or drops later, the app offers (or performs, per the decision below) the switch to the next available source, and returns to the preferred source when it becomes reachable again without interrupting what is playing.
- Fallback never discards settings or tokens of the unavailable source.

## Plan

### Scope and decisions

**Decision (a revisable default, set by the orchestrator on 2026-10-14; the user can override it before implementation).** Fallback is **automatic**: if the selected source isn't configured, or is configured but unreachable at launch or drops later, the app switches to the next available source in the order Music Assistant → Plex → local folder and shows a brief notice (the marquee, plus a line in Settings › Library and the Library window saying which source is in use and why). Switching **back is also automatic** when the preferred source becomes reachable again, and it never interrupts playback: the browser switches back, the queue keeps playing on This Mac. If the user prefers a one-click offer instead, only section 5's `.activate` handling changes (post the offer, activate on accept); the engine, probes and tests stay.

This issue builds on #0070 (`LibrarySourceController`, the one switch) and must land after it. #0063 (MA settings) and #0061 (MA client) are not done, so with today's sources the behaviour covers Plex ↔ Local Folder; section 13 says where MA plugs in without touching the engine. #0045's `StatusNotice` is the marquee slot for the notice. Nothing here changes `MusicBackendKit`'s protocol, `PlexKit`, `PlexBackendKit`, `LocalPlayback`, `AudioCore` or `TrackCache`.

- **Three parts, two of them pure.** (1) A per-source *probe* (`SourceProbe`: "is this source usable right now?"). (2) A pure state machine, `LibraryFallbackPolicy`, in the `LibraryBrowser` target: preferred, active, reason, per-source health and the retry schedule; it takes events and a time value and returns effects, no I/O, no clock, no actors. (3) A `@MainActor` driver, `LibraryFallbackController`, also in `LibraryBrowser`: owns the policy, an injected `Clock`, the probe tasks and the timers, and turns effects into `LibrarySourceController.select` calls and notices. #0070 says "the controller never switches on its own"; the driver is the one thing that calls `select` besides the Settings picker.
- **No I/O at launch, ever.** `start()` reads only `LibrarySource.isConfigured` (UserDefaults; #0070). A network probe runs only (a) when the Library window's own `connect()` fails or a browse/play throws `.unreachable`/`.unauthorized` on the active source, (b) on the retry schedule while in fallback, (c) on a settings change or a Retry, and in every case only for a source whose `isConfigured()` is true. In the Tart guest nothing is configured, so `app-launch` performs no request and never touches the Keychain; the existing "the Library window connects, nothing connects at launch" rule is kept.
- **The engine only moves on probe results.** The Library window's `connect()` outcome *is* a probe result for the active source (no second request). A browse or play failure on the active source is a *report*, confirmed by one probe before falling back (a lost page is not proof the server is gone; the probe is two small requests for Plex, a `stat` for the folder). Every switch, forward or back, follows a `.reachable` result for the source being activated, so the browser never lands on a source that was just seen down.
- **Cheap probes, no hammering.** Plex: `PlexBackend.connect()` (the existing three-step `PlexConnectionTest`: identity, sections with the token, music section; `connectionTimeout` 15 s; reads the Keychain once per call, as it does today). Folder: `FolderBackend.checkReachable()`, a `stat` (`storedFolder` non-nil, exists, directory, readable), no index, no scan. MA later: its own handshake probe. Schedule while in fallback: 5, 10, 20, 40, 80, 160 s, then every 300 s; at most one probe in flight and one timer per source; a minimum spacing of 5 s between probes of one source whatever triggered them; a trigger (report, settings change, Retry) resets the backoff to the first step. Only sources *ahead of the active one* in candidate order are retried; the active source is never polled (its failures reach the engine through the browser).
- **Candidate order = the preferred source, then the others in list order.** `LibrarySourceController.sources` is already in fallback order (#0070: MA → Plex → folder once #0063 prepends MA). With the preferred `P`, candidates are `[P] + sources.filter { $0.id != P }`. So a user who prefers the folder and loses it falls back to MA, then Plex; the acceptance criterion's order is the list order.
- **Preferred vs active.** #0070's `select(_:)` persists the choice; the fallback must not overwrite the user's preference, so the controller gains `preferredID` (persisted) beside `selectedID` (active) and `select(_:persist:)`. The driver always passes `persist: false`; the picker goes through `fallback.userSelected(_:)`, which sets both. The fallback state itself is never persisted: a relaunch always starts on the preferred source when it is configured, which is the cheapest way to "switch back".
- **Nothing is discarded.** The driver writes no defaults, never calls `disconnect()`, never touches a token store. `PlexBackend.connect()` failing calls its private `reset()` (in-memory client only), as it does today; `FolderBackend.checkReachable()` reads nothing but the path. Tested in section 9 (`fallbackNeverWritesDefaultsOrDisconnectsABackend`).
- **Switching keeps playback by construction** (#0070: Plex and the folder share one `LocalPlayerOutput`/`Player`; `select` touches no transport, and the now-playing subscription is re-pointed, not reset). The driver adds no transport call anywhere; a test asserts no `.transport` reaches either stub across a fallback and a restore.
- **Messages.** Marquee notices (≤ 31 UTF-16 units so they sit still, per #0045): `Using Local Folder` with detail `Plex can't be reached` or `Plex isn't set up`; `Back on Plex` on restore. Settings › Library, under the picker: `Using Local Folder: Plex can't be reached. SkinAmp switches back when it is.` / `Using Local Folder: Plex isn't set up.`; nothing when the active source is the preferred one. Library window subtitle: `Local Folder (Plex unavailable)`. All built by one pure `FallbackText` from display names, tested.
- **Verification is `scripts/run-tests-vm.sh --launch` only.** Nothing on the host. Tests use `StubMusicBackend`s, a `ManualClock`, a private `UserDefaults` suite and closures for probes; no `Player`, no audio, no network, no Keychain, no token or address anywhere.

### 4. `LibraryFallbackPolicy.swift` (pure)

```swift
public enum SourceProbeOutcome: Hashable, Sendable { case reachable, notConfigured(String), unreachable(String) }

public enum FallbackReason: Hashable, Sendable { case notConfigured, unreachable(String) }

public struct RetrySchedule: Hashable, Sendable {
    public var steps: [Duration]          // 5, 10, 20, 40, 80, 160 s
    public var cap: Duration              // 300 s
    public var minimumSpacing: Duration   // 5 s
    public static let `default`: RetrySchedule
    /// steps[failures - 1], the last step repeated, never above `cap`; `failures` ≥ 1.
    public func delay(afterFailures failures: Int) -> Duration
}

public struct SourceHealth: Hashable, Sendable {
    public var outcome: SourceProbeOutcome?   // last result, nil until probed
    public var failures: Int                  // consecutive, reset by .reachable, retryRequested and userSelected
    public var lastProbeEnded: Duration?      // engine time
    public var isProbing: Bool
    public var hasTimer: Bool
}

public struct LibraryFallbackPolicy: Hashable, Sendable {
    public enum ActivationKind: Hashable, Sendable { case user, fallback, restore }
    public enum Event: Hashable, Sendable {
        case start, userSelected(String), configuredChanged, retryRequested
        case failureReported(String), probeResult(String, SourceProbeOutcome), probeAborted(String), probeDue(String)
    }
    public enum Effect: Hashable, Sendable {
        case activate(String, ActivationKind), probe(String), schedule(String, after: Duration), cancelSchedule(String)
    }

    public let order: [String]
    public let schedule: RetrySchedule
    public private(set) var preferred: String
    public private(set) var active: String
    /// nil exactly when `active == preferred`.
    public private(set) var reason: FallbackReason?
    public private(set) var health: [String: SourceHealth]
    public var candidates: [String] { [preferred] + order.filter { $0 != preferred } }

    public init(order: [String], preferred: String, schedule: RetrySchedule = .default)
    /// `configured` is read at the moment of the event (defaults only); `now` is any monotonic duration.
    public mutating func handle(_ event: Event, configured: (String) -> Bool, now: Duration) -> [Effect]
}
```

`precondition`s: `order` non-empty and distinct, `preferred` in `order`. Rules (each pinned by a test in section 9):

- **Invariants.** `active ∈ order`; `reason == nil ⇔ active == preferred`; per source at most one of `isProbing`/`hasTimer`; a timer exists only for a source that is configured and *ahead* of `active` in `candidates`; `.probe` is never emitted for an unconfigured source or one already probing.
- **`.start`**: `active` = the first configured candidate, else `preferred`. If `active != preferred`: `reason = .notConfigured`, effect `[.activate(active, .fallback)]`. No `.probe`, no `.schedule` (the preferred is unconfigured, so nothing ahead qualifies). With nothing configured: `active = preferred`, `reason = nil`, no effects (the Library shows its own "not set up" message with Open Settings…, as today).
- **`.probeResult(id, .reachable)`**: `failures = 0`, `isProbing = false`, `lastProbeEnded = now`. If `id` is ahead of `active`: `active = id`; `reason = nil` if `id == preferred` else unchanged; effects `[.activate(id, id == preferred ? .restore : .fallback)]` plus `.cancelSchedule` for every timer no longer ahead (none in practice; kept for the invariant) and `.schedule` for every configured candidate still ahead of the new `active` without a timer (`delay(afterFailures: max(1, failures))`). If `id` is behind `active` (it was probed while advancing): same activation with `.fallback`. If `id == active`: no effect.
- **`.probeResult(id, .unreachable(m))`**: `failures += 1`, `outcome` recorded, `isProbing = false`, `lastProbeEnded = now`. If `id == preferred`: `reason = .unreachable(m)` (even while still active; it becomes visible once something else is active). Then: `id == active` → *advance*: the first configured candidate after `id` that is not probing → `[.probe(next)]`; none → `[]` (stay; the Library keeps showing the error with Retry). `id` behind `active` (an advance step that failed) → advance from `id` likewise. `id` ahead of `active` → `[.schedule(id, after: delay(afterFailures: failures))]`, `hasTimer = true`.
- **`.probeResult(id, .notConfigured(m))`**: like unreachable but `failures = 0`, no timer (it waits for `.configuredChanged`); `reason = .notConfigured` when `id == preferred`.
- **`.probeAborted(id)`**: `isProbing = false`, nothing else (a cancelled probe is no evidence).
- **`.probeDue(id)`**: `hasTimer = false`; `[.probe(id)]` iff `configured(id)`, `id` ahead of `active` and not probing; else `[]`.
- **`.failureReported(id)`**: `[.probe(id)]` iff `id == active`, `configured(id)`, not probing and `lastProbeEnded` is nil or older than `minimumSpacing`; if a probe ended within the spacing: `[.schedule(id, after: remaining)]` unless a timer exists. (The active source is the one exception to "timers only ahead": this timer is a deferred confirmation; `.probeDue` for the active source probes it iff `configured` and not probing.) `id != active` → `[]`.
- **`.configuredChanged`**: for every configured candidate ahead of `active` with neither probe nor timer: `.probe(id)` if the spacing allows, else `.schedule(id, after: remaining)`. For every timer whose source is no longer configured: `.cancelSchedule(id)`. If `!configured(active)`: treat as `.probeResult(active, .notConfigured("…"))` (advance; the browser will show "Choose a music folder…" meanwhile).
- **`.retryRequested`**: `failures = 0` for every source; then as `.configuredChanged`, with timers that exist cancelled and replaced by an immediate `.probe` (spacing permitting) so a Retry at the 300 s cap does not wait.
- **`.userSelected(id)`** (`id ∈ order`, else `[]`): `preferred = id`, `active = id`, `reason = nil`, all `failures = 0`, every timer cancelled (`.cancelSchedule`), `[.activate(id, .user)]` last. Even when `id` is known unreachable: the user asked, the browser connects, reports, and the fallback engages again with a notice.

Effects are emitted in a fixed order (cancels, then probes/schedules, then the activation) so tests can compare arrays.

### 5. `LibraryFallbackController.swift` (driver) and `FallbackText.swift`

```swift
public typealias SourceProbe = @Sendable () async -> SourceProbeOutcome
public extension SourceProbe {  // static helpers on a namespace enum `SourceProbes` if Swift rejects the typealias extension
    /// `.reachable` when `check` returns; `.notConfigured`/`.unreachable` from the thrown `MusicBackendError`
    /// (any other error is `.unreachable(localizedDescription)`). Rethrows nothing: cancellation is detected by the driver.
    static func checking(_ check: @escaping @Sendable () async throws -> Void) -> SourceProbe
}

public struct FallbackStatus: Hashable, Sendable {
    public var preferredID: String, preferredName: String, activeID: String, activeName: String
    public var reason: FallbackReason?
}

public struct FallbackNotice: Hashable, Sendable { public var text: String; public var detail: String? }

@MainActor @Observable
public final class LibraryFallbackController {
    public private(set) var status: FallbackStatus
    /// The policy, for tests and the Settings line.
    public private(set) var policy: LibraryFallbackPolicy
    /// Called for every automatic switch (never for `userSelected`). PlayerModel posts it in the marquee.
    public var onNotice: (@MainActor (FallbackNotice) -> Void)?

    public init(sources: LibrarySourceController, schedule: RetrySchedule = .default,
                clock: any Clock<Duration> = ContinuousClock())
    public func start()                      // handle(.start); defaults only; call once from PlayerModel.init
    public func userSelected(_ id: String)   // the picker's setter
    public func settingsChanged()            // UserDefaults.didChangeNotification
    public func retryNow()                   // a Retry button, NSWorkspace.didWakeNotification
    /// PlayerModel.playFromLibrary's catch. Only `.unreachable` and `.unauthorized` matter; everything else is ignored.
    public func report(_ error: any Error, from sourceID: String)
    public func stop()                       // cancels timers and probes (tests, deinit)
    // tests
    public var timerCount: Int, probeCount: Int
}
```

- `init` installs `sources.onBackendFailure = { [weak self] id, error, phase in … }`: `.connect` phase → `handle(.probeResult(id, outcome(error)))` (`.notConfigured(m)` → `.notConfigured(m)`; `.unreachable(m)`/`.unauthorized`/`.backend(m)` → `.unreachable(error.errorDescription)`); `.browse` phase with `.unreachable`/`.unauthorized` → `handle(.failureReported(id))`; anything else ignored. `report(_:from:)` is the same mapping for the browse phase. A failure arriving for an id that is not `sources.selectedID` is ignored (a stale model).
- `handle(_ event:)`: `let effects = policy.handle(event, configured: { id in source(id)?.isConfigured() ?? false }, now: uptime())`, then `apply(effects)`, then `status = FallbackStatus(policy, sources)`. `uptime()` is `start.duration(to: clock.now)`, with `start = clock.now` captured in `init`; the engine never sees an `Instant`.
- `apply`: `.activate(id, kind)` → `sources.select(id, persist: kind == .user)`; for `.fallback`/`.restore`, `onNotice?(FallbackText.notice(kind:status:))`. `.probe(id)` → `probes[id] = Task { let outcome = await probe(); guard !Task.isCancelled else { return handle(.probeAborted(id)) }; handle(.probeResult(id, outcome)) }` (the task inherits the main actor; the probe closure runs wherever the backend does). `.schedule(id, after)` → `timers[id] = Task { try? await clock.sleep(for: after); guard !Task.isCancelled else { return }; timers[id] = nil; handle(.probeDue(id)) }`. `.cancelSchedule(id)` → cancel and drop. `stop()` cancels all of both.
- Logging: `Logger(subsystem: "com.brennanmke.SkinAmp", category: "LibraryFallback")`, `info` for every activation (`"fallback to <id>: <reason case>"`, `"restored <id>"`), `debug` for probes and schedules; ids and case names only, never a message that could carry a host (the backend messages are user-facing and hostless already, but keep them out of logs anyway).

`FallbackText` (pure, tested):

```swift
public enum FallbackText {
    /// "Using Local Folder" / detail "Plex can't be reached" or "Plex isn't set up"; "Back on Plex" with no detail.
    public static func notice(kind: LibraryFallbackPolicy.ActivationKind, status: FallbackStatus) -> FallbackNotice
    /// Settings › Library: nil when active == preferred; else
    /// "Using Local Folder: Plex isn't set up." / "Using Local Folder: Plex can't be reached. SkinAmp switches back when it is."
    public static func summary(_ status: FallbackStatus) -> String?
    /// Library window: "Local Folder" or "Local Folder (Plex unavailable)".
    public static func subtitle(_ status: FallbackStatus) -> String

```

The `.unreachable` message itself (e.g. Plex's "Can't reach the server. Check the address…") is not repeated in the notice or summary; it is already on screen in the Library window's `.failed` state and in Settings › Plex.

### 6. Probes per source (composition in `PlayerModel.init`)

```swift
LibrarySource(backend: stack.backend, isConfigured: { PlayerModel.plexIsConfigured() })        // probe default: connect()
LibrarySource(backend: folderBackend, isConfigured: { FolderBackend.storedFolder() != nil },
              probe: SourceProbe.checking { try FolderBackend.checkReachable() })
```

- **Plex**: `connect()` is the probe. It is the cheapest existing path that answers "can I use this library" (three small requests, `connectionTimeout` 15 s) and on success leaves the backend connected, so the browser's `appeared()` after the switch is a second cheap test, not a cold start. A failed probe calls `reset()` (in-memory), never the token store. It reads the Keychain once per probe through `settingsProvider`, which only runs when `plexIsConfigured()` (defaults) is true, i.e. after the user set Plex up and approved the item; never in the guest.
- **Folder**: `checkReachable()` is a `stat`; a folder on an unmounted volume is `.unreachable("The music folder “X” can't be read.")` and keeps its path, as #0065 decided. Reconnecting after the volume returns goes through the browser's `connect()`, which serves the cached index.
- **Music Assistant (later)**: `LibrarySource(backend: ma, isConfigured: { host stored }, probe: SourceProbe.checking { try await ma.probe() })` where `probe()` is a handshake without subscribing to events; until #0061 defines it, the default `connect()` works.

### 7. How it drives `LibrarySourceController.select`

- Launch: `fallback.start()` after the controller is built. Preferred unconfigured, folder configured → `select("folder", persist: false)`; the Library window, when opened, connects the folder model (#0070's `.task(id:)`). Nothing else happens until a window connects.
- Library window opens on the preferred, `connect()` fails `.unreachable` → hook (`.connect`) → `probeResult(plex, .unreachable)` → `.probe(folder)` (a stat) → `.reachable` → `select("folder", persist: false)` + notice → the window's `.task(id: ObjectIdentifier(player.library))` re-runs `appeared()` on the new model → the folder connects and shows → `.schedule(plex, 5 s)`.
- Timer: `probeDue(plex)` → `connect()` → still down → `.schedule(plex, 10 s)` … up → `select("plex", persist: false)` + `Back on Plex` → the window reconnects Plex; the queue on This Mac never noticed. If the window is closed at that moment the model is rebuilt idle and connects when the window next opens.
- Plex drops mid-session: a page, tracks, search or `playFromLibrary` throws `.unreachable` → `failureReported(plex)` → one confirming `connect()` → down → `.probe(folder)` → … as above.
- Settings: the picker's setter is `fallback.userSelected(id)` → `select(id, persist: true)`; `UserDefaults.didChangeNotification` (any write, including the folder path and the Plex selection) → `fallback.settingsChanged()`; the engine re-reads `isConfigured` and probes a newly configured preferred at once (spacing permitting). A Retry Now button beside the summary line calls `retryNow()`.

### 11. Risks and gotchas

- **`select` persistence.** #0070's `select(_:)` writes defaults. Every call from the driver must pass `persist: false`; the test `fallbackNeverWritesDefaultsOrDisconnectsABackend` is the guard. If #0070 lands with a different signature, add the flag there in this issue and say so in `## Fix`.
- **A confirming probe on the active Plex backend resets its client.** `connect()` failing calls `reset()`, so a browse still in flight on the old client then throws `.notConnected` (ignored by `reportFailure`). The probe only runs after the active source has already failed, and the model is rebuilt on the switch, so nothing the user sees changes; note it in `## Gotchas` if the reviewer asks.
- **`any Clock<Duration>` as an existential.** `clock.sleep(for:)` on the existential compiles on the toolchain in the golden image (Swift 6 language mode); if it does not, make the driver generic over `C: Clock where C.Duration == Duration` and let `PlayerModel` hold `LibraryFallbackController<ContinuousClock>`. The engine takes `Duration`, not an `Instant`, for exactly this reason.
- **Keychain.** Every Plex probe reads the Keychain through `settingsProvider`, as `connect()` already does from the Library window. It never runs unless `plexIsConfigured()` (defaults only) is true, never at launch, and never in tests (probes are closures over stubs). Do not call `PlexBackend.settingsProvider` from `isConfigured`.
- **`UserDefaults.didChangeNotification` fires for every write** (time mode, skin path, cache limit…). `settingsChanged()` then costs one `isConfigured` read per source and probes only if something ahead is configured and the 5 s spacing allows; the engine's coalescing (one probe or timer per source) is what makes this safe. Do not filter by key.
- **Notices on a flapping server.** Backoff bounds the probes; the marquee's "last wins" rule (#0045) bounds the noise; the Settings line is the durable place to read the state. If it still feels chatty, raise `steps[0]` to 15 s: one constant.
- **The Library window must key its task on the model** (#0070's `.task(id: ObjectIdentifier(player.library))`), or a fallback while the window is open leaves the new model idle. With the window closed nothing connects, which is fine: the next open does.
- **Observation.** `status` is a stored property on the driver, so Settings and the subtitle re-render; `policy` is stored too but views must not read it (tests only). The failure hooks run on the main actor by construction (`PagedList.fail`, `connectFinished`, `tracksFinished`, `searchFinished` are `@MainActor`).
- **Stale reports after a switch.** A task started on the old model can still fail after `select`; the driver drops reports whose id is not `sources.selectedID`, and `reportFailure` ignores `.notConnected`.
- **Selected output.** Fallback never touches `PlayerModel.selectedOutput`; with #0064's remote outputs, a switch away from MA must follow #0070 section 9's rule there, not here.
- **Removable folders.** The stat probe is instant and FSEvents keeps watching the old path; when the volume returns, the browser's `connect()` serves the cache. SMB/NFS folders answer the stat even when stale; a play failure (`"None of these tracks is on disk any more."`, a `.backend` error) is not a reachability report by design.
- **Swift 6.** The policy is a value type and `Sendable`; the driver is `@MainActor`; probe closures are `@Sendable`; `ManualClock` keeps its sleepers under a lock and resumes them outside it.
