## Root cause

SkinAmp had no way to move a Music Assistant playlist out as an M3U file or bring one in: the backend protocol had no export/import calls and the Library offered no commands for them.

## Fix

`MARequest.exportPlaylist` sends `music/playlists/export_playlist` with `db_playlist_id` (the playlist's library row id, looked up through `music/playlists/get`) and returns the M3U8 text; `MARequest.importPlaylist` sends `music/playlists/import_playlist` with `m3u_data` and `library_matching: true` and decodes the new `Playlist`. Command and argument names match design §1's command table. `MusicBackend` gains `exportPlaylist(_:)` / `importPlaylist(m3u:)` (default: unsupported; the stub implements both). `PlaylistsModel.exportM3U` / `importM3U` report failures through `message`; import lists the new playlist first and selects it. The App adds "Export as M3U8…" (save panel whose message says entries refer to paths and URIs on the Music Assistant server) and "Import Playlist…" to the Library playlist context menu, plus an Import toolbar button on the Playlists tab.

Review notes (accepted): `canExport` is gated on the `playlistEditing` capability although export only reads; on Music Assistant both come together, so this has no visible effect. Empty files are refused locally before the server is called.
