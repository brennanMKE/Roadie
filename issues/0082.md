## Description

The playlist window's LIST menu has New List, Save List and Load List. New List clears the playlist; Save List and Load List do nothing. Winamp saves and loads `.m3u`, `.m3u8` and `.pls`, and opens them from File › Open and by drag and drop.

Expected: Save List writes the queue's local files as an extended M3U (`#EXTM3U`, `#EXTINF:<seconds>,<artist> - <title>`, paths), with `.pls` as an option. Load List, File › Open and dropping a playlist file on the playlist window read M3U, M3U8 and PLS, resolve relative paths against the playlist's folder, skip missing files with a notice, and replace or append like other opens. Library tracks from a server (Plex, Music Assistant) that have no local path are skipped on save with a notice.

## Root cause

There was no playlist file format support: the LIST menu's Save List and Load List sprites fell through `run(_:)` with no action, `LocalTrackLoader` treated `.m3u`/`.pls` as "not an audio file", and the open panel did not allow playlist types.

## Fix

Followed the plan. New `PlaylistFile` in `AudioCore` parses M3U/extended M3U/M3U8/PLS (BOM stripped, UTF-8 with Windows-1252 fallback except `.m3u8`, CRLF/CR/LF, PLS keys case-insensitive and ordered by number, `[playlist]` content detection), resolves entries (absolute, `file://`, relative with `\` → `/`; streams and nested playlists skipped) and serializes extended M3U or PLS v2 with paths relative to the playlist folder when inside it. `LocalTrackLoader.load` expands explicitly given playlist files in place before folder collection, so Open/Add/drop/Load List share one path and the existing "Skipped N of M files" notice covers missing entries; folder walks still keep only audio files. `PlayerModel+PlaylistFiles.swift` adds `loadPlaylistFile()` and `savePlaylistFile()` (save panel with an M3U8/M3U/PLS popup accessory that sets `allowedContentTypes`; format follows the final extension). Wired LIST › Save/Load List, and File › Load Playlist… / Save Playlist… (⌘S).

Small deviations: when every queued track is a Plex track, the notice is "Nothing to save" with detail "Plex tracks have no local file" (decided after the panel, since the queue is non-empty). A skipped entry's log URL is built from the playlist's folder rather than the playlist URL. The popup is an `NSStackView` accessory held by a private `NSObject` target (no existing closure-based popup in the app).

## Plan

### Scope and decisions

Add a Foundation-only M3U/M3U8/PLS reader and writer to `AudioCore`, next to `EQFFile` (the precedent for a Winamp file format there). Have `LocalTrackLoader.load` expand playlist files in place so that File › Open, Add, drop and Load List all go through `PlayerModel.importLocalFiles`. Then wire LIST › Save List and Load List. This plan writes no code, and status stays `open`.

- **The format lives in `AudioCore`.** `Track` and `LocalTrackLoader` are there, and the target has no UI. `Package.swift` and `project.yml` are not touched. The tests go in `AudioCoreTests`, which `scripts/run-tests-vm.sh` already runs as `playerkit-tests`.
- **One loading path.** A playlist URL passed to `LocalTrackLoader.load` is replaced by its entries, resolved to file URLs, at that point in the input order. After that, the existing checks run: a missing entry becomes `SkippedFile(reason: "file not found")`, a non-audio entry becomes "not an audio file", and an unreadable audio file reports the AVAudioFile error. The existing `StatusNotice.skipped` ("Skipped 2 of 14 files — see Console") is the "skip missing files with a notice" the issue asks for. Each entry's tags come from the file through `loadTrack`, as with any other open. `#EXTINF`/`TitleN`/`LengthN` are parsed but only used by tests. Winamp also re-reads the files.
- **Folder walks never pick up playlists.** `walk(_:into:)` keeps only `isAudio` files. A test pins that `.m3u`/`.pls` inside a dropped folder are ignored, so a folder that holds both `album.m3u` and its tracks is not queued twice. This matches FolderIndexer's `sidecarExtensions`, which treats m3u/m3u8/pls as sidecars. Only playlist files given explicitly are expanded.
- **No nesting and no streams.** A playlist entry that is itself a playlist is skipped with reason "nested playlist". An entry with a non-`file` scheme (`http://`, `https://` and so on) is skipped with reason "streams are not supported", in line with #0081's Add URL. A playlist that cannot be read or decoded is skipped with "could not read playlist".
- **Path resolution.** Leading and trailing whitespace is trimmed. Blank lines and `#` lines are dropped (M3U). `file://` entries become `URL(string:)?.standardizedFileURL`. An entry starting with `/` is absolute. For anything else, `\` is replaced by `/`, so Windows-made relative lists such as `Artist\Album\01.mp3` work, and the result is resolved against the playlist's folder (`URL(filePath:relativeTo:)`, then `.standardizedFileURL`, which removes `..`). A Windows drive path (`C:\…`) resolves to a path that does not exist and is reported as "file not found".
- **Encodings.** A leading UTF-8 BOM is stripped. `.m3u8` is decoded as UTF-8, lossily. `.m3u` and `.pls` are tried as UTF-8 first and fall back to Windows-1252, as Winamp writes them (the same fallback `EQFFile` uses). CRLF, LF and CR line endings are all accepted.
- **Format detection.** By extension: `m3u`/`m3u8` → M3U, `pls` → PLS. A file whose first non-blank line is `[playlist]` (case-insensitive) is read as PLS whatever its extension.
- **The writer.** Output is UTF-8 with LF line endings. Extended M3U: `#EXTM3U`, then per track `#EXTINF:<seconds>,<display>` and the path. `<seconds>` is `Int(duration.rounded())`, or `-1` when the duration is 0. `<display>` is `artist - title`, or just `title` when the artist is empty. PLS: `[playlist]`, then `FileN=`, `TitleN=`, `LengthN=` (1-based, same seconds rule), `NumberOfEntries=<n>` and `Version=2`. A track inside the playlist's folder or one of its subfolders is written relative to that folder, with `/` separators. Any other track is written as an absolute path. Only `.file` sources are written. `.plex` tracks have no local path (their cache file is internal) and are counted as skipped. The local queue holds only `.file` and `.plex` sources. Music Assistant playback never fills `player.queue`, and the playlist window shows `player.queue`.
- **Save.** `NSSavePanel` with the default name `Playlist.m3u8` and a small accessory `NSPopUpButton` ("M3U8 playlist", "M3U playlist", "PLS playlist"). The popup sets `allowedContentTypes` to the chosen type, which rewrites the name's extension, so `.pls` is a visible option. The written format follows the final URL's extension. Notices: "Saved 12 tracks"; "Saved 10, skipped 2 server tracks" (detail: "Plex tracks have no local file"); "Nothing to save" when no track is a file, in which case no file is written; "Could not save <name>" with `error.localizedDescription` on a write failure. All go through `post(StatusNotice(...))`, as `saveEQF` does.
- **Load List** shows an `NSOpenPanel` limited to playlist types, with a single selection. It calls `importLocalFiles([url], replace: true)`, which replaces the queue and plays like File › Open. **File › Open / Add** add the playlist types to `allowedContentTypes`, and their behaviour follows from `open(_:replace:)`. **Drop** on the player or playlist window appends, like any drop, through the existing `dropDestination` calls. No change is needed there. **Finder double-click / Dock drop of a playlist** is out of scope: it needs `CFBundleDocumentTypes` entries and a `check-info-plist.sh` update. `AppDelegate.application(_:open:)` already routes through `open`, so it would work once types are declared. File a follow-up if wanted.
- **#0071 is unaffected.** The persisted queue stays JSON (`queue.json`) and is not replaced by a `winamp.m3u`. A loaded playlist mutates `player.queue`, so `QueueAutosaver` saves it like any other change.

### 1. `AudioCore`: `Packages/PlayerKit/Sources/AudioCore/PlaylistFile.swift` (new)

```swift
/// Winamp playlist files: M3U / extended M3U, M3U8 (UTF-8) and PLS v2. Parsing never throws for content; entries
/// are returned in file order.
public enum PlaylistFile {
    public enum Format: Sendable, Equatable { case m3u, pls }
    public struct Entry: Equatable, Sendable {
        public var location: String      // as written, trimmed
        public var title: String?        // #EXTINF display text or TitleN
        public var duration: Int?        // seconds; nil for -1 / missing
    }
    public static let fileExtensions: Set<String> = ["m3u", "m3u8", "pls"]
    public static func isPlaylist(_ url: URL) -> Bool          // by extension, case-insensitive
    public static func format(for url: URL, data: Data) -> Format
    public static func decode(_ data: Data, pathExtension: String) -> String
    public static func parse(_ data: Data, format: Format, pathExtension: String = "m3u") -> [Entry]
    /// `.file(url)` or `.skip(reason)` per entry: streams, nested playlists.
    public enum Resolved: Equatable, Sendable { case file(URL), skip(location: String, reason: String) }
    public static func resolve(_ entry: Entry, relativeTo playlistURL: URL) -> Resolved
    /// Writes the `.file` tracks; `skipped` counts the others.
    public static func serialize(_ tracks: [Track], format: Format, playlistURL: URL) -> (data: Data, written: Int, skipped: Int)
}
```

PLS parsing: split lines on `=` at the first occurrence and compare keys case-insensitively. `FileN`, `TitleN` and `LengthN` are collected into a dictionary keyed by `N`. The output is sorted by `N`, and a number with no `FileN` is dropped. `NumberOfEntries` and `Version` are ignored, because real files often get them wrong. Lines outside `[playlist]` are ignored. M3U `#EXTINF:<sec>,<text>` applies to the next location line only.

### 2. `AudioCore`: `LocalTrackLoader.swift`

- `load(_:)`: before `collectAudioURLs`, map the input through a new `private static func expandPlaylists(_ urls: [URL]) -> (urls: [URL], skipped: [SkippedFile])`. Each `PlaylistFile.isPlaylist(url)` that is not a directory is read with `Data(contentsOf:)`, parsed and resolved. `.file` URLs are spliced in at its position. `.skip` entries become `SkippedFile(url: playlistURL.appending(path: location), reason:)`; this URL is only used for the log line. A read failure becomes one `SkippedFile(url: playlistURL, reason: "could not read playlist")`. Expanded entries that are themselves playlists are skipped as "nested playlist" and not expanded again. Merge the skips into the result: the playlist skips first, then the existing index-ordered ones. `LocalImport.skipped` order is not otherwise relied on. Log one `info` line per playlist ("Playlist <name>: N entries").
- `collectAudioURLs` and `walk` stay as they are. Rely on the test below to show that `isAudio` rejects playlist extensions. If `UTType` turns out to call `.m3u` audio on the guest's macOS, add an explicit `!PlaylistFile.isPlaylist(entry)` guard in `walk`.
- Add `public static let playlistTypes: [UTType] = ["m3u", "m3u8", "pls"].compactMap { UTType(filenameExtension: $0, conformingTo: .data) }`. Use `UTType(filenameExtension:conformingTo:)`, as `presetFileTypes` does, rather than relying on named constants.
