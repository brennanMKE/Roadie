# 0223 — The Music Assistant backend can't list genres or a genre's albums, artists and tracks

| | |
|---|---|
| **Status** | open |
| **Module** | MusicAssistantKit / PlayerKit |
| **Platform** | macOS |
| **First seen** | 2026-10-27 |

## Description

`MusicBackend` has no genres: no capability, no `MediaKind`, no listing, no per-genre lists, and `play_media` is never sent with `shuffle`. Music Assistant has all of it (`music/genres/*`, the `genre` filter on `library_items`, `play_media {shuffle}`), and #0222 records the responses. This issue adds the source-neutral API, the Music Assistant implementation, and genres in `StubMusicBackend` and `ScriptedMusicAssistant`, so #0224 and #0225 can build the UI on tested ground. No UI. Design: [docs/design/genres.md](../docs/design/genres.md) §3, §4.

## Plan

Read #0222's `## Notes`/resolution and `docs/ma-protocol-notes.md` › Genres first: the probe decides the listing rule (step 5) and `media_counts`' shape (step 4). Where the probe changed design §3, follow the probe.

### `MusicBackendKit`

1. `MediaKind.genre`. Fix every exhaustive switch the compiler lists: `MAMediaKind` gains `.genre` (`plural` → `genres`, and both mapping switches), `FavoriteKind.init?(_:)` → nil, `FolderBackend.play` → `throw .unsupported(.genres)`, `StubMusicBackend`, `ScriptedMusicAssistant.expand` (step 9), `LibraryBrowserModel`/`FavoritesModel` switches (no-op or unsupported), `App/Browser/DiscoverView.swift`'s symbol table (`guitars`).
2. `Genres.swift` (new, next to `Radio.swift`): `BackendCapabilities.genres` (`1 << 9`), `GenreCounts` (`tracks`, `albums`, `artists`, `playlists`; `hasMusic` = tracks + albums + artists > 0), `LibraryGenre` (`id`, `name`, `sortName`, `members: [MediaID]`, `counts`), and the protocol requirements with defaults that throw `.unsupported(.genres)`:
   - `genres() async throws -> [LibraryGenre]` (one per server genre, unmerged, with counts);
   - `albums(inGenre:page:)`, `artists(inGenre:page:)`, `tracks(inGenre:page:)` → `Page<…>` (the genre's `members` all at once).
   Declare them in the `MusicBackend` protocol (so the MA backend's versions are dynamically dispatched), defaults in the extension, as `Radio.swift` does.
3. `GenreList` (pure, in `Genres.swift`): `visible(_:)` drops `!counts.hasMusic`, merges names equal under `compare(options: [.caseInsensitive, .diacriticInsensitive])` after trimming (members concatenated in input order, counts summed, `id`/`name`/`sortName` from the first), orders by tracks desc, albums desc, then `sortName ?? name` ascending (same comparison); `countsText(_:)` → "649 tracks · 3 artists" (non-zero parts, in the order tracks, albums, artists; singular "1 track").
4. **Play with shuffle.** Add `func play(_ items: [MediaID], on output: OutputDevice.ID, mode: PlayMode, shuffled: Bool) async throws` to the protocol; default: `try await play(items, on: output, mode: mode)` then, when `shuffled`, `try await transport(.setShuffle(true), on: output)`. `PlayRequest` gains `shuffled: Bool = false` (init parameter defaulted, so existing call sites stay) and `play(genre:)`, `shuffle(genre:)`, `next(genre:)`, `append(genre:)` (items = `genre.members`). `PlayerModel.playFromLibrary` (App) calls the four-argument `play` when `request.shuffled`, the old one otherwise; log `shuffled` in its info line. That one App line is the only App change here.

### `MusicAssistantKit`

5. `Models/MAGenre.swift`: `MAGenre: Codable` (`item_id`, `provider`, `name`, `sort_name?`, `uri?`, `favorite?`, `content_type?`, `genre_alias_count?`) with the same lenient list decoding the other models use (`MARadio.lenientList`'s pattern). `MAGenreCounts`: decode the `media_counts` result as recorded (per #0222; expected `{"<id>": {"track": n, "album": n, "artist": n, "playlist": n}}`), unknown keys ignored, missing ones 0.
6. `MARequest+Genres.swift`: `genres(limit:offset:contentType:mediaType:hideEmpty:)` (only the set args sent; `order_by: "sort_name"`), `genreMediaCounts(ids: [String])`, and `libraryItems(_:limit:offset:orderBy:albumArtistsOnly:genres: [Int] = [])` (the existing builder; `genre` sent as an int array only when non-empty). `playMedia(…, shuffle: Bool? = nil)` sends `shuffle` only when non-nil.
7. `MusicAssistantBackend+Genres.swift`:
   - `genres()`: the listing rule from #0222 (design §3 default: `content_type: "music"`, pages of 100 at offsets 0, 100, …, stop on an **empty** page, cap 20 pages, dedupe by `item_id`; or the `media_type` union if the probe says so), then one `media_counts` call for all ids (chunks of 200), mapped with `LibraryGenre(ma:counts:)` (in `MAMapping.swift`; `id`/members `MediaID(.genre, uri)`, `uri` falling back to `library://genre/<item_id>`). A genre whose `item_id` isn't an integer is dropped with a `Logger` line (design risk 4).
   - `albums/artists/tracks(inGenre:page:)`: `library_items {genre: members' Int ids, limit, offset, order_by: "sort_name"}` (artists without `album_artists_only`: a genre maps track artists too), mapped with the existing `init(ma:)`s; `total` = the genre's count for that kind (so `PagedList` knows the end); `hasMore` also false on an empty page.
   - `play(_:on:mode:shuffled:)`: as `play(_:on:mode:)` with `shuffle: true` on `.replace` when `shuffled` (and `shuffle` omitted otherwise: "Play" keeps the queue's own setting).
   - `capabilities` gains `.genres`.
   - **Fallback** (design §4.3): when `play_media` with a genre URI answers an error frame, expand each member with `music/genres/tracks {item_id, limit: 0, order_by: "random" when shuffled}` and play the track URIs, capped at 2,000. Add `music/genres/tracks` to `MARequest+Genres.swift`.
8. `docs/ma-protocol-notes.md` › Genres: note what Roadie sends.

### Stub and scripted server

9. `ScriptedMusicAssistant`: load the genre fixtures into `Library` (`genres`, `genreCounts`, `genreFilters[kind]` keyed by the recorded genre id, `genreTracks`). Answer `music/genres/library_items` (filter the recorded full listing by `content_type`, or serve the matching recorded `media_type`/`content_type` listing; apply `limit`/`offset`), `music/genres/count`, `music/genres/media_counts` (the recorded object filtered to the requested ids), `music/genres/tracks`, and `music/<kind>s/library_items` with a `genre` arg (the recorded `genre-<kind>s-filter` rows when the ids include the recorded genre, else `[]`, honouring `offset`). `expand` for a `library://genre/<id>` URI → the recorded `genre-tracks` rows (SYNTHETIC expansion, say so in the exceptions list). `summary` already prints `shuffle=true` (every arg is printed), check it.
10. `StubMusicBackend`/`StubLibrary`: four genres over the stub's own items: two named "Rock" and "rock" (merge), one with only tracks, one empty; lists filtered from the stub's albums/artists/tracks; `play(_:on:mode:shuffled:)` records the call (for #0225's tests). The genre methods answer only when the test passes `.genres` in `StubMusicBackend(capabilities:)` (they throw `.unsupported(.genres)` otherwise, like the playlist methods); the default capability set stays `[.search, .artwork, .localOutput]`, so no existing `sections` assertion changes.
