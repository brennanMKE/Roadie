## Description

M14 work item W11 from [docs/design/release.md](../docs/design/release.md). Depends on: W8, W9, W10, W12.

## Expected behavior

`scripts/release.sh X.Y.Z`: rehearsal by default, `--publish` to notarize, tag, push and create the GitHub release after a confirmation prompt. A 0.0.1 rehearsal produces the DMG, `.sha256`, item and notes without touching `website/` or git.

## Resolution notes

> 🟢 Resolved 2026-10-23 — `scripts/release.sh X.Y.Z` rehearses the whole release by default; `--publish` notarizes, tags the built commit, commits `website/`, pushes after a y/N prompt and creates the GitHub release.

## Root cause

Shipping Roadie meant running preflight, the VM build, signing, the DMG, notarization, the appcast, the changelog,
the download link, the tag, the push and the GitHub release by hand, in the right order, with no rehearsal.

## Fix

- `scripts/release.sh X.Y.Z [--publish] [--notary-profile NAME] [--identity NAME] [--repo OWNER/NAME]
  [--skip-build ZIP] [--sign]` runs §2.5 steps 0-15. `set -euo pipefail`, refuses xtrace, never sources `.env`, no
  secret on a command line.
- Rehearsal (default): non-strict preflight (failures listed under "Fix before --publish"), no notarization, steps
  9-11 against a temporary copy of `website/`, writes only under `build/release/X.Y.Z/`. The appcast item uses a stub
  signature unless `--sign` asks for the real `sign_update`, so a rehearsal never touches the Sparkle key.
- `--publish`: strict preflight; staple/spctl/`verify-dmg.sh`; `.sha256` checked against the DMG; tag on the commit
  recorded before the build (`BUILT_COMMIT`), not a later HEAD; the y/N prompt defaults to no (also on EOF);
  `git push --atomic origin main vX.Y.Z` before `gh release create --verify-tag`; re-download and sha256 compare.
  An EXIT trap says how far a failed publish got (website edited / tagged and committed / pushed / released) and
  prints the undo or retry command.
- Copies the VM zip's `sparkle-bin` into `build/sparkle/bin` (bbf71fc).
- Review: `CHANGELOG.md` 0.0.1 dropped its `music-assistant.io` link, which `check-website.sh` rejects on
  `changelog.html` (only github.com and the canonical host are allowed); the rehearsal failed at step 11 without it.
- `docs/releasing.md` updated (`--sign`, atomic push, partial-failure messages).
