# 0012 — Plain HTTP and LAN connections are blocked by ATS and Local Network privacy

| | |
|---|---|
| **Status** | open |
| **Module** | App |
| **Platform** | macOS |
| **First seen** | 2026-10-12 |

## Description

Add `NSAppTransportSecurity.NSAllowsLocalNetworking` and `NSLocalNetworkUsageDescription` through `project.yml`, and verify `joe`, the `.local` name, and a LAN IP all connect.

## Acceptance criteria

- All three address forms connect over HTTP in a Debug build.
- The can't-reach message mentions the Local Network setting.
- Results recorded in `docs/plex-music-library.md` (removing the "not yet tested" note where verified).

## Plan

### Scope and decisions

This issue is configuration plus wording, and a proof that the configuration shipped. It adds the two Info.plist keys through `project.yml`, gives the connection test its App Transport Security (ATS) and Local Network messages, adds a step to the VM run that reads the built app's Info.plist, and writes down the by-hand checks that only the user can run on the host. No new types, no UI changes (`PlexSettingsView` already shows `failure.message` and the `underlying` detail line), no downloads (#0013; they inherit the same ATS rule because part URLs are on the same base URL), no plex.tv or `plex.direct` (#0014; `https://` needs no ATS change).

- **The narrowest ATS key, and nothing broader.** `NSAppTransportSecurity` → `NSAllowsLocalNetworking = true` only. Apple's definition of "local" for this key is exactly the three address forms in the acceptance criteria: an unqualified single-label name (`joe`, whatever it resolves to, including a Tailscale 100.x address through MagicDNS), a `.local` name (`brennan-mac-mini-m1.local`), and an IP address literal. Everything else over plain `http` stays blocked, which is the behaviour `docs/plex-music-library.md` already promises: a full Tailscale name (`joe.<tailnet>.ts.net`) or any other dotted hostname fails with `-1022` and the user is told to use the short name, the `.local` name, an IP, or `https://`. Not added: `NSAllowsArbitraryLoads` (turns ATS off for every host, including plex.tv), `NSExceptionDomains` (an exception needs a literal domain, and a tailnet suffix is per user; `ts.net` with `NSIncludesSubdomains` would cover every tailnet on earth), `NSBonjourServices` (only needed to *browse* for service types with `NWBrowser`/`NSNetServiceBrowser`; resolving a `.local` hostname and connecting by unicast is not browsing), and `com.apple.security.network.client` (a sandbox entitlement; the app is unsandboxed, and the hardened runtime does not restrict networking).
- **`NSLocalNetworkUsageDescription`** = "SkinAmp connects to your Plex Media Server on your local network to browse and play your music." It is the sentence under the system prompt ("“SkinAmp” would like to find and connect to devices on your local network."), so it says what is contacted and why, in the app's voice, no marketing.
- **Three wordings for `.unreachable`, chosen by the underlying `PlexError`, all still in `PlexConnectionFailure.message`.** The connection test cannot tell a Local Network denial from a server that is down: Apple's local network privacy makes a denied unicast connection fail at the socket (no route to host), which `URLSession` reports as an ordinary transport error. So the hint rides on every transport failure. An ATS refusal is different: it is a distinct `URLError` code (`-1022`, `.appTransportSecurityRequiresSecureConnection`), it never means the server is down, and the fix is a different address, so it gets its own sentence. A server that answered but is not Plex (404, HTML, a 500) keeps the original shorter message, because neither hint applies when something answered. The enum's shape does not change; `statusMessage`/`statusDetail` in `PlexSettingsModel` and the view are untouched.
- **Proof that the keys shipped comes from the built product, in the guest.** The host never builds, so the check is a step in `scripts/run-tests-vm.sh` after `app-build`: a small committed script reads `SkinAmp.app/Contents/Info.plist` with `plutil` and fails unless the ATS and Local Network keys are there with the right types, the broad keys are absent, and #0047's `UTExportedTypeDeclarations` survived. The same script runs on the host against the regenerated source `App/Info.plist` (reading a plist is not a build) so the implementer can see the keys before the VM run. The unit tests cannot cover ATS at all: `StubURLProtocol` sessions bypass it, which is why `http://stub.local` has worked without the key.
- **The connections themselves are checked by hand, on the host, by the user.** The guest has no token and must never reach joe. Section 9 lists the checks, including the full Tailscale name that must *stay* blocked and the deny path for the Local Network setting. The implementer prepares the results table in the doc with the expected outcome per row and leaves the results blank; it does not claim any by-hand result.

### 2. Messages (`Sources/PlexKit/PlexConnectionTest.swift`)

```swift
    /// The user-facing text (docs/plex-music-library.md). The one place these strings live.
    public var message: String {
        switch self {
        case .invalidAddress:
            "The server address is not valid."
        case .unreachable(.transport(.appTransportSecurityRequiresSecureConnection)):
            // ATS refused plain http: the address is a dotted name that is not .local. The server may be fine.
            "Plain http isn't allowed for this address. Use a short name like joe, a .local name, an IP address, or an https:// address."
        case .unreachable(.transport):
            // No response at all. A Local Network denial looks exactly like this.
            "Can't reach the server. Check the address, whether you're on the home network or Tailscale, and that SkinAmp is allowed under System Settings › Privacy & Security › Local Network."
        case .unreachable:
            // Something answered, but it is not Plex (404, HTML, a 500).
            "Can't reach the server. Check the address, and whether you're on the home network or Tailscale."
        case .unauthorized: "Signed in, but this account can't access this server."
        case .noMusicLibrary: "This server has no music library."
        case .cancelled: "The connection test was cancelled."
        }
    }
```

`caseName` (the log line) becomes `"unreachable(\(code.rawValue))"` for `.unreachable(.transport(let code))` so a `-1022` is visible in Console without the message; other cases unchanged. `errorDescription`, `underlying` and `check()` do not change. The `.transport(.unknown)` that `failure(_:)` produces for a non-`PlexError` falls under the hint wording, which is fine.

### 4. The Info.plist check (`scripts/check-info-plist.sh`, a step in `scripts/run-tests-vm.sh`)

New, committed, executable `scripts/check-info-plist.sh <Info.plist>`. `plutil -extract <keypath> raw -o - <file>` prints a value and exits non-zero when the key is missing; `-expect bool` fails if XcodeGen had emitted a string instead of a boolean (a string `"true"` would print the same and ATS would ignore it). Sketch; the implementer makes it robust under `set -euo pipefail`:

```zsh
#!/bin/zsh
# check-info-plist.sh — assert the app's Info.plist carries the networking keys (#0012)
# and still carries the .wsz type (#0047). Reads only; runs on the host against the
# regenerated App/Info.plist and in the guest against the built SkinAmp.app.
# Usage: scripts/check-info-plist.sh <path/to/Info.plist>
set -euo pipefail
P=${1:?usage: check-info-plist.sh <Info.plist>}
get()    { plutil -extract "$1" raw -o - "$P" 2>/dev/null; }
expect() { local got; got="$(get "$1" || true)"; print -r -- "$1 = ${got:-<absent>}"
           [[ "$got" == "$2" ]] || { print -u2 -r -- "!! $1: expected '$2'"; return 1; }; }
absent() { if get "$1" >/dev/null; then print -u2 -r -- "!! $1 must be absent"; return 1; fi
           print -r -- "$1 absent (ok)"; }

plutil -extract NSAppTransportSecurity.NSAllowsLocalNetworking raw -expect bool -o - "$P" >/dev/null
expect NSAppTransportSecurity.NSAllowsLocalNetworking true
absent NSAppTransportSecurity.NSAllowsArbitraryLoads
absent NSAppTransportSecurity.NSExceptionDomains
absent NSBonjourServices
desc="$(get NSLocalNetworkUsageDescription || true)"
print -r -- "NSLocalNetworkUsageDescription = ${desc:-<absent>}"
[[ "$desc" == *Plex* ]] || { print -u2 "!! NSLocalNetworkUsageDescription is missing or does not mention Plex"; exit 1; }
expect UTExportedTypeDeclarations.0.UTTypeIdentifier com.brennanmke.skinamp.wsz
print -r -- "Info.plist OK: $P"
```

`scripts/run-tests-vm.sh`, after `run_step app-build …` and before the `--launch` block:

```zsh
run_step app-plist "scripts/check-info-plist.sh build/DerivedData/Build/Products/Debug/SkinAmp.app/Contents/Info.plist"
```

`run_step` already runs the command in the guest with `pipefail` and tees it to `app-plist.log`, so the printed values come back in `build/vm-tests/<run-id>/app-plist.log` as evidence. The script is a tracked file, so the working-tree export carries it into the guest. Update the header comment's numbered list in `run-tests-vm.sh` (step 4: the Info.plist check; the launch becomes 5). The `--launch` step is unaffected: the app does no network I/O at launch (#0011's model does nothing until Settings opens), so adding the usage description cannot make the headless guest show a Local Network prompt. Keep it that way.

### 10. Risks

- **The exemption's exact coverage is Apple's, not ours.** Apple documents `NSAllowsLocalNetworking` as covering unqualified names, `.local` names and IP addresses; the by-hand checks are what confirm each form on the host. If any of the three fails with `-1022`, section 9 says what to do; no subagent adds a broader key on its own.
- **Local Network denial is invisible to the code.** The connection fails like a down server, so the hint rides on every transport failure, including on Tailscale, where the setting is irrelevant. The message keeps "Check the address" first and the setting last, so the common case still reads right. Trying to detect the denial (a local-address heuristic on the host, or reading the error's POSIX `errno`) is not worth the false positives; revisit only if users are confused.
- **TCC and ad-hoc signing.** The Local Network grant is keyed to the app's identity; with `CODE_SIGN_IDENTITY: "-"` the signature changes on every rebuild, so the prompt may come back after each build, like #0011's Keychain dialog. Dev-build behaviour only; `mac-release` signing ends it. The guest never sees the prompt because the app does no network I/O at launch.
- **`joe` may resolve to the LAN rather than Tailscale** when the host is at home (depends on the resolver order). Then step 1 prompts and step 2 does not; both still connect. The results table records what happened; it is not a failure.
- **Message length.** The hint sentence makes the status line three lines in the 480 pt Settings form. `Label` wraps; nothing is truncated. If it looks heavy, the System Settings path could move to the detail line, but the acceptance criterion asks for the can't-reach message itself to name the setting, so it stays in `message`.
- **`plutil -extract … -expect`** exists on macOS 12 and later; the guest is 26.6.2 and the host 27. If the guest's `plutil` rejects `-expect`, drop that one line and keep the `raw` checks (a boolean prints `true`, and the type is visible in `git diff App/Info.plist` as `<true/>`); say so in `## Fix`.
- **Step order in the summary.** `run-tests-vm.sh` prints `PASS`/`FAIL` lines in hash order, not run order; `app-plist` can appear anywhere in the list. Look for it, don't expect it after `app-build`.
- **Not Plex vs. not reachable.** A random web server on port 32400 still gets "Can't reach the server…" (the shorter one), with the status in the detail line, as #0010 chose. A dedicated "This isn't a Plex server" message is a one-row addition to the table if M3 wants it; not in scope here.
- **The sandbox.** Off, so no entitlement. If #0043's Quick Look extensions or a later issue turn it on, `com.apple.security.network.client` is needed for the app; the doc already says so and section 1 adds the reminder next to `ENABLE_APP_SANDBOX`.

### Room left for the sibling issues

- **#0013** downloads parts from the same `baseURL` with `client.request(path: part.key)`, so `NSAllowsLocalNetworking` covers them with no further key; a `-1022` there can only happen for an address the connection test would already have refused. Its `URLSessionDownloadTask` sends the token in the header, never in the URL, as before.
- **#0014** gets its working `https://` from the `plex.direct` URIs in `/resources` (a valid certificate, TLS 1.2+), and plex.tv itself is `https`, so neither needs an ATS exception. The ATS message's last clause ("or an https:// address") is what its server picker supplies; when it lands, the doc's ATS bullet can say "pick the server in Settings" instead of "ask users to enter the short name".
- **UI tests** (later) keep using stub sessions, which bypass ATS; nothing here changes the `-UITestStubPlex` plan. The `app-plist` step is the one automated check of the networking keys and should stay in the script when the UI-test step is added.
