## Resolution notes

> 🟢 Resolved 2026-10-23 — `CHANGELOG.md`, `render-changelog.py` and `appcast-item.sh` produce the changelog article, appcast description, GitHub notes and a checked, valid appcast item.

## Root cause

Release notes had no source and appcast items had no generator, so they would have been written by hand.

## Fix

- `CHANGELOG.md` with `## [Unreleased]`.
- `scripts/render-changelog.py X.Y.Z`: prepends `<article id="vX-Y-Z">` after `<!-- releases:begin -->` in
  `website/changelog.html` (refuses a duplicate or a page without both markers) and writes
  `build/release/X.Y.Z/{changelog-article.html,appcast-description.html,release-notes.md}`.
- `scripts/appcast-item.sh <dmg> --version X.Y.Z`: mounts the DMG read-only, reads both versions from the app,
  `sign_update --account Roadie` (keychain key, never `-s`), checks `length` equals the DMG's size, inserts the item
  first and runs `xmllint --noout`. URLs match docs/website-hosting.md (`/downloads/Roadie-X.Y.Z.dmg`,
  `/changelog.html#vX-Y-Z`). `insert-appcast-item.py` from the issue text is the inline Python in this script.
- Review fix (99e3c3a): `appcast-item.sh` required an integer `CFBundleVersion` and so refused every real build
  (`YYYYMMDD.HHMM`); it now requires that form. A fixture-DMG test covers it.
