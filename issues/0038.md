## Description

Run SkinKit against a random 1,000-skin sample and the full corpus; fix crashes, record the failure rate, and measure performance.

## Root cause

There was no way to run SkinKit over more than a handful of skins, so crash rate, missing-sprite rate and per-skin timing across the real corpus were unknown. This pass builds the tooling and proves it on the 19 samples; the numbers need the full corpus.

## Fix

- `skintool corpus <dir> --out <dir> [--resume] [--timeout] [--max-memory] [--sample N] [--seed n] [--manifest f]` (`Tooling/CorpusRun.swift`): lists `.wsz`/`.zip`, md5s them (listing cached in `listing.json` so restarts do not re-hash), dedupes by md5, seeded sample, parse plus `MainWindowRenderer.render`, journals `start`/`result` lines to `results.jsonl`, watchdog thread turns a hang or runaway footprint into a `timeout` (exit 124) or `memory` (exit 125) record, `--resume` marks an unfinished skin `crashed`.
- `skintool corpus-report` (`Tooling/CorpusReport.swift`): `summary.json` + path-free `report.md` (rates over unique classic skins, nearest-rank median/p95/p99, slowest 20, failure classes, crash table, seeded sample section) and `gate: PASS|FAIL`.
- `scripts/run-skin-corpus.sh` (guest wrapper, restart loop on 124/125/signal) and `scripts/run-tests-vm.sh --corpus DIR [--corpus-sample N]` (second read-only share, copied to guest disk; steps `corpus-run`, `corpus-report`); `docs/testing-in-vm.md` updated.
- Adaptations to the plan: (1) no `SkinArchive` change, `SkinArchive.Limits` (#0043) already caps entry/total size and extensions, so there is no `skipped` list and no new parser warning; (2) `entries` is the number of extracted files (not the archive's entry count); (3) `required` sprites are the plan's list, not yet the renderer's own (the renderer exposes none); (4) the driver always creates `results.jsonl` when `--resume` finds none, because the wrapper always passes `--resume`; (5) `footprintMiB` is written on every record (lifetime peak) so the report gets the peak across restarts without parsing `time -l`; (6) corpus steps run after `app-quicklook`/`app-launch`; (7) no `Issue` column hand-editing yet beyond a default map (#0020 classes, `accepted` for modern).

## Plan

### Scope and decisions

This issue adds a batch mode to `skintool` that runs every skin in a folder through the parser (and the main-window renderer once #0026 has landed), survives crashes, hangs and memory blow-ups, and writes a per-skin JSONL log plus a summary; a guest-side wrapper that restarts it after a crash; a `--corpus <dir>` option in `scripts/run-tests-vm.sh` that carries the user's corpus into the VM; a committed markdown report with the numbers; and the triage that turns failure classes into issues. It writes no downloader (see "What the user must provide"), no library/index code (#0033), no cursors (#0037).

- **What "full corpus" means.** `docs/plan.md` (M7) and the brief (`winamp-skin-player-brief.md`, Milestones 1 and 5, Acceptance criteria) mean the Winamp Skin Museum's classic skins, with the Internet Archive `collection:winampskins` as the fallback source (`docs/winamp-skin-museum-access.md`). Queried on 2026-10-13 (one `statistics`/`bulkDownload(first: 1)` POST to `https://skins.webamp.org/graphql`, nothing downloaded): **103,079 unique classic skins**, `bulkDownload.totalCount` 105,780 (classic plus modern), `estimatedSizeBytes` ≈ 6.07 GB, files served from `https://r2.webampskins.org/skins/<md5>.wsz`. The "random 1,000-skin sample" is a seeded sample drawn from that set, not a separate download.
- **The corpus is the user's, on the host, never in git and never in the export.** `*.wsz` and `/Skins/` are gitignored and the VM export is `git ls-files -co --exclude-standard`, so a corpus can only reach the guest if the script is told to carry it. It goes in as a second read-only virtio-fs share (`--dir=corpus:<dir>:ro`, mounted at `/Volumes/My Shared Files/corpus`; Tart requires named shares when there are two), and the guest copies it to its own disk (`~/corpus`) before timing anything, so the numbers do not include share I/O. The guest disk is 140 GB with about 67 GB free; the copy lands in the clone, which the host's 20 GiB free-space check already covers. Nothing third-party is committed: not a skin, not a screenshot, not a readme. The report names skins by file name and md5 only.
- **Order.** After #0020 (fallbacks, so "missing sprite" means what the brief means: a sprite that nothing can draw) and #0026 (`MainWindowRenderer`, so the timed unit is parse *plus* render). If this is implemented before #0026 lands, the run measures parse only, the report says `render: not available`, and the issue stays open for a re-run; do not fake a render phase. #0020's `-v` fallbacks list and `skintool` exit status, and #0026's `Tooling/SkintoolOptions.swift`, are reused where present; #0033's `skintool index` subcommand sets the subcommand style followed here.
- **One in-process pass with a resume journal, not one process per skin.** Spawning 103k processes costs an hour by itself. Instead the driver appends a `start` line to `results.jsonl` before each skin and a `result` line after it, flushing both. A crash kills at most the skin in flight; the wrapper restarts the driver with `--resume`, which marks the unfinished skin `crashed` and continues after it. A watchdog thread turns a hang into a `timeout` result and a runaway footprint into a `memory` result, each followed by a clean exit that the wrapper treats like a crash. Every skin therefore ends with exactly one status, which is the brief's first acceptance criterion.
- **Release build, single-threaded, numbers from the VM.** Timings come from `swift build -c release`; a Debug `skintool` would report meaningless numbers. One skin at a time keeps per-skin times free of contention and keeps the resume journal trivial (`--jobs` is not added). The guest is a 6-vCPU VM, so the report records the environment and the numbers are relative (parser regressions, hot spots), not host figures; CoreGraphics rendering is CPU work, so the paravirtualized GPU caveat in `docs/testing-in-vm.md` does not apply.
- **Definitions used in the report.** *Unique skin*: one per md5 (the Museum de-duplicates by md5; the IA set does not). *Classic*: parsed, or failed with anything other than `SkinError.modernSkin`; modern skins are excluded from every rate. *Crash-free*: zero `crashed`, `timeout` and `memory` results. *Renders with no missing sprites*: parse succeeded and every sprite the main window draws resolves (`skin.image(for:)` non-nil, which after #0020 includes the fallbacks); `partial` skins that only lack `pledit`/`eqmain`/`gen` sheets still count, exactly as the brief says ("fallbacks count as warnings, not failures"). *Per-skin time*: `ContinuousClock` around `SkinParser.parse(url:)` (archive read, every sheet decoded, viscolor) plus around `MainWindowRenderer.render(skin:state: .webampScreenshot)`; md5 hashing is outside it. *Median/p95/p99*: nearest-rank over every attempted parse (ok, partial, failed, modern). *Peak memory*: the driver's `ri_lifetime_max_phys_footprint` (`proc_pid_rusage`), max across restarts, cross-checked by the wrapper's `/usr/bin/time -l`.
- **Verification is `scripts/run-tests-vm.sh` only**, with and without `--corpus`. Nothing is built, tested or run on the host; the implementer never runs `skintool` on the host, not even on `untitled folder/`.

### 1. Driver: `skintool corpus` (`Packages/SkinKit/Sources/SkinKit/Tooling/CorpusRun.swift`, `Sources/skintool/main.swift`)

```
skintool corpus <dir> --out <dir> [--resume] [--timeout <s>=10] [--max-memory <MiB>=4096]
                      [--sample <N>] [--seed <n>=1] [--manifest <manifest.jsonl>]
```

- **Listing.** Recursive, regular files whose extension lowercases to `wsz` or `zip` (the Museum normalizes to `.wsz`; the IA set has `.zip`; `.wal` is never listed), sorted by path relative to `<dir>`. Then md5 of every file (`Insecure.MD5`, mapped data; about 6 GB at disk speed, a minute); the first path per md5 in sort order is the skin, later ones get a `duplicate` result with `of: <path>` and are never parsed. With `--sample N`, a SplitMix64-seeded Fisher–Yates shuffle of the unique list keeps the first N (in sort order afterwards), so a sample is reproducible from `(corpus listing, seed)`; `N ≥ count` keeps all.
- **Per skin**, in order: write `{"event":"start","i":12,"path":"ab/Foo_[S123].wsz","md5":"…","size":123456}`; set the watchdog's current-skin box; `SkinParser.parse(url:)`; if it parsed and the renderer exists, `MainWindowRenderer.render(skin:state:.webampScreenshot)`; compute `mainWindowComplete`; clear the box; write the result:

  ```
  {"event":"result","path":"…","name":"Foo_[S123]","md5":"…","size":123456,"entries":17,
   "status":"ok|partial|failed|modern|duplicate|crashed|timeout|memory",
   "mainWindowComplete":true,"warnings":[…],"fallbacks":[…],"error":null,
   "parseMs":4.2,"renderMs":0.9,"ms":5.1,"of":null}
  ```

  `status`: `ok` (no warnings), `partial` (warnings), `modern` (`SkinError.modernSkin`), `failed` (any other `SkinError`, text in `error`). `entries` is the archive's file count. `fallbacks` is present only once #0020 has landed. `mainWindowComplete` is `MainWindowSprites.required.allSatisfy { skin.image(for: $0) != nil }` where `required` is one representative sprite per sheet the main window draws: `MAIN_WINDOW_BACKGROUND`, `MAIN_TITLE_BAR`, `MAIN_PLAY_BUTTON`, `MAIN_STEREO`, `DIGIT_0`, `MAIN_PLAYING_INDICATOR`, `MAIN_POSITION_SLIDER_BACKGROUND`, `MAIN_SHUFFLE_BUTTON`, `MAIN_VOLUME_BACKGROUND`, `MAIN_BALANCE_BACKGROUND` (plus the `text.bmp` sprite once #0021 adds `TEXT` to the table). After #0026 the list is replaced by the renderer's own sprite list so the two cannot drift.
- **Resume.** With `--resume`, read `results.jsonl` first: paths with a `result` are skipped; a `start` without a `result` gets `{"status":"crashed","restart":<n>}` written immediately; the listing, md5 pass and sample are recomputed (deterministic) and the loop continues from the first unfinished path. The `summary` is only written by a run that reaches the end.
- **Watchdog.** A `Thread` polling every 250 ms under a lock shared with the main loop: if the current skin has run longer than `--timeout`, write its `timeout` result and `exit(124)`; if `ri_phys_footprint` exceeds `--max-memory`, write `memory` and `exit(125)`. The writer takes the same lock to write a result and clear the box, so a result and an abort can never both be written for one skin. `CorpusRunner` takes the parse/render step, the footprint reader, the clock and the abort action as injectable closures (defaults: the real ones and `exit`), so every path is unit-testable without exiting the test process.
- **Output discipline.** Per-skin lines go only to `results.jsonl`. stdout gets a progress line every 1,000 skins or 5 s (`[12000/103079] ok 71.2% partial 26.1% failed 2.7% 5.3 ms/skin`) and the final counts; stderr (CoreGraphics and ImageIO complaints about bad BMPs, thousands of lines on a real corpus) is redirected by the wrapper to `corpus-stderr.log`. `--manifest` joins the Museum manifest by md5 (if the user synced with one) to add `museum_url` and `nsfw` to each record; absent, `museum_url` is `https://skins.webamp.org/skin/<md5>` for classic skins, which is enough to reproduce a failure without shipping the file.
- Exit codes: 0 when the loop finished; 124/125 from the watchdog; 64/66 usage (as today). A `crashed` status comes from the restart, never from the driver.

### 2. Guest wrapper: `scripts/run-skin-corpus.sh` (runs in the Tart guest, like `stress-realtime-gapless.sh`)

```
scripts/run-skin-corpus.sh <corpus-dir> <out-dir> [extra skintool corpus args]
```

1. `swift build -c release --package-path Packages/SkinKit --product skintool`; `BIN=$(swift build -c release --package-path Packages/SkinKit --show-bin-path)/skintool`.
2. Write `env.json`: `sw_vers -productVersion`, `xcodebuild -version | head -1`, `sysctl -n hw.ncpu hw.memsize`, the commit from `$RESULTS/commit.txt` (the export has no `.git`; the host script writes `git rev-parse --short HEAD` plus a `-dirty` flag there), whether the corpus was read in place or copied, and the start time.
3. Loop: `/usr/bin/time -l "$BIN" corpus "$CORPUS" --out "$OUT" --resume "$@" 2>>"$OUT/corpus-stderr.log"`; rc 0 → done; rc 124/125 or ≥ 128 (signal) → `sleep 2` (lets ReportCrash finish), `restarts++`, loop; any other rc → stop and fail. A cap of 1,000 restarts guards a driver that cannot make progress (the resume journal makes the same skin crash at most once, so hitting the cap means a bug in the driver). Each iteration's `time -l` block (max RSS, "peak memory footprint") is appended to `corpus-run.log`.
4. Copy `~/Library/Logs/DiagnosticReports/skintool*` into `$OUT/crashes/` and print `corpus: <unique> unique of <files> files, <restarts> restarts, <crashed> crashed, <timeout> timed out, <memory> over memory`.

### 3. Report: `skintool corpus-report`

```
skintool corpus-report <results.jsonl> --markdown <report.md> --json <summary.json> [--env <env.json>] [--sample <N>=1000] [--seed <n>=1] [--crashes <dir>]
```

- `summary.json` (`CorpusSummary`, Codable): environment; files, unique, duplicates, modern, classic; counts and rates for ok / partial / failed / crashed / timeout / memory and `mainWindowComplete`, over unique classic skins; timing (count, median, p95, p99, max, total parse+render, total wall from the journal's first start to last result, peak footprint); the slowest 20 (name, md5, size, entries, ms, status); failure classes; the 1,000-sample section computed from the same results by applying the seeded sample to the unique list (one full run yields both numbers; the sample's rate is the acceptance figure, the full set's rate is reported next to it).
- **Failure classes** are warnings and errors normalized to a class key: `Missing <sheet>.bmp` → `missing <sheet>`, `Undecodable <sheet>.bmp` → `undecodable <sheet>`, viscolor messages → `viscolor`, `SkinError` cases by case name, crash/timeout/memory by status; each class carries a count, the share of unique classic skins, and up to 5 examples (name + md5 + museum URL). Crash signatures (exception type and top SkinKit/ZIPFoundation frame from the `.ips` files in `--crashes`) are added by hand during triage; the report leaves a `Crash signatures` table with one row per crashed skin for that.
- `report.md` is the committed artifact (section 5): a header table (date, run id, commit, corpus source and size, guest environment), the headline numbers, the timing table, the slowest-20 table, the failure-class table, the crash table and the sample section. It contains basenames and md5s only: never `/Users/…`, `/Volumes/…` or the host path (a test enforces this, because the file is committed).
- Gate: prints `gate: PASS` or `gate: FAIL (crashes=N, sample complete=NN.N% < 95%)` and exits 1 on FAIL, so the VM summary shows the acceptance criteria as a step result.

### 6. Fixing crashes and hot spots

- **Proactive hardening, in this issue:** `SkinArchive(url:)` currently inflates every entry of the archive into memory, including bundled MP3s, videos, nested zips and anything a zip bomb declares. Add `maxEntryBytes` (default 64 MiB) and `maxTotalBytes` (default 256 MiB), checked against `Entry.uncompressedSize` before extraction and against bytes actually received during it; an entry over the cap is skipped and recorded in a new `skipped: [String]` on the archive (`"<name>: <size> bytes, over the <cap> limit"`), which the parser surfaces as a warning only when the entry was a sheet it needed. Both caps are init parameters so a test can use 1 KiB.
- **Crashes found by the run** are fixed here when the fix is a guard in SkinKit (an index out of range in a parser, a `precondition` reachable from malformed input, a nil unwrap). Re-run with `--corpus-sample` on a folder of the crashing skins' md5s (copy them into a temp folder on the host from the corpus; the folder is gitignored by `*.wsz`) until the sample is clean, then the full run. A crash inside ZIPFoundation on a malformed central directory is caught by validating what the typed API exposes before extraction, or by filing it with the md5 if that is not enough; never by catching a trap.
- **Hot spots:** the slowest-20 table carries `size` and `entries`. Expected causes, in order: bundled non-skin files (fixed by the caps and by extracting only entries the parser uses: the sheet names, `*.txt`, `*.cur`, keeping the rest as names and sizes for #0033's readme heuristic), oversized sheets (a 2000×2000 `main.bmp`), and BMP variants that ImageIO decodes slowly. Fix the first if the data confirms it; file the others with the md5s and the measured ms.

### 7. Triage → issues

After the full run, for each failure class in the report, one of:

- `crashed` / `timeout` / `memory`: one issue per distinct crash signature or cause, filed through the issues skill as a child of #0036 (Module `SkinKit`), with the class count, 5 md5s with Museum URLs, the signature from the `.ips`, and the per-skin ms; fixed in this issue if it is a guard (section 6), otherwise left open with the numbers.

### 10. Risks and notes

- **Obtaining the corpus is the gating step** and needs the user's say-so: about 6 GB from one person's hobby CDN. The bulk-download page is a single browser action; the API downloader in `docs/winamp-skin-museum-access.md` is not built by this issue (file it if the user wants a repeatable sync). Be gentle with the Museum (sequential pages, modest concurrency, never re-download); the doc suggests asking for the sqlite dump instead of paging.
- **Run length and the lease.** The full pass holds one of the host's two VM slots for the copy, the release build and 10–20 minutes of parsing; a crash-heavy first pass adds restarts. Use `--corpus-sample` until the sample is clean. Run in the foreground; a dropped session costs a clone, not the journal (it is in the guest, which is deleted — so re-run; keeping the clone for a look is described in `docs/testing-in-vm.md`).
- **Numbers are VM numbers.** 6 vCPUs, paravirtualized storage; a host run would be faster. The report says so; compare runs against each other, not against the host.
- **ReportCrash timing.** The `.ips` may land a second or two after the process dies; the wrapper sleeps 2 s before resuming and collects at the end. A missing `.ips` still leaves the journal's `crashed` record.
- **Watchdog exit while a result is half-written.** The lock around write-and-clear prevents a double record; flush before `exit`. A hang inside ImageIO cannot be cancelled, which is why the answer is exit-and-resume rather than cancellation.
- **Memory.** Each parse decodes every sheet; one skin at a time keeps the footprint small, and the caps in section 6 stop a single archive from inflating gigabytes. The guest has 12 GB; the default cap of 4 GiB leaves room for the build caches.
- **Duplicates and modern skins** are expected in bulk and are reported, not counted against the rates. `.wsz` files that are really modern skins (`skin.xml`) show up as `modern` and are excluded like `.wal`.
- **Report content.** The only third-party text that reaches git is file names (and md5s). Readmes, screenshots and bitmaps never leave `build/`. Read the names before committing (section 5).
- **Does not change `SkinParser`'s results** except through the caps; a corpus-visible change in warnings (new `skipped` warning) is a `parser_version` bump for #0033 once that lands — note it in the commit message.
