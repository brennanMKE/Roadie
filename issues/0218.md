## Root cause

No bug here. Several playlist code paths had no unit tests because they show real panels or need a real drag. `loadPlaylistFile`, `savePlaylistFile`, `exportLibraryPlaylist` and `importLibraryPlaylist` open `NSOpenPanel`/`NSSavePanel` directly, and `saveQueue` asks for a name with an `NSAlert`. The picker's filter and the name rule were private to their views. `PlaylistListInputView` read its drops only through `NSDraggingInfo`, and a test can't conform a fake to it under MainActor default isolation.

## Fix

Commit 0d0a88b.

- **Seams, Debug only.** Two new `PlayerModel` properties sit inside the same `#if DEBUG` block as `systemRequestOverride`: `panelChooserOverride: ((PanelRequest) async -> URL?)?` and `queueNameOverride: (() async -> String?)?`. Their readers, `panelChooser` and `queueNamePrompt`, are also guarded by `#if DEBUG`, so Release always uses the real panels and `SaveQueueSheet.askName`. The chooser is checked before `intercepted` and the UI-test stand-ins.
- **Export and import.** `exportLibraryPlaylist(_:in:)` and `importLibraryPlaylist(in:)` take an optional `PlaylistsModel`, which defaults to the Library's. `RoadieTests` now links `MusicBackendStub` (test bundle only, `project.yml`).
- **Helpers moved out of the views.** `PlaylistFormatChooser` and `apply(index:)` are now `internal`. `SaveQueueSheet.playlistName(from:)` and `PlaylistPickerSheet.matching(_:search:)`/`chosen(in:selection:)` are `static`, and the views call them. The views behave as before.
- **Drop handling split.** `PlaylistListInputView`'s drop handling is now `dragOperation(pasteboard:mask:)` and `performDrop(pasteboard:at:)`. The `NSDraggingDestination` overrides call these with the sender's pasteboard, mask and location, and behave as before. Tests call the two functions with uniquely named pasteboards.
- **Not tested, because the code can't be reached:**
  - **Dead code in `writePlaylistFile`.** The skipped-tracks notice and "The playlist has no local files" can never run. `Track.Source` has only `.file`, so `PlaylistFile.serialize` never skips a track, and an empty queue is refused earlier. The plan's "server tracks only" and "mixed" cases are dropped. This could be filed separately.
  - **`.refused` is unreachable.** `saveQueue`'s `.refused` branch, and `loadList`'s `[]` branch, can't happen from `PlayerModel`. `PlaybackRouter`'s remote is always Music Assistant, whose capabilities include `.queueEditing`. `QueueSaveTargetTests` covers the choice itself.
  - **No internal row move on a drop.** Row moves are mouse drags, which other tests already cover.
- **After review (second commit):** main merged. The tests are added to `docs/design/test-automation.md` §5. The cancel checks now wait for a later action's effect, which shows the cancelled Task has finished. The file drop lands on row 1's point, and the test checks the inserted order. `testSaveQueueCancelledOrRefused` is renamed `testSaveQueueCancelledOrFailed`.
- **Tests:** XCTest `test…` names, like the rest of `RoadieTests`.
  - `PlaylistFilesTests`: load, the save round trip, save notices, export/import, the format chooser.
  - `QueueSaveTests`: save to a speaker playlist, cancelled or failed, name trim, picker filter and grouping.
  - `PlaylistOverlaysTests`: drop operation by pasteboard, drops reaching the model.
