## Description

In #0212's run `20261029-191545-21712`, #0203's UI tests left `JumpToFilePanel` at 90 % (226 of 251 lines) and `PlaylistWindowOverlays` at 73.4 % (267 of 364). The panel's remaining lines (Enter, Queue, the arrow and page keys) are [#0204](0204.md)'s UI tests. What remains here:

- `PlayerModel+PlaylistFiles` is at 22 % (44 of 200). The panel paths of `loadPlaylistFile` and `savePlaylistFile` (the UI tests use stand-ins), `writePlaylistFile`'s failure and skipped-tracks notices, the Library playlist M3U8 `exportLibraryPlaylist` and `importLibraryPlaylist` (0 %), and the save panel's `PlaylistFormatChooser` (0 %) never run.
- `PlaylistPickerSheet` (141 lines, LIST › Load on a Music Assistant queue) is at 0 %: its name filter, grouping and Load/cancel.
- `SaveQueueSheet` (22 lines) is at 0 %, and `PlayerModel+QueueSave` is at 33.3 % (14 of 42): Playback › Save Queue as Playlist… to a Music Assistant playlist (the `.remote` path, its success and failure notices, the Library refresh) and the `.refused` notice never run.
- `PlaylistWindowOverlays`' drop side is at 0 %: `dragOperation`, `draggingEntered`, `performDragOperation` and `clearDropCue` of `PlaylistListInputView` (row hits and internal moves are covered).

## Plan

1. Panel seams: give `PlayerModel` an injectable open/save URL chooser (`(PanelRequest) async -> URL?`, defaulting to the real `NSOpenPanel`/`NSSavePanel`), used by `loadPlaylistFile`, `savePlaylistFile`, `exportLibraryPlaylist` and `importLibraryPlaylist`, and a name prompt (`() async -> String?`, defaulting to `SaveQueueSheet.askName`) used by `saveQueue`. Debug-only overrides never touch real user state.
2. `Tests/RoadieTests/PlaylistFilesTests.swift`, through the seams:
   - `loadPlaylistFile` with a chosen `.m3u`/`.pls` fixture fills the queue; cancelled leaves it
   - `savePlaylistFile` writes M3U or PLS by extension and reads back the same tracks; a queue of server tracks only posts "Nothing to save"; mixed posts the skipped count; an unwritable URL posts "Could not save"
   - `exportLibraryPlaylist` writes the backend's M3U8 text and `importLibraryPlaylist` sends a file's text, both against `MusicBackendStub`, with their notices
   - `PlaylistFormatChooser.apply(index:)` sets the panel's content type (make it `internal` for the test)
3. `Tests/RoadieTests/QueueSaveTests.swift`: `saveQueue` on a scripted speaker with a name sends `saveQueueAsPlaylist(on:named:)` and posts "Saved queue as …"; cancelled sends nothing; a backend error posts "Couldn't save the queue"; a source with no playlists posts "Can't save this queue". `SaveQueueSheet`'s trim-and-blank rule moves into a `static` function and is tested on its own.
4. `PlaylistPickerSheet`: move `matching` (trimmed, case-insensitive filter) and `chosen` into `static` helpers and test them with `MusicBackendStub`'s playlists; the Load/cancel clicks are [#0206](0206.md)'s.
5. `Tests/RoadieTests/PlaylistOverlaysTests.swift`: `PlaylistListInputView.dragOperation` and `performDragOperation` with a fake `NSDraggingInfo` whose pasteboard holds file URLs, library `MediaID`s or an internal row move: the operation returned, what reaches the model, and that the drop cue clears. Plain `NSView` containers; no window server events.

## Tests
