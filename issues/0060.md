## Description

Many details of MA's WebSocket protocol in [docs/music-assistant-integration.md](../docs/music-assistant-integration.md) are marked **VERIFY**: the server-info handshake fields, the `auth` command, the result/partial/error/event envelope, the heartbeat, `players/all` and player transport commands, `music/search`, the `library_items` listings, event subscription, artwork URLs and the Bonjour service type. Record the real shapes from a running server before writing the client.

## Root cause

The integration doc was written from the Python client and partial docs, so its handshake, envelope, command and artwork details were guesses. No client code existed to check them against a live server.

## Fix

Added `scripts/record-ma-fixtures.py` as planned (stdlib Python 3.9, minimal RFC 6455 client, in-process scrubbing, secret gate, `--check`, `--out`, `--events-seconds`). Recorded 40 scrubbed fixtures to `Packages/PlayerKit/Sources/MusicAssistantKitStub/Fixtures/`, `commands.json`, `openapi.json` and `dns-sd.txt` to `docs/ma-protocol/`, and wrote `docs/ma-protocol-notes.md`. Deviations from the plan: the user name is also scrubbed from free text such as player names; `size=256` and `fmt` artwork probes were added after `size=200` returned 400; the `playlist-tracks` fixture keeps 5 items per frame and records the real count in `original_item_counts`; `commands.json` and `openapi.json` have only string-level scrubbing (no key renames).

Key findings: first frame is bare with 12 fields; errors are `{message_id, error_code:int, details}` frames and the socket stays open (20 unauthenticated, 23 bad token, 12 unknown command); results carry `partial`; `playlist_tracks` streams chunk frames (not cumulative) then an empty `partial:false`; `*/library_items` return bare arrays and `*/count` bare ints; `players/get` of an unknown id is `result: null`; `queue_id == player_id`; server sends a WS ping at about 25 s; image proxy is keyed by `proxy_id`, needs no auth and rejects `size=200` (allowed 0, 80, 160, 256, 512, 1024); no `_music-assistant._tcp` advertised.

## Plan

### What the unauthenticated endpoints already say (checked 2026-10-14, no token used)

`GET /info` and `GET /api-docs/*` answer without auth, so these facts are settled before the recorder runs; the recorder confirms them and fills in the rest.

- **Server:** `server_version` 2.10.6, `schema_version` **65**, `min_supported_schema_version` 28, `homeassistant_addon` true, `onboard_done` true, `status` `running`. `/info` has twelve fields, not the six the doc expects: also `name`, `status`, `internal_url`, `external_url`, `has_remote_access`, `homeassistant_addon`. `base_url` and `internal_url` are LAN addresses, which is why `.env` names the host by DNS name instead. The OpenAPI `ServerInfoMessage` schema has the same twelve fields, so the first WebSocket frame should match `/info`.
- **`/api-docs` is an HTML landing page**, not the command list. The machine-readable lists are `GET /api-docs/commands.json` (310 commands, ~190 KB: `command`, `category`, `summary`, `description`, `parameters[{name,type,required,description}]`, `return_type`, `authenticated`, `required_scope`) and `GET /api-docs/openapi.json` (127 schemas, ~77 KB; `servers[0].url` is the LAN base URL and must be scrubbed). `commands.json` contains no host, server id or token. `/api-docs/commands`, `/api-docs/schemas` and `/api-docs/swagger` are HTML views of the same data.
- **Auth** is documented on the landing page and is *not* in `commands.json` (handshake-only): first message `{"message_id":…,"command":"auth","args":{"token":…}}`, result `{"message_id":…,"result":{"authenticated":true,"user":{"user_id","username","role"}}}`. Long-lived tokens expire after ten years. The page warns clients to check that `server_id` matches the one seen when the user signed in before sending a token to a host:port (two servers can share `homeassistant.local:8095`); #0063 should do that.
- **No subscribe command.** Nothing named `start_listening`/`subscribe` exists; events are pushed to every authenticated socket. Event names on the page: `player_added/updated/removed`, `player_config_updated`, `queue_added/updated/items_updated/time_updated`, `media_item_added/updated/deleted/played`, `providers_updated`, `tasks_updated`, `music_sync_completed`, `application_shutdown`. The page shows an event frame as `{"event":…,"data":…}`; whether `object_id` is present is for the recorder.
- **Unauthenticated commands:** only `time` (server UTC seconds; the description says clients use it to correct `elapsed_time_last_updated` for clock skew) and the `auth/login`-family. `info` as a *command* requires auth even though `GET /info` does not.
- **Listings:** `music/{artists,albums,tracks,playlists}/library_items` take `favorite, search, limit, offset, order_by ('sort_name', 'timestamp_added'), provider, genre, played_only, summary (default true: slim items for a list view), reachable_via, user`, plus `album_artists_only`/`artist_type` for artists and `album_types` for albums. They return a bare array with **no total**; `music/{artists,albums,tracks,playlists}/count` gives the totals. Each entry also lists a `kwargs: Any, required: true` parameter, which looks like a doc-generator artifact; the recorder sends only named args and records whether the server objects.
- **Children:** `music/artists/artist_albums(item_id, provider_instance_id_or_domain, provider_filter?)`, `music/artists/artist_tracks`, `music/albums/album_tracks(item_id, provider_instance_id_or_domain, in_library_only?)`, `music/playlists/playlist_tracks(item_id, provider_instance_id_or_domain, force_refresh?, allow_dynamic_tracks?)`. `playlist_tracks` (and `music/podcasts/podcast_episodes`) returns an `AsyncGenerator`, so it is the one call that should show the streamed/partial envelope. `music/item_by_uri(uri)`, `music/{type}/get(item_id, provider_instance_id_or_domain)` fetch single items.
- **Search:** `music/search(search_query, media_types?, limit? (per type), providers? (["library"] restricts to the library; library_only is deprecated), user?)` returns `SearchResults{artists, albums, genres, tracks, playlists, radio, audiobooks, podcasts, sound_effects}`. One call, not three (answers #0062 section 10).
- **Players and queues:** `players/all(return_unavailable?, return_disabled?, provider_filter?, return_protocol_players?)` → `Player{player_id, provider, type (player|stereo_pair|group|protocol|display|…), name, available, enabled, hide_in_ui, supported_features, playback_state (idle|paused|playing|unknown), elapsed_time, elapsed_time_last_updated, powered, volume_level, volume_muted, group_members, synced_to, active_group, active_source, current_media (PlayerMedia{uri, media_type, title, artist, album, image_url, duration, elapsed_time, elapsed_time_last_updated, queue_item_id, …}), needs_setup, …}`. `player_queues/all` → `PlayerQueue{queue_id, active, display_name, available, items, shuffle_enabled, repeat_mode (off|one|all), current_index, elapsed_time, elapsed_time_last_updated, state, current_item, next_item, …}`; `player_queues/items(queue_id, limit?, offset?)` → `QueueItem{queue_id, queue_item_id, name, duration, media_item, image, index, available, …}`. Transport: `players/cmd/{play,pause,play_pause,stop,next,previous}(player_id)`, `players/cmd/seek(player_id, position s)`, `players/cmd/volume_set(player_id, volume_level 0..100)`, `volume_mute(muted)`, `shuffle(shuffle_enabled)`, `repeat(repeat_mode)`; queue-level twins `player_queues/{play,pause,play_pause,stop,next,previous,seek,shuffle,repeat,resume}(queue_id, …)`. `player_queues/play_media(queue_id, media: uri | item | [uri|item], option: QueueOption (play|replace|next|replace_next|add), start_item?, sort_by?, start_from_beginning?, shuffle?)`. Scopes: `players.read`, `queues.read`, `library.read` for everything the recorder sends; `*.control`/`*.write` only for what it never sends.
- **Artwork:** `MediaItemImage{type (thumb|landscape|fanart|…), path, provider, remotely_accessible, proxy_id}`; `metadata/get_image_palette` calls `proxy_id` "the opaque imageproxy image id". So the proxy path is `/imageproxy…`, but whether it is keyed by `proxy_id` or by `path`+`provider` (the older `?path=&provider=&size=` form) is unknown; `PlayerMedia.image_url` and `QueueItem.image` should show the server's own URL shape. The recorder probes both forms (read-only `GET`s, bytes discarded).
- **Errors:** the only error-shaped schema is `ProviderError{error_code: int, message, translation_key, translation_args, translation_owner}`; the WebSocket error envelope itself is undocumented and must be recorded (the doc guesses `error_code` + `details`).

### Decisions

- **One self-contained Python 3 stdlib script, `scripts/record-ma-fixtures.py`**, run as `/usr/bin/python3 -I scripts/record-ma-fixtures.py` (Apple's 3.9: no `match`, no `X | Y` annotations; Homebrew 3.15 also works). Rationale: the host has `python3`, `curl`, `jq` and `dns-sd` but no `websocat`/`wscat`/`websockets`; the protocol is a stateful JSON-RPC over one socket with pushed events and streamed results, which a `curl`-per-request shell script cannot record; `socket`+`ssl`+`base64`+`hashlib`+`struct`+`json` are enough for a minimal RFC 6455 client (~100 lines: GET `/ws` upgrade with `Sec-WebSocket-Key`, verify `Sec-WebSocket-Accept`, client frames masked, text/continuation frames reassembled by FIN, 7/16/64-bit lengths, answer ping with pong, send close); scrubbing happens in-process with the secrets held only in variables, which is harder to get wrong than a `jq` pipeline; and nothing from the app is built or imported, which `swift` (the interpreter JIT-compiling a `URLSessionWebSocketTask` script, with no `-I` equivalent) would make less obviously true. `Spikes/` stays for things that need Xcode (the AirPlay spike); a recorder is a script like `record-plex-fixtures.sh`.
- **The script reads `.env` itself** (`KEY=value` lines, quotes and whitespace stripped; `MUSIC_ASSISTANT_URL` trailing `/` removed, `ws(s)://` derived by swapping the scheme). The token lives in one local variable, goes only into the `auth` frame and `Authorization: Bearer` headers, never into argv, the environment, a URL, a log line or a file. Every outbound frame is logged only after `token` values are replaced by `"<redacted>"`. No `set -a; source .env` wrapper, which would hand the token to every child process.
- **Read-only, no audio, no state changes.** The allowed command list is a literal in the script and is the only thing `call()` accepts; it is every `*/all`, `*/get`, `*/items`, `*/count`, `*/library_items`, `*_tracks`, `*_albums`, `item_by_uri`, `search`, `auth/me`, `info`, `time`, `providers`, plus `auth`. Nothing under `players/cmd/*`, `player_queues/*` other than `all`/`get`/`items`/`get_active_queue`, `config/*/save|setup|remove`, `music/sync`, `music/favorites/*`, `music/library/*`, `music/tracks/preview`, `metadata/*`, `auth/token/*`, `auth/user/*` is ever sent. `player_queues/play_media`'s shape comes from `commands.json`, not from sending it. The error-envelope fixtures use harmless inputs (a wrong token, an unknown command, an unknown `player_id`), never the real token on a failing path.
- **Fixtures are raw frames, not shaped data,** so #0061 can replay them through a stubbed WebSocket: each file is `{"command": …, "args": {…}, "frames": [ …verbatim server frames in order… ]}` for a call, `{"frames": […]}` for the handshake, and `{"events": [{"after_ms": n, "frame": {…}}]}` for the event window. The `message_id`s are left as sent (`"1"`, `"2"`, …).
- **Where things go.** Scrubbed fixtures: `Packages/PlayerKit/Sources/MusicAssistantKitStub/Fixtures/` (mirrors `PlexKitStub/Fixtures`; #0061 adds the `MusicAssistantKitStub` target with `resources: [.copy("Fixtures")]` and a `MAFixture` enum like `PlexFixture`; until then it is an undeclared directory that SwiftPM ignores, which the VM run confirms; if SwiftPM complains, move it to `Packages/PlayerKit/Tests/MusicAssistantKitTests/Fixtures/` and say so in `## Fix`). Command list: `docs/ma-protocol/commands.json` (verbatim) and `docs/ma-protocol/openapi.json` (`servers[].url` scrubbed), both ~tens of KB and the source of truth the notes cite. Notes: `docs/ma-protocol-notes.md`, written by hand by the implementer from the fixtures and the transcript. The unscrubbed-but-token-redacted transcript goes to `build/ma-recorder/<run-id>/transcript.jsonl` (gitignored under `build/`); it holds LAN addresses and the user name and never leaves the host.

### The recorder, step by step

Each step has a timeout (10 s per call, 60 s whole handshake, the event window as given); the run is bounded at about two minutes. `--out DIR` redirects every output (the reviewer uses it), `--events-seconds N` sets the event window (default 30), `--check` runs only the secret gate against the committed fixtures and docs and makes no network call.

1. `GET /info` (no auth) → remember `server_id`, `name`, `base_url`, `internal_url`, `external_url` as scrub targets; save as `info-http.json`.
2. `GET /api-docs/commands.json` and `/api-docs/openapi.json` → `docs/ma-protocol/`; `GET /api-docs` HTML is read for the auth/event text but not saved (it embeds the LAN IP and the external DNS name eight times).
3. **Connection A, no auth:** open `/ws`, save the first frame as `server-info.json`; send `time` (unauthenticated) → `time.json`; send `players/all` without auth → `error-unauthenticated.json` (or note that the server closed the socket). Close.
4. **Connection B, wrong token:** `auth` with `"not-a-real-token"` → `error-auth.json`. Close.
5. **Connection C, real token:** `auth` → `auth-ok.json` (user fields scrubbed). Then, in order, each saved under the name given: `auth-me.json`; `info-ws.json` (the `info` command, to compare with step 1); `providers.json` (`provider_type: "music"`: the Plex instance id is what `provider_instance_id_or_domain` wants when not using `library`); `players-all.json`, `players-all-unavailable.json` (`return_unavailable: true, return_disabled: true`), `player-get.json` (first player), `error-unknown-player.json` (`players/get` with `player_id: "skinamp-no-such-player"`), `error-unknown-command.json` (`skinamp/no_such_command`); `player-queues-all.json`, `player-queue-get.json`, `player-queue-active.json` (`get_active_queue` for the first player), `player-queue-items.json` (`limit: 3, offset: 0`); `artists-count.json`, `artists-page.json` (`limit: 3, offset: 0, order_by: "sort_name", album_artists_only: true`), `artists-last-page.json` (`offset: count-1`), `artists-page-full.json` (`limit: 1, summary: false`); the same four for albums and tracks (`albums-*.json`, `tracks-*.json`; no `album_artists_only`); `playlists-count.json`, `playlists-page.json`; `artist-albums.json` (first artist, `provider_instance_id_or_domain: "library"`); `album-tracks.json` (first album, `"library"`, `in_library_only: true`); `album-get.json` (`music/albums/get` for it); `playlist-tracks.json` (first playlist; this is the streamed one, so keep every frame until the terminating one); `item-by-uri.json` (the album's `uri`); `search.json` (`search_query`: first word of the first track's name, `media_types: ["artist","album","track","playlist"]`, `limit: 3, providers: ["library"]`). Every listing uses `limit: 3`, as the Plex recorder does, so fixtures stay small.
6. **Artwork probe** (still connection C for nothing; this is HTTP): take the first `MediaItemImage` from `album-get.json` and the first `PlayerMedia.image_url`/`QueueItem.image` seen; `GET` with `Authorization: Bearer` and again without: `/imageproxy?path=<path>&provider=<provider>&size=200`, `/imageproxy/<proxy_id>?size=200`, and the server's own `image_url` verbatim. Record only `{candidate (host replaced), authorized, status, content_type, bytes}` in `artwork-probe.json`; discard the bytes. `ArtworkCache.thumbnailPixels` is 200, so `size=200` is the size #0061 will ask for.
7. **Event window:** keep connection C open for `--events-seconds`, answering pings; save every pushed frame with its offset in `events.json` (cap 40 frames; note the cap if hit). Print a line before the window starts: *"Now, from the MA web UI, pause and resume a speaker that is already playing, or skip a track, to capture player/queue events; the recorder itself never sends a transport command."* If nothing arrives, `events.json` is empty and the notes say so; `player_updated`/`queue_time_updated` cannot be provoked read-only.
8. Close with a proper close frame; note in the transcript whether the server sent any ping of its own during the window (the doc's "55 s heartbeat" is the Python client's `aiohttp` setting, not a protocol message).
9. **Bonjour:** run `dns-sd -B _music-assistant._tcp` and `dns-sd -B _services._dns-sd._udp` (all service types, in case the add-on advertises something else) as subprocesses killed after 5 s each (`timeout` is not installed; use `subprocess.run(..., timeout=5)` and catch `TimeoutExpired`). Save `dns-sd.txt` under `docs/ma-protocol/` with instance names replaced by `<instance>` and any `.local` host replaced; if the type is found, also `dns-sd -L <instance> _music-assistant._tcp` for 5 s to capture the TXT record (scrub it the same way: it may carry `server_id`, `base_url` and the name).
10. **Scrub every fixture in memory, write, then run the gate** (next section). Print one summary line per file: name, frame count, bytes. Nothing else is printed about the data.

### Scrub rules (applied to every fixture and to `docs/ma-protocol/*` before writing)

Same spirit as `record-plex-fixtures.sh`, done in Python on the parsed JSON, recursively:

- **Secrets:** any string containing the token (exact, and URL-encoded) → `"<redacted>"`. Any key named `token`, `access_token`, `token_hash`, `api_key`, `password` → `"<redacted>"`. Any string containing `X-Plex-Token=` or `token=` (the Plex provider's `ProviderMapping.url`/`details` and image `path`s may carry the Plex token) → the query string is dropped.
- **Identity:** `server_id` → `"0123456789abcdef0123456789abcdef"` (same length, 32 hex); `user_id` → `"00000000-0000-0000-0000-000000000000"`; `username`/`display_name` → `"user"`; `avatar_url`/`email` → `null`; the server `name` (from `/info`) → `"Music Assistant"`; `owner` on playlists → `"user"`; `device_name` → `"SkinAmp"`.
- **Addresses:** every host from `/info` (`base_url`, `internal_url`, `external_url`), the `.env` host, `homeassistant.local`, any RFC 1918 or link-local IPv4 (`10.*`, `172.16–31.*`, `192.168.*`, `169.254.*`) and any `*.local` name → `ma.example` (keeping scheme, port and path, so URL shapes survive: `http://ma.example:8095/imageproxy?…`). `openapi.json`'s `servers[].url` gets the same treatment. Provider instance ids (`plex--xxxx`) and `library://…` URIs are kept; they are not personal.
- **Bulk:** `metadata.description`, `review`, `lyrics`, `lrc_lyrics`, `transcript` → first 160 characters; `transcript_cues`, `chapters` → `[]`. Listings are already `limit: 3`; `events.json` keeps at most 40 frames.
- Fixture bytes are what the stubbed WebSocket will replay, so no key is renamed or reordered; scrubbing changes values only.

### Secret gate (also `--check`)

After writing, and again on `--check`, the script reads back every file it owns (`Packages/PlayerKit/Sources/MusicAssistantKitStub/Fixtures/**`, `docs/ma-protocol/**`, `docs/ma-protocol-notes.md` if present) and fails, deleting what it just wrote on a recording run, if any file contains: the token (plain or URL-encoded); `server_id`'s real value; the `.env` host; any host from `/info`; any RFC 1918 or link-local IPv4; any `.local` name; the server `name`; the user name from `auth-ok` before scrubbing; or the substrings `X-Plex-Token`, `token=`, `Bearer `. On `--check` the real values come from `.env` and a fresh `GET /info` (no token sent), so the reviewer can run it on the committed tree without a recording. The same checks are what the implementer and reviewer quote in `## Verification`; `git grep` by hand must not be used for the token (it would put the token on a command line).

### `docs/ma-protocol-notes.md` (written by the implementer from the fixtures)

Header: server version, schema version, recording date, run id, the command the reviewer repeats. Then one subsection per VERIFY item in `docs/music-assistant-integration.md`, each quoting the recorded frame (scrubbed) and ending with a one-line verdict the doc can be updated with:

1. **Server-info handshake:** the first frame's exact keys and values (expect the twelve `/info` fields; confirm whether the frame is bare or wrapped).
2. **`auth`:** request and result shapes; what happens on a bad token (`error-auth.json`) and on a command before auth (`error-unauthenticated.json`: error frame vs. socket close).
3. **Envelope:** success (`message_id` + `result`), the streamed `playlist_tracks` frames (what flags them partial/last, whether `result` is a chunk or cumulative), error (`error-unknown-command.json`, `error-unknown-player.json`: field names, whether `error_code` is a string or an int, whether `details` exists), event (`event`, `data`, and whether `object_id` is present). Whether a `null` result arrives as `"result": null`.
4. **Heartbeat:** whether the server pings or expects one (from the transcript); recommendation for #0061's keep-alive.
5. **Players and transport:** `players/all` fields that matter for `OutputDevice` (`player_id`, `name`, `type`, `available`, `enabled`, `hide_in_ui`, `group_members`, `synced_to`, `active_group`, `supported_features`), the exact arg names of every transport command from `commands.json`, and whether `queue_id == player_id` holds in the recordings (`player-queues-all` vs `players-all`), plus `get_active_queue` for a grouped player if one exists.
6. **Search:** one call; which `SearchResults` keys carry what; whether `providers: ["library"]` was honored.

### Risks and surprises

- **Schema 65 against a doc written for "2.10.6" with six `/info` fields.** The doc's handshake, envelope and command tables were partly guessed from the Python client; the server's own docs differ (no subscribe command, `info` needs auth, twelve info fields, `summary` listings, `providers` instead of `library_only`). Expect more doc corrections than the VERIFY markers suggest; the notes list them for #0061 to apply.
- **Paging has no totals.** `library_items` returns a bare array; `Page.make(items:request:total:)` works with `total: nil` (next page when `items.count >= limit`) and `*/count` can supply the total. Fine for the browser's `PagedList`, but the notes must say which.
- **`playlist_tracks` streams.** The one `AsyncGenerator` command the client needs; if the partial envelope turns out to be cumulative or unflagged, #0061's partial-result assembly changes shape. If the library has no playlist, the recorder skips the call and the notes say the envelope is unrecorded (then #0061 should treat `music/podcasts/podcast_episodes` as the alternative to record).
- **Events need a hand action.** With nothing playing, only `tasks_updated`/`providers_updated`-type events might arrive. Recording `player_updated` requires the user to pause/resume a speaker that is already playing from the MA UI during the window; the recorder cannot cause audio and must not.
- **`summary: true` slim items.** The default listing may omit `artists`, `album`, `metadata.images` or `duration`; if so, #0061 either requests `summary: false` for the browser or fetches details per item. The full-vs-slim fixtures settle it.
- **Artwork may need the bearer header** (HA add-on behind its own auth). If the image proxy refuses anonymous `GET`s, `MusicAssistantBackend.artwork` must send the header; if `PlayerMedia.image_url` is absolute with a LAN host, the client must rewrite the host to the configured one.
- **The `.env` host is a DNS name, `base_url` is a LAN IP, and the add-on also has an external name.** Discovery (Bonjour) will hand the client a `.local` name or IP that differs from what the user typed; the server-ID check the API docs recommend is the right guard and belongs in #0063's Test Connection.
- **`dns-sd` may show nothing.** The HA add-on may not advertise `_music-assistant._tcp`; recording `_services._dns-sd._udp` as well tells whether any MA type exists. If none, #0063 keeps Bonjour behind the manual field and `NSBonjourServices` lists the type only if one was seen.
- **Stray `kwargs: required` in `commands.json`.** If the server really rejects calls without it, the notes record the error and the arg to pass; more likely it is ignored.
- **Python 3.9 on the host path.** `/usr/bin/python3` is 3.9.6; keep the script 3.9-compatible and run it with `-I` so no `json.py` in the cwd can be picked up.
- **Fixtures contain the Plex provider's item ids and the MA library's titles.** Titles are not secrets (the Plex fixtures already contain them); provider `url`s are stripped of query strings in case they carry a Plex token, and the gate greps for `X-Plex-Token`.
