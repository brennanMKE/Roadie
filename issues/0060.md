# 0060 — Music Assistant's real message shapes are unverified

## Description

Many details of MA's WebSocket protocol in [docs/music-assistant-integration.md](../docs/music-assistant-integration.md) are marked **VERIFY**: the server-info handshake fields, the `auth` command, the result/partial/error/event envelope, the heartbeat, `players/all` and player transport commands, `music/search`, the `library_items` listings, event subscription, artwork URLs and the Bonjour service type. Record the real shapes from a running server before writing the client.

## Acceptance criteria

- A spike (Swift CLI under `Spikes/`, or `curl` + `websocat`) connects to `/ws`, logs the server-info message, authenticates with a long-lived token, calls `player_queues/all`, `players/all` and one library listing, and subscribes to events.
- `docs/ma-protocol-notes.md` records each message shape and resolves every VERIFY item in the doc, with the MA server version it was taken from and the `/api-docs` command list saved alongside.
- Small JSON fixtures for the client's unit tests, scrubbed of the token, user names, server ids and LAN addresses (same rules as `scripts/record-plex-fixtures.sh`: token only in a shell variable, grep the fixtures for it before committing).
- `dns-sd -B _music-assistant._tcp` result recorded.

## Notes

Needs a running MA server on the home LAN with the Plex library added as a source (doc section 3). The recording runs by hand on the host (network only, no audio); the VM never gets the MA token.
