## Description

Found at the end of milestone M11. The orchestrator started the milestone-end full run (`scripts/run-tests-vm.sh --head --full --launch`, run `20261019-021207-89719`) while an implementer's run for #0091 started at about the same time. The full run's guest died during `skinkit-build` (`Error: unavailable (14): Transport became inactive`, then `VM "skinamp-test-20261019-021207-89719" is not running`).

Cause: the stale-clone sweep in `scripts/run-tests-vm.sh` (lines 161–168) stops and deletes every `skinamp-test-<date>-<time>-<pid>` clone except its own, including clones that belong to a run that is still going. `tart-lease` allows two guests, so two runs at once are expected; whichever starts second kills the first.

Second problem: when the guest dies, the summary reports `Skip: … (build failed)` and exits 2, as if the code did not compile. An infrastructure failure should be reported as one (for example `==> FAIL  guest lost`), so agents don't go looking for a compile error.

Expected:

- The sweep only removes clones whose run is gone: the `<pid>` in the name is not a live `run-tests-vm.sh` process (and, as a fallback, the clone is older than the longest plausible run).
- Two runs started together both complete.
- A lost guest is reported as an infrastructure failure, distinct from FAIL/SKIP for build or tests.

## Plan

Only one file holds the logic: `scripts/run-tests-vm.sh`, plus its docs in `docs/testing-in-vm.md`. No Swift changes. Notes on how the failure happened:

- Run A (`…-021207-89719`) and run B (`…-021231-89965`) started 24 s apart. B's sweep (lines 161–168) runs **before** `tart-lease acquire`, saw A's clone and `tart stop`/`tart delete`d it. B's own lease is stamped with its pid (`tart-lease acquire --pid $$`), and `ps -p <pid> -o command=` for a live run prints `/bin/zsh scripts/run-tests-vm.sh …`, so the pid in the clone name plus the command line is enough to tell whether the run that owns a clone is still alive.
- After the guest died, every later `run_step` printed `Skip: … (build failed)`, because a dead `tart exec` looks like a non-zero build step. The exit was 2 rather than the summary's 1 because `gx "tar …" | tar -x` (line 341) failed under `set -euo pipefail` before the summary was printed, and `tart exec`'s own status went out through the `EXIT` trap. Exit 2 already means "usage error" in this script (lines 69–100), which makes it misleading on top of that.

### 1. Sweep only orphaned clones

Replace lines 161–168 with a helper, `run_is_live <pid>`, and a sweep that uses it:

```zsh
# Max plausible run: a full --corpus run plus --stress 200 is well under this.
MAX_RUN_HOURS=8
run_is_live() {   # true if <pid> is a live run-tests-vm.sh process
  local cmd
  cmd=$(ps -p "$1" -o command= 2>/dev/null) || return 1
  [[ "$cmd" == *run-tests-vm.sh* ]]
}
for old in $(tart list --quiet); do
  [[ "$old" =~ '^skinamp-test-([0-9]{8})-([0-9]{6})-([0-9]+)$' ]] || continue
  [[ "$old" == "$CLONE" || "$old" == "$GOLDEN" ]] && continue
  pid=$match[3]
  started=$(date -j -f '%Y%m%d%H%M%S' "$match[1]$match[2]" +%s 2>/dev/null) || started=0
  age_h=$(( ($(date +%s) - started) / 3600 ))
  if run_is_live "$pid" && (( age_h < MAX_RUN_HOURS )); then
    log "Leaving clone of a live run: $old (pid $pid)"; continue
  fi
  log "Sweeping stale clone: $old (pid $pid gone$( (( age_h >= MAX_RUN_HOURS )) && print -n ", ${age_h}h old"))"
  tart stop "$old" >/dev/null 2>&1 || true
  tart delete "$old" >/dev/null 2>&1 || true
done
```

- Keep the exact anchored regex (the golden-deletion lesson). Use `tart list --quiet` (names only, Tart 2.32.1) instead of awk on column 2. `[[ =~ ]]` in zsh fills `$match`; don't `setopt BASH_REMATCH`.
- `ps -p` exits 1 when the pid is gone, so the `|| return 1` keeps `set -e` happy. Don't use `kill -0`: it fails with EPERM for another user's process and can't see the command. Don't use `pgrep -f`: it matches by pattern, not by pid.
- **Pid reuse** is covered by the command check (a recycled pid is almost never another `run-tests-vm.sh`), with the age fallback as backstop: a clone whose run-id timestamp is older than `MAX_RUN_HOURS` goes even if the pid looks live. Take the age from the run id, not `tart list`'s `Accessed` column, which changes whenever the VM is touched. The run id is the host's local `date`, and `date -j -f` parses it in local time too, so the two agree.
- Never touch anything else. Golden images, other projects' `*-uitest-golden` and hand-renamed clones don't match the regex.
- Leave the sweep where it is (before the lease). With the liveness check, its position no longer matters.
- Update the comment above the sweep: it removes clones whose run is gone (SIGKILL / OOM), and two concurrent runs are expected (`tart-lease` allows two).

### 2. Report a lost guest as an infrastructure failure

- **Detection helper:**
  ```zsh
  guest_alive() { tart exec "$CLONE" true >/dev/null 2>&1 && return 0; sleep 2; tart exec "$CLONE" true >/dev/null 2>&1; }
  ```
  Probe twice so one transport hiccup doesn't count. Optionally also check that `tart list --format json` shows `"Running": true` for `$CLONE`. The probe alone is enough, because a stopped VM fails `tart exec` immediately (`VM "…" is not running`).
- **In `run_step`:** after `step_rc[$name]=$?`, if the rc is non-zero and `! guest_alive`, set `step_rc[$name]=lost`, `guest_lost=1`, `lost_step=$name` and log `Guest lost during $name`. Do **not** set `build_failed`. At the top of `run_step` (and in `skip_step`), once `guest_lost` is set, record `step_rc[$name]=lost-skip` and log `Skip: $name (guest lost)` instead of running it. `skip_step` currently hard-codes "(build failed)", so give it a reason argument.
- **Other `gx` calls outside `run_step`** need guarding: the prep calls on lines 228–238, the corpus `du`/`df`/`cp`, and the results pull. If a prep `gx` fails and `! guest_alive`, call `infra_fail "guest lost during prepare"`. For the results pull, write `if (( ! guest_lost )); then gx "tar …" | tar -x … || { guest_alive || { guest_lost=1; lost_step=${lost_step:-results}; }; }; fi` so a dead guest still gets a summary. Run `mkdir -p "$RESULTS_DIR"` regardless.
- **Boot timeout** (line 221) is the same kind of failure. Route it through `infra_fail "guest not reachable within ${BOOT_TIMEOUT_SECS}s"`, where `infra_fail() { log "INFRA  $*"; exit 3; }` (the `EXIT` trap still cleans up). Preflight failures (no Tart, disk, memory) stay `fail` / exit 1. They are host conditions with their own messages.
- **Summary:** add cases to the step loop. `lost)` prints `FAIL  $name (guest lost)`; `lost-skip)` prints `SKIP  $name (guest lost)`. After the loop, if `guest_lost`, print
  `==> INFRA  guest lost during <lost_step>: the VM stopped or tart exec lost its transport; not a build or test failure -- rerun` and set `overall=3`. Leave the `BUILD failed` / compiler-error block keyed on `build_failed` only, so it never fires for a lost guest. If both a real test failure and a lost guest happen in one run, exit 3 wins: the run is incomplete, so a rerun is the action.
- **Header exit codes** (replace lines 43–44): `0` = everything passed and silent; `1` = a build/test/check step failed, or the host audio check tripped, or a preflight check failed; `2` = bad arguments; `3` = infrastructure: the guest didn't boot or was lost mid-run (summary line `INFRA`), not a code problem, rerun.

### 3. Docs (`docs/testing-in-vm.md`)

- **How a run works, step 2:** the sweep removes `skinamp-test-<YYYYMMDD>-<HHMMSS>-<pid>` clones whose `<pid>` is no longer a live `run-tests-vm.sh` process, or whose run id is older than 8 h. Clones of a live run (another agent's concurrent run) are left alone, and nothing outside that exact name shape is ever touched.
- **Summary section:** add an example of a lost-guest summary (`FAIL  skinkit-build (guest lost)`, `SKIP  … (guest lost)`, `INFRA  guest lost during …`) and a sentence: an `INFRA` line (exit 3) means the VM went away, not the code, so rerun rather than looking for a compile error. List the exit codes 0/1/2/3 next to the existing "It exits non-zero if…" paragraph.
- **Known limits:** two runs at once are fine (up to the `tart-lease` limit of two, shared across projects). A third waits for a slot.
- **Debugging a run:** a clone kept by commenting out `tart delete` is swept by the next run once its run has exited. To keep it, `tart rename` it to a name outside the pattern (e.g. `skinamp-keep-<id>`) and delete it by hand later.

## Resolution notes

> 🟢 Resolved 2026-10-19 — the sweep now removes only clones whose run is gone (pid not a live `run-tests-vm.sh`, or run id over 8 h old), and a lost guest is reported as `INFRA` (exit 3) instead of a build failure.

Review (Opus, ada3486): diff read in full. The anchored regex plus the `$CLONE`/`$GOLDEN` skips mean the golden and non-matching names can't be touched; a reused pid only keeps a clone if the new process is itself a `run-tests-vm.sh` (`*run-tests-vm.sh*` doesn't match other projects' `run-ui-tests-vm.sh`), and the 8 h fallback clears that case. Lost-guest marking requires a non-zero step **and** two failed `tart exec true` probes, so a real compile or test failure with a live guest still reports FAIL/`BUILD failed`; the results pull, prep `gx` calls and corpus probes are guarded so `set -e` can't skip the summary. Header and docs agree on 0/1/2/3. (2) A boot failure from a host problem (e.g. the `Code=-9` HostKey error outside the Aqua session) now exits 3 "rerun", though rerunning won't help; the message does point at `tart-run.log`. (3) If the results pull fails while the guest is still alive, the run carries on without a message and the summary comes from whatever logs exist.

## Root cause

The stale-clone sweep in `scripts/run-tests-vm.sh` stopped and deleted every `skinamp-test-<date>-<time>-<pid>` clone but its own, including the clone of a concurrent run that `tart-lease` had legitimately admitted. The dead guest then made every later `tart exec` fail, which `run_step` read as a build failure, and the unguarded results pull (`gx "tar …" | tar -x` under `set -euo pipefail`) exited 2 before the summary.

## Fix

Followed the plan.

- Sweep: `run_is_live <pid>` (`ps -p <pid> -o command=` containing `run-tests-vm.sh`) plus an 8 h age fallback taken from the run id; `tart list --quiet` with the anchored zsh `=~` regex. Live runs log `Leaving clone of a live run: …`.
- Lost guest: `guest_alive` (two `tart exec true` probes). `run_step` marks a non-zero step with a dead guest `lost`, later steps `lost-skip` via `skip_step` (which now picks its reason); `build_failed` is never set for it. Prep `gx` calls go through `gx_prep` (INFRA exit 3 if the guest is gone, `fail` otherwise); boot timeout uses `infra_fail` (exit 3); corpus `du`/`df` are guarded and followed by a liveness check; the results pull is skipped or guarded so the summary always prints. Summary prints `FAIL … (guest lost)`, `SKIP … (guest lost)`, `INFRA  guest lost during <step> …` and exits 3 (the audio check cannot downgrade 3 to 1).
- Header exit codes 0/1/2/3; docs updated (sweep, lost-guest summary example, exit codes, concurrent runs, keeping a clone with `tart rename`).
- Small deviation: the sweep log says `(pid N not a live run…)` instead of the plan's `(pid N gone…)`, since pid 1 in the orphan test is live, just not this script. The orphan-sweep run below predates that wording change (it logged `pid 1 gone`); only the log text changed.
