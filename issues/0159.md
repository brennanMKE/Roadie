## Description

M14 work item W8 from [docs/design/release.md](../docs/design/release.md). Depends on: W7.

## Expected behavior

`make-dmg.sh` signs Sparkle's XPC services, Autoupdate and Updater.app inside-out with Developer ID, hardened runtime and timestamps; `Roadie-X.Y.Z.dmg`; notarize and staple; `.sha256`; `scripts/verify-dmg.sh`.

## Resolution notes

> 🟢 Resolved 2026-10-23 — `make-dmg.sh --release` signs Sparkle's nested code inside-out and writes `Roadie-X.Y.Z.dmg` with its `.sha256`; `verify-dmg.sh` checks the result.

## Root cause

`make-dmg.sh` signed only the frameworks, appexes and app, so Sparkle's XPC services, `Autoupdate` and `Updater.app`
would keep their ad-hoc signatures and fail notarization. It also named the DMG after the build, not
`Roadie-X.Y.Z.dmg`, wrote no checksum, and nothing checked a finished DMG the way a recipient's Mac sees it.

## Fix

- `make-dmg.sh --release X.Y.Z [--out DIR]`: version gate (app and both appexes report `X.Y.Z (<build>)`); signs
  `Installer.xpc`, `Downloader.xpc`, `Autoupdate`, `Updater.app`, then `Sparkle.framework`, the appexes and the app,
  each with `--options runtime --timestamp` and its own entitlements minus `get-task-allow`; `codesign --verify --deep
  --strict`; a per-Mach-O check (not ad-hoc, team, Developer ID authority, runtime, timestamp); `Roadie.dmg` as the
  working name, notarize and staple with `--notary-profile`, then `mv` to `Roadie-X.Y.Z.dmg`, `.sha256` written in
  the folder, and the dSYM zip and UUIDs copied alongside. Refuses to run with xtrace on.
- `scripts/verify-dmg.sh`: DMG signature and team, stapler, spctl on the DMG, volume layout, deep verify, spctl exec on
  the app, every Mach-O's authority/team/runtime/timestamp, and a Safari-quarantine copy assessed by spctl.
  `--allow-unnotarized` reports the four notarization checks as expected failures.
- `docs/releasing.md`, `docs/code-signing.md`.
