## Description

Phase B of M15, the playlist editor UI for the play-next list from #0177.

- A bare `Q` in the playlist editor toggles the queue for the selected rows.
- Queued rows show their place, `[1]`, `[2]`, …, which count down as they play.
- A new right-click menu on the rows offers Queue / Dequeue and Clear Queue.

This covers the local queue only. On a Music Assistant queue, `Q` and the menu item come in #0182; until then they're hidden or do nothing there.

**Correction to the spec:** the spec puts the menu in `PlaylistContextMenus` as "the playlist right-click menu", but the playlist has no right-click menu. `PlaylistContextMenus` only builds the SORT and MISC pop-ups. Right-click is wired only for the main window (`SkinWindowController.init`, `onRightMouseDown` when `kind == .main`), and Control-click on a row is a ⌘-click (toggle selection) in `PlaylistListInputView.mouseDown`. This issue adds the menu on `rightMouseDown` and leaves Control-click as it is.

**Defaults until #0174 confirms them:**

- Row 1: the marker sits in its own cell just before the time column, in the row's normal colour, and the title truncates before the marker does.
- Row 3: `Q` dequeues when every selected row is queued, and otherwise queues the rest at the end.

`Q` isn't a Winamp global hotkey, so it lives in the playlist view, not `WinampHotkeys`.

## Root cause

The play-next list from #0177 had no UI. The playlist editor had no key to queue rows and no right-click menu, and the rows couldn't show where a track sits in the queue.

## Fix

Done as planned. `PlaylistText.queueMarker` formats the marker. `PlaylistModel.Row.marker` is filled only on the local queue, and when `upNext` is empty the lookup is skipped. `PlaylistModel` gains `hasUpNext`, `selectionIsQueued`, `toggleQueue(_:)`, `toggleQueueForSelection()` and `clearUpNext()`; none of them call `onPlayLocal()`. The marker has its own `fixedSize()` cell before the duration, so the title truncates first. A bare Q in `PlaylistListInputView.keyDown` toggles the queue (ignored on key repeat and with any modifier held). `rightMouseDown` selects the row under the pointer if needed and pops up `PlaylistContextMenus.rowMenu`, which offers Play, Queue/Dequeue (hidden on a remote queue until #0182), Clear Queue (only when something is queued), Remove and File Info…. Control-click is unchanged. There's a CHANGELOG entry.

One small addition to the plan: `toggleQueue` drops out-of-range indices and returns early when no IDs are left.

## Plan

### 1. Marker text (`Packages/SkinKit/Sources/SkinKit/Display/PlaylistText.swift`)

```swift
/// A queued row's place in the play-next list (#0179): "[n]" for 1-based `position`, "" when not queued.
public static func queueMarker(_ position: Int?) -> String
```

nil, 0 and negative positions give "".

### 2. Model (`App/Playlist/PlaylistModel.swift`)

- `Row`: add `let marker: String`. In `rows`:
  - Set it to `PlaylistText.queueMarker(player.queue.upNextPosition(of: track.id))` only when `remote == nil && isLocal()`; otherwise "".
  - With `upNext` empty, skip the lookup (a fast path), so a 10,000-row queue with no markers costs nothing.
- Add:
  ```swift
  /// Something is queued on the local queue (the menu shows Clear Queue).
  var hasUpNext: Bool { remote == nil && isLocal() && !player.queue.upNext.isEmpty }
  /// Every selected row is queued (the menu says Dequeue then).
  var selectionIsQueued: Bool
  /// Q, the menu's Queue/Dequeue and Jump to File's Queue (#0180): toggles `indices` (row order) in the play-next list.
  func toggleQueue(_ indices: [Int])
  func toggleQueueForSelection() { toggleQueue(selectedIndices.sorted()) }
  func clearUpNext()
  ```
- `toggleQueue`:
  - `guard remote == nil, isLocal() else { return }`. The remote branch lands in #0182; put a `// #0182` comment where it will go.
  - Map the indices to `player.queue.tracks[i].id`, then `player.toggleUpNext(ids)`.
  - Don't call `onPlayLocal()`. Queueing doesn't start playback or take This Mac back from Music Assistant.
- `clearUpNext()`: `player.clearUpNext()` when local.

### 3. Rows (`App/Playlist/PlaylistWindowView.swift`, `PlaylistTrackListView`)

Between the name `Text` and the duration `Text`, add:

```swift
if !row.marker.isEmpty {
    Text(" " + row.marker).font(font).tracking(0.5).lineLimit(1).fixedSize()
}
```

- It takes the row's foreground (current or normal colour).
- `fixedSize()` keeps it whole while the name's `.truncationMode(.tail)` gives way first.

### 4. Q key (`App/Playlist/PlaylistWindowOverlays.swift`, `PlaylistListInputView.keyDown`)

- Before the `switch`: if `!event.isARepeat`, the device-independent modifier flags hold none of ⌘ ⌃ ⌥ ⇧, and `event.charactersIgnoringModifiers?.lowercased() == "q"`, call `model.playlist.toggleQueueForSelection()` and return.
- ⌘Q never gets here: the menu bar's Quit takes it first.
- A remote queue falls through to the no-op until #0182.

### 5. Row menu (`PlaylistListInputView`)

```swift
override func rightMouseDown(with event: NSEvent) {
    MainActor.assumeIsolated {
        window?.makeFirstResponder(self)
        let playlist = model.playlist
        playlist.openMenu = nil
        guard let index = row(atY: skinPoint(event).y) else { return }
        if !playlist.isSelected(index) { playlist.click(index) }   // Finder-style: right-click selects the row
        NSMenu.popUpContextMenu(PlaylistContextMenus.rowMenu(model), with: event, for: self)
    }
}
```

In `App/Playlist/PlaylistContextMenus.swift`, add `static func rowMenu(_ model: PlayerModel) -> NSMenu`. Build the items with `ActionMenuItem`, `autoenablesItems = false`:

- **Play**: `playlist.playFirstSelected()`.
- **Queue** or **Dequeue**, titled by `selectionIsQueued`, running `toggleQueueForSelection()`. Hidden when `playlist.remote != nil` until #0182.
- **Clear Queue**: `clearUpNext()`, only when `hasUpNext`.
- A separator.
- **Remove**: `removeSelected()`.
- **File Info…**: `model.showFileInfo(for:)` with `playlist.fileInfoTrack`, disabled when nil.

`popUpContextMenu` runs synchronously inside the event, unlike `popUp(_:)`, which defers a turn for the skinned menus. That's fine here, because no skinned menu is open.
