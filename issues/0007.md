## Description

Publish track info through `MPNowPlayingInfoCenter` and handle play/pause/next/previous/seek from `MPRemoteCommandCenter`.

## Acceptance criteria

- Keyboard media keys and Control Center work while the app is in the background.
- Album art is shown when available.

## Plan

### Assumptions about #0002 (adapt names to whatever it actually shipped)

This plan was written before #0002 landed. It assumes `Packages/PlayerKit` exists with an `AudioCore` library target (Swift 6 language mode, `platforms: [.macOS(.v14)]`, Swift Testing) and:

- `Track` — `Sendable` struct with `title: String`, `artist: String`, `duration: TimeInterval`, and a `source` (file URL or Plex part + cache key). **It probably has no `album`.** Add `album: String?` (defaulted to `nil`) if missing; it is a one-line, source-compatible change.
- A `@MainActor` player controller (called `Player` below) with `currentTrack: Track?`, `state: PlaybackState` (`.stopped / .playing / .paused`), `currentTime: TimeInterval`, and `play() / pause() / stop() / next() / previous() / seek(to:)`. If the controller is an `actor` instead of `@MainActor`, every call below just gains an `await`.
- `App/PlayerModel.swift` owns the `Player` (its current `play()/pause()/…` stubs were replaced by #0002).

Check `git log --oneline -- Packages/PlayerKit` and read `Packages/PlayerKit/Sources/AudioCore/` before starting; if #0002 is not merged yet, stop and bail per Issues.md ("When the subagent can't finish") — this issue cannot be built without it.

### Where the integration lives

Everything goes in **AudioCore**, not the app. `docs/plan.md` lists Now Playing under "Playback (AudioCore)", and `MediaPlayer.framework` is available on macOS 10.12.2+, so the package can `import MediaPlayer` directly. AudioCore stays Plex-agnostic: the bridge only ever sees `Track` fields and a *local file URL* (after #M2 TrackCache, a Plex track is also just a cached file by the time it plays). Plex album art (M3) will come later through the injectable artwork provider described below, from the app side.

New files:

```
Packages/PlayerKit/Sources/AudioCore/NowPlaying/
  NowPlayingSnapshot.swift      pure data: what the system should show right now
  NowPlayingInfoBuilder.swift   pure mapping Snapshot -> [String: Any]  (unit-tested)
  NowPlayingBridge.swift        @MainActor; owns MPRemoteCommandCenter + MPNowPlayingInfoCenter
  EmbeddedArtworkLoader.swift   AVAsset commonMetadata -> Data?
Packages/PlayerKit/Tests/AudioCoreTests/
  NowPlayingInfoBuilderTests.swift
```

Wiring in `App/PlayerModel.swift`: after creating the `Player`, create `NowPlayingBridge(player: player)` and call `bridge.install()`. Keep the bridge alive for the app's lifetime (stored property). Nothing else in the app changes.

### Two seams between the bridge and the player

1. **Commands (bridge → player).** A small `@MainActor protocol NowPlayingCommandTarget: AnyObject { func play(); func pause(); func togglePlayPause(); func stop(); func next(); func previous(); func seek(to seconds: TimeInterval) }`. `Player` conforms (add `togglePlayPause()` if #0002 did not; it is `state == .playing ? pause() : play()`). The bridge holds `weak var target`.
2. **State (player → bridge).** The bridge must be told *when* something changed, not poll. Preferred: `Player` exposes `public var events: AsyncStream<PlayerEvent>` with `enum PlayerEvent: Sendable { case trackChanged(Track?), stateChanged(PlaybackState), seeked(TimeInterval) }`. The bridge consumes it in a `Task` started by `install()` (cancelled in `uninstall()`/`deinit`). If #0002 shipped no event stream, add one — it is also what #0003 (gapless auto-advance) needs to tell the UI the track changed. Fallback if adding a stream is too invasive: give the bridge three public entry points (`trackDidChange(_:)`, `playbackStateDidChange(_:elapsed:)`, `didSeek(to:)`) and have `Player` call them from the same spots.

Either way the bridge reads the current elapsed time from `player.currentTime` at the moment of the event; it does not keep its own clock.

### MPRemoteCommandCenter: which commands, and the main-actor hop

In `install()`, on `MPRemoteCommandCenter.shared()`:

| Command | Enable | Handler |
|---|---|---|
| `playCommand` | yes | `target.play()` |
| `pauseCommand` | yes | `target.pause()` |
| `togglePlayPauseCommand` | yes | `target.togglePlayPause()` — this is what the keyboard F8 / play-pause media key sends |
| `stopCommand` | yes | `target.stop()` |
| `nextTrackCommand` | yes | `target.next()` |
| `previousTrackCommand` | yes | `target.previous()` |
| `changePlaybackPositionCommand` | yes | `target.seek(to: event.positionTime)` — scrubbing in Control Center |
| `seekForwardCommand`, `seekBackwardCommand`, `skipForwardCommand`, `skipBackwardCommand` | **set `isEnabled = false`** | none — otherwise Control Center may show ±15 s skip buttons instead of track skip |

Concurrency under Swift 6 strict checking: `addTarget(handler:)` takes a non-isolated `@Sendable` closure returning `MPRemoteCommandHandlerStatus` synchronously, and `MPRemoteCommandEvent` is not `Sendable`. Pattern for every handler:

```swift
let token = center.changePlaybackPositionCommand.addTarget { [weak self] event in
    // Extract Sendable values BEFORE hopping; do not capture `event`.
    guard let position = (event as? MPChangePlaybackPositionCommandEvent)?.positionTime else {
        return .commandFailed
    }
    Task { @MainActor [weak self] in self?.target?.seek(to: position) }
    return .success
}
```

Do **not** use `MainActor.assumeIsolated` — Apple does not document the handler thread, and it traps if wrong. Store every returned token in `[Any]` and call `command.removeTarget(token)` in `uninstall()`, so tests and re-installs do not stack handlers. `MPRemoteCommandCenter.shared()` and `MPNowPlayingInfoCenter.default()` are only touched from the `@MainActor` bridge.

### MPNowPlayingInfoCenter: keys, and when to publish

`NowPlayingSnapshot` (Sendable, Equatable): `title`, `artist`, `album: String?`, `duration: TimeInterval`, `elapsed: TimeInterval`, `state: PlaybackState`, `artwork: Data?` (ignored by the builder's tests apart from presence).

`NowPlayingInfoBuilder.info(for:)` returns `[String: Any]` with exactly:

| Key | Value |
|---|---|
| `MPMediaItemPropertyTitle` | `title` |
| `MPMediaItemPropertyArtist` | `artist` |
| `MPMediaItemPropertyAlbumTitle` | `album` (omit key when `nil`) |
| `MPMediaItemPropertyPlaybackDuration` | `duration` as `Double` |
| `MPNowPlayingInfoPropertyElapsedPlaybackTime` | `elapsed` as `Double` |
| `MPNowPlayingInfoPropertyPlaybackRate` | `1.0` when `.playing`, else `0.0` |
| `MPNowPlayingInfoPropertyDefaultPlaybackRate` | `1.0` |
| `MPNowPlayingInfoPropertyMediaType` | `MPNowPlayingInfoMediaType.audio.rawValue` |
| `MPMediaItemPropertyArtwork` | `MPMediaItemArtwork` when artwork data is present (added by the bridge, not the builder, so the builder stays `MPMediaItemArtwork`-free and trivially testable) |

The system extrapolates the position from elapsed + rate + the time of the last update, so **do not update on a timer**. Publish only on:

| Event | What the bridge does |
|---|---|
| `trackChanged(track)` | Rebuild the full dictionary (elapsed 0, current state), set `nowPlayingInfo`, set `playbackState`, then start the async artwork load; when it returns (and the current track is still the same one), merge `MPMediaItemPropertyArtwork` into the existing dictionary and re-set it. `trackChanged(nil)` → `nowPlayingInfo = nil`, `playbackState = .stopped`. |
| `stateChanged(.playing / .paused)` | Copy the existing dictionary, update only elapsed (from `player.currentTime`) and rate, re-set it; set `playbackState`. |
| `stateChanged(.stopped)` | `nowPlayingInfo = nil`, `playbackState = .stopped`. |
| `seeked(t)` | Copy the existing dictionary, update elapsed (and rate from current state), re-set it. |

`MPNowPlayingInfoCenter.default().playbackState` is **macOS-only** and is what tells the system the app is "now playing"; set it on every event above, *after* `nowPlayingInfo`. Keep the info dictionary while paused (Control Center should keep showing the track); only clear it on stop / end of queue / eject.

### Album art from the file

`EmbeddedArtworkLoader.artworkData(for url: URL) async -> Data?`:

```swift
let asset = AVURLAsset(url: url)
let metadata = try await asset.load(.commonMetadata)
let items = AVMetadataItem.metadataItems(from: metadata, filteredByIdentifier: .commonIdentifierArtwork)
return try await items.first?.load(.dataValue)
```

This covers ID3 `APIC` (mp3) and iTunes `covr` (m4a/aac). It runs off the main thread by virtue of being `async` on AVFoundation; keep it `nonisolated`. Cache the result per track source in the bridge (`[URL: Data?]`, bounded or just the current track) so play/pause does not reload it.

Make the loader injectable: `NowPlayingBridge.init(player:artwork: @Sendable (Track) async -> Data? = EmbeddedArtworkLoader.artwork(for:))`. The default reads the track's file URL; M3 will pass a closure that fetches Plex `thumb` bytes from the app side, so AudioCore never learns about Plex.

Creating the artwork object under Swift 6: `MPMediaItemArtwork(boundsSize:requestHandler:)` takes a `@Sendable (CGSize) -> NSImage` handler and may call it on any thread, repeatedly. `NSImage` is not `Sendable`, so **capture the `Data`, not an `NSImage`**, and decode inside the handler (`NSImage(data: data) ?? NSImage()`); pass `boundsSize` as the decoded image's size (decode once up front to read it, discard that image). If the compiler still complains, wrap the data in a tiny `struct ArtworkBytes: Sendable { let data: Data }`.

### What is unit-testable vs. manual

**Unit tests** (`Packages/PlayerKit/Tests/AudioCoreTests/NowPlayingInfoBuilderTests.swift`, Swift Testing, `import MediaPlayer` is fine in tests on macOS):

- Playing snapshot → rate `1.0`, elapsed and duration as given, title/artist/album present, media type audio.
- Paused snapshot → rate `0.0`; stopped → rate `0.0`.
- `album == nil` → `MPMediaItemPropertyAlbumTitle` key absent.
- The dictionary contains no key the table above does not list (guards against accidental per-tick keys like `MPNowPlayingInfoPropertyPlaybackProgress`).
- `NowPlayingBridge` "delta" logic if factored as a pure function (`apply(event:to dictionary:)`): a state change leaves title/artist/duration untouched and changes only elapsed + rate.

Do **not** unit-test `MPRemoteCommandCenter` / `MPNowPlayingInfoCenter` — they are process-wide singletons that talk to the system media daemon, and asserting on them in `swift test` is flaky. Artwork extraction is also not unit-tested unless a tiny `.m4a` fixture with a `covr` atom is added under `Tests/AudioCoreTests/Fixtures/` (optional; `afconvert` cannot embed art, so only add one if a suitable file is already at hand).

**Manual check** (the implementer records exactly which of these were done, and which were not, in `## Verification`; the reviewer repeats them):

1. Build and launch the app (command below). Open a local audio file with embedded artwork and press Play (requires #0006's open/drop path; if #0006 is not done, temporarily use `Player.load(url:)` from a debug menu item and remove it before committing).
2. Open Control Center › Now Playing (or the Now Playing menu bar item): title, artist, album and the cover image appear; the position bar advances and the duration is right.
3. Click another app (Finder) so SkinAmp is in the background. Press the keyboard play/pause media key: playback pauses; press again: resumes. Press next/previous media keys: the track changes and Control Center updates. (If Music.app opens instead, see Risks.)
4. In Control Center press pause, play, next, previous, and drag the scrubber: each reaches the player, and after the scrub the elapsed time in Control Center matches the app.
5. Stop the player: the entry disappears from Control Center. Pause: it stays, showing the paused state.
6. Watch the Xcode console for Swift concurrency runtime warnings (none expected).

### Risks

- **The app must actually be producing audio** through `AVAudioEngine` (engine running, player node playing a file) for macOS to designate it the Now Playing app; setting `nowPlayingInfo` alone does nothing visible. Verify #0002's playback is audible before debugging the bridge.
- **Music.app steals media keys** if it was the most recent Now Playing app. Quit Music, start SkinAmp playback, and retry. If F8 types a character instead, the keyboard is set to "Use F1, F2… as standard function keys" — use `fn`+F8.
- **No Info.plist key is required on macOS** (`UIBackgroundModes` is iOS-only); no entitlement is needed for MediaPlayer with the sandbox off. Do not add either.
- **`MPNowPlayingSession` is iOS/tvOS-only**; the macOS API surface is `MPNowPlayingInfoCenter` + `MPRemoteCommandCenter` only.
- **Swift 6 strict concurrency**: the two traps are the non-`Sendable` `MPRemoteCommandEvent` (extract values before `Task { @MainActor in }`) and `NSImage` in the artwork request handler (capture `Data`). Keep `MediaPlayer` use confined to the `@MainActor` bridge.
- **FLAC**: AVFoundation decodes FLAC but may not surface its picture block as `commonIdentifierArtwork`; acceptable — art is "when available".
- **Gapless auto-advance (#0003)** must emit `trackChanged` through the same event path, or Control Center will show the previous track after the queue advances on its own. Note this in `## Gotchas` if #0003 is not done yet.

## Root cause

Nothing published player state to the system or listened for remote commands, so macOS had no Now Playing app and the media keys did not reach SkinAmp.

## Fix

New `AudioCore/NowPlaying/`: `NowPlayingSnapshot` + pure `NowPlayingInfoBuilder` (title, artist, album when non-nil, duration, elapsed, rate 1/0, default rate, media type audio), `EmbeddedArtworkLoader` (AVURLAsset common metadata, returns `Data`), and the `@MainActor` `NowPlayingBridge`. The bridge registers play, pause, togglePlayPause, stop, next, previous and changePlaybackPosition on `MPRemoteCommandCenter`, disables seek/skip forward/backward, and removes its targets in `uninstall()`. Each handler maps the non-Sendable event to a `Sendable` `NowPlayingCommand` before `Task { @MainActor in ... }` (no `assumeIsolated`). It sets `nowPlayingInfo` then `playbackState`, and clears both when the player is stopped or has no track (info is kept while paused). `PlayerModel` creates and installs the bridge.

Deviations from the plan, because the Player already existed:
- No `AsyncStream<PlayerEvent>`. `Player` has `public var onEvent: (@MainActor (PlayerEvent) -> Void)?` (single observer), fired from `didSet` on `state` and on `queue` (when `queue.current?.id` changes) and after a `seek`. Gapless auto-advance (#0003) changes `queue` in `segmentFinished`, so it updates Now Playing with no extra code. `didSet` that only calls out (never reassigns) is safe under `@Observable`.
- The bridge rebuilds the whole dictionary from `player.state` / `queue.current` / `currentTime` on every event instead of patching a copy; it is cheap, and elapsed is read at event time (0 progress is not stale because `begin()` sets `currentTime = 0` before `state = .playing`). It publishes nothing per tick.
- `NowPlayingCommandTarget` exists as planned; `Player` conforms (added `togglePlayPause()` forwarding to `togglePause()`). `Track` gained `album: String?` (default nil); nothing fills it yet (local files use the file name as title and no tags).
- Routing is tested through `NowPlayingBridge.perform(_:on:)` (internal), not by firing the real command center.
- Artwork provider is injectable (`Track` to `Data?`, default reads local files only) so Plex art can come from the app later; AudioCore knows nothing of Plex.

## Gotchas

- `MPMediaItemArtwork`'s request handler is called by MediaPlayer on its own queue. A closure created inside a `@MainActor` method inherits main-actor isolation and traps (SIGTRAP, "signal code 5") the moment the info is published with artwork. `makeArtwork` is `nonisolated static` and the closure `@Sendable`; this only showed up in the test that attaches artwork.
- `MPNowPlayingInfoCenter` is process-wide, so parallel tests that install a bridge race each other (one failure in the first full run). Those tests live in one `.serialized` suite (`NowPlayingInfoCenterTests`).
- `Player.pause()` calls `playerTimeForNodeTime`, which throws an NSException when the engine is in offline manual-rendering mode and is not being rendered; the bridge tests therefore use the real output device with `volume = 0`.
- `Player.onEvent` is a single observer slot; if another consumer (e.g. the UI) needs events, turn it into a list or a stream.
- Local tracks have no tags yet, so Control Center shows the file name as title and an empty artist until a metadata issue fills `Track.title/artist/album`.
- Music.app may take the media keys if it was last to play; quit it when testing.

## Review notes

Reviewed 2026-10-12 (Opus) against c87cfc1. **Bounced**: one correctness bug in the acceptance path, and the test that should catch it is flaky.

What passed: `xcodegen generate` (no diff), `xcodebuild ... Debug ... build` (BUILD SUCCEEDED, no warnings), SkinKit 5/5. Command handlers are registered once (guarded by `installed`), map the non-Sendable event to `NowPlayingCommand` before `Task { @MainActor in }`, return `.commandFailed` for an unmappable event, and are removed in `uninstall()`; seek/skip ±15 s are disabled. `makeArtwork` is `nonisolated static` with a `@Sendable` handler capturing `Data` - correct. Artwork is loaded once per current track (`artworkRequestedFor`) and reused across play/pause/stop/play. `queue`'s `didSet` fires on every queue mutation (enqueue, shuffle, remove, in-place `mutating` calls) but `emitTrackChangeIfNeeded` dedupes by track id, so enqueue does not republish; the `didSet`s only call out, no recursion. Info is cleared on stop and on an empty queue; kept while paused. The app builds tracks with `LocalTrackLoader`, so title/artist from tags *are* used (the Gotcha "local tracks have no tags yet" is wrong - only `album` is unfilled).

**Must fix**

1. **Stale elapsed after gapless auto-advance.** In `Player.segmentFinished(.advanced)` the queue advances (its `didSet` fires `trackChanged`, and the bridge publishes reading `player.currentTime`) *before* `currentTime = 0`, and `state` does not change, so nothing republishes. Control Center then shows the new track with the previous track's end time as elapsed and extrapolates from there for the whole track. Reproduced in the scratch harness (3 s track A, 6 s track B, artwork `nil`): after the advance `nowPlayingInfo` had title `B`, elapsed `2.9067`, rate 1 while `player.currentTime` was `0.43`; one second later still `2.9067`. Fix either side, ideally both: in `segmentFinished` set `currentTime = 0` (and `file`) before `queue.advanceAfterTrackEnd()` mutates the queue, or emit a seek/position event after it; and/or have the bridge publish elapsed `0` on `.trackChanged` instead of reading `currentTime`. The same ordering gives a brief stale elapsed on `next()`/`previous()`/`play(at:)` while playing (harness: title `C`, elapsed `1.464` until `begin()` republishes) - publishing `0` on `trackChanged` fixes that too.
2. **`autoAdvanceUpdatesInfoCenterAndAttachesArtwork` is flaky (fails ~50%) because of bug 1.** Full-suite runs: 2 of 3 passed; `--filter NowPlayingInfoCenterTests` ×6: 3 failed, all at `NowPlayingTests.swift:171` (`elapsed < 0.5`). The 0.5 s test files make the stale value sometimes < 0.5, so it only passes by luck. After the fix, make the test deterministic: use files of a few seconds (`MixedFormatSupport.writeSine(..., seconds: 2)`) and, after the title becomes `second`, assert elapsed < 0.5 with `artwork: { _ in nil }` (the artwork republish can mask the bug), then re-run the suite at least 5× green.

**Should fix (same pass, small)**

3. `LocalTrackLoader` reads title/artist but not album: add `commonIdentifierAlbumName` -> `Track.album` so Control Center shows it. Correct the Gotcha about tags.
4. `Player.onEvent` is a single slot that `NowPlayingBridge.install()` overwrites and `uninstall()` nils, so the first other consumer (#0041 loading state, #0013 prefetch, M4 UI) silently disconnects Now Playing. Either make it multi-observer now (e.g. `addEventObserver(_:) -> token` / `removeEventObserver`) or file a follow-up issue linked from #0013/#0041; the current Gotcha alone is easy to miss.

Hand checks still owed after the fix (user): F8/next/previous media keys with another app frontmost, Control Center title/artist/album/cover and moving position, scrubbing, entry disappears on stop and stays on pause, no concurrency warnings in the console.
