## Description

Index a folder of `.wsz` files in the background into SQLite: content hash, name, readme text, parse status and warnings, with de-duplication by hash.

## Acceptance criteria

- 100k skins index without blocking the UI.
- Re-index only changed files.

## Plan

### Scope and decisions

This issue adds a `SkinLibrary` target to `Packages/SkinKit`, a Skins tab in Settings that points at a folder and shows the index state, and an `index` subcommand in `skintool`. It writes no thumbnails (#0034), no browser, no search UI, no Skins menu and no "apply skin from the index" (#0035), and no Quick Look (#0043). The read API it exposes (`skins(...)`, `search(...)`, `randomSkin()`, counts) is what #0035 builds on, and the content hash it stores is the key #0034 names its thumbnails by.

- **The folder is a setting, never a path in code.** The 19 sample skins currently live in `untitled folder/` at the repo root; nothing renames, moves or references that folder. The app reads the folder from `UserDefaults` (`skinsFolderPath`, set in Settings › Skins with a directory `NSOpenPanel`), `skintool index <folder>` takes it as an argument, and tests use temp directories. With no folder set the app opens no database and does no I/O at launch.
- **New target `SkinLibrary` in `Packages/SkinKit`, not code inside `SkinKit`.** `SkinKit` stays "UI-free parsing": no SQLite, no folders, no persistence. `SkinLibrary` depends on `SkinKit` (and `CryptoKit`, `SQLite3` from the SDK). It lives in the SkinKit package rather than PlayerKit because it is about skins and must not drag AudioCore or PlexKit in. `scripts/run-tests-vm.sh` needs no change: `swift test --package-path Packages/SkinKit` runs every test target in the package.
- **System SQLite through a thin wrapper, no third-party dependency.** `import SQLite3` (the SDK module over `libsqlite3.dylib`) behind an internal `SQLiteDatabase` class of about 150 lines: open/close, `execute`, a prepared `Statement` with bind/step/column accessors, `transaction { }`, cached statements for the hot paths. GRDB or SQLite.swift would add a large dependency, their own SQLite build and version-pinning policy, and Swift 6 concurrency annotations we do not control, for a schema of three tables. The FTS5 virtual table is part of the schema now so #0035's search is a query, not a migration; Apple's `libsqlite3` ships FTS5, and a test asserts `PRAGMA compile_options` lists `ENABLE_FTS5` so the assumption fails loudly, not at runtime.
- **One connection, owned by an actor.** `SkinIndexStore` is an actor that owns the `SQLiteDatabase` (created inside the actor's `init`, never passed out: `OpaquePointer` is not `Sendable`). WAL mode, `synchronous=NORMAL`, `foreign_keys=ON`, `busy_timeout=5000`. Every read and write from the indexer, the app and the CLI goes through the actor, so SQLite's threading mode never matters. A second read-only connection for the browser is a later option if #0035 measures contention; it is not needed for 100k rows.
- **Content hash = SHA-256 of the file bytes**, hex-encoded, over the whole `.wsz`. It is cheap (CryptoKit, ~1 GB/s), stable across parser versions, and defined even for archives the parser rejects, so a `failed` row has a key too. Two files with the same bytes are one skin. A re-zipped copy of the same skin (different bytes, same entries) is not de-duplicated by this issue; hashing the sorted entry contents is a documented follow-up (section 11).
- **Change detection = size + modification time.** The `files` table stores each file's relative path, size and `mtime` as reported by `FileManager`. A pass lists the folder, compares with the table, and touches only new, changed (size or mtime differ) and missing files; unchanged files cost one `stat` and nothing else. A `parser_version` stored per skin forces a re-parse of everything when the parser changes (new warnings, new fallbacks) without re-hashing being avoidable: changed detection and parser bumps both route through the same "ingest" path. "Rescan everything" in Settings ignores the stamps and re-hashes every file; only hashes that changed are re-parsed.
- **Hash first, parse only unknown hashes.** The indexer hashes the changed files in parallel, asks the store which hashes it already has, links the known ones (new `files` row, no parse) and parses only the unknown ones, once per hash even when several new files share it. This is what makes duplicate-heavy corpora (the Internet Archive collection has many) and "same bytes, new mtime" cheap.
- **Off the main actor, in bounded batches, cancellable at batch boundaries.** `SkinIndexer` is an actor; the pass runs in a `Task(priority: .utility)`. Per batch of 64 changed files it hashes and parses in a task group bounded to `max(1, activeProcessorCount - 1)` workers, then applies the batch to the store in one transaction. Progress is delivered through a `@Sendable` callback at most every 250 ms. `Task.checkCancellation()` between batches; a cancelled pass keeps every committed batch, so the next pass resumes from the stamps. The main actor only ever `await`s the store or receives progress values; the only skin-parsing work on main today (`PlayerModel.loadSkin`) is unchanged.
- **Status mirrors `skintool`:** `ok` (no warnings), `partial` (warnings), `failed` (a `SkinError`, or an I/O error reading the file; the reason is stored in `warnings`). A `failed` row is not retried until the file's stamp changes or the parser version bumps.
- **Readme extraction is a heuristic over the archive's `.txt`/`.nfo` entries**, decided from the sample corpus: `readme.txt` / `Readme.txt` at the root or in a subfolder, `MatrixCode.txt`, `winampmb.txt` (not a readme), `PLEDIT_EXAMPLE.TXT` (not a readme), and skins with no text at all. Rule: candidates are entries whose base name ends in `.txt` or `.nfo` and is not one of `pledit.txt`, `viscolor.txt`, `region.txt`, `winampmb.txt`, `pledit_example.txt`, `mb.ini`; prefer a base name containing `readme` (then `read me`, `read_me`), otherwise the largest candidate; decode UTF-8, falling back to Windows-1252 (never fails); strip NULs, normalize CRLF to LF, trim, cap at 64 KiB. No candidate means `readme IS NULL`.
- **The database lives in Application Support**, `~/Library/Application Support/com.brennanmke.SkinAmp/SkinLibrary/index.sqlite` (`SkinIndexStore.defaultURL`), not Caches: an index of 100k skins is minutes of work and must not be purged by the system. `skintool index` writes the same file unless `--db` says otherwise, so a CLI index is what the app browses. Paths in `files` are relative to the folder, so moving the folder and pointing Settings at the new location re-indexes nothing.
- **Verification is `scripts/run-tests-vm.sh --launch` only.** No `swift test`, `swift run`, `xcodebuild` or app launch on the host. The sample corpus never reaches the guest (`*.wsz` is gitignored and the export is `git ls-files -co --exclude-standard`), so every test builds its own skins: tiny real `.wsz` archives for behaviour, and 100,000 stub files with a stub ingester for scale (section 9).

### 3. `SQLiteDatabase` (`SQLite/SQLiteDatabase.swift`, internal)

- `init(url: URL) throws`: `sqlite3_open_v2(path, &db, SQLITE_OPEN_READWRITE | SQLITE_OPEN_CREATE, nil)`, then `PRAGMA journal_mode=WAL; synchronous=NORMAL; foreign_keys=ON; temp_store=MEMORY; busy_timeout=5000`. `deinit` finalizes cached statements and `sqlite3_close_v2`.
- `execute(_ sql: String) throws` for DDL and pragmas (`sqlite3_exec`).
- `statement(_ sql: String) throws -> Statement` returns a cached prepared statement (reset + clear bindings on hand-out). `Statement.bind(_:at:)` overloads for `Int64`, `Double`, `String`, `String?`; `step() throws -> Bool` (`SQLITE_ROW` → true, `SQLITE_DONE` → false, else throw); `int64(_:)`, `double(_:)`, `string(_:)`, `optionalString(_:)`; `reset()`.
- `transaction<T>(_ body: () throws -> T) throws -> T`: `BEGIN IMMEDIATE` / `COMMIT`, `ROLLBACK` on throw.
- `let SQLITE_TRANSIENT = unsafeBitCast(-1, to: sqlite3_destructor_type.self)` at file scope (the macro does not import); every `sqlite3_bind_text` uses it.
- `userVersion: Int32` get/set over `PRAGMA user_version`.
- Errors carry `sqlite3_errcode` and `sqlite3_errmsg`; never the SQL with a bound value.

### 4. `SkinIndexStore` (actor)

Schema, applied in `migrate()` from `user_version` 0 → 1 inside one transaction (future versions append to a `[Int32: [String]]` list; a DB whose version is above `schemaVersion` throws `.incompatibleDatabase`, and the Settings model offers Reset):

```sql
CREATE TABLE skins (
  id              INTEGER PRIMARY KEY,
  hash            TEXT    NOT NULL UNIQUE,
  name            TEXT    NOT NULL,
  readme          TEXT,
  status          TEXT    NOT NULL,              -- ok | partial | failed
  warnings        TEXT    NOT NULL DEFAULT '',   -- '\n'-joined
  size            INTEGER NOT NULL,
  parser_version  INTEGER NOT NULL,
  first_indexed   REAL    NOT NULL
);
CREATE TABLE files (
  path    TEXT    PRIMARY KEY,                   -- relative to the folder
  size    INTEGER NOT NULL,
  mtime   REAL    NOT NULL,
  skin_id INTEGER NOT NULL REFERENCES skins(id) ON DELETE CASCADE
);
CREATE INDEX files_skin ON files(skin_id);
CREATE INDEX skins_status ON skins(status);
CREATE INDEX skins_name ON skins(name COLLATE NOCASE);
CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);   -- folder, last_scan, last_summary
CREATE VIRTUAL TABLE skins_fts USING fts5(name, readme, content='skins', content_rowid='id', tokenize='unicode61 remove_diacritics 2');
CREATE TRIGGER skins_ai AFTER INSERT ON skins BEGIN INSERT INTO skins_fts(rowid, name, readme) VALUES (new.id, new.name, new.readme); END;
CREATE TRIGGER skins_ad AFTER DELETE ON skins BEGIN INSERT INTO skins_fts(skins_fts, rowid, name, readme) VALUES ('delete', old.id, old.name, old.readme); END;
CREATE TRIGGER skins_au AFTER UPDATE OF name, readme ON skins BEGIN
  INSERT INTO skins_fts(skins_fts, rowid, name, readme) VALUES ('delete', old.id, old.name, old.readme);
  INSERT INTO skins_fts(rowid, name, readme) VALUES (new.id, new.name, new.readme);
END;
```

API (all `async` by virtue of the actor; each method is one statement or one transaction):

- `static func open(at url: URL) async throws -> SkinIndexStore` (creates the directory, migrates); `static var defaultURL: URL`.
- `fileStamps() throws -> [String: (stamp: FileStamp, parserVersion: Int)]` — the whole `files ⋈ skins` table as a dictionary; 100k rows is a few MB and one pass over a `SELECT`.
- `skinIDs(forHashes: [String]) throws -> [String: Int64]` — chunked `IN (?,?,…)` of 500.
- `apply(_ batch: [IngestOutcome]) throws -> AppliedCounts` — one transaction. Sorted by path before applying so the skin created by the lexicographically first file names the skin. For `.parsed`: `INSERT INTO skins … ON CONFLICT(hash) DO UPDATE SET status, warnings, readme, parser_version` (a parser bump re-parses and updates in place; `name` and `first_indexed` are kept); for `.linked(hash)`: look up the id; both then `INSERT OR REPLACE INTO files(path, size, mtime, skin_id)`. A replaced `files` row that pointed elsewhere leaves a possibly orphaned skin, pruned at the end of the pass.
- `removeFiles(_ paths: [String]) throws -> Int` — one transaction, prepared `DELETE` in a loop.
- `pruneOrphans() throws -> Int` — `DELETE FROM skins WHERE id NOT IN (SELECT skin_id FROM files)`; the trigger keeps the FTS in step.
- `checkpoint()` — `PRAGMA wal_checkpoint(TRUNCATE)` after a pass so the WAL does not stay at the size of the biggest batch.
- Reads: `counts() -> (files: Int, skins: Int, byStatus: [SkinStatus: Int])`; `skins(status: SkinStatus? = nil, limit: Int = 200, offset: Int = 0) -> [SkinRecord]` (ordered by `name COLLATE NOCASE, id`); `search(_ text: String, status: SkinStatus? = nil, limit: Int = 200) -> [SkinRecord]` (`skins_fts MATCH ?` ordered by `bm25(skins_fts)`; the query is built as one quoted prefix token per whitespace-separated word, `"` doubled, so user punctuation can never make FTS throw); `skin(id:)`, `skin(hash:)`; `files(forSkin: Int64) -> [FileStamp]`; `randomSkin(status:) -> SkinRecord?` (`ORDER BY random() LIMIT 1` on the ids, then fetch, fine at 100k). `SkinRecord` rows come from one `SELECT … LEFT JOIN (SELECT skin_id, COUNT(*), MIN(path) FROM files GROUP BY skin_id)`.
- `meta(_ key:) -> String?`, `setMeta(_:_:)`.
- `reset() throws` — drops every table and migrates again (Settings › Reset Index, and a schema too new).

`IngestOutcome` (internal, `Sendable`): `.parsed(stamp: FileStamp, hash: String, name: String, readme: String?, status: SkinStatus, warnings: [String], parserVersion: Int)` or `.linked(stamp: FileStamp, hash: String)`.

### 5. `FolderScanner`

`static func list(folder: URL) throws -> [FileStamp]`. Root = `folder.standardizedFileURL.resolvingSymlinksInPath()`. `FileManager.enumerator(at:includingPropertiesForKeys: [.isRegularFileKey, .fileSizeKey, .contentModificationDateKey], options: [.skipsHiddenFiles, .skipsPackageDescendants])` — regular files whose extension lowercases to `wsz` (an `extensions` parameter defaults to `["wsz"]`; the CLI may pass `["wsz", "zip"]` like the report mode does). Relative path = the enumerated URL's `path` with the root prefix and separator dropped. A missing or unreadable folder throws `.folderUnreadable`. The enumerator does not follow symlinked directories, so a link loop cannot hang the pass. Sorted by path on return, so batches and names are deterministic.

### 6. `SkinReadme` and `SkinIngester`

```swift
public protocol SkinIngesting: Sendable {
    /// Cheap: reads the file, returns its content hash. I/O errors throw.
    func hash(_ url: URL) throws -> String
    /// Expensive: parses the archive. Never throws; a rejected skin is a `.failed` inspection.
    func inspect(_ url: URL) -> SkinInspection
}
public struct SkinInspection: Hashable, Sendable {
    public var readme: String?; public var status: SkinStatus; public var warnings: [String]
}
public struct SkinIngester: SkinIngesting {
    public static let parserVersion = 1          // bump when SkinParser's output changes
    public init() {}
}
```

`hash`: `Data(contentsOf: url, options: .mappedIfSafe)` → `SHA256.hash(data:)` → lowercase hex. `inspect`: `SkinArchive(url:)` then `SkinParser.parse(archive:)`; `ok`/`partial` from `warnings.isEmpty`; a thrown `SkinError` → `.failed` with `[error.description]`; readme from `SkinReadme.extract(from: archive)` even when parsing failed (a modern skin may still have a readme). The parsed `Skin` is dropped immediately; only its warnings survive, so a batch of 64 holds at most `concurrency` decoded sheet sets at a time. `SkinArchive` lowercases base names and drops directories, which is exactly what the readme rule needs.

`SkinReadme.extract(from: SkinArchive) -> String?` as decided above; `decode(_ data: Data) -> String` tries UTF-8 then `String(data:encoding:.windowsCP1252)`.

### 7. `SkinIndexer` (actor)

```swift
public actor SkinIndexer {
    public init(folder: URL, store: SkinIndexStore, ingester: any SkinIngesting = SkinIngester(),
                parserVersion: Int = SkinIngester.parserVersion,
                concurrency: Int = max(1, ProcessInfo.processInfo.activeProcessorCount - 1),
                batchSize: Int = 64)
    /// One pass. Throws `.passAlreadyRunning` if one is in flight. `full` ignores the stamps.
    public func run(full: Bool = false, progress: (@Sendable (SkinIndexProgress) -> Void)? = nil) async throws -> SkinIndexSummary
    public func cancel()
    public var isRunning: Bool
}
```

The pass:

1. `scanning`: `FolderScanner.list(folder:)` (synchronous inside the actor; ~1–2 s for 100k on APFS) and `store.fileStamps()`. Changed = on disk and (not in the table, or stamp differs, or `parserVersion` differs, or `full`). Missing = in the table, not on disk. Emit progress with `changed` and `totalFiles`.
2. `store.removeFiles(missing)`.
3. `indexing`, per batch of `batchSize` changed stamps in path order: task group bounded to `concurrency` computing `hash`; an I/O failure becomes a `.parsed` outcome with `status: .failed`, `hash` = SHA-256 of the path string prefixed `unreadable:` (so the row is stable and does not collide with real content), `warnings: [reason]`. Then `store.skinIDs(forHashes:)`; outcomes whose hash is known become `.linked`; the rest are de-duplicated by hash within the batch, inspected in a second bounded task group (one inspection per distinct hash, its result copied to every file sharing the hash), and `store.apply(batch)`. `Task.checkCancellation()` before each batch; progress after each.
4. `pruning`: `store.pruneOrphans()`, `setMeta("last_scan", ISO-8601 now)`, `setMeta("folder", path)`, `checkpoint()`.
5. Return the summary; on `CancellationError` return a summary with `cancelled: true` after step 4 runs for what was committed (prune is still correct: every committed batch is self-consistent).

`cancel()` sets a flag checked with `Task.checkCancellation()` at the batch boundary (the running `Task` is also stored so `cancel()` cancels it). Logging through `os.Logger(subsystem: "com.brennanmke.SkinAmp", category: "SkinLibrary")`: one `info` line per pass with the summary, `debug` per batch, file names only ever at `.private`.

### 9. Tests (`Packages/SkinKit/Tests/SkinLibraryTests/`, Swift Testing)

House rules: temp directories under `FileManager.default.temporaryDirectory/<uuid>` removed in `defer`; no fixed sleeps; every test builds its own data because the guest has no `.wsz` files. `TestSupport.swift` provides:

- `SyntheticSkins.write(to url: URL, sheets: [String] = SkinSprites.sheets.keys.sorted(), readme: String? = "readme", visColors: Bool = true, extra: [String: Data] = [:])` — a real `.wsz` through ZIPFoundation's `Archive(url:accessMode:.create)` with a 2×2 24-bit BMP (`tinyBMP()`: 54-byte header + 16 bytes of pixel rows, built by hand) per sheet, a 24-line `viscolor.txt`, and the readme as `readme.txt` (or under the names a test asks for). `.modern()` writes `skin.xml` only; `.garbage()` writes 100 random bytes. These parse through the real `SkinParser` in a few hundred microseconds each.
- `StubIngester: SkinIngesting` with counters (`hashes`, `inspections`, atomically via a lock) and a `hash` derived from the path (`"stub:" + path`) or from a per-path override, `inspect` returning a canned inspection; optional `delayPerFile` and a `recordThread` flag.
- `makeStore()` → `SkinIndexStore.open(at: temp/index.sqlite)`; `touch(url, mtime:)` sets `.modificationDate`; `waitFor` is not needed (everything is awaited).

Suites and tests:

- `SQLiteDatabaseTests`: `opensWithWALAndForeignKeys` (`PRAGMA journal_mode` → `wal`, `foreign_keys` → 1); `fts5IsCompiledIn` (`PRAGMA compile_options` contains `ENABLE_FTS5`); `transactionRollsBackOnThrow`; `bindsAndReadsEveryType` (Int64, Double, String with a `'` and `"`, NULL); `errorsCarryCodeAndMessage` (bad SQL → `.sqlite(code: SQLITE_ERROR, …)`).

### 12. Risks and gotchas

- **FTS5 in the system SQLite.** Apple's `libsqlite3` has shipped FTS5 for years, and `fts5IsCompiledIn` proves it in the guest. If it ever fails, the fallback is `LIKE` over `name`/`readme` behind the same `search` signature; the schema would drop the virtual table and triggers in a version-2 migration.
- **`SQLITE_TRANSIENT` and string lifetimes.** Binding with the `-1` destructor copies the bytes; binding with `nil` (static) over a Swift `String` is a use-after-free that only shows up under load. Every text bind uses `SQLITE_TRANSIENT`.
- **Swift 6 and the C API.** `OpaquePointer` is not `Sendable`: the database and statements never leave the store actor, and the actor's `init` creates them. `sqlite3_column_text` returns `UnsafePointer<UInt8>?`; wrap with `String(cString:)` only after a nil check. The `SQLite3` module needs `linkerSettings: [.linkedLibrary("sqlite3")]` in SwiftPM.
- **Modification-time granularity.** APFS stores nanoseconds but a copy tool may truncate to seconds; a file rewritten within the same second with the same size is missed by the stamp. `Rescan All` exists for that, and a parser bump re-ingests regardless. Compare `mtime` as the exact `Double` that went in (REAL round-trips a double), not with a tolerance.
- **Memory while indexing.** Each inspection decodes every sheet of one skin into `CGImage`s; with `concurrency` ≤ cores − 1 and the `Skin` dropped right after, the peak is a few tens of MB. Do not keep `Skin` values in the batch. Mapped `Data` for hashing is released per file.
- **The 100k scale test's cost.** Creating and deleting 100,000 files in the guest takes seconds each and the whole test well under a minute on an SSD; the time limit guards a slow volume. Keep the stub ingester free of I/O so the test measures the scanner and the store, not the stub.
- **Parallel tests share a temp root.** Every suite makes its own UUID directory; never use the default `SkinIndexStore.defaultURL` from a test (it is the user's real index on the host if a test is ever mistakenly run there, and the guest's Application Support in the VM).
- **Path encoding.** Store the relative path exactly as the enumerator gives it (no Unicode normalization); the same enumerator produces the next pass's paths, so comparison is byte-stable. Resolve symlinks only on the root.
- **Progress callbacks run on the indexer's executor.** The model must hop to main (`Task { @MainActor in … }`); never touch `@Observable` state in the callback directly. Throttling at 250 ms keeps the Settings view from re-rendering per file.
- **Keep the index out of Caches and out of the skins folder.** Writing `index.sqlite` into the user's folder would make the scanner's listing see it (it filters by extension, but still) and would pollute a read-only or synced folder.
- **De-duplication is byte-level.** Re-zipped copies of one skin are two rows; a content-level hash (sorted entry names + bytes) is a later `parser_version`-style bump if the corpus shows it matters.
- **Sandboxing.** The app is unsandboxed (`ENABLE_APP_SANDBOX: NO`), so a plain path works. If the sandbox is ever enabled, `skinsFolderPath` becomes a security-scoped bookmark; note it next to the existing comment in `project.yml` rather than building it now.

## Root cause

There was no index: nothing listed, hashed or parsed a folder of `.wsz` files ahead of time, so there was no stored name, readme, parse status or de-duplication by content, and nothing for the thumbnail cache (#0034) or the browser (#0035) to build on.

## Fix

Followed the plan: a new `SkinLibrary` target in `Packages/SkinKit` (system `SQLite3`, no new dependency) with `SQLiteDatabase`, the `SkinIndexStore` actor (schema v1, FTS5 with triggers, `skins(status:limit:offset:)`, `search`, `skin(id:)`/`skin(hash:)`, `files(forSkin:)`, `randomSkin`, `counts`, `meta`, `reset`), `FolderScanner`, `SkinReadme`, `SkinIngesting`/`SkinIngester`, and the `SkinIndexer` actor. `skintool index <folder> [--db] [--full]`, `SkinLibraryModel` and a Skins tab in Settings (alongside the new Library tab) complete it. The folder is the `skinsFolderPath` default; nothing names `untitled folder/`.

Adaptations and divergences from the plan:
- `SkinContentHash` (`hex(of: URL)`, `hex(of: Data)`, `isValid`) exists as its own file as #0034 specified; `SkinIngester.hash` calls it, so there is one hash function.
- `IngestOutcome`, `AppliedCounts`, `apply`, `fileStamps`, `removeFiles`, `pruneOrphans` and `checkpoint` are internal (tests use `@testable import`). Added internal `knownSkinIDs(forHashes:parserVersion:)`: a hash only counts as known when its stored parser version is at least the current one, which is what makes a parser bump re-parse each distinct hash once; public `skinIDs(forHashes:)` is the version-agnostic form.
- `updated` means "a path that was already indexed was ingested again" (including same-hash touch); `added` is a new path with a new skin; `linked` is a new path whose skin already existed. That is the classification the plan's tests assert.
- `SkinIndexer.cancel()` is `nonisolated` (a lock-protected flag) so it can be called synchronously from the progress callback and from the main actor; `init` gained `progressInterval` (default 250 ms) so tests can receive every progress value. The folder listing runs in a detached utility task so the indexer actor stays responsive.
- Folder scanner accepts either spelling of the root (`resolvingSymlinksInPath` drops `/private`, the enumerator reports it); the first VM run caught this (scanner returned nothing for temp dirs).
- Search drops words with no letter or digit (so `"` or `*` return `[]`) and quotes the rest as prefix tokens. `SkinsSettingsView` and `SkinLibraryModel` also expose `openStoreIfNeeded()`, `folderURL` and `passFinished` for #0035 (additive).
- `SkinReadme` prefers a name containing `readme` (then `read me`, `read_me`), else the largest candidate, with ties broken by name. The plan's FTS5 and `StubIngester` keys: the stub keys by the last two path components, so tests use `dNNN/NNNNN.wsz` names.
- The 100k tests keep 100,000 (no downgrade to 50k was needed).
