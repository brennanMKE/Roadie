# 0002 — AudioCore has no AVAudioEngine playback graph

## Description

Create `Packages/PlayerKit` with an `AudioCore` library: `Track`, a play queue, and an `AVAudioPlayerNode` → `AVAudioUnitEQ` → main mixer graph with play, pause, stop, seek, volume and balance.

## Acceptance criteria

- `Track` holds title, artist, duration, optional bitrate / sample rate / channels, and a source (file URL, or Plex part + cache key).
- Seek stops the node and schedules a segment from the target frame.
- Balance maps to the player node's `pan`; volume to the mixer.
- PlayerKit is added to `project.yml` and the app's transport buttons drive it.
- Unit tests cover queue navigation (next, previous, repeat, shuffle).

## Plan

Scope: the package, the value types, the queue, a working single-file player with seek/volume/balance, app wiring, and queue tests. Gapless (0003), EQ bands (0004), analyzer (0005), file metadata/open panel (0006) and Now Playing (0007) are **not** implemented here, but the seams below are shaped for them.

### 2. Public types

```swift
public struct Track: Identifiable, Hashable, Sendable {
    public enum Source: Hashable, Sendable {
        case file(URL)
        case plex(partKey: String, cacheKey: String)   // resolved to a file by TrackCache (M2)
    }
    public let id: UUID            // per queue entry, so the same file can be queued twice
    public var title: String
    public var artist: String
    public var duration: TimeInterval
    public var bitrate: Int?       // kbps
    public var sampleRate: Double? // Hz
    public var channels: Int?
    public var source: Source
    public init(id: UUID = UUID(), title:, artist:, duration:, bitrate: = nil, sampleRate: = nil, channels: = nil, source:)
}

extension Track {
    /// Minimal local-file constructor: title = file name, artist = "", duration/sampleRate/channels
    /// from AVAudioFile. 0006 replaces the metadata part with AVAsset tag reading; keep the signature.
    public static func file(at url: URL) throws -> Track
}
```

```swift
public enum RepeatMode: Sendable, CaseIterable { case off, all, one }

public struct PlayQueue: Equatable, Sendable {
    public private(set) var tracks: [Track]
    public private(set) var currentIndex: Int?
    public var repeatMode: RepeatMode = .off
    public private(set) var isShuffled = false
    public var current: Track? { currentIndex.map { tracks[$0] } }

    public init(tracks: [Track] = [])
    public mutating func append(_ new: [Track])
    public mutating func remove(at index: Int)
    public mutating func removeAll()
    public mutating func select(_ index: Int)                 // user picked a row; sets currentIndex
    @discardableResult public mutating func next() -> Track?      // user pressed Next
    @discardableResult public mutating func previous() -> Track?  // user pressed Previous
    @discardableResult public mutating func advanceAfterTrackEnd() -> Track?  // track finished naturally
    public func indexAfterCurrentEnds() -> Int?              // pure peek used by 0003 to pre-schedule
    public mutating func setShuffle<G: RandomNumberGenerator>(_ on: Bool, using rng: inout G)
    public mutating func setShuffle(_ on: Bool)               // uses SystemRandomNumberGenerator
}
```

Queue semantics to implement exactly (these are what the tests pin down):

- `next()` / `previous()` return the new current track, or `nil` and leave `currentIndex` unchanged when there is nowhere to go. `repeatMode == .all` wraps at both ends; `.off` and `.one` do not wrap on user presses (`.one` only affects natural track end, like Winamp's "repeat one").
- `advanceAfterTrackEnd()`: `.one` → returns the same track; `.all` → next with wrap; `.off` → next, or `nil` at the end (the player then stops). `indexAfterCurrentEnds()` is the same decision without mutating; `advanceAfterTrackEnd` must be implemented in terms of it so the two can never disagree.
- Shuffle is an ordering, not a reshuffle per press: `private var shuffleOrder: [Int]` (a permutation of `tracks.indices`) and `private var shufflePosition: Int`. Turning shuffle on moves the current index to the front of the order, so Previous walks back through what was actually played. Reaching the end of the order with `.all` reshuffles and continues; with `.off`, `next()` returns `nil`. Turning shuffle off keeps `currentIndex` where it is.
- Mutation keeps the order consistent: `append` shuffles the new indices into the unplayed remainder of `shuffleOrder` (new tracks must come up before the order is exhausted); `remove(at:)` drops that index from the order and decrements larger ones, and fixes `currentIndex` (removing the current track makes the next one current, or `nil` if the queue is empty). Reordering (`move`) is deferred to the playlist window (M5).
- `select` on an empty or out-of-range index is a no-op.

### 3. Engine and controller

`AudioGraph` (`@MainActor final class`, internal) owns the AVFoundation objects, all of which are non-`Sendable`:

- `engine: AVAudioEngine`, `playerNode: AVAudioPlayerNode`, `eq: AVAudioUnitEQ(numberOfBands: 10)`. Attach both, connect `playerNode → eq → engine.mainMixerNode` (the mixer → output connection is implicit). For this issue set `eq.bypass = true` and leave the bands untouched; 0004 configures frequencies/gains/`globalGain` on the same instance. Expose `eq` and `mainMixerNode` so 0004 and 0005 (its tap) do not need to open the class up again.
- `connect(format: AVAudioFormat)`: reconnect `player → eq → mixer` with the file's `processingFormat` when the sample rate or channel count differs from the current connection format. Only ever call it while `playerNode` is stopped. Keep a `connectedFormat` so the common case (same format) does nothing — 0003 can only pre-schedule gaplessly when the next file's format matches, and this is where it checks.
- `start()`: `engine.prepare()` then `try engine.start()` lazily on the first play; rethrow as `AudioCoreError.engineStart(underlying:)`. Leave the engine running across stop/pause (cheap, avoids restart glitches).
- `volume: Float` (0…1) → `engine.mainMixerNode.outputVolume`; `balance: Float` (−1…1) → `playerNode.pan`. Clamp both. Winamp sliders map linearly: volume 0–100 → 0…1, balance −100…100 → −1…1 (a loudness curve can come later with the skin sliders in M4).

`Player` (`@MainActor @Observable public final class`) is the one object the app holds:

```swift
public private(set) var queue: PlayQueue
public private(set) var state: PlaybackState = .stopped
public private(set) var currentTime: TimeInterval = 0   // updated ~10 Hz while playing
public private(set) var errorMessage: String?
public var volume: Float { didSet }                     // forwards to graph
public var balance: Float { didSet }
public var repeatMode: RepeatMode { get set }           // forwards to queue
public var isShuffled: Bool { get set }

public init(resolver: any TrackResolver = FileTrackResolver())
public func enqueue(_ tracks: [Track])
public func play()                 // paused → resume; stopped → play queue.current (or first); empty → no-op
public func play(at index: Int)    // select + start from frame 0
public func pause()                // playing → paused; else no-op
public func togglePause()          // what the skin's pause button does
public func stop()                 // node stop, currentTime = 0, state .stopped
public func next() / previous()    // queue.next()/previous(); nil → stop() (next) or restart current (previous)
public func seek(to seconds: TimeInterval)
public func removeTrack(at:) / clearQueue()
```

Publishing to SwiftUI: `Player` is `@Observable` and `@MainActor`, so views read `player.state` / `player.currentTime` directly through `@Environment` or via `PlayerModel`. Every AVFoundation call stays on the main actor — the audio render thread never touches `Player`. The only cross-thread edges are (a) `scheduleSegment` completion handlers and (b) the future mixer tap (0005), both handled below.

`TrackResolver` seam:

```swift
public protocol TrackResolver: Sendable {
    func localURL(for track: Track) async throws -> URL
}
public struct FileTrackResolver: TrackResolver {   // .file(url) → url; .plex → throws AudioCoreError.unresolvableSource
```

`Player.startCurrentTrack()` is `async`: it awaits the resolver, then opens `AVAudioFile(forReading:)` on the main actor (header read only; fine for local files). Guard against stale completions by capturing `queue.current?.id` before the `await` and bailing if it changed. M2's `TrackCache` becomes the resolver and the "Buffering…" state hangs off this await.

### 4. Scheduling, seek and time

Keep one private method that every path uses, so 0003 can reuse it for the pre-scheduled next file:

```swift
private var file: AVAudioFile?
private var frameOffset: AVAudioFramePosition = 0   // frame the current segment started at
private var generation = 0                           // bumped on every stop()/seek/new track

private func schedule(_ file: AVAudioFile, from frame: AVAudioFramePosition) {
    generation += 1
    let gen = generation
    let count = AVAudioFrameCount(clamping: file.length - frame)   // guard count > 0
    playerNode.scheduleSegment(file, startingFrame: frame, frameCount: count, at: nil,
                               completionCallbackType: .dataPlayedBack) { [weak self] _ in
        Task { @MainActor in self?.segmentFinished(generation: gen) }
    }
    frameOffset = frame
}
```

- `segmentFinished(generation:)` ignores a mismatched generation (a `playerNode.stop()` fires completion handlers for every pending segment — that is the stale-callback trap). On a match: `queue.advanceAfterTrackEnd()` → `startCurrentTrack()` or `stop()`.
- **Seek** (acceptance criterion): clamp seconds to `0…duration`; `frame = AVAudioFramePosition(seconds * file.processingFormat.sampleRate)`; `wasPlaying = state == .playing`; `playerNode.stop()`; `schedule(file, from: frame)`; if `wasPlaying` then `playerNode.play()`, otherwise stay `.paused` with `currentTime = seconds` (the segment is queued and resumes on `play()`). Seeking to the very end with nothing left to schedule behaves like the track finishing.
- **Current time**: `frameOffset + playerNode.playerTime(forNodeTime: playerNode.lastRenderTime!).sampleTime`, divided by `file.processingFormat.sampleRate`. Both calls can return `nil` right after `play()`; fall back to the last published value. A `Task` loop (`ContinuousClock`, 100 ms) runs only while `.playing`, is cancelled on pause/stop, and writes `currentTime`. Pause snapshots `currentTime` so the UI doesn't drift while paused.
- `play()` from `.stopped` schedules from frame 0; `stop()` bumps `generation`, calls `playerNode.stop()`, resets `frameOffset`/`currentTime`.
- Engine configuration changes: observe `.AVAudioEngineConfigurationChange` (output device changed; the engine stops itself). If `state == .playing`, re-`start()` the engine and re-run the seek path from the last `currentTime`; if paused, just restart the engine. Keep this small but present — without it a headphone unplug leaves a silent "playing" state.

### 6. Tests (`Tests/AudioCoreTests`)

Use a tiny seeded generator in the test target (e.g. SplitMix64 conforming to `RandomNumberGenerator`) so shuffle tests are deterministic. Helper `func queue(_ n: Int) -> PlayQueue` builds tracks `"t0"…"t(n-1)"` with `.file` sources.

`PlayQueueTests`:
- empty queue: `current == nil`, `next()`/`previous()`/`advanceAfterTrackEnd()` all return `nil`.
- `select(1)` then `next()` → `t2`; `previous()` twice → `t0`; `previous()` at 0 with `.off` → `nil`, index unchanged.
- `.off`: `next()` at the last track → `nil`; `advanceAfterTrackEnd()` at the last → `nil`.
- `.all`: `next()` at last → `t0`; `previous()` at first → last.
- `.one`: `advanceAfterTrackEnd()` → same track; `next()` still advances to the following track.
- shuffle on with a seeded rng: the sequence of `next()` results visits every track exactly once and starts with the current track; `previous()` retraces the same path; `.off` returns `nil` after the last; `.all` continues and the following pass is again a full permutation.
- `setShuffle(false)` keeps `current`; a later `next()` is `currentIndex + 1`.
- `append` while shuffled: the new track appears in the remaining `next()` results before exhaustion.
- `remove(at:)` of the current track makes the next one current; removing the only track → `current == nil`; indices in the shuffle order stay valid (no crash walking the rest of the order).
- `indexAfterCurrentEnds()` agrees with `advanceAfterTrackEnd()` for each repeat mode.

`TrackTests`: `Track.file(at:)` on a generated WAV (write one with `AVAudioFile(forWriting:)` and a silent buffer in a temp dir) reports the right duration, sample rate and channels; a non-audio file throws. `Player` itself is not unit-tested here — `AVAudioEngine.start()` needs an output device and fails on headless CI; verify it by hand in the app (and `Player` construction must not touch the engine so it stays safe to instantiate in tests later).

### 8. Risks and gotchas

- **Stale completion handlers**: `playerNode.stop()` fires every pending segment's completion. Without the `generation` check a seek would immediately "finish" the track and skip to the next one.
- **Completion thread**: the handler runs on an internal AVFoundation queue; always hop with `Task { @MainActor in … }` and never touch `file`, `queue` or `state` inside the closure itself. Capture only `gen` and `[weak self]`.
- **Swift 6 strict concurrency**: `AVAudioFile`, `AVAudioPlayerNode`, `AVAudioEngine` are not `Sendable`. Keep them inside `@MainActor` classes and never pass them across an `await` boundary into a detached task; `Track`, `PlayQueue`, `Source` must be `Sendable` values.
- **Format changes between files**: a 48 kHz file after a 44.1 kHz one needs the nodes reconnected while stopped; otherwise the player node resamples silently or `scheduleSegment` plays at the wrong pitch depending on the OS version. Do the reconnect explicitly.
- **`AVAudioFrameCount` is 32-bit**: clamp `file.length - frame`; files over ~27 h at 44.1 kHz are not a concern but the conversion must not trap.
- **Engine start failures** (no output device, CI): surface through `errorMessage`, never `try!`.
- **`AVAudioEngineConfigurationChange`** silently stops the engine on device changes; handle as in §4.
- **XcodeGen scheme syntax** for a package test target is `- package: PlayerKit/AudioCoreTests` (same form as the existing SkinKit entry).
- **Observation churn**: `currentTime` at 10 Hz re-renders only views that read it; don't read it from `MainWindowView`'s body until the time digits land in M4.
