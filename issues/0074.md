## Description

The user decided on 2026-10-14 to drop direct Plex Media Server support. Music Assistant already offers Plex as one of many music sources, so SkinAmp's own Plex client, sign-in, server picker, download cache and Plex backend are redundant. The source order becomes Music Assistant (default) → local folder.


**Hold lifted (2026-10-19, user's decision):** the user can't use Plex ("it is hostile to integrations") and wants the app usable on Music Assistant alone. Remove direct Plex now, without waiting for #0066; #0066 (Sendspin playback on This Mac) follows and is the way Plex music reaches the Mac, through Music Assistant's Plex provider. ~~On hold (2026-10-18): don't remove direct Plex support until Music Assistant can play through this Mac.~~ The plan below was written against `main` at 21355e2; re-check it against current `main` (#0063, #0064, #0067, #0075, #0084 have landed since) before implementing.

## Acceptance criteria

- Remove the `PlexKit`, `PlexKitStub` and `PlexBackendKit` targets and their tests, the Plex Settings tab and sign-in flow, the Plex `LibrarySource` and its fallback probe, `PlexPlaybackStack`, and the Plex fixtures and `scripts/record-plex-fixtures.sh`.
- Remove `TrackCache`, the Cache Settings tab and the progressive-download path from #0039 if nothing else uses them once Plex is gone; keep anything the folder source or Music Assistant needs (decide in the plan, with a reason).
- The "This Mac" output (`LocalPlayerOutput`) moves out of the Plex composition root so the folder source and, later, Music Assistant's local playback keep it.
- Plex entries in the saved queue (#0071) are dropped or skipped cleanly on restore.
- On first launch after the change, leftover Plex data is cleaned up: the Keychain item `com.brennanmke.SkinAmp.plex`, the Plex defaults, and the `Tracks/` cache directory.
- `App/Info.plist` keys added only for Plex (#0012) are re-checked; the local-network keys stay because Music Assistant also needs them.
- Docs (`docs/plan.md`, `docs/plex-music-library.md`, `docs/music-assistant-integration.md`, `README.md`) say Plex is reached through Music Assistant.
- The VM run passes with the Plex suites gone and no Plex symbols left (`grep -ri plex` shows only history, docs about the change, and Music Assistant's Plex provider).

### 5. `LocalPlayback`: `QueueSnapshot.swift` and `QueueAutosaver.swift`

`StoredSource` keeps only `.file(path:)`; its `kind` switch keeps the `default:` that throws `DecodingError` for an unknown kind (that is what `"plex"` becomes). `StoredItem` gains a custom `init(from:)` that decodes `source` as `try? c.decode(StoredSource.self, forKey: .source)` into `var source: StoredSource?`, so an item of a removed or unknown kind, or with a malformed source, survives decoding as "no source" instead of failing the file. `load()`:

```swift
/// What `loadQueue()` found: the queue minus items of kinds this build cannot play.
public struct LoadedQueue: Equatable, Sendable {
    public var snapshot: QueueSnapshot
    /// Items dropped because their source kind is unknown (a queue saved with the removed Plex source).
    public var droppedItems: Int
}

/// nil as `load()`; otherwise the surviving items in order, `currentIndex` remapped (nil when the current item was dropped).
public func loadQueue() -> LoadedQueue?
public func load() -> QueueSnapshot?   // loadQueue()?.snapshot
```

Rules: file missing, unreadable, not JSON, `version != 1` or `items` malformed → nil, file left alone (as today); items with `source == nil` are skipped; `currentIndex` → the new position of the same item when it survived, else nil (a restore with no current track is stopped; `Player.play()` from `.stopped` with no current selects index 0, `Player.swift` line 249); `droppedItems` is the count; `log.info("queue restore dropped \(n) item(s) of an unknown kind")` once when `n > 0`, never a path or key. `save` is unchanged except for the single source case. The key allowlist stays as documented minus the Plex source keys.

`QueueAutosaver` gains `public func saveNow()`: the body of `flush()` without the `saveCount == 0 && snapshot == baseline` guard (writes the current queue synchronously, `saveCount += 1`). `flush()` keeps its guard (review e5109f8's reason still holds for an unreadable or newer file). `PlayerModel` calls `saveNow()` right after `start()` when `droppedItems > 0`, so a queue that lost its Plex entries is rewritten once and the `partKey`s leave the disk; a later launch finds a clean file and drops nothing.

### 7. `App/LegacyDataCleanup.swift`

```swift
/// One-time removal of what the removed Plex source (#0074) left on this Mac: its Keychain item, its defaults
/// and the track cache. Runs before anything reads defaults; idempotent through `versionKey`; logs counts and
/// statuses only. In the Tart guest nothing exists, so every step is a no-op and nothing can prompt.
enum LegacyDataCleanup {
    static let versionKey = "legacyCleanupVersion"
    static let version = 1
    static let defaultsKeys = ["PlexServerSelection", "PlexClientIdentifier", "TrackCacheLimitBytes"]
    static let keychainService = "com.brennanmke.SkinAmp.plex"
    static let removedSourceID = "plex"

    static func run(defaults: UserDefaults = .standard, bundleIdentifier: String? = Bundle.main.bundleIdentifier)
}
```

`run`, synchronously on the main actor, each step independent of the others' outcome:

1. `guard defaults.integer(forKey: versionKey) < version else { return }`.
2. `removeObject(forKey:)` for each of `defaultsKeys`; if `defaults.string(forKey: LibrarySourceController.defaultsKey) == removedSourceID`, remove that key too (the resolver then picks the default source, Music Assistant; a user who had chosen the folder keeps it).
3. Keychain: `SecItemCopyMatching` with `kSecClass: kSecClassGenericPassword`, `kSecAttrService: keychainService`, `kSecMatchLimit: kSecMatchLimitAll`, `kSecReturnAttributes: true` and **no** `kSecReturnData` (attribute queries never prompt and never decrypt). `errSecItemNotFound` → nothing (the guest). `errSecSuccess` → `SecItemDelete([kSecClass: kSecClassGenericPassword, kSecAttrService: keychainService])`, logging the `OSStatus` at `error` if it is not `errSecSuccess`/`errSecItemNotFound`. Any other query status is logged by number and skipped. The token is never read.
4. `~/Library/Caches/<bundle id>/Tracks` (`FileManager.default.urls(for: .cachesDirectory, in: .userDomainMask)[0]/<bundleIdentifier ?? "SkinAmp">/Tracks`): if it exists, `removeItem` on a `Task.detached(priority: .utility)` (a few GB of parts can take a second; nothing reads the directory any more), logging the result. If removal fails the directory stays and macOS purges Caches on its own; not retried.
5. `defaults.set(version, forKey: versionKey)` after steps 2 and 3 (not after 4: the flag means "attempted", and a failed cache removal is not worth a second Keychain round).

Logging: `Logger(subsystem: "com.brennanmke.SkinAmp", category: "LegacyCleanup")`, `info` "removed Plex defaults (n keys), Keychain item: found/absent, cache dir: removed/absent/failed(status)". No test target covers `App/` (as for `PlayerModel`); `app-launch` in the guest exercises the all-absent path, and the host checklist in section 13 covers the rest. It is the only new code with `import Security`.

### 15. Risks and gotchas

- **#0061/#0063 may have reached into Plex code.** The two places to look are `StubURLProtocol` (section 8 (c)) and the token types (8 (d)). Both have a stated fallback; neither changes this plan's shape. Check them first, before deleting anything.
- **The queue file must never be nil'd by a Plex entry.** Today's `QueueStore.load()` fails the whole file on an unknown kind; the lenient per-item decode in section 5 is what protects a mixed queue. The new test pins it, including `currentIndex` remapping. A file written by this build and read by an older build still decodes (the key set only shrank).
- **Keychain deletion and prompts.** The attribute query never prompts. `SecItemDelete` on an item this app created normally needs no authorization; the app is ad-hoc signed, so macOS *may* treat a rebuilt binary as a different app and ask once. The guest never has the item, so `app-launch` cannot hit this; the host checklist records what happened. The flag is set either way so the question is asked at most once; the token is never read.
- **`LibrarySource` defaults value `"plex"`.** `LibrarySourceSelection.resolve` already maps it to the default, so even without the cleanup the app would come up on Music Assistant; the cleanup removes it so a later change of the default reaches these users too (#0070's rule: nothing is written until the user picks).
- **`Track.Source` becomes a single-case enum.** `switch` statements over it (`FileTrackResolver`, `QueueSnapshot`, `TrickleResolver`, `EmbeddedArtworkLoader`'s `guard case`) compile unchanged; do not collapse the enum into a `URL`, or every future stream source reopens `Track`. `QueueSnapshot`'s `StoredSource` keeps its `kind` discriminator for the same reason.
- **The progressive tests must not lose their marker.** `TrickleResolver` decides by URL identity now; a test that builds a `Track.file(at:)` for the same WAV must use the real URL, not the marker, or it would trickle too. `ProgressiveFixtures` and `TrickleByteSource` are unchanged.
- **`FallbackText` strings are user-visible.** "Music Assistant can't be reached" and "Music Assistant isn't set up" are details; the texts "Using Local Folder" (18) and "Back on Music Assistant" (23) fit the marquee's 31 units. The test keeps the check.
- **`check-info-plist.sh` ordering with #0063.** If #0063 landed its `NSBonjourServices` change, keep it; this issue touches only the description assertion. If the guest's plist still mentions Plex because #0063 reworded it to name both, the new assertion still passes (it looks for "Music Assistant"), and the description must lose "Plex" in `project.yml` here.
- **`docs/plan.md` is the master plan; keep history readable.** Mark removed items, do not delete them; resolved issues (#0008, #0011–#0014, #0036, #0039, #0062) keep pointing at it.
- **Nothing in this issue may run on the host.** The only host commands are `xcodegen generate`, `plutil -lint`, `scripts/check-info-plist.sh` on the source plist, and `git`. The removed `record-plex-fixtures.sh` was host-and-network by design; nothing replaces it.
- **Swift 6.** `LocalPlaybackStack` is `@MainActor` like its predecessor; `LegacyDataCleanup.run` is called on the main actor from `init` and the detached removal captures only a `URL`; `QueueStore.LoadedQueue` is `Sendable`; `QueueAutosaver.saveNow()` is `@MainActor` like `flush()`.
