## Description

When an import finds nothing playable, the "Skipped N file(s)" message only appears on the no-skin placeholder. With a skin loaded, dropping or opening only unsupported files shows nothing on screen; the only trace is the Console warning. The message is also not cleared by a later successful import. Found in the #0006 review.

## Steps to reproduce

1. Load a skin.
2. Drop a folder that holds only unsupported files (for example `.txt` or a corrupt `.mp3`).

## Expected behavior

The user sees a brief notice that the files were skipped, and the notice clears on the next successful import.

## Actual behavior

Nothing appears on screen.

### Scope and decisions

- **Where the message goes: the marquee, for a few seconds.** Webamp reserves exactly this slot: `userInput.userMessage` (`js/reducers/userInput.ts` 7, 34–37, `SET_USER_MESSAGE` / `UNSET_USER_MESSAGE`) is the first thing `getMarqueeText` returns when set (`js/selectors.ts` 633–636), ahead of the slider-focus texts and the track name. Winamp 2 uses the same strip for its transient texts ("Volume: 51%", "Seek to: …"). An `NSAlert` for a dropped `.txt` is un-Winamp and modal; a SwiftUI overlay would need its own font and would sit on top of the skin. So: #0021's `PlayerModel.marqueeText` gains a top-priority **notice**, which the marquee draws like any other text. On the no-skin placeholder the same notice replaces the old `errorMessage` line, so both windows show one thing from one source. Planner's copies of the two Webamp files (fetched 2026-10-13 from `captbaritone/webamp` master, `packages/webamp/`) are in `/private/tmp/claude-501/-Users-brennan-Developer-brennanMKE-SkinAmp/5851b7d4-5135-49c1-ac3b-f5d40617c8c8/scratchpad/plan0045/webamp/` (`js_selectors.ts`, `js_reducers_userInput.ts`); session-scoped, re-fetch with `curl -sS -f -o <dest> https://raw.githubusercontent.com/captbaritone/webamp/master/packages/webamp/<path>` into an empty scratchpad directory, never under the repo.
- **`errorMessage` stops carrying import results.** Today `importLocalFiles` writes "Skipped N file(s) — see Console" into `PlayerModel.errorMessage`, which only `PlayerView`'s placeholder reads and which only a later successful *skin* load clears (`App/PlayerModel.swift` 65, 132; `App/PlayerView.swift` 17). After this issue `errorMessage` means one thing, "why there is no skin", and import feedback is a `StatusNotice` with its own expiry. The same defect hides a failed skin load when a skin is already up (`loadSkin` failure sets `errorMessage`, nothing shows it), so that path posts a notice too; it is the same two lines.
- **Timing: 3 seconds, last message wins.** A notice is a value `(text, detail, shownAt)`; it is active until `shownAt + 3 s`. Posting a new notice replaces the current one and restarts the window (Webamp's `SET_USER_MESSAGE` replaces, it does not queue). Counts are per import, not cumulative: two drops in a row show the second drop's count. A successful import with nothing skipped clears the notice at once (the issue's expected behaviour); a partial import ("Skipped 1 of 5 files") posts a fresh notice and the title takes over 3 s later. Loading a skin neither posts nor clears an import notice. Three seconds reads 20 characters comfortably and is shorter than one full scroll of a long title; it is a constant in one place.
- **Texts are short and fit the 31-character marquee** (`MarqueeLayout.maxLength`), so a notice sits still rather than scrolling: `Skipped 1 file`, `Skipped 3 files`, `Skipped 1 of 5 files`, `Could not load <skin name>`. The file names and reasons stay in Console (`LocalTrackLoader` already logs each skip); the placeholder, which has room, appends the `detail` ("see Console"). The skin name is the only text that can exceed 31 characters; then it scrolls like a long title, which is fine for 3 s.
- **Testable part lives in AudioCore.** The app target has no test bundle. The text rules and the expiry arithmetic go into `StatusNotice` in AudioCore (the module that already owns `LocalImport`/`SkippedFile`, and where #0021 puts `MarqueeText`), tested with Swift Testing, no timers, no AppKit. `PlayerModel` keeps only the wiring: one stored property, one `Task` that sleeps until the expiry.
- **Not in scope:** `Player.errorMessage` (a playback failure that stops the player) is also shown nowhere. It belongs in the same slot, but it is a different code path and a different issue; file it as a follow-up ("Playback errors are not shown") rather than widen this one.

### 1. AudioCore: `StatusNotice` (`Packages/PlayerKit/Sources/AudioCore/StatusNotice.swift`, new)

```swift
/// A short message that takes over the marquee for a few seconds: Webamp's `userInput.userMessage`,
/// the first thing `getMarqueeText` returns. A value with explicit times so it is testable without timers.
public struct StatusNotice: Equatable, Sendable {
    /// How long a notice stays up before the marquee goes back to the track.
    public static let duration: Duration = .seconds(3)

    /// What the marquee shows. Short enough to sit still (31 UTF-16 units or fewer) wherever possible.
    public let text: String
    /// A longer hint for places with room (the no-skin placeholder), nil when `text` is all there is.
    public let detail: String?
    public let shownAt: ContinuousClock.Instant

    public init(text: String, detail: String? = nil, shownAt: ContinuousClock.Instant = .now)
    public var expiresAt: ContinuousClock.Instant { shownAt + Self.duration }
    public func isActive(at now: ContinuousClock.Instant) -> Bool { now < expiresAt }

    /// "Skipped 1 file", "Skipped 3 files", "Skipped 1 of 5 files" (when some tracks loaded);
    /// nil when nothing was skipped. `detail` is "see Console" (the loader logs each file and reason).
    public static func skipped(_ result: LocalImport, shownAt: ContinuousClock.Instant = .now) -> StatusNotice?
    /// "Could not load <name>" for a skin that failed to parse; `name` is the file name without extension.
    public static func skinFailed(_ name: String, shownAt: ContinuousClock.Instant = .now) -> StatusNotice
}
```

`skipped`: `let n = result.skipped.count; guard n > 0 else { return nil }`; `let total = n + result.tracks.count`; `let files = total == 1 ? "file" : "files"`; text is `"Skipped \(n) \(files)"` when `result.tracks.isEmpty`, else `"Skipped \(n) of \(total) \(files)"`; `detail: "see Console"`. No `String(localized:)`; the marquee font has no localization and the app has none.

### 2. App: `PlayerModel` (`App/PlayerModel.swift`)

- Add `private(set) var notice: StatusNotice?` and `@ObservationIgnored private var noticeTask: Task<Void, Never>?`.
- Add, with doc comments:

```swift
/// Shows `notice` in the marquee (and the no-skin placeholder) until it expires. A new notice
/// replaces the current one and restarts the clock; Webamp's SET_USER_MESSAGE does the same.
private func post(_ notice: StatusNotice) {
    noticeTask?.cancel()
    self.notice = notice
    noticeTask = Task {
        try? await Task.sleep(until: notice.expiresAt, clock: .continuous)
        guard !Task.isCancelled, self.notice == notice else { return }
        self.notice = nil
    }
}

private func clearNotice() {
    noticeTask?.cancel()
    notice = nil
}
```

  `PlayerModel` is `@MainActor`, so the `Task` inherits the actor and both mutations happen on the main actor. The equality guard means an expired sleep never clears a newer notice even if cancellation raced.
- `importLocalFiles`: after `let result = await LocalTrackLoader.load(urls)`, replace the `errorMessage =` branch with: `if let n = StatusNotice.skipped(result) { post(n) } else { clearNotice() }`, then the existing `guard !result.tracks.isEmpty else { return }` and the enqueue code unchanged. Net: nothing skipped → any old notice is cleared immediately; something skipped → posted whether or not tracks also loaded.
- `loadSkin` failure: keep `errorMessage = "\(url.lastPathComponent): \(error)"` and add `post(.skinFailed(url.deletingPathExtension().lastPathComponent))`. Success keeps `errorMessage = nil` and does not touch `notice`.
- `marqueeText` (added by #0021 as `marqueeOverride ?? MarqueeText.display(queue: player.queue, state: player.state)`) becomes `notice?.text ?? marqueeOverride ?? MarqueeText.display(...)`. If #0023 has already turned `marqueeOverride` into a `sliderFocus`-derived text, the rule is the same: the notice is the first `??` operand, matching Webamp's order (user message, then focus text, then track). Nothing else in the chain changes.
- Remove the `errorMessage = "Skipped …"` line; `errorMessage` is now written only by `loadSkin`.

### 8. Risks

- **Observation of `notice` from the marquee.** `marqueeText` reads `notice` inside a computed property, so SwiftUI tracks it like `marqueeOverride`; if the marquee does not swap when a notice is posted, check that `notice` is a stored property on the `@Observable` model, not `@ObservationIgnored` (only `noticeTask` is ignored).
- **Expiry during a scroll.** A long skin name scrolls and the notice drops out mid-scroll after 3 s; the marquee's global step counter means the title resumes mid-phase, exactly as a track change does in Webamp. Not a bug.
- **Races between imports.** Two overlapping `LocalTrackLoader.load` calls post in completion order, so a slow folder can post after a fast one; "last wins" makes that harmless. The clear-on-success rule can hide a skip notice from a still-pending earlier import; acceptable, the Console has it.
- **Placeholder precedence.** A skin error line hides behind an import notice for 3 s on the placeholder, then reappears (test (6)). That is the intended reading order; if it reads wrong in practice, swap the two lines in `placeholderText`, no other change.
- **`Task.sleep(until:clock:)`** needs macOS 13; the package and app target macOS 14.
- **#0062 is refactoring `PlayerModel` in the working tree** (a `MusicBackend`, `nowPlaying` snapshots replacing `player.state`, transport commands through `send(_:)`). Two consequences, neither changing this plan's shape: `MarqueeText.display(...)` may take `nowPlaying` instead of `player.queue`/`player.state` by the time #0021 lands, and the notice is still the first `??` operand; and `send(_:)` writes `errorMessage` on a transport failure, one more message no skinned window shows. Post that one as a notice too (`post(StatusNotice(text: error.localizedDescription))`) if the line exists when this is implemented, and say so in `## Fix`; otherwise it goes in the "Playback errors are not shown" follow-up with `Player.errorMessage`.

## Root cause

`importLocalFiles` wrote the skipped-file count into `PlayerModel.errorMessage`, which only the no-skin placeholder displays and which only a later successful skin load cleared. With a skin up nothing showed it, and a later good import never cleared it.

## Fix

Followed the plan: `StatusNotice` (AudioCore) holds text/detail/shownAt with a 3 s expiry; `PlayerModel` gains `notice`, `post(_:)`, `clearNotice()` and `placeholderText` (internal, not private, so #0068 can use them). `marqueeText` is now `notice.text`, else `marqueeOverride`, else the now-playing text (adapted to the landed #0021/#0023/#0062 code: `MarqueeText.display(nowPlaying, number:)`). `importLocalFiles` posts the skipped notice or clears it; `loadSkin` failure keeps `errorMessage` and also posts `.skinFailed`. `PlayerView` shows `model.placeholderText`.

Adaptation: the plan's #0062 note applied, so the transport-loop failure and `playFromLibrary` failure (both formerly `errorMessage =`) now post `StatusNotice(text: error.localizedDescription)`. #0068 is expected to replace these with its own wording. `MainWindowView` already reads `model.marqueeText`, so no change was needed there.
