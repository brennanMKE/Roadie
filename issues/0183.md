## Description

Phase C of M15. Winamp put dropped files at the row under the pointer. Roadie always appends: `PlaylistView`'s `.dropDestination(for: URL.self)` calls `model.open(urls, replace: false)`, and `importLocalFiles` calls `player.enqueue`. `PlayQueue` has no insert at all.

This issue adds:

- `PlayQueue.insert(_:at:)` and `Player.insert(_:at:)`, keeping shuffle bookkeeping consistent.
- An AppKit drop target on the track list (`PlaylistListInputView`) that inserts dropped files and folders before the row under the pointer, or appends below the last row.

#0184 reuses the same drop target for Library rows.

**Why AppKit:** the rows are covered by `PlaylistListInputView`, a sibling of the SwiftUI hosting view (`PlaylistWindowOverlays`), and it already maps y to a row (`row(atY:)`). The SwiftUI `.dropDestination` on `PlaylistView` stays for drops elsewhere in the window: the title bar and the bottom bar still append, and skins dropped anywhere still load.

## Root cause

`PlayQueue` had no insert, and the only drop target on the playlist was SwiftUI's `.dropDestination` on `PlaylistView`, which calls `open(urls, replace: false)` and so always appends. The AppKit `PlaylistListInputView` covering the rows (which knows y to row) wasn't a drop target.

## Fix

Followed the plan.

- `PlayQueue.insert(_:at:)` clamps the index, appends at `count`, otherwise inserts, shifts `currentIndex`, and while shuffled shifts `shuffleOrder`/`nextPass` then places the new indices via a new private `addToShuffle(_:)` (factored out of `append`). `shufflePosition`, `upNext` and `isPlayingFromUpNext` are untouched.
- `Player.insert(_:at:)` calls it and `reconcileSchedule()`.
- `PlayerModel.open`/`importLocalFiles` take `at row: Int?`; with a row (and not replacing) they insert at `min(row, count)` and play there if the player was idle.
- `PlaylistListInputView` registers for `.fileURL`, returns `.copy` for file URLs, and in `performDragOperation` inserts at the row under the pointer (or `playlist.count` below the last row); with `playlist.remote != nil` it passes `at: nil` (append). `skinPoint` gained a `windowPoint:` overload.
- Deviation: the optional insertion-line indicator (`dropIndicatorRow`) was not built.

## Plan

### 1. Queue (`Packages/PlayerKit/Sources/AudioCore/PlayQueue.swift`)

```swift
/// Inserts `new` before row `index` (clamped to 0...count; `count` appends). The current track keeps its identity,
/// `upNext` keeps its ids, and while shuffled the new rows join the rest of this pass and the next pass at random
/// places, as `append` does (#0183).
public mutating func insert(_ new: [Track], at index: Int)
```

- `guard !new.isEmpty`. Clamp `index`. If `index == tracks.count`, call `append(new)` and return.
- `let n = new.count`, then `tracks.insert(contentsOf: new, at: index)`.
- If `let c = currentIndex, c >= index`, then `currentIndex = c + n`.
- If shuffled:
  - Shift the old indices: `shuffleOrder = shuffleOrder.map { $0 >= index ? $0 + n : $0 }`, and the same for `nextPass`.
  - Then for each new index in `index..<index + n`, insert it as `append` does: into `shuffleOrder` at a random spot in `min(shufflePosition + 1, count)...count`, and into `nextPass` anywhere. Factor `append`'s loop into a private `addToShuffle(_ indices: Range<Int>)` used by both.
  - `shufflePosition` doesn't change: the new entries are inserted after it.
- `upNext` and `isPlayingFromUpNext` don't change (ids).

### 2. Player (`Packages/PlayerKit/Sources/AudioCore/Player.swift`)

```swift
/// Inserts before row `index` (see `PlayQueue.insert`); the pre-scheduled next file may now be the wrong one.
public func insert(_ tracks: [Track], at index: Int) {
    queue.insert(tracks, at: index)
    reconcileSchedule()
}
```

### 3. App: loading at a row (`App/PlayerModel.swift`)

- `open(_ urls: [URL], replace: Bool, at row: Int? = nil) -> Bool` passes `row` to `importLocalFiles`.
- `importLocalFiles(_ urls: [URL], replace: Bool, at row: Int? = nil)`. In the `Task`, after the existing gates, when `!replace`, `let row`:
  - `let at = min(row, player.queue.tracks.count)` (the queue may have changed during the load).
  - `player.insert(result.tracks, at: at)`.
  - `if wasIdle { player.play(at: at) }`.
  - Otherwise keep the existing append path.
- Everything else is unchanged: the refusal while a speaker is selected, `applyFeed(.localPlayRequested)`, `stopOthers`.

### 4. App: the drop target (`App/Playlist/PlaylistWindowOverlays.swift`, `PlaylistListInputView`)

- In `init`, call `registerForDraggedTypes([.fileURL])`.
- `draggingEntered(_:)` / `draggingUpdated(_:)`: return `.copy` when the pasteboard can read file URLs (`sender.draggingPasteboard.canReadObject(forClasses: [NSURL.self], options: [.urlReadingFileURLsOnly: true])`), else `[]`.
  - Optional, recommended: show where the drop lands. Store `dropRow: Int?` (the row under the pointer, or `count` below the last row). Set it on `model.playlist.dropIndicatorRow` (a new observable `var` on `PlaylistModel`, nil when not dragging), and draw a 1 px line in `style.current` at the top of that row in `PlaylistTrackListView`.
  - Clear it in `draggingExited` and `concludeDragOperation`.
- `performDragOperation(_:)`:
  - Read the URLs with `readObjects(forClasses: [NSURL.self], options: [.urlReadingFileURLsOnly: true])`.
  - The row is `row(atY: skinPoint)` for a point from `convert(sender.draggingLocation, from: nil)`. Divide by `scale` like `skinPoint(_:)`, and refactor `skinPoint` to take an `NSPoint`.
  - Below the last row, or nil, use `model.playlist.count`.
  - Call `model.open(urls, replace: false, at: row)` and return its result.
  - `open` loads a `.wsz` among them as a skin, and the other files go in at the row.
- **Remote queue showing** (a speaker, or This Mac fed by Music Assistant): keep today's behaviour. `importLocalFiles` already refuses on a speaker with the notice. On This Mac fed by Music Assistant it takes This Mac back, and the local queue appears. So when `model.playlist.remote != nil`, pass `at: nil`: the remote row index means nothing in the local queue, so append.

### By hand

1. Drag three audio files from Finder onto row 5 of a 20-row playlist: they appear as rows 5–7, in Finder's order, and the playing track keeps playing (its row number moves down by 3).
2. Drop below the last row: they're appended. Drop on the title bar or the bottom bar: they're appended (the SwiftUI path).
3. Drop a folder: its tracks go in at the row. Drop a `.wsz` on the list: the skin loads.
4. Drop onto an empty, stopped playlist: the first dropped track starts, as before.
5. With shuffle on, the dropped tracks come up later in the pass, and the current one continues.
6. With a speaker selected, the drop is refused with the same notice as today.
7. The insertion line (if built) follows the pointer and disappears when the drag leaves.
