# 0041 — Player state is stale while a track is still loading

| | |
|---|---|
| **Status** | open |
| **Module** | AudioCore |
| **Platform** | macOS |
| **First seen** | 2026-10-12 |

## Description

Between `play(at:)` and the async track resolve finishing, `Player.state` is still `.stopped` (from cold) or the previous track's `.playing`, so a second Play press restarts the load. Found in the #0002 review.

## Steps to reproduce

1. With the player stopped, call `play(at:)` on a track whose resolve takes a moment.
2. Read `state`, or press Play again before the resolve finishes.

## Expected behavior

The player reports that it is loading the track, and a repeated Play during the load does not start it again.

## Actual behavior

`state` reports the old value, and a second Play restarts the load.

## Plan

Written while #0003 is landing in `Player.swift` (the per-player `generation` counter has moved into `GaplessScheduler`, bumped by `scheduler.invalidate()` / `discardSchedule()`), so this describes the state machine rather than line numbers. Builds on #0040's `startCurrentTrack(autoplay:)` and its `autoplayAfterLoad` flag; if #0040 has not landed first, add them here.

### State

Add `case loading` to `PlaybackState` (`Packages/PlayerKit/Sources/AudioCore/PlaybackState.swift`) rather than a separate `isLoading` flag: one value can't disagree with itself, and every `switch` (including the app's play indicator) is forced to handle it. `.loading` means "a track is selected and its resolve/open is in flight; nothing is scheduled; `currentTime` is 0". The pending intent (play or park paused) lives in `autoplayAfterLoad`.

Transitions:

| From | Event | To |
|---|---|---|
| any | `play(at:)`, `next()`, `previous()`, `removeTrack` of current (non-stopped), natural end → next track | `.loading` (synchronous) |
| `.loading` | resolve + open succeed, `begin(file)` | `.playing` if `autoplayAfterLoad`, else `.paused` at 0:00 |
| `.loading` | resolve/open throws | `.stopped` + `errorMessage` (existing `fail`) |
| `.loading` | `stop()` | `.stopped` (load task cancelled, schedule invalidated) |
| `.loading` | `play()` | `.loading`; `autoplayAfterLoad = true` (no new resolve) |
| `.loading` | `pause()` | `.loading`; `autoplayAfterLoad = false` |
| `.loading` | `togglePause()` | `.loading`; flips `autoplayAfterLoad` |
| `.loading` | `seek(to:)` | no-op (`file` is nil during a load) |
| `.loading` | a new selection | `.loading` again; the old load is superseded |

### Change (`Player.swift`)

1. `startCurrentTrack(autoplay:)` sets state synchronously: cancel `loadTask`, invalidate the schedule, stop the node, `file = nil`, `currentTime = 0`, `errorMessage = nil`, `autoplayAfterLoad = autoplay`, `state = .loading`, then launch the load task. Also cancel the time loop (it already exits when `state != .playing`).
2. Supersede by generation, not by track id. Capture `let gen = scheduler.generation` after the invalidate and, after the `await` resolve (and again after opening the file, which #0003 may move to a detached task), `guard !Task.isCancelled, scheduler.generation == gen else { return }`. The current `queue.current?.id == track.id` check misses "same track re-selected" (`previous()` restarting a track, or play(at:) on the current index); the generation covers that because every new selection invalidates. Keep the `Task.isCancelled` check too so a cancelled task never calls `begin`.
3. `play()` gains `case .loading: autoplayAfterLoad = true` (a no-op when already set — it must never call `startCurrentTrack`). `pause()`'s guard becomes a switch: `.playing` as today, `.loading` → `autoplayAfterLoad = false`, else return. `togglePause()`: `.loading` → flip the flag.
4. `begin(file)` consults `autoplayAfterLoad` (#0040) and is the only place that leaves `.loading` on success; `fail` leaves it on error via `stop()`.
5. `removeTrack(at:)` of the current track while `.loading` → `startCurrentTrack(autoplay: autoplayAfterLoad)` or `stop()` when the queue is empty.
6. `handleConfigurationChange()` returns early for `.loading` as it does for `.stopped` (nothing scheduled; the load will connect and start the engine when it finishes). `scheduleNextIfNeeded()` (#0003) must not pre-schedule while `.loading`: its `scheduler.items.count == 1` guard already covers it, but add `state == .playing || state == .paused` for clarity.
7. Swift 6 / `@Observable` notes: `state` and `autoplayAfterLoad` are plain stored properties — no `didSet` (the #0002 Gotchas recursion). The load task is an unstructured `Task {}` created inside a `@MainActor` method, so it inherits the main actor and may read `scheduler.generation` and mutate `state` after the `await` without a hop; the only non-isolated code remains the `.dataPlayedBack` closure, which captures only the `Sendable` token. Adding an enum case is a source-breaking change for exhaustive switches: update `togglePause()`, `pause()`, and `App/MainWindowView.swift`'s `playIndicator`.

### App UI

- `PlayerModel.playbackState` already forwards `player.state`; add `var isLoading: Bool { player.state == .loading }` for the marquee.
- `MainWindowView.playIndicator`: `.loading` → `"MAIN_PLAYING_INDICATOR"` (Winamp shows the play glyph while opening a file). In #0022 (M4 time/indicator work), also draw `MAIN_WORKING_INDICATOR` beside it while `isLoading` and `MAIN_NOT_WORKING_INDICATOR` otherwise — the `PLAYPAUS` sprites already exist in `SkinSprites.swift`. Only the `switch` fix is in scope here; the working indicator is a one-line follow-up noted for #0022.
- #0013 (TrackCache) derives the marquee's "Buffering…" from `isLoading`; a cached track resolves immediately, so the state flashes by and no debounce is needed in AudioCore. If the marquee flickers for local files, debounce in the view, not the player.

### Tests (`Packages/PlayerKit/Tests/AudioCoreTests/`, headless — no engine)

Add `GateResolver` to `TestSupport.swift`: an `actor` conforming to `TrackResolver` whose `localURL(for:)` records the call (`calls: [Track.ID]`) and suspends in `withCheckedThrowingContinuation` until `release(_ id: Track.ID, with: Result<URL, Error>)` resumes it. Wrap the wait in `withTaskCancellationHandler` so a cancelled load resumes with `CancellationError` instead of leaking a continuation; have every test release whatever is still pending before it ends. Releasing with a URL to a nonexistent file makes `AVAudioFile(forReading:)` throw, which is the headless way to observe "this load was acted on" (`state == .stopped`, `errorMessage != nil`) versus ignored (state unchanged, `errorMessage == nil`). Poll with the `settle(until:)` helper from #0040 (10 ms, up to ~2 s) wherever a `Task` must run.

- `playAtIsLoadingSynchronously`: `play(at: 0)` → immediately `state == .loading`, `currentTime == 0`, `queue.currentIndex == 0`; settle → `resolver.calls == [t0.id]`.
- `repeatedPlayDuringLoadDoesNotRestart`: `play(at: 0)`, then `play()` three times and `togglePause()` twice → still `.loading`, `calls.count == 1`, `autoplayAfterLoad == true` (`@testable`).
- `pauseDuringLoadParksIntent`: `play(at: 0)`, `pause()` → `.loading`, `autoplayAfterLoad == false`; `play()` → `true`.
- `newSelectionSupersedesLoad`: `play(at: 0)`, `play(at: 1)` → `.loading`, `currentIndex == 1`, `calls == [t0, t1]`; release `t0` with a bad URL → settle; still `.loading`, `errorMessage == nil`; release `t1` with a bad URL → settle → `.stopped`, `errorMessage != nil` (the live load was acted on, the stale one was not).
- `restartingSameTrackSupersedesLoad`: `play(at: 0)`, `previous()` (restarts track 0) → `calls == [t0, t0]`; release the first with a bad URL → still `.loading`.
- `stopDuringLoadCancels`: `play(at: 0)`, `stop()` → `.stopped`; release `t0` → settle → still `.stopped`, `errorMessage == nil`.
- `loadFailureStops`: release with `.failure(AudioCoreError.unresolvableSource(...))` → `.stopped`, `errorMessage != nil`.
- `removeCurrentWhileLoadingReloadsNext`: `play(at: 0)`, `removeTrack(at: 0)` → `.loading`, `current?.id == t1.id`, `calls == [t0, t1]`; with `pause()` first, `autoplayAfterLoad` stays `false` across the reload.
- `nextAtEndOfQueueDuringLoadStops`: single track, `play(at: 0)`, `next()` → `.stopped`, later release ignored.
