# 0041 — Player state is stale while a track is still loading

| | |
|---|---|
| **Status** | open |
| **Module** | AudioCore |
| **Platform** | macOS |
| **First seen** | 2026-10-12 |

## Description

Between `play(at:)` and the async track resolve finishing, `Player.state` is still `.stopped` (from cold) or the previous track's `.playing`, so a second Play press restarts the load. Found in the #0002 review.

## Steps to reproduce

1. With the player stopped, call `play(at:)` on a track whose resolve takes a moment.
2. Read `state`, or press Play again before the resolve finishes.

## Expected behavior

The player reports that it is loading the track, and a repeated Play during the load does not start it again.

## Actual behavior

`state` reports the old value, and a second Play restarts the load.

## Notes

Harmless with local files, which resolve almost instantly. It matters once Plex tracks are downloaded through `TrackCache` (#0013), which is where a "Buffering…" state belongs. See the `## Review notes` in [#0002](0002.md).
