## Description

Add the position, volume and balance sliders and the shuffle, repeat, EQ and playlist toggles using skin sprites.

## Acceptance criteria

- Volume and balance backgrounds use the correct frame for the current value.
- Dragging the position slider seeks on release.

## Plan

### Scope and decisions

Seven main-window elements, all drawn from skin sprites and wired to the existing `Player`: the position, volume and balance sliders, the shuffle and repeat toggles, and the EQ and playlist toggles. Status stays `open`; this plan writes no code.

- **AudioCore needs no new playback support.** `Player` already has `volume` (0...1), `balance` (-1...1), `seek(to:)`, `isShuffled` and `repeatMode` (`PlayQueue.swift`: `RepeatMode.off/all/one`), and the setters re-reconcile the pre-scheduled next track. `PlayQueueTests` already cover shuffle and repeat order. The only AudioCore addition is a one-line `RepeatMode.toggled` rule (below).
- **Geometry and frame math live in SkinKit, not the app.** The app target has no test bundle and `scripts/run-tests-vm.sh` runs only the package tests, so every number that can be wrong (origins, thumb travel, frame index, snap, sprite names) goes into one pure type, `MainSliders`, in SkinKit, with Swift Testing tests. `App/` keeps only SwiftUI: views, gestures and the model wiring.
- **Volume and balance apply live; position seeks once, on release.** That is what Webamp does: `Volume.tsx` / `Balance.tsx` dispatch on every `onChange`, while `Position.tsx` records a scrub position during the drag and dispatches `SEEK_TO_PERCENT_COMPLETE` only in `onPointerUp` (`References/webamp/packages/webamp/js/components/MainWindow/Position.tsx`). Playback keeps running during the drag; the thumb follows the pointer, not the clock.
- **Balance snaps to centre.** Webamp's `setBalance` (`js/actionCreators/media.ts`, "The balance clips to the center") zeroes any `|balance| < 25`. Ported as `|b| < 0.25 → 0` in the pointer-to-value mapping, so the stored `Player.balance` is already snapped (the thumb jumps to centre while dragging, as in Winamp).
- **Repeat is a two-state toggle on the main window.** Webamp's repeat is a boolean (`reducers/media.ts` `TOGGLE_REPEAT`). With AudioCore's three modes: `off → all`, `all → off`, `one → off`; the button is "selected" whenever `repeatMode != .off`. M5's playlist window can expose `.one` later without changing the main window.
- **EQ and playlist toggles record state only.** Webamp's buttons mirror `getWindowOpen("equalizer"/"playlist")` (`EqToggleButton.tsx`, `PlaylistToggleButton.tsx`). There are no EQ or playlist windows until M5, so `PlayerModel` gets `isEQWindowOpen` and `isPlaylistWindowOpen` Booleans that the buttons flip and draw as selected; nothing else reads them yet, and they are not persisted (M5 item 3 decides persistence). M5 replaces the Booleans with the real windows' visibility behind the same property names, so `MainWindowView` does not change.
- **Slider drags publish a focus state for the marquee (#0021).** Webamp swaps the marquee text while a slider is held (`selectors.ts` `getMarqueeText`: "Volume: 57%", "Balance: Center" / "Balance: 40% Left", "Seek to: 1:23/3:45 (37%)", formats in `js/marqueeUtils.tsx`). This issue adds `PlayerModel.sliderFocus` only; the text belongs to #0021 and lands in whichever of the two issues is implemented second.
- **Webamp source.** `References/webamp` is gitignored and absent. For this plan a shallow clone of `captbaritone/webamp` at `79117c66d` (2026-10-12) was made in the planning scratchpad (`/private/tmp/claude-501/-Users-brennan-Developer-brennanMKE-SkinAmp/5851b7d4-5135-49c1-ac3b-f5d40617c8c8/scratchpad/webamp-src/webamp`); it may be gone by implementation time. Re-clone to `References/webamp` (ignored, never staged) if a citation below needs checking. Paths below are relative to `packages/webamp/`.

```swift
/// Main-window slider and toggle geometry, from Webamp's css/main-window.css, in skin pixels.
public enum MainSliders {
    public struct Slider: Sendable, Equatable {
        public let origin: CGPoint      // background top-left
        public let size: CGSize         // background size
        public let thumbSize: CGSize
        public let thumbInsetY: CGFloat // 1 for volume/balance ("top: 1px"), 0 for position
        public let travel: CGFloat      // input width − thumb width (a native range thumb moves this far)
        /// Thumb x for a 0...1 fraction: origin.x + round(fraction * travel).
        public func thumbX(for fraction: Double) -> CGFloat
        /// Inverse: the thumb is centred on the pointer, clamped to the track.
        public func fraction(forPointerX x: CGFloat) -> Double
    }
    public static let volume   = Slider(origin: (107, 57), size: (68, 13), thumbSize: (14, 11), thumbInsetY: 1, travel: 51)   // 65 − 14
    public static let balance  = Slider(origin: (177, 57), size: (38, 13), thumbSize: (14, 11), thumbInsetY: 1, travel: 24)   // 38 − 14
    public static let position = Slider(origin: (16, 72),  size: (248, 10), thumbSize: (29, 10), thumbInsetY: 0, travel: 219) // 248 − 29

    /// Frame height in volume.bmp / balance.bmp; 28 frames fill the 420-row sprite.
    public static let frameHeight = 15
    public static let frameCount = 28
    /// Webamp MainVolume.tsx: sprite = round(percent * 28); offset = (sprite − 1) * 15.
    /// sprite 0 gives offset −15, an invalid CSS position the browser ignores, so frame 0 shows: clamp at 0.
    public static func volumeFrame(_ volume: Float) -> Int   // max(0, min(27, Int((volume * 28).rounded()) − 1))
    /// Webamp MainBalance.tsx offsetFromBalance: floor(|balance| / 100 * 27) * 15 (MainBalance.test.js: 50 → 195, 100 → 405).
    public static func balanceFrame(_ balance: Float) -> Int  // min(27, Int((abs(balance) * 27).rounded(.down)))
    /// The 13 visible rows of frame `frame` of a 15-row-per-frame background sprite.
    public static func frameRect(of sprite: Sprite, frame: Int) -> CGRect // (sprite.x, sprite.y + frame*15, sprite.width, 13)
    /// Webamp setBalance: |balance| < 25 % snaps to centre.
    public static func snappedBalance(_ balance: Float) -> Float
    /// Balance fraction ↔ value: fraction = (balance + 1) / 2.
    public static func balance(forFraction f: Double) -> Float
    public static func fraction(forBalance b: Float) -> Double

    public enum Toggle: CaseIterable { case shuffle, repeat_, equalizer, playlist }
    public struct ToggleFrame { public let origin: CGPoint; public let size: CGSize }
    public static func frame(of toggle: Toggle) -> ToggleFrame
    /// Sprite name for a toggle state. Suffix order differs per sheet row: SHUFREP's shuffle/repeat use
    /// `_SELECTED_DEPRESSED`, EQ/PL use `_DEPRESSED_SELECTED` (skinSelectors.ts lines 225–243).
    public static func spriteName(_ toggle: Toggle, selected: Bool, pressed: Bool) -> String
}
```

Frame crop height is 13, not 15: Webamp's `#volume` and `#balance` divs are 13 px tall, so `background-position: 0 -offset` shows the top 13 rows of the frame. This also tolerates the common 418/433-row sheets (the four skins checked have 68×433 `volume.bmp`: 28 frames, a 2-row gap, the 11-row thumbs). Frame 27 reads rows 405...417.

Why `rounded()` and not `Int(…)`: `(0.5 * 28).rounded()` is 14 → frame 13, which is what Webamp shows for volume 50 (offset 195 = 13 × 15); `Int(0.5 * 28) - 1` would give 13 as well but 0.52 would differ (Webamp: round(14.56) = 15 → frame 14). Swift's default `.toNearestOrAwayFromZero` agrees with JS `Math.round` for non-negative input.

Built on the same name lookup as `image(for:)`. Coordinate with **#0020**: its balance → volume fallback (`Skin.tsx` `FALLBACKS`: `MAIN_BALANCE_BACKGROUND → MAIN_VOLUME_BACKGROUND`, `MAIN_BALANCE_THUMB → MAIN_VOLUME_THUMB`, `MAIN_BALANCE_THUMB_ACTIVE → MAIN_VOLUME_THUMB_SELECTED`) must apply to the frame crop too, so both `image(for:)` overloads resolve the sheet and sprite through one private `resolve(_ name:) -> (CGImage, Sprite)?`. `CGImage.cropping(to:)` clamps to the image bounds and returns nil when there is no intersection; a short sheet therefore yields a shorter frame rather than a crash. `Pika_Amp.wsz` has a 306-wide `posbar.bmp`, so `MAIN_POSITION_SLIDER_THUMB_SELECTED` (x 278, width 29) comes back 28 wide; draw thumbs in a fixed `thumbSize` frame, leading-aligned, so a clipped sprite does not shift the layout.

`positionFraction` is `player.currentTime / duration` with `duration = player.queue.current?.duration`, nil when `playbackState` is `.stopped` or `.loading` (Webamp hides the thumb under `.stop`, and `Player.seek` is a no-op without an open file) or when `duration <= 0` (Webamp: `position = duration ? … : 0`). Webamp quantises the thumb to whole percent (`step="1"`, `Math.floor(timeElapsed)`); a 219-px travel at 1-px resolution is finer, so no quantising. `seek(toFraction:)` calls `player.seek(to: f * duration)`; `Player.seek` clamps and emits `.seeked` for the Now Playing bridge.

### 10. Risks

1. **Gesture coordinates under `scaleEffect`.** The plan assumes `DragGesture(coordinateSpace: .local)` on a child of the scaled view reports unscaled skin pixels. If the user's host check shows the thumb moving at half speed (2× scale), divide the location by `model.scale` in `SkinSlider` (pass the scale in) and add nothing else; the math stays in `MainSliders`.
2. **Odd sheet sizes.** Short or narrow `volume.bmp` / `balance.bmp` / `posbar.bmp` crop to smaller images (`cropping(to:)` clamps). Fixed-size thumb frames and 13-row frame crops absorb the common cases; anything worse shows a gap, not a crash, and belongs to #0020's fallback work or #0026's comparison notes.
3. **`Player.currentTime` updates at 10 Hz**, so the position thumb advances in ~0.5 px steps on a 3-minute track; fine. It is also 0 while `.loading`, which is why the thumb is hidden then.
4. **Seeking a track that is still downloading** (`.loading`) is a no-op in `Player.seek`; the thumb is hidden in that state, so no drag starts.
5. **Balance snap during drag** moves the thumb under the pointer inside ±25 %; that is Winamp's behaviour (Webamp ports it), not a bug.
6. **Repeat `.one`** is unreachable from the main window; if M5 adds it, the main button still shows selected and turns it off, as planned.

## Root cause

The main window drew only the background, title bar, status layer, transport buttons and marquee. No slider, shuffle, repeat, EQ or playlist views existed, and nothing mapped pointer positions to volume, balance or seek values.

## Fix

- `MainSliders` (SkinKit, new, `Layout/MainSliders.swift`): origins, sizes, thumb travel (51/24/219), `volumeFrame`, `balanceFrame`, 13-row `frameRect`, balance snap, balance fraction mapping, toggle frames and sprite names, as planned.
- `Skin.image(for:frame:)` crops through `resolve`, so #0020's balance-to-volume fallback applies to frame crops; returns nil when the frame is past the sheet.
- `App/SliderViews.swift`: `SkinSlider` (background, thumb, drag gesture) and `ToggleSpriteButtonStyle`; `MainWindowView` adds three sliders and four toggles at `MainSliders` origins.
- Adaptations to the landed code (#0062, #0021, #0022):
  - Transport goes through `MusicBackend.transport`. `TransportCommand` gained `setBalance(Float)`, `setShuffle(Bool)` and `setRepeat(Bool)` (alongside the existing `seek` and `setVolume`), handled in `LocalPlayerOutput.perform`. `RepeatMode.toggled` is used by the model to decide the next repeat value.
  - `PlayerModel.send` now feeds one serial `AsyncStream` consumed by a single task, so a fast slider drag reaches the output in order. `volume` and `balance` are stored on the model (optimistic) and `volume` follows `NowPlaying.volume` when the slider is not held. `isShuffled` and `isRepeating` read the local player and are false for other outputs.
