## Description

`Player` plays a queue of files (gapless through `GaplessScheduler`, or progressively through `Player+Progressive`). Music Assistant's Sendspin stream (#0066) is different: the server owns the queue and pushes raw PCM chunks, each stamped with the moment its first frame must leave the speaker, already gapless across tracks. AudioCore needs a second input mode that schedules such chunks on the same player node, so the EQ, balance, volume and the visualizer tap apply to it unchanged, keeps them in sync with the stamped times, and gives the node back to file playback cleanly.

AudioCore stays Sendspin-free: it takes PCM bytes and *local* presentation times (microseconds on the host-time clock). #0108 converts server times with the Sendspin time filter.

- `clearDropsScheduledAudioAndReanchors`: the loosened check is a render-pipeline allowance, not a hidden defect. After the first 512-frame block, the next 1 536 frames must stay below 1e-4 against a 0.5-amplitude sine (undropped audio would fail by more than three orders of magnitude), and the re-anchor assertion would fail if the old 300 ms were still queued. The near-zero values match the residual of ten active 0 dB parametric EQ bands.
- `installedBridgePublishesAndClearsInfoCenter` (failed once in 20261019-230050-55041): not caused by #0106. That test never streams, every stream path is gated on `stream != nil`, and only the serialized `NowPlayingInfoCenterTests` suite installs a bridge. It passed in both later runs.
- Follow-up (not blocking): after an underrun the player node's sample time keeps running while nothing is scheduled, so the drift measurement (`anchor + sample / rate`) can't see the offset and no snap happens. The spec asks for a re-anchor after an underrun. A `.gap` also schedules its whole silence as one buffer, however long the gap is. Re-anchor when the node has played past `scheduledNodeFrames`, or when a gap exceeds `snapMicros`.

## Root cause

AudioCore only knew how to play a queue of files (gapless or progressive). It had no input that takes raw PCM chunks stamped with local presentation times, so Music Assistant's Sendspin stream had nothing to play through.

## Fix

Followed the plan: `StreamFormat`/`StreamChunk`, `PCMStreamDecoder` (16/24/32-bit LE, mono→stereo, >2 ch → first two, continuous `AVAudioConverter` with `primeMethod = .none`), pure `StreamTimeline`/`StreamDriftCorrector`, the `StreamRenderClock` seam (host-time and sample-time clocks), and `Player+Stream.swift` (`beginStream`, `changeStreamFormat`, `appendStream`, `clearStream`, `endStream`, `isStreaming`, `streamOutputSampleRate`). Start and snap use `play(at:)`; every other chunk is chained with `scheduleBuffer(at: nil)`. Local transport (`play`, `play(at:)`, `next`, `previous`, `seek`, `pause`, `startCurrentTrack`) ends the stream and emits `.streamPreempted`; `stop()` ends it. `reconfigureOutput()` restarts the engine, then clears the stream and rebuilds the decoder at the new rate and latency. `GaplessScheduler` is untouched.

Divergences from the plan:
- **Gap:** a `.gap` (`.gap(atMicros:silenceMicros:)`) schedules that much silence and then the chunk, without restarting the node. The plan said re-anchor, but a restart would throw away audio already scheduled. The stamped-time model stays consistent because silence counts as played frames.
- **Pending corrections:** the drift measurement subtracts corrections already scheduled but not yet played. Without this, the delay between scheduling and playback would make the corrector overshoot.
- **Fallback rate:** `AudioGraph.outputSampleRate()` falls back to 44 100, not 48 000, so it matches `connectIfNeeded`, which now calls it.
- **Queue edits while streaming:** `removeTrack`, `removeTracks` and `clearQueue` no longer restart or stop the transport while streaming, so editing the local list doesn't preempt the server stream.
- **No latency offline:** output latency is 0 in manual rendering mode (no device).
- **New error:** `AudioCoreError.unsupportedStreamFormat` is added and thrown by `beginStream` for a format the decoder can't take.

## Plan

### API (new, `Packages/PlayerKit/Sources/AudioCore/Stream/` and `Player+Stream.swift`)

```swift
/// Signed little-endian interleaved PCM (16 or 24 bit packed), as Sendspin sends it.
public struct StreamFormat: Hashable, Sendable { public var sampleRate: Double; public var channels: Int; public var bitDepth: Int }

/// One chunk: whole frames, and the local time (µs, CLOCK_UPTIME_RAW / host-time base) its first frame must be heard.
public struct StreamChunk: Sendable { public var presentationMicros: Int64; public var pcm: Data }

extension Player {
    public var isStreaming: Bool { get }
    /// The rate the graph runs at (the output's), for the hello's single supported format. Starts no engine.
    public var streamOutputSampleRate: Double { get }
    public func beginStream(_ format: StreamFormat) throws   // takes the node from file playback
    public func changeStreamFormat(_ format: StreamFormat)   // stream/start during a stream: same timeline
    public func appendStream(_ chunk: StreamChunk)
    public func clearStream()                                // stream/clear: drop scheduled audio, next chunk re-anchors
    public func endStream()                                  // stream/end: stop, state .stopped
}
```

### Files

1. **`Stream/StreamFormat.swift`** — `StreamFormat`, `StreamChunk`, `frameCount(of:)`, `bytesPerFrame`.
2. **`Stream/PCMStreamDecoder.swift`** — `struct PCMStreamDecoder` turning `Data` into an `AVAudioPCMBuffer` in the graph's processing format (Float32, non-interleaved, the node rate, 2 channels): 16-bit (`Int16(littleEndian:) / 32768`) and 24-bit packed (sign-extended / 8_388_608); mono duplicated to both channels; more than 2 channels → first two. When `format.sampleRate != nodeRate`, an `AVAudioConverter` (Float32 source buffer at the stream rate → node rate) kept across chunks so the resampler state is continuous; reset on `clearStream`. `func decode(_ data: Data, dropLeading: Int = 0, duplicateLast: Int = 0) -> AVAudioPCMBuffer?` applies the sync corrections below at the source rate before conversion.
3. **`Stream/StreamSync.swift`** — pure value types, no AVFoundation, the unit-tested core:
   - `struct StreamSyncPolicy { deadBandMicros = 100; snapMicros = 10_000; maxSpeedFraction = 0.005; lateDropMicros = 0 }`.
   - `struct StreamTimeline` tracking the anchor (`anchorMicros`, `anchorFrame` on the stream's frame count), `nextChunkMicros` (where the next contiguous chunk should start), and frames scheduled. `mutating func place(_ chunkMicros: Int64, frames: Int, nowMicros: Int64, rate: Double) -> StreamPlacement` with `enum StreamPlacement { case start(atMicros: Int64, dropLeading: Int), contiguous, gap(atMicros: Int64), overlap(dropLeading: Int), late(dropAll) }`: first chunk or after `clear` → `.start`, dropping the frames whose time is already past `nowMicros + outputLatency`; a chunk starting within ±1 ms of `nextChunkMicros` → `.contiguous`; later by more → `.gap` (re-anchor: silence then resume, logged); earlier → `.overlap` (drop the duplicate prefix); entirely past → `.late` (dropped, counted).
   - `struct StreamDriftCorrector` with `mutating func correction(errorMicros: Int64, chunkFrames: Int, rate: Double) -> StreamCorrection` → `.none`, `.drop(frames)`, `.duplicate(frames)` or `.snap`. Error = actual output time of a frame − its stamped time (positive: playing late → drop). Spec's suggested strategy: dead band 100 µs; `N = max(1, round(21 µs × rate))` frames per chunk, at most `floor(0.005 × chunkFrames)`; `.snap` when |error| > `snapMicros` (rare: after a stall or device change).
4. **`Stream/StreamRenderClock.swift`** — the seam that makes this testable offline:
   ```swift
   protocol StreamRenderClock {
       /// Local µs at which the node sample in `renderTime` reaches the speaker (includes output latency).
       func outputMicros(of renderTime: AVAudioTime, latencySeconds: Double) -> Int64?
       /// The AVAudioTime to pass to `playerNode.play(at:)` so the first scheduled frame is heard at `micros`.
       func startTime(forOutputMicros micros: Int64, latencySeconds: Double, nodeRate: Double) -> AVAudioTime
       func nowMicros() -> Int64
   }
   ```
   `HostStreamRenderClock` (real): `AVAudioTime.seconds(forHostTime:)` / `hostTime(forSeconds:)` on `renderTime.hostTime`; latency = `engine.outputNode.presentationLatency` + the device's `kAudioDevicePropertyLatency` + safety offset (read once per `start()` through `OutputDeviceProvider.describe`, add `public let latencySeconds: Double` to `OutputDeviceDescription` with an `init` parameter defaulting to 0 so `FakeOutputDevices` and other callers compile unchanged; `SystemOutputDeviceProvider.describe` fills it from `kAudioDevicePropertyLatency` + `kAudioDevicePropertySafetyOffset` (output scope) ÷ nominal rate). `SampleStreamRenderClock` (internal, for tests in offline manual rendering where host time is invalid): µs = `renderTime.sampleTime / rate × 1e6 + originMicros`, and `startTime` returns `AVAudioTime(sampleTime:atRate:)`. `Player` holds `var streamRenderClock: any StreamRenderClock = HostStreamRenderClock()` (internal, tests swap it).
5. **`Player+Stream.swift`** — internal `final class StreamSession { format; decoder; timeline; corrector; scheduledFrames; generation }` held in `Player.stream: StreamSession?`.
   - `beginStream`: if a file or progressive track is loaded, do what `stop()` does to the node and the schedule **without** touching `queue` (`discardSchedule()`, `playerNode.stop()`, `file = nil`, `closeProgressive()`, `loadTask?.cancel()`), then `stream = StreamSession(…)`, `startedGraph()`, `state = .loading`, `currentFormat = PlaybackFormat(sampleRate:, channels:)`, `currentTime = 0`. Emit `PlayerEvent.streamStarted`.
   - `appendStream`: ask the timeline; on `.start`/`.gap`/snap: `playerNode.stop()` (bump the stream generation first so stale completions are ignored), schedule the buffer with `at: nil`, then `playerNode.play(at: clock.startTime(…))`; `state = .playing`, `startTimeUpdates()`. On `.contiguous`: measure drift from `playerNode.lastRenderTime` (`outputMicros` of the frame being rendered vs the stamped time of that frame, known from the anchor and frames played) and apply the corrector's drop/duplicate inside `decoder.decode`, then `scheduleBuffer(_, at: nil)`. Completion handlers capture the generation and only decrement a `pendingBuffers` count (used for an underrun log line); they never advance the queue.
   - `clearStream`: generation bump, `playerNode.stop()`, `timeline.reset()`, `decoder.reset()`; state stays `.playing` (the stream continues), the next chunk re-anchors.
   - `endStream`: generation bump, `playerNode.stop()`, `stream = nil`, `currentFormat = nil`, `currentTime = 0`, `state = .stopped`, emit `.streamEnded`. The local `queue` is untouched, so the user's local playlist is still there afterwards.
   - **Local transport while streaming:** `play()`, `play(at:)`, `next()`, `previous()`, `seek(to:)` and `startCurrentTrack` on the file path first call `endStream()` and emit `PlayerEvent.streamPreempted` (the bridge tells Music Assistant to stop sending, #0108). `pause()` while streaming mutes nothing and emits `.streamPreempted` too after `endStream()` (a server-timed stream cannot be paused locally). `stop()` calls `endStream()` if streaming.
   - `currentTime` while streaming: seconds of audio played since the last `.start` (the app shows Music Assistant's elapsed time for this mode anyway, #0109).
   - **Output changes:** `reconfigureOutput()` (device change, engine configuration change) with a stream active: rebuild as it does today, then `clearStream()` so the next chunk re-anchors with the new latency and rate (the decoder's converter is recreated for the new node rate).
   - **Gapless:** nothing in `GaplessScheduler` changes. The stream mode never calls `scheduler.append`; `discardSchedule()` on entry invalidates the file generation so a file completion firing after `playerNode.stop()` is stale. The stream is gapless because the server sends one continuous timeline across tracks.
   - `PlayerEvent` gains `streamStarted`, `streamEnded`, `streamPreempted` (check every `switch` over `PlayerEvent` in the app and `NowPlayingBridge` compiles).
6. **`AudioGraph.swift`** — `func outputSampleRate() -> Double` (the output node's rate without starting, as `connectIfNeeded` reads it; 48 000 when it reports 0). No change to connections: buffers are scheduled in the processing format, so player → EQ → mixer → analyzer tap carry the stream exactly as they carry files.

### Notes

- Plan against `main` after #0074 (7c2d3bb): `Track.Source` has only `.file`; nothing here adds a `Track.Source` case, because a stream is not a queue entry.
- Do not use `AVAudioPlayerNode.scheduleBuffer(_:at:)` with host times for every chunk: chaining with `at: nil` keeps the node sample-contiguous; only the start and snaps carry a time.
- Keep the stream's work on the main actor like the rest of `Player` (chunks arrive every 15 to 150 ms; decoding a 25 ms chunk is microseconds). If profiling shows main-thread stalls, move decoding to a detached task later, not in this issue.
