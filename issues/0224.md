# 0224 — The Library has no Genres section

| | |
|---|---|
| **Status** | open |
| **Module** | LibraryBrowser / App |
| **Platform** | macOS |
| **First seen** | 2026-10-27 |

## Description

The Music Assistant web app browses by genre (Classical, Experimental, Electronic, Rock, …); Roadie's Library window has no genres at all, so music the user finds that way in Music Assistant can't be found in Roadie. This issue adds a **Genres** section to the Library sidebar, after Albums, whose content column lists the genres that have music, largest first, with their track counts, duplicate names merged. Selecting one opens it in the detail column (#0225 fills that in; here it shows a placeholder). Only with a backend that has `.genres` (Music Assistant). Design: [docs/design/genres.md](../docs/design/genres.md) §2.1, §2.2, §4.5.

## Plan

1. **`LibrarySection.genres`** (`Packages/PlayerKit/Sources/LibraryBrowser/LibraryBrowserModel.swift`), inserted after `.albums` in `sections` when `backend.capabilities.contains(.genres)` (`[.artists, .albums, .genres?, .playlists?, .favorites?, .radio?]`).
2. **`GenresModel`** (`Packages/PlayerKit/Sources/LibraryBrowser/GenresModel.swift`, new), `@MainActor @Observable`, owned by `LibraryBrowserModel` (`public let genres: GenresModel`, created in `init` like `favorites`):
   - `phase: LibraryBrowserModel.LoadState<[LibraryGenre]>` holding `GenreList.visible(try await backend.genres())`;
   - `load()` (if idle), `reload()`, generation-guarded so a stale load after a source switch is dropped (as `FavoritesModel.loadCounts`);
   - `selectedGenreID: MediaID?` and `selectedGenre: LibraryGenre?` (looked up in the loaded list; a reload keeps the selection when the id survives, clears it otherwise);
   - `onFailure` → `LibraryBrowserModel.reportFailure(_, .browse)`.
   - `LibraryBrowserModel.loadSection(reloading:)` gains `case .genres` (`reloading ? genres.reload() : genres.load()`); `clearSelection()` leaves the genre selection alone (the section keeps it, as Favorites keeps its kind).
3. **Sidebar** (`App/Browser/LibrarySidebarView.swift`): `case .genres: Label("Genres", systemImage: "guitars")`; AXID `library.sidebar.genres` comes from the existing `AXID.Library.sidebar(section.rawValue)`.
4. **Content column** (`App/Browser/GenreListView.swift`, new; wired in `LibraryWindowView.contentList`): a `List(selection:)` over the loaded genres (no paging view: the list is small and loaded whole):
   - row: name (one line) and, trailing, the track count in `.secondary`, `.monospacedDigit()`; `.help(GenreList.countsText(genre.counts))`; `.accessibilityLabel("\(name), \(countsText)")`; AXID `AXID.Library.row("genre", genre.id.rawValue)`;
   - loading: `ProgressView`; failed: the error text and a Retry button (copy what `RadioListView` or `PagedListView` shows); empty: `ContentUnavailableView("No genres with music", systemImage: "guitars")`;
   - list AXID `library.genres`.
   - No row actions yet (#0225 adds Play, Shuffle, Play Next, Add to Queue and double-click).
5. **Detail column** (`LibraryWindowView.detailColumn`): `case .genres`: `ContentUnavailableView("Select a genre", systemImage: "guitars")` with no selection, else `ContentUnavailableView(genre.name, systemImage: "guitars", description: Text(GenreList.countsText(genre.counts)))` with AXID `library.genre.detail` (#0225 replaces it with the real detail).
6. Refresh (the toolbar button) already calls `library.refresh()` → `loadSection(reloading: true)`: nothing else to do.
7. **Feature inventory**: add to `docs/design/test-automation.md` §5.7 the row "Genres: sidebar section (Music Assistant only), genres with music by size with counts, duplicate names merged" → UI `GenresUITests.genresAreListedBySize`, `.folderLibraryHasNoGenres`; Unit `GenresModelTests`, `GenreListTests`.
