## Description

`issues/Issues.md` says the fast tier must pass, but it lets an issue reach review with a plan that names no test, a bug fix with no regression test, and a UI change with no UI test; `AGENTS.md` says nothing about tests. This issue writes the rules from [docs/design/test-automation.md](../docs/design/test-automation.md) §7 into the two guides and the two companion docs, once the mechanisms they rely on exist (#0200's UI runs, #0201's `--expect-fail`). Docs only; no code.

## Plan

### 1. `issues/Issues.md`

- **"Filing a new issue", step 7 (planning):** the `## Plan` must end with `## Tests` (unit tests by name, with the `--expect` list), `## UI tests` (the `RoadieUITests` classes and tests, or `none (no UI change)`), `## Which tier` (`fast`, `full`, or `ui` with the `--ui-filter` classes; `full` when AudioCore/SkinLibrary code a slow test guards changes), and `## By hand`. A feature issue also names the row(s) it adds or changes in the design doc's §5 inventory.
- **Phase 2, step 4:** "Fast tests must pass before review" made explicit: `DONE` requires a quoted `VERIFY PASS` of a complete fast run, including `app-unit-tests`, with every new test in `EXPECT`, and, when `## Which tier` says `ui`, a `--ui --ui-filter …` run with its `UI` line. A `DONE` without them is a bail. Add the **regression-test-first** rule: for a bug fix, write the test, ask `VERIFY: scripts/verify.sh --expect-fail <test>` before the fix, then fix and ask the normal run; quote both. If the test can't fail on the current code (the fix is already in), say so in `## Verification` instead.
- **Phase 2, step 7 (`## Verification`):** lists the tests by name (the `EXPECT` and `EXPECT-FAIL` lines, the UI classes).
- **Phase 2v:** `--ui`, `--ui-skins all` and `--coverage` runs go in the background; the runner waits for the completion notification. The runner still returns stdout verbatim.
- **Phase 3 (review):** the reviewer re-runs the same command(s) with `--head`, bounces when a bug fix has no regression test or a UI change has no UI test, and the `## Resolution notes` blockquote names the tests that prove the fix.
- **"Build / verify command":** the tier table from the design doc §1 (fast, UI, slow, milestone end); `app-unit-tests` in the fast tier; `--ui`, `--ui-filter`, `--ui-skins`, `--test-skins`, `--coverage`, `--expect-fail`; the prerequisite `scripts/fetch-test-skins.sh` on the host.
- **"Milestone end":** `scripts/verify.sh --head --full --ui --ui-skins all --coverage`, recording the `PASS`/`FAIL`, `TIER`, `UI`, `AUDIO` and `COVERAGE` lines; a coverage floor breach files a backfill issue like any failure.
- **Module conventions:** add `RoadieTests` / `RoadieUITests` under `App`, and `Tooling` for scripts.

### 2. `AGENTS.md`

A `## Tests` section (four bullets): builds and tests run only in the VM through the Haiku runner and `scripts/verify.sh` (never `xcodebuild`, `swift test` or XCUITest on the host); every bug fix lands with a regression test proven by `--expect-fail`, every user-facing change with a UI test; `scripts/fetch-test-skins.sh` and `scripts/record-ma-fixtures.py` are host-only and read-only, and `.env` never enters the VM, a fixture or a log; the feature inventory in `docs/design/test-automation.md` §5 is updated with the feature.

### 3. `docs/issues-workflow.md`

The Verification table gains the UI row and the milestone-end row from design §1; "The pipeline" mentions `--expect-fail`. `docs/testing-in-vm.md`: check that #0200/#0201/#0212 left it consistent with Issues.md (same flag names), fix drift.

### 4. `docs/design/test-automation.md`

Mark §7 as "in force since #0213" with the date; nothing else.

## Root cause

The workflow guides predated the M16 test mechanisms (#0200 UI runs, #0201 `--expect-fail`), so nothing required a plan to name tests, a bug fix to carry a regression test, or a UI change to carry a UI test.

## Fix

Wrote design §7 into the guides as planned. `issues/Issues.md`: planning sections `## Tests` / `## UI tests` / `## Which tier` / `## By hand`; phase 2 rules (fast tests pass before review, regression test first with `--expect-fail`, UI test per user-facing change that fails on a no-op, UI tests only in the guest, no test-skin cache via `--skins`, Debug-only test hooks that never touch real user state); verification quotes `EXPECT`/`EXPECT-FAIL`/`UI`; runner backgrounds UI and coverage runs; reviewer bounce rules and resolution notes citing tests and run ids; tier table and flags; milestone end `--head --full --ui --ui-skins all --coverage`; `Tooling` module and the test targets under `App`. `AGENTS.md`: four-bullet `## Tests`. `docs/issues-workflow.md`: UI and milestone-end rows, `--expect-fail` mention. Design §7 marked in force.

`--coverage` arrives with #0212 (in progress; it adds the flag to `run-tests-vm.sh`/`verify.sh`). The text says it is "available once #0212 is merged"; drop that qualifier when #0212 merges. `docs/testing-in-vm.md` already matched the flag names, so it is unchanged.
