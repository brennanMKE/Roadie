# 0044 — Real-time seek test fails intermittently under load

| | |
|---|---|
| **Status** | open |
| **Module** | AudioCore |
| **Platform** | macOS |
| **First seen** | 2026-10-12 |

## Description

`seekInResampledFileKeepsFileTime`, a real-time test added in #0042, sleeps a fixed 200 ms of wall-clock time after seeking to 0.6 s and expects `currentTime` within a narrow window. When the engine is slow to start under parallel test load it reads outside the window (0.664 was seen during #0004), so `swift test` can fail even though playback is correct.

## Steps to reproduce

1. Run `swift test --package-path Packages/PlayerKit` repeatedly, especially alongside the offline render tests.

## Expected behavior

The test passes whenever playback is correct, regardless of machine load.

## Actual behavior

It occasionally fails on the time window. It passed 3 of 3 in the #0004 review and failed once during #0004's implementation.

## Notes

The #0004 reviewer suggests timing the sleep and asserting `0.6 < currentTime <= 0.6 + elapsed + 0.1`, or polling until `currentTime > 0.65` with a timeout. Apply the same scrutiny to `mixedFormatsAdvanceWithoutGapRealtime`.
